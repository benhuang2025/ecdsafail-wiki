## Summary

mochimodev rebased a batch of Toffoli levers onto `4eb93cb`. moscowchill's
`51c6c31` had been promoted 45 minutes earlier, but it is not in this tree.
The peak stays at 1273. Five levers are on by default:

1. **Level-2 Karatsuba in the square.** The 128-bit and 129-bit half squares
   (`y_lo` and the sum) are each split again into three ~64-bit squares, folded
   straight into the accumulator. This is the largest single item by the
   commit's own measurement.
2. **Fused walk round 1.** Round 1's target is still the constant `p`, so its
   257-bit walk add collapses to a sparse constant subtract of about 53
   Toffoli.
3. **Sparse round-0 lift.** The forward round-0 lift's 254-bit carry chain
   becomes a 52-bit truncated sparse add.
4. **Signed frame for the divide replay.** Coefficients are kept as signed
   values, so each replay cell needs one correction AND instead of three and
   no overflow-flag compare. It still needs a 22-bit repair.
5. **Smaller walk adds and comparator tops.** Two provably redundant walk-add
   carries are no longer allocated, which lets fewer walk adds split. The
   replay's boundary-repair compare loses its top Toffoli.

The chunk compare is widened 20 → 21 to pay some of the saving back as lower
Lambda. Net: 5,442 fewer average Toffoli at the same 1273 qubits.

## What changed and why it saves Toffoli

### 1. Level-2 Karatsuba square (`trailmix_ludicrous/square/product_register.rs`)

Background: `square_sub` computes `out −= y²` with one Karatsuba split
`y = a + b·2^128`. Branch A squares `a` (128 bits), branch B squares `b`, and
branch C squares `a + b` (129 bits). Each branch builds a triangular square
(`tri_square`) in a scratch product register, folds it into `out`, and
uncomputes it. See [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).

- New `karatsuba_branch(circ, x, coefficients, out, sign, overflow)` replaces
  the single `tri_square` of branches A and C. Branch B is unchanged.
  - It splits `x` into `a = x[..lo]` and `b = x[lo..]`, and builds
    `t = a + b` in a fresh `hi + 1` register.
  - It uses `x² = (1 − 2^lo)·a² + 2^lo·t² + (2^(2lo) − 2^lo)·b²`.
  - For each of `a`, `t` and `b`, it builds the sub-square, folds it into
    `out` once per pair of (local shift, parent shift), and uncomputes it.
  - Branch A passes the parent coefficients `[(0, +), (h, −)]`, and branch C
    passes `[(h, +)]`.
- New `fold_shifted(…, shift, negate)` adds `±product·2^shift mod p`. It
  picks one of four forms: a guarded `window_add`, `mod_add_top`, a split
  `mod_add_top` + `apply_f`, or `apply_f` alone when `shift = 256`.
- Why it is cheaper: a triangular square of `m` bits costs about
  `m(m−1)/2` Toffoli. Three ~64-bit squares instead of one 128-bit square
  remove about a quarter of that, and the square is built and uncomputed
  each time. The cost is more folds: 10 for branch A and 5 for branch C,
  instead of 2 and 1.
- The comment measures −2,682 executed Toffoli at an unchanged peak. It was
  measured on the author's earlier 1278-qubit tree, not on `4eb93cb`.
- `karatsuba2_enabled()` is on unless `SUB4_SQUARE_KARATSUBA2=0`.

### 2. Fused walk round 1 (`pingpong_div.rs`)

- In round 1 the target is `u`, which still holds exactly `p`, because round
  0 only touched `v`. Both values are odd, and `(p+1)/2 = 2^255 − h` with
  `h = 2^31 + 488` (`round1_h()`). So
  `(p ± v)/2 = (p+1)/2 ± (v>>1)`, minus 1 for the minus arm.
- `fused_round1_forward` builds this with Clifford gates plus two small
  constant adds:
  - set `sign = u[1] ⊕ v[1]`;
  - clear `p` with X gates;
  - CX in the arithmetic shift `v >> 1`;
  - XOR `sign` across `u`;
  - `sub_nbit_const_direct_uncontrolled_fast(u[..w], h)`;
  - add 1 into `u[255..]`.
- `fused_round1_reverse` is its exact mirror.
- The window is `w = round1_window(width) = 32 + endpoint_fold_window() = 52`
  positions, so a borrow that runs past bit 51 is dropped (about 2^-20 per
  execution).
- The comment says "one 257-Toffoli walk add becomes ~53, on all four
  traversal executions" (walk and walk-back, in both divide and multiply).
- `walk_round`, `walk_back_round`, `value_walk` and `value_walk_back` use it
  at round 1, unless `SUB4_PP_FUSE_ROUND1=0`. The replay's round 1
  (`seed_round_one`) is unchanged.

### 3. Sparse forward round-0 lift (`pingpong_div.rs`)

- `mux_round0_correction(…, subtract = false)` is the walk's forward round-0
  lift inside `fused_lift_round0_forward`. It now calls the new
  `mux_round0_correction_forward_sparse`.
- The dense version added a per-position mux of `f`, `0 − h` and `f − h`
  across `N − 2 = 254` carry positions. `0 − h` is dense above bit 32.
- The sparse version uses `x − M = NOT(NOT x + M)` under an `a1`-controlled
  complement. This turns the correction into one sparse add of
  `M = (¬a1·¬a0)·f + a0·h + (¬a1·a0)·1`, truncated at
  `replay_fold_window() − 2 = 52` positions.
- The ancilla AND count is unchanged. The comment says −404 Toffoli,
  peak-neutral, and no change in classical failures on a 72,192-shot
  population. `SUB4_PP_ROUND0_SPARSE_FWD=0` restores the dense lift.

### 4. Signed frame for the divide replay (`pingpong_div.rs`)

`signed_frame()` is on unless `SUB4_PP_SIGNED_FRAME=0`. It applies only to
the divide traversal's `replay_halving` / `replay_halving_round`.

- At round 2, `to_signed_frame` maps each canonical residue in `[0, p)` to a
  signed value in `(−2^255, 2^255)`. It adds `f` to the low 64 bits when the
  top bit is set.
- Before the terminal `conditional_mod_negate`, `from_signed_frame` maps
  back.
- New cell `signed_mod_add_pm_halve_fused_signed`:
  - The sum `target ∓ source` is exact in 257 bits. The 257th bit is a new
    `hi` wire, so `cell_extra` for Divide becomes 1.
  - To make the sum even, it adds `eps·p` with `eps ∈ {−1, 0, +1}`. The base
    cell needed `{−1, 0, +1, +2}`. That takes one AND (`minus_f`) instead of
    three.
  - There is no unsigned overflow flag, so the `REPLAY_FLAG_COMPARE` repair
    is gone. `fused_fold_maskfree` takes `plus_2f: Option` and gets `None`.
- The cost is the reduction decision. The parity wire is measured out with
  `hmr`, and its phase is repaired by `signed_parity_repair`, a truncated
  compare over the top `SUB4_PP_SIGNED_REPAIR = 22` positions. That is the
  same width as the flag compare it replaces.
- The comment measures the frame at −8,813 Toffoli and the repair at +7,632,
  for a net −1,181 on the divide traversal. That was on a 1278-qubit tree.

### 5. Walk adds and the boundary-repair compare

- **`signed_add_wrapping_sigma`** (the walk add). `carries[0]` is
  `sign ⊕ target0_is_one` and `carries[1]` is `source[1]`. Both are copies of
  live wires, so they are no longer allocated. Each use is replaced by CX and X
  gates on `sign` and `source[1]`. Carry wires go from `n − 1` to `n − 3`,
  with no Toffoli change.
- **`walk_low_chunk`**. A walk add is split into two ripples with a measured
  boundary only when its ladder does not fit under the walk peak. Since the
  unsplit add now needs `width − 3` ancillas, the threshold moves from
  `ladder >= width − 1` to `ladder >= width − 3`. Fewer rounds split, so fewer
  split-boundary compares are paid.
- **`cmp_lt_phase_conditioned`** (`arith/compare.rs`, the replay's
  chunk-boundary phase repair). The top carry was used only as a Z on
  `u[n−1]`. Its phase factors into `Z(u[n−1])·CZ(u[n−2], v[n−1])` after two
  CXs, so the top CCX and its carry wire are dropped. That is one Toffoli
  less per repair. It runs under `push_condition`, so it executes on about
  half the shots. The `c_in` wire stays.
- **`walk_top_skip`** (skip the top AND on schedule step-down rounds) is added
  but **off**, unless `SUB4_PP_WALK_TOP_SKIP` is set. Its comment says it
  measured 80 → 86 classical failures, so it is "NOT SAFE TO SHIP".

### 6. Knobs and nonce

- `SUB4_PP_REPLAY_CHUNK_COMPARE`: 20 → 21. This costs about +1,191 Toffoli
  for lower phase Lambda, per the comment (measured on an earlier tree).
- `plan()`: the `SUB4_PP_R1` default goes 340 → 341. `R2` 628 and `PEAK` 1273
  are unchanged.
- `SUB4_PP_ROUNDS` stays **696**. The long "BAKE … 704, not 700" comment
  above it describes the author's earlier tree. It does not match the code.
  `ROUNDS_MUL` stays 696.
- Tail nonce: 65700024945645 → 5020638865.

The per-item numbers above come from different trees, so they do not add up
to the measured −5,442.

## Why it is still correct, and what it risks

- **Exact.**
  - The level-2 Karatsuba identity. The comment reports 0 failures over 2.56M
    random square shots for branches A and C.
  - The removed walk-add carries, which were copies of live wires.
  - The phase-only top of `cmp_lt_phase_conditioned`.
  - The signed-frame arithmetic itself.
- **Probabilistic.**
  - The fused round 1 drops a borrow past 52 positions, about 2^-20 per
    execution.
  - The sparse round-0 lift is truncated at 52 positions.
  - The signed-frame parity repair and the frame conversions are truncated.
  - Fewer split boundaries and the wider chunk compare lower Lambda.
- **How failures would show.** A dropped borrow gives a wrong walk value,
  which is a classical or ancilla failure. A wrong repair is a phase failure.
- The shipped nonce draws a clean test set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

By the commit's own measurements, the level-2 Karatsuba square is the largest
single lever. It swaps the squarer's half-width triangular squares for a
deeper decomposition, so the commit is a multiplier/squarer swap. This was a
close call:

- The signed frame (−1,181) and the two walk-round fusions (about −816 and
  −404) are each smaller.
- The comparator-top cut could rival the square. It saves about half a
  Toffoli per boundary repair, and there are a few thousand repairs per
  shot. It was never measured on its own.
- If it is larger, Gate Fusion or measurement uncompute would be the
  alternative.

+/// Generalises `apply_shift_half`/`apply_shift_full` to an arbitrary shift and
+/// product width, folding `+/- product * 2^shift` (sign chosen by `sign` XOR
+/// `negate`) straight into the persistent mod-p accumulator `out`.

+/// Four regimes, chosen purely by how `shift + product.len()` compares to
+/// `out.len()` (== 256 here): a plain guarded window add when there is room
+/// to spare; `mod_add_top` alone on an exact top-aligned fit (no window
+/// guard exists past bit 256, so `window_add` would overrun `out` by
+/// construction — this must NOT fall through to the windowed case); the
+/// mixed top+tail split when the product straddles bit 256; and a pure
+/// `apply_f` reduction when the shift itself is already >= 256.
+fn fold_shifted(
+    circ: &mut B,
+    sign: QubitId,
+    product: &[QubitId],
+    out: &[QubitId],
+    overflow: QubitId,
+    shift: usize,
+    negate: bool,

+    if negate {
+        circ.x(sign);
+    }
+    let n = out.len();

+    // composed fold table tops out at exactly `shift == n` (the b0^2 / bs^2
+    // 2^256 terms), so this is unreachable -- pin it so a future coefficient
+    // edit fails loudly instead of panicking inside a slice index.
+    debug_assert!(shift <= n, "fold shift {shift} past the accumulator top");
+    if shift == n {
+        apply_f(circ, sign, product, out);
+    } else if shift + product.len() == n {
+        mod_add_top(circ, sign, product, out, overflow, shift);

+        apply_f(circ, sign, &product[lo..], out);
+    }
+    if negate {
+        circ.x(sign);
+    }
+}

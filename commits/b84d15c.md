## Summary

This is the same lever as [`98416e4`](98416e4.md), re-applied on the newer
tree. `DIALOG_GCD_WIDTH_SLOPE_X1000` goes from 1004 to 1005, so the binary GCD's
working width falls slightly faster with the step number. Because the width is
rounded up to an even number, only the 24 even steps 202 to 248 change, each by
2 bits. At about 20 executed Toffoli per bit-step, that saves 960 Toffoli, the
same amount as in `98416e4`. Qubits are unchanged. The tail nonce was
re-hunted.

## What changed and why it saves Toffoli

**Background.** The circuit is the dialog-GCD route (`emit_dialog_gcd_raw_pa`
in `src/point_add/mod.rs`). Two calls each run a reversible binary GCD on
(u, v) = (p, factor): the quotient dy/dx and the product with c = ox − Rx. Each
call has a forward pass, an apply pass and a reverse pass. Each GCD step
compares, swaps, subtracts and halves, using only the low `active_width(step)`
bits. [98416e4](98416e4.md) lists one step.

**The width envelope.** `dialog_gcd_tobitvector_active_width(step)` is
`clamp(2·⌈(256 − step·SLOPE/1000 + MARGIN)/2⌉, 1, 256)`. `MARGIN` is 9 on this
tree.

**The changes in `configure_ecdsafail_submission_route()`:**

- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 1004 → 1005.
  - The window shrinks by 2 bits at steps 202, 204, …, 248 (64 → 62 down to
    18 → 16). That is 48 bit-steps.
  - In each of the four GCD passes (forward and reverse, in two calls), one bit
    of window costs about 5 Toffoli: 1 in the comparator, 1 in the cswap, 2 in
    the controlled subtract or add, and 1 in the K=2 halving cascade.
  - On these steps the window is narrower than the comparator cap
    (`DIALOG_GCD_COMPARE_BITS = 72`), so the comparator shrinks with it.
  - 48 × 20 = 960, which matches the measurement.
- `DIALOG_TAIL_NONCE`: 3155 → 189322128207780.

## Why it is still correct, and what it risks

The envelope is an empirical bound on the GCD registers' bit length plus a
margin. An input whose registers are still too wide at one of the narrowed
steps loses its top bits. The GCD then goes wrong, which is a classical failure.
On `dda7bfd`, the parent of `af0f90a`, 10d9e measured that this notch alone breaks 13
test inputs at the inherited nonce (`memory/2026-06-05-kalfold23-island-3155.md`,
added in `bc858e8`). The fold-23 lever of `af0f90a` broke only 6. robertkodra
found a clean island with a long tail-nonce search: `189322128207780` draws a
clean set, with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.

## Classification rationale

The only circuit change narrows the GCD registers' working width, which is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout af0f90a -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol af0f90a b84d15c -- src/point_add` is 4 changed
   lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b84d15c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset. Expect:
   - 1390 qubits
   - 1,530,393 average Toffoli (rounded)
   - score 2,127,246,270
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `189322128207780` and an identical op
stream. Any other change needs a new nonce hunt.

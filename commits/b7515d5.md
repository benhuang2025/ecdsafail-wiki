## Summary

There are two exact levers, both of which replace coherent uncompute with
measurement. Qubits stay at 1285.

1. **Big fold adders of the λ² reduction.** The x-tail reduces λ² in place
   with five big adds, one per signed term of `c = 2^32 + 2^10 − 2^5 − 2^4 + 1`,
   in the fold and again in the unfold. Their widths are 224–256 bits.
   [c27e8a5](c27e8a5.md) left them as coherent Cuccaro, about 2 CCX per bit,
   because a measured-carry adder needs a carry wire per bit, and that did
   not fit under the peak.
   - This commit splits each add at bit 34 into two measured-carry blocks.
     The carry between the blocks lives on one wire, which is erased by a
     34-bit comparison.
   - The carry wires needed at once drop to the larger block's width, and
     the cost is about one CCX per bit plus 34.
   - About −2,120 Toffoli.
2. **The controlled in-place Cuccaro of the streamed GCD body bits** (from
   [da398df](da398df.md)). Each controlled MAJ/UMA contains a 3-control X
   that computes `ctrl ∧ x` into a scratch wire and then uncomputes it with
   a CCX. The uncompute is now a measurement plus a `cz_if`. That is −1 CCX
   per MAJ/UMA, −528 in total.

## What changed and why it saves Toffoli

1. **`ROUND84_BIGFOLD_SPLIT=34`** (pinned in `configure_ecdsafail_submission_route()`,
   `src/point_add/mod.rs`). It is read by the new `round84_bigfold_split()`
   in `arith/multiply.rs`.
   - The new wrappers `round84_add_big` / `round84_sub_big` replace
     `add_nbit_qq` / `sub_nbit_qq` at the five term adds of
     `round84_fold_hi_into_lo_aggregate` and the five inverse adds of
     `round84_unfold_hi_from_lo_aggregate`.
   - Those adds are `lo[shift..] (+wrap) ±= hi[..n − shift] (+0 top)` with
     shifts 0, 4, 5, 10 and 32. The top source bit is known to be 0, so the
     wrapper adds `a[..w−1]` into the `w`-bit target as a "low-to-ext" add.
   - With `split > 0` the wrappers call the new
     `cuccaro_add_fast_split2_low_to_ext` /
     `cuccaro_sub_fast_split2_low_to_ext` in `arith/adder.rs`:
     ```
     low block  [0, s):  cuccaro_add_fast(a[0..s] ++ |0>, acc[0..s] ++ cout, c_in)   // carry out into cout
     high block [s, n]:  cuccaro_add_fast_low_to_ext(a[s..n], acc[s..n+1], cout)     // cout as carry-in
     cmp_lt_into_fast_with_cin(acc[..s], a[..s], c_in, cout)                         // cout := 0
     ```
     After the add, the low block's carry-out equals `acc_new[..s] < a[..s]`.
     That is why one `s`-bit compare clears `cout` exactly. The subtract
     twin uses the borrow form, X-conjugating `a[..s]`.
   - Cost per add: about `n` CCX for the two fast blocks plus about `s` for
     the compare, against about `2n` coherent. The saving is about `n − s`.
     Over the five widths (256 + 252 + 251 + 246 + 224 = 1,229) that is
     1,229 − 5 × 34 = 1,059 per pass, and 2,118 for the fold plus the unfold.
     The author measured −2,124.
   - Carry wires live at once: `max(s + 1, n + 1 − s)`. The author reports
     `s = 34` as peak-neutral at 1285. A smaller `s` would need more carry
     wires in the high block. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
2. **`DIALOG_GCD_CTRL_LOWQ_MEASURED=1`**, read by the new
   `mcx3_measured_uncompute_enabled()` in `arith/adder.rs`.
   - In `mcx3_polar(c1, c2, c3, target, scratch)` the sequence was
     `ccx(c1,c2,scratch); ccx(scratch,c3,target); ccx(c1,c2,scratch)`. The
     last CCX becomes `hmr(scratch, m); cz_if(c1, c2, m)`.
   - `mcx3_polar` is called only from `ctrl_maj`, `ctrl_uma`, `ctrl_inv_maj`
     and `ctrl_inv_uma`, the building blocks of `cuccaro_add_ctrl_lowq` /
     `cuccaro_sub_ctrl_lowq`. On this route those are used only for the
     streamed suffix of the GCD walk body.
   - A suffix of `s ≥ 2` bits has `2(s − 1)` controlled MAJ/UMA. The 16
     map entries with `s ≥ 2` stream 82 bits, so there are
     2 × (82 − 16) = 132 per walk, and 4 walks give exactly −528.
3. **`DIALOG_TAIL_NONCE`: 11205317877 → 32800438302.**
4. **Dormant or unused code**, which does not change the circuit:
   - `ROUND84_BIGFOLD_BLOCKS` routes to the existing equal-split
     `cuccaro_*_fast_windowed_low_to_ext`. It is not set.
   - `ROUND84_BIGFOLD_WINDOW` routes to the new
     `add_nbit_qq_hybrid` / `sub_nbit_qq_hybrid` (`arith/nbit.rs`), which
     call `cuccaro_*_hybrid_lowfast` (low `k` bits fast, high bits
     coherent). It is not set. The code comment itself says this route
     leaves its carry dirty and fails the phase check.
   - Four `*_topclean` adder variants, and their self-tests
     `body_topclean_selftest` / `prefix_topclean_selftest`, are added to
     `adder.rs`. Nothing in the build calls them.

The sum of the two levers, 2,124 + 528 = 2,652, is within draw variance of
the measured −2,679.

## Why it is still correct, and what it risks

Both levers are exact.
- The split adder computes the same sum as the coherent adder. Its
  inter-block carry is cleared by an exact recompute (`acc[..s] < a[..s]`
  after the add), and its fast-block carries are erased by measurement with
  `cz_if` fixes.
- In `mcx3_polar`, the scratch holds exactly `c1 ∧ c2`, and neither control
  has changed when it is measured. The `cz_if(c1, c2, m)` cancels the phase
  that the X-basis measurement leaves.

No truncation changes, so Lambda does not change, and the nonce was
re-hunted only because the op stream changed. A wrong uncompute would show
up as phase or ancilla garbage. The shipped nonce `32800438302` draws a test
set with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both savings replace coherent uncompute (UMA halves, and an AND-uncompute
CCX) with measurement uncompute. That fits measurement uncompute. The split
adder is also a fast-adder reroute (Strength Reduction), which is the
runner-up.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout c27e8a5 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol c27e8a5 b7515d5 -- src/point_add` is
   817 lines in 4 files, and 711 of the added lines are in
   `arith/adder.rs`.
2. **Copy the adder file from the commit:**
   `git checkout b7515d5 -- src/point_add/arith/adder.rs`.
   - It is hand-written, not generated, and copied only because its diff is
     too large to inline.
   - It adds the split2 adders, the measured `mcx3_polar` switch, and the
     dormant hybrid and topclean variants with their self-tests, as
     described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `arith/multiply.rs`, `arith/nbit.rs` and `mod.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol b7515d5 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `MOD_*` or `ROUND84_*` environment variables set.
   Expect:
   - 1285 qubits
   - 1,385,437 average Toffoli (rounded)
   - score 1,780,286,545
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `32800438302` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

The commit changes three source defaults in `build()`, `TLM_HYB_V_DELTA`,
`TLM_COUT_K_DELTA` and `TLM_FOLD_DELTA`, from 2 to 3. It also bakes a new tail
nonce. Each delta is subtracted from a baked per-call value in the trailmix
schedule: how many carries of an adder or fold get their own clean,
measurement-vented ancilla. A larger delta therefore means fewer clean carry
ancillas in the calls where that schedule value is the binding limit.

The measured average went from 1,378,635.594 to 1,378,635.428, a drop of 0.17
Toffoli, which rounds to −1 on the leaderboard. Peak qubits stay at 1159. A
nonce reroll alone moves the average by about this much. The diff does not show
how much of the change comes from the deltas and how much from the new draw.

## What changed and why the score moves

All changes are `set_default_env` lines in `build()`, `src/point_add/mod.rs`.

- **`TLM_HYB_V_DELTA` 2 → 3.** `next_hyb_v_fit()` reads the next entry of
  `schedule::HYB_V` and subtracts the delta (`fit_schedule_value`, with
  `saturating_sub`). `controlled_hybrid_add_refs_impl` in `gidney.rs` then uses
  `vents = min(selected, TLM_TARGET_Q headroom)`.
  - The first `vents` carries of the Gidney AND-carry adder land in fresh
    ancillas. They cost one CCX forward and are erased by `hmr` + `cz_if_bit`.
  - The remaining carries are Toffoli'd straight into the addend and re-Toffoli'd
    on the way back, which is two CCX each but needs no extra wire.
  - So one less vent costs about one Toffoli in that call and frees one wire
    during it. See [adders-and-carries](../concepts/adders-and-carries.md) and
    [measurement-uncompute](../concepts/measurement-uncompute.md).
- **`TLM_COUT_K_DELTA` 2 → 3.** `next_cout_k()` subtracts the delta from
  `schedule::APPLY_COUT_K`. The result is the `k` given to
  `controlled_hybrid_add_cout_refs`, the apply-step cofactor add. `k` picks the
  chunk layout: `searched_cout_layout(n, k)`, chunked-then-Cuccaro, or a plain
  hybrid add.
- **`TLM_FOLD_DELTA` 2 → 3.** `next_fold()` subtracts the delta from each
  non-negative `schedule::FOLD_SCHED` entry. That entry is `nv`, the number of
  clean vents in the fused double/cdouble `+f` fold (`fused_fold`, `fused.rs`).
  Negative entries, which select the chunked fold, are left alone. `nv` is also
  capped by `headroom − reserve`.
- **Tail nonce:** `DIALOG_TAIL_NONCE` 200003194569 → 200007643711. The
  trailmix builder appends 48 `X;X` pairs chosen by the nonce bits. They do not
  change the computation, only the Fiat–Shamir test draw.

The deltas were introduced by jieyilong's `31421df` (in its
`configure_q1162_rebased_ffg1_route`); on this tree they come from BitWonka's
port in [`7b7bd12`](7b7bd12.md), which sets them to 2 in `build()` to trim the
peak. Here every call
already has the `TLM_TARGET_Q = 1159` headroom cap. One more unit of delta only
matters in calls where the schedule value, not the cap, is the smaller of the
two. The author's note says only that the setting is "one-Toffoli-lower". It
reports 10,116,815 emitted ops, but gives no op count for the base, so the
change to the op stream cannot be checked from the notes.

## Why it is still correct, and what it risks

- Fewer clean vents is still exact arithmetic. The carries that are no longer
  vented go back to the reversible in-place path, which leaves no measured
  phase to repair. The deltas cannot raise the peak, because they only lower
  the wire count in each call.
- Correctness of the draw: the new nonce gives 9,024 of 9,024 shots clean, with
  0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
- The −1 is a rounding-level gain. Most of it is probably the reroll. Re-running
  with the old deltas and the new nonce would separate the two effects.

## Classification rationale

The commit tunes existing threshold knobs with no new code, so it is filed as
iteration/threshold tuning. The runner-up is a pure nonce reroll (Verifier
Search), because the score change is about the size of a reroll.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f6ce76d -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol f6ce76d f861f87 -- src/point_add` is
   8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f861f87 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1159 qubits
   - 1,378,635 average Toffoli (1,378,635.428 before rounding)
   - score 1,597,837,965
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `200007643711` and an identical op
stream. Any other change needs a new nonce hunt.

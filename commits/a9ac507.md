## Summary

In the trailmix circuit, each GCD apply step does a controlled modular add
whose `+f` reduction ripples through a 54-bit window. A baked table, `FFG_G`,
says how many of those carry positions get a clean ancilla. The clean ones are
uncomputed by measurement. The rest are handled by a costlier graduated
chunked adder. This commit adds one clean carry to every entry that is already
24 or more. That makes 100 of the 516 folds slightly cheaper, at the cost of
one transient qubit each, at points that are not at the peak. The result is
exact and saves 53 average Toffoli against its base at 1166 qubits. The tail
nonce was re-hunted.

## What changed and why it saves Toffoli

### `src/point_add/trailmix_ludicrous/mod.rs`, `load_schedule()`

- `load_schedule()` now reads three variables:
  - `LUD_EXTRA_FOLD_VENTS` (default 0);
  - `LUD_EXTRA_FOLD_MIN_G` (default 0);
  - `LUD_EXTRA_FOLD_MAX_G` (default unbounded).
- It loads `FFG_G` through `fold_g`. Each entry `x` with
  `MIN_G ≤ x ≤ MAX_G` becomes `min(x + EXTRA, 53)`. The other tables load
  unchanged.
- How the table is used:
  - `apply_step_*` in `gcd.rs` takes the next `FFG_G` entry and passes it to
    `arith::controlled_mod_add_k(…, Some(k), Some(ffg))`. That function ends in
    `add_f_window(ctrl, y, LSBS = 54, f, Some(g))`.
  - With `g ≥ 53`, the whole window is a clean carry chain
    (`add_f_window_clean`).
  - Otherwise `add_f_window_hybrid` runs a `g`-bit clean prefix: one CCX per
    carry, each carry uncomputed with `hmr` plus a conditional Z. It then adds
    the remaining `54 − g` bits with
    `controlled_add_const_chunked_graduated_off`, which costs more Toffoli per
    bit.
  - Moving one bit from the suffix into the clean prefix therefore saves
    Toffoli. It needs one more carry qubit while that fold runs. See
    [modular-fold](../concepts/modular-fold.md) and
    [measurement-uncompute](../concepts/measurement-uncompute.md).
- In the baked `FFG_G` (516 entries), 489 are at least 24 and 389 are already
  53. So 100 entries actually change. The threshold keeps the extra qubit away
  from the folds that run with little headroom, where a low `g` was chosen
  because qubits are scarce. See
  [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

### `src/point_add/mod.rs`

- `build()` sets `LUD_EXTRA_FOLD_VENTS = "1"`, `LUD_EXTRA_FOLD_MIN_G = "24"`
  and `DIALOG_TAIL_NONCE = "40003939"` (was 6147), with `set_default_env`.
- The same three settings are also added to
  `configure_ecdsafail_submission_route()`. That function belongs to the old
  dialog route, which `build()` no longer calls, so those lines have no
  effect.

## Why it is still correct, and what it risks

- **Exact.** Both adder layouts add the same constant into the same 54-bit
  window and drop the same carry out of it. This change touches no
  truncation, so the hard inputs are the base's.
- **Peak.** The extra transient qubit could only matter at the peak. The
  run shows 1166 qubits, so these folds are not the high-water mark.
- **Nonce.** The new nonce `40003939` was found with the `GPU_FILTER=ludicrous`
  prefilter and full local validation: 0 classical, 0 phase and 0 ancilla
  failures over 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is fold/carry truncation. The change does tune the fold's
carry handling, but it truncates nothing: it buys an exact cheaper adder
layout with spare qubits. "Budget/headroom retune", spending qubit headroom
for Toffoli, would describe it better. Fold/carry truncation is the nearest
existing type. The header keeps the published label.

     holds the `apply_route_overlays` schedule overlays and the

     those overlays and the cap.
   - Against `ab1b2d6`, `git diff --ignore-cr-at-eol ab1b2d6 a9ac507 -- src/point_add`
     is 45 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol a9ac507 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `LUD_*`, `TRAILMIX_*`, `DIALOG_*` or `TLM_*` environment variables set. Expect:
   - 1166 qubits
   - 1,422,563 average Toffoli (1,422,562.776 before rounding)
   - score 1,658,708,458
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `40003939` and an identical op
stream. Any other change needs a new nonce hunt.

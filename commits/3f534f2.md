## Summary

The shift22 helper (`v · 2^22 mod p`, see [`1b913c5`](1b913c5.md)) folds the
22 bits that spill off the top back in as `spill · c`, using five full-width
Cuccaro adds at bit offsets 0, 4, 6, 10 and 32. The added operand is only
22 bits wide, so above bit 22 the carry can only ripple through a run of
ones. This commit stops each of those carry chains 63 bits up. A
Cuccaro add costs two Toffoli per carry position, so each op drops from
about 450–512 Toffoli to 126.

Over the five ops forward and five in the inverse, a shift22 pair saves 3,652
Toffoli. Three pairs are executed, which gives exactly the observed −10,956.
Qubits are unchanged.

## What changed and why it saves Toffoli

**Background.** In `mod_shift_left_by_k` (`src/point_add/solinas.rs`), step 2
adds `spill · c` with `c = 2^32 + 2^10 − 2^6 + 2^4 + 2^0`. Each term is one
`cuccaro_op(pos, is_sub)`: allocate a `padded` register of width `257 − pos`,
copy the 22 spill bits into its low end, and add (or subtract) it into the
slice `v_ext[pos..257]` with an in-place Cuccaro ripple adder. The default
`LOWQ_SHIFT22` path uses the plain `cuccaro_add`/`cuccaro_sub`. These have
one Toffoli per MAJ and one per UMA, so an `m`-bit op costs `2(m − 1)` Toffoli
and no measurement. `mod_shift_right_by_k` repeats the five ops in reverse
with flipped signs.

**The change.**

- `src/point_add/cuccaro.rs`: new `cuccaro_add_cut(b, a, acc, c_in, cut)` and
  its exact gate-level inverse `cuccaro_sub_cut`.
  - Positions `0..=cut` run the normal MAJ sweep, the boundary sum bit and the
    UMA sweep, so they compute `(acc + a) mod 2^(cut+1)` exactly.
  - Bits above `cut` only get `acc[i] ^= a[i]`, with no carry-in.
  - With `cut = n − 1` this is the original adder.
- `src/point_add/solinas.rs`:
  - New switch `shift22_spill_carrytail()` (env `SHIFT22_SPILL_CARRYTAIL`,
    default on).
  - New cut `shift22_spill_carrytail_cut()` = `22 + SHIFT22_SPILL_W`, with
    `W = 41` by default, so the cut is 63.
  - In both `mod_shift_left_by_k` and `mod_shift_right_by_k`, the `lowq` branch
    of `cuccaro_op` calls `cuccaro_add_cut`/`cuccaro_sub_cut` with that cut
    instead of the full adders.

**Why it saves Toffoli.** The cut op costs `2 × 63 = 126` Toffoli whatever its
width. The full ops cost 512, 504, 500, 492 and 448 Toffoli (widths 257, 253,
251, 247, 225), 2,456 in total. Five cut ops cost 630, so one direction saves
1,826 and a forward/inverse pair saves 3,652. The observed drop of 10,956 is
three executed pairs. The Toffoli are unconditional, so average and emitted
counts move together. The `padded` registers are still allocated at full
width, so the transient width does not change and the peak stays at 2309.

## Why it is still correct, and what it risks

- **Exact unless a carry crosses bit 63 of the slice.** The addend is zero
  above bit 21, so a carry that reaches bit 22 can only propagate through ones
  (for an add) or zeros (for a subtract). It is dropped only if bits 22…63 of
  the slice are all ones (or all zeros), about 2^-42 per op on a random value.
  A dropped carry gives a wrong `v · 2^22 mod p` and shows up as a classical
  mismatch.
- **Forward and reverse are exact inverses.** Every op is addition modulo
  2^64 on its low 64 bits plus an XOR of zeros above, and the inverse uses the
  same cut. So the shift22 pair restores its registers on every input and
  nothing is left dirty.
- **Island.** There is no tail nonce on this line (this tree does not contain
  the `KAL_REROLL` knob of `6e71096`). The test set is a hash of the op
  stream, and `W = 41` is the value whose stream draws a clean set:
  9,024 of 9,024 shots, 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from cutting the carry chains of the fold adds inside the
modular shift, which is fold/carry truncation. No runner-up: nothing else
changes.

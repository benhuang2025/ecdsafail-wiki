## Summary

Two changes in `src/point_add/mod.rs`:

1. Inside `mod_shift_left_by_k(hi, 22)`, which every Solinas fold uses to
   build its `hi·2^32` term, the spill add at bit position 32 now uses the fast
   Cuccaro adder, which erases its carries by measurement. It used the plain
   Cuccaro adder, which undoes them with a second Toffoli sweep. This applies
   only in the forward (left) shift. The reverse shift keeps the plain adder.
   This saves about 224 Toffoli per fold, and five folds run per point
   addition.
2. Pair 2's Kaliski loop runs 397 iterations instead of 398. That saves one
   iteration forward and backward, plus one modular doubling of `λ`.

Together these save 4,811 Toffoli. The submission note says that 397 was
"phase-fragile on the prior circuit hash". It validates on this op stream's
test draw only because change 1 re-rolled the draw. Qubits are unchanged.

## What changed and why it saves Toffoli

1. **New `shift22_fast_pos(pos, reverse)`**, used by the five-op spill add in
   `mod_shift_left_by_k` (`reverse = false`) and `mod_shift_right_by_k`
   (`reverse = true`).
   - The ops are add at positions 0, 4, 10 and 32 and subtract at 6. Each adds
     the 22 spilled top bits of `hi` into `v_ext[pos..257]`. The old code
     picked the plain `cuccaro_add` / `cuccaro_sub` whenever `lowq_shift22()`
     was on (env `LOWQ_SHIFT22`, default on), and the fast measured-carry
     versions otherwise.
   - Now the fast form is used when `shift22_fast_pos` returns true. With
     `lowq_shift22()` off it always does. With it on, the default is
     `!reverse && pos >= 32`, so only the forward position-32 add. Env knobs
     `LOWQ_SHIFT22_FAST_{FWD,REV,}_MIN_POS` move the cut-off.
   - At position 32 the op is 257 − 32 = 225 bits wide. The plain adder costs
     one Toffoli per MAJ and one per UMA, about 448. The fast adder pays only
     the MAJ sweep, about 224, and holds about 224 carry wires while it runs.
     The note says those wires stay under the 2708 peak.
   - The reverse shift does not replay the forward gates. It runs its own
     inverse ops (subtract where forward added), so the forward op may use a
     measured erase while the reverse stays plain. The note says the symmetric
     version, fast in both directions, "was not valid in the full harness".
   - In the default circuit, five folds run per point addition (pair 1's
     Karatsuba write, the `λ²` reduction into `breg`, the y-update multiply,
     the `breg` clear and pair 2's Karatsuba multiply-add), so this saves
     about 5 × 224 ≈ 1,100 Toffoli. See
     [measurement-uncompute](../concepts/measurement-uncompute.md) and
     [adders-and-carries](../concepts/adders-and-carries.md).
2. **`pair2_default`: 398 → 397** in `build_standard_point_add` (the
   non-tagged path; env `KAL_PAIR2_ITERS` overrides it).
   - One fewer generic Kaliski iteration in pair 2's forward and backward
     runs. In this line the bulk prefix ends at 394, so iterations 394 and up
     are generic.
   - One fewer `mod_double_inplace_fast(lam)` in phase `pair2_double`, which
     removes the `2^{iters}` factor.
   - One fewer `m_hist` qubit in pair 2. Pair 2 does not set the peak.
   - This part saves about 3,700 Toffoli, the remainder of the measured
     total. The loop structure is described in [`a16788e`](a16788e.md).
3. A code comment beside `pair2_default` is rewritten to describe the new
   value.

## Why it is still correct, and what it risks

- **Part 1 is exact.** The fast and plain adders compute the same sum, and the
  measured carry erase uses the standard `hmr` plus `cz_if` identity. The
  reverse shift's plain inverse ops restore `hi` and `spill` as before. A
  wrong phase fix would show up as phase failures, which is what the
  symmetric variant produced according to the note.
- **Part 2 is probabilistic.** Pair 2 frees its Kaliski state by value
  (`u = 1`, `v_w = 0`, `s = p`, `f = 0`). That is only right if the input's run
  has terminated before the last iteration begins, so that a generic
  iteration sees `v_w = 0` and clears `f`. An input that needs more iterations
  leaves the freed registers dirty (ancilla failure) and gives a wrong
  inverse, which leaves `λ` uncleared (classical failure).

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream. Part 1 changed the op stream, and with it the draw, and the
new draw contains no input that needs more than 397 pair-2 iterations. The
note reports 9,024 of 9,024 shots with 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as Strength Reduction → fast-adder reroute, which fits
part 1. Part 2 is a larger share of the saving, about 3,700 of 4,811, and is
iteration/threshold tuning (the census label for the same kind of change in
[`a16788e`](a16788e.md) and [`9bd0748`](9bd0748.md)). Part 1 is what made the
cut possible, by re-rolling the test draw.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9bcc27d -- src/point_add`.
   - Do not start from the git parent `74a1a8b`, cryptogakusei's λ²-fold
     edit. This commit was built on the tree before it.
   - Against the parent the diff is 58 lines. It turns 74a1a8b's from-zero
     and low-scratch fold adds back into `mod_add_qq_fast`.
   - Against `9bcc27d`, `git diff --ignore-cr-at-eol 9bcc27d 04b3a76 -- src/point_add`
     is 30 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 04b3a76 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `LOWQ_SHIFT22*`, `AFFINE_*`, `DUMMY_TOFFOLIS` or other environment
   overrides set. Expect:
   - 2708 qubits
   - 3,541,843 average Toffoli (3,541,843.000 before rounding, per the note)
   - score 9,591,310,844
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score, and the clean draw, only reproduce with an identical
op stream.

## Summary

Near the end of the point addition, the "x-tail" squares λ into a 512-bit
temporary and reduces it in place modulo p with a Solinas fold. This is the
`round84` in-place fold path in `arith/multiply.rs`. The fold contains a few
small fixed-width adders: building and unbuilding `quotient · c` (33 × 33 bits
into 66), and a 67-bit narrow correction. They used the coherent Cuccaro
adder (MAJ/UMA, about 2 CCX per bit, no carry wires).

This phase runs well below the qubit peak, so it can afford a carry wire per
bit. The commit switches these adders to the measured-carry Cuccaro: about
1 CCX per bit, with the carries erased by measurement. That saves about one
Toffoli per adder bit, about 1,434 emitted (−1,415 measured), with the peak
unchanged at 1285.

## What changed and why it saves Toffoli

1. **New pin `ROUND84_FOLD_FAST_ADD=1`** in `configure_ecdsafail_submission_route()`
   (`src/point_add/mod.rs`), read by the new `round84_fold_fast_add_enabled()`
   in `arith/multiply.rs`.
2. **New wrappers `round84_add_small` / `round84_sub_small`.** With the pin
   set, they call `add_nbit_qq_fast` / `sub_nbit_qq_fast` (`cuccaro_add_fast`
   with measured-carry uncompute) instead of `add_nbit_qq` / `sub_nbit_qq`
   (coherent `cuccaro_add`). Four call sites switch to them:
   - `round84_compute_quotient_c_product`: `quotient · c` is built as
     shifted copies of the 33-bit quotient at the set bits
     `4, 6, 7, 8, 9, 32` of `c = 2^32 + 977`. That is six adds into
     `product[shift..]`, with widths 62 + 60 + 59 + 58 + 57 + 34 = 330 bits.
   - `round84_uncompute_quotient_c_product`: the same six as subtracts,
     330 bits.
   - `round84_add_narrow_correction` and `round84_sub_narrow_correction`:
     one 67-bit add or subtract each.
   - The fold (`round84_fold_hi_into_lo_aggregate`) runs compute, add and
     uncompute. The unfold (`round84_unfold_hi_from_lo_aggregate`) runs
     compute, sub and uncompute. That is 2 × (330 + 67 + 330) = 1,454 adder
     bits per point add, each about 1 CCX cheaper, in line with the
     comment's −1,434.
3. The big fold adders (224–256 bits) stay coherent. The code comment
   explains that a measured version would need about 256 carry wires on
   top of the 1160 live wires in this phase, above the peak.
4. **`DIALOG_TAIL_NONCE`: 92428802 → 11205317877.**
5. **A stray file `src/point_add/arith/compare.rs.patch`** is added. It is a
   unified diff, from the author's machine, that would add a
   `ccx_cmp_lt_into_fast_vent_uncompute` function to `compare.rs`. It is not
   a `.rs` file and nothing applies it, so it has no effect on the build.

See [adders-and-carries](../concepts/adders-and-carries.md) for the two
Cuccaro forms and [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md)
for why a non-peak phase can spend wires.

## Why it is still correct, and what it risks

The change is exact. The measured-carry Cuccaro computes the same sum as the
coherent one. Each carry wire is erased by an X-basis measurement, and the
phase it leaves is fixed by a `cz_if` on the two operand bits, so there are
no new hard inputs and Lambda does not change. The new carry wires live only
inside a phase that is far below 1285, so the peak does not move. A wrong
phase fix would show up as phase garbage.

The shipped nonce `11205317877` draws a test set with 0 classical, 0 phase
and 0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from replacing coherent carry uncompute (the UMA half of
the Cuccaro adder) with measurement uncompute. That is measurement
uncompute. Strength Reduction → fast-adder reroute is the runner-up, since
it is literally a swap of adder form.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 980ed3a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 980ed3a c27e8a5 -- src/point_add` is
   104 lines in 3 files, one of them the new inert `compare.rs.patch`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol c27e8a5 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `MOD_*` or `ROUND84_*` environment variables set.
   Expect:
   - 1285 qubits
   - 1,388,116 average Toffoli (rounded)
   - score 1,783,729,060
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `11205317877` and an identical op
stream. Any other change needs a new nonce hunt.

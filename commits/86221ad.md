## Summary

The division `y/x mod p` and the multiplication `y·x mod p` in the point
addition were both done by GCD Skywalk. Skywalk is a binary-GCD walk of
about 393 ticks. Each tick records a trit, and each payload cell pays for a
data-dependent 256-bit route swap. This commit replaces both walks with
**Leapfrog**, a new walk in `src/point_add/leapfrog.rs`.

**What one tick does.** Two rails alternate roles on a fixed schedule: the
target is rail `t mod 2`. Each tick performs:

1. two forced add-halves;
2. one choice add-halve, picking the "deep" candidate when it is allowed;
3. a barrel that strips up to 3 more trailing zeros.

So each tick removes 3 to 6 low bits from the target, and records a 5-qubit
letter.

**Why it is cheaper.** The roles are fixed when the circuit is built, so no
route swap is needed. The payload follows each tick with three replay cells
and one controlled multiply by 2^−e. 139 ticks are enough.

**The trade.**

- Payload work falls from about 393 cells plus 393 route swaps per pass to
  139 × 4 operations. Average Toffoli falls 15%.
- The raw tape (139 × 5 = 695 qubits, no codec) is longer than Skywalk's
  packed trits, so the peak rises 6%.
- The score falls 9.8%, from 1.108 billion to 999.6 million.

The full mechanism, with the seed, endpoint, reorder and envelope fit, is in
[leapfrog](../concepts/leapfrog.md). This note lists what the commit changes
and where.

## What changed and why it is cheaper

### New file `src/point_add/leapfrog.rs` (4,147 lines, copied)

Note: the module's own header comment is out of date. It describes three forced ping-pong steps, a six-qubit letter (s0, s1, s2, s3, k1, k2) and an `R[0] = d` seed. The shipped recipe (`install_recipe()`) uses two forced steps, a five-qubit letter (s0, s1, s3, k1, k2), and `LF_SEED=half`. Trust the recipe and the code paths it enables, not the header.

- **Entry points.**
  - `install_recipe()` sets the Leapfrog knobs on top of the Skywalk recipe.
  - `divide_seamed` and `multiply_seamed` are the two field operations, with
    the coordinate ops fused into their seeds.
  - `enabled()` returns true when `LEAPFROG=1`.
- **The recipe** (`install_recipe`):

  | knob | value | role |
  | --- | --- | --- |
  | `LEAPFROG_M` | 2 | two forced add-halves per tick (code default 3) |
  | `LF_FAST`, `LF_SEED=half` | 1, half | fast rail ops; seed R0 = d or d − p, R1 = (R0 ± p)/2, payload (y, y/2) |
  | `LF_W1`, `LF_W1K` | 1, default 24 | equal-sign e = 1 choice decided by a 24-bit window compare of \|T\| > 4\|B\|, anchored per tick (`anch_w1.txt`) |
  | `LF_PEEL` | 1 | 139-tick envelope `env_w1_peel139.txt` and per-step widths `env_w1_peel139_steps.txt` |
  | `LF_TRIM`, `LF_SIGNWIRE`, `LF_EARLY` | 1 | rails held at already-implied widths, or without their constant bit-0 wire, so cells get the freed wires |
  | `LF_MERGED`, `LF_MERGED_LATE`, `LF_MERGED_LATE_WIN` | 1, 1, 58 | third add-halve and the payload barrel run as one merged op; late fold window 58 |
  | `LF_REORDER` | 76 | ticks 0–75 of the payload-fused passes run as a rails-only pass plus a payload-only pass over the taped letters (comment: "−5.9k T") |
  | `LF_TIE_SEED`, `LF_TIE_FROM` | 1, 999 | tie-safe cell mode off. Leapfrog rail steps are always odd, so a cell target is never 0 |
  | `LF_SEAMS` | 1 | `coord_x_sub`, `coord_add3x` and `coord_rsub_final` fused into seed and unseed |
  | `LF_CELL_FOLD_MIN`, `LF_CMP_SHIFT` | 56, `2,3` | cell fold window floored at 56; chunk and flag compares widened by 2 and 3 bits |
  | `HEO_PIN_PP_WALK_MAX_QUBITS` | 1243 | walk cap (the doc comment above still says 1265) |
  | `NATIVE_SFUSE_B` | 1 | the square's B fold stays plain |

  It also removes `BACK_SEAM_FUSE`, Skywalk's back-seam fusion.
- **The tick** (`fwd_tick_fast` / `rev_tick_fast`).
  - Forced signs come from `pp_sign_into1` (2 CX).
  - The choice letter s3 and the barrel letters k1 and k2 come from
    `fast_choice`.
  - `lin_rail_barrel` shifts the rail; `cmod_barrel` / `rot4` shift the
    payload.
  - The payload cells are ping-pong's `add_halve` / `double_add`, reached
    through `pingpong::heo_hooks`, at the proxy round of the rail width
    (`proxy_fold`).
  - On the reverse tick, the forced letters are recomputed, and s3, k1 and
    k2 are erased by measurement (`fast_choice_erase`, `fast_k_erase`).
    See [measurement-uncompute](../concepts/measurement-uncompute.md).
- **The legs.**
  - `divide_dbg`: rails-only ticks 0–75, then P1 = y/2, then a payload-only
    pass over ticks 0–75, then fused ticks 76–138. Next comes the endpoint
    (negate P1 on s0 ⊕ s1, clear it by CX, negate P0 on s0). Last, a
    rails-only walk-back and the unseed.
  - `multiply`: rails-only forward, the reversed endpoint, the fused
    walk-back for ticks 138 to 76, a payload-only pass for 75 to 0. Then
    P1 is doubled to equal P0 and cleared by CX, and the rails-only reverse
    for 75 to 0 runs.
  - That is 4 rail traversals and 2 payload passes per point addition.

### Edits to existing files (the patch below)

- **`mod.rs`**
  - Declares `mod leapfrog;` and makes `build_point_add` `pub(crate)`.
  - `build()` calls `leapfrog::install_recipe()` after the Skywalk recipe
    and `EXACT_PAIR_CARRY` (`const LEAPFROG_SUBMISSION: bool = true`).
  - `build_point_add()` gains a Leapfrog branch, which runs these phases in
    order: `coord_y_sub`, `divide` (`divide_seamed`), `square`, `multiply`
    (`multiply_seamed`), `coord_y_sub_final`. Without seams it would also
    run `coord_x_sub`, `coord_add3x` and `coord_rsub_final`.
  - Skywalk's SAT rewrite table is skipped when Leapfrog is on
    (`if !leapfrog::enabled()`), because its rows are keyed to the Skywalk
    op stream.
  - `TAIL_NONCE` goes from 281309007763416 to 10002555178.
- **`pingpong.rs`**
  - `heo_tie()` is replaced at the cells' compare sites by `tie_borrow()`,
    which returns `None` when `LF_TIE_SEED=1`.
  - The route bypasses use `tie_route_ok(bit)`. `LF_TIE_ALLOW` /
    `LF_TIE_ROUTES` are unset, so this is the same as `heo_tie().is_none()`.
  - `heo_hooks` gains three helpers for the merged op: `flag_erase`, the
    cell's own flag-compare erase; `add_consume_exact`, a chunked add with
    an exact top-ripple overflow erase; and `with_bridge`. It also gains
    `split_compare_width`.
- **`classical.rs`**: `add3x_operand`, `plus1_operand` and `release_operand`,
  the classical operands for the seams.
- **`builder.rs`**: `expected_total()`, used by Leapfrog's optional profiler
  (`LF_PROF2`).

`heo.rs`, `heo_carry.rs` and the Skywalk data stay compiled but are not
called. The Skywalk recipe still configures the shared replay cells, the
coordinate ops and the square. Their compare and fold settings are
therefore 9db31da's (for example `HEO_FIT_K` 19, `ERASE_COMPARE` 20), as
modified by `LF_CELL_FOLD_MIN` and `LF_CMP_SHIFT`.

## Why it is still correct, and what it risks

- **Exact parts.**
  - Every rail step.
  - The letters, which are a deterministic function of the pre-step state.
    A wrong W1 window verdict only picks the other valid step.
  - The barrel identity.
  - The measured letter erasure.
  - The merged op's exact overflow erase, where it fits.
- **Probabilistic parts.**
  1. **Depth.** A walk that has not parked after 139 ticks gives a wrong
     result.
  2. **Envelope.** A walk wider than its per-tick width leaves garbage.
     Together with depth, this shows up as **classical** or **ancilla**
     failures.
  3. **Inherited payload-cell windows.** These are the chunk and flag
     compares (**phase**) and the fold windows and the retained-prebias
     32-bit low cut (**classical**). The recipe widens the compares and
     floors the fold.
  4. **The merged op's and barrel's fold windows.**
- **λ.** The author measured 14.4 ± 0.4 over 96 nonces, below the 19.5 limit
  inherited from the Skywalk line. By the author's account about 12.8 of it
  is the walk's envelope tail plus no-park, predicted by a classical screen.
  The rest is payload windows.
- The shipped nonce `10002555178` draws a clean island: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit replaces the walk that implements modular division and
multiplication with a different algorithm, keeping the shell, square and
cells. That is inversion/division algorithm swap, like ping-pong's arrival
in [`897dda2`](897dda2.md) and Skywalk's in [`8ee337c`](8ee337c.md). Like
those, it trades qubits for Toffoli.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9db31da -- src/point_add`.
   - The submission note's base is "the GCD Skywalk line (1172q × 945k)",
     which is jackylee0424's `9db31da` (1172 × 945,335). The tree confirms
     it: the diff touches only the Leapfrog files and the four files that
     hook them in. Every other file equals `9db31da`.
   - **Not the git parent.** That is dysnasia's `0c373cd` (Q1170).
     Diffing against it (9,776 lines in 43 files) would wrongly show this
     commit reverting the whole q71/q70 line: the pair-carry twins, need
     tables, head trim, re-fitted cell tables, rewrite tables and recipe
     values.
   - `git diff --ignore-cr-at-eol 9db31da 86221ad -- src/point_add` is
     6,736 lines in 19 files.
2. **Copy the new walk from the commit:**
   `git checkout 86221ad -- src/point_add/leapfrog.rs src/point_add/leapfrog_data`.
   That is the 4,147-line walk and its 14 data files described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `builder.rs`, `classical.rs`, `mod.rs` and
   `pingpong.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol 86221ad -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs both recipes, so `LF_*`,
   `HEO_*`, `GO_*`, `PP_*` and `SUB4_*` overrides have no effect. Do not set
   them anyway. Expect:
   - 1243 qubits
   - 804,160 average Toffoli (804,159.97 before rounding, by the submission
     note)
   - score 999,570,880
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `10002555178` and an identical op
stream.

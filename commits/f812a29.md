## Summary

Three exact savings and one error repackage, all at 1251 qubits.

- **Square carry-in spread (about −1,676 Toffoli).** Each triangular leaf
  square used a separate ripple add to put the diagonal bits `x_j·2^(2j+1)`
  into the product. This commit feeds each diagonal bit in as the carry-in of
  its own row add, which costs no Toffoli. The separate add is gone.
- **Prebiased doubling (about −730 Toffoli).** In each multiply replay round,
  the main add no longer computes the carry out of bit 0. That carry is merged
  into the fold's own bit-1 carry, using the one AND gate the fold already had.
- **Known tops on odd Karatsuba nodes (about −7 Toffoli).** One more
  structurally zero top bit is cleaned by measurement instead of a CCX.
- **Fold repackage (about −330 Toffoli by subtraction).** The early +1 fold
  window is removed, the 94 "full finite" retained folds go back to their
  32-bit low cut, and 3 window bits are added at late retained sites. The
  author measured that the package lowered λ.

The Toffoli figures are the author's. The repackage figure is the total minus
the three exact savings.

## What changed and why it saves Toffoli

### 1. `SQ_CIN_SPREAD=1`: diagonal spread through the row carry-ins (`square.rs`)

Background: [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).
A leaf square `tri_square(x, product)` of `m` bits builds `x²` from rows.

- **Old leaf** (`cc7f10e`):
  - Row `i` is `row_addsub`: `product[2i+1..i+m+1] += (2x_i − 1)·x[i+1..]`.
    It is a complement-frame add (subtract when `x_i = 0`), done with `X` on
    `x_i` and CX from `x_i` onto the accumulator.
  - After the rows, `tri_corr` adds `diag_spread` (the diagonal terms
    `Σ x_j·2^(2j+1)`) and `diag_correction` (the constant that fixes up the
    subtract frames).
  - `SQ_DIAG_PRELOAD` already copied the low half of the diagonal in for free.
    The upper half still cost a full ripple add of about `2m − 2·(m/2) − 1`
    positions, that is about 31 Toffoli for a 32-bit leaf. It runs once
    forward and once in the inverse.
- **New leaf** (`tri_square_cin`, `row_addsub_cin`):
  - The complement frame is driven by `X` on the accumulator plus CX from
    `x_i`, so the wire `x_i` itself stays intact.
  - `x_i` is then passed as the ripple's **carry-in**. When `x_i = 1` the row
    adds `v + 1`. When `x_i = 0` it subtracts `v` with carry-in 0. In both
    cases the result is `(2x_i − 1)(v + x_i) = (2x_i − 1)·v + x_i`, because
    `x_i² = x_i`. At offset `2i+1` that extra `x_i` is exactly the diagonal bit
    `x_i·2^(2i+1)`.
  - The last diagonal bit `x_{m−1}·2^(2m−1)` lands on a wire that is still zero,
    so it is one CX.
  - There is no preload and no spread add. Only `diag_correction` remains.
    `diag_correction_known_top` is used in the inverse, because the result's
    top bit is known to be zero there, so its terminal CCX becomes a
    measurement (see [measurement-uncompute](../concepts/measurement-uncompute.md)).
- **Supporting edits in `modular.rs`:**
  - `ripple_add_proved` is made `pub(crate)`.
  - The `known_output` path now accepts a carry-in. Its pre-pass only reads
    `carry[j−1] = addend[j] ⊕ acc[j] ⊕ sum[j]` for `j ≥ 1`.
  - A new row-0 case: when the caller proves `acc[0] = NOT carry_in`,
    `MAJ(addend0, acc0, carry_in) = addend0`, so the first carry is a CX copy.
  - These keep the earlier row-0 shortcuts working on the carry-in rows:
    `SQ_ROW0_CARRY` (forward) and `SQ_ROW0_INVERSE_CARRIES` (inverse, with the
    known outputs "x0 on the low k bits, 1 on top").
- **Size:** with policy 7 there are 27 leaves of 32–34 bits, each run forward
  and inverse. At about 31 Toffoli per spread add that gives the author's
  −1,676.

### 2. `PP_PREBIAS_DOUBLE=1`, `PP_PREBIAS_DOUBLE_FALLBACK=1`: bit 0 leaves the multiply replay's add (`pingpong.rs`, `joint_lowfold.rs`)

Background: [pingpong-division](../concepts/pingpong-division.md) and
[modular-fold](../concepts/modular-fold.md).

- **Where.** In the multiply replay cell `replay_double_add`, the target is
  doubled. The doubled bit 0 is 0, so after the sign frame `target[0] = s`
  (the tape sign). The main add `target += source` then makes bit 0
  `z0 = s ⊕ v0` with carry `s ∧ v0`, where `v0 = source[0]`.
- **What changes.** With the flag, bit 0 is done by one CX (`cx(source[0], target[0])`).
  The ripple starts at bit 1 with no carry-in:
  - on the retained route, `joint_lowfold::try_replay` ripples from `at = 1`;
  - on the fallback route, `replay_double_add` calls `chunked_add(&source[1..], &target[1..])`.
  So the carry `s ∧ v0` is "owed".
- **Where the owed carry goes.** The fold in `fold_double_joint` already
  computes its own carry into bit 1, `first = z0 ∧ (d ⊕ o)`. Here `d` is the
  doubling's out bit and `o` the add's overflow. The two carries are mutually
  exclusive: if `s ∧ v0 = 1` then `z0 = 0`. Their sum is therefore
  `MAJ(s, v0, d ⊕ o)`. With `pre`, `first` is computed as that majority: XOR
  `o` into `s` and `v0`, one `and_clean`, XOR `o` into the result, then undo
  the XORs. It is the same single AND as before. The main add's bit-0 CCX is
  simply gone.
- **Boundary compare.** When the first chunk's boundary compare spans the
  whole chunk, it now starts at bit 1 (`from = 1`), because the add no longer
  covers bit 0.
- **Size:** about one Toffoli per multiply replay round, about −730 in total.

### 3. `SQ_ODD_NODE_TOPS=1`: known top on odd Karatsuba nodes (`square.rs`)

- In `tri_square_k2r_inner` and `_inv`, a node with `lo = hi − 1` (odd `m`)
  has `t² − a² = b(2a + b) < 2^(2hi+1)`. So the top bit of the
  `2(hi+1)`-bit cross word is zero right after `cross −= a²`, and again after
  the inverse re-adds `b²`.
- Those two subtracts and adds now use `addsub_wide_known_top`, which replaces
  the terminal CCX with a measurement plus phase repair.
- About 4 odd nodes, forward and inverse: about −7 Toffoli.

### 4. Fold repackage (`mod.rs` table, `pingpong.rs`)

Background: [modular-fold](../concepts/modular-fold.md). See
[`cc7f10e`](cc7f10e.md) items A5–A7 for the retained routes.

- **`PP_FOLD_WIDEN`: 242 → 0.** Rounds 0–241 lose their +1 fold-window bit,
  in every route and in both traversals. The next commit's note prices the
  reverse step, 0 → 242, at +482 Toffoli.
- **`PP_RETAIN_EXACT_DIV` and `PP_RETAIN_EXACT_MUL`: 1 → 0.**
  - At the retained sites where `cc7f10e` released up to 4 extra prefix wires
    to fit the full finite fold (83 divide and 11 multiply sites, by its
    note), the code now uses the explicit 32-bit low cut instead.
  - The low cut is `split_half` on the divide and the `GUARD` branch of
    `fold_double_joint` on the multiply. It drops the carry from bit 31 of the
    low constant part into bit 32.
  - This saves the extra prefix bits and their exact boundary compare.
- **`PP_RETAIN_LATE_WIDEN` = 3, new knob.** New `retained_window(fold_window, round)`
  adds 3 bits to the fold window passed to `retained_prebias::try_replay` and
  `joint_lowfold::try_replay` when `policy_width(round) < 32` (rounds
  632–697). The plain route is unchanged.
- **Author's rationale:** the exact restoration cost about 743 Toffoli per unit
  of λ. The late widening buys λ back at about 115 Toffoli per unit. The early
  +1 run was no longer needed.
- **Tail nonce:** `TAIL_NONCE` 7978492 → 9342055114.

## Why it is still correct, and what it risks

- **Carry-in spread: exact.** It is an algebraic identity on every input, and
  the inverse mirrors the forward row by row.
- **Odd-node tops: exact.** The zero top bit is a proved bound.
- **Prebiased doubling: exact in practice.** The owed bit-0 carry now
  propagates only inside the fold window, instead of up the full main add. The
  result differs only when that carry would have rippled through every window
  bit (about 2^-50). That is far rarer than the window's own dropped carry.
  The author counts it as exact.
- **Repackage: probabilistic.**
  - Removing the early widening and the exact restoration adds
    **classical** error: dropped fold carries, and the low-cut carry into
    bit 32.
  - The late widening removes some.
  - Measured λ: 16.71 ± 0.36 over 128 nonces, against 17.34 ± 0.50 for
    `cc7f10e` (64 nonces). That is under the [`cc7f10e`](cc7f10e.md)
    contract's limit of 18.
- The shipped nonce draws a clean set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
- **The author's submission note misattributes some code.** It credits this
  commit with `direct_add_hold`, `held` carries and the `joint_lowfold::plan`
  F-cost change. Those are not in this diff. They arrive in the next commit,
  [`b788efc`](b788efc.md).

## Classification rationale

The two large savings merge a separate arithmetic step into an existing one.
The diagonal spread add rides in on the rows' carry-ins, and the bit-0 carry
rides in the fold's existing AND. That is gate/op fusion. The repackage is a
smaller fold/carry-truncation retune, made to stay inside the λ contract.

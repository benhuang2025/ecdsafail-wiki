## Summary

`build()` cleans the finished op stream with a chain of exact post-passes.
The chain ends with the witness pass, which turns some CCX gates into CX
gates. This commit adds one more pass after it: a second run of the product
simplifier, `truth_simplify::simplify_products`. The witness rewrite makes
some wire values simpler, so the second run can prove a few more CCX gates
redundant. The circuit's function is unchanged on every input.

The gain is tiny: 1 average Toffoli, at the same 1250 qubits. The tail nonce
was re-hunted because the op stream changed. Some of that 1 Toffoli may come
from the new test draw rather than from the pass (see below).

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `build()`. The post-pass order was:
  1. the `PP_SIMPLIFY` chain `product,affine,quadratic,truth`;
  2. `interned_witness::witnesses(ops)`;
  3. the 96-X nonce tail.

  This commit inserts `ops = truth_simplify::simplify_products(ops);` between
  steps 2 and 3. The code comment calls it an "isolated exact-cost screen
  after the existing witness rewrite".
- What the two passes do:
  - `interned_witness::witnesses` tracks every wire as an XOR of immutable
    atoms. When a CCX's control product equals the current value of another
    wire (a "witness"), it replaces `CCX(a, b → t)` with `CX(w → t)`.
  - `simplify_products` (`truth_simplify.rs` plus `product_simplify.rs`)
    re-derives affine, quadratic and six-atom truth-table facts from the
    stream. It drops a CCX whose product is provably 0, and turns a CCX into
    a CX (or X plus CX) when its product equals a live wire or its
    complement.
- Why a second run finds more: before the witness pass, the target of each
  rewritten CCX held an opaque product atom. After it, that target holds a
  plain XOR of existing values. Later gates controlled by that wire can now be
  proved constant, equal to another wire, or zero. The first run of the chain
  happened before these rewrites, so it could not see those facts.
- The tail nonce, `TAIL_NONCE` in `env_raw()`, goes from 141341059326522 to
  280927477331701.

Rest of the raw diff: `mod.rs` was also converted from LF to CRLF line
endings, so a plain `git diff` shows the whole file changed. With
`--ignore-cr-at-eol`, the diff is 4 lines.

## Why it is still correct, and what it risks

The new pass is exact. It removes or weakens a CCX only when it has proved
the gate's product from the stream itself, so the circuit computes the same
thing on every input. It adds no hard inputs. Lambda stays at the base's
level.

The nonce still had to be re-hunted, because any change to the op stream
re-rolls the Fiat–Shamir test set. The shipped nonce draws a clean set: 0
classical, 0 phase and 0 ancilla failures. If the pass were wrong somewhere,
it would show up as a classical mismatch, or as a phase failure if the gate
sat inside a phase repair.

A caution about the size of the gain: the score uses the *average executed*
Toffoli over the 9,024 shots, and many Toffoli run only under a classical
condition. A new nonce alone can move the average by a few Toffoli (see
[`a9af194`](a9af194.md)). So the −1 is the combined effect of the pass and
the new draw, and the two cannot be separated from the leaderboard numbers.
See [scoring-and-validation](../concepts/scoring-and-validation.md).

## Classification rationale

The pass deletes or simplifies CCX gates that are provably redundant, as a
post-pass over the finished stream. That is dead-gate removal of the exact
kind. A nonce-only reroll was the runner-up, given how small the gain is, but
the op stream really does change through the new pass.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 03d9ecd -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 03d9ecd 17bc487 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 17bc487 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. In this tree
   `env_raw()` is a fixed table and does not read the process environment, so
   `SUB4_*` or `PP_*` variables have no effect. Leave them unset anyway.
   Expect:
   - 1250 qubits
   - 889,046 average Toffoli (rounded)
   - score 1,111,307,500
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `280927477331701` and an identical op
stream. Any other change needs a new nonce hunt.

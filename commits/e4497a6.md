## Summary

Each step of the dialog binary GCD decides whether to swap `u` and `v` by
comparing them. That comparison only looks at the top `DIALOG_GCD_COMPARE_BITS`
bits of the step's active window. This commit lowers the cap from 48 to 47.
Each comparator bit costs one Toffoli, and the cap binds on 219 of the 259 GCD
steps in each of four transcript passes, so the change saves 4 × 219 = 876
average Toffoli. Qubits stay at 1320. The tail nonce was re-hunted because the
op stream changed.

## What changed and why it saves Toffoli

Background (see [dialog-gcd-early](../concepts/dialog-gcd-early.md) for this early route;
see [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) for the later lineage).
In this 1320-qubit route everything lives in `src/point_add/mod.rs`. The
inversion is Schrottenloher's dialog binary GCD, run on two factors per point
add: `dx = Px − Qx` and `c = Qx − Rx`. For each factor a forward transcript
pass runs `DIALOG_GCD_ACTIVE_ITERATIONS = 259` steps on `(u, v)`, the apply
replays the recorded decisions on `(x, y)`, and a reverse pass erases the
transcript. With `DIALOG_GCD_K2=1` each step can strip up to two factors of 2.
Each step works only on the low `active_width(step)` bits, where
`dialog_gcd_tobitvector_active_width` = `256 − step × WIDTH_SLOPE + WIDTH_MARGIN`,
rounded up to an even number (here slope 1.005, margin 10).

Both changes are in `configure_ecdsafail_submission_route()`:

1. **`DIALOG_GCD_COMPARE_BITS`: 48 → 47.**
   - In each forward step (`..._tobitvector_branch_bits` phase) the circuit
     writes `b0 = v[0]` and then `b0_and_b1 = b0 AND (u > v)` with
     `dialog_gcd_ccx_cmp_gt_truncated_into_width_hosted`. The comparison uses
     only `u[aw − k .. aw]` and `v[aw − k .. aw]`, the top `k` bits of the
     active window, where `k = dialog_gcd_compare_bits_for_step(step, aw)`.
   - With `DIALOG_GCD_PA9024_COMPARE_SCHEDULE=0`, `k = min(COMPARE_BITS, aw)`.
   - The comparator (`ccx_cmp_lt_into_fast_borrowed_carries`) computes one
     carry per bit with a Toffoli and erases the carries by measurement
     (`hmr` + `cz_if`), so it costs about one Toffoli per compared bit. See
     [measurement-uncompute](../concepts/measurement-uncompute.md).
   - The reverse pass recomputes the same comparator to erase `b0_and_b1`.
   - With slope 1.005 and margin 10, `aw ≥ 48` on 219 of the 259 steps, so the
     cap removes one bit on exactly those steps. Forward and reverse, for two
     factors, is 4 passes: 4 × 219 = 876, the measured saving.
2. **`DIALOG_TAIL_NONCE`: 188481450290415 → 148111066097918.** The nonce sets
   which of tx[0] or tx[1] each of 48 identity `X;X` pairs at the end of the
   op stream targets. It reseeds the 9,024 Fiat–Shamir test inputs and does not
   change the arithmetic. See
   [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

The truncated comparison is probabilistic. When `u` and `v` agree on all of
the top 47 bits of the active window but differ below, the comparator reports
`u ≤ v` even if `u > v`. The step then skips the swap it needed, the subtract
underflows, and the transcript no longer converges. That shows up as a
classical failure, and usually as phase or ancilla garbage as well, because the
reverse pass no longer mirrors the forward one. Because `aw` sits about 10 bits
above the real bit length, the comparison effectively sees about 37 significant
bits, so mis-decisions are rare, but one bit less doubles their rate and raises
λ. The analysis filter added later the same day in `ec0fa98`
(`dialog_gcd_classical_filter.rs`) can flag this as a `ComparatorMismatch`
hard input, but only with `DIALOG_GCD_FILTER_STRICT_COMPARE=1`; by default it
follows the truncated decision and leaves such cases to full validation.

The new nonce draws a clean set. The submission note reports 0 classical,
0 phase and 0 ancilla failures over all 9,024 shots.

## Classification rationale

The only circuit change narrows a comparator, so comparator/width truncation
fits. The nonce change comes with every circuit change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout db60686 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol db60686 e4497a6 -- src/point_add` is 4 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol e4497a6 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because `set_default_env`
   keeps any value already in the environment. Expect:
   - 1320 qubits
   - 1,542,945 average Toffoli (rounded)
   - score 2,036,687,400
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=148111066097918` and an
identical op stream. Any other change needs a new nonce hunt.

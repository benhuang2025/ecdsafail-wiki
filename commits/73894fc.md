## Summary

Each divide-side replay cell leaves an overflow flag. Where the cell cannot
erase the flag exactly, it measures the flag out and repairs the phase with a
truncated compare of the top `k` bits of the two replay registers. The base
added one extra bit to `k` on every divide round whose walk register is at
least 38 bits wide. This commit raises that threshold to 696. Walk widths
never exceed 259, so the extra bit is never added.

Those flag compares become one bit narrower, which saves about 0.5 executed
Toffoli each. The total is −17 Toffoli at the same 1249 qubits. The cost is a
roughly doubled error rate at those compares, so the nonce was re-hunted.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `env_raw()`: `PP_FLAG_WIDEN_DIV` goes from `"38"` to
  `"696"`.
- What the knob means. It is read by `flag_widen_div()` (`pingpong.rs`) and
  used in exactly one formula, at every divide-side flag site:

  ```
  k = flag_compare(round) + [policy_width(round) >= PP_FLAG_WIDEN_DIV]
  ```

  - `policy_width(round)` is the walk register's width in that round, from
    `PP_WIDTH_SCHEDULE`, between 259 and 8 bits. It is not a round index.
  - `flag_compare(round)` is `PP_REPLAY_FLAG_COMPARE` (20) plus the
    `PP_FLAG_SHAPE` band offset (`38:0,25:-1,0:-3`).
  - With threshold 38, the 616 divide rounds whose width is at least 38
    (rounds 0–615) got `k = 21` instead of 20, before the seeding adjustment.
  - With 696, no width qualifies, and `k = 20` there. Any value above 259
    would have the same effect. The multiply side never uses this knob.
- The sites that use it, all with `multiply = false`:
  - `replay_add_halve_impl` (both the `PP_REUSE_DIV_PARITY` path and the
    plain path);
  - `joint_prebias::joint_prebias_div`;
  - the divide branch of the `joint_lowfold` planner;
  - the `retained_prebias` planner.
- How the compare is used. At the two cell sites, the flag is measured out
  with `hmr`. Then `erase_with_compare` runs `cmp_lt_phase` on
  `target[N−k..]` and `source[N−k..]` under `push_condition` on the
  measurement bit. So the compare executes on only about half the shots. Each
  bit is one Toffoli when it runs. See
  [measurement-uncompute](../concepts/measurement-uncompute.md) and
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- Why the saving is only 17 Toffoli and not about 300:
  - `replay_add_halve_impl` tries `retained_prebias::try_replay` first. Cells
    that take that path erase the overflow exactly from the live top-bit
    frame (`erase_overflow_from_frame`, `hmr` plus CZ/Z, no compare).
  - There, the widened `k` only enters the planner's estimate
    `saving = (fk − 1)/2 − …`.
  - So only the divide cells that fall back to `joint_prebias` or the plain
    cell actually ran the widened compare. The −17 is consistent with about
    34 such compare bits at 0.5 executed Toffoli each.
  - This count is inferred from the measured delta, not traced.
  - A lower `fk` also makes the retained plan look 0.5 Toffoli less
    profitable, which could switch a marginal round to the fallback path.
- **Tail nonce** `TAIL_NONCE`: 280927574775975 → 91400000113896.

## Why it is still correct, and what it risks

The flag compare is approximate. It gives the wrong phase repair when the two
registers tie on all `k` compared bits, with probability about 2^-k per call.
Removing the extra bit roughly doubles that rate on the divide cells that
still run this compare. Lambda goes up, and a failure would show up as a
phase error. The value outputs stay right.

The submission is valid because the re-hunted nonce `91400000113896` draws a
clean set: 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change makes one family of truncated compares one bit
narrower. That is comparator/width truncation. The same lever was applied
again later on the 1250-qubit line in [`718a807`](718a807.md).

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 454ff5a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 454ff5a 73894fc -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 73894fc -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. In this tree
   `env_raw()` is a fixed table and does not read the process environment, so
   `SUB4_*` or `PP_*` variables have no effect. Leave them unset anyway.
   Expect:
   - 1249 qubits
   - 889,604 average Toffoli (rounded)
   - score 1,111,115,396
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `91400000113896` and an identical op
stream. Any other change needs a new nonce hunt.

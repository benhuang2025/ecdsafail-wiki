## Summary

The GCD apply pass reduces mod p in two places, and both add the constant
c = 2^32 + 977 with a ripple carry that stops a fixed number of bits above
bit 32:

- the doubling (and halving) of `y`, with window `KAL_DOUBLE_CARRY_TRUNC_W`;
- the fold after each modular add (and subtract), with window
  `KAL_FOLD_CARRY_TRUNC_W`.

This commit cuts both windows from 23 to 22 bits. Each removed position is one
Toffoli per call. There are about 1,040 doubling or halving calls and 520 folds
per shot, so the saving is about 1,560 Toffoli; the measured figure is 1,562.
Qubits are unchanged.

The author also moved a second reroll knob, `DIALOG_POST_SUB_REROLL`, together
with the tail nonce to find a clean island. The commit is built on `06b07ee`,
not on the frontier `94e9418`, so it keeps slope 1005. Its gain over the
frontier is only 146 Toffoli.

## What changed and why it saves Toffoli

**Background.** The circuit is the dialog-GCD route (`emit_dialog_gcd_raw_pa`
in `src/point_add/mod.rs`). Two calls each run a reversible binary GCD: the
quotient dy/dx and the product with c = ox − Rx. Each call's apply pass does,
per GCD step, `y = 2y mod p` (plus a controlled second doubling for K=2), then
`y = y ± b0·x mod p` (which ends in a fold), then a conditional swap.
[fa5347c](fa5347c.md) explains the doubling window, and [af0f90a](af0f90a.md)
explains the fold window. Both go through `cadd_nbit_const_direct_trunc_fast`
or `csub_nbit_const_direct_trunc_fast`, which compute carries only at positions
`0 ..= 32 + w`. Each position above bit 32 costs one CCX.

**The changes in `configure_ecdsafail_submission_route()`:**

- `KAL_DOUBLE_CARRY_TRUNC_W`: 23 → 22. There are two calls per apply step (the
  plain double or halve and the K=2 controlled one), over 260 steps, in 2 GCD
  calls: 1,040 calls, each one Toffoli cheaper.
- `KAL_FOLD_CARRY_TRUNC_W`: 23 → 22. There is one fold per apply step, over
  260 steps, in 2 GCD calls: 520 folds, each one Toffoli cheaper.
- `DIALOG_POST_SUB_REROLL`: 503292 → 631921.
  - `build_builder()` emits this many `X;X` pairs on `tx[1]` right after the
    two coordinate subtractions, under phase `dialog_post_sub_reroll`.
  - `X;X` is the identity and costs no Toffoli, no counted Clifford and no
    qubit. So this only changes the op stream's hash, and with it the
    Fiat–Shamir test set and measurement outcomes. It adds 257,258 ops.
  - It is a second, variable-length reroll knob, used here together with the
    fixed-length 48-bit tail nonce.
- `DIALOG_TAIL_NONCE`: 108 → 1476.

1,040 + 520 = 1,560, and the measured drop is 1,562.

## Why it is still correct, and what it risks

Both windows are probabilistic. A call is wrong only when the carry from adding
c has to run through all 22 positions above bit 32, about 2^-23 per call where
the reduction fires. On a failure `y` keeps wrong high bits, which is a
classical failure. The fold comment calls its lever "value-exact on the
reachable support", which is too strong.

With about 780 firing calls per shot, the two windows together add roughly
0.8 expected failing shots per draw at width 22, about double the figure at
23. The author searched both reroll knobs together with a CPU harness on a
rented machine to find a clean combination. It draws a clean set: 0
classical, 0 phase and 0 ancilla failures over all 9,024 shots.

## Classification rationale

The census files this under comparator/width truncation. Both knobs narrow the
carry window of a constant add inside the modular reduction, so "fold/carry
truncation" fits better, as for [`438ef00`](438ef00.md). The reroll knob is not
a circuit change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 06b07ee -- src/point_add`.
   - The git parent is `94e9418`, newjordan's own slope-1008 tree. Against it,
     the diff also sets `DIALOG_GCD_WIDTH_SLOPE_X1000` back from 1008 to 1005.
     This tree was not built on that commit.
   - Against `06b07ee`, `git diff --ignore-cr-at-eol 06b07ee a92d098 -- src/point_add`
     is 8 changed lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a92d098 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset. Expect:
   - 1320 qubits
   - 1,563,855 average Toffoli (rounded)
   - score 2,064,288,600
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_POST_SUB_REROLL = 631921`, the nonce
`1476` and an identical op stream. Any other change needs a new hunt.

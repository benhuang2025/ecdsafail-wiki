## Summary

This is one more step of the budget trade in [`0b82781`](0b82781.md). Both
owners of the qubit peak are lowered by one wire. The replay's
`SUB4_PP_PEAK` goes 1276 → 1275, with the interleave checkpoints moved to
fit, and the square's `SQUARE_LADDER` goes 246 → 245. The chunked adds then
need a few more chunk boundaries, each with a measured erase and a truncated
repair compare.

To pay part of that back, the multiply traversal runs one round fewer:
`rounds() − 7 = 693` instead of 694. The net is −1 qubit for +472 Toffoli,
below the break-even of about 738 Toffoli per qubit at this size.

## What changed and why it saves qubits

All in `src/point_add/pingpong_div.rs` unless noted.

1. **Replay budget and checkpoints (`plan()`)**:

   | knob | base | new |
   |---|---|---|
   | `SUB4_PP_R1` | 292 | 289 |
   | `SUB4_PP_R2` | 608 | 598 |
   | `SUB4_PP_PEAK` | 1276 | 1275 |

   - Each replay cell's chunked add gets a live-ladder budget of
     `allowance = peak − (tape_len + 2·N + 2·walk_width)` minus the cell's
     extra wires (`pick_chunks` / `ladder_for_allowance`; the 3..8 chunk-count
     search `chunks_for_allowance` is only the `SUB4_PP_LEGACY_LADDER` mode).
     One wire less of `peak` pushes some rounds to one more chunk, and so to
     one more boundary repair.
   - The checkpoints decide which rounds are replayed in the early batch
     (below `r1`), which beside their walk round (`r1..=r2`), and which at the
     terminal state (above `r2`). That sets how long the tape and how wide the
     walk registers are when each cell runs. Lowering `r2` from 608 to 598
     moves ten rounds into the terminal batch.
   - See [pingpong-division](../concepts/pingpong-division.md) and
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
2. **Square ladder (`trailmix_ludicrous/square/product_register.rs`)**:
   `SQUARE_LADDER` 246 → 245. The square's wide adds (at least 200 bits) go
   through `add_chunked_measured_budgeted` with this live-ladder budget. The
   square is the other peak owner, so it has to drop with the replay. See
   [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).
3. **Multiply depth (`rounds_for`)**: the default of `SUB4_PP_ROUNDS_MUL`
   goes from `rounds() − 6` to `rounds() − 7`, so 694 → 693 rounds. One
   fewer walk round, replay cell and walk-back round in the multiply
   traversal is worth about 370–380 T in this family of trees (compare
   [`4417b24`](4417b24.md), [`5c23d45`](5c23d45.md)). It also shortens the
   multiply tape by one wire, which helps that traversal fit the lower
   budget.
4. **Tail nonce** (`src/point_add/mod.rs`): `SUB4_PINGPONG_TAIL_NONCE`
   default 21955808 → 23157411.

**Net.** The budget step costs roughly +850 T in extra repairs, the depth
cut gives back roughly −375 T, and the total is +472 T. The break-even for
one qubit is 940,495 / 1275 ≈ 738 T, so the score drops by 338,695.

## Why it is still correct, and what it risks

- **The budget changes are exact as layouts.** Every chunked add still
  computes the same sum.
- **More truncated repairs raise λ a little.** Each extra chunk boundary is
  one more truncated `cmp_lt_phase_conditioned`, which leaves a wrong phase
  when the compared top bits tie.
- **The depth cut is a truncation.** Inputs whose multiply walk needs more
  than 693 rounds give wrong products and dirty walk registers. The
  `rounds_for` comment prices this at about +0.05 λ per round.
- The shipped nonce `23157411` draws a clean test set: 0 classical, 0 phase
  and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The score gain is the qubit, bought by lowering the live-carry budgets of
both peak owners. Budget retunes are filed as ancilla-lifetime / venting. The
depth cut is a compensating iteration/threshold move.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0b82781 -- src/point_add`.
   - `git diff --ignore-cr-at-eol 0b82781 84a93cd -- src/point_add` is 12
     changed lines in 3 files.
   - Do not start from the git parent `d1bb787`, benhuang2025's 1278-qubit
     tree. Against it the diff is 213 lines in 4 files. It would add the
     dead-low helpers that `0b82781` already brought (182 lines in
     `arith/const_arith.rs`). It would also *widen* `SUB4_PP_ENDPOINT_FOLD_WINDOW`
     from 20 to 28, which only undoes `d1bb787`'s own narrowing; this
     commit's line never had it.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 84a93cd -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1275 qubits
   - 940,967 average Toffoli (rounded)
   - score 1,199,732,925
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `23157411` and an identical op
stream. Any other change needs a new nonce hunt.

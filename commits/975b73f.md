## Summary

This is the third step of the same lever, after [`fe29b53`](fe29b53.md) and
[`47f30d4`](47f30d4.md). Each dialog-GCD step decides `u > v` from only the
top few bits of the two registers. This commit lowers the global cap on that
comparison from 58 to 57 bits. The cap binds on 254 of the 399 steps, and the
comparison runs four times per step at one Toffoli per bit, so it saves
4 × 254 = 1,016 Toffoli. Qubits are unchanged. The reroll pair was
re-searched to (6, 12).

It was built on the author's own 1542-qubit tree, in parallel with
fortunexbt's 1541-qubit [`7297f4f`](7297f4f.md), which was accepted first.
Its score is still lower than that commit's, so it became the frontier.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_COMPARE_BITS`: 58 → 57.**
   - The branch bit `b0_and_b1 = b0 AND (u > v)` decides each step's
     conditional swap. `u > v` is computed by
     `dialog_gcd_cmp_gt_truncated_into_width` with `ccx_cmp_lt_into_fast` on
     the top `compare_bits` bits of the active registers, at one Toffoli per
     bit (carries cleared by `hmr` + `cz_if`).
   - `dialog_gcd_compare_bits_for_step` returns
     `min(SCHEDULE[step] + 5, active_width, DIALOG_GCD_COMPARE_BITS)`. With the
     baked 399-entry `DIALOG_GCD_PA9024_COMPARE_SCHEDULE`, margin 5 and
     `DIALOG_GCD_WIDTH_MARGIN=27`, the summed widths go from 19,772 to 19,518
     bits: the cap now binds on steps 53 to 320, 254 bits in all.
   - The comparison runs in the forward and reverse transcript passes of both
     GCD pairs: 4 × 254 = 1,016 Toffoli.
2. **Reroll pair: `DIALOG_REROLL` 14 → 6, `DIALOG_POST_SUB_REROLL` 4 → 12.**
   Identity `X;X` counts that re-draw the 9,024 test inputs without changing
   the circuit (see [`ecbf87b`](ecbf87b.md)).

The comments are updated to match.

## Why it is still correct, and what it risks

The truncated comparison is approximate. When `u` and `v` agree on their top
57 active bits it can give the wrong `u > v`. The step then takes the wrong
branch and the transcript no longer matches the true GCD. That shows as a
classical failure, or as phase or ancilla garbage if the uncompute no longer
mirrors the forward pass. Each bit removed roughly doubles the per-step risk
on the affected steps, so λ keeps growing as the cap falls.

The reroll pair (6, 12) draws a clean set: 9,024 of 9,024 shots pass with
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is dead-gate/self-inverse removal, but no gate is removed
as dead and nothing cancels. The only circuit change is a narrower, approximate
comparator, the same lever as `47f30d4` and `ecbf87b`. Comparator/width
truncation fits the diff. The published label is kept in the header.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 47f30d4 -- src/point_add`.
   - The git parent is `7297f4f` (fortunexbt, 1541 qubits). Diffing against it
     (143 lines) would revert that commit's windowed row-0 half-squares,
     `KARA_FREE_Z1_LOBIT` and its F_CUT 79 back to 78. This commit was built on
     `47f30d4`.
   - `git diff --ignore-cr-at-eol 47f30d4 975b73f -- src/point_add` is 20 lines
     in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 975b73f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1542 qubits
   - 1,680,191 average Toffoli (rounded)
   - score 2,590,854,522
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=6`,
`DIALOG_POST_SUB_REROLL=12` and an identical op stream. Any other change needs
a new reroll search.

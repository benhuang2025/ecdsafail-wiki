## Summary

One constant. The W-TRUNC margin, the slack added on top of the empirical
bit-length envelope that clips the Kaliski width loops, goes from 20 to 10
bits. Every clipped OR chain, comparator and STEP 4 load/subtract loses up to
10 more bit positions, and clipping now starts earlier, at iteration 44. The
result is 41,700 fewer average Toffoli at 2309 qubits. The submission note
calls this an env-only change, but the default in the code changes, so no env
setting is needed to reproduce it.

## What changed and why it saves Toffoli

- `src/point_add/kaliski_state.rs`, `kal_wtrunc_margin()`: the default of
  `KAL_WTRUNC_MARGIN` goes from 20 to 10. The comment now records that
  margins 5 and 12 fail on the 9,024-shot scorer.
- The clipped width is `min(n, 256 − ⌊(it − 27)·2/3⌋ + margin)` for
  `it ≥ 27` (see [`36e8578`](36e8578.md)). With margin 10, clipping starts
  once `⌊(it − 27)·2/3⌋ > 10`, which is at iteration 44 instead of 59. From
  there on each clipped loop is 10 bits narrower than at margin 20.
- The clipped loops cost about one Toffoli per bit:
  - the generic STEP 0 `v_w == 0` OR chain;
  - the STEP 2 `u > v_w` comparator;
  - the STEP 4 `tmp = add_f & u` load and the `v_w −= tmp` subtract;
  - the backward mirrors of all of these.

  Both Kaliski pairs run forward and backward, so the saving is spread over
  about 1,600 iterations per shot.

## Why it is still correct, and what it risks

- **Margin 10 is probabilistic.** The envelope was fitted to 80,000 random
  inputs. The comment in [`36e8578`](36e8578.md) reports that on 300,000 fresh
  inputs the minimum slack in the clipped region equalled the margin. So
  margin 10 leaves about 10 bits above the largest bit length seen. An input
  that exceeds the envelope by more than that loses a live high bit in a
  comparator, subtractor or OR chain. Its inverse is then wrong: a classical
  mismatch, and usually phase garbage from the mismatched backward run.
- **Margin 5 failing** is consistent with a real truncation failure becoming
  likely on 9,024 shots.
- **Margin 12 failing while 10 passes** cannot be a W-TRUNC failure, because a
  wider margin is never less safe on a given input. It is a different op stream,
  so a different hashed draw, which most likely trips another empirical knob
  (the iteration counts, `BULK_PREFIX_SAFE_ITERS` or `R_SMALL_THRESHOLD`).
- There is no tail nonce in this era. The shipped draw is clean: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A truncation margin is narrowed: comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0e32587 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 0e32587 b86e789 -- src/point_add` is
   9 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b86e789 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `POINT_ADD_*` or `BY_*` environment variables set. Expect:
   - 2309 qubits
   - 2,973,304 average Toffoli (rounded)
   - score 6,865,358,936
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era: the test set is a hash of the op stream,
so the score only reproduces with an identical op stream.

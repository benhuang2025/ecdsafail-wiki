## Summary

This is the next step of the author's co-binder cut in [`a8ab75a`](a8ab75a.md).
The two peak owners, the ping-pong replay and the product-register square,
each size their chunked carry ladders against a budget. This commit lowers
the replay budget `SUB4_PP_PEAK` from 1273 to 1271 and `SQUARE_LADDER` from
243 to 242, and re-picks the interleave checkpoints. The measured peak drops
by one, to 1272. The extra chunk boundaries cost Toffoli, and two knobs pay
part of it back: the replay flag compare goes from 21 to 20 bits, and the
multiply walk loses the round that `a8ab75a` had restored (694 → 693 rounds).
Net against `a8ab75a`: one qubit for +459 Toffoli, well under the ~740 a
qubit is worth.

Against the base `8d3517a` the commit is the two steps together: two qubits
for +1,157 Toffoli.

## What changed and why it saves a qubit

All in `src/point_add/pingpong_div.rs` unless noted. Values are given as
base `8d3517a` → `a8ab75a` → this commit.

1. **Peak budgets (the qubit).**
   - `plan()`: `SUB4_PP_PEAK` 1274 → 1273 → 1271, `SUB4_PP_R1`
     286 → 283 → 280, `SUB4_PP_R2` 603 → 589 → 608.
     - The peak is the budget behind
       `allowance = peak − tape_len − 2·N − 2·walk_width`, which every replay
       cell's chunk ladder must fit.
     - It also sets the split point of the interleaved walk adds
       (`walk_low_chunk`).
     - `r1`/`r2` choose which rounds are batch-replayed, interleaved, or
       replayed in the trailing batch at the loaned terminal state.
   - `SQUARE_LADDER` 244 → 243 → 242 in
     `src/point_add/trailmix_ludicrous/square/product_register.rs`. This is
     the live-ladder budget of the square's wide chunked adds.
   - The budget fell by 2 but Q fell by only 1, to 1272. So something outside
     the plan's model, most likely the square or a terminal fold chain, now
     sets the peak at 1272. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - Cost: more chunk boundaries, each a measured carry erase with a 23-bit
     conditioned compare (about 11.5 executed Toffoli each).
2. **`replay_flag_compare()`: 24 → 21 → 20** (`SUB4_PP_REPLAY_FLAG_COMPARE`).
   - The replay cell's overflow flag is measured out with `hmr`, and its
     phase is repaired by a top-`k`-bit `cmp_lt_phase_conditioned` that runs
     on about half the shots.
   - One more bit off saves about 0.5 Toffoli per cell, about 700 over the
     ~1,390 cells. See
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
3. **`rounds_for(Multiply)`: `rounds() − 7` → `rounds() − 6` → `rounds() − 7`**
   (`SUB4_PP_ROUNDS_MUL`, `rounds()` = 700). Against the parent this cuts one
   multiply round (694 → 693), saving one walk add, walk-back add and replay
   cell. Against the base it is unchanged.
4. **`endpoint_fold_window()`: 20 → 28 → 28** (`SUB4_PP_ENDPOINT_FOLD_WINDOW`).
   Unchanged from the parent; against the base it is `a8ab75a`'s λ buy-back
   (8 more carry positions in each of the 8 endpoint folds). See
   [modular-fold](../concepts/modular-fold.md).
5. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 25125857 (base) → 28861078. The parent had
   26010236.

## Why it is still correct, and what it risks

- **Budget changes are layout changes.** The adds stay exact in value.
  Extra replay boundaries add approximate 23-bit phase repairs, so λ rises
  slightly.
- **The 20-bit flag compare** is wrong on a 20-bit tie, about 2^−20 per cell.
  That is a **phase** failure.
- **The 693-round multiply walk** fails classically on inputs that need more
  rounds to converge. The code prices about +0.05 λ per round per traversal.
- The shipped nonce `28861078` draws a clean set: 0 classical, 0 phase and
  0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The score gain is the peak qubit, bought by lowering the ladder budgets of
both peak owners together. That is the budget-retune form of
ancilla-lifetime / venting. The flag compare and the round cut are
compensating truncations.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8d3517a -- src/point_add`.
   - `git diff --ignore-cr-at-eol 8d3517a 0440b62 -- src/point_add` is
     14 lines in 3 files.
   - The git parent `a8ab75a` is equally close (also 14 lines) and is the
     author's own previous step. Diffing against it shows only the second
     step: peak 1273 → 1271, r1 283 → 280, r2 589 → 608, `SQUARE_LADDER`
     243 → 242, flag compare 21 → 20 and `ROUNDS_MUL` −6 → −7. Either start
     works; this note uses `8d3517a`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 0440b62 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1272 qubits
   - 942,840 average Toffoli (rounded)
   - score 1,199,292,480
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `28861078` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

One constant changes. Each Kaliski iteration doubles the coefficient register
`r`. Below `R_SMALL_THRESHOLD` the doubling is a free wire rotation, and from
the threshold on it is a Solinas modular double that costs about 255 Toffoli.
The base switched at iteration 263. This commit moves the switch to iteration
326, so 63 more iterations double for free in each of the four Kaliski runs.
That is 63 × 4 × 255 = 64,260 Toffoli, exactly the measured saving. Qubits are
unchanged.

The free rotation is only correct while `r` has not reached `2^255`. That is
guaranteed while the Kaliski run is still active, and stops being true after
the input's run has terminated. Iteration 326 sits close to the earliest
termination of a typical input, so the setting is a bet that the drawn test
inputs all run longer.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`: `const R_SMALL_THRESHOLD` goes from 263 to 326. It
  is read through `r_small_threshold()` (env `KAL_R_SMALL_THRESHOLD`) at four
  places: the forward bodies `kaliski_iteration` and
  `kaliski_iteration_bulk_prefix3`, and their `_backward` mirrors.
- In STEP 7+8 of each iteration (`r := 2r mod p`), for
  `iter_idx < r_small_threshold()` the code calls `mod_double_no_corr(r)`. It
  is a swap cascade that moves every bit up one place and the top bit into
  bit 0, with 0 Toffoli. From the threshold on it calls
  `mod_double_inplace_fast(r, p)`. That shifts with the top bit into an
  overflow qubit and adds `c = 2^32 + 977` under it with
  `cadd_nbit_const_fast`, a 256-bit carry chain of about 255 Toffoli. See
  [modular-fold](../concepts/modular-fold.md) and
  [adders-and-carries](../concepts/adders-and-carries.md).
- The four runs are pair 1 and pair 2, each forward and backward; see
  [`a16788e`](a16788e.md) for the loop structure. All four run more than 326
  iterations (399 and 398), so each gains the full 63 iterations.

## Why it is still correct, and what it risks

The doc comment above the constant justifies the rotation with
`max(r, s) ≤ 2^iter_idx`. That proves the top bit of `r` is 0 only up to
iteration 255, so the comment does not cover 326.

The bound that does apply is the Kaliski invariant `u·s + v·r = p`. It holds
after every iteration from the start `(u, v, r, s) = (p, dx, 0, 1)`. All four
terms are non-negative. So while the run is active (`v ≥ 2` after the halving
of STEP 6), the doubled `r` is at most `p / 2`, below `2^255`. The rotation then
gives exactly `2r`, which is already reduced. Once an input's run has
terminated (`v = 0`), `r` keeps doubling with no bound, and the rotation wraps
its top bit into bit 0. That gives a wrong inverse, which shows up as a
classical mismatch, and garbage in the backward run, which shows up as ancilla
failures.

So the threshold is safe for every input whose Kaliski run lasts at least
about 326 iterations, and fails for inputs that converge faster. Lower-bound
proofs only reach 256 iterations. The code's later history puts the edge here:
later commits move this constant between 319 and 327, and comments in
later commits record 328 and 329 as rejected.

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, and this commit's draw contains no input that terminates
early enough to break. The run passed with 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit moves the iteration at which a cheaper body takes over. That is
iteration/threshold tuning. "Dead-Code" fits in the sense that the Solinas
correction it skips is the identity on every input it is meant for.

4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `DUMMY_TOFFOLIS` or other environment overrides set. Expect:
   - 2708 qubits

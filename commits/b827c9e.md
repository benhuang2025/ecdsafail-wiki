## Summary

The Solinas reduction of a 512-bit product `lo + 2^256·hi` adds
`hi·(1 + 2^4 − 2^6 + 2^10 + 2^32)` into the accumulator. In two reduction
routines, the last term, `hi·2^32` (built by shifting `hi` left 22 places after
it has been doubled 10 times), still used the slow modular add `mod_add_qq`.
That adder uses no carry wires, but each of its adders costs about two Toffoli
per bit. Those sites had been kept slow to save qubits at a former peak.

This commit switches both to `mod_add_qq_fast_lowscratch` from
[`bc9728a`](bc9728a.md). That adder erases its carries by measurement, so each
adder costs about one Toffoli per bit, and it adds the constant with the
register-free direct adder. Only one of the two sites runs in the default
circuit. That site saves 1,000 Toffoli. The extra carry wires fit under the
existing 2708-qubit peak.

## What changed and why it saves Toffoli

Both edits are in `src/point_add/mod.rs`. Each replaces
`mod_add_qq(b, acc, &hi, p)` with `mod_add_qq_fast_lowscratch(b, acc, &hi, p)`,
between `mod_shift_left_by_k(hi, 22)` and `mod_shift_right_by_k(hi, 22)`:

- **`mod_add_solinas_ext_product(acc, tmp_ext)`.** This reduces a 512-bit
  product held in `tmp_ext` into `acc`. In the default path it is called once
  per point addition, from `square_tx_and_combined_ty_l2minus3qx` (phase
  `affine_combined_breg_red`), to reduce `λ²` into the scratch register
  `breg`. This is the site that saves.
- **`mod_mul_add_into_acc_karatsuba_lowq_with_tmp_ext`.** The low-qubit
  Karatsuba multiply-add. In this tree it is only reached through
  `pair1_mul2_add_into_acc` (skipped when `POINT_ADD_AFFINE_COMBINED_Y` is on,
  the default) or through env-gated paths, so this edit does not change the
  default op count.

Cost of the two adders, each a 257-bit modular add `acc += a mod p`:
- `mod_add_qq` uses the plain Cuccaro adder `add_nbit_qq` (MAJ and UMA, about
  2 Toffoli per bit) for the operand add, for `+c` (with `c` loaded into a
  register by `add_nbit_const`), for the conditional `−c`, and for the
  `cmp_lt_into` that clears the flag. That is roughly 2,000 Toffoli in all.
- `mod_add_qq_fast_lowscratch` does the same four steps with the measured
  Cuccaro `add_nbit_qq_fast`, the direct constant adders and
  `cmp_lt_into_fast`. Each erases its carries with `hmr` plus `cz_if` and
  costs about one Toffoli per bit, roughly 1,000 Toffoli in all.

The difference is the measured −1,000. The fast adder holds a bank of about
256 carry wires while it runs, which the slow adder does not need. At this
site that bank stays below the 2708 peak, which is set elsewhere. See
[adders-and-carries](../concepts/adders-and-carries.md),
[measurement-uncompute](../concepts/measurement-uncompute.md) and
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

The matching subtract in `mod_sub_solinas_ext_product`, which runs twice
(un-reducing `breg` and updating `tx`), still uses the slow `mod_sub_qq`. It
was left for a later commit.

## Why it is still correct, and what it risks

The change is exact on every input. Both adders compute `acc + hi mod p` with
the same add, `+c`, conditional `−c` and flag-clearing comparison. Only the
gate-level implementation of the adders differs. The measured carry erase is
exact. A wrong `cz_if` fix would show up as a phase failure.

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed. The base's probabilistic Kaliski
settings passed on the new draw with 0 classical, 0 phase and 0 ancilla
failures.

## Classification rationale

The census files this as Register and Scratch Allocation → ancilla-lifetime /
venting. The diff swaps a slow, carry-free adder for a fast measured-carry
adder. It spends idle qubit headroom (about 256 carry wires below the peak)
to save Toffoli, and nothing is vented or freed early. That is closer to
Strength Reduction → fast-adder reroute.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9bd0748 -- src/point_add`.
   - Do not start from the git parent `a444668`. That is the author's per-pass
     `R_SMALL_THRESHOLD` split, and this commit was built on the tree before
     it.
   - Against the parent the diff is 110 lines. It deletes
     `r_small_threshold_for`, `KalPass` and `R_SMALL_THRESHOLD_PAIR1_BK`, and
     the threshold plumbing through the Kaliski loop drivers.
   - Against `9bd0748`, `git diff --ignore-cr-at-eol 9bd0748 b827c9e -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b827c9e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `POINT_ADD_*`, `DUMMY_TOFFOLIS` or other environment overrides set. Expect:
   - 2708 qubits
   - 3,838,944 average Toffoli (rounded)
   - score 10,395,860,352
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score only reproduces with an identical op stream.

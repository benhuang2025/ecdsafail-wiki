## Summary

In the base the global peak, 1567, sat in the x-tail Karatsuba square, where a
"shift left by 22 mod p" keeps 24 flag qubits alive across a modular subtract.
This commit computes the same value with 22 in-place modular doublings, which
keep no flags. The square phase then falls to about 1543, and the next binder
is the GCD apply pass at 1558. Moving the apply add's chunk split from bit 70
to bit 78 shrinks its upper chunk by 2 × 8 qubits and brings it under the
square, so the global peak is 1543.

Both changes cost Toffoli: the doublings about +4,788 and the wider boundary
compare +6,384, together +11,172. At 1543 qubits one qubit is worth about
1,100 Toffoli of score, so −24 qubits pays well.

This is the same pair of levers that mpjunior92 had shipped in `b113c6f`
(doublings) and `40574d3` (cut at 79), built independently on the older
`ecbf87b`. Apart from the reroll pads, the only op-level difference from the
frontier `40574d3` is the cut at 78 instead of 79, one comparator bit cheaper, which is the −798 Toffoli of
the leaderboard Δ.

## What changed and why it saves qubits

### 1. `ROUND84_XTAIL_BORROW_CARRIES=1`: doublings instead of the shift (`squaring_sub_from_acc_karatsuba`)

- This function computes `acc −= x² mod p` for the x-tail square. It builds
  `x²` as a 512-bit `lo + hi·2^256` in `tmp_ext`, with the 258-qubit `z1_reg`
  still live, then reduces with the Solinas identity
  `2^256 ≡ 2^32 + 977 (mod p)`: `acc −= lo`, `acc −= hi·977` (as a chain of
  doublings, adds and subtracts), and `acc −= hi·2^32`. See
  [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md) and
  [modular-fold](../concepts/modular-fold.md).
- By the time the `2^32` term is reached, `hi` has already been doubled 10
  times, so the remaining factor is `2^22`. The base did it with
  `mod_shift_left_by_k_lowq(hi, p, 22)`, then `mod_sub_qq(acc, hi, p)`, then
  `mod_shift_right_by_k_lowq` (since `KARA_SOL_SHIFT_FAST` is unset). The shift
  returns `spill` (22 qubits), `flag_inv` and `ovf`, which stay live across the
  subtract so that the right shift can undo them. Those 24 wires, on top of
  `z1_reg`, `tmp_ext` and the subtract's own transient, set the 1567 peak.
- New gated branch (`shift_dirty`): 22 × `mod_dbl(hi)`, then
  `mod_sub_qq(acc, hi, p)`, then 22 × `mod_hlv(hi)`. With `KARA_SOL_DBL_FAST`
  unset these are `mod_double_inplace_direct_const_fast` and its halving twin.
  A doubling rotates the wires (free), moves the old top bit into a fresh `ovf`,
  adds `c = 2^256 − p` controlled on `ovf`, and then clears `ovf` exactly with
  `cx(v[0], ovf)`, because the result is odd exactly when a reduction happened.
  No flag outlives the call, so nothing is parked across the subtract.
- The new code also adds `set_phase` labels (`r84k_sol_*`, `r84k_inv_combine`,
  `r84k_z_inv_squares`) for peak tracing; they emit no gates.
- The code comment says the doubles "borrow `acc` via Gidney venting". They do
  not: the doubling and halving touch only `hi` and their own `ovf`. The saving
  comes only from not keeping the shift's flags.
- **Cost.** 44 doublings and halvings of a 256-bit register cost more than the
  two 22-bit shifts. `b113c6f`, which ships the same op sequence under the name
  `KARA_SOL_SHIFT22_DOUBLES`, measured +4,788 Toffoli.

### 2. `DIALOG_GCD_APPLY_CHUNKED_F_CUT`: 70 → 78 (`configure_ecdsafail_submission_route`)

- With `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS=2`, the apply pass's controlled
  modular add and subtract (`dialog_gcd_add_ctrl_chunked_low_to_ext` and
  `dialog_gcd_sub_ctrl_chunked_low_to_ext`) split the 257-bit extended
  accumulator at `F_CUT`. The upper chunk `[F_CUT, 257)` loads
  `ctrl & a[F_CUT..256]` and adds it with `cuccaro_add_fast_low_to_ext`, which
  holds one carry wire per bit, so it holds about 2 × (256 − F_CUT) scratch
  qubits. Moving the cut by 8 bits frees 16 of them, which takes the
  `dialog_gcd_materialized_special_chunked_raw_{sum,difference}` phases from
  1558 to just below the square. See [`40574d3`](40574d3.md) for the same lever
  at 79.
- **Cost.** The carry (or borrow) out of the lower chunk is cleared with an
  exact compare of the low `F_CUT` bits, `ccx_cmp_lt_into_fast(..., ctrl, cout)`,
  one Toffoli per bit. It runs once in the add and once in the subtract per GCD
  step, over 399 steps: 8 × 2 × 399 = 6,384 Toffoli.
- 4,788 + 6,384 = 11,172, the measured change.

### 3. Reroll pair: `DIALOG_REROLL` 0 → 28, `DIALOG_POST_SUB_REROLL` 10 → 5

Identity `X;X` counts that re-draw the 9,024 test inputs without changing the
circuit (see [`ecbf87b`](ecbf87b.md)). The author's log says clean islands had
about 0.4% density on this stream.

## Why it is still correct, and what it risks

Both levers are exact. `hi · 2^22 mod p` is the same value whether it is
computed by a 22-bit shift with spill correction or by 22 modular doublings, and
the halvings undo the doublings exactly, so `hi` is restored. The chunked add
computes the full 257-bit sum wherever the split is, and the boundary compare is
a full compare of the low bits. Neither change adds a failure mode.

What changes is the test set. The existing approximations (the 59-bit GCD
branch comparator, the 19-bit apply-clean compare, the GCD width schedule and
the fold windows) must all be right on the new draw. The reroll pair (28, 5)
draws a set where they are: 9,024 of 9,024 shots pass with 0 classical,
0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both levers lower the peak by holding fewer wires at the binding moment: the
first drops 24 flags that lived across a subtract, the second rebalances chunk
scratch. Neither removes work (both add Toffoli), so ancilla-lifetime / venting
fits. Strength reduction was the runner-up for the shift → doublings swap, but
that swap is more expensive, not cheaper, and was made only for qubits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ecbf87b -- src/point_add`.
   - The git parent is `40574d3`, mpjunior92's cut-79 submission. Diffing
     against it (134 lines) would show the frontier's
     `KARA_SOL_SHIFT22_DOUBLES` block and its comments replaced by this
     commit's `ROUND84_XTAIL_BORROW_CARRIES` block, which emits the same ops,
     plus F_CUT 79 → 78. This commit was built on `ecbf87b`, not on that tree.
   - `git diff --ignore-cr-at-eol ecbf87b 287595e -- src/point_add` is 118
     lines in 2 files (one of them the new memory log).
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 287595e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1543 qubits
   - 1,695,087 average Toffoli (rounded)
   - score 2,615,519,241
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=28`,
`DIALOG_POST_SUB_REROLL=5` and an identical op stream. Any other change needs
a new reroll search.

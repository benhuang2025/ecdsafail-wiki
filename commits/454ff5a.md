## Summary

The square's B branch folds `b2 = y_hi²` into the output with the NAF terms of
`f = 2^32 + 977`. Since `PP_J_BMERGE`, the last four of those folds share one
33-bit window value `R = high32 + high10 − high6 + high4`. Building `R` uses a
small correction register and four adds, and clearing it uses four more adds
in reverse.

This commit makes two exact savings there:
- The correction register shrinks from 11 to 10 bits, because its value never
  exceeds 975.
- Two of the four reverse adds have outputs that are already known, since
  they restore copies of live wires. They now run as known-output adds, which
  rebuild each carry with CNOTs and erase it by measurement. These adds cost
  zero Toffoli.

The commit also widens the shell's erase compare from 25 to 28 bits, which
costs Toffoli and buys back Lambda. The net is −29 Toffoli at the same 1249
qubits.

## What changed and why it saves Toffoli

### `src/point_add/square.rs`: `b_merged_folds` and the new `with_merged_high`

The body that builds, uses and clears `R` moves out of `b_merged_folds` into
`with_merged_high(circ, high, consume)`, where `high = b2[N−32..]`. The
caller's `wcin_windows(..., r, ...)` becomes the `consume` closure, and
`wcin_finish` moves after the call. The gate order is the same except for the
changes below. Here `hi(s)` is the top `s` bits of `b2`, the same wires as
before.

The sequence, old → new:

| step | old | new | Toffoli (old → new) |
| --- | --- | --- | --- |
| `small = hi(10)` (CX copy) | 11-bit `small` | 10-bit `small` | 0 |
| `small −= hi(6)` | `addsub_wide` | same | 10 → 9 |
| `small += hi(4)` | `addsub_wide` | same | 10 → 9 |
| `r = hi(32)` (CX), `r += small` | `addsub_wide`, 33-bit `r` | same | 32 → 32 |
| consume `r` | `wcin_windows` | same | unchanged |
| `r −= small` | `addsub_wide(.., true)` | `stream_wide::add` | 32 → 0 |
| `r ^= hi(32)`, free `r` | | | 0 |
| `small −= hi(4)` | `addsub_wide` | same | 10 → 9 |
| `small += hi(6)` | `addsub_wide` | `stream_wide::add` | 10 → 0 |
| `small ^= hi(10)`, free `small` | | | 0 |

The per-step counts use the `addsub_wide` cost from `modular.rs`, which is
`acc.len() − 1` Toffoli. The total goes from about 104 to about 59 emitted
Toffoli for each call, so about 45 fewer. These adds are unconditional, so
executed equals emitted. The exact post-pass simplifiers may already have
removed part of the old cost.

1. **Why 10 bits are enough.** Write `high10 = 16u + v`, where `u = high6` is
   the top 6 bits and `v < 16`. Then `high4 = ⌊u/4⌋`, and the intermediate
   values are:
   - `high10 − high6 = 15u + v`;
   - `+ high4` gives `15u + v + ⌊u/4⌋ ≤ 15·63 + 15 + 15 = 975`.

   Every intermediate value lies in `[0, 1023]`, so the old 11th bit was
   always 0. Each of the three remaining adds on `small` loses one ripple
   position.
2. **Known-output inverse adds.** `stream_wide::add(a, b, cin, out)` adds `a`
   into `b` when the result bits are already known as XORs of live wires
   (`out[i] = (complement, wires)`). Working from the top bit down, it:
   - rebuilds each incoming carry with CNOTs as `c_i = a_i ⊕ b_i ⊕ s_i`;
   - writes the sum;
   - erases the previous carry with `hmr` and a CZ/Z phase fix.

   It needs no Toffoli and at most two carry wires. See
   [measurement-uncompute](../concepts/measurement-uncompute.md) (known-output
   receivers).
   - **`r −= small`.** `r = high32 + small` exactly, and this fits in 33 bits.
     In the complement frame, `~r + small = ~high`, including the zero top
     bit, which becomes a constant 1. The code passes
     `restored_high = [(true, [high_i])…, (true, [])]` and wraps the call in
     `x_all(&r)`.
   - **`small += hi(6)`.** After `small −= hi(4)`, `small = high10 − high6`,
     so adding `hi(6)` gives exactly `high10`. The code passes
     `restored_small = [(false, [hi(10)_i])…]`.

### `src/point_add/mod.rs`

- **`ERASE_COMPARE`: 25 → 28.** This is the width of the measured-erasure
  compare after the coordinate shell's modular add and subtract
  (`modular.rs`) and the fused `j_fuse.rs` cells. The square's B branch also
  calls `mod_addsub` three times before the merge. Each extra bit costs about
  0.5 executed Toffoli per site, because the compare runs only when the `hmr`
  outcome is 1. Each extra bit also halves that site's error, so 3 bits cut
  it by about 8×. This gives back part of the 45-Toffoli saving: the measured
  net is −29. See
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- **Tail nonce** `TAIL_NONCE`: 280927512368737 → 280927574775975.

## Why it is still correct, and what it risks

- **Both square edits are exact.**
  - The 10-bit bound holds for every value of `b2`.
  - The known-output adds are valid on every input. Their outputs equal copies
    of `high` and `high10` by construction, since `r` and `small` were built
    from those wires.
  - The `hmr` phase fixes are deterministic CZ/Z gates.

  No new hard inputs come from this part. If one of the known outputs were
  wrong, the carry rebuilds would be wrong and the run would show phase or
  ancilla garbage.
- **`ERASE_COMPARE` 28 lowers Lambda.** It makes the shell's truncated erase
  compares fail about 8× less often than at 25. The commit pays Toffoli for
  that. A likely motive is to make the clean-nonce hunt easier on the 1249
  line, which already carried the extra BADJ error from [`a4b4125`](a4b4125.md).
  This is an inference: no note states it.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Most of the saving comes from replacing two reverse ripple adders with
measured, known-output carry erasure. That is measurement uncompute. The
10-bit register is a small exact width cut, and the `ERASE_COMPARE` widening
goes the other way, as a Lambda buy-back. The runner-up was comparator/width
truncation, for the register narrowing.

   39 lines in 2 files.

   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 454ff5a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. In this tree
   `env_raw()` is a fixed table and does not read the process environment, so
   `SUB4_*` or `PP_*` variables have no effect. Leave them unset anyway.
   Expect:
   - 1249 qubits
   - 889,621 average Toffoli (rounded)
   - score 1,111,136,629
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `280927574775975` and an identical op
stream. Any other change needs a new nonce hunt.

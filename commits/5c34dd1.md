## Summary

Two small, value-exact removals in the trailmix circuit, both behind new
default-on switches.

1. The `+f` fold window drops its carry out of the top bit anyway. In the
   "graduated staircase" path the base still computed that top carry into a
   fresh qubit and then erased it with a measured erase plus a conditional
   comparator. The commit simply never computes it.
2. In the forward multiply, the first apply step starts from `y = 0`, so after
   its controlled add `x` and `y` hold the same value and the 256-wire
   controlled swap that follows is the identity. The commit skips it.

Together they save 562 average Toffoli: 256 from the swap, the rest from the
carry. Peak qubits stay at 1159. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

**1. Graduated `+f` suffix without the final carry-out**
(`src/point_add/trailmix_ludicrous/arith.rs`, switch `TLM_GRAD_FINAL_NO_COUT=1`).

- *Context.* `add_f_window(ctrl, reg, LSBS, f)` computes
  `reg[..LSBS] += ctrl·f (mod 2^LSBS)`. This is the gated `+f` correction of
  the pseudo-Mersenne fold ([modular-fold](../concepts/modular-fold.md)). Its
  doc comment says the carry out of bit `LSBS−1` is dropped. When qubit
  headroom allows only `g < LSBS−1` clean carries, it calls
  `add_f_window_hybrid`. That function runs a clean, measurement-vented carry
  chain over the low `g` bits, then adds the suffix `[g, LSBS)` with
  `controlled_add_const_chunked_graduated_off`.
- *Graduated staircase.* That function splits the suffix into chunks of width
  `k−3, k−4, …` (`k = graduated_const_kmin(n)`). Each chunk is a
  `const_chunk_add_clean`: a const-add carry chain whose internal carries are
  erased by `hmr` + `cz_if_bit`, and whose carry-out goes to a fresh `cout`
  qubit that feeds the next chunk. After all chunks, a reverse loop erases each
  `cout` with `controlled_erase_carry_gated_const`: `hmr` the carry, then,
  only on shots whose outcome bit is 1, run `compare_geq_const_cin_middle`
  over the chunk to put back the phase. That costs about one Toffoli per chunk
  bit on half the shots ([measurement-uncompute](../concepts/measurement-uncompute.md)).
- *The waste.* The last chunk's `cout` is the carry out of bit `LSBS−1`, which
  the window discards. The base still paid one CCX to compute it and a
  chunk-wide conditional comparator to erase it.
- *The change.* New `const_chunk_add_clean_drop_cout(ctrl, a, c, coff, cin)`,
  used for the last chunk only (`j + 1 == bounds.len()`):
  - it builds only `s−1` internal carries (no CCX for the top bit);
  - it sets the top sum bit directly: `a[s−1] ^= ctrl·c[s−1]`, then
    `a[s−1] ^= carry_{s−2}`;
  - the reverse vent of the internal carries is the same as before.
  - The erase loop now runs over `carries.len()` instead of `bounds.len()`, so
    the last chunk has nothing to erase.
- *Saving.* Per hybrid `+f` call, 1 CCX plus the last chunk's conditional
  comparator, which runs on about half the shots.

**2. Skip the cswap in the first forward-apply step**
(`src/point_add/trailmix_ludicrous/gcd.rs`, `apply_step_forward`, switch
`TLM_APPLY_FWD_FIRST_CSWAP_SKIP=1`).

- *Context.* The forward multiply (`tlm_forward_multiply`, `y ← y·x`) is
  `mod_mul_inverse_in_place(…, Direction::Forward)`. It swaps the multiplicand
  into `tmp`, so the apply pair starts as `x_reg = tmp = z` and `y_reg = y = 0`.
  It then runs `reverse_gcd_jump`, which calls `apply_step_forward` for
  `i = ITERS−1` down to `0` ([trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md)).
  Each step does: (1) `y += sub·x mod q` (`controlled_mod_add_k`);
  (2) `cswap(swp, x, y)` on all 256 bits; (3) the controlled doublings.
- *Why the first swap is the identity.* The first step executed is
  `i = ITERS−1 = 257`. There `y = 0` exactly:
  - if `sub = 0`, the swap flag `swp` (which holds `subtracted AND (v < u)` for
    `i ≥ 1`) is 0, so the swap does nothing;
  - if `sub = 1`, the add gives `y = 0 + z = z` with no carry out, so the `+f`
    fold does not fire. Now `x = y` bit for bit, and swapping two equal
    registers does nothing.
- *The change.* When the switch is set and `i + 1 == ITERS`, the 256 `cswap`
  calls are skipped. Each `cswap` in the trailmix builder is `cx; ccx; cx`, so
  this removes 256 Toffoli. The forward multiply runs once per point add, so
  the saving is exactly 256.

**3. Defaults and nonce** (`src/point_add/mod.rs`, `build()`): the two new
`set_default_env` lines turn on both switches. `DIALOG_TAIL_NONCE` goes from
800001625921 to 200017925264.

The measured total is −562 Toffoli: 256 from the swap, and about 306 from the
dropped carries across all hybrid `+f` calls.

## Why it is still correct, and what it risks

- **Both changes are exact.** The dropped carry was always thrown away by the
  window (mod `2^LSBS`), so the register value and phase are unchanged. The
  top sum bit is still `a ⊕ c ⊕ carry_in`. The skipped swap acts on two
  registers that are equal, or it has a zero control, on every input.
- No approximation is added, so the hard-input set (Lambda) is the base's. A new
  nonce was still needed because the op stream changed. The shipped nonce
  `200017925264` draws a clean set: 9,024 of 9,024 shots, with 0 classical,
  0 phase and 0 ancilla failures. A mistake in the drop-cout chain would show
  up as a classical failure (wrong sum bit) or an ancilla failure (an internal
  carry left dirty). See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as measurement uncompute, because the larger code change
removes a carry whose cleanup was an `hmr` measured erase. The diff suggests
dead-gate removal fits better. Neither change alters how anything is
uncomputed. Both delete work whose result is discarded (the top carry) or is
the identity (the first swap). The swap is also the larger part of the saving.
The runner-up, and the better fit, is Dead-Code and Redundancy Elimination →
dead-gate/self-inverse removal.

   and run `git checkout f0c1c42 -- src/point_add`.
   - Do not start from the git parent `5f3a0e3`. That is bket7's next commit,
     built on `d11bdbb`: it cuts the wide `GAP_J2` entries in `schedule.rs` by
     3 instead of 2, and lacks `662e267`'s classical `coord_add3x` in
     `ec_add.rs`. This commit was built on `f0c1c42`, which has the 2-bit cut
     and the classical `coord_add3x`.
   - Against the parent, the diff is 435 lines and would carry those
     differences.
   - Against `f0c1c42`, `git diff --ignore-cr-at-eol f0c1c42 5c34dd1 -- src/point_add`
     is 79 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 5c34dd1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1159 qubits
   - 1,378,834 average Toffoli (rounded)
   - score 1,598,068,606
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `200017925264` and an identical op
stream. Any other change needs a new nonce hunt.

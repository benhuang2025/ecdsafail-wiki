## Summary

Two exact gate identities, no knob changes. First, the controlled constant
adder `cadd_nbit_const_direct_fast` gets the same majority fold that
[`0be8d11`](0be8d11.md) gave the subtractor: each carry
`MAJ(acc_i, ctrl, carry_i)` at a set bit of c goes from three Toffoli to one.
Second, the Kaliski "frame" qubit that carries a deferred swap control across
an iteration boundary is reset with `a_f AND (r0 XOR s0)`, which the old code
built with two Toffoli and the new code builds with one. Both compute the same
values, so the measured uncomputes downstream are unchanged. The saving is 6,772
average Toffoli at the same 2309 qubits.

## What changed and why it saves Toffoli

1. **MAJ-fold on the ADD path**, `src/point_add/cuccaro.rs`,
   `cadd_nbit_const_direct_fast`.
   - At each bit `i ≥ 1` where `c = 2^32 + 977` has a 1, the old forward sweep
     wrote `MAJ(acc_i, ctrl, ci)` into the fresh carry with
     `ccx(acc,ci,t); ccx(ctrl,acc,t); ccx(ctrl,ci,t)`.
   - The new code uses `MAJ(a,b,d) = d ^ ((a^d) & (b^d))` with the carry-in as
     pivot: `cx(ci,acc); cx(ci,ctrl); ccx(acc,ctrl,t); cx(ci,t); cx(ci,ctrl); cx(ci,acc)`.
   - c has 6 such bits (4, 6, 7, 8, 9, 32), so each call saves 12 Toffoli.
   - This adder does every `mod_double_inplace_direct` (Kaliski STEP 7+8 `r`
     doublings past `R_SMALL_THRESHOLD`) and the `+c` step of the low-scratch
     modular adders and Solinas folds. The 397 pair2 `lam` doublings use
     `mod_double_inplace_fast`, which by default goes through the
     register-loaded `cadd_nbit_const_fast` and is not affected.
   - New switch `majfold_add_enabled()` in `kaliski_state.rs`
     (`KAL_MAJFOLD_ADD`, default on).
2. **Frame-reset select**, `src/point_add/kaliski_walk.rs`, in
   `kaliski_iteration_bulk_prefix3`, `kaliski_iteration` and both `_backward`
   bodies.
   - Background: the "(r,s) cswap boundary merge" defers iteration k's STEP-9
     swap and fuses it with iteration k+1's STEP-3 swap, since
     `cswap(p)·cswap(q) = cswap(p ⊕ q)`. A one-qubit `frame` holds the deferred
     control `a_{k−1}` across the boundary. After the merged swap the frame is
     reset to 0 with the identity `a_{k−1} = NOT(a_k ? r[0] : s[0])`, using
     `a_f = a_k` as the select.
   - The select is `s0 ^ (a_f & (r0 ^ s0))`. The old code formed the AND term
     with two Toffoli, `ccx(a_f, r0, frame); ccx(a_f, s0, frame)`. The new code
     XORs `s0` into `r0` for a moment: `cx(s0, r0); ccx(a_f, r0, frame); cx(s0, r0)`.
     One Toffoli.
   - This runs once per merged iteration boundary, in each of the four Kaliski
     runs (forward and backward of both pairs), so it saves about one Toffoli
     per iteration per run.

## Why it is still correct, and what it risks

Both rewrites are exact: they are Boolean identities that produce the same
value in the same target, and every wire used as a pivot is restored. The
measured uncomputes (`hmr` plus `cz_if`) that later erase those carries and the
frame see identical states, so no phase changes. No approximation knob moved.

The op stream still changes, so the 9,024-shot test set is redrawn (there is no
nonce in this era). The circuit carries the same approximate knobs as the base
(W-TRUNC, carry-tail, iteration counts), so a new draw could in principle hit a
hard input. This draw is clean: 0 classical, 0 phase and 0 ancilla failures.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both changes replace a Toffoli-heavy form of a function with a cheaper
equivalent, which is Strength Reduction. As with [`0be8d11`](0be8d11.md), the
change-type "fast-adder reroute" is loose. No adder is rerouted; "majority /
AND-XOR gate fold" describes it better.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a97b4e9 -- src/point_add`.
   - Do not start from the git parent `ac52c2e`. That is the author's own
     parallel submission, which raised `R_SMALL_THRESHOLD` to 327 and lowered
     the W-TRUNC margin to 2.
   - Against the parent, the diff is 70 lines in 3 files. It would show those
     two knobs going back to 326 and 3, which is not part of this change.
   - Against `a97b4e9`, `git diff --ignore-cr-at-eol a97b4e9 d4959a1 -- src/point_add`
     is 47 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol d4959a1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,811,789 average Toffoli (rounded)
   - score 6,492,420,801
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

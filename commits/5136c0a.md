## Summary

Three approximation knobs in `src/point_add/kaliski_state.rs` move together:
- the Kaliski W-TRUNC envelope starts at iteration 22 instead of 24;
- the constant-adder carry-tail window shrinks from 22 to 20 bits;
- `R_SMALL_THRESHOLD` goes from 323 to 321.

The first two narrow loops and carry chains and save Toffoli. The third
costs a little and changes the op stream, so the test set is drawn again. The
author found this triple with a joint grid search, where each knob alone had
failed. Net: −10,856 average Toffoli at the same 2309 qubits.

## What changed and why it saves Toffoli

1. **`kal_wtrunc_k0()`: 24 → 22.**
   - The envelope `n − ⌊(it − K0)·2/3⌋` (margin 0, `n = 256`) shifts two
     iterations earlier. Every later iteration is 1 or 2 bits narrower, 4/3
     bits on average. See [`179ab10`](179ab10.md) for the arithmetic.
   - It applies to every W-TRUNC loop: the STEP-0 OR chain, the STEP-2
     comparator, the STEP-4 load and subtract, and the STEP-3 and STEP-9
     (u, v_w) swaps.
   - [`49b7969`](49b7969.md) measured 4,362 Toffoli for 2/3 bit, so this is
     roughly −8,700.
2. **`kal_carrytail_w()`: 22 → 20**, on the default branch where the add path
   is truncated.
   - The direct constant adder and subtractor now compute carries and borrows
     only up to `33 + 20 = 53` positions for the sparse `c = 2^32 + 977`.
   - That is 2 fewer CCX per call, over about 1,250 calls, roughly −2,500.
3. **`R_SMALL_THRESHOLD`: 323 → 321.**
   - Kaliski iterations 321 and 322 now double `r` with the full modular
     double instead of the Toffoli-free rotate. That costs a few hundred
     Toffoli.
   - It is the safer direction. Its real role is to re-roll the island.

None of the comments are updated. The one on `kal_wtrunc_k0` still talks
about `K0 = 25`.

## Why it is still correct, and what it risks

All three knobs are probabilistic. The two that save Toffoli are past the
margins the comments' Monte Carlo can back.

- **Carry-tail at `W = 20`.**
  - The chain now ends at bit 53. The 3M-trial Monte Carlo in the comments
    found borrow runs above bit 32 up to 19 bits (bit 51) for subtracts, and
    carry runs up to 28 bits (bit 60) for adds.
  - So subtracts have about 2 bits of slack left, and adds are well inside
    the range where real inputs drop carries. A run of 20 or more 1-bits has
    probability about 2^-20 per add call that carries out of bit 32.
  - The submission note says the chain "reaches bit 69, far above any
    realizable run". That describes the old `W = 36`, not this commit.
- **W-TRUNC at `K0 = 22`, margin 0.** This spends another 4/3 bits of the
  envelope's slack. A slow-converging input breaks a comparison, subtraction
  or swap.
- **Failure channels.** Either kind of failure gives a classical mismatch, and
  the GCD case often gives phase garbage too.
- **Island.** There is no nonce in this era. The author ran a parallel grid
  with full 9,024-shot validation: `K0` in {22, 23, 24}, `R_SMALL` from 319
  to 327, and `W` in {18, 20, 22, 24}.
  - `K0 = 22`, `R_SMALL = 321`, `W = 20` is clean.
  - `K0 = 21` fails, and so do `W` 16 and 18 at these thresholds.
  - Moving `R_SMALL` by ±2 mostly fails.

  This draw is clean: 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Most of the saving comes from moving the W-TRUNC envelope earlier, which
narrows the GCD walk's loops. That is comparator/width truncation. The
carry-tail cut is a smaller fold/carry truncation part, and `R_SMALL` is an
island knob.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 49b7969 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 49b7969 5136c0a -- src/point_add` is
   6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 5136c0a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,424,136 average Toffoli (rounded)
   - score 5,597,330,024
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

## Summary

Each step of the dialog-GCD walk writes a swap bit, `b0_and_b1 = b0 AND (u > v)`.
Before this commit, the walk computed `u > v` into a scratch wire, applied
one Toffoli to write the swap bit, and then ran the whole comparison again to
clear the scratch wire. This commit applies the Toffoli directly to the
comparator's top carry while the carry chain is still live, and then erases the
chain by measurement. The comparison now runs once instead of twice. That
saves `compare_bits` Toffoli at each of the 4 sites per step, 90,392 Toffoli in
total. It costs no qubits, and the result is bit-for-bit the same.

## What changed and why it saves Toffoli

All code changes are in `src/point_add/mod.rs`. The route is described in
[`4b9cfbb`](4b9cfbb.md). The commit also adds a note,
`src/point_add/memory/2026-06-02-fused-branch-bits.md`, which records two
rejected probes.

1. **New `ccx_cmp_lt_into_fast(u, v, ctrl, target)`**, next to
   `cmp_lt_into_fast`. Its body is the same as `cmp_lt_into_fast`:
   - Negate `u`.
   - Run a forward MAJ sweep that writes each carry into a fresh wire with one
     CCX. The top carry `[u < v]` ends up in `u[n−1]`.
   - Erase the carries in reverse, each with `hmr(carry, m)` followed by
     `cz_if(u[i−1], v[i], m)`.
   - Un-negate `u`.

   The only difference is that `cx(u[n−1], flag)` becomes
   `ccx(ctrl, u[n−1], target)`. This writes `ctrl AND [u < v]` straight into
   `target`. If `KAL_VENT_MODADD=1`, which is not set here, it falls back to
   compute, CCX, recompute.
2. **New `dialog_gcd_ccx_cmp_gt_truncated_into_width(u, v, ctrl, target, compare_bits)`**.
   It takes the same top-`compare_bits` slice as
   `dialog_gcd_cmp_gt_truncated_into_width` and calls the fused comparator with
   the operands swapped, so it computes `u > v`.
3. **Six walk loops**, gated by the new `dialog_gcd_fused_branch_bits_enabled()`:
   - `emit_dialog_gcd_raw_tobitvector_steps` and its `_reverse`;
   - `emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle` and its `_reverse_`;
   - `emit_dialog_gcd_compressed_sidecar_tobitvector_steps` and its `_reverse`.

   Each loop replaces

   ```
   cmp_gt(u, v -> cmp);  ccx(b0, cmp -> b0_and_b1);  cmp_gt(u, v -> cmp)
   ```

   with one fused call, `ccx_cmp_gt(u, v, ctrl = b0, target = b0_and_b1)`.
   The `cmp` wire is still allocated and freed, but it is no longer used.
4. **`configure_ecdsafail_submission_route()`** sets
   `DIALOG_GCD_FUSED_BRANCH_BITS=1`.

**Count.** The shipped route uses the compressed-sidecar block-lifecycle loops
(`DIALOG_GCD_COMPRESSED_SIDECAR_LOG=1`, `DIALOG_GCD_COMPRESSED_BLOCK_LIFECYCLE=1`).
The old site cost `2·k + 1` Toffoli and the fused one costs `k + 1`, where

```
k = max(1, min(DIALOG_GCD_COMPARE_BITS = 63, active_width(step)))
active_width(step) = 256 − 0.7075·step + 28, rounded up to even and clamped to [1, 256]
```

Every step has 4 sites: the forward and reverse walks, in both GCD pairs. The
saving is `4 · Σ_step k` over the 399 steps, which is 4 × 22,598 = 90,392. That
is exactly the measured drop.

**Why it is peak-neutral.** The fused call keeps the same carry wires alive
for the same span as one unfused call. It needs no extra wire, and the old
`cmp` wire is still allocated, so the peak stays at 1698.

## Why it is still correct, and what it risks

- **Exact.** The fused gate writes `b0 AND [u_top > v_top]` into
  `b0_and_b1`, the same value as before, on every input. The comparator's
  carries are then erased by the same exact measured unwind. The comparison
  window is the same 63-bit cap as in the base, so the commit adds no new
  approximation.
- **Unchanged risk.** The truncated comparison still gives the wrong answer
  when u and v tie on their top `k` bits. That shows up as a classical failure.
- The reroll stays at 5, the base's value. The op stream changed, so the
  island changed too, but the author's `./benchmark.sh` run shows 0 classical,
  0 phase and 0 ancilla failures over 9,024 shots.
- The new memory file records two rejected probes:
  - `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS=1` was classically correct, but
    phase-dirty in all 141 batches.
  - A special fold width of 8 failed all 9,024 shots.

## Classification rationale

Two gates that used to need separate comparator passes, the swap-bit Toffoli
and the comparator's uncompute, now share one pass of the carry chain. That is
gate/op fusion. The runner-up was measurement uncompute, because the fused
chain is erased by `hmr`. But the base already erased the comparator that way.
The saving comes from removing the second comparison, not from the measurement.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 3c30191 -- src/point_add`.
   - Do not start from the git parent `1846bf7`. This commit was built on
     `3c30191`.
   - Against the parent, the diff is 224 lines. It would also revert two
     other contestants' changes. One is saucegodbased's measured apply-clean
     compares from [`4b9cfbb`](4b9cfbb.md). The other is megabyte0x's compare
     cap 62 and reroll 0 from [`1846bf7`](1846bf7.md).

     is 201 lines in 2 files, one of which is the new memory note.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9b6b9d6 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1698 qubits
   - 1,861,990 average Toffoli (rounded)
   - score 3,161,659,020
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 5 and an identical op stream.
Any other change needs a new reroll search.

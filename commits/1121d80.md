## Summary

In [`cee4044`](cee4044.md) the author had loosened the carry window of the
GCD apply's modular double and halve from 21 to 24 bits to make a clean nonce
easier to find. This commit takes two of those three bits back (24 → 22).
Each fused double or halve then makes two fewer carry positions, at one
Toffoli each, over about 518 calls per shot. That is the measured −1,040
average Toffoli. Qubits are unchanged. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`KAL_DOUBLE_CARRY_TRUNC_W`: 24 → 22.**
   - Read by `double_carry_trunc_window()`. With
     `DIALOG_GCD_APPLY_FUSED_FOLD=1`, every K=2 apply step runs one
     `dialog_gcd_fused_double_y`, and every reverse apply step one
     `dialog_gcd_fused_halve_y` (see [`8a47cf5`](8a47cf5.md)).
   - Each of those does a single truncated ripple that adds (or subtracts) the
     Solinas correction `c·e + 2c·d`, with `c = 2^32 + 977` (see
     [modular-fold](../concepts/modular-fold.md)). The ripple has carry
     positions `0..=33 + W`, and its carries are erased by measurement, which
     costs no Toffoli.
   - Above bit 33 the addend has no set bits, so each carry position removed
     costs exactly one CCX. Two positions over 259 + 259 calls is 1,036. The
     measured −1,040 matches that. The extra 4 presumably come from
     `mod_double_inplace_fast` / `mod_halve_inplace_fast` calls outside the
     apply, for example in the square, which read the same window.
2. **`DIALOG_TAIL_NONCE`: 4596 → 2000181.** The author's note says that a
   classical GCD prefilter proposed candidates, and that one of them (1000129)
   still failed the full simulation with one classical mismatch. The trusted
   simulator was therefore kept as the final check.

## Why it is still correct, and what it risks

The truncated ripple is wrong only when a carry runs through about 22
consecutive ones in `y` above bit 33, about 2^−23 per call, four times the
rate at 24 bits. A wrong result leaves stale high bits in `y`, which shows up
as a classical mismatch. Forward and reverse use the same window, so they stay
exact inverses when no truncation fires. The new nonce `2000181` draws a clean
set: 9,024 of 9,024 shots, with 0 classical, 0 phase and 0 ancilla failures.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A carry window is narrowed, which is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout cee4044 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol cee4044 1121d80 -- src/point_add` is
   15 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1121d80 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*` or `DIALOG_*` environment variables set. Expect:
   - 1309 qubits
   - 1,514,748 average Toffoli (rounded)
   - score 1,982,805,132
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=2000181` and an identical
op stream. Any other change needs a new nonce hunt.

## Summary

In every dialog-GCD step, the controlled subtract `v −= b0·u` (and the add
that undoes it in the reverse pass) runs a Cuccaro adder. It works on borrowed
scratch: idle future-transcript wires and the unused high bits of `u` and `v`,
topped up with fresh qubits when those run short. The adder starts at bit 1,
because bit 0 is handled separately (the "odd-u fast path"), and the carry into
bit 1 is known to be 0. The base still reserved a scratch wire as the
adder's carry-in, plus one structural gap lane.

This commit adds Cuccaro variants that have no carry-in wire at all. The
known-zero carry-in is folded into the first MAJ and the last UMA gates. The
scratch demand per step drops from `2·aw − 1` to `2·(body_w − 1) − 1` lanes,
two fewer when the body is untrimmed. At the step that set the 1320 peak, the
pool then needs fewer fresh qubits, and the peak drops to 1319. The Toffoli
count is identical, since the first MAJ still has exactly one Toffoli. The tail
nonce was re-hunted.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`.

1. **New `cuccaro_add_fast_borrowed_carries_no_cin` and
   `cuccaro_sub_fast_borrowed_carries_no_cin`.**
   - These are same-width `acc ± a (mod 2^n)` ripple adders that take only `a`,
     `acc` and `n − 1` borrowed carry wires. Carries are cleared by
     `hmr` + `cz_if` (see
     [measurement-uncompute](../concepts/measurement-uncompute.md)).
   - They come from the existing `..._borrowed_carries` versions by setting
     `c_in = 0`. The seed `cx(c_in, acc[0]); cx(a[0], c_in); ccx(c_in, acc[0], c0)`
     becomes `cx(a[0], acc[0]); ccx(a[0], acc[0], c0)`. The final
     `cz_if(c_in, acc[0], m0)` becomes `cz_if(a[0], acc[0], m0)`, because
     `c_in` only ever held a copy of `a[0]`. The trailing CX gates that reset
     `c_in` drop out.
   - The Toffoli count is unchanged.
2. **`dialog_gcd_controlled_sub_selected` and
   `dialog_gcd_controlled_add_selected`.** These are the GCD-body
   `v −= b0·u` (forward pass) and `v += b0·u` (reverse pass). They gain a
   `nocin` branch, enabled by the new pin `DIALOG_GCD_SELECTED_BODY_NOCIN=1`.
   It requires `body_start ≥ 1`, which is the odd-u fast path, and a borrowed
   slice of at least `2·body_len − 1` lanes, where `body_len = body_w − 1`.
   - Lane layout: `carries = c[..body_len − 1]`,
     `gated = c[body_len − 1 .. 2·body_len − 1]`.
   - Load `gated[j] = b0 AND u[1 + j]` with CCX gates.
   - Then `cx(ctrl, acc[0])` for bit 0. On the reachable support `u[0] = 1`
     and `acc[0] = v[0] = b0`, so bit 0 becomes 0 with no borrow into bit 1.
     That is the premise the base already used, when it parked the carry-in
     on a wire that stayed |0⟩ (`DIALOG_GCD_BODY_HOST_CIN`).
   - Run the no-c_in adder on `acc[1..body_w]`, then clear `gated` by
     measurement.
   - The old path needed `2·aw − 1` lanes: `n − 1` carries, then `n` gated
     wires whose slot 0 was the parked carry-in.
   - A diagnostic mode `=2` keeps the old pool layout, to separate body
     correctness from the repacking. It is not used.
3. **`dialog_gcd_build_composite_scratch` gains a `step` argument.** It is
   passed from the forward and reverse step loops, and it sizes the pool to the
   body's real demand: `want = min(2·body_len − 1, 2·aw − 1)`. The pool is
   filled from the free future-log prefix, `v[aw..]` and `u[aw..]` (excluding
   transcript cells), and only the remainder is freshly allocated. Asking for
   two lanes fewer means up to two fewer fresh qubits at the busiest step. The
   global peak falls by one, to the next binding phase at 1319. See
   [venting-and-wire-loans](../concepts/venting-and-wire-loans.md) and
   [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
4. **`dialog_gcd_selected_body_nocin_selftest()` plus a unit test**
   `dialog_gcd_selected_body_nocin_matches_cin_reference`. It sweeps every
   operand and accumulator value at widths 4–8, with both control values and
   both directions. For each case it checks, on 64 measurement streams, that
   the no-c_in body gives the same accumulator as the c_in reference, restores
   the gated lanes and carries to |0⟩, and leaves no phase. It runs only under
   `cargo test`.
5. **`configure_ecdsafail_submission_route()`**: adds
   `set_default_env("DIALOG_GCD_SELECTED_BODY_NOCIN", "1")`. The
   `DIALOG_TAIL_NONCE` goes from 10429 to 620000849.

## Why it is still correct, and what it risks

The change is exact relative to the base. The folded carry-in was |0⟩ in the
base too, so the new adder computes the same values with the same carries and
the same phase corrections. The self-test checks this exhaustively at small
widths. The one premise, that there is no borrow from bit 0 into bit 1, is
inherited from the existing odd-u fast path and is not new. An input that broke
it was already a failure in the base.

If the scratch repacking were wrong, for example a lane overlapping live data,
the result would be ancilla or phase garbage. The commit validated 0 classical,
0 phase and 0 ancilla failures over all 9,024 shots with nonce 620000849. The
nonce was re-hunted only because the op stream changed. The average Toffoli is
identical to the base, 1,534,277.

## Classification rationale

The census files this as host-derived / classical specialization. The adder is
specialized to a carry-in that is classically known to be 0, and that removes
the wire. The effect is purely a lower peak through a smaller scratch pool, so
Register and Scratch Allocation (ancilla-lifetime / venting) is a close
runner-up.

## Summary

Each dialog-GCD walk step decides its branch with a truncated comparison
`u > v` of the top few bits of the active window. Background:
[8316db1](8316db1.md) for the June comparator, [0780f67](0780f67.md) for the
K=2 walk. On the K=2 tree the per-step schedule is off. Each step compares
`min(DIALOG_GCD_COMPARE_BITS, active_width)` bits.

This commit lowers the cap from 74 to 73. Under the margin-9, slope-1.004
envelope, steps 0–192 are at least 74 bits wide, so 193 steps compare one bit
fewer. One comparator bit costs one Toffoli, and four walks run the
comparator, so the saving is 4 × 193 = 772 Toffoli, exactly the measured drop.
Qubits are unchanged. A new tail nonce was found.

## What changed and why it saves Toffoli

`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:

- `DIALOG_GCD_COMPARE_BITS`: 74 → 73.
- `DIALOG_TAIL_NONCE`: 7046 → 211.

`dialog_gcd_compare_bits()` reads the cap. Because
`DIALOG_GCD_PA9024_COMPARE_SCHEDULE = 0` on this tree,
`dialog_gcd_compare_bits_for_step(step, active_width)` returns
`min(73, active_width)`. The fused branch comparator
(`dialog_gcd_ccx_cmp_gt_truncated_into_width`, with
`DIALOG_GCD_FUSED_BRANCH_BITS = 1`) compares only the top `k` bits of the
`active_width` window. It costs one Toffoli per bit, and its carries are
erased by measurement.

Replaying `active_width = 256 − 1.004·step + 9` (rounded up to even), steps
0 to 192 have width ≥ 74. Those 193 steps lose one compared bit, and the later
steps are already below 73. The four walks (forward and reverse, in two
divisions) give 4 × 193 = 772 Toffoli.

## Why it is still correct, and what it risks

The comparator is approximate. When `u` and `v` agree on all compared top
bits, it can give the wrong branch. The walk then skips a swap it needed, the
subtract wraps, and the GCD does not converge. That shows as a classical
mismatch, and ancilla garbage after the reverse walk. One bit fewer roughly
doubles the tie probability on the 193 affected steps. Those are the early
and middle steps, where 73 compared bits make a tie very unlikely.

The author's tail-hunt harness found nonce `211` with exact validation on.
It gives 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A narrower truncated comparator is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5174a69 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 5174a69 4527ae1 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 4527ae1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,532,643 average Toffoli (rounded)
   - score 2,130,373,770
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=211` and an identical op
stream. Any other change needs a new nonce hunt.

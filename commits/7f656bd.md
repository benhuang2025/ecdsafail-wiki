## Summary

This commit adds five lines at the very top of
`configure_ecdsafail_submission_route()`. `set_default_env` sets a variable
only if it is still unset, so the first call wins, and these lines override
the pins further down without editing them. Three are truncations that save
Toffoli:

- the dialog-GCD branch comparator is capped at 46 bits instead of 50;
- the apply overflow-clean comparator goes from 23 to 18 bits;
- the apply double/halve carry window goes from 24 to 22.

The fourth goes the other way. The walk's width envelope shrinks more slowly
(slope 1.013 → 1.008), which costs Toffoli and lowers the overflow risk. The
author's note says it was eased "just enough to hold the 1309q peak after the
tighter comparators". The net is −4,110 average Toffoli at 1309 qubits, with
a new tail nonce.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, at the start of
`configure_ecdsafail_submission_route()`. The old pins further down stay in
the file but no longer take effect (`set_default_env` checks
`std::env::var_os(name).is_none()`).

| knob | effective before → after | what it is | estimated Δ Toffoli |
| --- | --- | --- | --- |
| `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` | 23 → 18 | width of the truncated compare that clears the overflow/underflow flag after each apply add/sub (`ccx_cmp_lt_into_fast` on the top `k` bits; see [`2f1f175`](2f1f175.md)), 518 calls at 1 Toffoli per bit | −2,590 |
| `KAL_DOUBLE_CARRY_TRUNC_W` | 24 → 22 | carry window of the fused K=2 apply double and halve (see [`1121d80`](1121d80.md), which makes the same cut on a sibling tree) | −1,036 |
| `DIALOG_GCD_COMPARE_BITS` | 50 → 46 | cap of the per-step branch comparator, `min(cap, active_width)` | about −3,490 (replayed: 872 bits per walk × 4 walks) |
| `DIALOG_GCD_WIDTH_SLOPE_X1000` | 1013 → 1008 | slope of `active_width(step) = 256 − slope·step + 10` (rounded up to even); a smaller slope means a **wider** envelope | about +3,000 (replayed: +172 width bits per walk × 4 walks, about 4.4 Toffoli per bit) |
| `DIALOG_TAIL_NONCE` | 4596 → 450007074 | new test island | 0 |

The first three rows are exact counts or replays of the formulas. The slope
row is the remainder that makes the total match the measured −4,110. The
width bits feed the walk step's branch cswap, gated load and controlled
subtract, and the reduced-width compare.

## Why it is still correct, and what it risks

- **Apply clean at 18 bits.** The overflow flag fails to clear when the sum
  and the addend agree on their top 18 bits, about 2^−18 per call, over 518
  calls per shot. That is by far the largest new risk here. A missed clear
  leaves a dirty flag, which shows up as ancilla or phase garbage.
- **Branch compare at 46 bits.** A tie in the top 46 bits sends the walk
  down the wrong branch, which gives a classical mismatch.
- **Window 22.** A fold carry that leaves the window corrupts the high bits of
  `y`, which gives a classical mismatch.
- **Slope 1.008** makes the envelope safer, so it partly offsets the
  others.
- The author's note calls the tightenings "value-exact on the reachable
  support". That is not right in general. They are probabilistic, and the
  shipped nonce `450007074` was chosen so that its 9,024-shot test set
  avoids every failing input: 0 classical, 0 phase and 0 ancilla failures.
  See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from three narrowed comparators and windows, which is
comparator/width truncation. The slope change is a counter-move inside the
same family.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout cee4044 -- src/point_add`.
   - Do not start from the git parent `1121d80`. That is odinfree's tree,
     which changes the in-place `KAL_DOUBLE_CARRY_TRUNC_W` pin to 22 and the
     nonce to 2000181. Diffing against the parent would wrongly show this
     commit putting that pin back to 24 and restoring the old nonce comments
     and value. Neither matters for the build, because the new top-of-route
     overrides win either way.
   - Against `cee4044`, `git diff --ignore-cr-at-eol cee4044 7f656bd -- src/point_add`
     is 7 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7f656bd -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*` or `DIALOG_*` environment variables set. Expect:
   - 1309 qubits
   - 1,511,678 average Toffoli (rounded)
   - score 1,978,786,502
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=450007074` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

`94535d1` showed that a carry majority with three distinct inputs,
`maj(acc, k, cin)`, can be computed with 2 CCX and 2 CX instead of 3 CCX. It
used that only in the per-position-controlled fold of the apply phase's fused
double and halve. This commit applies the same identity to the other
controlled fold: `cadd_nbit_const_direct_trunc_fast` and
`csub_nbit_const_direct_trunc_fast`. These add or subtract the Solinas
constant `c = 2^32 + 977` into a low window under one control qubit.

Each call has six set bits of `c` that also take a carry-in, so it saves six
Toffoli. The measured −3,120 is 520 such calls. The change is exact and
qubit-neutral. The nonce was re-hunted.

## What changed and why it saves Toffoli

1. **`src/point_add/arith/const_arith.rs`**
   - New knob reader `fold_maj2_enabled()` (`DIALOG_GCD_FOLD_MAJ2`, default
     off).
   - In `cadd_nbit_const_direct_trunc_fast(b, acc, c, ctrl, window)`, the
     forward carry sweep computes `carry_{i+1} = maj(acc_i, ctrl·k_i, carry_i)`.
     At a position where `bit(c, i) = 1` and there is a carry-in, the effective
     addend bit is `ctrl`, so the majority has three distinct inputs:
     - old: `ccx(acc, ci, t); ccx(ctrl, acc, t); ccx(ctrl, ci, t)`, which gives
       `t ^= acc·ci ⊕ ctrl·acc ⊕ ctrl·ci`
     - new, with the knob on: `ccx(acc, ci, t); cx(acc, ci); ccx(ctrl, ci, t); cx(acc, ci)`,
       which gives `t ^= acc·ci ⊕ ctrl·(acc ⊕ ci)`. That is the same function,
       with 2 CCX.
   - The carry-in wire `ci` is changed only between the two CX, and it is
     restored before the sum CX and the measured carry clear read it.
   - Positions where `bit(c, i) = 0` (one CCX), and position 0 (no carry-in),
     are unchanged.
   - `csub_nbit_const_direct_trunc_fast` gets the identical change on the
     inverted `acc[i]` (borrow sweep).
2. **`src/point_add/mod.rs`**: `DIALOG_GCD_FOLD_MAJ2` = `1` (new pin) and
   `DIALOG_TAIL_NONCE` 100879 → 202000012549.

**Where it runs.** The callers are listed below.
- The truncated-carry branch of the modular doubling and halving in
  `arith/modular.rs` (`mod_double_inplace_fast_with_dirty`,
  `mod_halve_inplace_fast_with_dirty`, `cmod_double_inplace_lazy` and
  `cmod_halve_inplace_lazy`, under `KAL_DOUBLE_CARRY_TRUNC_W`).
- The pseudo-Mersenne controlled add/sub of the dialog-GCD apply phase in
  `rounds/dialog/mod.rs` (`dialog_gcd_cmod_add/sub_materialized_pseudomersenne*`).
  These add `c` into `acc[..DIALOG_GCD_SPECIAL_ADD_LSBS]` under the overflow
  bit.
- The in-place x-tail fold correction in `arith/multiply.rs`. It adds the
  constant 1, which has only bit 0, so it saves nothing.

`c` has set bits 0, 4, 6, 7, 8, 9 and 32. Six of them (all but bit 0) have a
carry-in and lie inside every window used, so each call of the Solinas fold
saves 6 Toffoli. 3,120 / 6 = 520 calls, which fits roughly two apply-phase
folds per GCD step of the 259-step walk.

See [adders-and-carries](../concepts/adders-and-carries.md) for the carry
recurrence and [modular-fold](../concepts/modular-fold.md) for the fold.

## Why it is still correct, and what it risks

The change is an exact Boolean identity built from CCX and CX only. It
produces the same carry bits and adds no phase. The truncation window and
every other approximation are unchanged, so λ is unchanged. The nonce was
re-hunted only because the op stream changed. Nonce `202000012549` validated
with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots. A
wrong majority would give a wrong field value (a classical mismatch) and would
leave carry wires dirty (ancilla garbage). See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit rewrites one gate pattern inside a constant adder into a cheaper
equivalent. That is strength reduction. Fast-adder reroute is the closest
published change-type. An exact-peephole label under Dead-Code and Redundancy
Elimination would also fit.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ea8ce7b -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol ea8ce7b 82f7a95 -- src/point_add` is
   35 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 82f7a95 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1306 qubits
   - 1,464,304 average Toffoli (rounded)
   - score 1,912,381,024
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=202000012549` and an
identical op stream. Any other change needs a new nonce hunt.

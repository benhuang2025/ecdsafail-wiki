## Summary

This commit changes one constant. In this early circuit the modular inverse is
a Kaliski binary almost-inverse, run four times per point addition. Its
per-iteration loops over the GCD registers `u` and `v_w` are clipped to an
empirical bit-length envelope (W-TRUNC) plus a safety margin. The margin goes
from 3 to 2 bits, so every clipped loop is one bit narrower in every iteration
where the clip binds. That saves 4,416 average Toffoli at the same 2309 qubits.
The cost is a higher chance that a rare input outgrows the envelope.

## What changed and why it saves Toffoli

**Background: the Kaliski inversion in this circuit.** The point addition
(`build_standard_point_add` in `src/point_add/point_add.rs`) needs `dx^-1`
twice, and each use is a forward Kaliski pass plus its reverse, so the
Kaliski iteration body runs about 4 × 400 times (`pair1_iters = 399`,
`pair2_iters = 397`). Each iteration (`kaliski_iteration` and
`kaliski_iteration_bulk_prefix3` in `kaliski_walk.rs`, and their `_backward`
mirrors) is the textbook binary GCD step on `(u, v_w)` with a Bézout
coefficient pair `(r, s)`: test `v_w == 0` (STEP 0, an OR chain), compare
`u > v_w` (STEP 2), conditionally swap, subtract/add (STEP 4), halve `v_w`,
double `r`. One history bit `m_hist[i]` per iteration is kept so the reverse
pass can undo it. See
[kaliski-almost-inverse](../concepts/kaliski-almost-inverse.md).

**W-TRUNC.** The bit lengths of `u` and `v_w` shrink as the GCD walk
proceeds. `kal_wtrunc_width(iter, n)` in `kaliski_state.rs` returns

```
env(it) = n                         for it < K0         (K0 = 25)
env(it) = n - floor((it - K0)*2/3)  for it >= K0
width   = min(n, env(it) + MARGIN)
```

The envelope was fitted to 80k random inputs. Every Toffoli-bearing width loop
takes `min(provable_bound, width)`: the STEP-0 OR chain (`or_width`), the
STEP-2 comparator (`cmp_width`) and the STEP-4 load/subtract (`load_width`),
in the forward and backward bodies. Bits above the width are assumed to be 0
and are not touched.

**The change.** `kal_wtrunc_margin()` in `src/point_add/kaliski_state.rs`:
the default of `KAL_WTRUNC_MARGIN` goes from 3 to 2. From iteration 30 on
(where `env + 2 < n`) each clipped loop loses one bit position. Each position
costs about one Toffoli in the OR chain and in the comparator, and about two in
the STEP-4 controlled load plus subtract, so over four Kaliski runs of about 400 iterations the
saving is a few thousand Toffoli, here 4,416. The comment is rewritten to
record the sweep that picked the value. Nothing else changes.

## Why it is still correct, and what it risks

The clip is probabilistic. If an input's `u` or `v_w` is longer than
`env(it) + 2` at some iteration, the high bits are ignored: the comparator can
pick the wrong branch or the subtraction can drop a borrow. The inversion then
returns a wrong value (a classical mismatch) or leaves garbage that shows up as
a phase or ancilla failure.

In this era there is no tail nonce. The 9,024 test inputs are a Fiat–Shamir
hash of the op stream itself, so each knob value draws its own "island" and
contestants sweep knobs until one lands on a clean island. The commit comment
records the sweep: with `K0 = 25`, margin 2 is clean (0/0/0) and margins 1 and
0 fail (2 classical mismatches, 1 phase batch). Margin 2 failed on the earlier
`K0 = 27` island, which is why the margin was not lowered before `K0` was. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md) and
[comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

## Classification rationale

The only change narrows the Kaliski width loops by one bit, which is
comparator/width truncation. The census label fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 179ab10 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 179ab10 e739b53 -- src/point_add` is
   18 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol e739b53 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,832,665 average Toffoli (rounded)
   - score 6,540,623,485
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

## Summary

One knob and the re-roll change. The register-free controlled constant adders
(`cadd/csub_nbit_const_direct_fast`) add or subtract `c = 2^32 + 977` with a
carry chain that stops `W` bits above `c`'s top bit. This commit lowers `W`
from 19 to 18, so each call computes 51 carries instead of 52 and saves one
Toffoli. Over the 1,277 executed calls that is −1,277 Toffoli, the same count
as the 20 → 19 step in [`6e71096`](6e71096.md). `KAL_REROLL` goes from 43 to
77 to land a clean test draw. Qubits are unchanged.

## What changed and why it saves Toffoli

1. **`kal_carrytail_w()`: 19 → 18** (`src/point_add/kaliski_state.rs`, the
   default when the add path is enabled, which is the default mode "both").
   - `kal_carrytail_count` and `kal_carrytail_count_c` return
     `min(n − 1, K0 + W)` with `K0 = 33`, one above bit 32, the top set bit of
     `c`. The direct adders in `cuccaro.rs` allocate that many carry (or
     borrow) qubits, compute them with one Toffoli each, apply the sum bits,
     and erase them with `hmr` plus `cz_if` (no Toffoli).
   - Their callers are the modular add, double and halve helpers in
     `modular.rs`, used by the Kaliski iterations, the `2^iters` scale-fix
     loops and the Solinas folds. The separate shift22 windows are not
     affected.
   - One fewer position per call gives the 1,277 Toffoli. See
     [adders-and-carries](../concepts/adders-and-carries.md).
2. **`KAL_REROLL`: 43 → 77** (`src/point_add/mod.rs`): 77 identity `X;X` pairs
   on `tx[0]`, which only re-draws the Fiat–Shamir test inputs.

## Why it is still correct, and what it risks

- **Truncation is at the edge of the measured bound.** The chain now stops
  after the borrow into bit 51. The code comments cite a 3M-trial Monte Carlo
  whose longest subtract-borrow run ends at bit 51. So `W = 18` keeps no
  slack against that sample, where earlier values had several bits. The
  author argues it is still sound. A longer run on some input would drop a
  carry and give a wrong sum, which shows up as a classical mismatch, or as
  phase garbage if the wrong bit feeds a comparison.
- **The add path.** The comment says the add-path truncation, not the
  subtract borrow, is what decides cleanliness, so this is a draw-dependent
  choice.
- **Island.** A 256-value `KAL_SCREEN` sweep found `rr = 77` clean. The
  shipped stream is clean: 0 classical, 0 phase and 0 ancilla failures over
  9,024 shots. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A carry chain in the constant adders used by the modular reductions is cut one
bit shorter, which is fold/carry truncation.

     directly on `233a44c` and does not contain the two `R_SMALL` commits in
     between.

     `R_SMALL_THRESHOLD` from 326 to 321, change the re-roll from 254 to 77,
     and delete the two `memory/*.md` notes files of

   - Against `233a44c`, `git diff --ignore-cr-at-eol 233a44c 8d83e8e -- src/point_add`
     is 30 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8d83e8e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `AFFINE_*`, `SHIFT22_*` or `LOWQ_*` environment variables set. Expect:
   - 2025 qubits
   - 2,559,226 average Toffoli (rounded)
   - score 5,182,432,650
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `KAL_REROLL = 77` and an identical op stream.
Any other change needs a new re-roll search.

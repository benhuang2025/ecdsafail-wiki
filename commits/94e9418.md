## Summary

teddyjfpender's 1320-qubit teardown [`06b07ee`](06b07ee.md) had been built on
the slope-1005 tree, so it lacked the 1006 and 1007 notches that 10d9e had
added on the other line. This commit jumps straight to
`DIALOG_GCD_WIDTH_SLOPE_X1000 = 1008`. The binary GCD's working window becomes
2 bits narrower on 43 steps between 125 and 258, which saves 1,416 Toffoli.
Qubits are unchanged. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

**Background.** The circuit is the dialog-GCD route (`emit_dialog_gcd_raw_pa`
in `src/point_add/mod.rs`). Two calls each run a reversible binary GCD: the
quotient dy/dx and the product with c = ox − Rx. Each call has a forward pass,
an apply pass and a reverse pass. [98416e4](98416e4.md) lists one GCD step and
the width formula
`active_width(step) = clamp(2·⌈(256 − step·SLOPE/1000 + MARGIN)/2⌉, 1, 256)`.

**The changes in `configure_ecdsafail_submission_route()`:**

- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 1005 → 1008, with margin 10 and 260 steps.
  - The rounded width drops by 2 bits at 43 steps: the odd steps 125 to 199
    (142 → 140 at step 125) and the even steps 250 to 258 (8 → 6 at step 258).
  - On the first 38 of these steps the window is wider than the 52-bit
    comparator cap, so each bit-step saves 16 Toffoli over the four passes: the
    cswap, the subtract or add, and the K=2 halving.
  - On the last 5 steps the comparator shrinks too, for 20 Toffoli per bit-step.
  - 38 × 2 × 16 + 5 × 2 × 20 = 1,416, the measured drop.
  - The comment above the knob was not updated. It still describes 1004 → 1005.
- `DIALOG_TAIL_NONCE`: 108 → 1876.

## Why it is still correct, and what it risks

A narrower window cuts the top bits of any input whose GCD registers have not
shrunk as fast as the envelope assumes. The GCD then goes wrong, which is a
classical failure. Three notches at once raise λ more than one, and the
apply-teardown tree had already needed two extra GCD steps to find a clean
island. The author searched exact candidates on a large CPU instance. Nonce
`1876` draws a clean set: 0 classical, 0 phase and 0 ancilla failures over all
9,024 shots.

## Classification rationale

The only circuit change narrows the GCD registers' working width, which is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 06b07ee -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 06b07ee 94e9418 -- src/point_add` is 4 changed
   lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 94e9418 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset. Expect:
   - 1320 qubits
   - 1,564,001 average Toffoli (rounded)
   - score 2,064,481,320
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `1876` and an identical op stream. Any
other change needs a new nonce hunt.

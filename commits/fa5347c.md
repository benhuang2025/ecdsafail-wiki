## Summary

In the GCD apply pass, each step doubles a 256-bit register mod p, and the K=2
variant can double it a second time. The quotient call does the same with
halvings. Each doubling shifts the register left by one bit. If a bit falls off
the top, it adds back c = 2^32 + 977, because 2^256 ≡ c (mod p). That constant
add uses a ripple carry, and `KAL_DOUBLE_CARRY_TRUNC_W` sets how far above
bit 32 the carry may run.

This commit cuts the window from 24 to 23 bits. That saves one Toffoli per
doubling or halving. There are about 2 × 259 × 2 = 1,036 of them per shot, which
is the measured 1,038 Toffoli, give or take 2. It is the doubling counterpart of
the fold cut in [`af0f90a`](af0f90a.md) and [`bc858e8`](bc858e8.md). Qubits are
unchanged. The nonce was re-hunted.

## What changed and why it saves Toffoli

**Background.** The circuit is the dialog-GCD route (`emit_dialog_gcd_raw_pa`
in `src/point_add/mod.rs`). Two calls each run a reversible binary GCD: the
quotient dy/dx and the product with c = ox − Rx. Each call's apply pass replays
the GCD's branch bits on a register pair. [98416e4](98416e4.md) has the GCD
step. Per step, `emit_dialog_gcd_compressed_sidecar_apply_bitvector_block_lifecycle`
runs:

```
mod_double_inplace_fast(y)                 # y = 2y mod p
cmod_double_inplace_lazy(y, ctrl = s2)     # K=2: a second double if the GCD halved twice
y += b0·x mod p;  cswap(x, y) if b0_and_b1
```

The quotient call runs the exact inverse
(`…apply_bitvector_reverse_exact_block_lifecycle`). It uses
`mod_halve_inplace_fast` and `cmod_halve_inplace_lazy`.

**The doubling.** `mod_double_inplace_fast_with_dirty` rotates `v` left by one
wire, putting the old top bit in a fresh `ovf` qubit. Then it calls

```
if let Some(w) = double_carry_trunc_window():          // KAL_DOUBLE_CARRY_TRUNC_W
    cadd_nbit_const_direct_trunc_fast(v, c, ovf, w)    // v += ovf·c, carries only up to bit 32 + w
```

Above bit 32, c has only zero bits, so each window position costs one CCX on the
carry chain. The carries are erased by measurement, which costs no Toffoli. The
halving and the two controlled K=2 versions call the same truncated add or
subtract with the same window, so a double and its matching halve stay exact
inverses. See [modular-fold](../concepts/modular-fold.md).

**The changes in `configure_ecdsafail_submission_route()`:**

- `KAL_DOUBLE_CARRY_TRUNC_W`: 24 → 23.
  - There are 2 calls per apply step (one plain and one controlled), over 259
    steps, in 2 GCD calls: 1,036 calls, each one Toffoli cheaper.
  - The fold window `KAL_FOLD_CARRY_TRUNC_W` stays at 23.
- `DIALOG_TAIL_NONCE`: 55 → 254.

## Why it is still correct, and what it risks

A doubling goes wrong only when the carry from adding c has to run through all
23 window positions above bit 32. That needs a long run of 1 bits in `v`, about
2^-24 per call where `ovf` = 1. On a failure the high bits of `y` stay wrong.
The new comment makes no exactness claim. The neighbouring fold comment's
"value-exact on the reachable support" would be too strong here too. With about 1,000 calls per shot, half of them firing, the expected
number of failing shots per draw is about 0.3. That is small, but twice the
fold lever's share, because there are twice as many calls.

The author found nonce `254` with a local exact search over the official
simulator checks. It draws a clean set: 0 classical, 0 phase and 0 ancilla
failures over all 9,024 shots.

## Classification rationale

The census files this under comparator/width truncation. The knob narrows the
carry window of a constant add inside the modular doubling, so "fold/carry
truncation" fits better. That is the label of [`438ef00`](438ef00.md), which
moves this same knob from 23 to 22.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout bc858e8 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol bc858e8 fa5347c -- src/point_add` is 13 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol fa5347c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset. Expect:
   - 1390 qubits
   - 1,518,179 average Toffoli (rounded)
   - score 2,110,268,810
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `254` and an identical op stream. Any
other change needs a new nonce hunt.

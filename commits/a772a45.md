## Summary

Each step of the dialog-GCD apply pass (background in [8316db1](8316db1.md)
and [0780f67](0780f67.md)) adds or subtracts a controlled 256-bit value into a
257-bit accumulator. The add is split into four chunks at bit cuts 56, 112
and 168. Each chunk loads its slice of `ctrl·a` into fresh wires and runs its
own Cuccaro adder with fresh carry wires. The last chunk, `[168, 257)`, was the
widest at 89 bits, and its transient wires set the 1394-qubit peak in the
apply raw sum/difference phases.

This commit moves the cuts to 58, 114 and 170. The last chunk shrinks to 87
bits, which needs 2 fewer loaded wires and 2 fewer carry wires, so the peak
falls by 4. The exact boundary-carry clear sweeps a prefix up to the last cut,
which is now 2 bits longer. That costs 2 Toffoli per apply step, 1,036 in
total. At this size a qubit is worth about 1,170 Toffoli of score, so the
trade pays. The arithmetic stays exact. Only the nonce was re-hunted.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:

- `DIALOG_GCD_APPLY_CHUNKED_F_CUT`: 56 → 58
- `DIALOG_GCD_APPLY_CHUNKED_F_CUT2`: 112 → 114
- `DIALOG_GCD_APPLY_CHUNKED_F_CUT3`: 168 → 170
- `DIALOG_TAIL_NONCE`: 124 → 141744616447148

How the cuts are used:

1. With `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS = 4` and `..._CUSTOM4 = 1`,
   `dialog_gcd_chunk_hi` returns the three cuts as the upper ends of chunks
   0–2. Chunk 3 runs to `ext_n = 257`.
2. `dialog_gcd_add_ctrl_chunked_low_to_ext` (the raw sum) and its `sub` twin
   (the raw difference) handle each chunk `[lo, hi)` like this:
   - `dialog_gcd_load_controlled_slice` allocates `hi − lo` fresh wires and
     loads `ccx(ctrl, a[i], f[i])` into them.
   - Chunks 0–2 add `f` plus a zero pad into `acc_ext[lo..hi]` plus a boundary
     carry-out wire, using `cuccaro_add_fast`.
   - The last chunk loads `a[lo..256]` (256 − lo wires) and adds it with
     `cuccaro_add_fast_low_to_ext`. That adder allocates one carry wire per bit
     and erases them by `hmr` plus `cz_if`.
   - The loaded slice is cleared by `hmr` plus `cz_if` and freed.
3. **The qubit saving.** The last chunk holds `2·(256 − lo)` transient wires at
   once. With `lo` going from 168 to 170, that drops from 176 to 172, so 4
   fewer qubits. The other chunks change from 56/56/56 bits to 58/56/56 bits.
   The first chunk grows by 2, but it was not the peak binder.
4. **The Toffoli cost.** Each source bit is loaded exactly once whatever the
   cuts, so the loads cost the same. The boundary carry-outs are cleared
   exactly by `ccx_cmp_lt_into_fast_prefix_targets` over the prefix
   `acc_ext[..p]`, where `p` is the last cut. One sweep clears all
   boundaries. The prefix grows from 168 to 170 bits, which costs 2 Toffoli
   per call. The apply passes make 259 calls each (one per walk step, since
   `DIALOG_GCD_ACTIVE_ITERATIONS = 259`) and there are two passes, so
   2 × 259 × 2 = 1,036 Toffoli. That is exactly the measured increase. The
   commit comment's "1,036 Toffoli per apply direction" is the total, not a
   per-pass figure.

## Why it is still correct, and what it risks

The chunked add is exact for any cut positions:
- Each chunk's carry-out is carried into the next chunk.
- The carry-outs are later cleared by an exact comparison: a carry leaves
  bit `p` exactly when the low-`p`-bit sum wrapped.
- The loaded slices are uncomputed by measurement with a phase fix.

Moving the cuts changes no approximation, so the failure rate (λ) is the
base's. Any wrong boundary clear would show as ancilla garbage.

The op stream changed, so the 9,024 test inputs changed with it. The new nonce
`141744616447148` draws a clean set: 0 classical, 0 phase, 0 ancilla failures.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit moves the block boundaries of a chunked (windowed) carry chain to
rebalance its transient width. That is windowed carry/shift blocks. The
runner-up is Register and Scratch Allocation, since the gain is purely a
peak-qubit trade.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0780f67 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 0780f67 a772a45 -- src/point_add` is
   13 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a772a45 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,630,487 average Toffoli (rounded)
   - score 2,266,376,930
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=141744616447148` and an
identical op stream. Any other change needs a new nonce hunt.

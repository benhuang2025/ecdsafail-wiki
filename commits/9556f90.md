## Summary

Sky15 repeats sky14's fold trade ([`cc530e2`](cc530e2.md)) one step further
and adds two one-bit compare sells. Four pins move:

| knob | change | sites (per leg for cells) | direction |
| --- | --- | --- | --- |
| `HEO_PIN_PP_FOLD_PROFILE` | new band `44:0`; width 38–43 goes 0 → −1 | cells at ticks 337–345 (9) | sell, 1 bit |
| `HEO_PIN_PP_FOLD_PROFILE` | width 25–31 goes −3 → −5 | cells at ticks 354–365 (12) | sell, 2 bits |
| `HEO_PIN_PP_FOLD_WIDEN` | 112 → 144 | cells at ticks 60–76 (17) | buy, 1 bit |
| `HEO_FIT_K` | 22 → 21 | boundary erases of adds split to fit under the cap | sell, 1 bit |
| `HEO_PIN_ERASE_COMPARE` | 22 → 21 | overflow-carry erase of every shell modular add/sub | sell, 1 bit |

The SAT rewrite table is re-mined (58 → 64 rows), and for the first time it
includes rows outside the square. This package is a net λ sell: the author
measured +0.080 λ. The net is −73 Toffoli at 1174 qubits.

## What changed and why it saves Toffoli

All circuit changes are pins in `install_skywalk_submission_recipe()`,
`src/point_add/mod.rs`.

1. **`HEO_PIN_PP_FOLD_PROFILE`: `38:0,32:-1,25:-3,19:-4,0:-5` →
   `44:0,38:-1,32:-1,25:-5,19:-4,0:-5`.**
   - The payload cell's fold window is `54 + fold_offset(proxy)`, where
     `fold_offset` reads this band table at `PP_WIDTH_SCHEDULE[proxy]` and
     adds 1 below `PP_FOLD_WIDEN`. The mechanism is described in the sky14
     note [`cc530e2`](cc530e2.md).
   - Walk width ≥ 44 keeps offset 0. The new top band only splits the old
     `38:0` band.
   - Walk width 38–43 (ticks 337–345 on both legs, by my mapping through the
     proxy envelope): window 54 → 53.
   - Walk width 32–37 (ticks 346–353) keeps −1.
   - Walk width 25–31 (ticks 354–365): window 51 → 49. This band is now two
     bits narrower than the 19–24 band below it. `parse_band_table` only
     requires the widths to descend, not the offsets, and the `fold_shape()`
     comment says the shape is measured, not derived.
   - Each window bit is about one Toffoli per cell (one stage of the fold's
     truncated carry chain). The sells cover 9 + 2 × 12 = 33 cell-bits per
     leg. See [modular-fold](../concepts/modular-fold.md).
2. **`HEO_PIN_PP_FOLD_WIDEN`: 112 → 144.**
   - Proxy rounds 112–143 now also get +1. On the proxy envelope that is
     ticks 60–76 (proxy rounds 113–142), whose window goes 54 → 55 on both
     legs: about 17 cell-bits per leg.
3. **`HEO_FIT_K`: 22 → 21.**
   - `heo::fit_window()` returns it when `HEO_FIT_MODE=win`.
     `ripple_add_proved` splits an exact add that does not fit under the
     1174-qubit cap into chunks. Each chunk boundary is erased right after
     the next chunk consumes it, with `hmr` and then a phase compare.
   - The compare is exact over a chunk that starts at bit 0 and is at most K
     bits wide. Otherwise it covers only the top `min(K, size)` bits.
   - One bit fewer is about 0.5 executed Toffoli per windowed boundary. See
     sky10 [`f260d33`](f260d33.md), which took it from 23 to 22.
4. **`HEO_PIN_ERASE_COMPARE`: 22 → 21.**
   - `modular::erase_compare()` is the width of the measured overflow-carry
     erase in `mod_addsub_with` and its fused relatives in the shell.
   - The erase measures the carry with `hmr`, and only on outcome 1 runs
     `cmp_lt_phase` on the top `k` bits. One bit fewer is about 0.5 executed
     Toffoli per modular add/sub. See
     [measurement-uncompute](../concepts/measurement-uncompute.md) and
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
   - The comment above `ERASE_COMPARE` ties it to `FOLD_GUARD` by a "balance
     rule". This package moves only `ERASE_COMPARE`, and `FOLD_GUARD` stays
     at 20.
5. **SAT rewrite rows: `sky14_rewrite.txt` (58 rows) → `sky15_rewrite.txt`
   (64 rows).**
   - The code comment says "57 square rows re-keyed to this op stream, 7 new
     rows from a whole-program span census, 3 of them outside the square".
   - In the file, 61 rows sit in the square's op range (about 4.60M–5.18M).
     The 3 outside it are at op 17,012, near the start of the stream, and at
     ops 8,896,638 and 8,898,701, in the multiply leg's head batch (sky16's
     comment names them "headbatch rows").
   - Only 12 rows name the same wires as a sky14 row, at several different
     index shifts (−574, −754, −912, −1240). So the stream moved by
     different amounts in different places.
   - The loader is unchanged. It needs one global shift under which every
     row names an unconditioned CCX. See
     [dead-gate-strip](../concepts/dead-gate-strip.md).
   - Six more rows are about −6 Toffoli on every shot.
   - `sky14_rewrite.txt` stays in the tree, unused.
6. **Tail nonce**: `TAIL_NONCE` goes from 14002253611947 to 15000704855378.

The diff alone does not fix how the −73 Toffoli splits among these levers. The
fold cell-bits are the largest countable part: about 66 sold and 34 bought
over the two legs.

## Why it is still correct, and what it risks

All four pin changes are probabilistic:

- **The fold sells** about double (or, on the 25–31 band, quadruple) the
  fold's escape rate on those cells. A dropped carry leaves a wrong field
  element, which shows up as a **classical** failure.
- **The FIT_K and ERASE_COMPARE cuts** double the tie error of those erases,
  about 2^-21 per site. A wrong compare leaves a wrong phase, which shows up
  as a **phase** failure.
- **The FOLD_WIDEN buy** halves the escape rate on 17 early cells per leg.
- The submission note gives the final λ as 19.341 ± 0.032 (est + 2 SE
  19.404), up 0.080 on sky14, inside the 19.5 limit that the code comment
  cites.
- The rewrite rows are exact on reachable states if their proofs hold. The
  build only asserts that each row still names its CCX.
- The shipped nonce `15000704855378` draws a clean island: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The largest countable lever is the fold-window trade, the same kind as sky14:
fold/carry truncation. The runner-up was comparator/width truncation, because
`HEO_FIT_K` and `ERASE_COMPARE` each lose a compare bit. Those are one-bit
cuts on fewer sites.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b997d0a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol b997d0a 9556f90 -- src/point_add` is
   81 lines in 2 files.
2. **Copy the new rewrite table from the commit:**
   `git checkout 9556f90 -- src/point_add/skywalk_data/sky15_rewrite.txt`.
   It holds the 64 SAT rows described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `mod.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol 9556f90 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `PP_*` and `SUB4_*` overrides have no effect. Do not set
   them anyway. Expect:
   - 1174 qubits
   - 944,526 average Toffoli (rounded)
   - score 1,108,873,524
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `15000704855378` and an identical op
stream. [`36d313e`](36d313e.md) keeps this circuit and only re-rolls the
nonce.

## Summary

The 1572/1571-qubit line descends from Gajesh2007's `b694e22`. That tree still
had the dialog-GCD comparator-schedule margin at 8. mpjunior92 had already cut
the margin to 5 on the older 1698-qubit line ([4b68e94](4b68e94.md)). This
commit brings the same setting, margin 5, to the current tree. The branch
comparator in each walk step looks at 1–3 fewer top bits on 179 of the 399
steps, 467 bits fewer per walk. At one Toffoli per bit and four walks, that
saves 1,868 Toffoli. Qubits are unchanged.

## What changed and why it saves Toffoli

Background on the walk step and the comparator schedule is in
[8316db1](8316db1.md).

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN` default 8 → 5, with a new
  comment.
  - `dialog_gcd_compare_bits_for_step(step, active_width)` =
    `min(SCHEDULE[step] + margin, active_width, 63)`.
  - It sets how many top bits of `u` and `v` the fused branch comparator
    (`dialog_gcd_ccx_cmp_gt_truncated_into_width`) compares, at 1 Toffoli
    per bit.
  - With `WIDTH_MARGIN = 27`, the per-walk sum goes from 21,167 to 20,700
    bits (−467). 4 walks × 467 = 1,868, exactly the measured drop.
  - Steps where `SCHEDULE[step] + 5` is still ≥ 63, or ≥ `active_width`,
    are unchanged.
- `DIALOG_REROLL` 1 → 3 and `DIALOG_POST_SUB_REROLL` 12 → 18. Both are counts
  of identity `X;X` pairs. The first is emitted on `tx[0]` before the circuit,
  the second on `tx[1]` after the coordinate subtractions. The author searched
  the two jointly and found that no single-knob value gave a clean draw.

## Why it is still correct, and what it risks

The narrower comparator is approximate. When `u` and `v` tie on all compared
bits, the walk can take the wrong branch. Going from margin 8 to 5 makes those
ties up to 8 times more likely on the affected steps. The submission note
says the dialog-GCD body "shares a single Fiat–Shamir error budget across all
aggressive truncations". In practice this means a clean draw had to be hunted
over a two-dimensional reroll grid.

A failure shows as a classical mismatch, usually with ancilla garbage from the
reverse walk. The shipped pair (3, 18) draws 0 classical, 0 phase and 0
ancilla failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

The submission note calls `DIALOG_REROLL` a "gate-bearing pad". It is not.
Like `DIALOG_POST_SUB_REROLL`, it emits only `X;X` pairs, so it has no
Toffoli and no effect on the computation.

## Classification rationale

A narrower truncated comparator is comparator/width truncation, the same as
8316db1 and 4b68e94.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 335ac78 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 335ac78 14fc786 -- src/point_add` is
   10 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 14fc786 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   Expect:
   - 1571 qubits
   - 1,743,333 average Toffoli (rounded)
   - score 2,738,776,143
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 3`,
`DIALOG_POST_SUB_REROLL = 18` and an identical op stream. Any other change
needs a new reroll scan.

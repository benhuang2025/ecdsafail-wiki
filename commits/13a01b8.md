## Summary

This trades 56,230 Toffoli for 56 qubits, about 1,004 Toffoli per qubit.
The break-even rate is T/Q = 1,724,981 / 1411 ≈ 1,222 Toffoli per qubit, so
the score falls. It makes four changes
that together lower every phase that sat near the 1411 peak:

1. **Transcript runway, uncapped.** [`3166bbd`](3166bbd.md) parked the last
   3 (later 4) compressed transcript blocks on high `u` wires that the
   shrinking GCD no longer uses. The cap goes to 999, so the layout parks the
   longest suffix that fits: 49 of the 132 blocks, 245 qubits instead of 20.
2. **Composite scratch.** With most of high `u` now holding transcript, each
   GCD step's borrowed carry and gated lane is stitched together from every
   clean source: the unwritten transcript, the dead top of `v`, the dead top
   of `u` that holds no transcript, and only then fresh qubits.
3. **Four-chunk apply adder** with cuts at 56, 112 and 168. The widest chunk
   goes from 117 to 89 bits.
4. **Schoolbook x-tail square.** `ROUND84_XTAIL_KARATSUBA` goes from 1 to 0,
   so `λ²` uses the self-hosted low-qubit schoolbook square instead of the
   wider Karatsuba square.

Items 1 and 2 are gate-neutral. The Toffoli cost comes from items 3 and 4.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`.

### Background

See [`dd188f8`](dd188f8.md) and [`3166bbd`](3166bbd.md) for the compressed
transcript (5 qubits per 3 GCD steps, 132 blocks for 396 steps), the
per-block raw block and the first u-high runway. In this tree the runway was
4 blocks (`e0cfe2b`). This early codec is covered in
[transcript-codecs](../concepts/transcript-codecs.md); [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) covers its successor.

### 1. `DIALOG_GCD_COMPRESSED_LOG_U_HIGH_RUNWAY_BLOCKS`: 4 → 999

- `dialog_gcd_runway_layout()` tries suffixes starting at
  `blocks − cap` and returns the longest one whose cells all fit: hosts are
  assigned downward from `u[249]`, and a block's 5 hosts must sit at or above
  the largest `active_width` of its 3 steps.
- With 396 steps and `DIALOG_GCD_WIDTH_MARGIN = 26`, that is the suffix from
  block 83 (steps 249 onward, threshold 106) to block 131: 49 blocks, on
  `u[249]` down to `u[5]`. Block 83 sits on `u[245..250]`, far above its
  threshold, but every later block's threshold falls by only about 2.1 per
  block, slower than its hosts move down (5 wires per block). The gap closes
  at the end: block 131 sits on `u[5..10]` against a threshold of 4, so a
  50th block would not fit.
- `dialog_gcd_allocated_compressed_sidecar_bits()` therefore allocates 415
  transcript qubits instead of 640. That lowers every phase that holds the
  transcript: the forward and reverse GCD and, because parked cells stay
  live while the rest of `u` is released, the apply replay.
- No gates change: the same swaps and compressions happen, on different
  wires.

### 2. `DIALOG_GCD_COMPOSITE_SCRATCH=1`

- Each GCD step's controlled subtract (forward) or add (reverse) needs
  `want = 2·active_width − 1` clean wires: a carry lane and a gated-addend
  register. Before, `dialog_gcd_pick_runway_safe_borrow_slice` took a single
  source (the future transcript prefix, or a `u[aw..aw+want]` window that
  holds no transcript), and the adder allocated its own lane when neither
  fit.
- New `dialog_gcd_build_composite_scratch` collects wires in this order,
  skipping duplicates, the raw block and the active parts of `u` and `v`:
  1. the runway-safe prefix of the future transcript
     (`dialog_gcd_runway_safe_future_prefix`, cut at the first active `u`
     wire);
  2. `v[active_width..]`, which is |0⟩ by the same envelope premise as `u`;
  3. `u[active_width..]` wires that are not transcript cells;
  4. fresh qubits for whatever is still missing, freed at the end of the
     step.
- It is used in both
  `emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle`
  and its reverse. This is what keeps the late GCD steps from allocating a
  full lane now that high `u` is mostly transcript.

### 3. Four-chunk apply adder: `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS` 3 → 4, `DIALOG_GCD_APPLY_CHUNKED_F_CUSTOM4=1`, cuts 116/140 → 56/112/168

- New `dialog_gcd_apply_chunked_f_cut3()` and
  `dialog_gcd_apply_chunked_f_custom4_enabled()`. In `dialog_gcd_chunk_hi`,
  with 4 blocks and the custom flag, the boundaries are
  `[CUT, CUT2, CUT3]` (asserted strictly increasing).
- The chunked controlled modular add and subtract of the apply replay load
  one chunk of the addend at a time, with its own carry lane, so the widest
  chunk sets the phase's peak. Chunks go from 116/24/117 to 56/56/56/89 bits.
- The cost: the carry-outs of the boundaries are cleared by an exact
  comparator over the prefix up to the last cut, which grows from 140 to
  168 bits. There are 2 × 396 = 792 apply calls, so that is about
  792 × 28 = 22,176 Toffoli. (The same rate fits [`dd188f8`](dd188f8.md):
  +3 bits, +2,376.)

### 4. `ROUND84_XTAIL_KARATSUBA`: 1 → 0

- `round84_emit_fused_square_xtail` now falls through to
  `squaring_sub_from_acc_schoolbook_lowq_shift22`, because neither
  `ROUND84_XTAIL_WALK_SQUARE` nor `ROUND84_XTAIL_SCHOOLBOOK` is set. With
  `XTAIL_SQ_SELFHOST` on by default, its rows use the self-hosted fast
  adder of [`fb83e6c`](fb83e6c.md) (and the safe-lane reuse of
  [`e0cfe2b`](e0cfe2b.md)).
- The Karatsuba square holds a 512-qubit product register and the 258-qubit
  `z1` register together. The schoolbook square needs only the 512-qubit
  product register, a row and 2 extra carry qubits, so it is narrower. It
  does more partial-product work (about `n²` instead of `¾ n²`), which
  accounts for most of the rest of the Toffoli increase, roughly 34,000 by
  difference.
- See [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).

### 5. Reroll

`DIALOG_REROLL` 67 → 171, `DIALOG_POST_SUB_REROLL` 101 → 0. These counts of
identity `X;X` pairs only re-seed the Fiat–Shamir test inputs.

## Why it is still correct, and what it risks

- **The runway and the composite scratch add no new failure mode.** They rely
  on the same premise as the width truncation: `u` and `v` are 0 above
  `active_width(step)`. An input that breaks this already fails the
  truncation. The safety checks of `3166bbd` still apply: asserts stop a
  parked block from being written or read while its hosts are inside the
  active prefix, and scratch never overlaps active `u`, active `v`, the raw
  block or a transcript cell. If the premise failed, the run would show
  classical or ancilla failures.
- **The 4-chunk adder and the schoolbook square are exact.**
- No truncation knob changed. The comparator cap stays at 58 and the width
  margin at 26.
- The shipped reroll (171, 0) is clean: 0 classical, 0 phase and 0 ancilla
  failures over all 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The two GCD changes, which enable the rest, put registers on wires that are
already allocated and known to be |0⟩. That is scratch/ancilla reuse. The
chunk layout and the square swap are peak rebalances that buy qubits with
Toffoli. One could also file the square swap under Algorithmic Substitution,
as a multiplier/squarer swap, but it reverts to a squarer already in the
tree and serves the same peak goal.

   and run `git checkout e0cfe2b -- src/point_add`.
   - The git parent is `5b5a5d4` (teddyjfpender), which set
     `DIALOG_GCD_COMPARE_BITS` 58 → 56 with its own reroll. This commit was
     built on `e0cfe2b` and keeps 58, so diffing against the parent (157
     lines) would also show a revert of that comparator cut and its comment.
   - `git diff --ignore-cr-at-eol e0cfe2b 13a01b8 -- src/point_add` is 150
     lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 13a01b8 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `ROUND84_*`, `XTAIL_*` or `SQUARE_*` environment variables
   set, because `set_default_env` keeps any value already in the
   environment. Expect:
   - 1355 qubits
   - 1,781,211 average Toffoli (rounded)
   - score 2,413,540,905
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL=171`,
`DIALOG_POST_SUB_REROLL=0` and an identical op stream. Any other change
needs a new reroll search.

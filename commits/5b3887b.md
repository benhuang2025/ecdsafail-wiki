## Summary

This is the same lever as the author's earlier [01260e8](01260e8.md)
(margin 25 → 18), pushed much further. It starts again from robertkodra's
`a772a45` tree and ignores the four commits in between (`9d30eb7`,
`01260e8`, `c6cc74e`, `657ae28`). It sets the
dialog-GCD width envelope `256 − slope·step + margin` to margin 12 and slope
0.948. The slope change slightly widens the late steps (0.948 < 0.950), and
the margin cut narrows every step by up to 13 bits.

Each step-bit costs 4 Toffoli in the K=2 walk, plus capped comparator bits.
The saving is 50,664 Toffoli, exactly what the width formula predicts. Qubits
are unchanged. As in [01260e8](01260e8.md), the inherited nonce
`141744616447148` happened to draw a clean test set again.

## What changed and why it saves Toffoli

`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:

- `DIALOG_GCD_WIDTH_MARGIN`: 25 → 12.
- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 950 → 948.
- `DIALOG_TAIL_NONCE` stays `141744616447148`.

Both knobs feed `dialog_gcd_tobitvector_active_width(step)`, which returns
`256 − slope·step + margin`, rounded up to an even number and clamped to
[1, 256]. That width bounds four loops in each walk step, each about 1 Toffoli
per bit:
- the branch `cswap`;
- the gated load;
- the subtract or add body;
- the K=2 conditional-shift cascade.

It also caps the branch comparator at `min(74, active_width)`. See
[01260e8](01260e8.md).

Replaying the formula over the 259 steps:

| | summed width per walk | summed comparator width | steps clamped at 256 |
| --- | --- | --- | --- |
| base (25, 0.950) | 40,922 | 18,422 | 29 |
| this commit (12, 0.948) | 37,900 | 17,844 | 15 |

Per walk that is 4 × 3,022 + 578 = 12,666 Toffoli. The four walks give
50,664, the measured drop. With slope 0.950, margin 12 alone would have been
72 width bits narrower per walk. So the slope change gives back about 1,250
Toffoli, presumably to keep the late steps safe. The runway transcript
allocation falls from 488 to 472 bits. The peak is still set by the apply
chunked add, so it stays at 1390.

## Why it is still correct, and what it risks

The envelope is a statistical fit. Every bit above `active_width` is assumed
to be 0 in both `u` and `v`. The swap, the subtract and the second shift
ignore it, and part of the transcript is parked on high `u` lanes on the same
assumption. An input whose GCD values shrink more slowly than the line breaks
the walk: the result is a classical mismatch, and ancilla garbage after the
reverse walk.

A 13-bit cut removes most of the safety margin that the earlier lineage kept
(37 bits in the original baseline). The failure rate must still be low,
because the inherited nonce, picked for a different op stream, gave 0
classical, 0 phase and 0 ancilla failures over all 9,024 shots for this one.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A narrower per-step register width is comparator/width truncation. The slope
change goes the other way, slightly widening the late steps. It is part of
the same envelope re-fit.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a772a45 -- src/point_add`.
   - Do not start from the git parent `657ae28`. That is PhantasticUniverse's
     tree, which sits on robertkodra's margin 17. johnbxx's `9d30eb7` is a git
     ancestor, but [01260e8](01260e8.md) dropped its changes.
   - Against the parent, the diff would also undo the late-band body trim
     `DIALOG_GCD_BODY_CARRY_BAND_TRIMS` (its function, its `step` plumbing and
     its default), and put the nonce back from 33 to 141744616447148.
   - Against `a772a45`, `git diff --ignore-cr-at-eol a772a45 5b3887b -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 5b3887b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,579,823 average Toffoli (rounded)
   - score 2,195,953,970
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=141744616447148` and an
identical op stream. Any other change needs a new nonce hunt.

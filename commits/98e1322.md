## Summary

[`08c5068`](08c5068.md) carried `DIALOG_GCD_APPLY_FINAL_TOPCLEAN=5` over from
the 1285-qubit frontier. In the final chunk of the apply phase's chunked
add/sub, it ran the top 5 bits as an in-place MAJ/UMA ripple, which needs no
carry wire but costs 2 Toffoli per bit, instead of the usual measured-carry
ripple, which costs 1 Toffoli per bit plus one carry wire per bit.

On the 1220-qubit route that saving of 5 wires is not needed, because the apply
ripple is already below the peak. This commit sets the knob back to 0, so the
final chunk uses the plain measured-carry adder. The saving is 2,591 Toffoli,
about 5 per call over 2 × 258 calls. The peak stays at 1220. The change is
exact, but the op stream changed, so the nonce was re-hunted.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_APPLY_FINAL_TOPCLEAN`: 5 → 0.**
   - Read by `dialog_gcd_apply_final_topclean_bits()`
     (`rounds/dialog/config.rs`). In `dialog_gcd_add_ctrl_chunked_low_to_ext`
     and `dialog_gcd_sub_ctrl_chunked_low_to_ext` (`rounds/dialog/mod.rs`),
     phase `dialog_gcd_apply_chunk_{add,sub}_final_ripple`:
     - with a value above 0, the final chunk calls
       `cuccaro_{add,sub}_fast_low_to_ext_topclean(..., 5)`;
     - with 0, and with `..._FINAL_WINDOWED_FAST_BLOCKS=0` and
       `..._FINAL_LOWQ=0`, it falls through to `cuccaro_{add,sub}_fast_low_to_ext`.
   - The top-clean adder (`arith/adder.rs`) allocates carries only for the low
     `n − 5` bits. Those cost one CCX each, with measured uncompute. It runs
     `maj`/`uma` on the top 5 bits, at 2 CCX each. The fast adder uses
     measured carries on all bits.
   - So going back saves about one CCX on each of the top 5 bits per call.
     There is one call in each step of the forward apply (add) and one in each
     step of the reverse apply (subtract), so about 5 × 516 ≈ 2,580, against
     the measured 2,591.
2. **`DIALOG_TAIL_NONCE`** (the top-of-route pin, which is the one that takes
   effect): 5200018704193 → 307003737209.

**Why the peak does not move.** The fast adder holds 5 more carry wires during
the final apply chunk. After the 10/11-chunk retunes of
[`7689eac`](7689eac.md) and [`572bba4`](572bba4.md), that phase is below the
1220-qubit binders, which are the windowed square and the round84 fold. So
the extra wires fit under the peak.

## Why it is still correct, and what it risks

Both adders compute the same sum exactly. The measured-carry adder erases each
carry with `hmr` + `cz_if`, which is phase-exact. So this change adds no
truncation and no new failure mode. The submission note says "value-exact ...
ancilla-garbage 0; peak unchanged". Correctness on the test set still depends
on the inherited probabilistic knobs, which are unchanged.

The shipped nonce `307003737209` draws a clean set: 9,024 of 9,024 shots, with
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is Dead-Code and Redundancy Elimination → fold/carry
truncation. The diff does not truncate anything. It swaps a partly coherent
adder (MAJ/UMA on the top 5 bits) for the fully measured-carry fast adder,
spending 5 qubits of slack under the peak to save Toffoli. That is closer to
Strength Reduction → fast-adder reroute. The carry chain in question is not a
fold.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 997dbd6 -- src/point_add`.
   - Do not start from the git parent `f4404de`. That tree has jackylee0424's
     `ROUND84_INPLACE_QUOTIENT_CARRY_TRUNC_W=20` and nonce 310772318.
   - Diffing against the parent would wrongly show this commit putting the
     window back to 21, and rewriting the lower stale nonce pin from 310772318
     to 165002130437.
   - Against `997dbd6`, `git diff --ignore-cr-at-eol 997dbd6 98e1322 -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 98e1322 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `ROUND84_*`, `R84_*`, `SQUARE_*` or `MOD_*`
   environment variables set, because they override the route defaults.
   Expect:
   - 1220 qubits
   - 1,401,609 average Toffoli (rounded)
   - score 1,709,962,980
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=307003737209` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

This is the third time the same edit landed, after [`4b9cfbb`](4b9cfbb.md)
and [`acf2bdb`](acf2bdb.md). Gajesh2007's [`f8a36ba`](f8a36ba.md) line was
built from a tree that did not have the edit, so it was missing there.

The apply loop has three 20-bit comparisons that clear the overflow or
underflow wire of the modular add and subtract. Each one moves from
`cmp_lt_into`, which costs 2 Toffoli per bit and has no carry wires, to
`cmp_lt_into_fast`, which costs 1 Toffoli per bit and erases its carries by
measurement. There are 1,197 calls, each saving 20 Toffoli, so 23,940 Toffoli
in total. Qubits are unchanged. The reroll goes from 22 to 21.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`:

- In `dialog_gcd_cmod_add_materialized_pseudomersenne`, the `overflow_clean`
  call changes from `cmp_lt_into(acc[236..], f[236..], acc_ovf)` to
  `cmp_lt_into_fast(...)`.
- In `dialog_gcd_cmod_sub_materialized_pseudomersenne` and
  `..._borrowed_subtrahend`, the two `underflow_clean` calls that compute
  and clear `underflow_pred` change the same way. The base's
  measured-underflow gate sits between those two calls and is kept.
- In `configure_ecdsafail_submission_route()`, `DIALOG_REROLL` changes from
  22 to 21, and the comment is updated.

**Cost.** `cmp_lt_into` uses n MAJ gates and then n inverse MAJ gates, so
2n CCX. `cmp_lt_into_fast` uses n carry CCX and then erases them with
`hmr` + `cz_if`, which costs no Toffoli. See
[measurement-uncompute](../concepts/measurement-uncompute.md). The window is
n = `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` = 20.

**Count.** The calls are:

- 399, one in each of pair 2's forward-apply adds;
- 798, two in each of pair 1's reverse-apply subtracts.

That is 1,197 × 20 = 23,940, the measured drop.

**Peak.** The 21 transient wires are taken only after the raw sum's carry
wires are freed, so the peak stays at 1698.

## Why it is still correct, and what it risks

The commit only changes how the carries are erased, and the measured erase is
exact. The 20-bit window approximation is unchanged. It fails with
probability about 2^−20 per call, when the operands tie on their top 20 bits,
and a failure would show up as ancilla or phase garbage. Reroll 21 draws a
clean set for the new op stream: 0 classical, 0 phase and 0 ancilla failures
over 9,024 shots.

## Classification rationale

The commit only changes how the comparator's carries are erased, from a
reverse sweep to measurement. That is measurement uncompute, the same as
`4b9cfbb`.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ad02935 -- src/point_add`.
   - Do not start from the git parent `0261289`. This commit was built on
     Gajesh2007's `ad02935`.
   - Against the parent, the diff is 324 lines. It would also revert several
     changes:
     - the odd-u fastpath from [`0261289`](0261289.md);
     - the 396-step cut from [`dd103cd`](dd103cd.md);
     - the compare cap 62 from [`27530d2`](27530d2.md).
   - Against `ad02935`, `git diff --ignore-cr-at-eol ad02935 985ae0f -- src/point_add`
     is 18 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 985ae0f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1698 qubits
   - 1,673,629 average Toffoli (rounded)
   - score 2,841,822,042
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 21 and an identical op
stream. Any other change needs a new reroll search.

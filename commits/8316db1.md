## Summary

In early June the circuit divides with the *dialog GCD*: a 399-step binary
GCD walk on `(u, v) = (p, dx)` whose per-step branch decision depends on a
truncated comparison `u > v` of the top few bits. The number of bits compared
at each step comes from a baked per-step table plus a global margin. This
commit lowers the margin from 6 to 5, so 179 of the 399 steps compare one bit
fewer. Each comparator bit costs one Toffoli, and each of the four GCD walks in
a point addition runs the comparator, so the saving is 4 × 179 = 716 Toffoli.
Qubits are unchanged. The Fiat–Shamir reroll count was re-tuned so that the
new op stream draws a clean test set.

## What changed and why it saves Toffoli

Background (the June dialog-GCD route, `emit_dialog_gcd_raw_pa` in
`src/point_add/mod.rs`; see [dialog-gcd-early](../concepts/dialog-gcd-early.md)). The same dialog-GCD
machinery runs twice: `emit_dialog_gcd_raw_quotient` (λ = dy/dx)
and `emit_dialog_gcd_raw_ipmul` (a multiply). Each runs a forward walk
(`..._tobitvector_steps_block_lifecycle`), an apply pass on 256-bit Bézout
registers, and a reverse walk, so a point addition has four walks. One walk
step at index `step` does:

```
b0        = v[0]                                   # v odd -> subtract
b0_and_b1 = b0 AND (u > v on the top compare_bits)  # fused CCX comparator
cswap(b0_and_b1, u[..w], v[..w])                    # w = active_width(step)
if b0: v -= u   (over w bits)
v >>= 1                                             # free wire rotation
```

The two raw bits per step are packed three steps at a time into 5 qubits of
the compressed log (`emit_dialog_gcd_round763_compressor`; 3 reachable
symbols per step, 27 < 32).

The change:

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN` default 6 → 5.
- It is read by `dialog_gcd_compare_bits_for_step(step, active_width)`, which
  returns
  `min(DIALOG_GCD_PA9024_COMPARE_SCHEDULE[step] + margin, active_width, DIALOG_GCD_COMPARE_BITS = 63)`.
  The schedule is a baked 399-entry table (values 1–73) fitted to the inputs.
- `dialog_gcd_ccx_cmp_gt_truncated_into_width` compares only
  `v[w-k..w] < u[w-k..w]` with `k` = that value, using `ccx_cmp_lt_into_fast`
  (one Toffoli per bit, carries erased by measurement).
- Summed over the 399 steps (with `WIDTH_MARGIN = 28`), the comparator width
  goes from 20,964 to 20,785 bits per walk: 179 steps lose a bit. The others are
  capped by the 63-bit global limit or by `active_width`. Four walks give
  4 × 179 = 716 Toffoli, exactly the measured drop.
- `DIALOG_REROLL` default 29 → 27. `build()` emits this many `X;X` pairs on
  `tx[0]` before the circuit. They are an exact identity with no Toffoli, but
  they change the op-stream hash and therefore the 9,024 test inputs. This is
  the June form of the tail nonce.

## Why it is still correct, and what it risks

The comparator is approximate. When `u` and `v` agree on all `k` compared
bits, it reports "not less" even when the low bits say otherwise. The walk
then skips a swap it needed, the subtraction `v -= u` wraps, and the input
does not reach `(1, 0)` in 399 steps. One bit fewer roughly
doubles that per-step tie probability on the affected steps. The submission
note calls the tail "measure-zero", which is not accurate: it is a real but
small failure rate. That is why margin 4 and the next carry-window tightening
were rejected on every reroll the author screened.

A wrong branch shows up as a classical mismatch (the output point is wrong)
and usually also as ancilla garbage, because the reverse walk no longer
restores `u` and `v`. The shipped reroll 27 draws a test set with 0 classical,
0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a narrower truncated comparator, which is
comparator/width truncation. The reroll is the nonce that comes with every
change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 1fd942d -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 1fd942d 8316db1 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8316db1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because they override the
   defaults that `configure_ecdsafail_submission_route()` sets. Expect:
   - 1698 qubits
   - 1,666,885 average Toffoli (rounded)
   - score 2,830,370,730
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 27` and an identical op
stream. Any other change needs a new reroll scan.

## Summary

Each replay cell's 256-bit add is split into chunks so that its carry ladder
fits under the qubit budget. The carry that crosses a chunk boundary is not
uncomputed with gates. It is measured out with `hmr`, and its phase is
repaired by a compare of the top `k` bits of the chunk below the boundary,
run only when the measurement outcome is 1.

This commit pins `k` (`SUB4_PP_REPLAY_CHUNK_COMPARE`) at 21 instead of 22.
That saves one Toffoli per boundary repair on about half the shots, 1,238
average Toffoli in total, at the same 1266 qubits. The compare is now wrong a
little more often, so λ rises and a new nonce was hunted. The change follows
straight on [`52da1ec`](52da1ec.md), which did the same to the overflow-flag
compare.

## What changed and why it saves Toffoli

1. **`SUB4_PP_REPLAY_CHUNK_COMPARE` 22 → 21**, a `set_default_env` pin in
   `build()`, `src/point_add/mod.rs`. `replay_chunk_compare()` in
   `src/point_add/pingpong_div.rs` reads it in two places.
   - **The boundary erase** in `add_chunked_measured_with`. Each boundary
     carry is erased as soon as the next chunk has consumed it:
     ```
     compare = min(k, chunk width)
     b.hmr(carry, phase);
     cmp_lt_phase_conditioned(b, &acc[hi-compare..hi], &addend[hi-compare..hi], phase);
     ```
     The carry out of a chunk equals `[acc_chunk < addend_chunk]` after the
     add. The conditioned compare recomputes that from the top `compare` bits
     and applies the cancelling phase. It costs about `compare` Toffoli and
     runs on about half the shots. See
     [measurement-uncompute](../concepts/measurement-uncompute.md).
   - **The layout chooser `chunk_layout`.** It uses `k` as the width below
     which a leading chunk's repair is exact: chunk 0 has no carry-in, so if
     it is at most `k` bits wide, the compare covers the whole chunk. With
     `k` = 21, that free leading chunk is one bit narrower, so the layouts the
     budget picks can shift slightly.
   - These adds run in every replay cell, in both traversals (the divide's
     `signed_mod_add_pm_halve_fused`, the multiply's
     `signed_mod_double_add_pm_fused`, and the unfused `signed_mod_add_pm`).
     A replay add usually has one or two approximate boundaries, so one bit
     off each repair, at half rate, adds up to the 1,238 saved. See
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
2. **Tail nonce:** `SUB4_PINGPONG_TAIL_NONCE` default 1562067597 →
   75787140768792.

## Why it is still correct, and what it risks

- **The chunk values are exact.** Only the phase repair is approximate. The
  truncated compare is wrong when the two operands' top `compare` bits tie
  and the lower bits would have decided. That is about 2^-k per boundary, so
  22 → 21 roughly doubles the rate.
- A wrong repair is a phase error only, caught by the phase channel. An
  earlier in-code note on this knob (above `replay_chunk_compare()`, written
  on a sibling tree) measured identical classical-failure counts for windows
  20, 21, 22 and 24; only the phase λ moved.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is one bit off a truncated compare window. That is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 52da1ec -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 52da1ec db7623e -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol db7623e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1266 qubits
   - 903,502 average Toffoli (rounded)
   - score 1,143,833,532
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `75787140768792` and an identical op
stream. Any other change needs a new nonce hunt.

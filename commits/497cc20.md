## Summary

The scorer charges a CCX one Toffoli whenever its classical condition is true,
even if one of its quantum controls is always |0⟩. Then the gate does nothing.
If one control is always |1⟩, the gate is really a CX, which is free.

This commit adds a post-pass, `constprop.rs`, that runs over the finished op
stream. It tracks every qubit and classical bit as Zero, One or Unknown,
starting from the fact that all ancillas start at |0⟩. CCX gates with a
provably constant control are dropped or folded to CX or X. The author's run
counts 679 drops and 575 folds to CX, which removes 1,254 emitted Toffoli. The
average executed Toffoli falls by 1,236 against `916c0e3`. Peak qubits stay at
1166. The rewrite is exact, but the op stream changed, so the tail nonce was
re-hunted.

## What changed and why it saves Toffoli

### New file `src/point_add/trailmix_ludicrous/constprop.rs` (607 lines, copied)

- **Lattice and seeds.** Each qubit gets a value in `{Zero, One, Unknown}`. All qubits
  start at `Zero`, except the input registers, which start at `Unknown`. The inputs are
  reg0 = `x2_init` (P.x) and reg1 = `y2` (P.y), and the caller passes them in. All
  classical bits start at `Zero`.
- **Transfer rules** (`analyze`), applied in stream order:
  - `X` and `CX` use XOR on known values.
  - `CCX` uses `target ^= AND(c1, c2)`.
  - `R` and `Hmr` set the qubit to `Zero`. `Hmr` also sets its classical bit to `Unknown`.
  - `BitStore0/1` and `BitInvert` update bits.
  - `Swap` exchanges the two values.
  - Phase ops (`Z`, `CZ`, `CCZ`, `Neg`) change nothing.
  - An op's classical condition is "always true" only if every bit on the
    `PushCondition` stack, and its own `c_condition`, is provably `One`. When the
    condition may be false, the write is merged: the result stays known only if the
    old and new values agree, and otherwise becomes `Unknown`.
- **Rewrite** (`apply_decisions`), for every CCX:
  - If either control is provably `Zero`, the gate is dropped (`DropZeroCtrl`). This
    does not depend on the classical condition, since a zero control makes the gate
    a no-op on every shot.
  - If exactly one control is provably `One`, it becomes a CX on the other control
    (`FoldCx`), keeping `c_condition`.
  - If both controls are `One`, it becomes an X on the target (`FoldX`).
- **`run(ops, input_qubits)`** prints `CONSTPROP ccx_total=… dropped=… folded_cx=… folded_x=…`.
  - With `CONSTPROP_VERIFY=<n>`, it first runs the *unmodified* stream through a
    copy of the simulator loop (`step_and_check`) on `n` extra input draws of 9,024
    shots each.
  - It undoes any rewrite whose claimed constant was ever violated. This is a
    debug cross-check, and the grader build does not set it.

**Where the constants come from.** The note does not list the gates. One
source is clear in the code. `forward_gcd_jump` loads its register `u` with the
constant q, using X gates on fresh ancillas, so `u`'s bits are known `One` or
`Zero`. They stay known until the first controlled swap with `v` mixes them.
Any carry, compare or subtract CCX on those bits in the first steps of each
walk is then removable. Fresh zero carry-ins and pads are another likely
source. I did not check which gates account for the 1,254.

### Edited `src/point_add/trailmix_ludicrous/mod.rs`

- It adds `mod constprop;`.
- At the end of `build_trailmix_ludicrous_ops()`, after the result routing swaps and the
  96-op nonce tail, the stream is passed through
  `constprop::run(ops, &input_qubits)`, with `input_qubits = x2_init ++ y2`.
- `CONSTPROP_DISABLE=1` skips the pass.
- The tail's `X;X` pairs act on input qubits (`Unknown`), so the pass never touches the tail.

### New file `src/point_add/island_search.rs` (747 lines, copied, not compiled)

This is a CPU nonce-search driver. It absorbs the fixed op-stream prefix into
SHAKE256 once, then for each candidate nonce absorbs only the 96-op tail and
runs the classical GCD prefilter on all 9,024 shots. No `mod island_search;`
line exists anywhere, so the file is not part of the build. It is tooling that
was committed alongside.

### Edited `src/point_add/mod.rs`

The default `DIALOG_TAIL_NONCE` in `build()` goes from 100000009632 to 400002427.

## Why it is still correct, and what it risks

The pass is exact by construction: a gate is rewritten only when its control is
proved constant on every basis input. Dropping a CCX whose control is always 0,
or replacing `CCX(1, c, t)` by `CX(c, t)`, leaves the unitary unchanged on every
input and every shot. It also does not touch phases.

There is one gap in the argument. The classical bit registers reg2 and reg3,
which hold Q.x and Q.y, are filled per shot, but the analysis seeds all bits
`Zero`. This is harmless as long as the circuit never inverts or stores into those bits.

- A `Zero` seed is never treated as an always-true condition.
- Writes under a maybe-false condition are only merged.

I did not check that no such op exists. The author's empirical cross-check
found no violated claim over 270,720 inputs (30 draws × 9,024 shots).

A wrong rewrite would show up as classical mismatches or ancilla garbage. The
new nonce `400002427` gives 0 classical, 0 phase and 0 ancilla failures over
all 9,024 shots. The circuit's other approximations, the trailmix `ITERS`,
`SCHED_J2`, `GAP_J2` and truncated folds, are unchanged. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The pass derives constant values of quantum wires on the host and specializes
the gates that use them. That fits constant propagation and classical
specialization. The runner-up is **Dead-Code and Redundancy Elimination →
dead-gate/self-inverse removal**, because 679 of the 1,254 removed Toffoli are
outright deletions of no-op gates. See [dead-gate-strip](../concepts/dead-gate-strip.md),
which describes this `constprop.rs` as an exact removal.

   and run `git checkout 916c0e3 -- src/point_add`.
   - `git diff --ignore-cr-at-eol 916c0e3 497cc20 -- src/point_add` is 4 files, 1,369 added lines,
     almost all in the two new files.

     `LUD_EXTRA_FOLD_MIN_G` 18 → 24, and the duplicated knobs in
     `configure_ecdsafail_submission_route()`. This commit was built on the
     tree without that change.
2. **Copy the two new files from the commit:**
   `git checkout 497cc20 -- src/point_add/trailmix_ludicrous/constprop.rs src/point_add/island_search.rs`.
   - `constprop.rs` is the pass described above.
   - `island_search.rs` is uncompiled nonce-search tooling.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It covers `mod.rs` and `trailmix_ludicrous/mod.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol 497cc20 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*`
   environment variables set. Expect:
   - 1166 qubits
   - 1,414,835 average Toffoli (rounded; 1,414,835.003 before rounding)
   - score 1,649,697,610
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `400002427` and an identical op
stream. Any other change needs a new nonce hunt.

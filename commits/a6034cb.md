## Summary

The division cells use a "retained prebias" route that folds the cell's
overflow into the top of its add instead of measuring it out with a flag
compare. That route needs free wires for its fold. When the room under the
1171 cap is short, it splits a carry prefix off the top chunk, and that
prefix costs a measured compare to erase. If the shortfall is too large, the
cell falls back to the plain route.

q71d adds a per-cell table, `q71d_need.txt`, that lowers the declared
workspace need on 32 late division cells. On those cells the plan finds a
smaller shortfall. The prefix is shorter or gone, and more cells qualify for
the retained route. The code comment describes the change as "32 div cells
P->R, fold workspace shortfall taken by the exact direct_plan split instead
of the carry prefix".

The op stream changes inside those cells, so the rewrite table is re-ported:

- 345 of q71b's 450 rows survive;
- 105 rows are lost, 79 of them in the changed cells.

The net is −104 Toffoli at the same 1171 qubits. The author measured +0.022
± 0.020 λ for the need table and calls it a sell.

## What changed and why it saves Toffoli

### 1. `S5_NEED_ADJ` in the two fold planners

`retained_prebias::plan()` (division cells) and `joint_lowfold::plan()`
(multiply cells) both size the top chunk of the cell's add like this:

```
need     = max(bits − 3, fw − 34)            // fold workspace the plan reserves
existing = room − (hi − lo) − 3               // (− 3 or − 4 in joint_lowfold)
missing  = max(need − existing, 0)
prefix   = missing == 0 ? 0 : missing + 1     // bits split off the top chunk
saving   = (fk − 1)/2 − missing/2 − (bits − 33) − db
```

The commit subtracts the cell pin `S5_NEED_ADJ` from `need` (saturating).

- **The route.** `try_replay` adds the low part of the top chunk `[lo, lo +
  prefix)` first. It holds the carry `m`, runs the rest of the chunk with
  the fold consumed inside the ripple, and then erases `m` with
  `erase_with_compare(m, b[lo..split], a[lo..split], cin)`. That compare
  runs over the whole prefix with its carry-in, so it is exact. Its cost is
  about `prefix/2` executed Toffoli.
- **What a lower need does.**
  - It shrinks `missing`, so the prefix is shorter.
  - It raises the plan's `saving`, so cells that returned `None` (saving ≤ 0,
    or `prefix + 1 ≥ hi − lo`) now take the retained route. The retained
    route saves the cell's flag-compare erase, the `(fk − 1)/2` term.
- **Where the shortfall goes.** The fold itself still needs its wires. In
  `joint_prebias::mapped_zero`, when `n − 2 > room` the fold's add is laid
  out by `width_composition::direct_plan`. That is a staged split with
  recomputed carries and no comparator.
- **Scope.** Division cells reach only `retained_prebias`, because
  `joint_lowfold::plan` returns `None` for division when
  `PP_PREBIAS_RETAIN_BITS` is set (it is, to 32). The `joint_lowfold` edit
  matters only for multiply cells listed in the table, and q71d lists none.

See [pingpong-division](../concepts/pingpong-division.md) and
[modular-fold](../concepts/modular-fold.md) for the replay cell and its
fold, and [measurement-uncompute](../concepts/measurement-uncompute.md) for
the measured erase.

### 2. `q71d_need.txt` (new, 32 lines, read in `k3b_cell`)

- `k3b_cell` loads the table when `S5_NEED_FILE` is set; the recipe sets it
  to `1`. For a listed cell it inserts the pin `S5_NEED_ADJ=adj`.
- Lines are `idx adj`. `idx` is the cell call index, the same counter the
  bridge/room table uses.
- The cells are idx 347–386 (32 of them, with gaps). The adjustments range
  from 1 to 12 and sum to 263.
- The table is compiled in with `include_str!`, with the comment "the
  official runner denies file reads".

### 3. Rewrite rows: `q71b_rewrite.txt` (450) → `q71d_rewrite.txt` (345)

- The submission note describes the port. 345 rows "were mapped by op-window
  matching plus a neighbour-shift recovery pass". The other 105, "79 of them
  in the division cells whose code the need table changes, have no exact
  counterpart and were dropped".
- The loader is unchanged. It needs one global shift. See
  [dead-gate-strip](../concepts/dead-gate-strip.md).
- Losing 105 rows puts back about 105 CCX per shot. By that count the need
  table itself saves on the order of 200 Toffoli. That is an estimate from
  the −104 net, not a measurement.
- The `mod.rs` comments are updated to "q71d package … 345 rewrite rows".

### 4. Tail nonce

`TAIL_NONCE` goes from 29000769323351 to 30000833880904.

## Why it is still correct, and what it risks

- **Exact parts.** The prefix erase and the `direct_plan` split are both
  exact. The code comment calls the split "exact".
- **What adds error.**
  - The retained route folds with a finite low cut of `bits` = 32
    (`PP_PREBIAS_RETAIN_BITS`), which is an approximation. Moving more
    cells onto it adds that route's error. A wrong fold gives a
    **classical** failure.
  - The author measured +0.022 ± 0.020 λ on 400 paired nonces, about one
    standard error.
- **λ.** The 16,384-nonce confirmation gives 19.318 ± 0.032 (est + 2 SE
  19.382), below the 19.5 limit of the 8ee337c note. The mean T on that run
  is 945,844.53, against 945,945.06 for q71b.
- **The 345 kept rows** are asserted against the new stream. They carry the
  same proofs, and the same census caveat, as in q71a and q71b.
- The shipped nonce `30000833880904` draws a clean island: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The lever changes how each cell spends its free room under the fixed cap.
It hands the fold's workspace shortfall to a staged split, so the carry
prefix and its compare shrink and the retained route becomes affordable.
That is ancilla-lifetime / venting, a room-allocation choice. The runner-up
was comparator/width truncation, since part of the saving is fewer
compare bits on the prefix erase. The prefix compare, however, stays exact.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a1e2b66 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol a1e2b66 a6034cb -- src/point_add` is
   847 lines in 7 files. Most of it is the deleted q71b table and the new
   q71d table.
2. **Delete the old table and copy the new one.** Delete `q71b_rewrite.txt`
   with the `rm` command under Patch below. Then copy the re-ported table
   from the commit:
   `git checkout a6034cb -- src/point_add/skywalk_data/q71d_rewrite.txt`.
   It holds the 345 rows described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `heo_carry.rs`, `joint_lowfold.rs`, `mod.rs`,
   `retained_prebias.rs` and the new `q71d_need.txt`.
4. **Check the tree.** `git diff --ignore-cr-at-eol a6034cb -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `S5_*`, `PP_*` and `SUB4_*` overrides have no effect. Do
   not set them anyway. Expect:
   - 1171 qubits
   - 945,839 average Toffoli (945,839.135 before rounding, by the submission
     note)
   - score 1,107,577,469
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `30000833880904` and an identical
op stream.

## Summary

The squarer builds `λ²` from small "leaf" squares of about 32 bits. Each leaf
is a triangle of shifted row adds, and row 0 is the first of them. Row 0 adds
into an all-zero window, so its result is a simple function of the input
bits, but the base still ran a full Toffoli ripple for it.

This commit writes a value one less than row 0's result instead. That value is
a plain bitwise copy, `x0 ? v : ~v`, made of CX and X gates only. Each leaf
then holds `x² − 2` instead of `x²`. These known constant errors add up through
the Karatsuba tree to one constant offset on the square's output. The host
computes that offset mod p and adds it to the classical `3·ox` operand of the
preceding `coord_add3x` phase, where it costs no Toffoli. About 30 Toffoli per
leaf disappear. The commit also widens one truncated compare by a bit
(`ERASE_COMPARE` 22 → 23), which costs a few Toffoli back. Net −831 Toffoli at
the same 1251 qubits.

## What changed and why it saves Toffoli

### Row 0 becomes a copy (`src/point_add/square.rs`)

- New switch `row0_copy()`: true when `SQ_ROW0_COPY` and `SQ_CIN_SPREAD` are
  both on. `mod.rs` pins `"SQ_ROW0_COPY" => "1"`.
- In `tri_square_cin(x, product, inverse)` (an `m`-bit leaf), row `i` adds
  `(2·x_i − 1)(v + x_i)` into `product[2i+1 ..]`, where `v = x[i+1..]`
  (see `row_addsub_cin`). Row 0 sees a zero window, so its `m`-bit result is
  `F = x0 ? v + 1 : 2^(m−1) − v`, placed at bit 1.
- The new branch, taken for `i == 0` in both directions, stores
  `F − 1 = x0 ? v : ~v` instead:
  `for j in 0..m-1 { cx(x[j+1], row[j]); x(row[j]); cx(x[0], row[j]); }`.
  That is `row[j] = x[j+1] XOR NOT x0`. The top row bit stays 0. The gates are
  self-inverse, so the inverse square runs the same three gates per bit.
- Saving: the forward row 0 used to be a ripple with one Toffoli per carry
  (`SQ_ROW0_CARRY` already made the first carry a copy). Under the split
  policy 7 used here, each of the three branch squares (A, B, C) has 9 leaves
  of 32 to 34 bits, 27 leaves in all, so roughly 27 × 30 Toffoli go. The
  inverse row 0 was already a known-output adder (`SQ_ROW0_INVERSE_CARRIES`)
  with almost no Toffoli; it is now a copy too. See
  [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md) and
  [adders-and-carries](../concepts/adders-and-carries.md).

### Keeping the identities exact downstream (`square.rs`)

Writing `F − 1` at bit 1 subtracts 2, so a leaf holds `x² − 2`. Several later
steps assumed exact bit patterns of `x²`, and get X fix-ups:

- `tri_square_k2r_inner` and `tri_square_k2r_inv`: `b2` (the high child's
  square) now holds `b² + Nb` with `Nb ≡ 2 (mod 4)`, so its bit 1 is always
  set. `x(b2[1])` before and after each add/subtract of `b2` into `cross`
  clears it, which keeps the bit-1 carry identities (`Carry1::CopiesCarry0`,
  known-top adds) valid and adds 2 to the node's cross offset.
- `assembly_loans`, `assembly_repay`, `assembly_repay_held`: `product[1]` is
  now 1 instead of 0 at the loan point, so it gets an `x()` around the loan.
- `cross2_erase` / `cross2_restore` (the `SQ_LEND_RETAINED_CROSS2` loan):
  each node's cross offset is 4 (mod 8), which flips cross bit 2. The erase
  unflips it before `hmr` so the CZ phase repair stays exact, and the restore
  flips it back.

### The offset is computed on the host (`square.rs`, `classical.rs`)

- `k2r_offset(m, flat)` mirrors the split decisions of
  `tri_square_k2r_inner`. A leaf contributes `−2`. A node with children
  offsets `Na`, `Nb`, `Nt` stores `x² + Na + c·2^lo + Nb·2^(2lo)`, where
  `c = Nt − Na − Nb + 2` (the +2 is the cleared `b2[1]`). All of this is
  plain `U256` arithmetic mod p.
- `sub_square_offset()` combines the three branch offsets with the same
  weights `sub_square` uses to fold A, B and C into the output
  (`A·(1 − 2^128) + B·(2^256 − 2^128) + C·2^128`, with `2^256 ≡ f`). It
  returns 0 when the switch is off.
- `classical.rs::coord_add3x` adds that offset to `3·ox` with the new
  `classical_add_const_mod_q` before the quantum `mod_add`. That helper uses
  only classical-bit ops (`bit_store`, `bit_xor_into`, `bit_and_xor_into`),
  so it emits no quantum gate. The square phase runs right after
  `coord_add3x` on the same register, so pre-adding the offset there cancels
  the square's constant error exactly. See
  [modular-fold](../concepts/modular-fold.md) for `f`.

### Other edits (`src/point_add/mod.rs`)

- `ERASE_COMPARE`: 22 → 23. This is the width of the compare in
  `modular::mod_addsub` and `mod_rsub_vented_loaded` (the coordinate-shell
  and square-fold modular adds). After the add, the overflow wire is measured
  out with `hmr`, and, only when the outcome is 1, `cmp_lt_phase` on the top
  `ERASE_COMPARE` bits repairs the phase. One more bit is more accurate and
  costs about half a Toffoli per call. It buys back failure rate (λ) so a
  clean nonce is easier to find. See
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- `TAIL_NONCE`: 9444541598 → 14939365091.

## Why it is still correct, and what it risks

- **The row-0 copy and the offset are exact.** `F − 1` is computed exactly,
  every X fix-up restores a bit pattern that holds on every input, and the
  offset is exact modular arithmetic done on the host.
- **One edge I did not test.** A leaf whose input is 0 or 1 would make
  `x² − 2` negative, so its register wraps. The code does not special-case
  this. For random λ it means a 32-bit chunk equal to 0 or 1, about 2^-31 per
  leaf, so it adds nothing measurable to λ.
- **The compare widening is a protection buy.** `ERASE_COMPARE = 23` is still
  a truncated compare, and a wrong result would be a phase failure.
- The shipped nonce `14939365091` draws a clean test set: 0 classical, 0
  phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from removing a known constant from the quantum squarer and
adding it back in host-computed classical data, so row 0 becomes
Clifford-only. That is host-derived / classical specialization. The runner-up
was "measurement uncompute" style adder tricks in the square, but no carry is
measured here: the adder is gone. The `ERASE_COMPARE` widening is a small
offsetting protection.

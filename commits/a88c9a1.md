## Summary

In the dialog-GCD apply phase (background in [8a47cf5](8a47cf5.md) and
[94535d1](94535d1.md)), each step runs a fused cell on the coefficient `y`:
`dialog_gcd_fused_double_y` in one division and `dialog_gcd_fused_halve_y` in
the other. The cell builds a few one-bit control ancillas (`e`, `d`, `h` and
two overflow bits), does one combined Solinas fold, and then clears the
ancillas. `94535d1` already replaced the CCX clear of `h` with a measurement.

This commit does the same for more of them:
- the `d` clear in `double_y`, which saves 1 CCX per call;
- the `e` and `d` clears in `halve_y`, which saves 3 CCX per call.

Each division has 258 apply steps, so the saving is 258 × (1 + 3) = 1,032
Toffoli, exactly the measured drop. Qubits are unchanged. A third measured
clear, for the overflow bits of `double_y`, is added but left off.

## What changed and why it saves Toffoli

A measured clear `hmr(q, m)` followed by `cz_if(…, m)` resets `q` to `|0⟩` at
no Toffoli cost. It is valid when, at that moment, `q` equals a known Boolean
function `f` of live qubits, and the phase fix applies `(−1)^{m·f}`. See
[measurement-uncompute](../concepts/measurement-uncompute.md).

1. **`dialog_gcd_fused_double_y` (`rounds/dialog/compressed.rs`), `d` clear.**
   - `d` is set before the fold as `ccx(ovf1, s2, d)`. The stock clear was
     `ccx(s2, y[1], d)`, which works because `y[1] == ovf1` after the fold.
   - Under `DIALOG_GCD_FUSED_DCLEAR_MEASURED=1` the clear is
     `hmr(d, m); cz_if(ovf1, s2, m)`.
   - Between the set and the clear, `ovf1` and `s2` are not changed. `ovf1` is
     an overflow holder the fold does not touch, `s2` is a read-only gate, and
     `d` is used only as a control. So `d = ovf1 ∧ s2` holds exactly at the
     measurement.
   - This saves 1 CCX per call.
2. **`dialog_gcd_fused_halve_y`, `e` and `d` clears.**
   - Here `y`'s low bits have already been consumed by the subtract, so the
     stock code cleared `e` and `d` from the live overflow bits with three CCX:
     `e ^= ¬s2·ovf1`, `e ^= s2·ovf2`, `d ^= s2·ovf1`.
   - Under `DIALOG_GCD_FUSED_HALVE_EDCLEAR_MEASURED=1` this becomes:
     - `hmr(e, me)`, then `cz_if(¬s2, ovf1, me)` (with `x(s2)` around it) and
       `cz_if(s2, ovf2, me)`. That is the phase `(−1)^{me·e}`, because
       `e = ¬s2·ovf1 ⊕ s2·ovf2`.
     - `hmr(d, md)`, then `cz_if(s2, ovf1, md)`, because `d = s2·ovf1`.
   - This saves 3 CCX per call.
3. **Added but not enabled: `DIALOG_GCD_FUSED_OVFCLEAR_MEASURED`.** In
   `double_y` it would clear `ovf1 = (s2 ? y[1] : y[0])` and `ovf2 = s2 ∧ y[0]`
   the same way, saving 3 more CCX. It is not pinned in `mod.rs`, so the stock
   CCX clears run.
4. **`rounds/dialog/config.rs`**: three new readers,
   `dialog_gcd_fused_dclear_measured_enabled`,
   `dialog_gcd_fused_ovfclear_measured_enabled` and
   `dialog_gcd_fused_halve_edclear_measured_enabled`, all default off. Their
   doc comments give the same set-to-clear argument.
5. **`src/point_add/mod.rs`**: pins `DIALOG_GCD_FUSED_DCLEAR_MEASURED=1` and
   `DIALOG_GCD_FUSED_HALVE_EDCLEAR_MEASURED=1`. `DIALOG_TAIL_NONCE` goes from
   218004368140 to 805000159304.

## Why it is still correct, and what it risks

Both enabled clears are exact. Each cleared qubit equals the stated Boolean
expression on every input when it is measured, so the measurement resets it to
`|0⟩` and the conditional CZ cancels its phase kick exactly. No value or
approximation changes, so λ does not change from these cuts.

The op stream changed, so the nonce was re-hunted. The author's H200 shard
`805000000000..805004999999` gave `805000159304`. It validated with 0
classical, 0 phase and 0 ancilla failures over all 9,024 shots. A wrong phase
expression would show up as phase garbage, and an ancilla left set would show
up as ancilla garbage. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit replaces CCX uncomputes with measured uncomputes, so Uncompute
Strategy → measurement uncompute fits exactly.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 1a7895c -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 1a7895c a88c9a1 -- src/point_add` is
   99 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a88c9a1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1306 qubits
   - 1,459,421 average Toffoli (rounded)
   - score 1,906,003,826
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=805000159304` and an
identical op stream. Any other change needs a new nonce hunt.

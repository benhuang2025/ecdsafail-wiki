## Summary

On benhuang2025's `cc82b18` tree, every structure that reaches the peak
sizes its carry ladder against a budget:
- the replay's chunked adders and the interleaved walk's exact split adder
  both use `plan.peak` (`SUB4_PP_PEAK`);
- the product-register square uses `SQUARE_LADDER`.

This commit lowers both budgets by one wire (peak 1278 → 1277,
`SQUARE_LADDER` 248 → 247) and moves the batch checkpoint `r1` from 298 to
295 to suit the new cap. All peak owners then fit in 1277 qubits. Narrower
ladders mean more carry repairs, which cost Toffoli. To win that back, the
multiply traversal runs two rounds fewer (`rounds() − 4` → `rounds() − 6`,
696 → 694 rounds). Net: one qubit saved for +7 average Toffoli.

## What changed and why it saves a qubit

1. **`plan()`: `SUB4_PP_PEAK` 1278 → 1277 and `SUB4_PP_R1` 298 → 295**
   (`r2` stays 613), in `src/point_add/pingpong_div.rs`. The peak budget is
   read in two places:
   - **Replay ladders.** `allowance(plan, tape_len, walk_width) = peak − tape_len − 2·N − 2·walk_width`
     is what `pick_chunks` gives each replay cell's chunked adder. One less
     means some cells need another chunk boundary, and each boundary has a
     measured erase with a 23-bit phase-repair compare.
   - **Interleaved walk adds.** `set_walk_peak(plan.peak)` feeds
     `walk_low_chunk(round, width)`, which splits a walk add at
     `low = width − ladder` with `ladder = peak − (round+1) − 2·N − 2·width`.
     A lower peak makes `low` one bit larger. The split adder
     (`signed_add_wrapping_sigma_split`) repairs its boundary exactly, with a
     compare over the whole low chunk, so this costs only Toffoli, about
     `low` emitted per split round.
   - The new comment says r1 = 295 is the cheapest checkpoint at a 1277 cap:
     nearby values either give the batch replay another repair boundary or
     put more walk rounds into the split form.
2. **`SQUARE_LADDER`: 248 → 247** in
   `src/point_add/trailmix_ludicrous/square/product_register.rs`. This is the
   live carry-ladder budget of the square's wide adds (≥ `SQUARE_CHUNK_MIN` =
   200 bits). The square is a co-binder of the peak, so it has to drop with
   the replay. See [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
3. **`rounds_for(Multiply)`: `rounds() − 4` → `rounds() − 6`**
   (`SUB4_PP_ROUNDS_MUL`, with `rounds()` = 700). The multiply walk goes from
   696 to 694 rounds; the divide traversal stays at 700. Each removed round
   deletes a walk add, a walk-back add and a replay cell. That is what offsets
   the extra repairs from steps 1 and 2. The git parent `03c9c5b` had already
   taken one of these two rounds (`rounds() − 5`).
4. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 45448000021 → 8547948.

## Why it is still correct, and what it risks

- **The budget changes are layout changes.** Every add stays exact in value.
  The walk split's boundary repair is exact. The replay's boundary repairs
  compare only the top 23 bits of a wide chunk, so they are wrong on a tie
  (about 2^−23 per call), which shows up as a **phase** failure. Extra
  boundaries add a little λ.
- **The two removed multiply rounds are a real truncation.** A multiply walk
  that needs round 695 or 696 to converge now fails, as a **classical**
  failure (wrong product, dirty walk registers). The code prices one round
  on one traversal at about +0.05 λ.
- The shipped nonce `8547948` draws a clean set: 0 classical, 0 phase and
  0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The score gain is the peak qubit, bought by shrinking the carry-ladder budgets
of all peak owners. That is the budget-retune form of ancilla-lifetime /
venting. The multiply round cut (iteration/threshold tuning) is secondary: it
only pays back the Toffoli.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout cc82b18 -- src/point_add`.
   - `git diff --ignore-cr-at-eol cc82b18 f615c6b -- src/point_add` is
     25 lines in 3 files.
   - The git parent `03c9c5b` is benhuang2025's follow-up to `cc82b18`. It
     changes only `ROUNDS_MUL` `rounds() − 4` → `rounds() − 5` and the nonce.
     A diff against it is the same size and shows `−5 → −6` instead of
     `−4 → −6`. Either start works; this note uses `cc82b18`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f615c6b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1277 qubits
   - 939,783 average Toffoli (rounded)
   - score 1,200,102,891
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `8547948` and an identical op stream.
Any other change needs a new nonce hunt.

## Summary

In this tree the qubit peak is set by one knob, `PP_WALK_MAX_QUBITS`. Every
carry ladder sizes itself to the room left under that cap. This commit lowers
the cap from 1250 to 1249, so the circuit's peak drops by one qubit.

The ladders that were already at the cap then have one wire less. To make
them fit, the commit re-places the "bridges": in-place carry stages that keep
a carry inside an operand wire instead of on a wire of its own. Each bridge
saves one carry wire and costs one extra CCX. The commit also narrows some
multiply-side chunk-boundary compares by one bit, which saves Toffoli and
spends Lambda, and widens the coordinate-shell erase compare by one bit,
which buys Lambda back.

The net cost is +604 Toffoli. Dropping one qubit saves 1 × 889,046 = 889,046
of score. The extra Toffoli cost 604 × 1249 = 754,396. So the score falls by
134,650.

## What changed and why it saves qubits

All edits are pins in `env_raw()`, `src/point_add/mod.rs`.

1. **`PP_WALK_MAX_QUBITS`: 1250 → 1249.**
   - `pingpong.rs` describes it as "the circuit's peak, and the only width
     knob there is". The replay's `chunked_add`, the walk's split adds,
     `ripple_add` and the square's windowed adds all compute
     `room = walk_max_qubits() − active_qubits()` and size their carry
     ladders to fit.
   - So lowering the cap by one lowers the achieved peak by one, as long as
     every site can still lay out its ladder in one wire less. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
2. **`I35_PROFILE`: the bridge profile is rewritten.**
   - Format: a list of `round:dir:bridges`, read by `bridge::enter()`.
     `dir` 0 is a divide replay cell (`replay_add_halve`), and 1 is a
     multiply replay cell (`replay_double_add`). `bridges` is the cell's
     budget of in-place stages.
   - How a bridge works (`bridge.rs`, `raw_run`): a normal ripple stage
     computes its carry onto a fresh wire with one CCX and later erases it
     for free with `hmr` plus `cz_if`. A bridge stage instead writes the
     carry into the operand wire `a[i]` (a Cuccaro MAJ step) and must undo
     it with a second CCX. One extra CCX buys one fewer live carry wire. See
     [venting-and-wire-loans](../concepts/venting-and-wire-loans.md) and
     [adders-and-carries](../concepts/adders-and-carries.md).
   - Where the budget is used: `chunked_add`, `composition_bounds`,
     `retained_rebalance` and `drop_exact_lead` plan the chunk layout with
     `room + bridge::budget()`. `ripple_add` and `ripple_add_consume` switch
     to `bridge::add` / `bridge::run` when the ladder is over the cap by at
     most the budget.
   - Old profile: 45 cells. Of these, 43 are multiply cells (621–623 and
     658–697) and 2 are divide cells (641, 646).
   - New profile: 35 cells. Of these, 33 are divide cells (600, 602, 640,
     642, 644, 646 and 672–698) and 2 are multiply cells (591, 620). Every
     entry has a budget of 1.
   - So the bridges move from the late multiply replay to the late divide
     replay, and there are fewer of them. At the lower cap, a different set
     of cells is the one that would otherwise overflow or need an extra chunk
     boundary. The code comment above the pin still describes the old
     placement ("Bridges move to the multiply tail"). It was not updated.
3. **`PP_N_BADJ`: three multiply rules are prepended.**
   - `e_badj()` in `pingpong.rs` applies this list to the seeded
     chunk-boundary (B) compares at the erase site. The planner still uses
     the unshifted width. The rules are scanned in order, and **the first
     rule whose round range and direction match wins**.
   - New rules: `350-399:m:0`, `400-553:m:-1`, `554-599:m:-2`.
   - Effect on multiply rounds, compared with the old list:
     - 350–399: the old match was `350-399:m:1` (+1). The new one is 0, so
       one bit narrower.
     - 400–553: no old rule matched (0). The new one is −1, so one bit
       narrower.
     - 554–599: the old match was `554-615:m:-1`. The new one is −2, so one
       bit narrower.
     - 600–615 still get −1 from the old rule.
   - Each rule moves the compare by exactly one bit relative to before, not
     one to two bits. The result is clamped to at least 2 bits. Divide
     rounds are unaffected.
   - Each bit removed saves about 0.5 executed Toffoli per boundary, because
     the compare runs only when the `hmr` outcome is 1. It raises the
     per-boundary phase error by about 2×. See
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
4. **`ERASE_COMPARE`: 24 → 25.** This is the width of the measured-erasure
   compare after the modular add and subtract in `modular.rs`
   (`mod_addsub`, `mod_rsub_vented_loaded`) and the fused cells in
   `j_fuse.rs`. One bit wider costs about 0.5 executed Toffoli per site and
   halves that site's error. This is a Lambda buy-back.
5. **`DUMP_REPLAY_SITES` → "1"** (new pin). `record.rs` then writes
   `replay_sites.tsv`, a map of every B and F repair site, at the end of the
   build. Its header states that the recorders only read the stream: the op
   stream is byte-identical with the flag on or off.
6. **Tail nonce** `TAIL_NONCE`: 280927477331701 → 280927512368737.

The +604 Toffoli is the net of the extra bridge CCX, the re-chunked ladders at
the lower cap, the BADJ saving and the `ERASE_COMPARE` cost. The commit does
not break it down, and the parts were not measured separately here.

## Why it is still correct, and what it risks

- **The cap and the bridges are exact.** A bridge stage is a standard
  Cuccaro carry step undone by its own inverse. A different chunk layout
  changes which approximate boundary compares exist and where, but the adder
  itself stays exact.
- **The BADJ narrowing is probabilistic.** A B compare is wrong when the top
  `k` bits of sum and addend tie. One bit fewer roughly doubles that rate on
  about 250 multiply rounds. A wrong compare leaves a phase error, so it would
  show up as a phase failure.
- **Moving chunk boundaries also moves error.** The layout at 1249 places
  boundaries at different bit positions, which changes where the approximate
  compares sit.
- **`ERASE_COMPARE` 25** halves the error of the shell's erase compares,
  which offsets part of the added Lambda.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The score gain comes entirely from the one-qubit peak drop. The cap could only
drop because carry wires were moved into operand wires at the cells that bind
the peak. That is in-place mutation, under Register and Scratch Allocation.
The two compare edits are a sell/buy pair of comparator/width truncation that
come with it. The runner-up was "ancilla-lifetime / venting" for the cap
change itself, but the wire is found by the bridges, not by freeing anything
earlier.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 17bc487 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 17bc487 a4b4125 -- src/point_add` is
   11 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a4b4125 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. In this tree
   `env_raw()` is a fixed table and does not read the process environment, so
   `SUB4_*` or `PP_*` variables have no effect. Leave them unset anyway. The
   build also writes `replay_sites.tsv` in the crate root. Expect:
   - 1249 qubits
   - 889,650 average Toffoli (rounded)
   - score 1,111,172,850
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `280927512368737` and an identical op
stream. Any other change needs a new nonce hunt.

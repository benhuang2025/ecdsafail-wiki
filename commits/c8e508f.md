## Summary

Most of the 23,000-line diff is a mechanical refactor: the single 11,800-line
`src/point_add/mod.rs` is split into 15 new files plus a 445-line `mod.rs`.
A function-by-function comparison against `77b87f1` shows that the refactor
moved code without changing it, except in four places:

1. **Shift-22 collapse.** The low-scratch Solinas reduction after a 22-bit
   left shift folded the 22 spilled bits back into the value with five
   full-width adds (weights 2^0, 2^4, −2^6, 2^10, 2^32). Now it first
   computes `m = spill · 977` into a 32-bit scratch register with four small
   adds, and then does only two full-width folds: `m` at weight 2^0 and
   `spill` at weight 2^32.
2. **Position-32 fold uses the fast adder.** In the Solinas fold of the
   512-bit product used by the affine square, the 2^32 term is added with
   `mod_add_qq_fast` / `mod_sub_qq_fast` instead of the slower `mod_add_qq` /
   `mod_sub_qq`.
3. **Pair2 iterations 397 → 399.** The two changes above re-roll the test
   draw, and on the new draw 397 and 398 each give one classical mismatch.
   Two iterations are given back.
4. `B::z_if` from [`b60eec2`](b60eec2.md) is added to the builder, but it is
   unused: the author keeps the constant-|1⟩ `f1` qubit, so the peak stays at
   2310.

Items 1 and 2 save roughly 9,400 Toffoli. Item 3 costs back about 7,000
(about 3,500 per pair2 iteration, see [`77b87f1`](77b87f1.md)). Net −2,347.

### 1. Shift-22 collapse (`solinas.rs`)

Background: `p = 2^256 − c` with `c = 2^32 + 977`, so `2^256 ≡ c (mod p)`.
To multiply a 256-bit value `v` by `2^22 mod p`, the code shifts `v` left 22
bits with swaps (free). The 22 bits that fall off the top, `spill`, are worth
`spill · 2^256 ≡ spill · c`, so `spill · c` must be added back. See
[modular-fold](../concepts/modular-fold.md).

- Old (`mod_shift_left_by_k_dirty`, STEP 2): five `shift22_spill_op_dirty`
  calls, adding `spill` at positions 0, 4, 10, 32 and subtracting it at 6,
  because `c = 2^32 + 2^10 − 2^6 + 2^4 + 2^0`. Each call is a k-bit Cuccaro
  add on the low window, then a venting controlled increment that carries the
  one carry bit through the whole high window (up to about 250 bits, borrowing
  the co-resident `lo` half of the product as a dirty donor), then a
  comparator `low_new < spill` that uncomputes the carry. The high-window
  increment is the expensive part, and it was paid five times.
- New (when `shift22_collapse()`, env `SHIFT22_COLLAPSE`, default on, and
  `k ≤ 22`): allocate `m` (32 qubits) and run the new
  `shift22_compute_m_977(b, &m, &spill, k, false)`. It does four Cuccaro
  adds or subtracts of `spill` into `m` at positions 0, 4, 6 (subtract) and
  10, each inside the 32-bit register, so `m = spill · 977`. Then only two
  full-width spill ops run: `m` at position 0 (k = 32) and `spill` at
  position 32. Then `m` is uncomputed by the same four small ops in reverse
  with flipped signs, and freed.
- `mod_shift_right_by_k_dirty` mirrors this: recompute `m`, undo the
  position-32 and position-0 folds, uncompute `m`.
- Why it is exact: `spill < 2^22`, so `spill · 977 < 2^22 · 977 < 2^32`, so `m`
  fits in 32 bits with no wrap. That is why the collapse is gated on `k ≤ 22`.
- Why it is cheaper: three of the five high-window carry propagations are
  gone. The four new adds are at most 32 bits wide each, and run twice
  (compute and uncompute).
- Qubits: `m` adds 32 live wires during this fold. This fold (the
  `shift22_pos32_dirty` phase in the affine y-multiply) sits below the
  global peak, so the peak stays 2310.

### 2. Fast adder for the position-32 term (`mul_affine.rs`)

`mod_add_solinas_ext_product` and `mod_sub_solinas_ext_product` fold a 512-bit
product `lo + hi · 2^256` into a 256-bit accumulator by adding `hi` at the
weights of `c`. They double `hi` in place between terms, and for the 2^32 term
shift it by 22 more with `mod_shift_left_by_k`.

- Old: the 2^32 term was added with `mod_add_qq` (subtracted with `mod_sub_qq`).
- New (when `sol_ext_product_pos32_fast()`, env `SOL_EXT_PRODUCT_POS32_FAST`,
  default on whenever the low-scratch Solinas path is on): `mod_add_qq_fast` /
  `mod_sub_qq_fast`, like the other four terms already used.
- `mod_add_qq_fast` uncomputes its reduction flag with the measurement-based
  comparator `cmp_lt_into_fast` instead of a Toffoli comparator, so it costs
  fewer Toffoli. It allocates more transient wires. The builder comment notes
  that the Kaliski state is not live at this fold, so the extra transient
  stays below the peak. See
  [measurement-uncompute](../concepts/measurement-uncompute.md) and
  [adders-and-carries](../concepts/adders-and-carries.md).

### 3. `point_add.rs`, `build_standard_point_add()`: `pair2_default` 397 → 399

The comment records that on the new op stream 397 and 398 each give one
classical mismatch, and 399 is clean. Two more pair2 iterations cost two
forward and two backward Kaliski iterations plus two modular doublings of λ.

### 4. Comment-only and unused edits

`builder.rs` gains `z_if` (unused). `kaliski_walk.rs` gains a comment that the
`f1` allocation is kept. `kaliski_state.rs` has a stale comment that says the
bulk cap is 401; the constant is still 400.

## Why it is still correct, and what it risks

- **The refactor is exact.** Apart from the items above, every function, const
  and impl block in the new files is byte-identical to `77b87f1` after
  removing `pub(crate)` qualifiers.
- **The shift-22 collapse is exact.** It computes the same value `spill · c`
  as before, with a different split into adds. The `m` register is
  uncomputed by exact reversal.
- **The fast position-32 adder** is the same value-exact modular add as the
  other fold terms. Its measured flag uncompute leaves phase that is repaired
  in place, so a mistake there would show as a phase failure.
- **Pair2 = 399 is empirical**, like all iteration counts in this era: an
  input whose Kaliski run needs more than 399 steps leaves λ uncleared
  (ancilla garbage or a classical mismatch).
- No tail nonce exists yet. The test draw is a hash of the op stream, and this
  stream's draw is clean: 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is dead-gate/self-inverse removal. The diff does not
remove dead or self-inverse gates. The Toffoli saving comes from rewriting the
Solinas fold of the shift-22 reduction (five full-width adds become one
32-bit precompute plus two full-width adds), with a smaller part from rerouting
one fold term to the fast adder. That fits Strength Reduction → solinas / NAF
fold better, with fast-adder reroute as the runner-up. The header keeps the
published label.

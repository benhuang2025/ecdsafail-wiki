## Summary

The early circuit multiplies values by 2^22 mod p in a helper called
`mod_shift_left_by_k` ("shift22"), and undoes it with `mod_shift_right_by_k`.
The last two steps of that helper are a final reduction: add `c = 2^32 + 977`
to the 257-bit value, read the top bit, and subtract `c` again if the value
was below `p`. The base did both steps with a full-width Cuccaro adder against
a 257-qubit register loaded with `c`, which costs 512 Toffoli per step. This
commit does them with the register-free direct constant adder, whose carry
chain stops after 70 positions and costs one Toffoli per position (70 Toffoli).

Each forward/inverse shift22 pair has four such steps, so a pair saves
4 × 442 = 1,768 Toffoli. The measured drop, 5,304, is exactly three pairs.
Qubits are unchanged because the peak is elsewhere. The window width 37 was
chosen by sweeping for an op stream whose test draw is clean.

## What changed and why it saves Toffoli

**Background: the shift22 helper (`src/point_add/solinas.rs`).** This era's
multipliers and the Kaliski inverse use `mod_shift_left_by_k(b, v, p, k)` with
`k = 22` (and once with a variable `delta`) to compute `v · 2^k mod p` in
place on a 256-bit register:

1. Rotate `v` left by `k` bits, catching the top `k` bits in a `spill`
   register.
2. Add `spill · c` back into `v_ext = v ‖ ovf` (257 bits), using five
   Cuccaro adds at bit offsets 0, 4, 6 (subtract), 10 and 32. This is the
   pseudo-Mersenne fold `2^256 ≡ c (mod p)`, see
   [modular-fold](../concepts/modular-fold.md). The result is below `2p`.
3. **Step 3:** `v_ext += c`. The top bit `ovf` is then set exactly when the
   value was `≥ p`, and `flag_inv = NOT ovf` records "value was `< p`".
4. **Step 4:** `v_ext −= c` controlled on `flag_inv`, which undoes step 3 when
   no reduction was needed.

`mod_shift_right_by_k` runs the same steps in reverse. The flags and `spill`
stay live between the two calls (Bennett pattern).

**The change.**

- New switch `shift22_carrytail()` (env `SHIFT22_CARRYTAIL`, default on) and
  new window `shift22_carrytail_cut()` = `33 + SHIFT22_CARRYTAIL_W`, with
  `W = 37` by default, so the cut is 70.
- In `mod_shift_left_by_k`:
  - Step 3 was `add_nbit_const(b, &v_ext, c)` (default `LOWQ_SHIFT22` path).
    That loads `c` into a fresh 257-qubit register and runs `cuccaro_add`,
    which has one Toffoli in each of 256 MAJ and 256 UMA gates: 512 Toffoli.
    It is now `cadd_nbit_const_direct_fast_cut(b, &v_ext, c, one, 70)`, with
    `one` a fresh qubit set to |1⟩ so the controlled adder acts
    unconditionally.
  - Step 4 was `csub_nbit_const(b, &v_ext, c, flag_inv)` (a `ctrl ? c : 0`
    register plus `cuccaro_sub`, also 512 Toffoli). It is now
    `csub_nbit_const_direct_fast_cut(b, &v_ext, c, flag_inv, 70)`.
- In `mod_shift_right_by_k`, reverse step 4 becomes the matching
  `cadd_..._cut(…, flag_inv, 70)` and reverse step 3 becomes
  `csub_..._cut(…, one, 70)`, so each forward call is undone by its exact
  inverse at the same width.
- `src/point_add/cuccaro.rs`: `csub_nbit_const_direct_fast` and
  `cadd_nbit_const_direct_fast` are split into a wrapper and a new `_cut`
  variant that takes the number of carry ancillae as an argument. The wrappers
  still compute the cut from the global Kaliski carry-tail window
  (`kal_carrytail_count` / `kal_carrytail_count_c`, `K0 = 33`, `W = 20`), so
  every other caller emits exactly the same gates. The shift22 window is
  separate so that the tuned Kaliski window does not move.

**Why the direct adder is cheaper.** `cadd/csub_nbit_const_direct_fast_cut`
never loads `c` into a register. Since `c` is a known constant, the carry into
each bit is computed with one Toffoli per position: `MAJ(acc_i, ctrl, carry_i)`
where `c_i = 1` (folded from three Toffoli to one by the MAJ-fold identity with
the carry-in as pivot), and `acc_i AND carry_i` where `c_i = 0`. The carries
are then erased with `hmr` plus `cz_if` phase fixes, which cost no Toffoli
(see [measurement-uncompute](../concepts/measurement-uncompute.md)). With a
cut of 70, a step costs 70 Toffoli instead of 512. Four steps per pair give
4 × 442 = 1,768, and three executed pairs give 5,304, which is the observed
drop. These Toffoli are unconditional, so the average and emitted savings are
the same. See [adders-and-carries](../concepts/adders-and-carries.md).

The transient width also drops (70 carries plus one control qubit instead of a
257-qubit constant register plus one carry-in), but shift22 is not the peak
phase, so peak qubits stay at 2309.

## Why it is still correct, and what it risks

- **The adders are exact below the cut.** Bits above the cut get the constant
  XOR (none, since `c` has no bits above 32) but no carry. The add is wrong
  only when a carry would leave bit 70 (the last bit that receives a carry).
  Above bit 32 a carry can only propagate, so this needs bits 33…70 of the
  value to be all ones: about 2^-38 per call on a random value.
- **The flag can be wrong on astronomically rare values.** If the value after
  step 2 lies in `[p, 2^256)`, the carry of step 3 must run all the way to
  bit 256 to set `ovf`. The truncated adder cannot do that, so the reduction
  is skipped. Such values have probability about `c / 2^256 ≈ 2^-223`.
- **Forward and reverse are exact inverses.** The truncated add is addition
  modulo 2^71 on the low 71 bits, and the truncated subtract with the same cut
  is its exact inverse. So `mod_shift_right_by_k` still restores the register
  and flags on every input, and nothing is left dirty. A wrong value would show
  up as a classical mismatch.
- **Island.** There is no tail nonce in this era. The test set is a hash of
  the op stream, so any gate change re-rolls it. The comment records a sweep of
  `SHIFT22_CARRYTAIL_W`: 37 and 40 give clean draws, while 20, 22, 25, 30, 35,
  36, 38, 39, 41, 42, 45, 50, 55, 60, 90 and even 223 (no truncation) do not.
  So the misses are island draws, not truncation errors. The shipped stream is
  clean: 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from replacing a full 257-bit carry chain with one that stops
70 bits up, inside the modular reduction. That is fold/carry truncation. A
large part of the saving is really the switch from a loaded-constant Cuccaro
(two Toffoli per bit) to the direct constant adder (one Toffoli per bit),
which would be Strength Reduction → fast-adder reroute. That is the runner-up:
without the cut, the direct adder would still save about 1,024 Toffoli per
pair, but the cut accounts for the rest.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5136c0a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 5136c0a 1b913c5 -- src/point_add` is
   102 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1b913c5 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `SHIFT22_*`, `KAL_*` or `LOWQ_*` environment variables set, because they
   override the defaults. Expect:
   - 2309 qubits
   - 2,418,832 average Toffoli (rounded)
   - score 5,585,083,088
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with an identical op stream: there is no nonce in
this era, so any other change, including another window width, draws a
different test set.

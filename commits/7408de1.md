## Summary

This commit was built on `335ac78`, in parallel with mpjunior92's
[14fc786](14fc786.md) and [6e7ca2c](6e7ca2c.md). It makes two truncations:

- It lowers the dialog-GCD comparator-schedule margin from 8 to 5, the same
  setting as 14fc786, which saves 1,868 Toffoli.
- It cuts the comparator that cleans the overflow/underflow flag in the
  apply-pass modular add and subtract from 20 to 19 bits. The add runs that
  comparator once per call and the subtract twice, so with 399 calls of each
  this saves 399 + 2 × 399 = 1,197 Toffoli.

The total is 3,065 Toffoli at the same 1571 qubits. It beat the frontier by
only 37 average Toffoli, because mpjunior92's 6e7ca2c had meanwhile used the
63 → 61 comparator cap instead of the apply-clean bit. 7408de1 does not have
that cap change.

## What changed and why it saves Toffoli

All defaults are in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN` 8 → 5.** This is identical in
   effect to 14fc786. The walk's branch comparator width
   `min(SCHEDULE[step] + margin, active_width, 63)` loses 467 bits per walk,
   and 4 walks × 467 = 1,868 Toffoli. See [8316db1](8316db1.md) for the
   mechanism.
2. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` 20 → 19.**
   - In the apply pass, each step does a controlled modular add
     (`dialog_gcd_cmod_add_materialized_pseudomersenne`, in the multiply) or a
     controlled modular subtract (`..._sub_materialized_pseudomersenne`, in the
     quotient) of the 256-bit Bézout registers.
   - Each adds into a 257-bit accumulator. It folds the overflow bit `acc_ovf`
     back with the pseudo-Mersenne constant `c = 2^256 − p` (see
     [modular-fold](../concepts/modular-fold.md)), and then has to erase
     `acc_ovf`.
   - The base erases it with a truncated comparison of the top
     `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` bits
     (`compare_start = N − bits`). For the add this is
     `cmp_lt_into_fast(acc[top], f[top], acc_ovf)`: the add overflowed exactly
     when the reduced result is below the addend. The subtract computes an
     underflow predicate with `cmp_lt_into_fast` on the top bits of `acc` and
     `~a`, uses it through a measured gate, and uncomputes it with a second
     `cmp_lt_into_fast`.
   - Each comparator costs one Toffoli per bit, so one bit fewer saves 1 per
     add and 2 per subtract. With 399 of each per point addition, the saving
     is 399 + 798 = 1,197.
3. **`DIALOG_REROLL` 1 → 0, `DIALOG_POST_SUB_REROLL` 12 → 23.** These are the
   two identity `X;X` pads that pick a clean Fiat–Shamir draw.
4. A new memory note, `src/point_add/memory/2026-06-02-apply-clean-19-island.md`,
   records the settings and the metrics.

1,868 + 1,197 = 3,065, the measured drop.

## Why it is still correct, and what it risks

Both changes are probabilistic. The walk comparator is discussed in 14fc786.
The apply-clean comparator decides whether the modular add wrapped from the top
19 bits only. If the result and the addend agree on those bits, the
comparator can return the wrong value. `acc_ovf` is then left dirty, or a
wrong phase is applied, and validation reports ancilla or phase garbage on
that shot.

Not every tie is harmful. When the step's control bit is 0, the add's addend
is zero and the subtract's predicate is never applied, so a wrong compare
cannot leave anything dirty. So the real failure rate is lower than 2^-19 per
call suggests, but it is not zero. The shipped pair (0, 23) draws 0 classical, 0 phase and 0
ancilla failures. The author's memory note says that neighbouring reroll pairs
still fail. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both changes narrow truncated comparators, which is comparator/width
truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 335ac78 -- src/point_add`.
   - Do not start from the git parent `6e7ca2c`. Against it, the diff also
     reverts mpjunior92's `DIALOG_GCD_COMPARE_BITS` 61 → 63 and the comments
     from 14fc786 and 6e7ca2c. This commit was built on solimander's `335ac78`
     and never had them.
   - `git diff --ignore-cr-at-eol 335ac78 7408de1 -- src/point_add` is 36 lines
     in 2 files, one of them the new memory note.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7408de1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   Expect:
   - 1571 qubits
   - 1,742,136 average Toffoli (rounded)
   - score 2,736,895,656
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 0`,
`DIALOG_POST_SUB_REROLL = 23` and an identical op stream. Any other change
needs a new reroll scan.

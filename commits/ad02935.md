## Summary

The commit turns on three small Toffoli cuts and re-seeds the test set with
reroll 22:

1. **Fold carry truncation (−3,990).** After the raw 256-bit add or subtract
   of each apply step, the overflow fold adds or subtracts `c = 2^32 + 977`
   into the low 73 bits. This commit stops that fold's carry ripple 22 bits
   above bit 32, using the truncated direct-constant adder from
   [`f8a36ba`](f8a36ba.md). That saves 5 Toffoli per call over 798 calls.
2. **Compressor dedup (−2,128).** The 3-step log compressor contained a
   Toffoli, a CX and the same Toffoli again. The CX does not touch the
   Toffoli's wires, so the two Toffolis cancel and are removed. That saves 2
   Toffoli in each of 1,064 compressor calls. This part is exact.
3. **Measured underflow clear (−399).** In the reverse-apply subtract, the
   Toffoli that clears the underflow wire becomes an X-basis measurement
   with a CZ fix-up. That saves 1 Toffoli in each of 399 calls.

Qubits stay at 1698. A fourth knob, a body-width truncation, is added but left
off.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`, except for one new note. The route
is described in [`4b9cfbb`](4b9cfbb.md).

**1. `KAL_FOLD_CARRY_TRUNC_W=22`.**

- New `fold_carry_trunc_window()` reads `KAL_FOLD_CARRY_TRUNC_W`.
- In the `overflow_fold` phase of `dialog_gcd_cmod_add_materialized_pseudomersenne`,
  the call `cadd_nbit_const_fast(acc[..73], c, acc_ovf)` becomes
  `cadd_nbit_const_direct_trunc_fast(acc[..73], c, acc_ovf, 22)`.
- In the `underflow_fold` phase of the two subtract variants, `csub_nbit_const_fast`
  becomes `csub_nbit_const_direct_trunc_fast` in the same way.
- The old call loaded `c` into a 73-qubit register and ran a 73-bit measured
  Cuccaro add, which costs 72 CCX.
- The new call ripples only up to carry `last = min(73 − 2, 32 + 22) = 54`.
  That costs 1 CCX at bit 0, 3 CCX at each of the six set bits 4, 6, 7, 8, 9
  and 32, and 1 CCX at each of the other 48 positions, so 67 CCX.
- The saving is 5 per call. Pair 2's forward apply has 399 adds and pair 1's
  reverse apply has 399 subtracts, so 798 × 5 = 3,990.

See [modular-fold](../concepts/modular-fold.md) for why only the low bits get
the fold.

**2. `DIALOG_GCD_ROUND763_DEDUP=1`.**

The compressed sidecar log (`DIALOG_GCD_COMPRESSED_SIDECAR_LOG=1`) packs
three walk steps into one 5-qubit block. Each step has 2 log bits, `b0` and
`b0_and_b1`, so three steps have 6 bits. But `b0_and_b1` implies `b0`, so a
step has only 3 reachable states, and 3^3 = 27 ≤ 32 states fit in 5 bits.

A fixed 10-gate reversible circuit does the packing.
`emit_dialog_gcd_round763_compressor` maps the 6 raw bits into 5 bits plus a
wire that ends at |0⟩, and `..._compressor_inverse` undoes it. They are used
when a block is written and when a raw copy of it is made or cleared
(`dialog_gcd_copy_compressed_block_to_raw` and `dialog_gcd_clear_raw_block_copy`).

Both functions contain this sequence:

```
ccx(block[1], block[3] -> block[4]);  cx(block[1] -> block[0]);  ccx(block[1], block[3] -> block[4])
```

The CX writes only `block[0]`, and neither Toffoli reads or writes it. So the
two Toffolis are adjacent in effect and cancel. Under the new
`round763_dedup_enabled()` the sequence becomes just `cx(block[1] -> block[0])`.
The compressor now costs 7 CCX instead of 9. There are 133 blocks, and each
GCD pair makes 4 compressor or inverse calls per block, so there are 1,064
calls. The saving is 1,064 × 2 = 2,128.

**3. `DIALOG_GCD_MEASURED_UNDERFLOW_GATE=1`.**

In `underflow_clean`, the subtract computes `underflow_pred` with a 20-bit
compare. It then clears `acc_ovf` with `ccx(ctrl, underflow_pred, acc_ovf)`,
because `acc_ovf` holds exactly `ctrl AND underflow_pred` at that point.

Under the new `dialog_gcd_measured_underflow_gate_enabled()`, this becomes:

```
hmr(acc_ovf, m);  cz_if(ctrl, underflow_pred, m)
```

That is Gidney's AND-erase, and it costs 0 Toffoli. See
[measurement-uncompute](../concepts/measurement-uncompute.md). It runs once
per reverse-apply step, so 399 times.

**4. Added but off: `DIALOG_GCD_BODY_CARRY_TRUNC_W`.**

The new `dialog_gcd_body_carry_trunc_width(n)` returns `n − w`, with a
minimum of 2. `dialog_gcd_controlled_sub_selected` and `..._add_selected` now
load and ripple only the low `body_w` bits. With the default `w` = 0,
`body_w = n`, so the emitted gates are the same as before.

**Other edits.**

- A new memory note, `src/point_add/memory/2026-06-02-cswap-floor-analysis.md`.
  It argues that the per-step cswaps, about 432k Toffoli in total, cannot be
  cut locally. It also records that `WIDTH_MARGIN=27` with reroll 5 was the
  only clean win it found (1,704,086 → 1,699,450), which is not shipped here.
- `DIALOG_REROLL` goes from 5 to 22.

The total is 3,990 + 2,128 + 399 = 6,517, which is exactly the measured drop.

## Why it is still correct, and what it risks

- **Exact: the compressor dedup.** It is an identity on every input.
- **Exact given the comparator: the measured underflow clear.** The erase
  needs `acc_ovf = ctrl · underflow_pred`, which is the same condition the old
  CCX needed to leave `acc_ovf` clean. If the 20-bit compare is wrong, the old
  code left ancilla garbage and the new code leaves a phase error. The failure
  set is unchanged.
- **Probabilistic: the fold truncation.** The carry from the fold dies within
  22 bits above bit 32 unless `acc` has a long run of ones there, which has
  probability about 2^−23 per call. A dropped carry leaves wrong high bits in
  y, which is a classical failure. It can also spoil the following clean
  compare and leave `acc_ovf` dirty. The kept carries are erased exactly. The
  add and subtract use the same window, so the reverse apply still undoes the
  forward apply exactly whenever neither one triggers.
- Reroll 22 draws a clean set: 0 classical, 0 phase and 0 ancilla failures
  over 9,024 shots.

## Classification rationale

The published label is comparator/width truncation, but this commit changes
no comparator or register width. The largest part, 3,990 of the 6,517
Toffoli, is the carry-tail truncation of the pseudo-Mersenne fold, so
**fold/carry truncation** fits better. The rest is an exact peephole
cancellation, 2,128, which would be "Dead-Code and Redundancy Elimination"
with an exact-peephole change-type, and a measurement uncompute, 399.

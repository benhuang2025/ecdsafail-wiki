## Summary

The circuit change is one constant. The dialog GCD runs a fixed number of
binary-GCD steps, and this commit lowers it from 396 to 395. Dropping the last
step removes its branch compare, conditional swap, subtract and halving in
all four transcript passes, plus its add or subtract in the apply pass. That
saves 2,154 Toffoli. Qubits are unchanged, because the compressed log still
needs `ceil(395 / 3) = 132` blocks, the same as at 396.

The cost is correctness on inputs whose GCD needs all 396 steps. The author
found a clean test draw with a very large reroll pair (745,048 and 679,742
identity pairs). The commit also carries a macOS `._mod.rs` metadata file
and flips 210 files from mode 644 to 755. Neither affects the build.

## What changed and why it saves Toffoli

1. **`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
   `DIALOG_GCD_ACTIVE_ITERATIONS` 396 → 395.**
   - `dialog_gcd_active_iterations()` bounds every per-step loop: the forward
     and reverse transcript passes
     (`emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle`
     and its `_reverse_` twin, in both GCD passes) and the apply pass.
   - Step 395 (0-based) is a narrow late step. Its `active_width` is 4 bits
     (`256 − 0.7075 · 395 + 26`, rounded up to even), so its body costs
     little. Most of the 2,154 Toffoli come from the apply pass, which works
     on the full 257-bit coefficient register on every step: the chunked
     controlled add or subtract, its fold, and its boundary and overflow
     compares.
   - `dialog_gcd_compressed_sidecar_blocks()` is `ceil(iterations / 3)`,
     which is 132 for both 395 and 396. The log width does not change, so
     there is no qubit saving (compare [`f42ce5c`](f42ce5c.md), where
     397 → 396 removed a block).
2. **Reroll pair: `DIALOG_REROLL` 0 → 745,048, `DIALOG_POST_SUB_REROLL`
   44 → 679,742.**
   - `build_builder()` emits that many `X;X` pairs on `tx[0]` before the
     first subtraction and on `tx[1]` after it. Each pair is an exact
     identity, so it changes only the op-stream bytes and therefore the
     Fiat–Shamir test draw. It adds no Toffoli and no qubits.
   - The numbers suggest the author searched a much larger reroll range than
     earlier contestants, who stayed below 1,000. That fits a cut that makes
     clean islands rarer.
3. **Non-code changes.**
   - New file `src/point_add/._mod.rs`, 4,096 bytes. This is an AppleDouble
     extended-attribute file that macOS writes next to `mod.rs` when copying
     to a non-Apple filesystem. Cargo ignores it, because no `mod` declaration
     names it. It stays in the tree in later commits.
   - 210 files change mode from 100644 to 100755. Git records the mode, but
     the content is unchanged.

## Why it is still correct, and what it risks

The cut is probabilistic. The binary GCD's step count depends on the input.
An input that has not converged after 395 steps leaves the transcript, the
GCD registers and the coefficients wrong, which shows up as a classical
failure, or as ancilla garbage after the reverse pass. The base still had the
apply overflow compare at 20 bits. The 19-bit cut in `34a514a` is not part of
this tree.

The reroll pair (745,048, 679,742) draws a clean set: 9,024 of 9,024 shots
pass with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is the GCD iteration count, so iteration/threshold
tuning fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5a2d910 -- src/point_add`.
   - Do not start from the git parent `34a514a`. Diffing against it would also
     show `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` going back from 19 to 20,
     which reverts twangodev's `34a514a`. This commit was built on `5a2d910`
     and never had that cut.
   - `git diff --ignore-cr-at-eol 5a2d910 339fe8d -- src/point_add` lists 211
     files. 210 are mode-only changes, one is the binary `._mod.rs`, and the
     content change is 6 lines in `mod.rs`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   The patch covers the 6-line change in `src/point_add/mod.rs`, the binary
   macOS metadata file `._mod.rs` (as a git binary patch; it has no effect on
   the build), and the 210 mode-only changes.
3. **Check the tree.** `git diff --ignore-cr-at-eol 339fe8d -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1434 qubits
   - 1,731,419 average Toffoli (rounded)
   - score 2,482,854,846
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=745048`,
`DIALOG_POST_SUB_REROLL=679742` and an identical op stream. Any other change
needs a new reroll search.

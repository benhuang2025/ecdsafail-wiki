## Summary

This is a merge-and-squeeze commit on the trailmix jump-GCD circuit. It takes
mpjunior92's 1159-qubit tree `20b9a1d`, pulls in the source changes of
BitWonka's 1156-qubit line (`6c0769f` / `27d4627` / `985eaec`: a classical
`3·ox` precompute, a cheaper `f·B` fold in the square, last-step skips in the
GCD apply, fold-boundary and reserve tweaks), and then adds its own "q1153"
route. That route lowers the qubit target from 1156 to 1152, caps the apply
fold's clean-carry count, removes a few transient wires from the fused fold
and the carry erase, and keeps the narrower GCD register schedule of the last
20 steps from `985eaec`. Peak qubits drop from 1159 (base) to 1153.

The narrower qubit budget forces more borrowed-dirty carries, which cost
Toffoli, and a little precision is given back in the fold window. The author
then turned off the CCX fan-out rewrite and mined two new positional
dead-CCX drop lists (13,880 + 2,638 op indices) for the resulting stream.
Net: 6 fewer qubits for 4,107 more average Toffoli, a 0.22% lower score. The
tail nonce was re-hunted (10058189779).

## What changed and why it saves qubits

Line counts below are against `20b9a1d`. Most of the source delta was already
present in BitWonka's `27d4627` (1156 qubits). Only part B is new in this
commit.

### A. Changes taken over from BitWonka's 1156 line (already in `27d4627`)

1. **Classical `3·ox`** (`trailmix_ludicrous/ec_add.rs`, `coord_add3x`).
   - `ox` (the classical point's x coordinate) is a per-shot classical bit
     register, so `t = 3·ox mod p` can be computed with classical bit ops.
     The new `classical_times3_mod_q` does this with `BitStore0/BitStore1/BitInvert`
     under conditions. The scorer charges these ops neither Toffoli nor
     Clifford cost.
   - The method: `s = ox + ox + ox` (258 bits, by `classical_add_into` ripple
     adds), then `r = lo + hi·C` with `C = 2^32 + 977`, since `2^256 ≡ C`. After
     that, a single conditional `−p` is done by computing `r + C` and keeping it
     when it reaches 2^256.
   - The quantum part then shrinks to one load of `t` into a 256-qubit temp,
     one `mod_add_exact`, and one unload. `mod_add_exact` is a new `mod_add`
     variant whose overflow-clean comparator is full width (256 bits) instead
     of the truncated top `MSBS` bits, so it is exact.
   - The old body was `dst += ox`, `mod_double(temp)`, `dst += 2·ox` and
     `mod_double_reverse` on a 257-qubit temp. The code comment puts that at
     about 754 Toffoli, against about 326 now.
2. **Shifted read for the square's `f·B` term** (`trailmix_ludicrous/square.rs`,
   `apply_f_times_value_tagged`).
   - `B = hi²` is a full 256-bit product, so none of the earlier shortcut
     branches applied (they need `len + 32 ≤ 256`). It used to be shifted by
     an explicit `mod_double` ramp: 32 doublings up to the largest NAF shift
     of `f`, then 32 back.
   - The new `value.len() == N` branch applies each NAF term `(0,−),(4,−),(6,+),(10,−),(32,−)`
     directly with `apply_shifted_hi_term`. That function reads `value` at the
     shift offset, adds or subtracts the low `256 − shift` bits, and folds the
     `shift` wrapped-out bits back in with controlled `±f` windows. This is
     value-exact and removes the doubling ramp.
   - The unused recursive Karatsuba (`kara_square_into_prod`, behind
     `TLM_SQUARE_KARA2`, never set) is deleted, and its call sites call
     `symmetric_square_into_prod` directly. That part is a no-op.
3. **GCD apply, last-step skips** (`trailmix_ludicrous/gcd.rs`, `apply_step_forward` / `apply_step_reverse`).
   - New predicates `apply_add_skip`, `apply_fwd_cswap_skip`, `apply_inv_cswap_skip`,
     `apply_fwd_s2_zero` and `apply_inv_s2_zero` each test `i + k ≥ ITERS`.
     They select the last `k` of the 258 jump-GCD steps.
   - In those steps the code assumes the divstep's decision bits are already
     zero, because the GCD has converged. It then skips the controlled
     cofactor add or sub, skips the 256 controlled swaps, or replaces the
     fused double-and-conditional-double with a plain double
     (`fused::fused_double_only` / `fused_double_only_reverse`, which run the
     `+f` fold on one overflow bit with `fused_fold_e_only`).
   - Defaults in `build()`: `TLM_APPLY_ADD_SKIP_LASTK = 1`,
     `TLM_APPLY_FWD_S2_ZERO_LAST = 1`, `TLM_APPLY_INV_S2_ZERO_LAST = 1`,
     `TLM_APPLY_FWD_CSWAP_SKIP_LAST = 2` and `TLM_APPLY_INV_CSWAP_SKIP_LAST = 1`.
4. **Fold boundary erase without a temp** (`fused.rs`, `fold_boundary_erase_zero_direct`, `TLM_FOLD_BOUNDARY_ZERO_DIRECT = 1`).
   - For a fold chunk whose addend controls are all `None` (the addend is
     zero), the boundary carry is erased by an HMR plus a phase-repair
     comparator that runs directly on `y` and `cin`.
   - Before, an `s`-qubit temp was materialised for the addend first. Now
     there is no temp, so the step uses fewer wires.
   - Also: `TLM_FOLD_CHUNK_FORCE = 4`, and per-call reserve overrides
     (`TLM_TARGET_FOLD_CALL_RESERVE_OVERRIDES`, `TLM_TARGET_FFG_CALL_RESERVE_OVERRIDES`,
     read through a new helper `env_index_value`).
5. **`GAP_J2` +1** (`schedule.rs`) on 98 of the 258 steps (indices 112–218).
   This widens the GCD's swap-decision comparator window by one bit there,
   which lowers the chance of a mis-decided swap at the price of one Toffoli
   per affected comparison.

### B. This commit's own q1153 route

The route is set by `configure_q1153_second512_submission_defaults()`, which
is the first call in `build()`, and again by `install_q1153_submission_defaults()`
at the top of `trailmix_ludicrous::build_trailmix_ludicrous_ops()`. The first
runs before the older `set_default_env` lines. The second runs after them but
uses `set_var`, unconditionally except for `DIALOG_TAIL_NONCE`, which is
already set by then. So the later `TLM_TARGET_Q = "1155"` and
`DIALOG_TAIL_NONCE = "2430844"` defaults are dead, and the effective values
are:

1. **`TLM_TARGET_Q`: 1159 (base) / 1156 (BitWonka) → 1152.**
   - `target_qubit_headroom()` returns `TLM_TARGET_Q − active_qubits`. Every
     headroom-driven choice uses it: the apply `+f` fold's clean-carry count
     `g` in `add_f_window`, and the fused fold's `nv` in `fused_fold`, each
     minus a per-call reserve.
   - Lowering the target makes every such fold keep fewer fresh clean carries
     and borrow more dirty register bits instead
     (`add_f_window_hybrid` / `dirty_carryin`). Borrowed-dirty carries cost
     more Toffoli but do not raise the peak.
   - The measured peak lands at 1153, one above the target.
2. **`TLM_FFG_MAX_G = 47`** (`arith.rs`, `add_f_window`). This is a hard cap on
   `g` after the schedule and headroom terms, so no `+f` window (apply folds
   and the mod-add/sub windows alike) uses more than 47 clean carries of its
   `LSBS − 1 = 52`.
3. **`TLM_FOLD_CHUNK_ZERO_CIN = 1`** (`fused.rs`, `add_mf_fold_chunked`).
   - The chunked fold no longer allocates a `cin0` qubit for chunk 0, whose
     carry-in is always 0. It passes `None` instead.
   - The matching boundary erase uses the new `erase_carry_gated_zero_cin_opt`,
     which reuses the measured carry wire as the zero carry-in. This saves one
     qubit during the fold.
4. **Carry lent back right after HMR** (`arith.rs`, `erase_carry_gated_opt`).
   - After `hmr(carry)` resets the boundary carry to |0⟩, it is returned to the
     free list at once with `loan_zero_qubit`, which emits no gate.
   - The phase-repair comparator that follows can then reuse that wire.
     Before, the caller freed it only after the comparator (the
     `zero_and_free(carry)` lines in `emit_chunked_capped` and
     `fold_boundary_erase` are removed). This saves one qubit at the erase.
5. **`TLM_FOLD_TAIL_CINC = 1`** (`fused.rs`, `add_carry_into_tail_prefix`). The
   clean-tail fold's carry-into-tail used a quadratic cascade of
   prefix-controlled `mcx` gates. It is replaced by the existing exact
   Khattar–Gidney controlled increment `mcx::cinc_khattar_gidney`, which costs
   linear Toffoli.
6. **Narrower GCD tail** (`schedule.rs`, `SCHED_J2`). This is the same cut as
   BitWonka's [`985eaec`](985eaec.md), the git parent, carried over (it is not
   in `27d4627`).
   - `SCHED_J2[i]` is the register width of the GCD state at step `i`. A step
     whose `max(bitlen(u), bitlen(v))` exceeds it truncates a needed bit.
   - Steps 238–257 lose 2 bits each, for example 28 → 26 at step 238 and 13 →
     11 at step 257. That gives fewer wires and cheaper subtracts and
     comparators in the last 20 steps, at a higher risk that a slowly
     converging input overflows.
7. **Fold window +1 bit** (`arith.rs`): `LSBS = PAD + F_BITLEN = 52` → `20 + F_BITLEN = 53`
   (`PAD = 19`; the old comment "54" was stale). The `+f` fold drops a carry
   that runs past bit `LSBS − 1`, with probability about 2^−(LSBS−33) per fire.
   One more bit halves that risk, at about one Toffoli per fold. The author
   calls it a "giveback", which pays for some of the risk added in 6.
8. **Fan-out rewrite off and new drop lists** (`mod.rs`).
   - `SINGLE_CCX_FANOUT_DISABLE = 1` makes `build()` skip the
     `single_ccx_fanout` closure (see [dead-gate-strip](../concepts/dead-gate-strip.md)).
     It goes straight to the new `apply_drop_dead_robust_if_enabled`.
   - That function applies two positional drop lists, embedded with
     `include_str!`.
     - **`drop_dead_robust_k1_skip_59084.idx`** (new, 13,880 indices, first line `idx`).
       These are op indices of CCX gates in the freshly built stream that never
       flipped their target in the author's random-input fire census. They are
       deleted (`DROP_DEAD_ROBUST = 1`). The name says the list was mined for
       the K1 apply-add-skip stream.
     - **`drop_dead_second_fs512.idx`** (new, 2,638 indices). A second list,
       applied to the stream after the first drop (`DROP_DEAD_ROBUST_SECOND = 1`).
       The note calls it the "second-512 scan". The name suggests a second
       census over 512 Fiat–Shamir-style shots, but the commit does not
       document this.
   - The base's `drop_dead_robust_15221.idx` and `drop_dead_robust_13873.idx`
     stay in the tree but are no longer read. `DROP_DEAD_FILE` and
     `DROP_DEAD_SECOND_FILE` can override the lists for experiments.
   - The note reports 10,203,570 emitted ops.
9. **Diagnostics and no-ops.**
   - `TRACE_ALLOC_NEAR_PEAK` (an allocation tracer in `alloc_qubit`) and
     `TRACE_TLM_FOLD_ALLOC`.
   - Classical bit helpers (`bit_store0`, `bit_copy`, `bit_xor_into`, …) and the
     test constructors `B::new_for_test` / `take_ops`. `trailmix_ludicrous`
     and `ec_add` are made `pub` for a unit test bin.
   - Test builders `build_times3_test` / `build_add3x_test`.
   - An unused `TLM_FUSE_X_RESTORE` hook in `coord_rsub`.
   - `TLM_CODEC_DIAMOND_MCX = 1`, which is set but read nowhere.
   - The removal of BitWonka's `advance_ffg_call_index(3)` shim, which shifts
     the FFG call indices that the per-call reserve tables refer to.

## Why it is still correct, and what it risks

- **Exact parts.**
  - The classical `3·ox` derivation is exact: `r = lo + hi·C < 2^256 + 2C < 2p`,
    so one conditional `−p` lands in `[0, p)`. It is followed by a full-width,
    exact `mod_add`.
  - The shifted-read `f·B` term, the Khattar–Gidney tail increment, the
    zero-cin and temp-free boundary erases, and the early carry loan change
    wiring and gate cost, not values. The loan is safe because HMR has
    already reset the wire to |0⟩.
  - Lowering `TLM_TARGET_Q` and capping `g` only move carries between clean
    and borrowed-dirty forms. Both are exact.
- **Probabilistic parts.**
  - The last-step apply skips are exact only for inputs whose GCD has
    converged before step 258 − k. A slower input gets a wrong `y`, which
    shows up as a classical failure.
  - The narrower `SCHED_J2` tail adds the same kind of risk: register
    overflow, a classical failure.
  - The positional drop lists are empirical. A dropped CCX that would fire
    on some input gives a wrong value or a dirty ancilla, so a classical or
    ancilla failure.
  - `GAP_J2 +1` and `LSBS +1` lower risk.
- The drop lists are tied to this exact op stream. Any upstream edit shifts
  the indices, and the drop then deletes live gates (see
  [dead-gate-strip](../concepts/dead-gate-strip.md)).
- The shipped nonce `10058189779` (`Q1153_SECOND512_SUBMISSION_NONCE`) draws
  a clean set: 9,024 of 9,024 shots, 0 classical, 0 phase and 0 ancilla
  failures, average Toffoli 1,368,486.555 (submission note). See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as dead-gate/self-inverse removal, because of the two
new drop lists. Measured against the base, though, the score gain comes from
peak qubits: 6 fewer qubits are worth about 8.2 M of score, while Toffoli goes
*up* by 4,107. The new drop lists (16,518 indices) replace the base's own
15,221-index list, so they are a re-mine for the new stream, not a new lever. The
qubit-side changes (target-Q squeeze, zero-cin fold, early carry loan,
narrower GCD tail) would fit a peak-reduction label such as "ancilla
lifetime / reserve tightening". The merged BitWonka changes add classical
specialisation (`3·ox`) and dead-code skips. Against BitWonka's `985eaec`, the
frontier it beat, the gain is only 97,609. The published label is kept, but it
describes the least important part of the change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 20b9a1d -- src/point_add`.
   - `git diff --ignore-cr-at-eol 20b9a1d da51a48 -- src/point_add` is 17,710
     lines in 10 files. 16,520 of them are the two new `.idx` files.
   - The git parent is BitWonka's `985eaec`, which is closer in source code
     (about 650 non-`.idx` diff lines) but much further in total: 74,114
     lines. Diffing against it would delete BitWonka's `dead_k1_nocoord3x.idx`
     and `dead_coord3x_sched_notc.idx`, and re-add mpjunior92's
     `drop_dead_robust_15221.idx` and `drop_dead_robust_13873.idx`. Those two
     come back unused, as carry-overs of the `20b9a1d` tree this commit was
     built on.
2. **Copy the two generated drop lists from the commit:**
   `git checkout da51a48 -- src/point_add/drop_dead_robust_k1_skip_59084.idx src/point_add/drop_dead_second_fs512.idx`.
   These are op-index lists produced by the author's fire census. They are
   not hand-written.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It
   covers the eight edited source files.
4. **Check the tree.** `git diff --ignore-cr-at-eol da51a48 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`,
   `TLM_*`, `DIALOG_*`, `DROP_DEAD_*` or `SINGLE_CCX_*` overrides set. Expect:
   - 1153 qubits
   - 1,368,487 average Toffoli (1,368,486.555 before rounding)
   - score 1,577,865,511
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `10058189779` and an identical op
stream. The drop lists are positional, so any other change also invalidates
them.

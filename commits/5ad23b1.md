## Summary

Two comparators in the dialog GCD only look at the top bits of their
operands. This commit makes both of them shorter:

- The GCD branch comparator, which decides at each step whether `u > v`, now
  looks at 46 bits instead of 52.
- The apply-phase clean comparator, which clears the overflow flag of each
  controlled modular add, now looks at 18 bits instead of 20.

Each compared bit costs one Toffoli per call, so the commit saves 6,244
average Toffoli at the same 1320 qubits. Both cuts can give a wrong answer on
rare inputs, and the clean test set became hard to find (the author estimates
about 1 nonce in 260,000). The author found nonce 60003453 with a classical
pre-filter that replays the truncated GCD.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_COMPARE_BITS`: 52 → 46.**
   - Each forward GCD step sets `b0_and_b1 = b0 ∧ (u > v)` with
     `dialog_gcd_ccx_cmp_gt_truncated_into_width(_hosted)`. That computes
     `v[start..] < u[start..]` on the top `compare_bits` bits of the step's
     active window, `start = active_width − compare_bits`.
   - `dialog_gcd_compare_bits_for_step()` returns
     `min(COMPARE_BITS, active_width)`, because the PA9024 schedule is off.
   - The comparator (`ccx_cmp_lt_into_fast`, or its borrowed-carry form) makes
     one carry CCX per compared bit. It erases them with `hmr` plus `cz_if`,
     which costs no Toffoli. Six fewer bits therefore save 6 Toffoli per call,
     on every step whose window is at least 52 bits wide (fewer on the
     narrower late steps). The transcript passes of both GCD uses, forward
     and reverse, make these calls.
2. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 20 → 18.**
   - After each apply-step controlled modular add,
     `dialog_gcd_cmod_add_materialized_pseudomersenne*` clears `acc_ovf` with
     `cmp_lt_into_fast(&acc[N − k..], &f[N − k..], acc_ovf)`. The subtract
     side clears it with `dialog_gcd_clean_truncated_underflow`, which does
     `ccx_cmp_lt_into_fast` on the same top `k` bits.
   - `k` is this knob, at one CCX per bit. There are about 520 apply adds and
     subtracts per shot, so 2 bits give about 1,040 Toffoli. That is the
     author's figure.
3. **`DIALOG_TAIL_NONCE`: 335 → 60003453.** The 48 `X;X` identity pairs at
   the end of `build_builder()` only reseed the 9,024 test inputs.

The measured total is −6,244. The author's note gives −3,456 for the
comparator and −1,040 for the clean compare, which add up to only −4,496. If
the clean compare gives 1,040, the comparator gives about 5,200, roughly 6
Toffoli on each of about 870 comparator calls. That fits two GCD uses times
forward and reverse over the ~215 steps whose window is at least 52 bits. I
take the −3,456 to be an error in the note.

## Why it is still correct, and what it risks

- **Branch comparator.** It is wrong when `u` and `v` agree on the top 46
  bits of the window but differ below. The step then takes the wrong branch,
  and the GCD may not converge in 259 steps. That gives a classical failure,
  or phase garbage when the transcript is uncomputed. The author's comment says it
  "still decides every branch on the reachable verifier support" and calls
  both cuts "value-exact", but it is not exact. Their own
  pre-filter flags comparator mis-decisions as hard inputs, and the island
  became sparse.
- **Clean compare.** If the sum and the addend agree on their top 18 bits,
  `acc_ovf` is not cleared. That leaves ancilla or phase garbage.
- **Nonce.** The author's pre-filter derives each nonce's 9,024 inputs and
  replays the truncated dialog GCD classically on both factors of the point
  add, the quotient's `dx = Px − Qx` and the multiply's `c = Qx − Rx`. It
  rejects any input that overflows the width envelope, does not converge
  within 259 steps, or mis-decides a branch. The surviving candidates are then
  fully simulated.
- Nonce 60003453 draws a clean set: 9,024 of 9,024 shots, with 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both changes cut the bit width of a truncated comparator, so the commit is
filed as comparator/width truncation. No runner-up fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout c64c03f -- src/point_add`.
   - Do not start from the git parent `a91b626`. That is robertkodra's
     1322-qubit four-chunk tree, which also carries mpjunior92's width-slope,
     band-trim and comparator changes.
   - Diffing against the parent (88 lines) would wrongly show this commit
     reverting the four-chunk apply layout to five chunks, the slope from
     1014 to 1005, the band trims and `KAL_FOLD_CARRY_TRUNC_W` 22 → 23.
   - Against `c64c03f`, `git diff --ignore-cr-at-eol c64c03f 5ad23b1 -- src/point_add`
     is 23 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 5ad23b1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*`, `DIALOG_*` or `SUB4_*` environment variables set, because they
   override the defaults. Expect:
   - 1320 qubits
   - 1,555,019 average Toffoli (rounded)
   - score 2,052,625,080
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `60003453` and an identical op
stream. Any other change needs a new nonce hunt.

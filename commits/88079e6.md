## Summary

Each dialog-GCD division (background in [8316db1](8316db1.md); see
[dialog-gcd-early](../concepts/dialog-gcd-early.md)) has an *apply* pass that replays the 258-step walk log on
the 256-bit Bézout registers. Every apply step does one controlled modular add
(or subtract) `y ± ctrl·x mod p`. That leaves an overflow bit, which is
cleaned by a comparison on the top `k` bits of the result and the addend. This
commit makes `k` 22 instead of 23. One comparator bit is one Toffoli, the apply
pass runs 258 steps, and there are two divisions, so the saving is
2 × 258 = 516 Toffoli, exactly the measured drop. Qubits are unchanged.

The commit also adds `src/point_add/dialog_gcd_classical_filter.rs`, a
classical replay of the truncated GCD walk used to pre-screen tail nonces. It is
declared as a module but nothing in `build()` calls it, so it does not change
the circuit.

## What changed and why it saves Toffoli

### `src/point_add/mod.rs` (the patch below)

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 23 → 22** in
   `configure_ecdsafail_submission_route()`.
   - Read by `dialog_gcd_apply_clean_compare_bits()` in
     `rounds/dialog/config.rs`. Its users are in `rounds/dialog/mod.rs`, all
     with `compare_start = N − k`.
   - On this route the apply pass uses the chunked materialized special add
     (`DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS=5`).
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked` does the
     controlled raw sum into a 257-bit `acc_ext` (top bit `acc_ovf`), then a
     constant fold that adds `2^256 − p` into the low 73 bits when `acc_ovf`
     is set (see [modular-fold](../concepts/modular-fold.md)). It then clears
     `acc_ovf` with
     `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)`. A modular
     add wrapped exactly when the result is smaller than the addend, so
     `ctrl AND (acc < a)` equals `acc_ovf` and XORs it back to 0.
   - That add form runs in the apply pass of the multiply-type division
     (`emit_dialog_gcd_compressed_sidecar_ipmul_block_lifecycle`). The quotient
     division (λ = dy/dx) runs the reverse-exact apply pass, which uses the
     subtract twin `dialog_gcd_cmod_sub_materialized_pseudomersenne_chunked`.
     Its `dialog_gcd_clean_truncated_underflow` does the same top-`k`
     comparison with `a` complemented.
   - The comparator costs about one Toffoli per compared bit. One add or
     subtract per apply step, 258 steps per apply pass, and one apply pass per
     division: 2 × 258 × 1 = 516 Toffoli.
2. **`DIALOG_TAIL_NONCE`: 213394 → 251235**, the fixed 48-pair `X;X`
   identity tail that reseeds the 9,024 test inputs.
3. **`pub mod dialog_gcd_classical_filter;`** declares the new file.

### New file `src/point_add/dialog_gcd_classical_filter.rs` (603 lines, copied)

An analysis-only classical model of the dialog-GCD walk, used offline to throw
away nonces whose test set contains a hard input before running the expensive
quantum check.

- `DialogGcdFilterConfig::from_env()` mirrors the route's env knobs: active
  iterations, global and scheduled compare bits, width slope and margin, body
  carry-band trims, the odd-u fast path and K2.
- `truncated_gcd_step` replays one step on `U256` values exactly as the
  circuit does it. It flags `WidthOverflow` if `u` or `v` exceeds
  `active_width(step)`, takes the branch from the truncated comparator,
  swaps (except bit 0), subtracts over the trimmed `body_w`, shifts, and does
  the K2 second shift. A truncated-versus-full comparator disagreement is only
  flagged under `DIALOG_GCD_FILTER_STRICT_COMPARE=1`, because such inputs can
  still converge.
- `check_gcd_factor` first counts the full-width K2 steps to zero
  (`NonConvergence` if more than 258), then runs the truncated replay.
  `check_point_add_inputs` and `check_all_shots` apply it to both GCD inputs
  of each shot, `dx = Px − Qx` and `c = Qx − Rx`.
- Helpers for jump-GCD convergence statistics (`measure_jump_convergence`) and
  two unit tests (a known clean nonce passes; width margin 8 is stricter than 9).

The filter models the walk only. It does not model the apply-phase comparator
that this commit narrows, so the author's hunt still needed the full
bit-exact run to confirm the nonce.

## Why it is still correct, and what it risks

The overflow clean is a truncated comparison, so it is approximate. When the
result and the addend agree on all top 22 bits, the comparison is decided by
the dropped low bits and can be wrong. Then `acc_ovf` is not returned to 0.
That shows up as an ancilla failure, and the wrong correction can also corrupt
later apply steps (a classical failure). Dropping the 23rd bit roughly doubles
the per-call chance of this. The submission note calls the cut "value-exact on
the reachable support", which is not accurate: it is a rare-input truncation
that the nonce has to dodge.

The shipped nonce `251235` draws a test set with 0 classical, 0 phase and
0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a comparator window, so comparator/width
truncation fits. The new filter file is tooling and adds no gates.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8e13587 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 8e13587 88079e6 -- src/point_add` is
   622 lines in 2 files. The new filter file is 603 of them.
2. **Copy the new file from the commit:**
   `git checkout 88079e6 -- src/point_add/dialog_gcd_classical_filter.rs`.
   It is hand-written analysis tooling, copied because it is too large to
   inline. The section above describes it.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `mod.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol 88079e6 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1309 qubits
   - 1,504,387 average Toffoli (rounded)
   - score 1,969,242,583
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=251235` and an identical op
stream. Any other change needs a new nonce hunt.

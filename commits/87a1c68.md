## Summary

This commit does not build on the 1249-qubit line of [`a4b4125`](a4b4125.md),
[`454ff5a`](454ff5a.md) and [`73894fc`](73894fc.md). Its `src/point_add` is
[`17bc487`](17bc487.md)'s tree, the last 1250-qubit commit, with one change:
the replay's chunk-boundary repair compare loses one more bit on rounds whose
walk register is 25 to 37 bits wide.

That saves 157 Toffoli against `17bc487`. At 1250 qubits the result,
1,111,111,250, beats the 1249-qubit frontier of 1,111,115,396. A 1250-qubit
tree with 888,889 Toffoli scores lower than a 1249-qubit tree with 889,604.
The cost is a higher phase-error rate at those boundaries, so the nonce was
re-hunted.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `env_raw()`: `PP_CHUNK_SHAPE` goes from
  `"64:0,38:1,25:-2,0:-4"` to `"64:0,38:1,25:-3,0:-4"`.
- What the knob means. `chunk_compare(round)` in `pingpong.rs` is the width
  of the compare that repairs a chunk-boundary carry in the replay's chunked
  adder:

  ```
  chunk_compare(round) = PP_REPLAY_CHUNK_COMPARE + band_at(PP_CHUNK_SHAPE, policy_width(round))
  ```

  - `PP_REPLAY_CHUNK_COMPARE` is 21.
  - `band_at` picks the first band whose lower bound is at or below the walk
    width `policy_width(round)`. The bands are: width ≥ 64 → +0, 38–63 → +1,
    25–37 → −2 (now −3), and below 25 → −4.
  - So in the 25–37 band the base width goes from 19 to 18 bits.
  - `boundary_repair_spec` then subtracts 1 for a seeded compare
    (`CMP_SEED_ALL`), and `e_badj` applies the per-range `PP_N_BADJ`
    offsets. Both act on top of the new value. So each compare in the band
    is one bit narrower than before. The exceptions are a chunk shorter than
    the compare (the width is capped at the chunk length `hi − lo`) and
    cases where the `e_badj` clamp already sets the width.
- Which rounds. In `PP_WIDTH_SCHEDULE`, the walk width is 25–37 on rounds
  616–648, which is 33 rounds. Both traversals read the same schedule, so
  both the divide and the multiply replay are affected on those rounds.
- Why it saves Toffoli:
  - Each boundary carry is measured out with `hmr`, then
    `erase_with_compare` runs a top-`k` compare under `push_condition` on
    the outcome.
  - One bit fewer saves one Toffoli on the about half of shots where the
    compare runs. Over all boundaries on those rounds, the measured total is
    −157.
  - The doc comment on `chunk_compare` says the shape changes only the
    comparison, not the chunk boundaries. But with `PP_NEW_REPLAY = 1`,
    `chunked_add` also uses `chunk_compare` to price the classic layout
    against the `width_composition` adder. A narrower width can therefore
    change which adder a round picks.
- Why this band. The same doc comment records measured per-boundary failure
  rates relative to wide rounds: 1.00 at walk width 69–38, 0.33 at 37–25 and
  0.04 below. The late bands fail less often per bit, which is why they
  already had negative offsets. This commit spends a little more Lambda there
  for 157 Toffoli. See
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- **Tail nonce** `TAIL_NONCE`: 280927477331701 → 85023914663.

Everything else is `17bc487` as it was:
- `PP_WALK_MAX_QUBITS` 1250 and the old `I35_PROFILE`;
- the old `PP_N_BADJ`, `ERASE_COMPARE` 24 and `PP_FLAG_WIDEN_DIV` 38;
- the 11-bit square merge.

## Why it is still correct, and what it risks

The boundary compare is approximate. It gives the wrong phase repair when the
compared top `k` bits of sum and addend tie, which happens with probability
about 2^-k. One bit fewer doubles the per-boundary error on rounds 616–648 in
both traversals. The value outputs are still right, and a failure would show
up as a phase error. Lambda goes up, which makes a clean nonce harder to find.

The shipped nonce `85023914663` draws a clean set: 0 classical, 0 phase and 0
ancilla failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Against its base the only circuit change is one narrower compare band. That
is comparator/width truncation. The return to 1250 qubits is not a change
here, because the base was already at 1250. It is a choice of base: the 1249
line paid 604 Toffoli for its qubit (see
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md)), and this
commit shows a cheaper 1250 tree beats it.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 17bc487 -- src/point_add`.
   - Do not start from the git parent `73894fc`. That is rubenmarcus's
     1249-qubit tree, and this commit was not built on it.
   - Against the parent, the diff is 50 lines in 2 files. It reverts the
     work of [`a4b4125`](a4b4125.md), [`454ff5a`](454ff5a.md) and
     [`73894fc`](73894fc.md):
     - `PP_WALK_MAX_QUBITS` 1249 → 1250, `I35_PROFILE` and `PP_N_BADJ` back
       to the old lists;
     - `ERASE_COMPARE` 28 → 24, `PP_FLAG_WIDEN_DIV` 696 → 38, and the
       `DUMP_REPLAY_SITES` pin removed;
     - `square.rs` back to the 11-bit merge with ripple inverse adds.
   - Against `17bc487`, `git diff --ignore-cr-at-eol 17bc487 87a1c68 -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 87a1c68 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. In this tree
   `env_raw()` is a fixed table and does not read the process environment, so
   `SUB4_*` or `PP_*` variables have no effect. Leave them unset anyway.
   Expect:
   - 1250 qubits
   - 888,889 average Toffoli (rounded)
   - score 1,111,111,250
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `85023914663` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

This is one more notch of the GCD width-envelope slope:
`DIALOG_GCD_WIDTH_SLOPE_X1000` goes from 1005 to 1006. The working window of
the binary GCD becomes 2 bits narrower on 17 odd steps between 167 and 199.
There the window is still wider than the 52-bit comparator cap, so each bit-step
saves about 16 Toffoli. That gives 34 × 16 = 544 Toffoli, the measured drop.
Qubits are unchanged. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

**Background.** The circuit is the dialog-GCD route (`emit_dialog_gcd_raw_pa`
in `src/point_add/mod.rs`). Two calls each run a reversible binary GCD on
(u, v) = (p, factor): the quotient dy/dx and the product with c = ox − Rx. Each
call has a forward pass, an apply pass and a reverse pass. [98416e4](98416e4.md)
lists one GCD step and the width formula
`active_width(step) = clamp(2·⌈(256 − step·SLOPE/1000 + MARGIN)/2⌉, 1, 256)`.

**The changes in `configure_ecdsafail_submission_route()`:**

- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 1005 → 1006, with `WIDTH_MARGIN` = 10 and
  258 steps.
  - Each extra 0.001 of slope moves the ideal width down by 0.001·step bits.
    Because of the round-up to even, the width only drops where that crosses
    an even boundary.
  - Here that happens at the odd steps 167, 169, …, 199: 17 steps, each 2 bits
    narrower (100 → 98 at step 167, 68 → 66 at step 199).
  - At these steps the window is above `DIALOG_GCD_COMPARE_BITS = 52`, so the
    comparator does not shrink. Each bit still saves about 4 Toffoli per pass:
    1 in the cswap, 2 in the controlled subtract or add, and 1 in the K=2
    halving cascade.
  - There are four passes (forward and reverse, in two GCD calls), so
    34 bit-steps × 16 = 544.
- `DIALOG_TAIL_NONCE`: 3577 → 13555.

Each further notch of this kind pays less, because the affected steps move
earlier and become fewer. That is why this notch is −544, against about −940
for 1004 → 1005 and −384 for the next notch, [`ae3b97b`](ae3b97b.md).

## Why it is still correct, and what it risks

A narrower window cuts the top bits of any input whose GCD registers are still
too wide at those steps. The GCD then goes wrong, which is a classical failure
that usually comes with ancilla garbage. The author measured that this notch
breaks 6 classical and 6 phase shots at the inherited nonce. That was the
gentlest single lever on this tree: 257 steps broke 13 + 5, margin 9 broke
9 + 4, and the apply-clean comparator at 19 broke 10 + 6. The local
full-validation searcher found nonce `13555` after about 13,600 tries, about 30
minutes on 11 threads. It draws a clean set: 0 classical, 0 phase and 0 ancilla
failures over all 9,024 shots.

## Classification rationale

The only circuit change narrows the GCD registers' working width, which is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout fec6d25 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol fec6d25 05d68e5 -- src/point_add` is 19 changed
   lines in 1 file, almost all of them comment.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 05d68e5 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset. Expect:
   - 1382 qubits
   - 1,513,677 average Toffoli (rounded)
   - score 2,091,901,614
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `13555` and an identical op stream.
Any other change needs a new nonce hunt.

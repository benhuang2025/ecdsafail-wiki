## Summary

The round84 λ² square reduces its 512-bit result with an in-place Solinas
fold. One step of that fold adds the 66-bit product `q · c` into the low 66
bits of `lo`. The carry out of that add, called `wrap`, then has to be
propagated into the bits above, as a controlled `+1`. That propagation is
truncated to a window of `w` carry stages. This commit makes `w` 20 instead of
21.

The emitted saving is tiny: one Toffoli in the fold and one in the unfold. The
measured average falls by 22 Toffoli, most of which is the different test draw
of the re-hunted nonce. Qubits are unchanged.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`ROUND84_INPLACE_QUOTIENT_CARRY_TRUNC_W`: 21 → 20.**
   - Read by `round84_inplace_quotient_carry_trunc_window()` in
     `arith/multiply.rs` (default 21).
   - `round84_add_narrow_correction` adds `product` (66 bits) into `lo[..66]`
     plus the `wrap` bit. Then, with `ROUND84_INPLACE_VENT_CARRY` off, it runs
     `cadd_nbit_const_direct_trunc_fast(high, 1, wrap, w)` on
     `high = lo[66..]`. That adds 1 controlled on `wrap`, with the carry sweep
     cut at bit `min(n − 2, 0 + w)` of `high`.
   - `round84_sub_narrow_correction` undoes it in the unfold with
     `csub_nbit_const_direct_trunc_fast(..., w)`.
   - One window bit less saves one carry stage, about one Toffoli, in each of
     the two calls.
2. **`DIALOG_TAIL_NONCE`: 5200018704193 → 310772318.** Both copies of the pin
   are changed. The top-of-route one is the one that takes effect.

**Why the score moves by 22.** The emitted change is about −2 Toffoli. The
rest is a different set of test shots: the new nonce draws inputs whose
conditional (measurement-dependent) gates fire slightly less often. See
[scoring-and-validation](../concepts/scoring-and-validation.md).

## Why it is still correct, and what it risks

The truncated `+1` is wrong when `wrap = 1` and the 20 bits of `lo` just above
bit 66 are all 1. Then the carry needs to travel further than the window, and
the top part of the folded value is off by 2^(66+20). For random-looking
values that is about 2^−20 per call, twice the rate at 21. A wrong fold gives
a wrong λ², which is a classical mismatch, or a dirty unfold, which is ancilla
or phase garbage.

The shipped nonce `310772318` draws a clean set: 9,024 of 9,024 shots, with
0 classical, 0 phase and 0 ancilla failures. The note says it was confirmed
CPU-clean first, then validated with the release `build_circuit` /
`eval_circuit`. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a narrower carry window, which is filed as
comparator/width truncation. Fold/carry truncation would fit as well, because
the window belongs to a Solinas fold.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 997dbd6 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 997dbd6 f4404de -- src/point_add` is 6 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f4404de -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `ROUND84_*`, `R84_*`, `SQUARE_*` or `MOD_*`
   environment variables set, because they override the route defaults.
   Expect:
   - 1220 qubits
   - 1,404,178 average Toffoli (rounded)
   - score 1,713,097,160
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=310772318` and an identical
op stream. Any other change needs a new nonce hunt.

## Summary

Two one-knob commits branched from `89abe1b`: [e0767c7](e0767c7.md) narrowed
the apply-clean comparator to 19 bits, and [ace6347](ace6347.md) added a third
body-trim band. This commit combines them. It takes the `ace6347` tree and
applies the same apply-clean change: `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`
from 20 to 19. One comparator bit per apply step, 259 steps, two divisions:
518 Toffoli, exactly the measured drop and the same as in `e0767c7`. Qubits
are unchanged, and a new tail nonce was hunted for the combined stream.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 20 → 19.**
   - `dialog_gcd_apply_clean_compare_bits()` sets `compare_start = N − k` in
     the apply pass's overflow clean.
   - In the multiply-type division, the clean is
     `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)` in
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`.
   - In the quotient division's reverse-exact pass, it is
     `dialog_gcd_clean_truncated_underflow`.
   - About one Toffoli per bit, once per apply step: 2 × 259 = 518 Toffoli.
   - [88079e6](88079e6.md) explains why `ctrl AND (acc < a)` recovers the
     overflow bit of a modular add.
2. **`DIALOG_TAIL_NONCE`: 13362 → 158127**, the fixed 48-pair `X;X` identity
   tail that reseeds the 9,024 test inputs.
3. Comments are updated. The long apply-clean comment from earlier commits is
   left as it was, and two lines are added below it.

## Why it is still correct, and what it risks

The truncated overflow clean can be wrong when the result and the addend agree
on all top 19 bits. That leaves the overflow bit dirty and corrupts later apply
steps, which shows up as classical and phase failures. Here it is stacked with
the three-band body trim from `ace6347`, which is a separate rare-input
hazard. The hard set is about the union of the two commits' hard sets, so a
nonce that is clean for both is rarer than for either.

The shipped nonce `158127` draws a test set with 0 classical, 0 phase and
0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A one-bit narrowing of a comparator window is comparator/width truncation. The
nonce change comes with every circuit change and is not a separate lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ace6347 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol ace6347 779fc2b -- src/point_add` is
   12 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 779fc2b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `R84_*` environment variables set, because `set_default_env`
   only fills in unset variables. Expect:
   - 1307 qubits
   - 1,487,670 average Toffoli (rounded)
   - score 1,944,384,690
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=158127` and an identical op
stream. Any other change needs a new nonce hunt.

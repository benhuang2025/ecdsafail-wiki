## Summary

Each dialog-GCD apply step does a 257-bit controlled modular add. That add is
built from five chunks (see [`a91b626`](a91b626.md) for how the chunks
work). The first four chunks use a fast adder: one Toffoli per bit, with its
carries erased by measurement. The last chunk, bits 200–256, used a slower
in-place Cuccaro adder at two Toffoli per bit, because there was not enough
qubit room for a carry lane there.

This commit splits that last chunk into two windows of about 28 bits, and
each window uses the fast adder. A short comparator then clears the one carry
between the windows. The final chunk drops from about 112 Toffoli to about
84 per add or subtract, and the qubit peak stays at 1320.

To land a clean test set, the author also gave back several truncation bits.
The net is −15,476 average Toffoli.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`.

### 1. Fast windowed final chunk (new pin `DIALOG_GCD_APPLY_FINAL_WINDOWED_FAST_BLOCKS=2`)

- New reader `dialog_gcd_apply_final_windowed_fast_blocks()`. When it is set,
  the final-chunk branch of `dialog_gcd_add_ctrl_chunked_low_to_ext` calls
  `cuccaro_add_fast_windowed_low_to_ext(b, &f, &acc_ext[lo..hi], carry, 2)`.
  `dialog_gcd_sub_ctrl_chunked_low_to_ext` calls
  `cuccaro_sub_fast_windowed_low_to_ext` the same way. Without the pin they
  still take the `DIALOG_GCD_APPLY_FINAL_LOWQ` path (plain `cuccaro_add`).
- The final chunk is `f = ctrl·x[200..256]` (56 bits) added into
  `y_ext[200..257]` (57 bits).
- The windowed adder cuts it at `57 / 2 = 28`:
  - Window 0 is a `cuccaro_add_fast` over bits 0–27 of the chunk, with a fresh
    `cout`. That is 28 CCX.
  - Window 1 is a `cuccaro_add_fast_low_to_ext` over the rest, about 28 CCX.
  - Their carries are erased with `hmr` plus `cz_if`, which costs no Toffoli.
  - Afterwards `cout` is cleared by a 28-bit comparator, another 28 CCX.
- In all that is about 84 CCX, against 2 × 56 = 112 for the old MAJ/UMA
  ripple. That saves about 28 Toffoli per apply add and per apply subtract.
  There are about 520 of those per shot (see [`a91b626`](a91b626.md)), so the
  windowing is worth roughly −14,500.
- **A needed fix in the windowed adder.** The final chunk's carry-in is the
  previous chunk's boundary carry `cout_200`. That carry is dirty and is not
  cleared until the apply's global boundary comparator runs.
  - The window boundary carry is 1 exactly when
    `y_new[..p] < f[..p] + c_in`. The old clear used `cmp_lt_into_fast`,
    which assumes `c_in = 0`.
  - The commit adds `cmp_lt_into_fast_with_cin`. It is the same measured
    comparator, but it starts its borrow chain from the given `c_in` wire
    instead of a fresh zero, so it computes `u < v` when `c_in = 0` and
    `u ≤ v` when `c_in = 1`.
  - `couts` now records each window's carry-in, and both windowed adders
    (`add` and `sub`) clear with it.
  - This is right for 2 windows, where the only boundary's carry-in is the
    adder's own `c_in`. With 3 or more windows, the later boundaries would
    pair a whole-prefix compare with a mid-chunk carry-in, so do not raise
    the pin past 2 without fixing that.
- **Qubits.** The fast windows need carry lanes of about 28 wires, plus the
  comparator's 28 carries. That makes the final chunk's transient about as
  large as the 50-bit chunks before it. It stays under the 1320 floor, so the
  peak is unchanged.

remaining ~14,150 of the measured −15,476, which matches the 28-per-call
estimate.

## Why it is still correct, and what it risks

- **The windowed final chunk is exact.** It computes the same sum as the
  plain Cuccaro adder. Its boundary carry is cleared by an exact (full-prefix)
  comparator that takes the incoming carry into account. Without the
  `_with_cin` fix, every shot whose carry into bit 200 is 1 would leave the
  window's `cout` dirty. The author's first prototype had exactly this bug,
  and it showed up as phase garbage.
- **The give-backs reduce risk.** The double and fold windows and the slope
  all get looser.
- **The 48-bit branch comparator adds risk.** It is tighter than the base's
  52, and a mis-decided branch can stop the GCD from converging (classical
  failure or phase garbage).
- Nonce 192345092161242 draws a clean set: 9,024 of 9,024 shots, with
  0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from splitting a carry chain into windows, each with its own
measured-uncompute adder and a comparator-cleared boundary carry. That is
windowed carry/shift blocks. The knob changes are mostly give-backs, and
only the comparator cut is a truncation saving.

   and run `git checkout c64c03f -- src/point_add`.
   - Do not start from the git parent `bbf7b3a`. That is AnalyticETH's tree,
     on the mpjunior92 / newjordan line, with compare 44, slope 1010, band
     trims and `DIALOG_REROLL=506906`.
   - Diffing against the parent (181 lines) would mix those differences into
     this change.
   - Against `c64c03f`, `git diff --ignore-cr-at-eol c64c03f 2eab923 -- src/point_add`
     is 138 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 2eab923 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*`, `DIALOG_*` or `SUB4_*` environment variables set, because they
   override the defaults. Expect:
   - 1320 qubits
   - 1,545,787 average Toffoli (rounded)
   - score 2,040,438,840
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `192345092161242` and an identical
op stream. Any other change needs a new nonce hunt.

## Summary

This is the same knob as [`61bdeb0`](61bdeb0.md), applied to Gajesh2007's
2006-qubit tree. `SHIFT22_CARRYTAIL_W` goes from 37 to 35, so the direct
constant adders in the shift22 final reduction (`+c`, conditional `−c` and
their two inverses) compute 68 carries instead of 70, which saves 2 Toffoli
per step. [`ccd7530`](ccd7530.md) moved pair1's multiply onto the dirty
shift22, which does not use this window. Only two forward/inverse pairs still
use the clean shift22, so the saving is 2 × 4 × 2 = 16 Toffoli. `KAL_REROLL`
goes from 3 to 27 to land a clean draw.

The commit also deletes two unused wrappers in `cuccaro.rs` and shortens some
comments. Neither changes the op stream.

## What changed and why it saves Toffoli

1. **`shift22_carrytail_cut()`: `SHIFT22_CARRYTAIL_W` 37 → 35**
   (`src/point_add/solinas.rs`).
   - The cut `33 + W` is used by `cadd_nbit_const_direct_fast_cut` and
     `csub_nbit_const_direct_fast_cut` in step 3 and step 4 of
     `mod_shift_left_by_k` and in the two reverse steps of
     `mod_shift_right_by_k`, at one Toffoli per carry position. See
     [`1b913c5`](1b913c5.md).
   - `mod_shift_left_by_k_dirty` (pair1's multiply since `ccd7530`) uses
     venting adders and is not affected. That leaves two executed clean
     shift22 pairs, which matches the clean position-32 folds in the affine
     recompute of [`233a44c`](233a44c.md). So the saving is 2 positions ×
     4 steps × 2 pairs = 16, exactly the observed drop.
   - The doc comment is rewritten, and the list of failing `W` values is
     removed.
2. **`KAL_REROLL`: 3 → 27** (`src/point_add/mod.rs`): identity `X;X` pairs
   that only re-draw the test inputs. A 256-value `KAL_SCREEN` sweep found
   `rr = 27`.
3. **Dead code** (`src/point_add/cuccaro.rs`): `add_nbit_qq_fast_borrow` and
   `sub_nbit_qq_fast_borrow` are removed. Nothing in `src/` calls them.
4. **Comments** in `kaliski_state.rs` (`kal_wtrunc_k0`, `kal_wtrunc_margin`)
   are shortened to cite the new `rr` and score. The values do not change.

## Why it is still correct, and what it risks

- **Exact in practice.** The chain still reaches 35 bits above `c`'s top bit,
  so a carry is dropped only if bits 33…68 of the value are all ones, about
  2^-36 per call. A wrong result shows up as a classical mismatch.
- **Island.** The shipped `rr = 27` draws a clean set: 0 classical, 0 phase
  and 0 ancilla failures over 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A carry chain in the modular reduction is cut two bits shorter, which is
fold/carry truncation. The dead-code removal does not touch the op stream.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ccd7530 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol ccd7530 115ab0e -- src/point_add` is
   50 lines in 4 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 115ab0e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `AFFINE_*`, `SHIFT22_*` or `LOWQ_*` environment variables set. Expect:
   - 2006 qubits
   - 2,575,667 average Toffoli (rounded)
   - score 5,166,788,002
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `KAL_REROLL = 27` and an identical op stream.
Any other change needs a new re-roll search.

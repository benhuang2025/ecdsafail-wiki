## Summary

This is the only commit in its stretch that raises the qubit count, and it
still lowers the score. Two things change:

- The apply loop's 257-bit controlled modular add is built from chunks. It
  now uses four chunks with cuts at 52, 104 and 156, instead of five chunks
  with cuts at 50, 100, 150 and 200. One boundary carry fewer, plus a shorter
  boundary-clearing comparator, makes each add and subtract about one Toffoli
  cheaper. The chunks are wider, though, so the peak rises from 1320 to 1322.
- The dialog-GCD width envelope shrinks faster (slope 1.010 → 1.014 bits per
  step), which narrows the late GCD steps.

Together they save 2,742 average Toffoli. At this size one qubit is worth
about 1,177 Toffoli of score (1,553,445 / 1320), so the 2 extra qubits cost
less than the Toffoli saved. The net score gain is 512,550.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

### 1. Four-chunk apply add: `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS` 5 → 4

Each apply step computes `y += b0 · x (mod p)`. The reverse apply runs the
matching subtract. With `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS` set,
`dialog_gcd_cmod_add_materialized_pseudomersenne_chunked` does the 257-bit
add in chunks, through `dialog_gcd_add_ctrl_chunked_low_to_ext` (or its `sub`
twin). This early-June mechanism is covered in [adders-and-carries](../concepts/adders-and-carries.md). It works like this:

- **Chunks.** `dialog_gcd_chunk_hi()` returns the chunk boundaries. With
  `CUSTOM4=1` and 4 blocks they are `CUT, CUT2, CUT3` and the end (257). With
  `CUSTOM5=1` and 5 blocks they are `CUT … CUT4` and the end.
- **Non-final chunk `[lo, hi)`.** Load `ctrl·x[lo..hi]` into fresh wires `f`
  (one CCX per bit). Add it into `y[lo..hi]` with a measured-uncompute
  Cuccaro adder (`cuccaro_add_fast`, one CCX per bit). The chunk's carry-out
  goes into a boundary wire `cout`. Then erase `f` with `hmr` plus `cz_if`.
  The next chunk uses `cout` as its carry-in.
- **Final chunk.** With `DIALOG_GCD_APPLY_FINAL_LOWQ=1` this is a plain
  in-place Cuccaro add (`cuccaro_add`, MAJ plus UMA, two CCX per bit and no
  carry lane).
- **Clearing the boundary carries.** Afterwards the dirty `cout` wires are
  cleared together by one comparator over the prefix up to the last cut.
  The carry into bit `p` of `y + x` is 1 exactly when the new
  `y[..p] < x[..p]`. That comparator is
  `ccx_cmp_lt_into_fast_prefix_targets_split`. It costs one CCX per prefix
  bit plus one per target. `DIALOG_GCD_APPLY_BOUNDARY_SPLIT` names a cut
  where the comparator restarts, using that boundary's `cout` as the carry-in
  of the upper window, so the two windows' carry lanes are never live at the
  same time.
- **Qubits.** The live transient during the add scales with the widest
  chunk (its `f` plus its carry lane) or the widest comparator window.

Old and new layout:

| | chunks | non-final adds (CCX) | final add (CCX) | boundary clear (CCX) | total per add, excluding the 256 load CCX |
| --- | --- | --- | --- | --- | --- |
| base | 50, 50, 50, 50, 57 | 4 × 50 = 200 | 2 × 56 = 112 | 200 + 4 targets = 204 | 516 |
| this | 52, 52, 52, 101 | 3 × 52 = 156 | 2 × 100 = 200 | 156 + 3 targets = 159 | 515 |

These counts are mine, from the code. The final chunk is about twice as
expensive per bit, and that offsets the shorter comparator. Net, each add and
each subtract saves about one Toffoli: one fewer boundary target. Each apply
step makes one add (or subtract) and two doubles (or halves), and the
one-bit double-window cut in [`c64c03f`](c64c03f.md) implies about 1,038
double/halve calls per shot. So there are about 520 apply adds and subtracts
per shot, and the re-cut saves on the order of 500 Toffoli. Pins changed:

- `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS`: 5 → 4.
- `DIALOG_GCD_APPLY_CHUNKED_F_CUSTOM4`: 0 → 1, and `CUSTOM5`: 1 → 0.
- `DIALOG_GCD_APPLY_CHUNKED_F_CUT` / `CUT2` / `CUT3`: 50 / 100 / 150 → 52 / 104 / 156.
  `CUT4` stays at 200, but the four-chunk layout ignores it.
- `DIALOG_GCD_APPLY_BOUNDARY_SPLIT`: 100 → 52, so the split is again on a cut.
  The comparator's upper window is now bits 52–156 (104 bits), against
  100–200 (100 bits) before.

The wider non-final chunks (52 against 50 bits) and the wider upper
comparator window (104 against 100 bits) raise the apply transient. The
global peak goes from 1320 to 1322.

### 2. `DIALOG_GCD_WIDTH_SLOPE_X1000`: 1010 → 1014

`dialog_gcd_tobitvector_active_width(step)` is
`256 − step × slope + WIDTH_MARGIN` (margin 10), rounded up to an even
number. A slope 0.004 steeper narrows step `s` by `0.004 × s` bits, about
1 bit at step 258. Each window bit removed from a step saves about one CCX in
the cswap and about two in the controlled subtract (gated load plus ripple),
in every forward and reverse pass. By the estimate above, the four slope
notches give the remaining ~2,200 Toffoli. Neither part was measured alone.

### 3. `DIALOG_TAIL_NONCE`: 22000964 → 198702767358738

The 48 `X;X` identity pairs at the end of `build_builder()` only reseed the
9,024 test inputs.

## Why it is still correct, and what it risks

- **The chunk re-cut is exact.** A chunked add gives the same sum for any
  set of cuts. The boundary-clear comparator is full width over the prefix,
  so it clears every `cout` exactly. A layout bug would show up as ancilla
  garbage.
- **The slope is probabilistic.** An input whose GCD registers shrink more
  slowly than the steeper envelope loses high bits. It gives a classical
  failure, or phase or ancilla garbage on the reverse pass.
- The author says they kept 259 steps instead of cutting to 258, because the
  hard inputs of the 258 routes cluster at convergence. Nonce
  198702767358738 draws a clean set: 9,024 of 9,024 shots, with 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The structural change is a re-cut of the chunked (windowed) carry blocks of
the apply adder, so the commit is filed as windowed carry/shift blocks. The
slope notch is a width truncation and is probably the larger Toffoli piece,
so comparator/width truncation is the runner-up. What sets this commit apart
is that it pays qubits for Toffoli.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 66c6dac -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 66c6dac a91b626 -- src/point_add` is 18 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a91b626 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*`, `DIALOG_*` or `SUB4_*` environment variables set, because they
   override the defaults. Expect:
   - 1322 qubits
   - 1,553,445 average Toffoli (rounded)
   - score 2,053,654,290
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `198702767358738` and an identical
op stream. Any other change needs a new nonce hunt.

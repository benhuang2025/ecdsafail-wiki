## Summary

In the base, the divide replay peaked at 1300 qubits and the multiply replay at
1301. The multiply cell keeps one extra wire alive during its chunked add, so
it was one qubit wider. This commit gives the multiply traversal one round
fewer than the divide traversal (699 against 700). Its tape is one qubit
shorter, so both replays now peak at 1300. Dropping that round also saves about
365 Toffoli.

The commit also switches the product-register square's wide adds from one
full-width carry ladder to the replay's chunked adder. That lowers the square's
own peak from 1287 to 1118 qubits, which does not move the global peak yet, and
costs about 429 Toffoli. Net: −1 qubit and +71 Toffoli. The square change
prepares for later commits that push the replay below 1287.

## What changed and why it saves a qubit

1. **Multiply depth: `rounds()` → `rounds() − 1`** in `rounds_for()`,
   `Multiply` arm, `src/point_add/pingpong_div.rs`.
   - `rounds_for(direction)` already existed in the base. `Divide` returns
     `rounds()` (700). `Multiply` returns
     `tuned_window("SUB4_PP_ROUNDS_MUL", &SLOT, default)`. Only the default
     changes, from `rounds()` to `rounds() − 1`, so the multiply walk,
     replay and walk-back run 699 rounds.
   - **Why the two traversals peak differently.** The multiply replay runs
     the doubling recurrence `t ← 2t ± s (mod p)`. Its fused cell must keep the
     bit shifted out of the top of `2t` (`doubled_out`) alive across the
     chunked add. The divide cell has no such bit. The author's note gives the
     two plateaus:
     ```
     divide:   tape 700 + coefficient 256 + numerator 256 + 2 terminal signs + 86-wide chunk ladder = 1300
     multiply: tape 699 + 512 + 2 + 86 + 1 (doubled_out)                                          = 1300
     ```
     Before this commit the multiply tape was 700 long, giving 1301. The note
     says several attempts to fold `doubled_out` away all moved it into a
     carry-in that is an AND of two data bits, so it is the same extra wire.
   - **Toffoli.** The removed round drops one walk add, one walk-back add and
     one fused replay cell. The author measures −365 executed Toffoli.
   - The code comment estimates the convergence cost of one round on one
     traversal at about +0.05 λ.
2. **Square chunking: `SQUARE_CHUNK_MIN` `usize::MAX` → `200`** in
   `src/point_add/trailmix_ludicrous/square/product_register.rs`.
   - `add_full(circ, addend, acc)` sends any add of at least `SQUARE_CHUNK_MIN`
     bits to `pingpong_div::add_chunked_measured`. Shorter adds keep
     `arith::hybrid_add_adaptive` with no chunking. At `usize::MAX` no add was
     ever chunked. The env override `SUB4_SQUARE_CHUNK_MIN` still works.
   - `add_chunked_measured` splits the add into chunks of at most `REPLAY_CHUNK = 96`
     bits, so a 257-bit add becomes 3 chunks (86, 86, 85) with 2 boundary carries. Each boundary
     carry is erased by `hmr` and a phase-conditioned compare of the top
     `REPLAY_CHUNK_COMPARE = 23` bits of the chunk. Only one chunk's carry
     ladder is live at a time. See
     [adders-and-carries](../concepts/adders-and-carries.md), "Chunked adders
     and carry erase".
   - The adds affected are the three `tri_corr` adds per triangular square,
     forward and inverse, plus the small-shift `mod_add_top` adds. The author
     counts about 24 such adds per shot.
   - The author's numbers: square peak 1287 → 1118, square executed Toffoli
     59,304 → 59,733 (+429), and about 48 extra boundary compares per shot.
     Before this, the square's peak owner was a 257-carry ladder on top of
     `product_c` (258), `sum` (129), pads (129), `x`, `y` (512) and 2 flags.
3. **Tail nonce**: the `SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`, goes from 1002365 to 2000563. The author found it
   after 563 early-abort draws.
4. **Notes**: `src/point_add/memory/07-pingpong-liveness.md` is deleted and
   `08-pingpong-1300.md` is added. The new note holds the plateau arithmetic
   above and a per-phase profile: each replay is about 241.6k executed
   Toffoli at peak 1300, each walk and walk-back about 98.8k at peak 1063. No
   effect on the circuit.

## Why it is still correct, and what it risks

- **The shorter multiply depth is probabilistic.** A multiply-direction input
  whose walk needs all 700 rounds now ends dirty, which gives classical and
  ancilla failures. The author's model gives a per-walk failure of about
  2.5–4×10⁻⁴ at 700 rounds, and one round on one traversal adds about
  0.05–0.1 to λ. They measured λ ≈ 7 on this stream (1 clean nonce in 1,280
  draws), in line with the parent (3 clean in 2,858).
- **The square chunking is value-exact but phase-probabilistic.** The sum is
  computed exactly. Each boundary carry is erased by measurement, and its
  phase repair compares only the top 23 bits. On a tie in those bits the repair
  is wrong and a phase failure results. With about 48 boundaries per shot the
  author estimates λ += 48 · 2⁻²³ · 9,024 ≈ 0.05. See
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- The shipped nonce `2000563` draws a clean test set: 9,024 of 9,024 shots, with
  0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change that moves the score is one fewer iteration of the multiply walk,
which shortens the tape at the peak. That is iteration/threshold tuning, the
same lever as [`be0c8bc`](be0c8bc.md). The square chunking is a liveness change
(ancilla-lifetime / scratch budget), but it does not touch the global peak in
this commit and costs Toffoli, so it is the runner-up, not the primary.

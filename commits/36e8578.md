## Summary

Inside the Kaliski inverse, the GCD registers `u` and `v_w` shrink as the
iterations go on. The code only used the provable bound on their width: 256
bits for the whole first 256 iterations, then `2n − iter`. In practice they
shrink much faster. This commit adds **W-TRUNC**, an empirical envelope fitted
to 80,000 random inputs:
- `w_env(it) = 256` for `it < 27`;
- `w_env(it) = 256 − ⌊(it − 27)·2/3⌋` afterwards.

It adds a safety margin of 32 bits and clips every Toffoli-bearing width loop
of the iteration to `min(provable, w_env + 32)`. The clipped loops are the
`v_w == 0` OR chain, the `u > v_w` comparator, and the STEP 4 load and
subtract.

From iteration 77 on, every such loop loses about two bits for every three
iterations. Over the roughly 1,600 Kaliski iterations per shot this saves
294,600 Toffoli, about 9% of the circuit. Qubits are unchanged. The cost is a
probabilistic assumption: an input whose GCD registers stay more than 32 bits
above the fitted envelope would be computed wrongly.

## What changed and why it saves Toffoli

Background on the Kaliski iteration: see [`a3ee589`](a3ee589.md).

### New knobs (`src/point_add/kaliski_state.rs`)

- `kal_wtrunc_enabled()`: on unless `KAL_WTRUNC=0`. The block comment says
  "Default OFF". That comment is stale: the code is default on.
- `kal_wtrunc_k0()`: 27 (`KAL_WTRUNC_K0`), the full-width prefix length.
- `kal_wtrunc_margin()`: 32 (`KAL_WTRUNC_MARGIN`). The comment above it
  says "Default 16", but the code returns 32.
- `kal_wtrunc_width(iter, n)` returns `min(n, w_env(iter) + margin)`.
  - Example: at iteration 100 it is `256 − 48 + 32 = 240`; at 254 it is
    `256 − 151 + 32 = 137`; at 350 it is `256 − 215 + 32 = 73`.
  - Before about iteration 77 the result is 256, so nothing changes there.
  - After iteration 256, the provable bound `2n − iter` is larger than the
    envelope (for example 162 vs. 73 at iteration 350), so W-TRUNC keeps
    clipping right to the end.

### Where it is applied (`src/point_add/kaliski_walk.rs`)

Every site takes `old_width.min(kal_wtrunc_width(iter_idx, n))`, so a loop is
never widened.

| Site | Function(s) | Cost per bit |
| --- | --- | --- |
| STEP 0 OR chain `or_width` (test `v_w == 0`) | generic `kaliski_iteration` and `kaliski_iteration_backward` | about 1 CCX |
| STEP 2 comparator `cmp_width` (`with_gt(u, v_w)`) | bulk and generic, forward and backward | about 1 CCX |
| STEP 4 `load_width`: `tmp[i] = add_f & u[i]`, then `v_w -= tmp` over the same width (`sub_nbit_qq_fast[_mfut]`) | bulk and generic forward | 1 CCX load, plus subtractor carries |
| STEP 4 reverse `transform_width` / `add_width` (must equal the forward `load_width`) | bulk and generic backward | as above |

The bulk forward STEP 4 unload also changes. `tmp` is measured away bit by
bit with `hmr`. Bits in `[transform_width, load_width)` are phase-repaired
with `cz_if(add_f, u[i])`. Bits at or above `load_width` were never loaded,
so they are |0⟩ and need no repair; before, they got a `cz_if` on a zero
`u` bit. See [measurement-uncompute](../concepts/measurement-uncompute.md).

The `(u, v_w)` swaps of STEP 3 and STEP 9 are **not** clipped. Neither are the
Bézout-side `r`, `s` loops, which grow instead of shrink.

## Why it is still correct, and what it risks

- **The clip is probabilistic.** A loop of width `w` assumes `u` and `v_w`
  have no set bit at or above `w`. If an input's GCD registers stay longer
  than the envelope plus 32 bits, a high bit is ignored. Then:
  - the comparison picks the wrong branch, or
  - the subtraction drops a borrow, or
  - the OR chain misses a nonzero `v_w`.

  The inverse is then wrong. That shows up as a classical mismatch, and the
  broken backward run can also leave phase or ancilla garbage.
- **How likely that is.** The code comment reports that the envelope has 1 to
  7 bits of slack above the 80,000-input sample maximum, and that on 300,000
  fresh inputs the minimum slack in the clipped region equalled the margin.
  So 32 bits of margin is a large cushion. Later commits push the margin down
  step by step: [`fc8b9e6`](fc8b9e6.md) takes it from 4 to 3,
  [`e739b53`](e739b53.md) from 3 to 2, and
  [`6eba4e3`](6eba4e3.md) and [`bf19c9e`](bf19c9e.md) to 1 and 0.
- **The forward and backward widths are the same function of
  `iter_idx`.** So the backward run undoes exactly what the forward run did,
  for every input that satisfies the envelope.
- There is no tail nonce in this era. The test set is a hash of the op stream,
  and this stream's draw is clean: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md)
  and [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

## Classification rationale

The commit narrows comparators, OR chains and adders to fewer bits on an
empirical bound: comparator/width truncation.

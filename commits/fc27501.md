## Summary

The binary GCD's swap decision compares the top `DIALOG_GCD_COMPARE_BITS` bits
of its two registers. Every earlier commit on this line had nudged that cap one
or two bits at a time (`4527ae1`: 74 → 73, `dda7bfd`: 74 → 72). This commit
asks how many bits are actually needed. A classical replay of the truncated GCD
over 300,000 inputs, run on both GCD factors, found that a 52-bit comparator
never makes a wrong decision. So the cap goes from 74 to 52, which saves 17,864
Toffoli.

Part of that slack is then spent on correctness margin elsewhere. The width
envelope's margin goes from 9 to 10 bits, which widens about half the GCD
steps by 2 bits and costs 4,184 Toffoli. The author found that width truncation
was the main source of hard inputs, and margin 10 cut the expected hard inputs
per draw from about 11 to about 5. That made the nonce hunt fast. The net is
−13,680 Toffoli at the same 1390 qubits.

## What changed and why it saves Toffoli

**Background.** The circuit is the dialog-GCD route (`emit_dialog_gcd_raw_pa`
in `src/point_add/mod.rs`). Two calls each run a reversible binary GCD on
(u, v) = (p, factor): the quotient dy/dx and the product with c = ox − Rx. Each
call has a forward pass, an apply pass and a reverse pass. [98416e4](98416e4.md)
lists one GCD step. [dda7bfd](dda7bfd.md) explains the comparator: it compares
`u[aw−k..aw]` against `v[aw−k..aw]`, where `aw` is the step's active width and
`k = min(DIALOG_GCD_COMPARE_BITS, aw)`. It costs one Toffoli per compared bit in
each of the four GCD passes.

**The changes in `configure_ecdsafail_submission_route()`:**

1. **`DIALOG_GCD_COMPARE_BITS`: 74 → 52.**
   - Until about step 190, the window is wider than 74 bits, so each comparison
     loses 22 bits. Between steps 190 and 212 the loss tapers to zero.
   - The total is 4,466 bit-steps × 4 passes = 17,864 Toffoli.
   - The comment says "73 → 52" because the author counted from the frontier
     `4527ae1`. The tree this commit actually edits, `5174a69`, has 74.
   - The commit comment claims "−28,392 (21 bits × 2 dirs × 2 passes, comparator = 2 T/bit)".
     That is an overestimate: the comparator costs 1 Toffoli per bit, not 2. The
     measured net matches the 1-Toffoli count.
2. **`DIALOG_GCD_WIDTH_MARGIN`: 9 → 10.**
   - The margin is the constant in
     `active_width(step) = clamp(2·⌈(256 − 1.004·step + MARGIN)/2⌉, 1, 256)`.
   - One more bit of margin pushes the rounded width up by 2 bits on every
     other step from step 11 on: 125 steps, or 250 bit-steps.
   - At about 16 to 20 Toffoli per bit-step over the four passes, that costs
     4,184 Toffoli. The commit comment gives the same cost as +5,815,760 score
     (4,184 × 1390).
3. **`DIALOG_TAIL_NONCE`: 7046 → 127.** The author found it with a parallel
   classical prefilter (`harness/fasteval`, not part of `src/point_add`) and then
   confirmed it with the full evaluator. The comment lists 354 and 418 as backup
   nonces.

−17,864 + 4,184 = −13,680, the measured change.

## Why it is still correct, and what it risks

- **Comparator.** A truncated comparator is wrong only when u and v agree on
  every compared bit but differ lower down. The swap is then skipped, `v − u`
  wraps, and the GCD output is wrong. That is a classical failure.
  - Early in the walk both values fill most of the 256-bit window, so 52
    compared bits are all significant, and a tie is vanishingly rare.
  - Later, the window's top bits lie above the values. The useful compared width
    is then roughly 52 minus the slack between the window and the real bit
    length.
  - The author's both-factor classical filter (`dx_hard_step`) saw 0
    mis-decisions at 52 bits over 300k checks. This is evidence, not a proof.
- **Margin.** Widening the window makes width-overflow failures rarer. This is
  the dominant hard-input source. The author counted about 83 failing factor
  checks per 300k at margin 9 and about 27 at margin 10.
- **Both factors.** The note stresses that a filter must replay both GCD inputs
  per point add: dx = Px − Qx, and c = ox − Rx, where Rx is the expected output
  x. Checking only dx undercounts the hard rate about 2×.
- The shipped nonce `127` draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures over all 9,024 shots.

## Classification rationale

The saving is a comparator narrowed to the bits that matter, which is
comparator/width truncation. The margin change goes the other way. It is a
deliberate give-back that buys λ, so it is not a separate lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5174a69 -- src/point_add`.
   - The git parent is `f0e2891`, robertkodra's tree. That tree carries the
     37 uncompiled files from `af0f90a`, comparator 72, slope 1008 and fold
     window 24.
   - Against the parent, the diff is 9,352 lines in 38 files. It deletes those
     37 files and reverts slope and comparator choices from that line. None of
     that is this commit's work.
   - Against `5174a69`, `git diff --ignore-cr-at-eol 5174a69 fc27501 -- src/point_add`
     is 30 changed lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol fc27501 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset. Expect:
   - 1390 qubits
   - 1,519,735 average Toffoli (rounded)
   - score 2,112,431,650
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `127` and an identical op stream. Any
other change needs a new nonce hunt.

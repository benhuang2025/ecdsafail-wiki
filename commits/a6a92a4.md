## Summary

One more step off the dialog-GCD length, after [11ceae2](11ceae2.md) (258 → 262)
and [f37a0bc](f37a0bc.md) (262 → 261). `DIALOG_GCD_ACTIVE_ITERATIONS` goes from
261 to 260, so every walk, apply pass and reverse walk is one step shorter. That
saves 2,845 Toffoli, almost all of it in the two apply passes. Qubits are
unchanged, and the tail nonce was re-hunted.

The submission note describes the change as 262 → 260 from `11ceae2`. The tree
is `f37a0bc` with one more step removed. Against `f37a0bc` the diff is
smaller, so that is the base.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 261 → 260.**
   - `dialog_gcd_active_iterations()` is the loop bound for every walk, apply
     and reverse-walk emitter in `rounds/dialog/` (background in
     [8316db1](8316db1.md)).
   - The dropped step 260 has `active_width` 4, so its walk steps are nearly
     free. Each division's apply step is a modular double or halve of `y`, a
     controlled 256-bit modular add or subtract with its overflow clean, and a
     256-wide controlled swap. That is about 1,400 Toffoli per division, 2,845
     in total.
   - The body band trim `"0,1"` now has band size `ceil(260 / 2) = 130`, so it
     trims steps 130 to 259 instead of 131 to 260. The number of trimmed steps
     stays 130. Only which step is trimmed moves, which explains the small
     difference from the 2,853 of [f37a0bc](f37a0bc.md).
2. **`DIALOG_TAIL_NONCE`: 5646 → 58134**, the fixed 48-pair `X;X` identity
   tail that reseeds the 9,024 test inputs.
3. The comments are updated to match.

## Why it is still correct, and what it risks

An input whose K2 GCD needs more than 260 steps does not reach its terminal
state. It gives a wrong slope, and so a wrong output point (a classical
failure) and leftover garbage after the reverse walk (an ancilla or phase
failure). The classical pre-filter from [88079e6](88079e6.md) flags such inputs
as `NonConvergence`. Each step removed adds inputs to the hard set, so clean
nonces get rarer. The author found clean islands at `58134` and `58618` with a
GPU nonce search.

All other truncations are unchanged. The shipped nonce `58134` draws a test
set with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a loop count, so iteration/threshold tuning fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f37a0bc -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol f37a0bc a6a92a4 -- src/point_add` is
   17 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a6a92a4 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1309 qubits
   - 1,492,097 average Toffoli (rounded)
   - score 1,953,154,973
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=58134` and an identical op
stream. Any other change needs a new nonce hunt.

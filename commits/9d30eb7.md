## Summary

This commit makes two changes on the author's own K=2 tree ([0780f67](0780f67.md)).

1. **Carry windows.** The apply passes of the dialog GCD double (or halve) the
   coefficient and fold in `c = 2^32 + 977` with constant adders whose carry
   chain stops `w` bits above bit 32. [0780f67](0780f67.md) had widened `w`
   from 20 to 24 for both the doubles and the folds. This commit puts both back
   to 20. That saves 4 Toffoli per truncated add, and there are about 1,550 of
   them, so about 6,220 Toffoli. The windows are probabilistic, so this adds
   failure risk.
2. **Last chunk cut.** The same 168 → 170 move as robertkodra's
   [a772a45](a772a45.md), but only for the last cut. The last apply-add chunk
   shrinks from 89 to 87 bits, so the peak falls by 4 qubits. The longer
   boundary-clear prefix costs 1,036 Toffoli.

The net is −5,188 Toffoli and −4 qubits. A new tail nonce was hunted.

## What changed and why it saves Toffoli and qubits

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`KAL_DOUBLE_CARRY_TRUNC_W`: 24 → 20 and `KAL_FOLD_CARRY_TRUNC_W`: 24 → 20.**
   - `double_carry_trunc_window()` is read by the lazy modular double and
     halve:
     - `mod_double_inplace_fast` and `mod_halve_inplace_fast`, run once per
       apply step;
     - the K=2 conditional `cmod_double_inplace_lazy` and
       `cmod_halve_inplace_lazy`, also run once per apply step.
   - `fold_carry_trunc_window()` is read by the pseudo-Mersenne overflow and
     underflow folds after each apply step's raw 256-bit add or subtract, for
     example in `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`.
   - All of these call `cadd_nbit_const_direct_trunc_fast` (or its `csub`
     twin). Its carry chain covers bits `0 ..= hi + w`, where `hi = 32` is the
     top bit of `c`. Above bit 32, `c` has only zeros, so each position costs
     one `ccx` (carry = `acc_i ∧ carry_{i−1}`). The carries are erased by
     measurement at no Toffoli.
   - So 4 fewer window bits save 4 Toffoli per call. There are about three
     truncated adds per apply step, in 259 steps and two passes, which is about
     1,554 calls. That gives about 6,220 Toffoli. Together with the +1,036
     below, this matches the measured −5,188.
2. **`DIALOG_GCD_APPLY_CHUNKED_F_CUT3`: 168 → 170.**
   - `CUT` and `CUT2` stay at 56 and 112. The chunks become 56/56/58/87 bits
     instead of 56/56/56/89.
   - The last chunk `[CUT3, 257)` holds `256 − CUT3` loaded wires plus as many
     carry wires (`cuccaro_add_fast_low_to_ext`). That drops from 176 to 172
     transient qubits, and the apply raw sum and difference were the peak
     phases, so the peak goes 1394 → 1390.
   - The exact boundary-carry clear `ccx_cmp_lt_into_fast_prefix_targets` runs
     over the prefix up to the last cut, now 2 bits longer. That is
     2 Toffoli × 259 steps × 2 passes = 1,036 Toffoli. The mechanism is
     described in detail in [a772a45](a772a45.md).
3. **`DIALOG_TAIL_NONCE`: 124 → 25**, the 48-pair identity tail that reseeds
   the 9,024 test inputs.

## Why it is still correct, and what it risks

- **The chunk cut is exact.** The chunked add is exact for any boundaries.
- **The 20-bit windows are probabilistic.** The truncated add gives a wrong
  high part when a carry from bit 32 or below runs through an unbroken run of
  `w + 1` ones above bit 32. That has probability about `2^-(w+1)` per call
  for random data, so going from 24 to 20 bits makes it about 16 times more
  likely. Summed over roughly 1,550 calls per shot, that is about 7 × 10^-4
  per shot. That is a rough estimate for uniform data, and the lazy coset
  values are not exactly uniform.
- **How a failure shows.** The carries themselves follow the exact recurrence
  and return to 0, so a hit leaves no ancilla garbage in the adder. It does
  give a wrong coefficient, so a classical mismatch. The forward and reverse
  apply also stop agreeing, which can leave garbage.
- The author reports that windows of 16 or less "break the uncompute" on
  their screen.
- The shipped nonce `25` draws a test set with 0 classical, 0 phase and
  0 ancilla failures over all 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Most of the Toffoli saving is a narrower carry window in the constant-fold
adders. That is a truncation of a carry chain, so "fold/carry truncation"
would fit as well as the published comparator/width truncation. The chunk-cut
move is a windowed-block rebalance that buys the 4 qubits. The census label is
kept.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0780f67 -- src/point_add`.
   - Do not start from the git parent `a772a45`. That is robertkodra's tree,
     which moves all three cuts, to 58/114/170.
   - Against the parent, the diff would show `CUT` and `CUT2` going back from
     58/114 to 56/112. This commit never moved them.
   - Against `0780f67`, `git diff --ignore-cr-at-eol 0780f67 9d30eb7 -- src/point_add`
     is 8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9d30eb7 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,624,263 average Toffoli (rounded)
   - score 2,257,725,570
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=25` and an identical op
stream. Any other change needs a new nonce hunt.

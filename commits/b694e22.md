## Summary

The author's [`0aa33ed`](0aa33ed.md) narrowed two carry windows on the
`ad02935` line. This commit re-tunes the same two windows on josusanmartin's
`985ae0f`, which carries the measured clean compares, with a slightly looser
fold window:

- **Double/halve window: 24 → 20.** The carry window of the truncated
  constant adder in the modular double and halve. Each removed carry position
  costs 1 Toffoli. There are 820 calls, so this saves 4 × 820 = 3,280.
- **Fold window: 22 → 20.** The window of the 73-bit pseudo-Mersenne fold in
  the apply-phase add and subtract. There are 798 calls, so this saves
  2 × 798 = 1,596.

The total is 4,876 Toffoli. Qubits stay at 1698. The reroll goes from 21 to
12.

## What changed and why it saves Toffoli

`configure_ecdsafail_submission_route()` in `src/point_add/mod.rs` changes
three pins:

- **`KAL_DOUBLE_CARRY_TRUNC_W`: 24 → 20.**
  - The adders are `cadd_nbit_const_direct_trunc_fast` and
    `csub_nbit_const_direct_trunc_fast`, introduced in [`f8a36ba`](f8a36ba.md).
    They are called from `mod_double_inplace_fast` and `mod_halve_inplace_fast`.
  - Each makes carries only up to `32 + window`. The last carry moves from
    56 to 52.
  - Carries 53–56 lie above the top set bit of `c = 2^32 + 977`, so each
    cost 1 CCX.
  - The calls are 399 + 399 apply-loop doubles and halves, 20 in the x-tail
    square and 2 in `mod_add_double_qb`. That gives 820 × 4 = 3,280.
- **`KAL_FOLD_CARRY_TRUNC_W`: 22 → 20.**
  - The folds are in the `overflow_fold` and `underflow_fold` phases of
    `dialog_gcd_cmod_add/sub_materialized_pseudomersenne`, introduced in
    [`ad02935`](ad02935.md).
  - The last carry moves from 54 to 52, which removes 2 CCX per call.
  - There are 399 adds and 399 subtracts, so 798 × 2 = 1,596.
- **`DIALOG_REROLL`: 21 → 12.** The number of identity `X;X` pairs on
  `tx[0]` that reseed the test set.

The total is 3,280 + 1,596 = 4,876, exactly the measured drop.

## Why it is still correct, and what it risks

Both windows are probabilistic. The truncated adder drops a carry only when
the register has a run of about `window + 1` ones just above bit 32. That
happens with probability about 2^−21 per call, for both windows at 20.

- A dropped carry corrupts the high bits of y, which is a classical failure.
- In the fold, it can also make the following 20-bit clean compare misjudge,
  which leaves the overflow wire dirty.
- The kept carries are erased exactly.

The fold is tighter than the base's 22 but looser than `0aa33ed`'s 18. The
memory note in [`eda50f2`](eda50f2.md) records that 19 failed on this line at
reroll 12. Reroll 12 draws a clean set: 0 classical, 0 phase and 0 ancilla
failures over 9,024 shots.

## Classification rationale

The published label is comparator/width truncation, but no comparator or
register width changes. Both knobs are carry-tail windows of
reduction-constant adders, so **fold/carry truncation** fits better. It is the
same lever as `0aa33ed`, which the census filed under yet another label,
measurement uncompute.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 985ae0f -- src/point_add`.
   - Do not start from the git parent `9805d0c`. This commit was built on
     `985ae0f`.
   - Against the parent, the diff is 91 lines. It would also revert
     Epistetechnician's odd-u fastpath from [`9805d0c`](9805d0c.md).
   - Against `985ae0f`, `git diff --ignore-cr-at-eol 985ae0f b694e22 -- src/point_add`
     is 6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b694e22 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1698 qubits
   - 1,668,753 average Toffoli (rounded)
   - score 2,833,542,594
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 12 and an identical op
stream. Any other change needs a new reroll search.

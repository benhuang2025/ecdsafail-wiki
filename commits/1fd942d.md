## Summary

This commit makes the same move as [`eda50f2`](eda50f2.md), but one bit
further. It was built in parallel on the same base. The margin added to the
per-step GCD comparator-width table goes from 8 to 6.

- On the 128 steps where the margin already bound at 8, the comparator loses
  2 bits.
- On 32 more steps, the margin now binds and the comparator loses 1 bit.

That is 288 bits in total. Each bit costs 1 Toffoli at each of the 4 fused
comparator sites per step, so the saving is 288 × 4 = 1,152 Toffoli. Qubits
stay at 1698. The reroll goes from 12 to 29.

## What changed and why it saves Toffoli

`configure_ecdsafail_submission_route()` in `src/point_add/mod.rs` changes
two pins:

- **`DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN`: 8 → 6.**
- **`DIALOG_REROLL`: 12 → 29.** The number of identity `X;X` pairs on `tx[0]`
  that reseed the test set.

Each step's compare width is

```
k(step) = max(1, min( min(63, w), min(max(table[step] + margin, 1), w) ))
```

from `dialog_gcd_compare_bits_for_step`. Here `w` is the step's active width
and `table` is `DIALOG_GCD_PA9024_COMPARE_SCHEDULE`, both described in
[`f8a36ba`](f8a36ba.md).

Going from margin 8 to margin 6 lowers `k` on 160 of the 399 steps:

- by 2 on 128 steps;
- by 1 on 32 steps, where `table + 7` hits the cap or the width.

These steps are mostly in the first ~200 steps of the walk. The sum of the
drops is 288.

The fused swap comparator ([`9b6b9d6`](9b6b9d6.md)) costs `k + 1` CCX. It
runs at 4 sites per step: the forward and reverse walk, in both GCD pairs. So
the saving is 4 × 288 = 1,152, exactly the measured drop.

## Why it is still correct, and what it risks

The narrower comparison misjudges `u > v` when u and v agree on their top `k`
bits. The walk then takes the wrong branch, which is a classical failure. Two
bits off the margin roughly quadruples that tie chance on the 128 steps where
the margin already bound. The narrowest early steps carry most of the risk.
The cost is a larger Lambda and a longer reroll search: the shipped value is
29. Reroll 29 draws a clean set: 0 classical, 0 phase and 0 ancilla failures
over 9,024 shots.

## Classification rationale

One comparator-window margin is narrowed, so this is comparator/width
truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b694e22 -- src/point_add`.
   - Do not start from the git parent `eda50f2`. This commit was built on
     the author's `b694e22`.
   - Against the parent, the diff is 42 lines. It would also delete
     Epistetechnician's memory note and replace that commit's margin 7 and
     reroll 4.
   - Against `b694e22`, `git diff --ignore-cr-at-eol b694e22 1fd942d -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1fd942d -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1698 qubits
   - 1,667,601 average Toffoli (rounded)
   - score 2,831,586,498
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 29 and an identical op
stream. Any other change needs a new reroll search.

## Summary

The author starts from the parent tree `58229f8` but reverts its only
circuit change, the late merged window 58 → 52. The result is
[`9440086`](9440086.md) plus a recipe retune. Everything changed is an
existing Leapfrog parameter, plus a second W1 anchor table. There are two
parts:

1. **A qubit-for-Toffoli dial.** The walk cap goes 1243 → 1244, and the
   early-tick reorder goes 76 → 77. The author measured −767 T for the extra
   qubit.
2. **Four window sells**, each priced by the author on common inputs:

   | lever | ΔT (author) | Δλ (author, shots per 9,024) |
   | --- | ---: | ---: |
   | `LF_W1K` 24 → 18, anchors −4 | −1,061 | +0.67 |
   | `LF_MERGED_WIN` 61 → 56 | −1,037 | +0.24 |
   | `LF_CELL_FOLD_MIN` 56 → 54 | −1,142 | +0.57 |
   | `LF_CMP_SHIFT` 2,3 → 1,1 | −1,307 | +0.64 |

Against `9440086` the net is +1 qubit and −5,349 Toffoli, a score of
−5,850,902. The author's own-source λ is 16.48 ± 0.36.

## What changed and why it saves Toffoli

All changes are in `src/point_add/leapfrog.rs`, except the nonce.

1. **`HEO_PIN_PP_WALK_MAX_QUBITS` 1243 → 1244 and `LF_REORDER` 76 → 77.**
   - The cap is `cells::cap()`, the room every split decision reads
     (`capped_add`, `rail_add`, `lpa_capped`, `merged_fits`, `merged_split`).
   - `LF_REORDER=T` moves ticks `0..T` of the payload-fused traversals into a
     rails-only pass plus a payload-only pass over the taped letters (see
     [`86221ad`](86221ad.md)). Tick 76 now joins that split.
   - With one more wire, fewer rail adds and folds must split their carry
     ladders, and a split costs about `(w − 1)/2` extra Toffoli. This is the
     only qubit change; the peak follows the cap to 1244.
2. **`LF_W1K` 24 → 18, with a new anchor table.**
   - `w1_anchor` now loads `leapfrog_data/anch_w1_k18a4.txt` when
     `w1_k() == 18`. The comment says: "K = 18 reads its window 4 bits lower:
     every anchor - 4, floored at 3".
   - The W1 window is `[anchor − K, anchor − K + K + 2)`. With the old anchor
     `a` it was `[a − 24, a + 2)`; now it is `[a − 22, a − 2)`. The bottom
     rises 2 bits and the top drops 4.
   - At tick 0 (anchor 258 → 254, choice width 258) the compare reads 20 rail
     wires instead of 23. Positions at or above the sign wire were already
     constants.
   - `w1_chain` spends about one AND per window position. That cost comes on
     every forward tick, and on half the reverse ticks (the W1 compare in
     `fast_choice_erase` runs only when the measurement outcome is 1).
   - The author found that the decision error comes mostly from where the
     window's bottom bit sits. Narrowing from the top while re-anchoring
     keeps most decisions. At the old anchors, 18 or 20 bits cost far more λ.
3. **`LF_MERGED_WIN` 61 → 56 (new pin; 61 was the default).**
   - This is the standard merged op's fold window `[0, MW)`, so each merged
     op (forward and reverse) loses 5 ladder positions.
   - `LF_MERGED_LATE_WIN` stays 58, but `merged_fits` takes
     `lw = LATE_WIN.min(MW)`, so the late window is now 56 too. The comment
     says "late 58, capped by the standard window".
   - Against `9440086` the escape margin above the < 2^37 constant falls from
     24 to 19 bits (standard op) and from 21 to 19 bits (late op).
   - The single-chunk test `merged_plan(MW − 4, budget)` also gets easier, so
     some ticks that took the split late op may now take the standard op.
4. **`LF_CELL_FOLD_MIN` 56 → 54.**
   - `proxy_fold` sets each payload cell's fold window to
     `max(fold_window(proxy), LF_CELL_FOLD_MIN)`, capped at `N − 8`.
   - Cells whose Skywalk-profile window is below 56 (the comment says it
     narrows to 49 late) now run at 54 or their profile value, whichever is
     larger. That is up to 2 fewer fold bits per cell.
5. **`LF_CMP_SHIFT` 2,3 → 1,1.**
   - Every payload cell runs inside `with_cmp_shift((dB, dF))`, which adds
     `dB` to `chunk_compare(round)` and `dF` to `flag_compare(round)` in
     `pingpong.rs`.
   - The chunk-boundary carry erases lose 1 bit and the overflow-flag erases
     lose 2 bits. The merged ops' flag and split compares are inside the
     same scope.
   - Each compare is an `hmr` followed, only on outcome 1, by a top-k phase
     compare, so a bit is worth about 0.5 executed Toffoli per site. The
     `cmp_shift` comment says each +1 "halves that compare's miss rate for
     about one Toffoli per cell".
6. **`src/point_add/mod.rs`**: `TAIL_NONCE` 1441041 → 281311494624979.

The author reports that the four sells add almost exactly: −4,546.5 T summed
singly, against −4,563.4 T measured together.

## Why it is still correct, and what it risks

- **The extra qubit and the reorder are exact.** They change only where
  ladders split, and kept carries are still erased by exact compares.
- **The W1 change is not a correctness truncation.** The choice is a fixed
  function of the window bits, recomputed exactly when its letter is erased.
  A different decision only changes the walk's path. Its risk goes through
  the width envelope (unchanged, 139 ticks): more walks may outgrow it or fail
  to park, which shows up as **classical** failures.
- **The merged and cell fold sells** narrow modular-fold carry windows. An
  escaped carry gives a wrong value: **classical**.
- **The compare sells** double or quadruple the top-k tie error of those
  erases, which leaves a wrong phase: **phase**.
- **The author's λ.** 16.48 ± 0.36 failing shots per 9,024 (128 fresh
  packets, unchanged evaluator) and 16.57 ± 0.25 (a second harness), both
  under the 19.5 limit and below `58229f8`'s reported 16.80. The paired
  pricing puts the four sells at +2.16 ± 0.15 over the 1244/77 base.
- The shipped nonce `281311494624979` draws a clean set: 9,024 of 9,024
  shots, with 0 classical, 0 phase and 0 ancilla failures.

## Classification rationale

The score change is a bundle:
- −767 T for +1 qubit (ancilla-lifetime / venting);
- about −2,180 T from fold windows (merged 61 → 56, cell floor 56 → 54:
  fold/carry truncation);
- about −2,370 T from compare widths (the cell chunk and flag compare shift,
  and the W1 magnitude-compare window: comparator/width truncation).

These are the author's paired figures. The compare levers are the largest
group, so the call is comparator/width truncation. Fold/carry truncation is
a close runner-up.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9440086 -- src/point_add`.
   - Do not start from the git parent `58229f8`. Against it the diff would
     also show `LF_MERGED_LATE_WIN` going 52 → 58. That only reverts
     `58229f8`'s own change, and is not a lever of this commit.
   - `git diff --ignore-cr-at-eol 9440086 308a6ea -- src/point_add` has
     about 30 changed lines in `leapfrog.rs`, `mod.rs` and the new
     `leapfrog_data/anch_w1_k18a4.txt`. The other listed files change only
     their mode or line endings.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   It creates the one-line anchor table.
3. **Check the tree.** `git diff --ignore-cr-at-eol 308a6ea -- src/point_add`
   should print only mode changes.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. The recipe is
   pinned in the source, and `build()` clears the environment. Expect:
   - 1244 qubits
   - 797,905 average Toffoli (rounded)
   - score 992,593,820
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `281311494624979` and an identical
op stream.

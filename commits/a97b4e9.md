## Summary

This commit changes one constant, the carry-tail window `W` of the
register-free controlled constant subtractor, from 49 to 36. The subtractor now
computes 13 fewer borrow bits per call, about 13 Toffoli each time, and it is
called about 600 times per point addition. The saving is 7,982 average
Toffoli at the same 2309 qubits. The window is still far wider than any borrow
run seen in simulation, so the arithmetic is effectively exact. The value 36
was picked because its op stream lands on a clean test island.

## What changed and why it saves Toffoli

- `src/point_add/kaliski_state.rs`, `kal_carrytail_w()`: the default of
  `KAL_CARRYTAIL_W` goes from 49 to 36. The comment is rewritten with the sweep
  result.
- **What `W` controls.** `csub_nbit_const_direct_fast` in `cuccaro.rs`
  subtracts `ctrl ? c : 0` with c = 2^256 − p = 2^32 + 977. It computes only
  `cut = kal_carrytail_count(n) = min(n − 1, K0 + W)` borrow bits, with
  `KAL_CARRYTAIL_K0 = 33`, one above c's top set bit. The forward sweep, the
  difference XORs and the measured reverse sweep all use the same `cut`, so the
  truncated adder is still self-consistent. It now computes 69 borrow
  bits (`cut = 33 + 36`) instead of 82.
- **Why it saves Toffoli.** Above bit 32 every constant bit is 0, so each borrow
  position is `!acc_i AND borrow_i`, one Toffoli. 13 fewer positions save 13
  Toffoli per call. The callers are the 399 pair1 `mod_halve` steps, the Solinas
  fold and the low-scratch modular adders (about 611 calls, from the author's
  MAJ-fold count in [`0be8d11`](0be8d11.md)), which matches the 7,982 saved.
- The carry-tail truncation is on for the SUB path only (`KAL_CARRYTAIL_TRUNC`
  defaults to `"sub"`). The comment in the base records that the ADD path leaks
  phase under truncation.

## Why it is still correct, and what it risks

Above bit 32 the borrow can only propagate, through a run of 0-bits of the
accumulator (`borrow_{i+1} = !acc_i AND borrow_i`). A 3M-trial Monte Carlo in the comments
found the longest run is 19 bits, which reaches bit 51. A 36-bit window covers
borrows up to bit 68, so there are about 17 bits of slack. A dropped borrow would give a wrong
difference and a classical mismatch, with probability far below 2^-30 per call.

The binding constraint is the island lottery. There is no nonce in this era:
each value of `W` changes the op stream and so draws a different 9,024-shot test
set. The comment records that on this base `W = 36` and `W = 49` are clean,
while 45, 42, 40, 38, 35 and every value from 34 down to 24 fail. Those failures
come from other approximate knobs (W-TRUNC, iteration counts) meeting a hard
input in the new draw, not from the carry-tail itself. This draw is clean:
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change shortens a carry/borrow chain, so fold/carry truncation fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0be8d11 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 0be8d11 a97b4e9 -- src/point_add` is
   26 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a97b4e9 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,818,561 average Toffoli (rounded)
   - score 6,508,057,349
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

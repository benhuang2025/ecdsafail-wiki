## Summary

After the inversion, the dialog-GCD point add works on the x register `tx`
with a fixed chain of modular operations against the classical point `Qx`.
Two stretches of that chain contain negations that cancel or merge. This
commit replaces them with two new primitives:
- `[+2Qx, neg, −Qx, neg]` becomes one `+3Qx`;
- `[neg, +Qx]` becomes one `tx := Qx − tx`.

Both are exact modular identities. They remove three 256-bit negation adders
and one modular reduction, which saves 1,534 average Toffoli. Qubits stay at
1170. The fusions do not touch any truncated arithmetic, so the set of hard
inputs is the base's; only the nonce had to be re-hunted.

## What changed and why it saves Toffoli

The point-add driver is `emit_dialog_gcd_raw_pa()` in
`src/point_add/rounds/dialog/mod.rs`. After `emit_dialog_gcd_raw_quotient`,
`tx` holds `dx = Px − Qx` and `ty` holds `λ`. In the base the chain on `tx` is:

1. `round84_emit_fused_square_xtail`:
   - `tx := dx − λ²` (the square);
   - `mod_add_double_qb(tx, Qx)`, so `tx := dx − λ² + 2Qx`;
   - `mod_neg_inplace_fast`, so `tx := λ² − dx − 2Qx = Rx`.
2. Phase `dialog_gcd_raw_pa_c_ox_minus_rx`: `mod_sub_qb(tx, Qx)` then
   `mod_neg_inplace_fast`, so `tx := Qx − Rx = c`.
3. The second product `emit_dialog_gcd_raw_ipmul` and the y output.
4. Phase `dialog_gcd_raw_pa_x_restore`: `mod_neg_inplace_fast` then
   `mod_add_qb(tx, Qx)`, so `tx := Qx − c = Rx`.

### FUSE_C_FORM (`DIALOG_FUSE_C_FORM = "1"`)

- `c = Qx − Rx = Qx − (λ² − dx − 2Qx) = (dx − λ²) + 3Qx`. The two negations in
  steps 1 and 2 cancel, and `+2Qx − Qx` under the second negation becomes a
  net `+3Qx`.
- `round84_emit_fused_square_xtail` now returns right after the square,
  leaving `tx = dx − λ²`.
- The driver calls the new `mod_add_triple_qb(tx, Qx)` in
  `src/point_add/arith/modular.rs`. It loads `Qx` into `a`, copies it into a
  fresh `d`, doubles `d` with `mod_double_inplace_fast`, does
  `mod_add_qq_vent(tx, d)` and `mod_add_qq_vent(tx, a)`, halves `d` back to
  `Qx`, clears `d` with CNOTs, and unloads `a`.
- Against the base, both versions have one double, one halve and two vented
  modular add/subs. The two `mod_neg_inplace_fast` calls disappear. Each is a
  bit flip plus a 256-bit `add_nbit_qq_fast` of the constant `p + 1`.

### FUSE_X_RESTORE (`DIALOG_FUSE_X_RESTORE = "1"`)

- `Rx = Qx − c`, so the restore is one "constant minus register" operation.
- New `mod_const_minus_reg_qb(tx, Qx)`:
  1. Complement `tx` (`~tx = 2^256 − 1 − tx`) and add `Qx` with carry-in 1 into
     `tx` extended by one bit (`cuccaro_add_low_to_ext_clean`). The result is
     `2^256 + Qx − tx`.
  2. Move the top bit into `flag`. `flag = 1` exactly when `Qx ≥ tx`.
  3. If `flag = 0` (underflow), subtract `c = 2^256 − p` with
     `venting::cisub_dirty_2clean_classical`, which is the same as adding `p`
     mod 2^256.
  4. Clear `flag` with a full-width `cmp_lt_into(Qx, new tx)` after an X. In
     the no-underflow case the new value is at most `Qx`. In the underflow case
     it is `p − (tx − Qx) > Qx`.
- Against the base, one negation adder and one of the two reductions
  disappear, at the price of one full compare to clear the flag.

### Other edits

- `src/point_add/rounds/dialog/config.rs`: `dialog_fuse_c_form_enabled()` and
  `dialog_fuse_x_restore_enabled()`, which read the two variables (`"1"` = on).
- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  - sets both flags to `"1"`. The comment next to them calls them OFF
    placeholders, but the shipped values are `"1"`;
  - `DIALOG_TAIL_NONCE` `"3480010331559"` → `"55432501896150"`. Two later
    fallback lines get the same value, and they have no effect because the
    first `set_default_env` wins.
- `build()`: a `DIALOG_FUSE_SELFTEST` hook runs the new
  `dialog_fuse_primitive_selftest()`. It simulates both primitives on 64
  random `(tx, Qx)` pairs and checks the result, a zero phase and clean
  ancillas.
- The submission note measures 1,434,070.266 → 1,432,535.509 average Toffoli
  (−1,534.5).

## Why it is still correct, and what it risks

- **Exact.** Both fusions are exact modular identities for `tx, Qx` in
  `[0, p)`, and the primitives use only exact adders, an exact full-width
  compare and the base's vented modular adds. No truncated comparator, fold
  window or carry cap is involved. The hard inputs, and so Lambda, are the
  same as the base's.
- **Footprint.** `mod_add_triple_qb` holds `a` and `d` (512 qubits) at once.
  This part of the circuit is below the 1170 peak, so the peak is unchanged.
- **Nonce.** The op stream changed, so the test inputs moved. Nonce
  `55432501896150` draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures over 9,024 shots. Any wrong value here would be a classical
  failure. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Several consecutive modular operations are merged into one equivalent
operation by algebra, which is gate/op fusion. Nothing is truncated or made
approximate.

## Summary

In the K=2 dialog GCD, every apply step multiplies the payload `y` by 2 or 4
(`dialog_gcd_fused_double_y`) and every reverse-apply step divides it by 2 or 4
(`dialog_gcd_fused_halve_y`). The optional second factor of 2 is a conditional
left or right shift, built as a cascade of 255 controlled swaps (Fredkin
gates) on neighbouring bits, controlled by the transcript bit `s2`.

The last swap of the left-shift cascade, and the first swap of the right-shift
cascade, act on `y[0]` and `y[1]`. At that point both wires are always 0,
whatever the input and whatever `s2` is, so the swap does nothing. This commit
skips it. Each Fredkin costs one Toffoli, so this saves one Toffoli per apply
double and one per reverse-apply halve, about 520 per shot. The measured saving
is 507. Qubits are unchanged, and the change is exact.

## What changed and why it saves Toffoli

1. **New switches in `src/point_add/rounds/dialog/compressed.rs`.** Seven
   small env readers are added:
   - `dialog_gcd_skip_zero_edge_cshift_enabled()` reads
     `DIALOG_GCD_SKIP_ZERO_EDGE_CSHIFT` and turns on everything below.
   - `..._tobit_cshift_enabled()`, `..._tobit_fwd_cshift_enabled()` and
     `..._tobit_rev_cshift_enabled()` cover the same skip in the GCD walk
     (`tobitvector`) itself. They are **not** switched on by this commit; the
     follow-up [`7822c37`](7822c37.md) does that.
   - `..._apply_cshift_enabled()` reads `DIALOG_GCD_SKIP_ZERO_EDGE_APPLY_CSHIFT`
     and turns on `..._apply_double_cshift_enabled()` and
     `..._apply_halve_cshift_enabled()`.
2. **`dialog_gcd_fused_double_y(b, y, p, s2)`.** This computes
   `y ← 2^(1+s2)·y mod p` with one shared fold.
   - First an unconditional left shift: `ovf1` takes `y[255]` and the swap
     chain moves every bit up by one. Afterwards `y[0] = 0`.
   - Then the conditional left shift: `cswap(s2, y[255], ovf2)`, then
     `cswap(s2, y[i], y[i+1])` for `i = 254` down to `0`.
   - When `s2 = 1`, the first cswap moves `y[255]` into `ovf2`, so `y[255]`
     becomes 0. Each later swap moves that 0 one place down. When the loop
     reaches `i = 0`, `y[1]` holds the travelling 0 and `y[0]` holds the 0 that
     the first shift put there. The swap exchanges 0 with 0.
   - When `s2 = 0`, a controlled swap does nothing anyway.
   - New code: `if dialog_gcd_skip_zero_edge_apply_double_cshift_enabled() && i == 0 { continue; }`.
3. **`dialog_gcd_fused_halve_y(b, y, p, s2)`.** This is the exact inverse,
   used by the reverse apply. After the fold has been subtracted, `y` holds
   the unfolded `2^(1+s2)·y`, so its low bit is 0, and when `s2 = 1` its two
   low bits are 0. The un-shift loop runs `cswap(s2, y[i], y[i+1])` for
   `i = 0..254`, so its first swap again exchanges two zeros. The same
   `i == 0` skip is added under `..._apply_halve_cshift_enabled()`.
4. **`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.**
   - Adds `set_default_env("DIALOG_GCD_SKIP_ZERO_EDGE_APPLY_CSHIFT", "1")`.
   - `DIALOG_TAIL_NONCE`: 213 → 700000459112.

**Why it saves Toffoli.** `cswap` (`arith/adder.rs`) is `CX; CCX; CX`, one
Toffoli, and it runs on every shot. The route runs 260 GCD steps. The point
addition uses the dialog GCD twice: the in-place multiply
(`emit_dialog_gcd_compressed_sidecar_ipmul`) runs the forward apply, which
calls the fused double once per step, and the division
(`emit_dialog_gcd_compressed_sidecar_quotient`) runs the reverse apply, which
calls the fused halve once per step. That is about
2 × 260 = 520 Toffoli removed. The measured average falls by 507, which also
includes the effect of drawing a different set of test shots with the new
nonce.

## Why it is still correct, and what it risks

The skipped gate is the identity on every input that reaches it, so the change
is exact. It does not depend on the width envelope or on any truncation: the
two zeros come from the shift structure itself (the bit shifted in by the first
shift, and the bit vacated by the second). The submission note describes it as
skipping a shift "whose controlling edge bit is zero"; that is not quite right,
because the control `s2` can be 1. What is always zero is the pair of swapped
wires.

Because the op stream changed, the Fiat–Shamir test set changed, and the tail
nonce was re-hunted. The shipped nonce `700000459112` draws a clean set: 9,024
of 9,024 shots, with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change deletes a gate that acts on known-zero wires and has no effect.
That is dead-gate removal. There is no runner-up: no width, compare or
iteration count changes.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 2a87f33 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 2a87f33 b8ce940 -- src/point_add` is 76 lines
   in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b8ce940 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or `ROUND84_*` environment variables set, because they
   override the route defaults. Expect:
   - 1285 qubits
   - 1,382,155 average Toffoli (rounded)
   - score 1,776,069,175
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=700000459112` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

Each dialog-GCD step decides `u > v` from only the top bits of the two
registers. The number of bits is set per step by a baked schedule plus a
margin, capped at 57 and at the active width. [`f42ce5c`](f42ce5c.md) had
widened the margin to 8 to find a clean island, and [`5a2d910`](5a2d910.md)
brought it back to 7. This commit takes it to 5. On the 59 early steps where
the margin term is the binding one, the comparator loses one or two bits:
113 bits in all. It runs four times per step at one Toffoli per bit, so the
saving is 4 × 113 = 452 Toffoli, exactly the measured change. Qubits are
unchanged. The reroll pair was re-searched.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN`: 7 → 5.**
   - `dialog_gcd_compare_bits_for_step(step, active_width)` returns
     `min(SCHEDULE[step] + MARGIN, active_width, DIALOG_GCD_COMPARE_BITS = 57)`.
   - Recomputing the table over this tree's 395 steps (width margin 26), the
     margin binds on 59 steps, all between steps 0 and 112, where the baked
     schedule is still well below the cap. The summed compare width falls
     from 19,544 to 19,431 bits. On later steps the 57 cap binds and nothing
     changes.
   - The comparator is the hosted branch-bit
     `ccx_cmp_lt_into_fast_borrowed_carries`, one Toffoli per bit. It runs in
     the forward and reverse transcript passes of both GCD passes:
     4 × 113 = 452 Toffoli.
   - See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
2. **Reroll pair: `DIALOG_REROLL` 6,458 → 1,844, `DIALOG_POST_SUB_REROLL`
   2,553 → 3,532.** These are the identity `X;X` counts that only re-draw the
   9,024 test inputs.

## Why it is still correct, and what it risks

The comparison is approximate. If `u` and `v` agree on all of the compared
top bits, it can return the wrong `u > v`, and the step takes the wrong GCD
branch. That shows up as a classical failure, or as phase or ancilla garbage.
Two bits less on the affected steps makes a miss there about 4× more likely.
The schedule was fitted to the test inputs of an older op stream, so the
margin is the only guard against inputs that need more bits.

The reroll pair (1,844, 3,532) draws a clean set: 9,024 of 9,024 shots pass
with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows an approximate comparator, so
comparator/width truncation fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5d2f6cf -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 5d2f6cf b343178 -- src/point_add` is
   10 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b343178 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1434 qubits
   - 1,729,113 average Toffoli (rounded)
   - score 2,479,548,042
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=1844`,
`DIALOG_POST_SUB_REROLL=3532` and an identical op stream. Any other change
needs a new reroll search.

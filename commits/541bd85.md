## Summary

This is the first tightening of the dialog-GCD route from
[`cddd5df`](cddd5df.md). Each GCD step decides whether to swap `u` and `v` by
comparing only the top `DIALOG_GCD_COMPARE_BITS` bits of the live slices.
This commit lowers that window from 75 to 74 bits, which saves 4,960 average
Toffoli at the same 1698 qubits.

The new op stream drew a failing test set. So the commit also adds the
route's first reroll knob, `DIALOG_GCD_REROLL`: a number of identity
`X(tx[0]); X(tx[0])` pairs appended after the point addition. It sets the
knob to 2.

## What changed and why it saves Toffoli

- **`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `DIALOG_GCD_COMPARE_BITS` 75 → 74.**
  - It is used in `dialog_gcd_compare_bits_for_step()`, as
    `min(DIALOG_GCD_COMPARE_BITS, w(s))`, where `w(s)` is the step's active
    width. The comparison is `cmp_lt_into` on `v[w−k..w]` against
    `u[w−k..w]`, which costs 2 Toffoli per bit (a MAJ sweep and its inverse).
  - Each step computes and uncomputes the compare, so it costs `4·k` Toffoli.
    There are four GCD passes per shot: forward and backward for the divide,
    and forward and backward for the multiply.
  - One bit fewer saves 16 Toffoli on every step whose width is at least 75.
    With the margin-37 width schedule that holds for 310 of the 399 steps, and
    16 × 310 = 4,960. That is exactly the measured saving.
- **`build_builder()`: new reroll block.** After the route returns, if
  `route_dialog_gcd_raw_pa` is set and `DIALOG_GCD_REROLL` parses, the builder
  appends `rr` pairs of `X(tx[0]); X(tx[0])`. These change the op-stream hash
  that seeds the 9,024 test inputs, but add no Toffoli and no qubits.
  `configure_ecdsafail_submission_route()` sets the default to `"2"`. The
  route test was also hoisted into a `route_dialog_gcd_raw_pa` variable,
  which does not change behaviour.

## Why it is still correct, and what it risks

- The compare is a truncation. If the two slices agree on their top 74 bits,
  the step may make the wrong swap decision, `v −= u` goes negative, and the
  GCD does not finish at `(1, 0)`.
- The live width carries a 37-bit margin above the expected bit length. So
  the window really covers about 37 significant bits, and one fewer bit
  roughly doubles that per-step risk from a small base.
- A failure would show as a classical mismatch with phase and ancilla garbage,
  because the terminal-reuse step resets a nonzero `u`.
- With `rr = 2` the full benchmark gives 0 classical, 0 phase and 0 ancilla
  failures over 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A comparator window is narrowed by one bit, so this is comparator/width
truncation. The reroll block is the nonce-equivalent that this circuit change
needed.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout cddd5df -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol cddd5df 541bd85 -- src/point_add` is 21 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 541bd85 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_GCD_*` or `ROUND*` environment variables set, because the route
   only fills in variables that are unset. Expect:
   - 1698 qubits
   - 2,442,886 average Toffoli (rounded)
   - score 4,148,020,428
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_GCD_REROLL = 2` and an identical op
stream. Any other change needs a new reroll search.

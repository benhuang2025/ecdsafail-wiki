## Summary

The trailmix square computes `out −= λ² mod p` by Karatsuba. Its last piece is
`B·2^256 ≡ f·B`, with `B = hi²` a full 256-bit product and
`f = 2^32 + 2^10 − 2^6 + 2^4 + 1`. The earlier square lanes already avoided the
"doubling ramp" for their 128-bit limbs ([`e25c7d8`](e25c7d8.md) and its
successors). `B` is 256 bits wide, so it failed their `value.len() + 32 ≤ 256`
test and still took the old route:
- double a 257-bit copy of `B` modulo p up to 32 times;
- add or subtract it at each NAF shift;
- halve it 32 times.

That is 64 `+f` fold windows.

This commit adds a path for a full-width value. Each NAF term
`±(B·2^s mod p)` is applied straight from the `B` register: a modular add or
subtract of its low `256 − s` bits at bit offset `s`, then one gated `+f`
window for each of the `s` top bits that wrap past bit 255. That uses
0 + 4 + 6 + 10 + 32 = 52 windows instead of 64, and no shuffling of a copy. The
measured saving is 592 average Toffoli. Qubits are unchanged. The tail nonce
was re-hunted.

## What changed and why it saves Toffoli

**`src/point_add/trailmix_ludicrous/square.rs`, `apply_f_times_value_tagged`.**
A new branch sits just before the fallback doubling ramp. It is taken when
`value.len() == N` (256). Only the `f·B` call in
`mod_square_sub_pm_secp256k1_symmetric` (phase `square_b_hi_apply_f_times_sub`)
reaches it, because the `×2^128` limbs of the `A`, `B` and `C` lanes (128 or
130 bits) take the earlier shifted-low branch.

- For each `(shift, op)` in `F_NAF_TERMS = [(0,Sub),(4,Sub),(6,Add),(10,Sub),(32,Sub)]`
  (sign flipped for an outer `Add`), it calls the existing
  `apply_shifted_hi_term(value, out, shift, op)`:
  1. `mod_add_shifted_low` / `mod_sub_shifted_low(value[..256−shift], out, shift)`
     adds or subtracts `value_low · 2^shift` with modular reduction. For
     shift 0 this is a plain `mod_sub`.
  2. For `t in 0..shift`, the bit `value[256 − shift + t]` would land at bit
     `256 + t ≡ 2^t·f (mod p)`. `add_f_window_shifted` (or its X-sandwiched
     `sub_` twin) adds `f` into `out[t..t + LSBS]`, controlled on that bit.
     `LSBS = 52` on this tree (`arith::PAD = 19`).
- **Base path, for comparison.** It copied `value` into a 257-bit `ext`. Each
  `arith::mod_double` is a free swap-chain shift plus one `add_f_window` on the
  shifted-out bit, over `LSBS` bits. The ramp ran 32 of them to reach shift 32,
  did 5 full-width adds, then ran 32 `mod_double_reverse`. So it used 64
  windows of about 51 Toffoli each.
- **Saving.** 64 − 52 = 12 fewer fold windows, about 12 × 51 ≈ 610 Toffoli.
  The shifted adds are also slightly narrower (`256 − shift` bits). The
  measured average drops by 592. See [modular-fold](../concepts/modular-fold.md)
  and [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).

**`src/point_add/mod.rs`, `build()`**: `DIALOG_TAIL_NONCE` 200017925264 →
720008097505.

## Why it is still correct, and what it risks

- **Same value mod p.** `B·2^s = B_low·2^s + Σ_t b_{256−s+t}·2^{256+t}`, and
  `2^{256+t} ≡ 2^t·f`. Each term adds the same residue that the ramp's
  `ext = B·2^s mod p` would have added.
- **Same kind of approximation as before.** Each per-bit `+f` window adds `f`
  into a 52-bit window of `out` and drops the carry out of the window's top
  bit, as every `+f` window in this tree does. Here the window sits on
  arbitrary data, so a dropped carry is possible with probability about
  2^-19 per window. The base ramp's 64 windows had the same per-window
  exposure. The new route has 12 fewer windows, so it adds no new
  approximation. The author calls it value-exact, which is true up to these
  window carries.
- A dropped carry would show up as a classical failure (a wrong `x3`), or as a
  phase failure through the later measured erasures. The shipped nonce
  `720008097505` draws a clean set: 9,024 of 9,024 shots, with 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as host-derived / classical specialization. That looks
wrong: nothing here is classical or precomputed on the host. The change applies
the Solinas fold by `f`, written in NAF, through a cheaper route: shifted reads
plus per-bit `+f` windows instead of a modular-doubling ramp. That is the same
lever as [`e25c7d8`](e25c7d8.md), filed as Strength Reduction → solinas / NAF
fold, and this commit should carry that label.

## Summary

Every step of the dialog-GCD walk (background in [8316db1](8316db1.md); see
[dialog-gcd-early](../concepts/dialog-gcd-early.md)) decides its branch with a truncated comparison
`u > v` on the top few bits of the active window. The number of bits is a
baked per-step schedule, capped by a global limit `DIALOG_GCD_COMPARE_BITS`.
This commit lowers the cap from 50 to 49. Only the 27 steps whose schedule entry
is 50 or more are affected, and each loses one comparator bit, which is one
Toffoli. Four walks run the comparator, so the saving is 4 × 27 = 108 Toffoli,
exactly the measured drop. Qubits are unchanged, and the tail nonce was
re-hunted.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_COMPARE_BITS`: 50 → 49.**
   - Read by `dialog_gcd_compare_bits()` in `rounds/dialog/config.rs`. On this
     route `DIALOG_GCD_PA9024_COMPARE_SCHEDULE=1` with margin 0, so
     `dialog_gcd_compare_bits_for_step(step, active_width)` returns
     `min(SCHEDULE[step], DIALOG_GCD_COMPARE_BITS, active_width)`.
   - `DIALOG_GCD_PA9024_COMPARE_SCHEDULE` is a baked 258-entry table: the
     observed worst-case comparator width needed per step over 8 million
     sampled GCD inputs. Its values run from 5 to 55.
   - With `active_width(step) = ceil((256 − 1.014·step + 10) / 2)·2`, exactly
     27 steps have `min(SCHEDULE[step], active_width) ≥ 50`: steps 135, 140,
     162, 182, 183, 185, 190–199, 201–203, 205 and 207–213. On those steps the
     comparator goes from 50 to 49 bits. All other steps are unchanged.
   - The comparator is `dialog_gcd_ccx_cmp_gt_truncated_into_width`, the
     fused form (`DIALOG_GCD_FUSED_BRANCH_BITS=1`) that writes
     `b0 AND (u > v)` straight into the log bit. It compares only the top `k`
     bits of the active window, at about one Toffoli per bit, with its carries
     erased by measurement.
   - The forward and the reverse walk of both dialog-GCD divisions run it once
     per step: 27 × 4 = 108 Toffoli.
   - `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` is set to 23 explicitly, so the
     apply-phase comparator does not inherit the new cap.
2. **`DIALOG_TAIL_NONCE`: 460000820 → 213394**, the fixed 48-pair `X;X`
   identity tail that reseeds the 9,024 test inputs.
3. The file modes of `mod.rs` and `venting.rs` change from 100755 to 100644.
   This has no effect on the build.

## Why it is still correct, and what it risks

The truncated comparator is approximate. When `u` and `v` agree on all `k`
compared bits, it can report the wrong order. The walk then skips a swap it
needed (or takes one it did not need), the subtraction goes the wrong way, and
the input does not reach its terminal state. The schedule entries above 49 were
measured maxima, so on those 27 steps a few sampled inputs really needed 50
bits or more. Capping them at 49 makes those rare inputs fail.

A wrong branch shows up as a classical mismatch (wrong output point) and
usually as ancilla garbage, because the reverse walk no longer restores `u`
and `v`. The shipped nonce `213394` draws a test set with 0 classical,
0 phase and 0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a comparator, so comparator/width truncation
fits. The nonce change comes with every circuit change and is not a separate
lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 004ffc0 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 004ffc0 8e13587 -- src/point_add` is
   6 lines in 1 file, plus a mode change on 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8e13587 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1309 qubits
   - 1,504,903 average Toffoli (rounded)
   - score 1,969,918,027
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=213394` and an identical op
stream. Any other change needs a new nonce hunt.

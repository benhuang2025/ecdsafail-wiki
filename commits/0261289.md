## Summary

In the dialog-GCD walk, u starts as p, which is odd, and it stays odd at
every step. So bit 0 of u is always 1, and two kinds of gates on it do
nothing useful:

- **The cswap on lane 0.** When the swap fires, both u and v are odd, so
  swapping bit 0 changes nothing.
- **The gated load of `ctrl AND u[0]`.** This value is just `ctrl`.

This commit skips the lane-0 cswap and turns the lane-0 load from a CCX into
a CX. That saves 1 Toffoli at each of 8 sites per step, 8 × 396 = 3,168
Toffoli on M3kko's 396-step route. The result is the same on every input.
Qubits stay at 1693. The reroll goes from 0 to 2.

## What changed and why it saves Toffoli

All code edits are in `src/point_add/mod.rs`. The route is described in
[`4b9cfbb`](4b9cfbb.md).

**The invariant.** One walk step does this:

```
b0 = v[0]                         # v odd?
b0_and_b1 = b0 AND (u > v)        # swap only if v is odd
cswap(b0_and_b1, u, v)
if b0: v -= u                     # dialog_gcd_controlled_sub_selected(u, v, b0)
v >>= 1                           # dialog_gcd_shift_right_assuming_even
```

u starts as p (odd). A swap only happens when v is odd, so the new u is also
odd. Without a swap, u does not change. So u[0] = 1 before and after every
step. This holds even when the truncated comparator misjudges `u > v`,
because the swap is still gated by `b0`. When a swap fires, u[0] = v[0] = 1,
so swapping lane 0 does nothing. The reverse walk visits the same states in
the opposite order, so the same holds there.

**The edits**, gated by the new `dialog_gcd_odd_u_lowbit_fastpath_enabled()`
(`DIALOG_GCD_ODD_U_LOWBIT_FASTPATH`):

1. In the `materialized_sub_load` phase of `dialog_gcd_controlled_sub_selected`,
   and in the `materialized_add_load` phase of `dialog_gcd_controlled_add_selected`,
   lane 0 changes from `ccx(ctrl, subtrahend[0], gated[0])` to
   `cx(ctrl, gated[0])`. Every caller passes `u_active` as the subtrahend or
   addend, so `subtrahend[0]` = u[0] = 1. The clear phase still uses
   `hmr(gated[0])` + `cz_if(ctrl, u[0], m)`. That gate is unchanged and is
   still the correct phase fix-up, because `gated[0]` = `ctrl`.
2. In the six walk loops (raw, compressed-sidecar and block-lifecycle, each
   forward and reverse), the `cswap(b0_and_b1, u[i], v[i])` loop skips
   `i = 0`. Each cswap is `cx; ccx; cx`, so skipping one saves 1 CCX.
3. `configure_ecdsafail_submission_route()` sets
   `DIALOG_GCD_ODD_U_LOWBIT_FASTPATH=1`. `DIALOG_REROLL` goes from 0 to 2.
4. A new memory note, `src/point_add/memory/2026-06-02-3b5d02e-odd-lowbit-reroll2.md`,
   records the run. It also records that rerolls 0 and 1 failed.

**Count.** Per step and per GCD pair, the change saves:

- 1 in the forward-walk load;
- 1 in the reverse-walk load;
- 1 in the forward cswap;
- 1 in the reverse cswap.

That is 4 per pair, so 8 per step with two pairs, and 8 × 396 = 3,168. This
is exactly the measured drop.

## Why it is still correct, and what it risks

- **Exact.** Both rewrites rely only on u being odd. That holds on every input
  and every path, so the commit adds no new approximation.
- **Unchanged risks.** The base's approximations are all still there. That
  includes the 396-step cut from [`dd103cd`](dd103cd.md), which is wrong on
  rare slow-converging inputs. The memory note says so: "It does not repair
  that route's documented approximation".
- **Seed.** The op stream changed, so the island moved. Reroll 2 draws a clean
  set: 0 classical, 0 phase and 0 ancilla failures over 9,024 shots.

## Classification rationale

The saving comes from a fact known before the circuit runs: the low bit of u
is always 1. The commit uses that fact to delete or weaken gates. That is
classical specialization. The runner-up was an exact dead-gate removal, since
the lane-0 cswap is a provable identity. The same lever was ported to the
399-step line as [`9805d0c`](9805d0c.md).

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout dd103cd -- src/point_add`.
   - Do not start from the git parent `0aa33ed`. This commit was built on
     M3kko's `dd103cd`.
   - Against the parent, the diff is 337 lines. It would also revert
     Gajesh2007's carry-window work from [`ad02935`](ad02935.md) and
     [`0aa33ed`](0aa33ed.md).
   - Against `dd103cd`, `git diff --ignore-cr-at-eol dd103cd 0261289 -- src/point_add`
     is 98 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 0261289 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1693 qubits
   - 1,694,009 average Toffoli (rounded)
   - score 2,867,957,237
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 2 and an identical op stream.
Any other change needs a new reroll search.

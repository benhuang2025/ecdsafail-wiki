## Summary

Two lines of work met here. 0xLucqs's [`e25c7d8`](e25c7d8.md) had the cheaper
square at 1164 qubits, and jieyilong's [`31421df`](31421df.md) had shown that
trimming the baked scratch-wire budgets reaches 1162 qubits. gnuchev's
[`aacf05c`](aacf05c.md) combined the two on the 1162 tree. This commit combines
them from the other side: it starts from `e25c7d8` and adds the budget trims
and fold-pad cuts, using BitWonka's own earlier knob code from the 1163-qubit
`b310de9` with stronger settings.

The trims lower the peak by 2 qubits. They cost Toffoli, because fewer carries
can be measured out, and the narrower fold pads win some of it back. The
commit also sets `CONSTPROP_MAX_ITERS` back from 256 to 16, which undoes the
extra CCX→CX conversions of [`d2643bc`](d2643bc.md). Net: −2 qubits for +752
Toffoli, a score 70,882 below `aacf05c`.

## What changed and why it saves qubits

The budget mechanism is described in [`31421df`](31421df.md): each adder and
`+f` fold reads its clean-scratch budget from a baked schedule
(`schedule.rs`) through `next_*()` cursors in `trailmix_ludicrous/mod.rs`. See
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md) and
[venting-and-wire-loans](../concepts/venting-and-wire-loans.md).

**Code (`trailmix_ludicrous/mod.rs`, `gcd.rs`).**

- New `env_delta(name)` and `sub_delta(v, name)`. `next_cout_k`, `next_ffg` and
  `next_hyb_v` return the schedule value minus `TLM_COUT_K_DELTA`,
  `TLM_FFG_DELTA` or `TLM_HYB_V_DELTA`, leaving the "no constraint" sentinel
  alone. `next_fold` subtracts `TLM_FOLD_DELTA` from non-negative codes (the
  clean-vent count of the fused double fold).
- `gcd.rs`: `controlled_add_active` gets the GCD step index `i`, and its carry
  budget becomes `maybe_adjust_late_gcd_k(i, next_gcd_k())`, which adds
  `TLM_GCD_K_ADJUST` when `AFTER ≤ i < BEFORE`.
- This is the same code as in BitWonka's `b310de9`. It is simpler than
  `31421df`'s version (no `_EXTRA` adjust and no per-index range knobs for the
  other schedules).

**Defaults (`src/point_add/mod.rs`, `build()`).**

| Knob | Base | New | Effect |
| --- | --- | --- | --- |
| `TLM_HYB_V_DELTA` | unset | 2 | every hybrid add vents 2 fewer carries |
| `TLM_COUT_K_DELTA` | unset | 2 | apply cofactor adds get a 2-wire smaller carry budget |
| `TLM_FOLD_DELTA` | unset | 2 | fused double folds vent 2 fewer carries |
| `TLM_FFG_DELTA` | unset | 0 | no change to the apply fold windows' own count |
| `LUD_EXTRA_FOLD_VENTS` / `_MIN_G` / `_MAX_G` | 2 / 16 / unset | 0 / 0 / 999 | drops the +2 extra clean carries on every apply fold window with `FFG_G ≥ 16` |
| `TLM_GCD_K_ADJUST` over `[169, 196)` | unset | −2 | GCD subtracts at steps 169–195 get a 2-wire smaller budget |
| `CONSTPROP_MAX_ITERS` | 256 | 16 | constprop stops after 16 sweeps again |
| `DIALOG_TAIL_NONCE` | 2207 | 100002962138 | new clean draw |

Compared with `31421df`: the same vent and cout trims; no `−1` on the fold
windows (`FFG_DELTA` 0 instead of 1); and the GCD trim covers three more steps
(169–171).

**Narrower folds (`arith.rs`, `schedule.rs`)**, as in `31421df`:

- `arith::PAD` 21 → 19. That makes `LSBS` 54 → 52 (the `// 54` comment is
  stale) and `MSBS` 21 → 19. Every `+f` window is 2 bits and about 2 CCX
  shorter, and every top-`MSBS` measured overflow compare is 2 bits shorter.
  See [modular-fold](../concepts/modular-fold.md) and
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- `schedule::PAD` 21 → 20. This is the `cap` of the GCD subtract's truncated
  chunk-carry erase (`gidney::controlled_hybrid_add_capped_branch`).

**Constprop cap.** `CONSTPROP_MAX_ITERS` is read in
`trailmix_ludicrous/constprop.rs::run()` (default 16). `d2643bc` had raised it
to 256 so that the pass reached its fixed point. Going back to 16 can only
leave more CCX unconverted. On `d2643bc`'s tree the extra sweeps were worth
324 Toffoli. The nonce comment says the island was hunted on
`e25c7d8 + CONSTPROP_MAX_ITERS=16`, so the cap seems to have been kept to
match the hunting pipeline. This commit's own gain does not come from it (see
[dead-gate-strip](../concepts/dead-gate-strip.md)).

**Dead-route nonces.** Three `DIALOG_TAIL_NONCE` defaults in
`configure_ecdsafail_submission_route()` (the old dialog route, unused by
`build()`) are deleted.

The +752 Toffoli is the sum of the trims (up), the PAD cuts (down) and the
constprop cap (up). The commit does not report the parts separately.

## Why it is still correct, and what it risks

- **Budget trims: value-exact decompositions.** A smaller budget only picks a
  different exact way to compute the same addition: more chunks, borrowed
  dirty bits, or recomputed instead of measured carries. Extra chunks in the
  GCD subtract each add one truncated `cap`-bit carry erase, which is
  probabilistic.
- **PAD cuts: probabilistic.** A 52-bit `+f` window drops a carry with
  probability about `2^-19` per firing, four times the base's rate. The 19-bit
  overflow compares and the 20-bit GCD chunk erases misjudge more often too.
  Lambda rises.
- **Constprop cap: exact.** Fewer proven rewrites leave the unitary the same.
- **Which channel catches it.** A dropped fold carry is a classical failure.
  A wrong truncated compare or erase is a phase failure.
- The shipped nonce 100002962138 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures (10,204,150 emitted ops),
  per the author's env-less run.

## Classification rationale

The published label is constant propagation / classical specialization,
presumably because of the `CONSTPROP_MAX_ITERS` line. But that line *raises*
Toffoli. The score gain comes from the 2-qubit drop, and that comes from the
schedule-budget trims, with the PAD cuts as the Toffoli-recovering part. The
diff suggests Register and Scratch Allocation (peak-budget trim, ancilla
lifetime / venting), with fold/carry truncation as the runner-up. It is the
same lever as `31421df`, ported to another base.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout e25c7d8 -- src/point_add`.
   - Do not start from the git parent `aacf05c`. That is gnuchev's port of the
     same idea onto `31421df`.
   - Against the parent, the diff is 398 lines in 4 files. It would replace
     jieyilong's range-adjust knob code with this simpler version, and swap
     `aacf05c`'s `TLM_SQUARE_A_DIRECT_SHIFT32` square path for `e25c7d8`'s
     tagged `TLM_SQUARE_F_*` paths.
   - Against `e25c7d8`, `git diff --ignore-cr-at-eol e25c7d8 7b7bd12 -- src/point_add`
     is 88 lines in 5 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7b7bd12 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1162 qubits
   - 1,389,038 average Toffoli (rounded)
   - score 1,614,062,156
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `100002962138` and an identical op
stream. Any other change needs a new nonce hunt.

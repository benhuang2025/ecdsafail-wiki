## Summary

The ping-pong divider runs its value walk for a fixed number of rounds and
writes one sign qubit per round onto a tape. During the coefficient replay
the whole tape is live, and that is where the qubit peak sits. So the round
count sets both the peak and, almost linearly, the gate count.

This commit lowers the round count from 704 to 703. The tape is one qubit
shorter, so the peak drops from 1320 to 1319 qubits. Each of the two
traversals (divide and multiply) also loses one walk round, one replay cell
and one walk-back round, which saves 719 average Toffoli. The cost is that
inputs whose walk needs all 704 rounds to converge now fail.

## What changed and why it saves qubits

1. **`ROUNDS_DEFAULT`: 704 → 703** in `src/point_add/pingpong_div.rs`.
   - It is the default of `rounds()`, which `SUB4_PP_ROUNDS` can override.
   - `rounds()` is the loop bound of `value_walk` (`for round in 0..rounds()`,
     one tape bit pushed per round) and of `value_walk_back`. The replays
     iterate over the tape, so they follow automatically. Both directions
     use the same depth at this point.
   - **Qubits.** The tape is 703 wires instead of 704. It is fully live
     during the replay, which binds the peak, so the peak drops by exactly 1.
     See [pingpong-division](../concepts/pingpong-division.md) ("The peak and
     why ladders matter") and
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - **Toffoli.** Per traversal, the commit removes:
     - the last walk round's signed add, which is narrow because
       `value_width` is near its floor by then;
     - the matching walk-back round;
     - one full 256-bit replay cell: the chunked add, the fold, and the
       chunk and flag repairs.
     With two traversals that is −719 T, in line with the roughly 365 T per
     round per traversal that the concept page quotes for later cuts.
   - The width schedule `value_width(round)` is unchanged. It is indexed by
     round, and `SUB4_PP_WIDTH_RESCALE` is not set, so the 703 rounds use the
     first 703 entries and the last entry is simply not reached. The
     self-test assert `value_width(rounds() − 1) >= 8` still holds.
2. **Tail nonce** (`src/point_add/mod.rs`): the default
   `SUB4_PINGPONG_TAIL_NONCE` goes from 30008 to 40355.

## Why it is still correct, and what it risks

- **Depth is a truncation.** The walk is correct only for inputs that reach
  the fixed point `(±1, ±1)` within the available rounds. An input that
  needed round 704 now finishes unconverged. Its quotient is wrong and the
  walk-back does not clear the registers, so the shot shows classical and
  ancilla failures.
- The concept page gives the per-walk failure near 700 rounds as about
  2.5–4×10⁻⁴. Each round cut raises it, and each shot runs two walks. So this
  adds hard inputs and raises λ.
- The arithmetic itself is unchanged.
- The shipped nonce `40355` draws a clean test set: 0 classical, 0 phase and
  0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change cuts a fixed iteration count against a measured convergence
failure rate, which is iteration/threshold tuning. Here it lowers the peak as
well, because the tape length is the round count.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8e8f047 -- src/point_add`.
   - `git diff --ignore-cr-at-eol 8e8f047 850db0c -- src/point_add` is 4
     changed lines in 2 files.
   - Do not start from the git parent `eb187a4`, the author's previous
     submission. Against it the diff is 6 lines and also *widens*
     `SUB4_PP_REPLAY_FLAG_COMPARE` from 24 to 25. That only reverts
     `e5c53dc`'s narrowing, which `eb187a4` carries and this commit's line
     never had. It is not part of this change.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 850db0c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set (in particular no `SUB4_PP_ROUNDS`). Expect:
   - 1319 qubits
   - 942,858 average Toffoli (rounded)
   - score 1,243,629,702
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `40355` and an identical op stream.
Any other change needs a new nonce hunt.

## Summary

[`bc9728a`](bc9728a.md) made the Karatsuba Solinas fold add the constant
`c = 2^32 + 977` with the controlled direct adder `cadd_nbit_const_direct_fast`,
driven by a fresh qubit set to `|1⟩`. That adder does not know its control is
1, so at each 1-bit of `c` it pays three Toffoli for the carry majority.

This commit adds an unconditional version, `add_nbit_const_direct_fast`, in
which the control is folded in as the constant 1. The majority then collapses
to an OR, which needs one Toffoli. Each call saves 13 Toffoli. There are 8
calls per point addition, so the total is −104. Qubits are unchanged.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`.

- **New `add_nbit_const_direct_fast(acc, c)`.** The same carry sweep as
  `cadd_nbit_const_direct_fast`, with `k_i = c_i` instead of `k_i = ctrl·c_i`:
  - where `c_i = 0`: `carry_{i+1} = acc_i AND carry_i`, one CCX (unchanged);
  - where `c_i = 1` and there is a carry-in: `carry_{i+1} = majority(acc_i, 1, carry_i) = acc_i OR carry_i`,
    computed as `cx(acc_i) ; ccx(acc_i, carry_i) ; cx(carry_i)`, using
    `a OR b = a ⊕ b ⊕ ab`. That is one CCX instead of three;
  - at position 0 (`c_0 = 1`, no carry-in): `carry_1 = acc_0`, a CX instead of
    one CCX;
  - sum bits: `x(acc_i)` where `c_i = 1` instead of `cx(ctrl, acc_i)`.
  - The carries are still erased by `hmr` with Clifford `cz_if` fixes. The
    fixes still name a control wire, so the function allocates a `|1⟩` helper
    qubit, `one`, for the CZs only. It costs no Toffoli.
- **Callers.** Step 2 (the unconditional `+c`) of
  `mod_add_qq_fast_lowscratch` and `mod_add_qq_fast_from_zero_lowscratch` now
  calls the new function instead of building `one` and calling the controlled
  adder. Step 3, the `−c` under the real `flag`, is unchanged.

**Count.** `c` has 1-bits at positions 0, 4, 6, 7, 8, 9 and 32. Positions 4,
6, 7, 8, 9 and 32 save two CCX each, and position 0 saves one, so 13 per call.
The two low-scratch adds are used at the eight Solinas-fold adds of the two
Karatsuba multipliers, each run once per point addition: 8 × 13 = 104. The
simulator charges every executed CCX, even one whose control is always 1, so
this specialisation is a real saving. See
[adders-and-carries](../concepts/adders-and-carries.md).

## Why it is still correct, and what it risks

The change is exact on every input. With the control equal to 1, the new
gates compute the same carries and sums as the controlled adder. The carry
erase uses the same identity, `carry_{i+1} = majority(NOT s_i, c_i, carry_i)`
after the sum is written, with the constant control represented by the
`one` wire. A wrong fix would show up as a phase failure. See
[measurement-uncompute](../concepts/measurement-uncompute.md).

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed. The base's probabilistic Kaliski
settings passed on the new draw with 0 classical, 0 phase and 0 ancilla
failures.

## Classification rationale

The saving comes from substituting a value known at build time, the control
bit 1, into the gate sequence and simplifying it. That is host-derived /
classical specialization.

op stream, so the score only reproduces with an identical op stream.

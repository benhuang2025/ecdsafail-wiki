## Summary

The dialog-GCD walk does its swap, subtract and compare only on the low
`active_width(step)` bits of `u` and `v`. That width follows a straight-line
envelope of how fast the GCD values shrink, plus a safety margin. This commit
lowers the margin from 28 to 27 bits. Because the width is rounded up to an
even number, 179 of the 399 steps get 2 bits narrower and the rest are
unchanged. Each step-bit costs 3 Toffoli per walk (swap, gated load and
subtract) and the comparator also loses a few capped bits, so each of the four
walks saves 1,159 Toffoli, 4,636 in total. Qubits are unchanged. The
Fiat–Shamir reroll was rescanned to 2.

## What changed and why it saves Toffoli

Background on the walk is in [8316db1](8316db1.md) (see
[dialog-gcd-early](../concepts/dialog-gcd-early.md)).

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `DIALOG_GCD_WIDTH_MARGIN` default 28 → 27 (and its comment).
- It is read by `dialog_gcd_width_margin()` inside
  `dialog_gcd_tobitvector_active_width(step)`:
  `ideal = 256 − 0.7075·step + margin`, rounded **up** to an even number and
  clamped to [1, 256]. 0.7075 bits per step is the measured average shrink rate
  of `max(bitlen u, bitlen v)`.
- `active_width` is the width of three per-step operations in the forward and
  reverse walks:
  - the `cswap(b0_and_b1, u_i, v_i)` loop, 1 Toffoli per bit;
  - the gated load `ccx(ctrl, subtrahend[i], gated[i])` in
    `dialog_gcd_controlled_sub_selected` / `_add_selected`, 1 Toffoli per bit;
  - the subtract or add body, `sub_nbit_qq_fast_borrowed_carries`, about 1
    Toffoli per bit (carries erased by measurement, gated register cleared by
    `hmr` + `cz_if` at no Toffoli).
  It also caps the comparator width in `dialog_gcd_compare_bits_for_step`.
- Per walk, the summed width goes from 56,930 to 56,572 bits (−358, i.e. 179
  steps × 2), and the summed comparator width from 20,964 to 20,879 (−85).
  3 × 358 + 85 = 1,159 Toffoli per walk, and × 4 walks = 4,636, the measured
  drop. The first 43 steps are clamped at 256 and do not change.
- `DIALOG_REROLL` default 29 → 2: the number of identity `X;X` pairs emitted
  on `tx[0]` at the start of `build()`. It re-seeds the 9,024 test inputs and
  changes nothing else.

## Why it is still correct, and what it risks

The width envelope is a statistical fit, not a bound. Bits above
`active_width` are simply left out of the swap and the subtraction, on the
assumption that both `u` and `v` are already zero there. An input whose GCD
shrinks more slowly than the envelope still has live bits in the dropped band.
The swap then misses them, and the walk produces a wrong result. A smaller
margin puts more inputs past the line.

The author reports that margin 27 failed on the old reroll 29 with 3–5
classical mismatches and a few phase-garbage batches, and that rerolls 7, 13,
19, 31, 43, 53 and 59 each failed by 1–9 shots. Reroll 2 draws a clean set
(0 classical, 0 phase, 0 ancilla). So the margin is well past the point where
failures are rare, and the submission rests on a lucky draw. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A narrower per-step register width is comparator/width truncation. No gates
were removed as dead, so the family label (Dead-Code and Redundancy
Elimination) fits only in the census's broad sense of dropping unneeded work.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 1fd942d -- src/point_add`.
   - Do not start from the git parent `8316db1`, the author's own previous
     submission. This commit was built on `1fd942d` instead. Against the parent
     the diff also reverts `DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN` 5 → 6,
     which is that commit's change.
   - `git diff --ignore-cr-at-eol 1fd942d 412312f -- src/point_add` is 17
     lines in 1 file, most of them comments.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 412312f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set. Expect:
   - 1698 qubits
   - 1,662,965 average Toffoli (rounded)
   - score 2,823,714,570
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 2` and an identical op
stream. Any other change needs a new reroll scan.

## Summary

The author had two separate one-bit cuts on johnbxx's fold-fusion tree
[`8a47cf5`](8a47cf5.md): the apply-clean comparator 24 → 23
([`2f1f175`](2f1f175.md)) and the branch comparator 52 → 51
([`9906ec0`](9906ec0.md)). This commit applies the first one on top of the
second. The two are independent, so the saving is the same as in `2f1f175`:
518 average Toffoli, one per apply-clean erase. Qubits are unchanged, and the
tail nonce was re-hunted for the stacked op stream.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 24 → 23.**
   - This is the width `k` of the truncated compare that erases the overflow
     flag `acc_ovf` after each controlled modular add in the GCD apply
     (`dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`:
     `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)`), and the
     underflow flag after each controlled subtract in the reverse apply
     (`dialog_gcd_clean_truncated_underflow`).
   - The test is that an overflow happened exactly when the sum is below the
     addend, decided on the top `k` bits only. One bit is one Toffoli. There
     are 259 steps × 2 apply passes = 518 erases per shot, which is the
     measured −518.
   - The mechanism is described in more detail in [`2f1f175`](2f1f175.md).
2. **`DIALOG_TAIL_NONCE`: 43780000903 → 44250004920.**

## Why it is still correct, and what it risks

The erase fails when the result and the addend agree on all 23 compared top
bits, about 2^−23 per call. The flag is then left dirty, which shows up as
ancilla or phase garbage. The branch-comparator cut already in the base adds
its own small risk, so λ is a bit higher than for either cut alone. The new
nonce `44250004920` was found with a CPU prefilter, and the trusted
evaluation confirmed it clean: 9,024 of 9,024 shots, with 0 classical,
0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

One comparator is narrowed by one bit, which is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9906ec0 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 9906ec0 373fb4d -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 373fb4d -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*` or `DIALOG_*` environment variables set. Expect:
   - 1313 qubits
   - 1,517,146 average Toffoli (rounded)
   - score 1,992,012,698
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=44250004920` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

In each apply step, `y` is doubled modulo p (forward apply) or halved (reverse
apply), and with K2 it may be doubled or halved a second time. Each of these
shifts the register and then, if a bit fell off the top, adds back the small
constant `c = 2^32 + 977`. That add ripples a carry upward from bit 32, and
`KAL_DOUBLE_CARRY_TRUNC_W` stops the ripple `w` bits above bit 32. This commit
lowers `w` from 22 to 21. That saves one Toffoli in each of the
4 × 259 = 1,036 doubling and halving calls. The measured saving is 1,038. Qubits
stay at 1313. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`.

1. **`KAL_DOUBLE_CARRY_TRUNC_W`: 22 → 21.**
   - `double_carry_trunc_window()` is read by four helpers:
     - `mod_double_inplace_fast` and `mod_halve_inplace_fast`, the
       unconditional per-step double or halve of `y`,
     - `cmod_double_inplace_lazy` and `cmod_halve_inplace_lazy`, the K2
       second double or halve, controlled on `s2`.
   - Each one shifts `y` by one bit through an overflow wire `ovf`, then runs
     `cadd_nbit_const_direct_trunc_fast(v, c, ovf, w)` (or the `csub` mirror).
     That is the Solinas fold `2^256 ≡ c (mod p)`, controlled on `ovf`. See
     [modular-fold](../concepts/modular-fold.md).
   - The truncated constant add stops the carry ripple `w` positions above the
     constant's top set bit (bit 32). Each position costs one Toffoli, and the
     carries are erased by measurement.
   - The apply runs per step `mod_double_inplace_fast` plus
     `cmod_double_inplace_lazy` (forward apply), or `cmod_halve_inplace_lazy`
     plus `mod_halve_inplace_fast` (reverse apply). That is 4 calls × 259
     steps = 1,036 Toffoli for one bit of window. The other 2 of the measured
     1,038 come from some other use of these helpers that I did not trace.
2. **`DIALOG_TAIL_NONCE`: 689 → 1000001157.** This reseeds the 9,024 test
   inputs. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

The comment says it is "value-exact on the reachable support (... ~2^-22/call
otherwise)". Only the second half is right: it is a probabilistic truncation.
The truncated add is wrong when the carry out of bit 32 runs through more than
`w` consecutive ones of `y` above it, about 2^−(w+1) per call for a random
`y`, now twice as likely as at 22. When that happens the top bits of `y` are
wrong. That gives a classical failure, and garbage in the reverse halving,
which uses the same window. The carry wires themselves still return to |0⟩.

λ rises a little. The shipped nonce 1000001157 draws a clean set, with
0 classical, 0 phase and 0 ancilla failures over all 9,024 shots in the
official run, per the commit comment.

## Classification rationale

The census files it as comparator/width truncation. The change is really a
carry-window cut inside the modular doubling's constant fold, which would fit
fold/carry truncation better, the label used for the sibling `KAL_FOLD` knob.
Both are truncations to fewer bits, so the published label is close.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9a81017 -- src/point_add`.
   - The git parent is `02049b8` (10d9e). It narrowed `DIALOG_GCD_COMPARE_BITS`
     46 → 45 with nonce 5005587, and added a jump-depth model to
     `dialog_gcd_classical_filter.rs` plus two memos. This commit was built on
     `9a81017` and keeps 46.
   - Diffing against the parent (206 lines) would wrongly show the comparator
     going back to 46 and those analysis additions being deleted.
   - Against `9a81017`, `git diff --ignore-cr-at-eol 9a81017 4ef0046 -- src/point_add`
     is 15 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 4ef0046 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because `set_default_env`
   keeps any value already in the environment. Expect:
   - 1313 qubits
   - 1,535,885 average Toffoli (rounded)
   - score 2,016,617,005
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=1000001157` and an
identical op stream. Any other change needs a new nonce hunt.

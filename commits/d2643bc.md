## Summary

The trailmix builder ends with a sound peephole post-pass over the finished op
stream, `constprop::run`. It repeats three analyses (constant propagation,
inverse-pair cancellation, and affine GF(2) relations between CCX controls)
until a sweep changes nothing, but it stopped after at most 16 sweeps by
default. In this circuit each sweep still found something, so the cap was
cutting the pass off early.

This commit sets `CONSTPROP_MAX_ITERS=256` as a default in `build()`. The
author reports that the loop now reaches its real fixed point at sweep 129 and
turns 334 more CCX into CX or X gates. Average executed Toffoli drops by 324.
The circuit's arithmetic and qubit count are unchanged. The tail nonce was
re-hunted.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `build()`: new line
  `set_default_env("CONSTPROP_MAX_ITERS", "256")`.
  - It is read in `src/point_add/trailmix_ludicrous/constprop.rs`, `run()`:
    `max_iters = CONSTPROP_MAX_ITERS`, default 16. The loop breaks when a sweep
    makes no transform, or when `iter >= max_iters`.
  - `run()` is called at the end of `build_trailmix_ludicrous_ops()`
    (`trailmix_ludicrous/mod.rs`) on the whole op stream, with the input
    registers `x2_init` and `y2` seeded as unknown and every other qubit as
    |0⟩.
- **What one sweep does.**
  1. `analyze`: forward abstract interpretation over {Zero, One, Unknown} for
     every qubit and classical bit. A CCX with a provably-0 control is dropped;
     one with a provably-1 control becomes a CX; with both controls 1 it
     becomes an X.
  2. `find_inverse_pairs`: removes `CCX … CCX` pairs on the same wires with
     nothing touching them in between.
  3. `analyze_affine`: tracks each qubit as an exact XOR of source variables
     plus a constant. If the two controls of a CCX always have the same form,
     `a & b = a` and the CCX becomes a CX. If they are always complementary,
     `a & b = 0` and the CCX is dropped.
  Each rewrite can make later gates provably constant or adjacent, so the next
  sweep finds more. See [dead-gate-strip](../concepts/dead-gate-strip.md).
- **Why it saves Toffoli.** The scorer counts every CCX whose classical
  condition holds, whether or not its quantum controls are ever both 1. A CX
  or X is free. Each extra conversion removes one counted Toffoli on every
  shot where the gate's condition is true. The submission note reports
  334 more conversions; the measured average fell by 324, since some of the
  gates sit under a measurement condition and run on only part of the shots.
  See [scoring-and-validation](../concepts/scoring-and-validation.md).
- **Tail nonce.** The `DIALOG_TAIL_NONCE` default goes from 82979 to 188337 in
  four places. The live one is in `build()`. The other three are in
  `configure_ecdsafail_submission_route()`, which only the older dialog route
  uses. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

- **Exact.** Every rewrite is proved for every basis input on every shot. A
  value is marked constant, or two controls are marked equal, only when the
  op-by-op transfer proves it; any conditional write that might not happen
  collapses the value to unknown or a fresh variable. Running more sweeps
  only applies more such proved rewrites, so the computed unitary is the
  same and the failure set (Lambda) is the base's.
- The pass has an optional empirical cross-check, `CONSTPROP_VERIFY=<n>`, which
  replays the unmodified stream over `n` nonces and reverts or panics on any
  claim that fails. It is off by default and not needed for correctness.
- The nonce changed only because the op stream changed. The author reports
  that the shipped nonce 188337 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures, and an exact average of
  1,390,627.914 Toffoli.

## Classification rationale

The saving comes from proving gate controls constant or related from the
circuit's classical structure and specializing the gates. That is constant
propagation / classical specialization, the published label. The runner-up is
Dead-Code and Redundancy Elimination, since dropped CCX and inverse pairs are
dead gates, but most of the change is CCX → CX folding by the constprop pass,
and the code change itself is an iteration cap.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 883f71a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 883f71a d2643bc -- src/point_add` is
   9 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol d2643bc -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1164 qubits
   - 1,390,628 average Toffoli (1,390,627.914 before rounding)
   - score 1,618,690,992
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `188337` and an identical op stream.
Any other change needs a new nonce hunt.

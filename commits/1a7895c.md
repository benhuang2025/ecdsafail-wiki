## Summary

The dialog-GCD inversion (background in [98416e4](98416e4.md); see
[dialog-gcd-early](../concepts/dialog-gcd-early.md)) runs a fixed number of walk steps. Each step works on a
window of `u` and `v` whose width shrinks linearly with the step number. This
commit tightens both budgets:

- **Steps.** `DIALOG_GCD_ACTIVE_ITERATIONS` goes from 259 back to 258. That
  removes the step `94535d1` had added to make its nonce findable.
- **Width.** `DIALOG_GCD_WIDTH_SLOPE_X1000` goes from 1014 to 1015. The
  window then reaches each even width one notch earlier, which narrows 15
  steps by 2 bits.

Both are pure Toffoli cuts: −3,333 in total, at the same 1306 qubits. Most of
it is the dropped step, mainly its two 256-bit apply steps. Both cuts make
more inputs fail, so the author hunted a nonce on GPU (one clean survivor out
of six prefilter candidates).

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 259 → 258.**
   - Both GCD divisions (the quotient for `λ` and the in-place multiply) run
     that many steps in each of their passes: forward walk, apply, and reverse
     walk.
   - One step fewer removes one narrow walk step from the forward and the
     reverse walk. More importantly, it removes one apply step, a controlled
     256-bit modular double or halve plus a controlled modular add/sub on the
     coefficient, in each division.
   - `94535d1` paid about 2,900 Toffoli to add this step.
2. **`DIALOG_GCD_WIDTH_SLOPE_X1000`: 1014 → 1015.**
   - `dialog_gcd_tobitvector_active_width(step) = clamp(2·ceil((256 − step·slope + margin)/2), 1, 256)`
     with `DIALOG_GCD_WIDTH_MARGIN=10`.
   - Going from 1.014 to 1.015 changes the rounded width at 15 of the 258
     steps (67, 69, 71, 134, 136, …, 211, 213), each by 2 bits: 30 bit-steps
     in all.
   - Each bit of window costs a few Toffoli per pass: the cswap, the controlled
     subtract or add body, the K=2 halving cascade, and the comparator where the
     window is narrower than the comparator's per-step width. There are four
     walk passes. See [98416e4](98416e4.md) for the per-bit accounting, which
     came to about 20 Toffoli per bit-step on that tree.
   - This part is a few hundred Toffoli. The rest of the −3,333 is the dropped
     step.
3. **`DIALOG_TAIL_NONCE`: 1076489 → 218004368140.**

## Why it is still correct, and what it risks

Both knobs are probabilistic budgets on the GCD.

- **Fewer steps:** an input whose binary GCD needs more than 258 steps to
  reach `v = 0` does not converge. Its inverse is wrong, so the output point is
  wrong.
- **Steeper slope:** an input whose `u` or `v` is still wider than the window
  at some step gets truncated, which also gives a wrong result.

Both show up as classical mismatches, usually together with phase or ancilla
garbage, because the reverse walk no longer restores the registers. They
raise λ. The author's GPU GCD prefilter on the shard
`218000000000..218004999999` gave six candidates. Five were dirty in trusted
validation (for example 1 classical and 2 phase failures). Only `218004368140`
was clean: 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit tunes two convergence budgets, the step count and the width-envelope
slope. That is iteration/threshold tuning. The width part on its own would be
comparator/width truncation, but the step count is the larger saving.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout fc84586 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol fc84586 1a7895c -- src/point_add` is
   6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1a7895c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1306 qubits
   - 1,460,453 average Toffoli (rounded)
   - score 1,907,351,618
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=218004368140` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

Leapfrog's merged op ([`86221ad`](86221ad.md)) needs a 5-bit word
`u = x + ov + 15·sg` before its fold. Here `x` is 4 bits and `ov` and `sg`
are single bits. The old helper built `u` with 8 temporary ANDs. This commit
writes the same integer as `(x + ov − sg) + 16·sg`: a 4-bit conditional
increment or decrement plus a top bit, which needs only 4 ANDs. Each AND
costs one Toffoli to compute, and its erase is measurement-based and costs
none, so every merged op saves 4 Toffoli. The change is exact. The width and
every window stay the same.

## What changed and why it saves Toffoli

**`src/point_add/leapfrog.rs`, `m_u_build`.** The function is called by
every merged op: `m_fold_fwd` (forward), `merged_rev` and `merged_rev2`
(reverse). It returns `u` as linear forms (`Lin`), with each AND recorded in
`recs` for the reverse-order measurement erase (`m_erase`).

- **Old** (8 ANDs):
  - a 4-AND increment of `x` by `ov` (`d1..d4`);
  - then a 4-AND chain (`e1` and three more) adding `15·sg`.
- **New** (4 ANDs):

  ```
  carry = ov ⊕ sg
  for each bit x_j:  u_j = x_j ⊕ carry ;  carry = AND(x_j ⊕ sg, carry)
  u_4 = sg ⊕ carry
  ```

  - With `sg = 0` this is an increment by `ov`. The carry-out is `u_4`, so
    `u = x + ov ≤ 16`.
  - With `sg = 1` it decrements by `1 − ov`, a borrow chain on `¬x_j`. Then
    `u_4 = 1 ⊕ borrow`, which adds 16 except when the low word wrapped to −1.
  - Both cases give `x + ov + 15·sg` exactly, including the end values 0
    and 31.

The new carries are still `m_and` records, so the existing reverse-order
`lin_and_erase` (an `hmr` plus a conditional CZ) clears them.

**Why only Toffoli moves.** `merged_fits` and `m_fold_plan` size the fold
with the fixed constants `M_FIXED_FWD` / `M_FIXED_REV2`, and those are
unchanged. The 4 freed helper wires therefore do not change which ticks take
the merged op or how its fold is chunked. The author says this is on
purpose: "Freed helper wires are deliberately not used to reprice the
planner". The author's builder count is 242 merged-op calls × 4 = 968
expected Toffoli. The benchmark gives −906 executed Toffoli on the new clean
draw.

**`src/point_add/mod.rs`**: `TAIL_NONCE` 10002555178 → 1441041.

## Why it is still correct, and what it risks

- **Exact.** The rewrite computes the same 5-bit value for all 64 inputs
  `(x, ov, sg)`; the author also checked this exhaustively. No window,
  envelope or compare changes, so λ is unchanged in expectation.
- **What would catch a bug.** A wrong `u` would give a wrong payload value,
  which the **classical** channel catches. A bad erase record would leave
  garbage, which the **ancilla** or **phase** channel catches.
- The shipped nonce `1441041` draws a clean set: 9,024 of 9,024 shots, with
  0 classical, 0 phase and 0 ancilla failures.

## Classification rationale

The same arithmetic, a small conditional add, is computed by a cheaper
adder formulation with half the AND gates. That is Strength Reduction →
fast-adder reroute. The runner-up is Dead-Code and Redundancy Elimination →
dead-gate/self-inverse removal. It was not chosen because no gate is proven
redundant on the old circuit: the computation is re-expressed.

   and run `git checkout 86221ad -- src/point_add`.

   - `git diff --ignore-cr-at-eol 86221ad 9440086 -- src/point_add` lists 98

   - The real change is 27 lines in `leapfrog.rs` and `mod.rs`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9440086 -- src/point_add`
   should print only mode changes.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. The recipe is
   pinned in the source, and `build()` clears the environment. Expect:
   - 1243 qubits
   - 803,254 average Toffoli (rounded)
   - score 998,444,722
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `1441041` and an identical op
stream.

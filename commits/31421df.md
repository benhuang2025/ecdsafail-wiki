## Summary

The trailmix circuit replays a baked per-call schedule (`schedule.rs`) that
tells each adder and each `+f` fold how many clean scratch wires it may use: a
carry budget `k` for every adder, a vent count for every hybrid add, and a
clean-carry count for every fold window. These numbers were tuned so the
circuit just fits under its qubit peak. This commit adds environment knobs that
shift the whole schedule down by 1 or 2 wires, plus a 2-wire cut in a band of
GCD steps, and sets them by default. With every budget smaller, the peak falls
from 1164 to 1162 qubits. The adders and folds then use more Toffoli, because
fewer carries can be measured out and more must be borrowed or recomputed.

To pay part of that back, it narrows the pseudo-Mersenne fold windows:
`arith::PAD` 21 → 19 (fold window 54 → 52 bits, overflow compare 21 → 19 bits)
and the GCD subtract's carry-erase compare `schedule::PAD` 21 → 20. These are
truncations, so failures become more likely, and the nonce was re-hunted. Net:
−2 qubits for +419 average Toffoli, a 2.3 M lower score.

## What changed and why it saves qubits

**Background: the baked budget schedule.** `trailmix_ludicrous/mod.rs`,
`load_schedule()`, copies the tables from `schedule.rs` into thread-local
cursors, and each circuit primitive reads its next entry as it is emitted:

- `next_gcd_k()` reads `GCD_SUB_K`: the carry budget of each controlled GCD
  subtract (`gcd.rs::controlled_add_active` →
  `gidney::controlled_hybrid_add_capped_branch`). It picks the chunk layout of
  the adder. A smaller `k` means fewer clean carry wires, so more chunks and
  more Toffoli.
- `next_cout_k()` reads `APPLY_COUT_K`: the same budget for the apply-phase
  cofactor add/sub (`arith::controlled_mod_add_k`, `controlled_mod_sub_vented`).
- `next_hyb_v()` reads `HYB_V`: how many carries of a Gidney hybrid add
  (`gidney.rs::controlled_hybrid_add_refs_impl`) land on separate ancillae that
  are later measured out with `hmr`. The rest are Toffoli'd into the addend and
  must be uncomputed with a second Toffoli.
- `next_ffg()` reads `FFG_G`: the number of clean carry wires `g` in an apply
  `+f` fold window (`arith::add_f_window`). Below `n − 1` it switches to the
  hybrid or dirty-borrow form, which borrows register bits and costs more
  Toffoli.
- `next_fold()` reads `FOLD_SCHED`: for the fused double fold
  (`fused.rs::fused_fold`) a non-negative code is the clean-vent count `nv`.

Each primitive allocates its scratch wires transiently, so the global peak is
the sum of the live registers and the largest of these budgets at the binding
call. See [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md) and
[venting-and-wire-loans](../concepts/venting-and-wire-loans.md).

**New knobs (code).**

- `trailmix_ludicrous/mod.rs`: `env_i32`, `env_usize`, `sub_delta` and
  `range_adjust_usize` / `range_adjust_i32`. `next_cout_k`, `next_ffg` and
  `next_hyb_v` now return `schedule value − <NAME>_DELTA` (unchanged if the
  value is the "no constraint" sentinel). `next_fold` subtracts
  `TLM_FOLD_DELTA` from non-negative codes. Each also accepts an
  `<NAME>_ADJUST` over a call-index range `[_ADJUST_AFTER, _ADJUST_BEFORE)`;
  none of these range knobs is set by default.
- `trailmix_ludicrous/gcd.rs`: `controlled_add_active` gains the GCD step
  index `i` (passed from `forward_gcd_jump` and `reverse_gcd_jump`), and its
  `k` becomes `maybe_adjust_gcd_k(i, next_gcd_k())`. That applies
  `TLM_GCD_K_ADJUST` and then `TLM_GCD_K_EXTRA_ADJUST` when
  `AFTER ≤ i < BEFORE`.

**New defaults (`src/point_add/mod.rs`).** A new
`configure_q1162_rebased_ffg1_route()` is called first in `build()` (and also
from `configure_ecdsafail_submission_route()`). `set_default_env` only sets a
variable that is still unset, so these values win over the later defaults in
`build()`:

The lower budgets let the peak fall by 2. Each smaller budget turns some
measured-out carries into recomputed or borrowed ones, which raises Toffoli.

**Narrower folds (to win back Toffoli).**

- `trailmix_ludicrous/arith.rs`: `PAD` 21 → 19. This sets
  `LSBS = PAD + 33` (54 → 52; the `// 54` comment is stale) and `MSBS = PAD`
  (21 → 19). Every `+f` window (mod add/sub, doubling, apply fold) works on 2
  fewer bits, about 2 fewer CCX each. Every top-`MSBS` measured overflow or
  borrow compare is 2 bits shorter; it runs on about half the shots. See
  [modular-fold](../concepts/modular-fold.md) and
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- `trailmix_ludicrous/schedule.rs`: `PAD` 21 → 20. Despite its comment, its
  only use is as the `cap` of `controlled_hybrid_add_capped_branch` in the GCD
  subtract. In the variable-chunk layout, a chunk's carry-out is measured out
  and its phase repaired by a comparison of only the top `cap` bits of the
  chunk (`controlled_erase_carry_gated_capped`). One bit fewer per chunk erase.

## Why it is still correct, and what it risks

- **Budget trims: value-exact.** A smaller `k`, `g`, vent count or `nv` only
  picks a different exact decomposition of the same addition (more chunks,
  more borrowed dirty bits, or recomputed instead of measured carries). Where
  a smaller budget gives more variable-size chunks, each extra chunk adds one
  more truncated `cap`-bit carry erase, which is probabilistic.
- **PAD cuts: probabilistic.** A 52-bit `+f` window drops a carry with
  probability about `2^-19` per firing, four times the base's `2^-21`, and the
  19-bit overflow compares misjudge about four times as often. The 20-bit GCD
  chunk erase misjudges about twice as often. These raise Lambda, the expected
  number of failing shots in a 9,024-shot draw.
- **Which channel catches it.** A dropped fold carry gives a wrong coordinate,
  a classical failure. A wrong truncated erase or compare leaves a phase
  error. An ancilla that a too-small budget left dirty would be an ancilla
  failure.
- The shipped nonce 168011267 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures, per the author's remote
  validation.

## Classification rationale

The published label is fold/carry truncation, which fits the two `PAD`
changes. But the score gain comes from the qubit drop: Toffoli went *up* by
419, and the two lost qubits are worth about 2.8 M of score at this Toffoli
count. The qubit drop comes from the schedule-budget trims, so Register and
Scratch Allocation (peak-budget trim, ancilla lifetime / venting) would
describe the main lever better. The PAD cuts are the secondary,
Toffoli-recovering part.

   complete diff against the base.

   should print nothing.

   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1162 qubits
   - 1,391,406 average Toffoli (1,391,406.421 before rounding)
   - score 1,616,813,772
   - 0 classical, 0 phase and 0 ancilla failures

stream. Any other change needs a new nonce hunt.

## Summary

This commit changes one constant and the tail nonce. The modular inverse
runs a binary GCD on two registers, `u` and `v`. Their values shrink as the
GCD proceeds, so the circuit only operates on a shrinking "active width" of
them at step `s`. That width comes from a linear envelope,
`256 − slope·s + margin`. This commit raises the slope from 1.015 to 1.016
bits per step. On 16 of the 258 steps the active width becomes 2 bits
narrower, and every add, subtract, swap and compare in those steps gets
cheaper. The result is −518 average Toffoli at the same 1211 qubits.

## What changed and why it saves Toffoli

**Background: the width envelope (see
[dialog-gcd-early](../concepts/dialog-gcd-early.md)).** In `src/point_add/rounds/dialog/mod.rs`:

```
dialog_gcd_tobitvector_active_width(step) =
    clamp( 2·ceil( (256 − step·slope + margin) / 2 ) + bump(step), 1, 256 )
```

- `slope` is `DIALOG_GCD_WIDTH_SLOPE_X1000 / 1000` (`dialog_gcd_width_slope()`).
- `margin` is `DIALOG_GCD_WIDTH_MARGIN = 10`.
- No `DIALOG_GCD_WIDTH_STEP_BUMPS` are set, so `bump(step)` is 0.
- The width is rounded up to an even number. It bounds `max(bitlen(u), bitlen(v))`
  at that step. The GCD body (the controlled swap, the subtraction, the
  branch compare) and the matching apply and reverse passes act only on the
  low `active_width` bits. The bits above are assumed to be zero.
- There are `DIALOG_GCD_ACTIVE_ITERATIONS = 258` steps. The inverse runs two
  such GCDs (the quotient `dx` and the in-place multiply factor), each forward
  and in reverse.

**The change.**
- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  - `DIALOG_GCD_WIDTH_SLOPE_X1000`: 1015 → 1016.
  - Both `DIALOG_TAIL_NONCE` lines: 30000009780549 → 1801000002650164. Only
    the first line takes effect.
- With the formula above, the steps whose rounded width drops by 2 are steps
  63, 65, 126, 128, 130, …, 199, 250, 252, 254 and 256. That is 16 steps, or
  32 width-bits in total. (I computed this with the formula. Float rounding at
  the exact boundaries could shift a step.)
- −518 / 32 ≈ 16 Toffoli per width-bit per step, summed over all passes.

## Why it is still correct, and what it risks

- **This is a probabilistic truncation.** If some input's `u` or `v` shrinks
  more slowly than the envelope at a narrowed step, its top bits fall outside
  the active window.
- The GCD then computes the wrong transcript, and the inverse comes out
  wrong. That shows up mainly as a classical failure, with garbage when the
  reverse pass cannot undo it.
- The submission note says this failure class is screened by the classical
  GCD-convergence/width prefilter (`dialog_gcd_classical_filter.rs` and the
  public GPU toolkit). So a candidate nonce can be checked cheaply before the
  full quantum run.
- The note also calls the change "value-exact on the reachable verifier
  support for the hunted island". That only means the 9,024 drawn inputs all
  fit. It is not exact in general.
- The shipped nonce `1801000002650164` draws a clean set: 9,024 shots, 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change narrows registers that hold a shrinking value. That is width
truncation, filed with comparator/width truncation. The nonce change comes
with every circuit change.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0d1d1e7 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 0d1d1e7 6777223 -- src/point_add` is
   6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 6777223 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with none of the
   route's variables (`DIALOG_*`, `SQUARE_*`, `KAL_*`, `KARA_*`, `ROUND84_*`,
   `R84_*`) set, because `set_default_env` only fills unset variables. Expect:
   - 1211 qubits
   - 1,404,146 average Toffoli (rounded; 1,404,146.281 in the submission note)
   - score 1,700,420,806
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `1801000002650164` and an identical
op stream. Any other change needs a new nonce hunt.

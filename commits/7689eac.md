## Summary

This is a low-qubit rebuild of the dialog-GCD route. The base `98dd2ad` sat at
1297 qubits, with the GCD walk as the binding phase. The commit lowers four
phases in turn, so that each time one drops, the next one becomes the binder:

1. **GCD walk.** The walk's controlled subtract/add stops materializing the
   gated operand. It uses a new controlled Cuccaro adder whose carries are
   parked on borrowed clean wires and erased by measurement. The walk's
   scratch pool shrinks from `2·body_len − 1` wires to about `active_width`.
2. **Point-addition glue.** Three modular adds of a classical-bit operand
   (`mod_add_qb`, `mod_add_double_qb`, `mod_sub_qb`) switch to the vented
   adder, which needs 2 clean wires instead of a 256-wire carry register.
3. **Apply phase.** The materialized apply add is cut into 10 even chunks
   instead of 5 custom ones, so its transient register is about 26 wires wide.
4. **λ² square.** Each schoolbook row wider than 199 bits is added in two
   windows instead of one, which removes the full-row source register from
   the square's peak.

The new peak, 1226, is set by the apply-phase fused double and halve. The cost
is +48,534 Toffoli, about +3.5%, against −5.5% in qubits. The commit also
re-applies the four truncation settings of [`8e0bf4f`](8e0bf4f.md) (from the
base's looser values) and ships a new nonce.

## What changed and why it saves qubits

### 1. Vented controlled GCD body (`DIALOG_GCD_RAW_TOBITVECTOR_MATERIALIZED_SUB` 1 → 0, new `DIALOG_GCD_CTRL_BODY_VENTED`)

- **Before.** `dialog_gcd_controlled_sub_selected` (`rounds/dialog/mod.rs`)
  took the "materialized" branch. It loads `gated[i] = ctrl & subtrahend[i]`
  into an `n`-wire register, does an uncontrolled measured-carry subtract with
  `n − 1` borrowed carry wires, then clears `gated` by measurement. That needs
  `2·body_len − 1` scratch wires on every walk step. The commit's new comment says
  this pinned the walk at 1297.
- **After.** With the materialized flag at 0, the `else` branch runs. If the
  borrowed slice has at least `n − 1` clean lanes, it calls the new
  `cuccaro_sub_ctrl_vented` (or `cuccaro_add_ctrl_vented` in the reverse walk,
  via `dialog_gcd_controlled_add_selected`). Otherwise it falls back to the old
  `cucc_*_ctrl_lowq`.
- **`cuccaro_add_ctrl_vented(b, addend, acc, ctrl, vent_pool)`**, new in
  `arith/adder.rs`, a port of trailmix's `controlled_hybrid_add_refs`:
  - It does the CX prologue of a Cuccaro adder. Then a forward carry chain
    puts `anc_i = acc[i] & addend[i]` on borrowed lane `i` (one CCX per bit)
    and folds it into `addend[i+1]`.
  - A reverse pass writes each sum bit under control, with
    `ccx(ctrl, addend[i+1], acc[i+1])`. It then clears `anc_i` with
    `hmr(anc_i, m)` followed by `cz_if(acc[i], addend[i], m)`, which costs no
    Toffoli. See [measurement-uncompute](../concepts/measurement-uncompute.md).
  - The total is about `2n` Toffoli, with `n − 1` borrowed lanes and no fresh
    wire. `cuccaro_sub_ctrl_vented` wraps it in X gates on `acc`, using
    `a − x = ~(~a + x)`.
- **Scratch sizing.** In `dialog_gcd_build_composite_scratch`
  (`rounds/dialog/compressed.rs`), the non-materialized case now asks for
  `max(compare_bits + 1, active_width − 1)` lanes, capped at
  `2·active_width − 1`. The first term is for the branch comparator, which
  borrows the same slice; the second is for the vented body. That is about
  half the old ask, which is where the walk-step peak comes down.
- **What it costs.** The controlled branch acts on the whole `subtrahend`
  slice, `active_width` bits. The per-step body trims, the odd-low-bit fast
  path and the stream-suffix maps all belong to the materialized branch, and
  no longer apply.
- New helper `dialog_gcd_ctrl_body_vented_enabled()` (`rounds/dialog/config.rs`)
  is on unless the variable is `"0"`.

### 2. Vented classical-operand modular adds (`arith/modular.rs`)

- `mod_add_qb`, `mod_add_double_qb` and `mod_sub_qb` load a classical bit
  register into a 256-wire quantum register `a`, add it to `acc` mod p, and
  unload it.
- They now call `mod_add_qq_vent` / `mod_sub_qq_vent` instead of
  `mod_add_qq_fast` / `mod_sub_qq_fast`. The switches are `MOD_ADD_QB_VENT`,
  `MOD_ADD_DOUBLE_QB_VENT` and `MOD_SUB_QB_VENT`, each on unless set to `"0"`.
- The vent version does the raw add in place, with `add_nbit_qq`, and the
  Solinas `±c` corrections with Gidney's 2-clean dirty-ancilla adder
  (`venting::iadd_dirty_2clean_classical`), borrowing `a` as dirty scratch. So
  the 256 live Cuccaro carries of the fast adder disappear, at the price of
  more Toffoli. See [venting-and-wire-loans](../concepts/venting-and-wire-loans.md).
- The comments name the phases this takes off the peak:
  `dialog_gcd_raw_pa_x_restore`, `round84_..._add_double_ox`, and the
  `c_ox_minus_rx` / `y_output` / reroll transients.

### 3. Ten-chunk apply ripple (`DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS` 5 → 10, `..._CUSTOM5` 1 → 0)

- The materialized apply add (`dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`
  and its subtract mirror) adds the 256-bit operand in chunks, with a carry
  wire carried across each chunk boundary and cleared by a boundary comparator.
- `CUSTOM5=1` used the hand-placed cuts 50/100/150/196. With `CUSTOM5=0` and 10
  blocks, the chunks are even, about 26 bits each, so the transient load and
  carry register is about 26 wires wide.
- The comment says this drops the apply ripple from 1266 to 1222, under the
  1226 fused double/halve binder, at about +250 average Toffoli for the extra
  boundary comparators.

### 4. Windowed square rows (new `SQUARE_ROW_MAX_SEG = 199`, `arith/multiply.rs`)

- `schoolbook_square_symmetric_lowq_selfhosted[_inverse]_with_clean_supplement`
  builds `x²` row by row into a 512-wire `tmp_ext`. Row `i` has width
  `257 − i`: bit 0 is `x_i`, bit 1 is 0, and bit `2 + k` is
  `x_i & x_{i+1+k}`. Before this commit, each row was materialized in full and
  added in one go, so peak = 1024 (product and source) + up to 257 (row), about
  1284.
- New `square_row_windowed_apply(b, x, tmp_ext, i, width, windows, forward)`:
  - Rows with `width > 199`, that is `i ≤ 57`, are split into
    `ceil(width / 199) = 2` windows.
  - Each window builds only its segment of the row (one CCX per cross term),
    adds it into `tmp_ext[2i + lo ..]` with `cuccaro_add_fast_borrowed_carries`,
    and clears the segment by measurement (`square_row_bit_clear_hmr`). The
    carry lane is borrowed from the still-zero high cells of `tmp_ext`.
  - The carry out of an interior window goes into a fresh `cout` wire, which
    is the next window's carry-in.
  - Afterwards, a reverse sweep rebuilds each interior segment and clears its
    `cout` with a comparator: the carry out is exactly
    `partial_sum < segment + c_in`. The comparator is the new
    `cmp_lt_into_fast_with_cin_borrowed_carries` (`arith/compare.rs`), a
    measured-uncompute comparator whose carry lane is passed in as borrowed
    clean wires.
  - The inverse square (`forward = false`) mirrors all of this with subtracts.
- The comment says this drops the square from 1284 to 1226 "while adding only
  ~26k avg Toffoli for the carry-recovery comparators", and that
  `SQUARE_ROW_MAX_SEG=0` restores the base square.
- Also added but unused on this route:
  - `SQUARE_ROW_WINDOWS` with `SQUARE_ROW_WINDOW_MIN_WIDTH` (a fixed window
    count), which is overridden whenever `SQUARE_ROW_MAX_SEG > 0`;
  - `cmp_lt_into_with_cin_slow`, a carry-array-free comparator selected only
    by `SQUARE_ROW_WINDOW_SLOW_CMP=1`.

### Where the Toffoli goes

The net is +48,534. The author's comments give about +26,000 for the square
windowing and about +250 for the apply chunks. The remaining ~+22,000 has three
sources:

- the vented classical-operand adds, whose in-place adds cost about 2 Toffoli
  per bit instead of 1;
- the controlled GCD body, which now runs at the full active width without the
  trims;
- a credit of a couple of thousand from the tightened truncation knobs.

This split was not measured.

## Why it is still correct, and what it risks

- **Exact parts.** The four peak levers are value-exact:
  - The vented controlled adder computes the same sum as the controlled
    Cuccaro, and each `hmr` + `cz_if` pair exactly cancels the phase of a carry
    wire that equals `acc[i] & addend[i]` at the time it is measured.
  - The vented modular adds compute the same result as the fast ones.
  - Chunking and windowing change only where carries live, not the sum. A
    window's carry out is recovered exactly by the comparator, because
    `partial_sum < segment + c_in` holds exactly when that window overflowed.
  - The comment on the square reports ancilla garbage 0 in testing.
- **Borrowed-lane assumption.** The vented body and the square windows rely on
  their borrowed lanes really being |0>. The square takes them from
  `tmp_ext[2i + width + 1 ..]`, which rows `0..=i` never write. The GCD body
  takes them from the composite scratch slice, which the code sizes for both
  consumers. A non-zero borrowed lane would show up as phase or ancilla
  garbage.
- **Probabilistic parts.** The four truncation knobs, and the rest of the
  inherited route (width envelope, 258 GCD steps, compare schedule), are
  probabilistic. The note says the author pre-screened nonces with a CPU
  filter and then with jieyilong's GPU toolkit (with a relaxed body-trim
  filter), and treated GPU-clean nonces only as candidates.
- The shipped nonce `9100016331678` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is Windowing → windowed carry/shift blocks. Two of the
four peak levers are windowing in that sense: the 10-chunk apply ripple, and
the two-window square rows with carries chained across the boundaries. The
other two are vented adders that borrow or dirty-borrow their carry wires, so
Register and Scratch Allocation → ancilla-lifetime / venting is a close
runner-up. The goal of the whole commit is peak qubits.

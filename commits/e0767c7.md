## Summary

The fourth one-bit step on the apply-phase overflow-clean comparator, after
[88079e6](88079e6.md), [b55ede3](b55ede3.md) and [3033d01](3033d01.md). Each
step of each dialog-GCD apply pass does one controlled modular add or subtract.
Its overflow bit is cleared by a comparison on the top `k` bits of the result
and the addend. This commit makes `k` 19 instead of 20. The GCD now runs 259
steps (since [f5f0f61](f5f0f61.md)), so one bit is 259 × 2 divisions = 518
Toffoli, exactly the measured drop. Qubits are unchanged, and the tail nonce
was re-hunted.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 20 → 19.**
   - `dialog_gcd_apply_clean_compare_bits()` sets `compare_start = N − k` for
     the overflow clean.
   - In the multiply-type division's apply pass, the clean is
     `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)` in
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`.
   - In the quotient division's reverse-exact pass, it is the subtract twin
     `dialog_gcd_clean_truncated_underflow`.
   - About one Toffoli per compared bit, once per apply step:
     2 × 259 × 1 = 518.
   - [88079e6](88079e6.md) explains why `ctrl AND (acc < a)` recovers the
     overflow bit of a modular add.
2. **`DIALOG_TAIL_NONCE`: 201664 → 60306**, the fixed 48-pair `X;X`
   identity tail that reseeds the 9,024 test inputs.
3. The comments are updated with the new count and nonce.

## Why it is still correct, and what it risks

The overflow clean is a truncated comparison. It can be wrong when the result
and the addend agree on all top 19 bits. Then the overflow bit stays dirty and
the wrong correction spreads into later apply steps, which shows up as
classical and phase failures. The author of [11ceae2](11ceae2.md) had tried
apply-clean 19 on the older 258-step route and found no clean island among the
filter survivors. The classical pre-filter does not model this comparator, so
every candidate has to be checked by the full run.

The shipped nonce `60306` draws a test set with 0 classical, 0 phase and
0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A one-bit narrowing of a comparator window is comparator/width truncation. The
nonce change comes with every circuit change and is not a separate lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 89abe1b -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 89abe1b e0767c7 -- src/point_add` is
   14 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol e0767c7 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `R84_*` environment variables set, because `set_default_env`
   only fills in unset variables. Expect:
   - 1307 qubits
   - 1,488,694 average Toffoli (rounded)
   - score 1,945,723,058
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=60306` and an identical op
stream. Any other change needs a new nonce hunt.

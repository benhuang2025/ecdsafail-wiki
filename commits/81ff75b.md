## Summary

Every Solinas fold in this circuit reduces `lo + 2^256·hi` by adding
`hi·(1 + 2^4 − 2^6 + 2^10 + 2^32)` into an accumulator. It builds the `2^32`
term with `mod_shift_left_by_k(hi, 22)`, which shifts `hi` up 22 places and
adds the 22 spilled top bits times `c = 2^32 + 977` back in. This commit,
labelled an "exhaustive audit" in the code, makes three exact savings in that
machinery, each behind its own default-on switch:

1. The spill add at position 0 lands on 22 bits that are known to be zero, so
   the 257-bit Cuccaro adder there is replaced by 22 CX gates. This applies in
   both the left and the right shift.
2. The `2^32`-term modular add or subtract, which most fold routines still did
   with the slow carry-free adder, now uses the fast measured-carry versions.
   The pair-1 Karatsuba fold, which sets the qubit peak, is excluded.
3. The first add of `mod_add_solinas_ext_product` goes into a freshly
   allocated `breg`, so it becomes a CX copy.

Together these save 8,123 Toffoli. Qubits are unchanged.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`.

**1. Shift-22 position-0 add → 22 CX** (switch `AUDIT_SHIFT22_POS0_CX`,
default on; function `audit_shift22_pos0_cx()`).
- `mod_shift_left_by_k(v, k = 22)` first shifts `v` up one place 22 times. The
  top bit goes into `spill[21 − i]` each time, so afterwards `v[0..22] = 0`.
  It then adds `spill·c` into `v_ext = v ‖ ovf` as five Cuccaro ops: add at
  bit positions 0, 4, 10 and 32, and subtract at 6. Each op adds a padded copy
  of `spill` into `v_ext[pos..257]`.
- At `pos == 0`, the padded addend is non-zero only in bits `0..22`, and the
  target is zero in exactly those bits. No carry can form, so the sum is a bit
  copy. The new code emits `cx(spill[i], v_ext[i])` for `i < 22` and returns.
- `mod_shift_right_by_k` applies the inverse ops in reverse order. When it
  reaches position 0, `v_ext[0..22]` equals `spill` again, so the same 22 CX
  clear it.
- This only applies when `lowq_shift22()` is on (env `LOWQ_SHIFT22`, default
  on). Then the ops use the plain Cuccaro adder `cuccaro_add`, which costs one
  Toffoli per MAJ and one per UMA, 512 Toffoli for 257 bits. The same edit is
  made in `mod_shift_left_by_k_lowq` and `mod_shift_right_by_k_lowq`, which
  always use the plain adder.
- In the default circuit, five folds run per point addition: pair 1's
  Karatsuba write, the `λ²` reduction into `breg`, the y-update schoolbook
  multiply, the `breg` clear and pair 2's Karatsuba multiply-add. Each does a
  left and a right shift, so this saves about 10 × 512 ≈ 5,100 Toffoli.

**2. `2^32`-term call-site swaps** (switch `AUDIT_SOL_FOLDS`, default on;
function `audit_sol_folds()`). Two new dispatchers:
- `sol_fold_add_qq` calls `mod_add_qq_fast_lowscratch` (from
  [`bc9728a`](bc9728a.md)) instead of `mod_add_qq`.
- `sol_fold_sub_qq` calls `mod_sub_qq_fast` instead of `mod_sub_qq`.

They replace the call between `mod_shift_left_by_k` and `mod_shift_right_by_k`
in `mod_mul_write_into_zero_acc_schoolbook{,_lowq}`,
`mod_mul_add_into_acc_schoolbook`, `mod_mul_add_into_acc_karatsuba{,_lowq}_with_tmp_ext`,
`mod_mul_write_into_zero_acc_karatsuba2`, `squaring_add_to_acc_schoolbook`,
`mod_add_solinas_ext_product`, `mod_sub_solinas_ext_product` and the two
`squaring_sub_from_acc_schoolbook*` functions.

The slow adders undo their carries with a second Toffoli sweep, and the fast
ones erase them by measurement. So each executed swap saves about 1,000
Toffoli (compare [`b827c9e`](b827c9e.md) and [`e33b400`](e33b400.md)). In the
default circuit, three executed sites change from slow to fast: the
y-update schoolbook multiply-add, the `breg`-clearing `mod_sub_solinas_ext_product`
and pair 2's Karatsuba multiply-add. The `λ²` reduction site was already fast
after e33b400. It now uses the low-scratch variant, which costs 24 Toffoli
more.

The pair-1 sister, `mod_mul_write_into_zero_acc_karatsuba_with_tmp_ext`, keeps
the slow `mod_add_qq`. A new comment marks it as "PEAK-PROTECTED": its fold
runs at the 2708 peak, and a fast adder's 256 carry wires would raise it.

**3. From-zero first add in `mod_add_solinas_ext_product`** (same switch).
Its only caller passes a fresh, zero `breg`. The first operand add,
`mod_add_qq_fast(breg, lo)`, becomes `mod_add_qq_fast_from_zero(breg, lo)`,
which CX-copies `lo` instead of running a 257-bit adder. That saves about 256
Toffoli.

Roughly, part 1 accounts for about 5,100 and parts 2 and 3 for about 3,000 of
the measured −8,123. The commit's submission note covers the whole author line
since [`a16788e`](a16788e.md), not this commit alone.

## Why it is still correct, and what it risks

All three parts are exact on every input.
- Part 1 relies on `v[0..22] = 0` after the shift loop, which holds by
  construction. The reverse CX copy runs after the other four ops and the
  reduction have been undone, so `v_ext[0..22] = spill` holds again. CX is
  self-inverse, so the CX copy has no phase side effects.
- Part 2 swaps adders that compute the same modular sum. Only their carry
  clean-up differs. A wrong `cz_if` fix in a measured erase would show up as a
  phase failure.
- Part 3 relies on `breg = 0` on entry. It is allocated just before the call
  in `square_tx_and_combined_ty_l2minus3qx`.
- The peak stays at 2708 because the one peak-phase fold is excluded. See
  [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed. The base's probabilistic Kaliski
settings passed on the new draw with 0 classical, 0 phase and 0 ancilla
failures.

## Classification rationale

The census files this as Uncompute Strategy → measurement uncompute, which
fits part 2. The larger share of the saving, parts 1 and 3, comes from
operands known to be zero at build time, so an adder becomes a CX copy. That
is Constant Propagation and Classical Specialization → host-derived /
classical specialization, which would describe the diff better overall.

   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.

   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `AUDIT_*`,
   `LOWQ_SHIFT22`, `KAL_*`, `DUMMY_TOFFOLIS` or other environment overrides
   set. Expect:
   - 2708 qubits
   - 3,811,834 average Toffoli (rounded)
   - score 10,322,446,472
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score only reproduces with an identical op stream.

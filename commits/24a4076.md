## Summary

In early June the circuit was the `DIALOG_GCD` route in `src/point_add/mod.rs`
(about 34,000 lines). One of its phases, the "ROUND84 x-tail", subtracts λ²
with a Karatsuba square. That square builds the half-squares `z0 = lo²` and
`z2 = hi²` row by row, and each row is added into the result with a Cuccaro
adder whose carries are erased by measurement. Each row add allocated two
scratch qubits: a zero "pad" bit and a fresh carry-in. The `z2` square also
took a few more qubits from the global pool for its carry lane.

This commit removes those extra qubits. A new adder form handles a result one
bit wider than the row, so the pad bit is no longer needed. For `z0`, the
carry-in comes from the still-clean `z2` slice. For `z2`, two bits that are
always 0 serve as extra carry lanes: bit 1 of `z1 = (lo+hi)²` and bit 1 of
`z0 = lo²`. The gate sequence keeps the same Toffoli count. The square phases
drop by 3 qubits, and the global peak falls from 1416 to 1413. The apply-phase
chunk cut is moved 118 → 116 so that the apply add/sub stays under the new
floor. The Fiat–Shamir reroll counts were re-hunted.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`.

1. **New adders `cuccaro_add_fast_low_to_ext_borrowed_carries` and
   `cuccaro_sub_fast_low_to_ext_borrowed_carries`.**
   - They compute `acc_ext += a` (or `-=`), where `acc_ext` has one more bit
     than `a`. The caller supplies `c_in` and `a.len()` clean carry wires.
   - The old route padded `a` with a zero qubit (`pad`) to make both operands
     the same width. It then called `cuccaro_add_fast_borrowed_carries` on
     n+1 bits, which makes n carries (n CCX).
   - The new adder makes the same n carries (n CCX). The top bit is written as
     `cx(a[n-1], acc_ext[n])`, because `a[n-1]` holds the last carry at that
     point. The pad wire is gone and the Toffoli count is the same.
   - The carries are erased with `hmr` plus `cz_if`, as before. See
     [measurement-uncompute](../concepts/measurement-uncompute.md) and
     [adders-and-carries](../concepts/adders-and-carries.md).
2. **New switch `SQUARE_SELFHOST_SAFE_LANE_REUSE`**, set to `1` in
   `configure_ecdsafail_submission_route()`. When it is on:
   - **`schoolbook_square_symmetric_hosted` (and `_inverse`)**, used for
     `z0 = lo²`: the carry lane was already hosted on the clean `z2` slice
     `tmp_ext[2h..4h]`. Now `c_in` is also `host[width]` from that slice,
     instead of a fresh allocation, and the pad is dropped. That saves 2
     transient qubits per row.
   - **`schoolbook_square_symmetric_lowq_selfhosted_with_clean_supplement`
     (and `_inverse_…`)**, used for `z2 = hi²`: this square hosts its carry
     lane on the not-yet-written high tail of its own output slice, and
     allocates only the remainder. The new `clean_supplement` argument is
     consumed before the global pool. In `squaring_sub_from_acc_karatsuba`,
     the supplement is `[z1_reg[1], tmp_ext[1]]`. The pad is also dropped.
     The fresh `c_in` is still allocated here (the next commit,
     [`e0cfe2b`](e0cfe2b.md), removes it).
   - **Why those two bits are zero.** At that point `z1_reg` holds
     `(lo+hi)²` and `tmp_ext[0..2h]` holds `lo²`. Every integer square is 0 or
     1 mod 4, so bit 1 of a square is always 0. Both wires are disjoint from
     `x_hi`, from the `z2` destination and from its tail lanes. The measured
     carry erase returns them to |0⟩ before anything reads them again.
   - The new `assert_qubit_slices_disjoint` checks at build time that no
     borrowed lane aliases an operand.
   - A debug knob `SQUARE_SELFHOST_GATE_PREFIX_ROWS` (default 0, so unused)
     can route the first rows through the plain `cuccaro_add`.
3. **`DIALOG_GCD_APPLY_CHUNKED_F_CUT`: 118 → 116.**
   - In the GCD "apply" phase, each controlled modular add or subtract
     (`dialog_gcd_add_ctrl_chunked_low_to_ext` and its `sub` twin) is split
     into blocks `[0, CUT)`, `[CUT, CUT2 = 140)` and `[140, 257)`.
   - Each block loads `ctrl·a` for its bits into fresh wires and adds them
     with their own carry lane. The live transient therefore scales with the
     widest block.
   - At 118 the first block was the widest. At 116 it is 116 bits, against
     117 for the last block, so the apply add/sub fall to 1411, under the new
     1413 floor.
   - The cut does not change the Toffoli count. Each address bit is loaded
     once whatever the cut, and the exact boundary-carry clear
     (`ccx_cmp_lt_into_fast_prefix_targets`) runs over the prefix up to the
     *last* cut, 140, which is unchanged.
4. **Reroll counts:** `DIALOG_REROLL` 9 → 109 and `DIALOG_POST_SUB_REROLL`
   0 → 100. In this era, `build_builder()` emits `DIALOG_REROLL` pairs of
   `X;X` on `tx[0]` right after the registers are declared. It emits
   `DIALOG_POST_SUB_REROLL` pairs on `tx[1]` after the `x − Qx`, `y − Qy`
   subtractions. They are identities that only change the op-stream hash,
   which selects the 9,024 test inputs. They serve the same role as the later
   tail nonce.

The author's phase trace after the change lists the 1413 co-binders: the
dialog `terminal_u` phases, `r84k_z_inv_squares` and the x-tail λ² square.
The apply add/sub sit at 1411.

## Why it is still correct, and what it risks

- **Exact.** The new adders compute the same sum as the padded ones. The
  borrowed wires are provably |0⟩ when borrowed, and the measured carry erase
  returns them to |0⟩. Nothing about the arithmetic is approximate. A wrong
  proof would show up as ancilla garbage, or as a corrupted `z1`/`z0` value
  and so a classical mismatch.
- **The F_CUT move is exact.** The chunked add and subtract are exact for
  any cut.
- No truncation changed, so λ, the expected number of failing test shots, is
  the base's. A new op stream still draws a new test set, so the counts were
  re-hunted. The author reports 0 classical, 0 phase and 0 ancilla failures
  over all 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Every saving comes from hosting scratch (the carry-in and carry lanes) on
wires that are already allocated and provably clean, and from removing a
wire that was always zero. That is scratch/ancilla reuse. The F_CUT move
only re-balances block widths so that another phase does not become the new
peak.

   and run `git checkout 3166bbd -- src/point_add`.
   - Do not start from the git parent `a392fd4`. That is aburan28's tree, and

     is 369 lines in 1 file.

   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 24a4076 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `SQUARE_*`, `KARA_*` or `KAL_*` environment variables set,
   because `set_default_env` only fills in unset variables. Expect:
   - 1413 qubits
   - 1,724,727 average Toffoli (rounded)
   - score 2,437,039,251
   - 0 classical, 0 phase and 0 ancilla failures

and an identical op stream. Any other change needs a new reroll search.

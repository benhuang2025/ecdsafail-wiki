## Summary

The dialog GCD works on a window of low bits that shrinks by `slope` bits
per step. [`6abbe60`](6abbe60.md) had loosened the slope from 1.010 to 1.009
to make room for a tighter comparator. This commit sets it back to 1.010 on
top of the 46-bit comparator from [`2f24e2f`](2f24e2f.md), and re-hunts the
tail nonce. The late GCD steps get slightly narrower again. That saves 592
average Toffoli at the same 1320 qubits.

The author's note says the change is "`DIALOG_GCD_COMPARE_BITS` 48 → 46".
That was true against an older tree. Against the frontier it was built on,
the comparator is already 46, and the only circuit change is the slope.

## What changed and why it saves Toffoli

Both changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_WIDTH_SLOPE_X1000`: 1009 → 1010.**
   - `dialog_gcd_tobitvector_active_width(step)` is
     `256 − step × slope + WIDTH_MARGIN` (margin 10), rounded up to an even
     number and clamped to 256. That sets how many low bits of `u` and `v` the
     step's branch compare, cswap and controlled subtract work on.
   - A slope 0.001 steeper narrows step `s` by `0.001 × s` bits, up to about
     a quarter of a bit at the last step. After rounding, some late steps
     lose 2 bits.
   - Each of those steps then needs fewer cswap and subtract Toffoli (about
     one and two per bit), in every forward and reverse pass of both GCD uses.
     That gives −592 in total.
2. **`DIALOG_TAIL_NONCE`: 100874459447525 → 444.** The 48 `X;X` identity
   pairs at the end of `build_builder()` only reseed the 9,024 test inputs.
   The author found 444 with a local early-exit nonce searcher. It derives
   `k·G` with a fixed-base comb in Jacobian coordinates, checks it against
   the affine reference at startup, and absorbs the shared SHAKE prefix only
   once.

## Why it is still correct, and what it risks

- The width envelope is an assumption that `u` and `v` have shrunk below
  `active_width(s)` bits by step `s`. An input that converges more slowly
  keeps a 1 in a bit that is no longer in the window. Its subtract then
  loses that bit, which gives a classical failure, or phase or ancilla
  garbage on the reverse pass.
- A steeper slope makes that a little more likely.
- Nonce 444 draws a clean set: 9,024 of 9,024 shots, with 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The slope narrows the per-step register window, which is comparator/width
truncation, so the published label fits. The author's note describes it as a
comparator cut, but the diff against the base shows only the slope.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 2f24e2f -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 2f24e2f 8a9d274 -- src/point_add` is 4 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8a9d274 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*`, `DIALOG_*` or `SUB4_*` environment variables set, because they
   override the defaults. Expect:
   - 1320 qubits
   - 1,551,859 average Toffoli (rounded)
   - score 2,048,453,880
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `444` and an identical op stream.
Any other change needs a new nonce hunt.

## Summary

This is the same one-notch cut that the author made on the 1285-qubit route in
[`707c1d9`](707c1d9.md), now applied to the 1221-qubit route. The 1221 route
descends from [`7689eac`](7689eac.md), which forked from an older tree and
shipped the window at 18.

In the dialog-GCD apply phase, every controlled modular add or subtract of the
256-bit payload ends with an overflow fold of `c = 2^32 + 977`. That fold's
carry chain stops `w` bits above bit 32. This commit makes `w` 17 instead of
18, one carry stage less per fold. Over 2 × 258 folds the average falls by 511
Toffoli. Qubits are unchanged. The cut is probabilistic, so the nonce was
re-hunted.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`KAL_FOLD_CARRY_TRUNC_W`: 18 → 17.**
   - Read by `fold_carry_trunc_window()` (`arith/const_arith.rs`). It sets the
     window of `cadd_nbit_const_direct_trunc_fast` and its subtract mirror in
     the materialized pseudo-Mersenne apply add/sub
     (`rounds/dialog/mod.rs`, phase `dialog_gcd_materialized_special_overflow_fold`).
   - The carry sweep runs for bit positions `0..=min(n − 2, 32 + w)`. Above
     bit 32 the constant is zero, so each extra stage only carries through a
     run of 1s in `acc`, at one CCX per stage.
   - One stage less per fold, for one fold per step in the forward apply and
     one in the reverse apply (258 steps each), is about 516 Toffoli; the
     measured average falls by 511. See [modular-fold](../concepts/modular-fold.md).
   - The fused double/halve fold has its own window, `KAL_DOUBLE_CARRY_TRUNC_W`
     (19 here), and is not affected.
2. **`DIALOG_TAIL_NONCE`: 165002130437 → 6002139682343.**

## Why it is still correct, and what it risks

The truncated fold is wrong when the carry out of bit 32 would run more than
17 further bits, about 2^−17 per fold, twice the rate at 18. A dropped carry
gives a wrong payload, which is a classical mismatch. Because the reverse
apply then no longer inverts the forward apply exactly, it can also show as
phase or ancilla garbage.

The submission note says that "on this nonce the dropped carry bits are zero
across the full reachable verifier support". More precisely, they are zero on
the 9,024 shots this nonce draws. The shipped nonce `6002139682343` draws a
clean set: 9,024 of 9,024 shots, with 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a narrower carry window in a constant adder, which
is comparator/width truncation, the same label as [`707c1d9`](707c1d9.md).
"Fold/carry truncation" would also fit.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 572bba4 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 572bba4 00fb66d -- src/point_add` is 4 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 00fb66d -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `ROUND84_*`, `R84_*`, `SQUARE_*` or `MOD_*`
   environment variables set, because they override the route defaults.
   Expect:
   - 1221 qubits
   - 1,427,661 average Toffoli (rounded)
   - score 1,743,174,081
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=6002139682343` and an
identical op stream. Any other change needs a new nonce hunt.

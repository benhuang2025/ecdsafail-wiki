## Summary

In this era the modular inverse is a reversible Kaliski "almost inverse" walk
on the pair `(u, v_w)`. Each iteration swaps `u` and `v_w` under its branch
bit at step 3 and swaps them back at step 9. An earlier commit had fused the
step-9 swap of iteration `k` into the step-3 swap of iteration `k+1`, so one
controlled swap does both jobs. That fusion is only valid while `u ≠ v_w`, so
it is limited to a prefix of the walk, `KAL_CSWAP_UV_MERGE_SAFE_ITERS`.

This commit raises that prefix from 254 to 255, which fuses one more
boundary (iterations 253 → 254). That deletes one controlled swap of about
100 bits in each of the four Kaliski walks, for −400 average Toffoli at the
same 2006 qubits. The reroll count `KAL_REROLL` changes from 3 to 28 so the
new op stream draws a clean test set.

## What changed and why it saves Toffoli

- **`src/point_add/kaliski_state.rs`, `kal_cswap_uv_merge_safe_iters()`: 254 → 255.**
  - Background: each Kaliski iteration `k` (in `kaliski_walk.rs`, forward
    `kaliski_iteration_bulk_prefix3` and the backward mirror) runs step 3
    `cswap(a_f, u[j], v_w[j])` to sort the pair and step 9 the same swap to
    restore it. Each `cswap` is CX, CCX, CX, so one Toffoli per bit. The width
    is `min(n or 2n − k, kal_wtrunc_width(k))`, the empirical bit-length
    envelope of the walk (full width for `k < K0 = 21`, then
    `256 − ⌊(k − 21)·2/3⌋`).
  - With the merge, step 9 of iteration `k` is skipped (`uv_merge_out`) and its
    control `a_k` is carried into iteration `k+1` on a `frame` qubit. Iteration
    `k+1`'s step 3 then swaps under `a_k ⊕ a_{k+1}`, using
    `cswap(p)·cswap(q) = cswap(p⊕q)`.
  - While the registers are still physically swapped by `a_k`, iteration
    `k+1` corrects its step-1 parity flags (one extra CCX in the
    `KAL_UV_STEP1_FANOUT` path) and its step-2 comparison with
    `l_gt ^= frame_in`. That second correction is right only when
    `u ≠ v_w`.
  - `uv_merge_in = iter_idx < safe_iters` and
    `uv_merge_out = iter_idx + 1 < safe_iters`. Going from 254 to 255 turns on
    `uv_merge_out` at iteration 253 and `uv_merge_in` at iteration 254.
  - The deleted step-9 swap at iteration 253 is `kal_wtrunc_width(253) =
    256 − 154 = 102` bits wide. Minus the extra step-1 CCX, that is about 100
    Toffoli per walk. The circuit has four such walks (forward and backward
    for each of the two inversion pairs, `pair1` and `pair2` in
    `point_add.rs`), so the saving is about 400. The measured saving is 400.
- **`src/point_add/mod.rs`, `build()`: the default `KAL_REROLL` goes from 3 to 28.**
  - `KAL_REROLL` appends `rr` pairs of `X(tx[0]); X(tx[0])` after the point
    addition. They are an identity with no Toffoli and no new qubits, but they
    change the op-stream hash that picks the 9,024 test inputs. In this era
    it does the job the later tail nonce does.
  - The author's screen of `rr = 0..255` found clean draws at 28, 35, 139 and
    199. 28 was chosen.

## Why it is still correct, and what it risks

- The fusion of two controlled swaps is an exact identity. The only
  approximation is the `l_gt ^= frame_in` shortcut, which gives the wrong
  branch if `u = v_w` at the entry of a merged iteration.
- With gcd 1, `u = v_w` means `(1, 1)`, one step before termination. The code
  proves (`bulk_prefix_safe_iters` comment) that a nonzero secp256k1 input
  needs at least 256 Kaliski steps to terminate. So `(1, 1)` cannot occur at
  iteration 254, and the new merged boundary is exact in practice.
- The reroll matters anyway, because the stream still carries other
  probabilistic truncations (the margin-0 width envelope, the dialog-fold
  slack, the carry-tail cut, the r-small threshold). Any change to the op
  stream redraws the test inputs, and one of those truncations may then fail
  on the new draw. A failure would show as a classical mismatch, usually with
  phase or ancilla garbage.
- With `rr = 28` the author ran the full 9,024-shot benchmark: 0 classical,
  0 phase and 0 ancilla failures.

## Classification rationale

The saving comes from fusing one more pair of controlled swaps across an
iteration boundary. That is **Fusion → boundary cswap-merge**, the same label
the census gives the identical lever in [`cd34b79`](cd34b79.md) (254 → 256)
and [`cef001a`](cef001a.md) (329 → 331). The published label "Register and
Scratch Allocation → scratch/ancilla reuse" does not match the diff: no
register or ancilla changes, and the peak is unchanged.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ccd7530 -- src/point_add`.
   - Do not start from the git parent `115ab0e`. That is xadenryan's commit,
     which this one was not built on.
   - Against the parent, the diff is 56 lines in 4 files. It would show this
     commit re-adding `add_nbit_qq_fast_borrow` and `sub_nbit_qq_fast_borrow`
     to `cuccaro.rs`, setting the carry-tail width `SHIFT22_CARRYTAIL_W` in
     `solinas.rs` back from 35 to 37, and rewriting the parent's `KAL_REROLL`
     and `K0` comments. Those are reverts of xadenryan's edits, not part of
     this change.
   - Against `ccd7530`, `git diff --ignore-cr-at-eol ccd7530 a8688f8 -- src/point_add`
     is 22 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a8688f8 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `AFFINE_*` or `SHIFT22_*` environment variables set, because they override
   the defaults in the patch. Expect:
   - 2006 qubits
   - 2,575,283 average Toffoli (rounded)
   - score 5,166,017,698
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `KAL_REROLL = 28` and an identical op stream.
Any other change draws a new test set and needs a new reroll search.

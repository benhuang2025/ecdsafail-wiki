## Summary

This is the same lever as [`e4497a6`](e4497a6.md), one bit further. The
dialog-GCD branch comparator, which decides `u > v` at every step, now looks at
the top 46 bits of the active window instead of 47. The cap binds on 218 of the
259 steps, and each step's comparator runs in four transcript passes, at one
Toffoli per bit. That gives 4 × 218 = 872 average Toffoli saved, at the same
1320 qubits. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_COMPARE_BITS`: 47 → 46.**
   - Each step computes `b0_and_b1 = v[0] AND (u > v)` with
     `dialog_gcd_ccx_cmp_gt_truncated_into_width_hosted`. It compares only the
     top `k = min(COMPARE_BITS, aw)` bits of `u[..aw]` and `v[..aw]`. See
     [`e4497a6`](e4497a6.md) for the route and the code path.
   - The comparator computes one carry per bit with a Toffoli and erases the
     carries by measurement, so it costs about one Toffoli per bit. See
     [measurement-uncompute](../concepts/measurement-uncompute.md).
   - At this base (slope 1.011, margin 10), `aw ≥ 47` on 218 steps, so 218
     steps lose one bit. The comparator runs forward and in reverse, for each
     of the two GCD factors: 4 × 218 = 872, the measured saving.
2. **`DIALOG_TAIL_NONCE`: 18509 → 20397.** This reseeds the 9,024 test
   inputs. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

The comment says the comparator "still decides every branch correctly on the
reachable support at 46". That holds only for the sampled inputs. In general
the truncated compare is wrong when `u` and `v` agree on all of the top 46 bits
of the window but differ below. The step then skips a needed swap, the subtract
underflows, and the run fails classically, with phase or ancilla garbage when
the reverse pass no longer mirrors the forward one. Each bit removed roughly
doubles that rate and raises λ. The new nonce 20397 draws a clean set, with
0 classical, 0 phase and 0 ancilla failures over all 9,024 shots per the commit
comment.

## Classification rationale

The only circuit change narrows a comparator: comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 83da96f -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 83da96f 351a0d0 -- src/point_add` is 10 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 351a0d0 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because `set_default_env`
   keeps any value already in the environment. Expect:
   - 1320 qubits
   - 1,534,757 average Toffoli (rounded)
   - score 2,025,879,240
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=20397` and an identical op
stream. Any other change needs a new nonce hunt.

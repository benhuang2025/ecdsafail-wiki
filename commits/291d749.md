## Summary

Two fold-window knobs in the pinned table of `mod.rs` change, plus the tail
nonce. No code changes.

The ping-pong replay folds `f` into a low window of the coefficient register
and drops any carry that leaves the window. A wider window gives fewer wrong
results but costs about one Toffoli per extra bit per fold. The base paid for
3 extra window bits on one kind of fold site in the last 66 rounds. This
commit sells those 3 bits (−254 Toffoli) and buys 1 extra bit on every fold
in the first 76 rounds instead (about +144 Toffoli). The author measured that
the early bit removes more classical failures per Toffoli than the late bits
did, so the package lowers both the Toffoli count and the classical error.

This partly undoes the line's own earlier choice. [`f812a29`](f812a29.md) had
set `PP_FOLD_WIDEN` 242 → 0 and added `PP_RETAIN_LATE_WIDEN` = 3. This commit
moves them to 76 and 0.

## What changed and why it saves Toffoli

Both knobs are read in `src/point_add/pingpong.rs`. Background on fold
windows is in [modular-fold](../concepts/modular-fold.md). The replay itself
is in [pingpong-division](../concepts/pingpong-division.md).

1. **`PP_RETAIN_LATE_WIDEN`: 3 → 0.**
   - It is read by `retained_window(fold_window, round)`. That function adds
     this many bits to the fold window when
     `policy_width(round) < PP_RETAIN_LATE_BELOW` (default 32). With this
     width schedule that means rounds 632–697.
   - It only feeds the two *retained* replay routes:
     `retained_prebias::try_replay` (divide, called from `replay_add_halve`)
     and `joint_lowfold::try_replay` (multiply, called from
     `replay_double_add`). These routes keep the final add's carry frame alive
     through the fold and use a 32-bit low-correction cut. See
     [`cc7f10e`](cc7f10e.md), items A4–A5.
   - In those rounds the window is 54 − 4 = 50 bits (fold profile band
     `19:-4`). The base widened the retained sites to 53 bits. Now they fold
     at 50.
   - The author measured −254.2 Toffoli for this change alone (exact count,
     32 paired nonces), and +0.107 model-failing shots per nonce.
2. **`PP_FOLD_WIDEN`: 0 → 76.**
   - It is read by `fold_offset(round)`:
     `band_at(fold_shape(), policy_width(round)) + isize::from(round < fold_widen())`.
     So rounds 0–75 get one more window bit.
   - `Plan::fold_window(r)` adds this offset for every fold route in both
     traversals: the retained routes, the prebias divide route and the plain
     fold.
   - In those rounds the walk is still 241–259 bits wide, so the window goes
     from 54 to 55 bits.
   - The source comment on `fold_shape` explains why early rounds are a good
     place for protection. The rate at which a dropped fold carry matters is
     flat while the walk is wide, and it collapses once the walk is below
     about 45 bits. An early bit therefore covers rounds where failures are
     common, and the late bits covered rounds where they were already rare.
   - The author priced this buy at about 1,040 Toffoli per model-failing shot
     removed. Selling the late bits saved about 2,370 Toffoli per shot added.
     Widening a base window to 55, or bumping a profile band, cost 1,180–1,840
     Toffoli per shot.
3. **Tail nonce** (`TAIL_NONCE` in the `env_raw` table in `mod.rs`):
   9422592313 → 9444541598.

Net: about −110 Toffoli predicted, and −104 at the ground nonce, at the same
1251 qubits.

## Why it is still correct, and what it risks

- Both changes move a truncation, so both are probabilistic. A dropped fold
  carry gives a wrong coefficient, which shows up as a **classical** failure.
- On the author's screen model the package removes slightly more error than it
  adds. Over 3,072 nonces it has 49 fewer model-failing shots than the base
  (41,751 against 41,800). The circuit λ is 16.64 ± 0.26 over 256 nonces,
  against 16.74 ± 0.26 for the base.
- This matters because the line carries the [`cc7f10e`](cc7f10e.md) "limiting
  contract": λ must stay at or below 18, and an error sell must be paired with
  a buy that removes at least as much error.
- The shipped nonce draws a clean set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit only redistributes fold-window width across rounds: narrower late,
wider early. That is a fold/carry-truncation retune. It is not iteration
tuning, because no round count moves.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b788efc -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol b788efc 291d749 -- src/point_add` is
   8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 291d749 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. This tree reads
   every knob from the fixed `env_raw` table in `mod.rs` and ignores the
   environment, so `SUB4_*`, `TLM_*`, `PP_*` or `HEO_*` variables have no
   effect. Expect:
   - 1251 qubits
   - 894,685 average Toffoli (rounded)
   - score 1,119,250,935
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `9444541598` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

The commit tightens three independent safety margins and finds one tail nonce
that is clean for all three together:

- The GCD width envelope shrinks a little faster.
- The fold that reduces each apply add or subtract mod p stops its carry ripple
  2 bits earlier.
- The comparator that erases the apply's overflow flag looks at one bit fewer.

The first saves 1,044 Toffoli. The other two run once per apply call, 518
times per point add, and save 2 and 1 Toffoli per call: 1,036 + 518. The total
is 2,598 average Toffoli at the same 1320 qubits. All three are probabilistic
truncations, so each raises λ a little.

## What changed and why it saves Toffoli

All changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`. Background on the route is in
[`ec0fa98`](ec0fa98.md): 259 K2 GCD steps, two factors, four transcript passes,
and an apply with one chunked modular add (forward) and one chunked modular
subtract (reverse) per step, 518 calls in all.

1. **`DIALOG_GCD_WIDTH_SLOPE_X1000`: 1009 → 1011.**
   - `active_width(step) = ceil_even(256 − step × slope + 10)`.
   - Σ aw over the 259 steps goes 35,370 → 35,306 (−64 bits). The comparator
     width `min(47, aw)` goes 11,337 → 11,332 (−5 bits).
   - Each width bit is about 4 Toffoli per step per pass (swap, gated load,
     subtract, K2 shift) and each comparator bit 1, over 4 passes:
     4 × (4 × 64 + 5) = 1,044 Toffoli.
2. **`KAL_FOLD_CARRY_TRUNC_W`: 24 → 22.**
   - After the raw 256-bit add `y += b0·x`, the overflow bit `acc_ovf` says the
     sum wrapped past 2^256. The fold adds `c = 2^32 + 977` back into the low 73
     bits (`DIALOG_GCD_SPECIAL_ADD_LSBS`), controlled on `acc_ovf`, because
     2^256 ≡ c (mod p). The subtract does the mirror image. See
     [modular-fold](../concepts/modular-fold.md).
   - `fold_carry_trunc_window()` makes `cadd_nbit_const_direct_trunc_fast` and
     `csub_nbit_const_direct_trunc_fast` stop the carry ripple `w` bits above
     the constant's top set bit (bit 32), instead of running to bit 73.
   - Each carry position is one Toffoli (the carries are erased by
     measurement). Two fewer positions is −2 Toffoli per call:
     2 × 518 = 1,036.
3. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 20 → 19.**
   - After the fold, `acc_ovf` still holds the overflow bit and must be
     erased. For an add, the sum wrapped exactly when the new `acc < x`.
   - The add path (`..._overflow_clean`) recomputes that test with
     `ccx_cmp_lt_into_fast`. The subtract path recomputes the matching
     underflow test with `dialog_gcd_clean_truncated_underflow` (a comparison
     against the complemented top bits of `x`). Both look only at the top
     `APPLY_CLEAN_COMPARE_BITS` bits, are controlled by `b0`, and XOR the result
     into `acc_ovf`.
   - One Toffoli per compared bit: −1 per call, 518 in all.
4. **`DIALOG_TAIL_NONCE`: 6416 → 18509.** This reseeds the 9,024 Fiat–Shamir
   inputs for the new op stream. See
   [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

The commit comments call the fold and comparator changes "value-exact on the
reachable support". They are not exact. Each is a truncation that fails on rare
inputs:

- **Width slope.** An input whose GCD converges more slowly than the envelope
  has a set bit above `aw`, and the transcript goes wrong. This gives classical
  failures, plus phase or ancilla garbage.
- **Fold window.** The truncated fold is exact unless the carry out of bit 32
  runs through `w + 1` consecutive ones above it. For a random accumulator that
  is about 2^−(w+1) per call. If it happens, the high sum bits are wrong, which
  gives a classical failure. The carries themselves still return to 0. Going
  from 24 to 22 makes this about 4× more likely.
- **Overflow-clean compare.** If the new `acc` and `x` agree on all 19 top
  bits, the truncated test cannot see the difference and leaves `acc_ovf`
  dirty. That gives ancilla garbage, and phase errors downstream. Each bit
  removed roughly doubles the rate.

All three raise λ. The commit stacks them under one search. The shipped nonce
18509 draws a clean set, with 0 classical, 0 phase and 0 ancilla failures over
all 9,024 shots per the commit comment.

## Classification rationale

All three levers narrow arithmetic to fewer bits: a register-width envelope, a
carry window, and a comparator window. The comparator and width parts fit
comparator/width truncation. The `KAL_FOLD` part alone would be fold/carry
truncation, the runner-up label.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ec0fa98 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol ec0fa98 83da96f -- src/point_add` is 20 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 83da96f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because `set_default_env`
   keeps any value already in the environment. Expect:
   - 1320 qubits
   - 1,535,629 average Toffoli (rounded)
   - score 2,027,030,280
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=18509` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

One constant. W-TRUNC, from [`36e8578`](36e8578.md), clips each
Toffoli-bearing width loop of the Kaliski iteration to an empirical bit-length
envelope plus a safety margin. This commit lowers the margin from 32 to 20
bits. Every clipped loop is then up to 12 bits narrower, and the number of
iterations where clipping applies grows. The result is 47,664 fewer average
Toffoli at the same 2310 qubits. The cost is a thinner cushion above the
fitted envelope.

## What changed and why it saves Toffoli

- `src/point_add/kaliski_state.rs`, `kal_wtrunc_margin()`: the default of
  `KAL_WTRUNC_MARGIN` goes from 32 to 20. The old comment ("Default 16", which
  did not match the code's 32) is replaced with the sweep result.
- The width at iteration `it` is
  `min(n, 256 − ⌊(it − 27)·2/3⌋ + margin)` for `it ≥ 27`, clamped again by
  the provable bound at each site.
  - With margin 20, clipping starts at iteration 59 instead of 77, because
    `⌊(it − 27)·2/3⌋` must exceed the margin.
  - From there on every clipped loop is 12 bits narrower than at margin 32.
- The clipped loops are:
  - the STEP 0 `v_w == 0` OR chain (generic iteration);
  - the STEP 2 comparator `u > v_w`;
  - the STEP 4 load `tmp = add_f & u` and the subtract `v_w −= tmp`;
  - their backward mirrors.

  Each costs about one Toffoli per bit. Two Kaliski pairs, each run forward
  and backward, give about 1,600 iterations per shot, so 12 bits off several
  loops in most of them gives the 47,664.

## Why it is still correct, and what it risks

- **The clip is probabilistic.** An input whose `u` or `v_w` keeps a set bit
  above `w_env(it) + 20` at some iteration makes a clipped comparator,
  subtractor or OR chain ignore it. The inverse is then wrong: a classical
  mismatch, often with phase garbage from the broken backward run. The code
  comment above the margin reported that over 300,000 fresh inputs the minimum
  slack equalled the margin, so 20 bits is still a wide cushion.
- **Which margins pass is not a safety curve.** The new comment says margins
  17–19 and 21–23 fail on the 9,024-shot scorer, and 20 passes. A wider margin
  is never less safe on a given input, so failures at 21 to 23 cannot come
  from W-TRUNC itself. Each margin is a different op stream and so a different
  hashed test draw. Those draws most likely hit one of the circuit's other
  empirical knobs instead: the pair iteration counts, `BULK_PREFIX_SAFE_ITERS`
  or `R_SMALL_THRESHOLD`. The author's comment rightly calls 20 "a banked
  exact island, not a monotone safety margin".
- There is no tail nonce in this era. The shipped draw is clean: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f9fae31 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol f9fae31 6da9882 -- src/point_add` is
   12 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 6da9882 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `POINT_ADD_*` or `BY_*` environment variables set. Expect:
   - 2310 qubits
   - 3,015,004 average Toffoli (rounded)
   - score 6,964,659,240
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era: the test set is a hash of the op stream,
so the score only reproduces with an identical op stream.

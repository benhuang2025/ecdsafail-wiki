## Summary

The Karatsuba multiplier reduces its 512-bit product mod p with a Solinas
fold: it adds the low and high halves, and shifted copies of the high half,
into the accumulator with the fast modular add `mod_add_qq_fast`. Each such
add corrects mod p by adding and conditionally subtracting the small
constant `c = 2^256 − p = 2^32 + 977`. The base did that by writing `c` into a
fresh 257-qubit register and running a quantum-quantum adder against it.

This commit adds two "low-scratch" copies of the modular add that do the `+c`
and `−c` steps with the direct constant adders instead. Those read the bits of
`c` classically and need no addend register. The fold is the peak phase, so
the peak falls from 2710 to 2708. Each replaced add costs 24 more Toffoli,
+192 in all. It is the same idea as cryptogakusei's [`168048c`](168048c.md),
which this line had not merged, applied only at the fold.

## What changed and why it saves qubits

All edits are in `src/point_add/mod.rs`.

- **New `mod_add_qq_fast_lowscratch(acc, a)`.** Same steps as
  `mod_add_qq_fast`:
  1. `add_nbit_qq_fast(a_ext, acc_ext)`, the 257-bit measured Cuccaro add;
  2. `+c` unconditionally;
  3. `flag = NOT acc_ovf`, then `−c` under `flag` (undo the `+c` when it did
     not overflow);
  4. clear `flag` with `cmp_lt_into_fast(acc, a)`.

  Steps 2 and 3 now call `cadd_nbit_const_direct_fast(acc_ext, c, one)`, with
  a fresh `|1⟩` qubit as the control, and `csub_nbit_const_direct_fast(acc_ext, c, flag)`.
  The base used `load_const` + `add_nbit_qq_fast` + `unload_const` for step 2,
  and built `flag ? c : 0` in a fresh 257-qubit register for step 3.
- **New `mod_add_qq_fast_from_zero_lowscratch(acc, a)`.** The same, for an
  accumulator known to be 0: step 1 is a CX copy of `a` into `acc`.
- **Call sites.** All eight fold adds are switched to the new functions:
  - four in `mod_mul_add_into_acc_karatsuba_with_tmp_ext`: `lo`, `hi`,
    `hi·2^4` and `hi·2^10`;
  - four in `mod_mul_write_into_zero_acc_karatsuba_with_tmp_ext`: the
    phases `sol_addlo` (the from-zero variant), `sol_add0`, `sol_add4` and
    `sol_add10`.
  The fold computes `acc += lo + hi·c` with `c = 1 + 2^4 − 2^6 + 2^10 + 2^32`,
  doubling `hi` in place between terms. The `−2^6` term (`mod_sub_qq_fast`,
  phase `sol_sub6`) and the `2^32` term after the `shift22` step (`mod_add_qq`)
  are unchanged.
- `mod_add_qq_fast` itself, and every other caller, are unchanged.

**Why the peak falls.** The direct adders compute each carry as
`majority(acc_i, k_i, carry_i)` with `k_i = ctrl` where bit `i` of `c` is 1
and `k_i = 0` elsewhere, then erase the carries with `hmr` and `cz_if`. Their
live scratch is the carry bank only. The old path held a 257-qubit constant
register on top of the carries. The code comment says the fold "owns the 2710
peak". Removing the register drops that phase below the next-highest one,
which now sets the peak at 2708. See
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

**Why Toffoli rises by exactly 192.** `c` has 1-bits at positions 0, 4, 6, 7,
8, 9 and 32. At each 1-bit with a carry-in, the direct adder needs three CCX,
`(acc·carry) ⊕ (ctrl·acc) ⊕ (ctrl·carry)`, because it cannot overwrite the
shared control wire as a Cuccaro MAJ overwrites its addend bit. Position 0
has no carry-in and costs one. So each direct call costs 2 × 6 = 12 Toffoli
more than the Cuccaro add it replaces, each modular add has two such calls,
and 8 adds × 24 = 192. See
[adders-and-carries](../concepts/adders-and-carries.md) and
[modular-fold](../concepts/modular-fold.md).

## Why it is still correct, and what it risks

The change is exact on every input.
- The direct adders compute the same sum and difference as the Cuccaro adds,
  bit for bit, and the rest of the modular add is unchanged.
- Their measured carry erase is exact. After the sum is written, each carry
  equals `majority(NOT s_i, k_i, carry_i)` for an add, and the `cz_if` gates
  apply that majority's phase as three pairwise CZs. A wrong fix would show
  up as a phase failure. See
  [measurement-uncompute](../concepts/measurement-uncompute.md).

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed. The Kaliski iteration cuts of the base
are still probabilistic, and the run passed with 0 classical, 0 phase and 0
ancilla failures on the new draw.

## Classification rationale

The saving is a 257-qubit scratch register that is no longer allocated, which
puts the commit in Register and Scratch Allocation. The published change-type
is ancilla-lifetime / venting. Nothing is vented or freed early, though: the
register disappears because a different adder does not need it. "Scratch
removal" or scratch/ancilla reuse describes it better. The runner-up family
was Strength Reduction → fast-adder reroute, the label the census gave the
same idea in [`168048c`](168048c.md), but the reroute costs Toffoli rather
than saving it.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a16788e -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol a16788e bc9728a -- src/point_add` is
   95 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol bc9728a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `DUMMY_TOFFOLIS` or other environment overrides set. Expect:
   - 2708 qubits
   - 3,904,204 average Toffoli (rounded)
   - score 10,572,584,432
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score only reproduces with an identical op stream.

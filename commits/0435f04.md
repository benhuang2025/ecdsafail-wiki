## Summary

This commit trades a little Toffoli for 4 qubits. The peak at 2006 was set by
two phases at once: the `pair2` Kaliski inversion (its step-4 adds) and the
affine square-uncompute. Both have to come down together, or the other one
keeps the peak.

- The Kaliski walk keeps one history bit per iteration. The "dialog fold"
  stores as many of those bits as it can in high bits of `v_w` that the
  shrinking GCD value no longer uses. A 4-bit safety band ("slack") kept the
  fold away from the top of the value. Setting the slack to 0 lets more
  history bits fold, so fewer dedicated qubits are needed. This lowers the
  `pair2` floor.
- The affine squarer uses a fast adder with a 2·width transient for rows up to
  width `mfw`, and a slower in-place adder above that. Lowering `mfw` from
  234 to 232 cuts the affine transient by 4 qubits, to the new floor.

The cost is +1,868 Toffoli from the two squarer rows that switch to the slower
adder. The net score change is −6.56 M. The reroll count changes from 3 to 47.

## What changed and why it saves qubits

1. **`src/point_add/kaliski_state.rs`, `kal_dialog_fold_slack()`: 4 → 0.**
   - Background, the dialog fold (`dialog_fold_vw_slotmap`): the Kaliski
     inversion writes one history qubit `m_hist[i]` per iteration so the walk
     can be undone. As the walk runs, `v_w` shrinks, and its bits at or above
     `kal_wtrunc_width(i)` (the empirical bit-length envelope that the circuit
     already truncates to) are |0⟩. The fold relabels each foldable
     `m_hist[j]` onto one of those idle `v_w` bits instead of a fresh qubit.
     This is pure qubit relabeling, so it costs no Toffoli.
   - A slot can only use a coordinate at or above its anchor,
     `wt_hi(i) = kal_wtrunc_width(i − 1) + slack`, taken as the maximum over
     the iteration that stores it and every iteration that borrows it as a
     step-4 carry. Slots are placed greedily by ascending anchor. Slots with no
     free coordinate stay on a dedicated register, and that register is part of
     the `pair2` step-4 peak.
   - The slack exists because the step-6 shift `v_w >>= 1` is truncated to
     `dialog_fold_shift_width = kal_wtrunc_width(i) + slack`, so that it never
     moves a folded history bit. The source comment explains why a band was
     kept: rare inputs carry a set bit one position above the envelope, and the
     wider shift brings it back down into range for the next iteration.
   - With slack 0, every anchor drops by 4, more slots fold, and the dedicated
     pool shrinks. The step-6 shift becomes exactly `kal_wtrunc_width(i)` wide.
     Swaps cost no Toffoli, so the Toffoli count does not change from this part.
2. **`src/point_add/mul_affine.rs`, `square_tx_and_combined_ty_l2minus3qx()`: the
   default `AFFINE_SQUARE_RECOMPUTE_MFW` goes from 234 to 232.**
   - The affine step squares λ into a 512-bit `tmp_ext`, folds it into `breg`,
     uncomputes the square, runs the y-multiply, then squares again to clear
     `breg`. That is four passes of `schoolbook_square_symmetric_pb` or its
     inverse, all while the 256-bit `breg` is live.
   - In each pass, row `i` adds a `width = n − i + 1` partial-product row into
     `tmp_ext`. Rows with `width ≤ mfw` use `cuccaro_add_fast`, which needs a
     carry register (a transient of about 2·width). Wider rows use the
     in-place `cuccaro_add`, which has a transient of about width but costs
     about `width` more Toffoli.
   - At 232, the rows of width 233 and 234 (`i = 24, 23`) switch to the
     in-place adder. The widest fast row's transient falls by 2·2 = 4 qubits,
     so the affine phase peaks at 2002, level with the new `pair2` floor. The
     author's comment says 231 would drop the affine to 2000, but `pair2` binds
     at 2002, so 232 is the cheapest value that reaches it.
   - Cost: 2 rows × about 234 Toffoli × 4 passes ≈ 1,870. The measured change
     is +1,868.
3. **`src/point_add/mod.rs`, `build()`: the default `KAL_REROLL` goes from 3 to 47.**
   This is the count of identity `X(tx[0]); X(tx[0])` pairs that re-seeds the
   9,024-shot test draw. In this era it does the job of the later tail nonce.
   The author's comment names `rr = 56` as another clean draw.

## Why it is still correct, and what it risks

- The `mfw` change is exact. Both adders compute the same sum, so only
  Toffoli and transient width change.
- The slack change is probabilistic. On an input whose `v_w` briefly carries a
  set bit just above `kal_wtrunc_width(i)`, the truncated step-6 shift now
  drops that bit, and it may also collide with a folded history bit. The GCD
  walk then goes wrong. That would show as a classical mismatch, together with
  phase and ancilla garbage, because the backward walk no longer clears the
  history.
- The author states that the excursion band is never needed on the `rr = 47`
  draw. The full benchmark gives 0 classical, 0 phase and 0 ancilla failures
  over 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The qubit saving comes from a change in where history ancillas live (folded
onto idle value bits instead of a dedicated pool) and from a shorter adder
transient. The published label, Register and Scratch Allocation →
ancilla-lifetime / venting, fits the first. "scratch/ancilla reuse" would fit
the fold just as well, since it reuses idle `v_w` bits. The `mfw` clamp is a
peak-for-Toffoli trade that only pays because both binders move together.

   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.

   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or `AFFINE_*` environment variables set. Expect:
   - 2002 qubits
   - 2,577,551 average Toffoli (rounded)
   - score 5,160,257,102
   - 0 classical, 0 phase and 0 ancilla failures

Any other change needs a new reroll search.

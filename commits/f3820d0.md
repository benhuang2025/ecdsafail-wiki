## Summary

[a5a590a](a5a590a.md) and [73f4f48](73f4f48.md) cut 2 high bits off the
dialog-GCD walk body at steps 9 and then 8, each time lowering the peak
by one. This commit extends the same 2-bit notch to steps 10 and 11. The
author's phase trace showed that the 1300 peak was set by the compressed
walk-body phases at those steps. After the notch they fall below the final
apply ripple, and the peak becomes 1299.

The commit also teaches the CPU classical pre-filter, used to screen nonces
for the GPU search, to apply the same trio and binder notches, so that it
rejects nonces against the body widths that are actually emitted. The
filter is analysis-only and does not change the circuit.

## What changed and why it saves qubits

1. **`DIALOG_GCD_BINDER_NOTCH_STEPS`: `8,9` → `8,9,10,11`**, with
   `DIALOG_GCD_BINDER_NOTCH_EXTRA` still 2, in
   `configure_ecdsafail_submission_route()` (`src/point_add/mod.rs`).
   - `dialog_gcd_body_carry_trunc_width(active_width, step)` returns
     `active_width − w`. `active_width` is still clamped to 256 at these
     steps (margin 10, slope 1.015). The band trims
     `DIALOG_GCD_BODY_CARRY_BAND_TRIMS` have 10-step bands, so steps 10–19
     are in band 1 with trim 3. Step 11 also has the default-on trio notch,
     +2.
   - Step 10's body goes from 253 to 251 bits, and step 11's from 251 to 249.
   - The body's composite scratch is `2·body_len − 1` wires, so each of these
     steps' scratch, and so its peak, falls by 2. Those were the 1300
     binders, and the next binder (the final apply ripple, per the author's
     trace) is at 1299. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - Emitted Toffoli: by the same count as [73f4f48](73f4f48.md), about
     −4 per body × 2 steps × 4 walks = −32. The *average executed* count
     moved by only −2. The average includes many classically conditioned
     Toffoli, such as the apply boundary replay of [bfd3fa6](bfd3fa6.md),
     and so it shifts from one nonce's test draw to the next. In the
     neighbouring commits the measured average is 2 to 18 Toffoli off the
     emitted-count prediction ([da55bbb](da55bbb.md): −516 predicted, −534
     measured). The gap of about 30 here is larger than those, and I could
     not confirm the emitted count without a build.
2. **`src/point_add/dialog_gcd_classical_filter.rs`**: new
   `body_carry_extra_notch(step)`, added to the trim in both
   `body_carry_trunc_width` and `body_carry_trunc_width_fast` of
   `DialogGcdFilterConfig`. It reads the same environment knobs as the
   emitter: `DIALOG_GCD_TRIO_WIDTH_NOTCH` (default on, step 11, +2) and
   `DIALOG_GCD_BINDER_NOTCH_STEPS` / `_EXTRA`. Before this, the filter used
   the band trim only, so it modelled steps 8, 9 and 11 as wider than they
   really are.
3. **`DIALOG_TAIL_NONCE`: 9831976 → 45892140.** The author searched nonces
   0 to 50,000,000 with the updated GPU filter, which gave 30 filter-clean
   candidates. Only `45892140` was clean under the trusted evaluator.

## Why it is still correct, and what it risks

The notch relies on the cut bits of `u` and `v` being 0 at steps 10 and 11
and on no carry reaching them. The code comment calls it value-exact on
the reachable support. The bound behind it is the empirical width bound
that the band trims also use, so treat it as probabilistic. A violation
sends the walk off its path, which shows up as a classical mismatch and
ancilla garbage.

That the filter needed the notches, and that 29 of 30 filter-clean
candidates still failed the full check, shows these are real hazards: the
classical filter models only width overflow, comparator mis-decisions and
non-convergence, not the apply-phase truncations. The shipped nonce
`45892140` draws a test set with 0 classical, 0 phase and 0 ancilla
failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows the body at two more steps, which is width
truncation. The purpose is the qubit, so Register and Scratch Allocation →
scratch/ancilla reuse would also fit. The filter edit is tooling.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout da55bbb -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol da55bbb f3820d0 -- src/point_add` is
   50 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f3820d0 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set. Expect:
   - 1299 qubits
   - 1,403,522 average Toffoli (1,403,521.775 before rounding)
   - score 1,823,175,078
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `45892140` and an identical op
stream. Any other change needs a new nonce hunt.

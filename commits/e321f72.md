## Summary

The dialog GCD stores its per-step transcript in pairs of steps (background in
[9a81017](9a81017.md); see [transcript-codecs](../concepts/transcript-codecs.md) for the K2 pair compressor). Five
of a pair's six bits are correlated: only 15 of their 32 combinations can
occur. A reversible 5-qubit encoder maps those 15 states onto states whose
first bit is 0. That bit can then be dropped, so a pair takes 5 stored bits
instead of 6. The encoder, and its inverse the decoder, runs 8 times per
2-step block: 8 × 129 = 1,032 times per run.

This commit replaces the 6-CCX encoder with a different one that uses 3 CCX and
some extra CX gates. It assigns different 4-bit codes to the 15 states, but it
is still a bijection onto `core[0] = 0`. The decoder is replaced by its exact
gate reverse. 3 CCX × 1,032 calls = 3,096 Toffoli, exactly the measured saving.
Qubits are unchanged. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

1. **`src/point_add/rounds/dialog/compressed.rs`, `emit_dialog_gcd_k2_pair_core_encoder(b, core)`.**
   - The input is `core = dialog_gcd_k2_pair_core(raw_block) = (b0_A, bb_A, s2_A, b0_B, bb_B)`.
     These are step A's branch bits and shift2 bit, then step B's branch bits.
   - The 15 reachable states satisfy `bb ≤ b0` for both steps (because
     `bb = b0 ∧ (u > v)`), and `s2_A = 0 ⇒ b0_B = 1`. If step A halved only
     once, `v` is odd when step B starts.
   - Old gate list: X, CX, then 6 CCX interleaved with X and CX.
   - New gate list (13 gates, 3 CCX):
     ```
     cx(c1,c2); cx(c0,c4); x(c3); ccx(c2,c3,c1); cx(c3,c4); ccx(c3,c4,c0);
     cx(c2,c4); cx(c0,c3); cx(c3,c2); cx(c3,c4); ccx(c1,c3,c0); cx(c1,c0); cx(c3,c0)
     ```
   - I enumerated both encoders on the 15 reachable states. Both send all 15
     to distinct states with `core[0] = 0`. The code words differ: for example,
     `(1,0,1,1,0)` encodes to `00000` under the old encoder and to `00011` under
     the new one.
2. **`emit_dialog_gcd_k2_pair_core_encoder_inverse`** is replaced by the new
   list in reverse order. Every gate is self-inverse, and the inverse undoes the
   encoder on all 32 basis states, which I also checked.
3. **`src/point_add/mod.rs`**: `DIALOG_TAIL_NONCE` 11201395269 → 60009363210,
   with a comment that records the result.

**Why a different code is allowed.** Nothing reads the compressed bits
directly. The forward compress (`dialog_gcd_k2_pair_clear_raw_block_copy`)
encodes. Every reader first decodes with the matching inverse:
`dialog_gcd_k2_pair_copy_compressed_block_to_raw` in both applies and in the
reverse walk. So any bijection onto `core[0] = 0` works, as long as encoder
and decoder change together. The "state-updating reverse pop" codec from
`3409fbd`, which would read controls straight out of the compressed block, is
not in this tree's lineage and is not enabled.

**Call count.** Each 2-step block goes through the codec 8 times: encode and
decode in each division's walk, and decode plus re-encode in each of the two
applies. That is 4 encodes and 4 decodes per block. With 258 steps there are
129 blocks: 8 × 129 × 3 = 3,096.

## Why it is still correct, and what it risks

The new encoder is a reversible permutation of the 5 core bits, and its decoder
is its exact inverse on every basis state. On the 15 states the walk can
produce, it clears `core[0]`, just like the old encoder. The 15-state support
follows from how the bits are built, not from probabilities, so this holds on
every input. The op stream changed, so the nonce was re-hunted. Nonce
`60009363210` validated with 0 classical, 0 phase and 0 ancilla failures over
all 9,024 shots.

If an unreachable state ever occurred, `core[0]` would not be 0 and the dropped
bit would be lost. That would show up as ancilla garbage and a wrong
transcript. That is the same exposure as with the old encoder. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is measurement uncompute, but the commit contains no
measurement. It re-synthesises a reversible codec with fewer Toffoli: an exact
gate-level rewrite. Strength Reduction (or Dead-Code and Redundancy Elimination
→ an exact peephole) fits better. A "transcript codec" change-type would fit
best.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout bde4caa -- src/point_add`. The author built on
   `bde4caa`, not on the git parent `94927be` (jackylee0424). Diffing against
   the parent (277 lines) would wrongly show this commit reverting
   jackylee0424's early body notches and their prefilter changes, and adding
   back `a88c9a1`'s measured clears and `bde4caa`'s trim schedule, overflow
   clears, `F_CUT4` move and binder-notch code.
   `git diff --ignore-cr-at-eol bde4caa e321f72 -- src/point_add` is 51 lines
   in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol e321f72 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1302 qubits
   - 1,453,867 average Toffoli (rounded)
   - score 1,892,934,834
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=60009363210` and an
identical op stream. Any other change needs a new nonce hunt.

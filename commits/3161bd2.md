## Summary

In the Skywalk tree, `HEO_PIN_PP_WALK_MAX_QUBITS` is the cap that every
payload cell, rail split and fitted add sizes itself against. This commit
lowers it from 1174 to 1173, so the peak drops by one qubit. The same
contestant did this move in the ping-pong tree in [`a4b4125`](a4b4125.md).

To make the cells fit and keep the error in range, the commit also:

- replaces the per-proxy-round bridge profile with a per-cell table of 141
  bridge and room adjustments;
- lets the fitted split add shrink its last chunk (`SKY_SPLIT_TRIM_LAST`);
- buys error back by widening the early flag compares (`GO_FLAG 0-63:4`) and
  the terminal fold (40 → 42);
- sells error by narrowing the fitted-add window (`HEO_FIT_K` 21 → 19) and the
  width-19–24 fold band (−5 → −7);
- replaces the 61-row SAT rewrite table with 11 rows proved on the new
  stream.

The net cost is +794 Toffoli. Dropping one qubit saves 943,826 of score, and
794 more Toffoli at 1173 qubits cost 931,362, so the score falls by 12,464. The
author reports λ about 19.73, above the 19.5 limit in the Skywalk contract.

## What changed and why it saves qubits

### 1. Walk cap: `HEO_PIN_PP_WALK_MAX_QUBITS` 1174 → 1173 (`src/point_add/mod.rs`)

- `pingpong::walk_max_qubits()` returns this pin plus the cell pin
  `K3B_EXTRA_ROOM`. `h7::cap()` is the same value.
- The cell layouts (`chunk_layout`, `composition_bounds`, `chunked_add`),
  `ripple_add`'s bridge test, and the room-fitted adds in `modular.rs`
  (`heo_split_ripple`) all size against it. So one wire less of room
  everywhere is what brings the measured peak to 1173.
- With less room, some adds need one more chunk boundary, or one more bridge.
  Either costs Toffoli. That is most of the +794.

### 2. Per-cell bridge and room table (`heo_carry.rs`, new `cap1173_bridge_room_profile_v2.txt`)

New code in `k3b_cell`, the per-cell pin harness:
- It loads the compiled-in file (`include_str!`). Each line is
  `idx bridge room tick dir`.
- It asserts that cell `idx` (the order of cell calls in the build) really is
  `dir` tick `tick`.
- It sets the cell pin `K3B_BRIDGE` to `bridge` and adds `room` to the
  cell's `K3B_EXTRA_ROOM`.
- `bridge::enter` reads `K3B_BRIDGE` as relative to the profile when it
  starts with `+` or `-`. So `+n` means n more bridges than
  `HEO_PIN_I35_PROFILE` gives that proxy round.
- The existing per-cell overrides in `ovr_v025_lamneutral.txt` are applied
  first. For 11 cells that file set `K3B_BRIDGE` to +1, +2 or +3, and the new
  table overrides it with `+0`.

The 141 entries cover 69 division cells (ticks 228–391) and 72 multiply cells
(ticks 216–362):

| field | values |
| --- | --- |
| bridge | `+0` ×91, `+1` ×26, `+2` ×4, `+3` ×7, `-1` ×13 |
| room | +2 ×28, +1 ×54, 0 ×33, −1 ×26 |

What the room values do:
- A listed cell's cap is `1173 + ovr room + room`. Before, it was
  `1174 + ovr room`. So room +1 keeps the cell at its old cap, +2 gives it one
  more wire than before, 0 takes one away like every unlisted cell, and −1
  takes two away.
- I checked every entry with room > 0 against `ovr_v025_lamneutral.txt`. Each
  one sits on a cell whose existing override is at least that negative. So no
  cell's cap goes above 1173.

What the bridge values do:
- `-1` removes the one bridge the profile gives 12 late division cells
  (ticks 363–391, proxy rounds 644–698) and multiply tick 331 (proxy round
  591).
- `+1` to `+3` add bridges to multiply ticks 220 and 283–362 and division
  ticks 228–232 and 307–332. These are the same regions where sky17
  ([`284e2b0`](284e2b0.md)) and sky19 ([`f904fca`](f904fca.md)) had
  added bridges by proxy round.

### 3. `HEO_PIN_I35_PROFILE` reset to the sky16 profile

- The value goes back to the 35-entry profile of [`799153a`](799153a.md)
  (division rounds 600–698 and multiply rounds 591 and 620, one bridge
  each).
- That drops sky17's 28 multiply entries and sky19's 9 division entries. The
  per-cell table above now carries the bridge choices, cell by cell.

### 4. Fitted-add split: `SKY_SPLIT_TRIM_LAST = 1` (set in `build()`)

- `modular::heo_split_ripple` splits a wide exact add into `nk` chunks under
  the room. It first gives back any excess width from the leading chunks.
- If excess is left after that, it normally tries one more chunk.
- With this flag (commented "fallback only"), it can instead shrink the last
  chunk, "so a ladder whose addend fills the last cap still splits under the
  cap". The add then keeps its chunk count.
- dysnasia's later note on [`ed31e8e`](ed31e8e.md) says that without it "the
  build stays at 1,174 qubits".

### 5. Error trades

| knob | change | sites | direction |
| --- | --- | --- | --- |
| `GO_FLAG` (new, in `build()`) | `0-63:4`: +4 bits on `flag_compare` | proxy rounds 0–63 = ticks 0–35, both legs | buy |
| `TERMINAL_FW` | 40 → 42 | the two `terminal_pair` cells | buy, 2 bits each |
| `HEO_FIT_K` | 21 → 19 | every windowed boundary erase of the room-fitted adds | sell, 2 bits |
| `HEO_PIN_PP_FOLD_PROFILE` | band `19:-5` → `19:-7` | fold window of walk widths 19–24 (ticks 366–373), both legs | sell, 2 bits |

- `GO_FLAG` goes through `go_slice` into `flag_compare(round)`, which is the
  width of each cell's overflow-flag erase: `hmr`, then a top-k phase compare
  only on outcome 1. Four more bits cost about 2 executed Toffoli per cell,
  and cut that compare's tie error by about 16×.
- The submission note explains why the wider early compare is safe: "A high
  prefix that already differs preserves its ordering when lower bits are
  read."
- The tick ranges are my mapping through the proxy envelope and the pinned
  width schedule.

### 6. Rewrite rows: `sky20_rewrite.txt` (61 rows) → `q1173_exact_rows.txt` (11 rows)

- The `build()` block now loads an 11-row file and asserts there are exactly
  11 rows. It applies them at their fixed op indices: the unique-shift search
  is gone, and a mismatch panics ("Q1173_EXACT11 source mismatch").
- All 11 rows are in the square (ops 4,613,741–5,039,919). None names the
  same wires as a sky20 row.
- The submission note says each was "mapped and checked on this circuit's own
  operation stream" under "conservative facts derived from the preceding
  circuit". Ten replace a CCX with a short CX chain, and one with a 28-wire
  chain.
- Losing 50 rows costs about +50 Toffoli on every shot.
  `sky20_rewrite.txt` stays in the tree, unused. See
  [dead-gate-strip](../concepts/dead-gate-strip.md).

### 7. Other edits

- `K3B_CELL_TRACE=1` is set in `build()`. It only prints a `K3B_CELL` line per
  cell to stderr.
- The sky20 package comment is deleted. The sky20 pin values stay, except
  where listed above.
- 92 files under `src/point_add` change mode from 100644 to 100755, and their
  contents are unchanged.
- `TAIL_NONCE`: 20500217557371 → 281303256604719.

## Why it is still correct, and what it risks

- **The cap and the room table are exact.** They change only how much room
  each add is laid out in. Every add still computes the same sum. The peak of
  1173 is measured by the benchmark, not inferred.
- **Bridges are exact.** Each in-place stage restores its operand. Where the
  table changes the bridge count, it changes which chunk boundaries are
  repaired approximately.
- **The sells add error.**
  - `HEO_FIT_K` 19 makes each fitted boundary erase 4× as likely to tie. A
    wrong compare shows up as a **phase** failure.
  - The two extra fold bits on widths 19–24 make a dropped carry, and so a
    **classical** failure, more likely there. The `fold_shape` comment puts
    the escape rate at that width near 0.074 of the flat rate.
- **The buys remove error**: the early flag compares and the terminal fold.
- **The rows** were checked by the author. The build asserts only that each
  still names its CCX at its exact op index.
- **λ.** The submission note reports a pooled failure-batch mean of 19.727 ±
  0.255 over 256 nonces. That is above the 19.5 limit in the 8ee337c Skywalk
  contract, and the author says so. None of those 256 nonces was clean.
- The shipped nonce `281303256604719` draws a clean island: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The win is one qubit of peak, bought by refitting the cells under a lower cap
with per-cell in-place bridges and room. That is in-place mutation, the same
label as this contestant's 1250 → 1249 move [`a4b4125`](a4b4125.md). The
runner-up was ancilla-lifetime / venting, since the cap change itself only
re-budgets room.

   parent. `git diff --ignore-cr-at-eol d6dd7ef 3161bd2 -- src/point_add`
   lists 94 files. 90 of them change only their mode, and the content changes

   `git checkout 3161bd2 -- src/point_add/skywalk_data/cap1173_bridge_room_profile_v2.txt src/point_add/skywalk_data/q1173_exact_rows.txt`.
   They are the 141-entry per-cell bridge/room table and the 11 rewrite rows
   described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `heo_carry.rs` and `mod.rs`. The mode-only changes of
   the other files are left out, and they do not affect the build.
4. **Check the tree.** `git diff --ignore-cr-at-eol 3161bd2 -- src/point_add`
   should show no content changes (mode lines aside).
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `PP_*`, `TLM_*` and `SUB4_*` overrides have no effect. Do
   not set them anyway. Expect:
   - 1173 qubits
   - 944,620 average Toffoli (rounded)
   - score 1,108,039,260
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `281303256604719` and an identical op
stream.

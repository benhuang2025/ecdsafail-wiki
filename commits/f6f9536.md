## Summary

The dialog GCD runs a fixed number of steps, set by
`DIALOG_GCD_ACTIVE_ITERATIONS`. This commit lowers it from 260 to 258. Every
removed step takes away one step from each of the four GCD walk passes and,
much more expensively, one 256-bit apply step (a modular double or halve, a
controlled modular add or subtract, and a 256-wide controlled swap) from each
of the two apply passes. Two steps save 5,121 average Toffoli, about 2,560 per
step.

The cost is convergence. An input whose GCD needs more than 258 K=2 steps to
reach its terminal state is no longer finished, and its result is wrong. The
tail nonce was re-hunted so that the test draw contains no such input. Qubits
stay at 1285.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 260 → 258.**
   - `dialog_gcd_active_iterations()` (`rounds/dialog/config.rs`) sets the
     loop bound of every walk and apply pass, `for step in 0..iters`.
   - It also sets the transcript size:
     `dialog_gcd_compressed_sidecar_blocks() = ceil(iters / 2)` blocks of
     5 bits (the K2 pair compressor stores two steps per 5-bit block). So
     130 blocks become 129.
   - The last steps of the walk are cheap, because the active width has shrunk
     to a few bits by then (`256 − 1.015·step + 10`, so about 6 bits at step
     258). The apply steps are not: each one acts on the full 256-bit payload
     `y`. Per step, the forward apply does `dialog_gcd_fused_double_y`, a
     materialized controlled modular add and a 256-wire `cswap`, and the
     reverse apply does the mirror with a halve and a subtract. That is where
     most of the ~2,560 Toffoli per step comes from.
   - Other step-indexed tables are unaffected. The band size of
     `DIALOG_GCD_BODY_CARRY_BAND_TRIMS` is `ceil(iters/26)`, which is 10 for
     both 260 and 258. The per-step compare schedule has 258 entries already.
2. **`DIALOG_TAIL_NONCE`: 800002627594 → 1000005782829.**

**Why qubits do not move.** The transcript blocks are hosted on high lanes of
`u` (`DIALOG_GCD_COMPRESSED_LOG_U_HIGH_RUNWAY=1`, all blocks), which are free
once `u` has shrunk, so one block fewer does not lower a fresh allocation at
the 1285-qubit peak.

## Why it is still correct, and what it risks

Each step that runs is exact; what changes is how many run. A K=2 step removes
one or two factors of 2 and, when `v` is odd, a subtraction, so the bit length
of the pair shrinks by about one bit per step on average. Inputs that shrink
more slowly need more steps. With 258 steps, a few more inputs out of the
whole input space fail to reach `v = 0`, and the transcript then encodes a
wrong inverse. That shows up as a classical mismatch, usually with phase or
ancilla garbage as well, because the reverse walk does not return to the
starting state.

The shipped nonce `1000005782829` draws a test set in which every shot
converges in 258 steps: 9,024 of 9,024 shots, with 0 classical, 0 phase and
0 ancilla failures. The submission note calls the change "exact across all
9024 shots", which is true of this draw but not of every input. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is the iteration count of the GCD, which is the
definition of iteration/threshold tuning. The stacked zero-edge skip mentioned
in the submission note is already in the base `7822c37`.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 7822c37 -- src/point_add`.
   - Do not start from the git parent `ab5469b`. That tree has jackylee0424's
     extra binder notch at step 14 and nonce 39354. Diffing against the parent
     would wrongly show this commit removing `14:1` from
     `DIALOG_GCD_BINDER_NOTCH_MAP` and rewriting the nonce comment.
   - Against `7822c37`, `git diff --ignore-cr-at-eol 7822c37 f6f9536 -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f6f9536 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or `ROUND84_*` environment variables set, because they
   override the route defaults. Expect:
   - 1285 qubits
   - 1,376,005 average Toffoli (rounded)
   - score 1,768,166,425
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=1000005782829` and an
identical op stream. Any other change needs a new nonce hunt.

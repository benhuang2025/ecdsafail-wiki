## Summary

Sky9 worked on the GCD walk. Sky10 sells λ outside it, in the coordinate
shell, the square and the fitted adds. Four pinned windows each lose bits:

| knob | bits | what it is |
| --- | --- | --- |
| `HEO_FIT_K` | 23 → 22 | boundary-carry erase of exact adds that were split to fit under the qubit cap |
| `ERASE_COMPARE` | 25 → 22 | carry erase of every modular add/sub in the shell |
| `SQ_ASM_TAIL` | 19 → 18 | how far the square's cross-term add ripples its carry |
| `FOLD_GUARD` | 21 → 20 | headroom bits of every truncated constant fold and shifted add |

The SAT rewrite table is re-mined for the new stream, and it has 13 fewer
rows (65 → 52). The code comment again cites the 19.5 λ limit. The net is −92
Toffoli at 1174 qubits.

## What changed and why it saves Toffoli

All four knobs are pins in `install_skywalk_submission_recipe()`,
`src/point_add/mod.rs`. Every change makes a window narrower, so every change
is a sell.

1. **`HEO_FIT_K`: 23 → 22.**
   - It is read by `heo::fit_window()` when `HEO_FIT_MODE=win`, and used in
     `heo_split_ripple()` in `modular.rs`.
   - Under the HEO walk, `ripple_add_proved` (the tree's exact ripple adder)
     checks whether its `width − 1` carry wires fit in the free room under the
     1174-qubit cap. If they do not, it splits the add into chunks that each
     fit. Each chunk vents its carry-out onto a boundary wire, which the next
     chunk takes as carry-in.
   - In `win` mode, each boundary is erased right after the next chunk
     consumes it. The erase is `erase_with_compare`: `hmr`, then a
     phase-conditioned compare.
     - It compares over the whole chunk, exactly, with borrow-in, if the
       chunk starts at bit 0 and is at most K bits wide.
     - Otherwise it compares only the top `min(K, size)` bits.
   - This is the same rule as `HEO_SPLIT_K` uses for the rail adds (see
     [`4ea960f`](4ea960f.md)), but for the ordinary adds that run near the cap.
   - 23 → 22 removes one compare bit at every windowed boundary, about 0.5
     executed Toffoli each.
2. **`HEO_PIN_ERASE_COMPARE`: 25 → 22.**
   - `modular::erase_compare()` is the width of the measured carry erase in
     `mod_addsub_with` and its relatives in `modular.rs`, `classical.rs`,
     `j_fuse.rs` and `heo_carry.rs`.
   - The relatives include the fused `coord_y_sub` and the y-final erases
     `r4_ysub_head` / `r4_yfin_tail` that this recipe uses
     (`R4_YSUB_FUSE`, `R4_YFIN_FUSE`).
   - Each modular add or subtract leaves an overflow carry. The circuit
     measures it out with `hmr`. On outcome 1 it runs `cmp_lt_phase` on the
     top `k` bits of the accumulator and the addend:
     `erase_with_compare(overflow, acc[N-k..], value[N-k..], None)`.
   - Three fewer bits per call is about 1.5 executed Toffoli per modular
     add/sub. See [modular-fold](../concepts/modular-fold.md).
3. **`HEO_PIN_SQ_ASM_TAIL`: 19 → 18.**
   - In `add_cross()`, `square.rs`, the square's exact `2ab` cross term is
     added into an accumulator whose upper bits hold `b²`.
   - With `SQ_ASM_TAIL = E`, the add's accumulator is cut to `cross.len() + E`
     bits, so the carry ripples only E bits past the cross word.
   - The code comment says those upper bits are random, so a carry reaches E
     bits in with probability about 2^-E. One bit shorter saves about one
     Toffoli per cross-term add, and that Toffoli runs on every shot. See
     [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).
4. **`HEO_PIN_FOLD_GUARD`: 21 → 20.**
   - `fold_guard()` is the headroom of every truncated fold in the tree.
   - `f_slice() = 33 + fold_guard()` is the slice width for a fold of the
     33-bit constant `f = 2^32 + 977`. `go_fs(key)` adds a per-site offset,
     and no `GO_FG_*` offset is set in this recipe.
   - The square's `window_add` uses `top = shift + len + fold_guard()`.
   - The sites are the shell's `+f` fold in `mod_addsub_with`
     (`cadd_const_trunc(&acc[..fs], f, overflow)`), the ping-pong cell
     fold steps reached through `GO_FG_P` / `GO_FG_PR` / `GO_FG_R1`, and the
     square's shifted window adds.
   - A carry that escapes the top of the slice is dropped, so the error is
     about 2^-guard per call. One bit narrower saves roughly one Toffoli per
     fold site, because each slice bit carries one controlled-constant or
     ripple stage.
   - The comment above `ERASE_COMPARE` ties the two knobs together by a
     "balance rule", so the author moved them together.
5. **SAT rewrite rows: `sky9_rewrite.txt` (65 rows) → `sky10_rewrite.txt` (52
   rows).**
   - The comment calls them "52 square rows re-proved by SAT on the sky10 op
     stream".
   - Comparing the files, 9 of the new rows name the same wires as a sky9
     row, at scattered index shifts. The rest are new.
   - The loader is unchanged. It needs one global shift under which every row
     names its CCX. See [dead-gate-strip](../concepts/dead-gate-strip.md).
   - 13 fewer rows costs about 13 Toffoli, which is part of the net −92.
   - `sky9_rewrite.txt` stays in the tree, unused.
6. **Tail nonce**: `TAIL_NONCE` goes from 9000851329353 to 10002233751843.

## Why it is still correct, and what it risks

All four cuts are probabilistic:

- **The FIT_K and ERASE_COMPARE erases** are wrong when the compared top
  bits tie, about 2^-22 per site. That leaves a wrong phase, so it shows up as
  a **phase** failure.
- **The SQ_ASM_TAIL cut and the FOLD_GUARD slices** drop a carry that would
  have escaped. That leaves a wrong value, so it shows up as a **classical**
  failure, or as ancilla garbage when the inverse fails to clean up.

The rewrite rows are exact on reachable states if their proofs hold. The
build checks only that each row still names its CCX.

The comment states the 19.5 λ limit. The shipped nonce `10002233751843` draws
a clean island: 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

All four levers narrow a compare or a carry window: comparator/width
truncation. The biggest single cut is the 3-bit `ERASE_COMPARE` cut. The new
rewrite table is a small, partly negative side effect, not the lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout bdff8c8 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol bdff8c8 f260d33 -- src/point_add` is
   68 lines in 2 files.
2. **Copy the new rewrite table from the commit:**
   `git checkout f260d33 -- src/point_add/skywalk_data/sky10_rewrite.txt`.
   It holds the 52 SAT rows described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `mod.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol f260d33 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `PP_*` and `SUB4_*` overrides have no effect. Do not set
   them anyway. Expect:
   - 1174 qubits
   - 944,811 average Toffoli (rounded)
   - score 1,109,208,114
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `10002233751843` and an identical op
stream. Any other change needs a new nonce hunt and re-keyed rewrite rows.

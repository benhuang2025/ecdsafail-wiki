## Summary

Every step of the dialog-GCD walk (background in [8316db1](8316db1.md) and
[8e13587](8e13587.md); see [dialog-gcd-early](../concepts/dialog-gcd-early.md)) decides its branch
with a truncated comparison `u > v` on the top few bits of the active window.
The number of bits is a baked per-step schedule, capped by the global limit
`DIALOG_GCD_COMPARE_BITS`. This commit lowers the cap from 49 to 48. Only the
36 steps whose schedule entry (and active width) is 49 or more are affected.
Each loses one comparator bit, which is one Toffoli. Four walks run the
comparator, so the saving is 4 × 36 = 144 Toffoli, exactly the measured drop.
Qubits are unchanged. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_COMPARE_BITS`: 49 → 48.**
   - Read by `dialog_gcd_compare_bits()` in `rounds/dialog/config.rs`. On this
     route `DIALOG_GCD_PA9024_COMPARE_SCHEDULE=1` with margin 0 and floor 1, so
     `dialog_gcd_compare_bits_for_step(step, active_width)` returns
     `min(SCHEDULE[step], DIALOG_GCD_COMPARE_BITS, active_width)`.
   - `DIALOG_GCD_PA9024_COMPARE_SCHEDULE` is a baked 258-entry table: the
     largest comparator width any of 8 million sampled GCD inputs needed at
     that step. Its values run from 5 to 55.
   - The route walks `DIALOG_GCD_ACTIVE_ITERATIONS=258` steps with
     `active_width(step) = ceil((256 − 1.014·step + 10) / 2)·2`
     (`dialog_gcd_tobitvector_active_width`, slope 1014/1000, margin 10).
     Exactly 36 steps have `min(SCHEDULE[step], active_width) ≥ 49`: steps 135,
     140, 145, 162, 173, 177, 179, 182, 183, 185, 186 and 190–214. On those
     steps the comparator goes from 49 to 48 bits. All other steps are
     unchanged.
   - The comparator is the fused form (`DIALOG_GCD_FUSED_BRANCH_BITS=1`) that
     writes `b0 AND (u > v)` straight into the log bit. It compares only the
     top `k` bits of the active window, at about one Toffoli per bit, with its
     carries erased by measurement.
   - The forward and the reverse walk of both dialog-GCD divisions run it once
     per step: 36 × 4 = 144 Toffoli.
2. **`DIALOG_TAIL_NONCE`: 812502068 → 1401613145**, the identity tail that
   reseeds the 9,024 test inputs.

## Why it is still correct, and what it risks

The truncated comparator is approximate. When `u` and `v` agree on all `k`
compared bits, it can report the wrong order. The walk then takes the wrong
branch, and that input does not reach its terminal state. The schedule entries
of 49 and above are measured maxima, so on those 36 steps a few sampled inputs
really needed 49 bits or more. Capping them at 48 makes those rare inputs
fail, and λ goes up slightly.

A wrong branch shows up as a classical mismatch (wrong output point) and
usually as ancilla garbage, because the reverse walk no longer restores `u`
and `v`. An audit note shipped in the tree
(`memory/2026-06-06-tony-anton-audit-loop.md`) records that `48` had failed to
find a clean nonce on earlier 1309-qubit trees. On this tree nonce
`1401613145` draws a test set with 0 classical, 0 phase and 0 ancilla failures
over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a comparator, so comparator/width truncation
fits. The nonce change comes with every circuit change and is not a separate
lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout c8f4536 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol c8f4536 8925623 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8925623 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1307 qubits
   - 1,484,125 average Toffoli (rounded)
   - score 1,939,751,375
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=1401613145` and an identical
op stream. Any other change needs a new nonce hunt.

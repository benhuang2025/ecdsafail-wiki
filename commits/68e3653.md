## Summary

The base circuit peaked at 1698 qubits in two places, and both had a
256-wide block of scratch on top of the long-lived registers. In the GCD
walk, the controlled subtract materialized a `gated = ctrl AND u` register of
up to 256 fresh qubits. In the apply pass, the controlled modular add/sub ran a
257-bit measured-carry adder whose 256 carry wires were live at the same time
as its 256-bit materialized addend `f`.

This commit removes both. It turns on an existing switch, `DIALOG_GCD_HOST_GATED`,
which places the walk's `gated` register on compressed-log slots that are
still guaranteed to be |0⟩. It also adds a *windowed* measured adder that
splits the 257-bit addition into two halves of about 128 bits and passes the
carry between them on one extra wire. Only about 130 carry wires are then live
at once instead of 256, so the peak drops by 126 to 1572. The cost is a
128-bit comparator per apply call, which clears the boundary carry. There are
798 such calls, so Toffoli rises by 798 × 128 = 102,144. A qubit is worth
about 1,100 Toffoli of score here, so the trade wins 1.75%.

## What changed and why it saves qubits

Background on the walk, apply pass and compressed log is in
[8316db1](8316db1.md). In short: the two GCD uses (`quotient`, `ipmul`) each
run forward walk → apply pass → reverse walk. The 399-step transcript lives in
`compressed_log`, 133 blocks × 5 qubits = 665 qubits. During the walk, the
blocks for later steps are still |0⟩.

### 1. `DIALOG_GCD_HOST_GATED = 1` (walk peak)

This switch already existed in the base; the commit turns it on in
`configure_ecdsafail_submission_route()`.

- In `dialog_gcd_controlled_sub_selected` / `_add_selected`, the controlled
  `v -= b0·u` first writes `gated[i] = b0 AND u[i]` (one CCX per bit), then
  subtracts `gated` from `v`, then clears `gated` by `hmr` + `cz_if` (no
  Toffoli). The adder's own carries already sit on future-log slots
  (`DIALOG_GCD_RAW_TOBITVECTOR_BORROW_FUTURE_LOG_CARRIES`, on in the base).
- With the switch on, `dialog_gcd_compressed_sidecar_future_carry_slice` asks
  for `2n − 1` future slots instead of `n − 1`. The first `n − 1` host the
  carries and the next `n` host `gated`. When fewer slots are left (the last
  blocks, where `n` is small), `gated` falls back to fresh qubits.
- Both uses leave the slots at |0⟩, so the future blocks that own them are
  unaffected. In the forward walk the future blocks have not been written yet.
  In the reverse walk, blocks are undone from last to first, so the "future"
  blocks have already been emptied.
- This removes up to 256 fresh qubits from the walk's high-water mark.

### 2. `DIALOG_GCD_APPLY_WINDOW_BLOCKS = 2` (apply peak)

New function `cuccaro_add_fast_windowed(b, a, acc, c_in, blocks)` and its
mirror `cuccaro_sub_fast_windowed`, both in `mod.rs`. They are used in
`dialog_gcd_cmod_add_materialized_pseudomersenne` (raw sum) and
`dialog_gcd_cmod_sub_materialized_pseudomersenne` (raw difference) when the new
`dialog_gcd_apply_window_blocks()` returns `Some(w)` with `w ≥ 2`.

- `cuccaro_add_fast(a, acc, c_in)` allocates `n − 1` carry wires, computes
  them with one CCX each, and erases them by measurement on the way back. For
  the 257-bit `f_ext`/`acc_ext` this is 256 live carries.
- The windowed version cuts the operands at `hi = (blk+1)·n/blocks`. For
  `n = 257`, `blocks = 2`, the cut is at bit 128.
  - Block 0 runs `cuccaro_add_fast` on bits 0..128 extended by one bit: a
    fresh |0⟩ on the `a` side and a fresh `cout` on the `acc` side. That top
    sum bit is the carry out of block 0.
  - Block 1 runs `cuccaro_add_fast` on bits 128..257 with `cout` as its
    `c_in`. `cuccaro_add_fast` restores `c_in`, so `cout` is still live
    afterwards.
  - The boundary carry is then cleared by recomputing it:
    `cout = [acc_final[0..128] < a[0..128]]`, using `cmp_lt_into_fast`. This
    is exact, because the carry out of a `p`-bit addition is 1 exactly when the
    low `p` bits of the sum are smaller than the addend's.
  - For subtraction the borrow is cleared with
    `[~a[0..p] < acc_final[0..p]]`, with `a` complemented in place by `X`
    gates and restored afterwards.
- Peak scratch: block 0 needs 128 carries + `cout` + the zero bit (130). The
  boundary clear needs 128 + 1 comparator wires + `cout` (130). Before, the
  adder needed 256. That is the −126.
- Toffoli: the two blocks cost 128 + 128 = 256 CCX, the same as the single
  257-bit adder. The boundary comparator adds 128. The apply pass calls one
  materialized add or sub per step, 399 steps × 2 apply passes = 798 calls, so
  the total is +102,144. That is exactly the measured rise.
- A self-test, `mbuc_windowed_add_selftest()`, simulates both adders for 64-bit
  operands and block counts 1–64. It checks the sum, that `a` is restored, that
  `c_in` is cleared, and that no phase is left. The build does not call it.

### 3. `DIALOG_REROLL` 12 → 41

This is the number of identity `X;X` pairs at the start of `build()`. It
picks a new clean 9,024-input draw for the new op stream.

The commit keeps the base's `COMPARE_SCHEDULE_MARGIN = 8` and
`WIDTH_MARGIN = 28`. It does not include mpjunior92's tightenings from the
same morning ([412312f](412312f.md), [4b68e94](4b68e94.md)).

## Why it is still correct, and what it risks

Both changes are exact:
- The hosted `gated` register only uses slots that are provably |0⟩, and it
  returns them to |0⟩.
- The windowed adder computes the same sum. Its boundary carry is cleared with
  an exact identity and a full-width (128-bit) comparator, not a truncated one.

Neither change adds a failure mode. The circuit's existing approximations (the
width envelope, the comparator schedule, and the truncated fold and clean
windows) are unchanged. The new reroll still had to be found, because the op
stream changed and the old draw is gone. The shipped reroll 41 draws 0
classical, 0 phase and 0 ancilla failures. If the hosted slots were not clean,
the result would be ancilla garbage on the later log blocks. A wrong boundary
clear would show as phase garbage.

The code comment says the boundary clear uses "the non-fast (no-carry-lane)
comparator". It actually calls `cmp_lt_into_fast`, which allocates 129 carry
wires. That is still within the 130-wire window, so the peak is unaffected.

## Classification rationale

Both levers shorten how long scratch wires are held at the peak: one parks a
register on idle wires, the other splits a carry lane in time. That is
ancilla-lifetime / venting. The runner-up would be an adder change
(windowed adder), but the adder computes the same thing at the same Toffoli
cost. Only the boundary bookkeeping is new, and it exists only to save
qubits.

## Summary

[`6c0769f`](6c0769f.md) had switched the `x2 += 3·ox` coordinate step to its
original quantum form. That form takes four modular folds: add `ox`, double
it, add again, halve it back. This commit switches the shell back to the
classical form, `coord_add3x`.

`ox` is a classical input, so `3·ox mod q` is computed with free classical-bit
ops, and the circuit does one exact modular add of that value. 6c0769f had
already added a call-index shim to the classical form: it advances the `+f`
call counter by 3, so the per-call reserve overrides still line up with the
calls that follow.

The op stream changes, so the positional dead-CCX list is regenerated for it,
with 14,498 entries instead of 14,361. The net saving is 278 average Toffoli
at 1156 qubits.

## What changed and why it saves Toffoli

1. **`src/point_add/trailmix_ludicrous/ec_add.rs`, `ec_add`** (phase
   `tlm_coord_add3x`): `coord_add3x_orig(circ, x2, ox)` → `coord_add3x(circ, x2, ox)`.
   - `coord_add3x_orig` loads `ox` into a 257-qubit temp, then runs
     `mod_add`, `mod_double`, `mod_add` and `mod_double_reverse`. That is two
     256-bit modular adds and two `+f` doubling windows on the quantum side.
   - `coord_add3x` instead runs `classical_times3_mod_q(ox)`:
     - classical ripple adds on `BitId`s give `3·ox` (258 bits);
     - the high part is folded with `C = 2^32 + 977`;
     - one conditional subtract of `q` follows.
   - Every op there is `BitStore0`, `BitStore1` or `BitInvert`, which cost no
     Toffoli and no Clifford in the scorer
     ([scoring-and-validation](../concepts/scoring-and-validation.md)).
   - It then loads the result into a 256-qubit temp with `x_if_bit` and does
     one `mod_add_exact`: a vented add, one `+f` window, and a full-width (not
     truncated) overflow compare-erase. Then it unloads the temp.
   - The code comment estimates about 754 emitted Toffoli for the old form and
     326 for the new.
   - At its end, `coord_add3x` calls `arith::advance_ffg_call_index(3)`, which
     was added in 6c0769f. The classical form makes one `add_f_window` call,
     where the quantum form makes four. Advancing the counter by 3 keeps every
     later call's index, and so its `TLM_TARGET_FFG_CALL_RESERVE_OVERRIDES`
     entry, the same as in the quantum form.
2. **New data file `src/point_add/dead_k1_coord3x.idx`** (generated). It has an
   `idx` header, then 14,498 positions from 4,762 to 10,140,209. These are the
   never-firing CCX of this stream, screened with the drop disabled over about
   9 M inputs, per the author's note. The old `dead_k1_nocoord3x.idx` is
   deleted. See [dead-gate-strip](../concepts/dead-gate-strip.md).
3. **`src/point_add/mod.rs`, `build()`.**
   - The drop block's `include_str!` now points at `dead_k1_coord3x.idx`.
   - `DIALOG_TAIL_NONCE` goes from 9500055003049 to 100118751586.

## Why it is still correct, and what it risks

- **The classical `3·ox` is exact.** `classical_times3_mod_q` returns
  `3·ox mod q` in `[0, q)`, and `mod_add_exact` uses a full-width compare, so
  the overflow flag is erased correctly on every input. The quantum form used
  two truncated compares and four `+f` windows (one per add, one per doubling
  or halving), against one window now, so this step now has fewer
  approximations.
- **The new list is empirical and positional**, like every list in this
  lineage. An unscreened input that fires a dropped gate becomes a hard input.
  That would be a classical failure, or a phase failure inside a recompute.
- The tail skips of [`cde752d`](cde752d.md) and the K1 add skip of
  [`6c0769f`](6c0769f.md) are unchanged.
- The shipped nonce `100118751586` was hunted with the drop on. It draws a
  clean set: 9,024 of 9,024 shots, with 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as dead-gate removal because of the regenerated list.
But the list only follows the circuit change. The real lever is moving a
classical-input computation into the free classical-bit domain. Most of the
change against the base is that step. The diff suggests
Constant Propagation and Classical Specialization → host-derived / classical
specialization as the better label.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 6c0769f -- src/point_add`.
   - This note uses the git parent `6c0769f`, not the precomputed base
     `cde752d`. Against `cde752d` the line count is smaller (14,602 lines,
     against 28,867), only because the parent's 14,362-line index file is
     deleted here.
   - A `cde752d`-based patch would mix in all of 6c0769f's own work: the drop
     block, the K1 add skip and the call-index shim.
   - Against `6c0769f`, the source diff is 6 lines in 2 files, plus the index
     swap.
2. **Copy the generated index list from the commit:**
   `git checkout 27d4627 -- src/point_add/dead_k1_coord3x.idx`.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It covers
   `mod.rs` and `ec_add.rs`. The `rm` line above it removes the old list.
4. **Check the tree.** `git diff --ignore-cr-at-eol 27d4627 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*`, `CONSTPROP_*`, `SINGLE_CCX_FANOUT_*` or
   `DROP_DEAD_*` environment variables set. Expect:
   - 1156 qubits
   - 1,365,960 average Toffoli (rounded)
   - score 1,579,049,760
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `100118751586` and an identical op
stream. Any other change needs a new nonce hunt and a regenerated list.

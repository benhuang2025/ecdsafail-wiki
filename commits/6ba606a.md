## Summary

This is a qubit trade. The trailmix circuit sizes most of its carry ancillas
from the live headroom under a target width, `TLM_TARGET_Q`. The commit lowers
that target from 1159 to 1157. Every adder, `+f` window and fold then uses up
to two fewer clean, measurement-vented carries wherever the headroom is the
binding limit. Those carries fall back to the costlier in-place path. That
costs Toffoli, but the peak drops by 2.

To make every local peak fit under 1157, the commit also:
- re-tunes the per-call reserves of the `+f` windows and the fused folds;
- stops holding the zero carry-in wire of the chunked fold through the whole
  fold;
- drops a forced conservative layout for one cout adder.

To win back some Toffoli, it skips the controlled swap in the last
inverse-apply step. In the last GCD step that swap is the identity on every
input the circuit gets right, so this saves 256 Toffoli.

The net is +2,254 Toffoli and −2 qubits. That lowers the score by 149,394,
because 2/1159 of the score (about 2.76 M) is more than 2,254 × 1157 (about
2.61 M).

## What changed and why it lowers qubits

All the defaults are `set_default_env` lines in `build()`, `src/point_add/mod.rs`.

1. **Width target `TLM_TARGET_Q` 1159 → 1157.**
   - `target_qubit_headroom(circ) = TLM_TARGET_Q − active_qubits`.
   - That headroom caps the clean-vent count of the Gidney hybrid adders
     (`vents = min(schedule, headroom)` in `gidney.rs`) and the cout adder's `k`.
     It also sets `g = headroom − reserve` for each `+f` window
     (`add_f_window`, `arith.rs`) and `nv = min(code, headroom − reserve)` for
     each fused fold (`fused_fold`, `fused.rs`).
   - A clean vented carry costs 1 CCX, plus a free `hmr` erase. A carry that has
     to go in place costs about 2 CCX. So two less headroom means more Toffoli
     in the calls near the peak. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md) and
     [adders-and-carries](../concepts/adders-and-carries.md).
2. **Per-call `+f` reserve fits** (`arith.rs`, `add_f_window`).
   - Two new env maps are read after the existing reserve logic.
     `TLM_TARGET_FFG_CALL_RESERVE_DELTAS` (`call:delta`) adds to the reserve.
     `TLM_TARGET_FFG_CALL_RESERVE_OVERRIDES` (`call:value`) replaces it.
   - The reserve is the number of wires left free for the window's own
     temporaries beyond its `g` carries. A larger reserve means fewer clean
     carries in that call.
   - Defaults are baked for calls 184–356 (deltas +1 to +3) and calls 364–458
     (overrides falling from 8 to 1). The existing `TLM_TARGET_FFG_CALL_RESERVES`
     map for calls 163–600 is unchanged.
3. **Per-call fold reserves** (`TLM_TARGET_FOLD_CALL_RESERVES`).
   - Several entries go up: calls 179, 181–184, 186, 327, 329–332 and 334 go from 0 to 3,
     and 337 goes from 1 to 3. New entries are added: 250:4, 263:3.
   - Several go down: 336, 338 and 340 go from 2 to 1.
   - These are the reserves for `nv` in the fused double/cdouble folds of the
     apply steps.
4. **Lazy fold carry-in** (`fused.rs`, `add_mf_fold_chunked`, switch
   `TLM_FOLD_CHUNK_LAZY_CIN0=1`).
   - The chunked fold's first chunk has carry-in 0. The base allocated a |0⟩
     wire `cin0` for it at the start and freed it only after the last
     boundary erase. So the wire was held live through every chunk.
   - Now the forward pass passes `cin = None` to `fold_chunk_clean`. Its bit-0
     cell becomes a single `ccx(ctl, y0 → carry)`, which is the same Toffoli as
     before with a known-zero carry-in.
   - Only the j = 0 boundary erase allocates a fresh |0⟩ `cin` and frees it
     right after. One wire fewer is live across the fold. See
     [venting-and-wire-loans](../concepts/venting-and-wire-loans.md).
5. **`TLM_COUT_LAYOUT_FORCE_M1_KS` "129" → ""** (`gidney.rs`,
   `searched_cout_layout`). The base forced margin 1 for cout adders whose
   budget was `k = 129`, which keeps one ancilla unused. With the empty list,
   every cout layout uses margin 0 (`TLM_COUT_LAYOUT_MARGIN=0`). The headroom
   cap from item 1 now keeps those calls under the target.
6. **Skip the cswap in the last inverse-apply step** (`gcd.rs`,
   `apply_step_reverse`, switch `TLM_APPLY_INV_FIRST_CSWAP_SKIP=1`).
   - The inverse direction (`tlm_inverse`, `y ← y·x⁻¹`) runs the apply inside
     `forward_gcd_jump` for `i = 0 … ITERS−1`. The step `i + 1 == ITERS` is the
     last one executed, even though the knob says "first". Its 256 `cswap(swp, x, y)` are
     now skipped. That is 256 CCX, since one `cswap` is `cx; ccx; cx`.
   - At `i = ITERS−1` the swap flag is `swp = subtracted AND (v < u)`. For the
     GCD to end at `v = 0`, the last step must either not subtract (then
     `swp = 0`) or subtract `v = u = 1` (then `v < u` is false). So `swp = 1`
     there only on an input whose GCD has not converged. The base circuit
     already gets that input wrong.
   - This mirrors BitWonka's forward-side skip in [`5c34dd1`](5c34dd1.md).
     That one is exact for a different reason: there `y = 0` at the start.
7. **New knobs that stay off.** These parse new env vars that `build()` does
   not set, so they emit nothing:
   - `TLM_APPLY_FWD_LAST_CSWAP_SKIP`, `TLM_APPLY_INV_LAST_CSWAP_SKIP` and
     `TLM_APPLY_INV_FIRST_SUB_SKIP` (`gcd.rs`);
   - `TLM_GAP_J2_DELTA`, `TLM_GAP_J2_INDEX_DELTAS` and
     `TLM_GAP_J2_INDEX_OVERRIDES` (`gap_j2_eff`, which now computes the
     swap-decision window in both GCD passes but returns `GAP_J2[i]` unchanged
     by default);
   - `TLM_FOLD_CALL_CODE_OVERRIDES` (`fused.rs`).
8. **Nonce:** `DIALOG_TAIL_NONCE` 200003194569 → 4585414.

## Why it is still correct, and what it risks

- Items 1–5 only change how many clean ancillas each carry chain gets. A carry
  that loses its ancilla goes back to the in-place reversible path, which is
  exact. The lazy carry-in is exact because the wire was always |0⟩. Item 6 is
  exact on every input the base circuit gets right, as argued above.
- A per-call reserve set too low could push a local peak above 1157. That
  would raise the reported qubit count, not cause a validation failure.
  The commit reaches 1157, so every call fits.
- The circuit stays approximate in the same ways as the base: the baked GCD
  widths, the truncated comparators and the dropped `+f` carries. The
  author's note says a random nonce on this route gave 7 classical and 5 phase
  failures. The shipped nonce `4585414` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as dead-gate/self-inverse removal. That describes only
item 6, the 256-Toffoli cswap skip. The score gain comes from the 2-qubit
peak cut, which costs Toffoli overall: a lower width target plus re-fitted
per-call ancilla reserves and one shorter wire lifetime. The diff suggests
Register and Scratch Allocation → ancilla-lifetime / venting (or a peak/width
trim) instead.

   and run `git checkout f6ce76d -- src/point_add`.

     `TLM_FOLD_DELTA` from 2 to 3. This commit was built on `f6ce76d` and

     is 181 lines in 4 files.

   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 6ba606a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1157 qubits
   - 1,380,890 average Toffoli (1,380,889.850 before rounding)
   - score 1,597,689,730
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `4585414` and an identical op stream.
Any other change needs a new nonce hunt.

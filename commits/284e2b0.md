## Summary

Sky17 changes one pin, `HEO_PIN_I35_PROFILE`, the per-cell budget of in-place
carry "bridges". It adds 28 entries, all on the multiply leg, keyed by proxy
round 501–698. Through the proxy envelope these cover the multiply cells at
ticks 278–391. A bridge keeps a carry inside an operand wire instead of on a
wire of its own: one extra CCX for one fewer carry wire. A cell with a bridge
budget of b sizes its chunked 256-bit add as if it had b more free wires than
the 1174 cap leaves. Its chunks can then be wider, so it needs fewer
approximate chunk boundaries, each with a measured erase and a top-k phase
compare. The chunk adds that come up short of wires borrow them as bridges.

Peak qubits do not change. The net is −149 Toffoli. The author reports
λ 19.203 against 19.143 for sky16. The SAT rewrite table carries over
unchanged, because the change only touches the multiply leg, which comes after
the square in the op stream.

## What changed and why it saves Toffoli

### `HEO_PIN_I35_PROFILE` (`install_skywalk_submission_recipe()`, `src/point_add/mod.rs`)

**How the profile is read** (`bridge.rs`, unchanged):
- Each entry is `round:leg:count`. Leg 0 is the division cell and leg 1 the
  multiply cell, and count is the bridge budget, at most 32.
- `replay_add_halve` (division) and `replay_double_add` (multiply) call
  `bridge::enter(round, multiply)` before running the cell. In the Skywalk
  tree `round` is the cell's **proxy round**,
  `h7::proxy_round(cell_proxy_w(cfg, t))`. That is the first ping-pong round
  whose pinned schedule width is at or below the tick's width in the proxy
  envelope `env_front07_R393_clamp.txt`. The `pingpong.rs` comment says
  "Round-INDEXED tables (`PP_FOLD_WIDEN` level, `I35_PROFILE` bridges) follow
  the proxy too".
- A round missing from the profile gets `I35_BUDGET`, which is 0. A
  `K3B_BRIDGE` cell pin can override the value.

**What a budget of b does inside the cell:**
- The chunk-layout code in `pingpong.rs` (`composition_bounds`,
  `chunked_add`, `loaned_chunk_bounds`, the drop-exact-lead path) sizes the
  layout with `room + bridge::budget()`. `chunk_layout` then picks the layout
  with the fewest approximate boundaries that fits that ladder.
- When a chunk's add runs, `ripple_add` / `ripple_add_consume` in
  `modular.rs` compute `missing = live + owned carries − walk_max_qubits()`.
  If `0 < missing ≤ budget`, they call `bridge::add` / `bridge::run` with
  `missing` in-place stages at the top of the carry ladder.
- A bridge stage is one Cuccaro step:
  `cx(a,b); cx(a,p); ccx(b,p,a)`, undone later by a second `ccx`. The file
  header says: "Each in-place stage trades one extra CCX for one fewer owned
  carry wire". An ordinary stage computes its carry with one CCX onto an
  owned wire and erases it with `hmr` + `cz_if`, which costs no Toffoli.
- So a bridge costs one extra CCX per stage. A boundary it removes saves that
  boundary's vented carry, its measured erase and the seeded top-k compare
  (about 0.5 executed Toffoli per compare bit), plus that compare's tie error.
  See [adders-and-carries](../concepts/adders-and-carries.md) and
  [venting-and-wire-loans](../concepts/venting-and-wire-loans.md).

That is about 46 multiply cells. On the multiply leg, ticks 278–369 run in
the fused walk-back and ticks 370–391 in the trailing batch (see
[`799153a`](799153a.md) for the schedule). The last multiply cell (tick 391)
is replaced by `terminal_pair`, so the entry for round 698 reaches only tick
390 of the multiply cells there.

The commit comment calls the change "bridge-width sells and buys priced on
paired CRN nonces". In the code every entry only raises a budget from 0, so
"sells" can only mean cells where the new layout ends up with more error. The
diff does not show how each cell's layout changes. That depends on each cell's
live count. The submission note gives the measured package effect: mean T
−154.5 on its paired nonces (−149 on the official draw).

## Why it is still correct, and what it risks

- **Bridges are exact.** A bridge stage computes the same carry as an owned
  carry wire and restores the operand wire on the way back. Only the cost
  changes.
- **The layout change moves approximations.** Fewer chunk boundaries means
  fewer approximate top-k repairs, but a different layout can put boundaries
  and compare windows in different places. A wrong boundary repair leaves a
  wrong phase, which shows up as a **phase** failure.
- The author measured λ 19.203 ± 0.032 on 16,384 nonces (est + 2 SE 19.267),
  up 0.060 on sky16, inside the 19.5 limit that the code comment cites.
- The 62 rewrite rows are exact for the reason above.
- The shipped nonce `17001330283497` draws a clean island: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only lever is the I35 bridge profile: in-place Cuccaro stages that keep a
carry inside an operand wire. That is in-place mutation, like
[`8bba91b`](8bba91b.md), which moved the same profile in the ping-pong tree.
The runner-up was ancilla-lifetime / venting, since the bridges are spent to
remove vented chunk boundaries.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 799153a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 799153a 284e2b0 -- src/point_add` is
   the `mod.rs` diff below. The raw diff also lists `sky16_rewrite.txt`, but
   only for its line endings.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol 284e2b0 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `PP_*`, `TLM_*` and `SUB4_*` overrides have no effect. Do
   not set them anyway. Expect:
   - 1174 qubits
   - 943,975 average Toffoli (rounded)
   - score 1,108,226,650
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `17001330283497` and an identical op
stream.

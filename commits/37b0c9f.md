## Summary

Each cell of the ping-pong coefficient replay computes
`target ← (target ± source)/2 mod p`. Before halving, it adds one of
`{−f, 0, +f, +2f}` (with `p = 2^256 − f`, `f = 2^32 + 977`) to make the sum
even and to fold back any overflow past bit 256. That small add is done only
on the low `W` bits of `target`, and any carry out of the top of that window
is dropped.

This commit makes the window 55 bits instead of 56. The fold's ripple-carry
chain gets one position shorter, which is one Toffoli less on every shot, in
each of about 1,400 replay cells. That saves 1,393 average Toffoli at 1320
qubits. The cost is that a carry escaping the window is about twice as
likely as before.

## What changed and why it saves Toffoli

1. **`replay_fold_window()`** in `src/point_add/pingpong_div.rs`: the default
   of `SUB4_PP_REPLAY_FOLD_WINDOW` goes from 56 to 55.
   - **The add-and-halve cell** (`signed_mod_add_pm_halve_fused`, divide
     replay) and **the double-and-add cell**
     (`signed_mod_double_add_pm_fused`, multiply replay) both call
     `fused_fold_maskfree(b, &target[..replay_fold_window()], f, &negative_f, plus_f, plus_2f, minus_f, …)`,
     with `negative_f = twos_complement_bits(f, replay_fold_window())`.
   - `fused_fold_maskfree` adds the one selected member of
     `{−f, 0, +f, +2f}` into the slice without building an operand register.
     A single roving wire carries the per-position XOR of the three selector
     bits. It allocates `width − 2` carries: each is computed with one CCX
     and erased with `hmr` plus `cz_if`, at no Toffoli cost. So one window
     bit is one CCX per cell, executed on every shot, and one fewer carry
     ancilla while the fold runs. See
     [modular-fold](../concepts/modular-fold.md) and
     [measurement-uncompute](../concepts/measurement-uncompute.md).
   - **`fused_lift_round0_reverse_sparse`** uses `replay_fold_window() − 2`
     as its truncation, so it also gets one position shorter.
   - Each point addition runs two replays (divide and multiply) of about 702
     fused cells each, so the expected saving is about 1,400 Toffoli. The
     measured saving is 1,393.
2. **Tail nonce** (`src/point_add/mod.rs`): the default
   `SUB4_PINGPONG_TAIL_NONCE` goes from 40561 to 20026.

The flag compare stays at 25 bits, as in the base. The git parent
`e5c53dc` had narrowed it to 24, but this commit was built on `6ee4d14` and
does not include that.

## Why it is still correct, and what it risks

- **The fold is truncated, so it is probabilistic.** The selected correction
  is at most `2f < 2^34`. A carry, or for `−f` a borrow, leaves a 55-bit
  window only if the target's bits from about 34 up to 54 are all 1, or all
  0. For random data that is about `2^(34−55) ≈ 2^−21` per call, double the
  rate at 56 bits.
- When it happens, the register ends `2^55` too small or too large. That is a
  wrong field element, which the validator sees as a classical mismatch.
  Spread over about 1,400 calls per shot, the narrower window adds hard
  inputs and raises λ.
- The carry erasures are exact. Qubits do not change, because the fold is
  not where the peak sits.
- The shipped nonce `20026` draws a clean test set: 0 classical, 0 phase and
  0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Truncating the replay fold's carry chain by one position is fold/carry
truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 6ee4d14 -- src/point_add`.
   - `git diff --ignore-cr-at-eol 6ee4d14 37b0c9f -- src/point_add` is 4
     changed lines in 2 files.
   - Do not start from the git parent `e5c53dc`. Against it the diff is 6
     lines and also *widens* `SUB4_PP_REPLAY_FLAG_COMPARE` from 24 to 25.
     That only reverts odinfree's narrowing, which this commit never had, so
     it is not part of this commit's change.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 37b0c9f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set, because they override the defaults in the patch.
   Expect:
   - 1320 qubits
   - 944,994 average Toffoli (rounded)
   - score 1,247,392,080
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `20026` and an identical op stream.
Any other change needs a new nonce hunt.

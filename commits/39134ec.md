## Summary

This commit does two things.

- **One more GCD step is cut.** `DIALOG_GCD_ACTIVE_ITERATIONS` goes from 395
  to 394, the next step after [`c3c3f8d`](c3c3f8d.md). As there, the GCD
  passes lose almost nothing (the last step is 2 bits wide), but the apply
  replay loses one full-width step in each of its two passes. The saving is
  2,200 average Toffoli, the same as in `c3c3f8d`, at the unchanged
  1355-qubit peak.
- **A new way to pick the test set.** Earlier commits re-seeded the
  Fiat–Shamir test inputs with variable-length runs of identity `X;X` pairs
  (`DIALOG_REROLL`, `DIALOG_POST_SUB_REROLL`) near the start of the op
  stream. Each candidate then needed the whole 12.7 M-op stream to be
  re-hashed. This commit adds `DIALOG_TAIL_NONCE`: a fixed block of 48
  `X;X` pairs at the very end of the stream, whose targets encode the nonce's
  bits. The hash of the long prefix can be computed once, and each candidate
  nonce only re-absorbs the 96-op tail. This is the mechanism behind every
  later `DIALOG_TAIL_NONCE` / `TAIL_NONCE` value.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 395 → 394** in
   `configure_ecdsafail_submission_route()`.
   - It sets the step count of the forward and reverse transcript passes and
     of the apply replay, for both GCD calls (the `dy/dx` quotient and the
     x-tail product).
   - The dropped step, index 394, ran at `active_width = 2`
     (`256 − 394 × 0.711 + 26 = 1.9`, rounded up to an even number), so the
     transcript passes save only a few Toffoli.
   - The apply replay
     (`emit_dialog_gcd_compressed_sidecar_apply_bitvector_block_lifecycle`
     and its reverse-exact twin) does a full-width modular double, a
     `b0`-controlled modular add and a 256-bit controlled swap per step. One
     step fewer in each of its two passes is most of the 2,200.
   - The transcript stays at `ceil(394 / 3) = 132` blocks (the last now holds
     1 step), so no qubits change.
2. **New tail-nonce block at the end of `build_builder()`.**
   - When `DIALOG_TAIL_NONCE` parses as a `u64`, the builder emits, for each
     of `NONCE_BITS = 48` bits `i`, the pair `b.x(q); b.x(q)` with
     `q = tx[1]` if bit `i` of the nonce is 1 and `q = tx[0]` otherwise, under
     the phase `"dialog_tail_nonce"`. The block is always 96 ops long.
   - `X·X` is the identity, so the circuit's action, Toffoli count and peak
     are unchanged. Only the targets of the last 96 ops vary with the nonce.
   - The evaluator derives the 9,024 test inputs (and the outcomes of every
     measurement) from a SHAKE256 hash of the whole serialized op stream. With
     a fixed-length tail, the sponge state after the prefix is the same for
     every nonce, so a search can absorb the prefix once and try each nonce
     by absorbing only the tail. The older reroll counts change the stream
     length, so each candidate meant re-hashing everything. See
     [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md) and
     [scoring-and-validation](../concepts/scoring-and-validation.md).
   - When the variable is unset, nothing is emitted, so older trees keep a
     byte-identical stream.
3. **`set_default_env("DIALOG_TAIL_NONCE", "296434")`** in the route. The
   old reroll counts stay at `DIALOG_REROLL=4269`,
   `DIALOG_POST_SUB_REROLL=503292`; only the tail moves the test set here.

## Why it is still correct, and what it risks

- **The step cut is probabilistic.** An input whose binary GCD of `(p, dx)`
  needs more than 394 steps leaves the transcript incomplete. The apply
  replay then computes a wrong quotient (classical failure), and the reverse
  pass no longer restores `u` and `v` (ancilla garbage). λ rises.
- **The tail nonce is exact.** It adds identity pairs only. It is a test-set
  selector, like the reroll counts: it does not make the circuit correct on
  more inputs, it only picks a 9,024-shot draw that avoids the rare inputs
  the truncations get wrong.
- The shipped nonce `296434` draws a clean set: 0 classical, 0 phase and 0
  ancilla failures over all 9,024 shots, per the author. The author's
  search binary hashed the prefix once and stopped each candidate at its
  first failing shot; the note estimates about 3 × 10⁵ candidates were
  needed.

## Classification rationale

The circuit change is a shorter fixed iteration count, which is
iteration/threshold tuning. The tail-nonce block changes no arithmetic, so
it does not decide the family, but it is the first instance of the
fixed-length tail nonce that later commits in every era use, which makes
this commit worth knowing for its tooling as much as for its score.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout c3c3f8d -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol c3c3f8d 39134ec -- src/point_add` is
   37 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 39134ec -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` keeps any
   value already in the environment. Expect:
   - 1355 qubits
   - 1,770,811 average Toffoli (rounded)
   - score 2,399,448,905
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=296434`,
`DIALOG_REROLL=4269`, `DIALOG_POST_SUB_REROLL=503292` and an identical op
stream. Any other change needs a new nonce search.

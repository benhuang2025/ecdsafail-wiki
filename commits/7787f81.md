## Summary

After [`b113c6f`](b113c6f.md), the qubit peak (1558) sat in the GCD "apply"
pass, inside the controlled 256-bit modular add and subtract. To save qubits,
that add is done in two chunks: the gated addend and the carry lane only exist
for one chunk at a time. The split point was bit 70, so the upper chunk was
187 bits wide and set the peak. This commit moves the split to bit 82. The
upper chunk is now 175 bits wide, and it needs 2 qubits per bit (addend copy
plus carry), so the apply phase holds up to 24 fewer qubits. The global peak
drops to 1543, where the x-tail square now binds.

The cost is that the comparison that clears the carry between the two chunks
now spans 82 bits instead of 70. That is 12 more Toffoli per call, at 2 calls
per GCD step for 399 steps, so +9,576 Toffoli, exactly the measured change.

## What changed and why it saves qubits

1. **`DIALOG_GCD_APPLY_CHUNKED_F_CUT`: 70 → 82** in
   `configure_ecdsafail_submission_route()`, `src/point_add/mod.rs`.
   - The apply pass replays the GCD transcript on the output register. Each
     step does a controlled modular add (product pair,
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`) or a controlled
     modular subtract (quotient pair, `..._sub_..._chunked`) of a 256-bit
     register `a` into `acc`.
   - With `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS=2`, `dialog_gcd_add_ctrl_chunked_low_to_ext`
     (and its `sub` twin) splits the 257-bit extended accumulator at
     `dialog_gcd_chunk_hi(2, 0, 257) = F_CUT`.
   - Chunk 0 is `[0, F_CUT)`. It loads `f = ctrl & a[0..F_CUT]` with one CCX per
     bit, runs a measured-uncompute Cuccaro add into `acc[0..F_CUT]` with a
     fresh carry-out qubit `cout`, then clears `f` by measurement (`hmr` +
     `cz_if`) and frees it.
   - Chunk 1 is `[F_CUT, 257)`. It loads `ctrl & a[F_CUT..256]` (256 − F_CUT
     qubits) and adds with `cuccaro_add_fast_low_to_ext`, which allocates one
     carry qubit per bit. So this chunk holds 2 × (256 − F_CUT) scratch qubits,
     on top of the pending `cout`.
   - At F_CUT = 70 that is 2 × 186 = 372 scratch qubits; at 82 it is
     2 × 174 = 348, so 24 fewer, which puts the apply phase near 1534. (The
     commit comment says 1542; the follow-up [`40574d3`](40574d3.md) states
     1540 at F_CUT = 79, which matches the 2-qubits-per-bit count.) The global
     peak becomes 1543, bound by `round84_emit_fused_square_xtail`, so any cut
     that clears 1543 gives the same score factor.
   - **Cost.** After both chunks, the boundary carry `cout` is cleared with
     `ccx_cmp_lt_into_fast(acc_ext[..F_CUT], a[..F_CUT], ctrl, cout)`: after
     the add, the low part of `acc` is smaller than the low part of `a` exactly
     when a carry left chunk 0. This compare is exact and costs about one
     Toffoli per bit, so it grows by 12. It runs once per step in each GCD
     pair's apply pass: 2 × 399 × 12 = 9,576 Toffoli.
   - The comment notes that F_CUT = 78 would reach 1543 more cheaply
     (+6,384), but the author found no clean reroll pair for it in the
     standard reroll grid.
2. **Reroll pair: `DIALOG_REROLL` 13 → 9, `DIALOG_POST_SUB_REROLL` 14 → 4.**
   Identity `X;X` counts that re-draw the 9,024 test inputs (see
   [`ecbf87b`](ecbf87b.md)).

## Why it is still correct, and what it risks

The change is exact. Moving the cut only changes where the add is split. The
two chunk adds plus the boundary carry compute the same sum for every input,
and the boundary compare is a full, untruncated compare of the low `F_CUT`
bits, so it always clears `cout` correctly. No approximation is added.

The new op stream draws a new test set, so the existing approximations
(the truncated GCD comparator and width schedule, the fold windows, the
19-bit overflow-clean compare) had to be re-checked against it. The reroll
pair (9, 4) is clean: 9,024 of 9,024 shots, 0 classical, 0 phase and
0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is fold/carry truncation, but nothing is truncated here.
The change moves a chunk boundary so that less scratch is live at the peak,
and pays for it with a wider exact boundary compare. Ancilla-lifetime / venting
(or a peak-qubit rebalancing change-type in Register and Scratch Allocation)
describes it better. The label is kept as published.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b113c6f -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol b113c6f 7787f81 -- src/point_add` is 14 lines
   changed in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7787f81 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1543 qubits
   - 1,698,279 average Toffoli (rounded)
   - score 2,620,444,497
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=9`,
`DIALOG_POST_SUB_REROLL=4` and an identical op stream. Any other change needs
a new reroll search.

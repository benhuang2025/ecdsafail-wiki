## Summary

This commit changes two knobs and the tail nonce.

The first knob, `SQUARE_ROW_MAX_SEG`, goes from 186 to 185. It is the widest
row of the `λ²` schoolbook square that is built in one piece. At 185, the
186-bit row is built in two windows, so the square's largest transient row
register is one bit narrower. The square was the phase holding the peak, so
the circuit drops from 1213 to 1212 qubits.

The second knob widens a truncated comparator instead of narrowing it. The
compare that erases the apply stage's overflow flag goes from 19 to 20 bits.
That costs about +250 Toffoli, but it removes failure risk. The commit needed
it to find a clean nonce at the new width.

Net: +322 Toffoli for −1 qubit. At this size one qubit is worth about 1,158
Toffoli of score (1,404,013 / 1212), so the trade pays.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`SQUARE_ROW_MAX_SEG`: 186 → 185.**
   - `schoolbook_square_symmetric_lowq_selfhosted` and its inverse (in
     `arith/multiply.rs`) build row `i` (width `257 − i`) in one piece when
     `width ≤ MAX_SEG`. Otherwise they call `square_row_windowed_apply` with
     `ceil(width / MAX_SEG)` windows.
   - A one-piece row allocates a `width`-bit transient register. A windowed row
     only ever holds one window, about `width / 2` bits.
   - Lowering the cap to 185 moves row `i = 71` (width 186) from one piece to
     two windows. The widest one-piece row is now 185 bits, which lowers that
     phase's high-water by one.
   - Cost: the new boundary needs one measured carry cleanup in each of the
     forward and inverse squares: 21 rebuilt bits plus a 21-bit conditional
     compare (see [`d636d62`](d636d62.md)). That is roughly 2 × 31.5 ≈ 63
     Toffoli.
2. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 19 → 20.**
   - The value is read by `dialog_gcd_apply_clean_compare_bits()` in
     `rounds/dialog/config.rs`. It is the default width of the compare that
     erases `acc_ovf`, the overflow (or underflow) flag of each apply-step
     modular add/sub (`dialog_gcd_cmod_{add,sub}_materialized_pseudomersenne_chunked`
     in `rounds/dialog/mod.rs`).
   - With `DIALOG_GCD_SPECIAL_CLEAN_CONDITIONAL_REPLAY=1`, the flag is
     `hmr`-measured. Its phase is then repaired by
     `cmp_lt_phase_conditioned_with_cin` on the top `k` bits of `acc` and `a`,
     under the outcome bit. So one more bit costs about ½ Toffoli per add/sub.
   - Steps listed in `DIALOG_GCD_SPECIAL_OVERFLOW_CLEAN_STEP_BITS` and
     `…_UNDERFLOW_CLEAN_STEP_BITS` keep their own 21 to 23 bits.
   - The very next commit on this knob, [`0d1d1e7`](0d1d1e7.md), moves it back
     from 20 to 19 with nothing else changed. That saves 242 average Toffoli
     on the leaderboard (−251.8 in its note). So the move up to 20 here costs
     about +245. The rest of the +322 is the square row above.
3. **`DIALOG_TAIL_NONCE`: 9300018914153 → 165408411.** Both
   `set_default_env("DIALOG_TAIL_NONCE", …)` lines are changed. Only the first
   one takes effect.

## Why it is still correct, and what it risks

- **The row windowing is value-exact.** The windowed row adds the same value
  into `tmp_ext`. The only new risk is one more truncated (21-bit) boundary
  cleanup per square. A tie there gives a phase failure.
- **The compare widening lowers risk.** The overflow-clean compare ignores
  the carry from below its window. A wrong result gives a wrong phase repair
  of `acc_ovf`. At 20 bits this happens about half as often as at 19.
- The shipped nonce `165408411` draws a clean set: 9,024 shots, 0 classical,
  0 phase and 0 ancilla failures (submission note). See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as comparator/width truncation. The diff does not
support that: the only comparator change makes a comparator *wider*. The
saving comes from the square row cap, which is a peak dial in the
row-windowing machinery. A better label would be **Windowing → windowed
carry/shift blocks**, or Register and Scratch Allocation if it is read as a
peak-budget change. The header keeps the published label.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 461a4a3 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 461a4a3 8cd8104 -- src/point_add` is
   8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8cd8104 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with none of the
   route's variables (`DIALOG_*`, `SQUARE_*`, `KAL_*`, `KARA_*`, `ROUND84_*`,
   `R84_*`) set, because `set_default_env` only fills unset variables. Expect:
   - 1212 qubits
   - 1,404,335 average Toffoli (rounded)
   - score 1,702,054,020
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `165408411` and an identical op
stream. Any other change needs a new nonce hunt.

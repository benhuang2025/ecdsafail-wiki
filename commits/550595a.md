## Summary

The commit changes two defaults in `build()`: `LUD_EXTRA_FOLD_MIN_G` from 18
to 17 and the tail nonce. The first edit has no effect. The knob adds extra
vents to every baked fold entry with `g ≥ MIN_G`, and the baked `FFG_G` table
has no entry equal to 17. So the set of entries at `g ≥ 17` is the same as at
`g ≥ 18`, and the circuit is unchanged. The only effective change is the nonce.
It draws a different set of 9,024 test shots whose average executed Toffoli is
1,414,438.346 against 1,414,439.206, which rounds to one Toffoli less. Peak
qubits stay at 1166. The author's own note calls it a tail reroll.

## What changed and why the score moves

- `src/point_add/mod.rs`, `build()`:
  - `LUD_EXTRA_FOLD_MIN_G`: 18 → 17.
    - `load_schedule()` in `trailmix_ludicrous/mod.rs` maps each `schedule::FFG_G` entry
      `x` with `MIN_G ≤ x ≤ MAX_G` to `min(x + LUD_EXTRA_FOLD_VENTS, 53)`. Here
      `LUD_EXTRA_FOLD_VENTS` is still 2.
    - `FFG_G`'s values below 53 are 9, 10, 11, 12, 13, 15, 16, then 18, 19, …, and none is 17.
      The two thresholds therefore select the same entries, and every fold keeps its vent count.
  - `DIALOG_TAIL_NONCE`: 123000008384 → 18381. The comment above it is updated.
- `build_trailmix_ludicrous_ops()` appends the nonce as 48 `X;X` identity pairs on
  `reg0[0]` / `reg0[1]`. The evaluator derives the 9,024 test inputs, and every `Hmr`
  outcome, from a SHAKE256 hash of the whole op stream, so a new nonce means a new draw.
- The score uses the *average executed* Toffoli. Many Toffoli in this circuit run only
  under a measurement outcome, so the count varies from shot to shot, and so does its
  average over a draw. See [scoring-and-validation](../concepts/scoring-and-validation.md).

## Why it is still correct, and what it risks

No arithmetic changed, so correctness is exactly the base's. The new draw only
has to avoid the trailmix circuit's rare hard inputs. Nonce `18381` does: 0
classical, 0 phase and 0 ancilla failures over all 9,024 shots. The author
reports 10,664,752 emitted ops. The nonce was picked from the best 10 of a
100k-nonce scouting window and then checked with the CPU evaluator. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this under fold/carry truncation because of the `MIN_G` edit,
but that edit does nothing on the baked table. The only effective change is the
nonce, so the commit belongs in **Verifier Search → nonce/island reroll**. The
header keeps the published label.

## Summary

This commit changes one constant. `KAL_WTRUNC_K0`, the iteration where the
Kaliski inverse's empirical width envelope starts to shrink, goes from 25 to
24. From there on, every W-TRUNC loop is 0 or 1 bit narrower, 2/3 bit on
average. That saves 4,362 average Toffoli at the same 2309 qubits.

The previous commit ([`53f0bdb`](53f0bdb.md)) changed the op stream and so
drew a new test set. On that op stream, `K0 = 24` is clean.

## What changed and why it saves Toffoli

- `src/point_add/kaliski_state.rs`, `kal_wtrunc_k0()`: the default goes from
  25 to 24. The comment above it is not updated. It still says that
  `K0 = 24` fails, which was true on the earlier island of
  [`141b79a`](141b79a.md).
- **What `K0` controls.**
  - `kal_wtrunc_width(it, n) = min(n, n − ⌊(it − K0)·2/3⌋ + margin)` for
    `it ≥ K0`, with `n = 256` and margin 0 in this tree.
  - With `x = it − 25`, the new envelope is lower by `⌊(2x + 2)/3⌋ − ⌊2x/3⌋`.
    That is 0 when `x mod 3 = 0`, and 1 otherwise.
- **Where the width is used** (`src/point_add/kaliski_walk.rs`, forward and
  backward):
  - the STEP-0 OR chain for `v_w == 0`;
  - the STEP-2 comparator `u > v_w`;
  - the STEP-4 load and subtract;
  - the STEP-3 and STEP-9 (u, v_w) swaps (`kal_cswap_wtrunc_enabled`).

  Each is about one Toffoli per bit. 2/3 bit less per loop per iteration,
  over about 1,600 iterations, gives the 4,362.

## Why it is still correct, and what it risks

This is a probabilistic truncation. With margin 0 already, moving `K0` earlier
spends another 2/3 bit of the slack the fitted envelope had over its
80k-sample maximum (1 to 7 bits). A slow-converging input whose `u` or `v_w`
still has a nonzero bit above the cut gets a wrong comparison, subtraction or
swap. That shows up as a classical mismatch, usually with phase garbage from
the broken uncompute.

There is no nonce in this era. The author re-swept `K0` together with the
banked `R_SMALL_THRESHOLD = 323` and carry-tail `W = 22`. `K0 = 24` is clean,
and `K0 = 23` fails. This draw is clean: 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only change narrows the GCD walk's comparators, OR chains, adders and
swaps, so comparator/width truncation fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 53f0bdb -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 53f0bdb 49b7969 -- src/point_add` is
   2 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 49b7969 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,434,992 average Toffoli (rounded)
   - score 5,622,396,528
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

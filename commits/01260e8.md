## Summary

The dialog-GCD walk works only on the low `active_width(step)` bits of `u`
and `v`. That width is a straight-line envelope of how fast the values shrink,
plus a safety margin. See [412312f](412312f.md) for the June mechanism and
[0780f67](0780f67.md) for the K=2 walk, where the slope is 0.95 bits per step.

This commit lowers the margin from 25 to 18 bits in one go. Every walk step
then gets up to 8 bits narrower, except those still clamped at 256. Each
step-bit costs 4 Toffoli in the K=2 walk: swap, gated load, subtract and the
conditional second shift. The comparator also loses a few capped bits. The
saving is 27,488 Toffoli, which matches the width formula exactly. Qubits are
unchanged. The tail nonce was not changed. The old nonce happened to draw a
clean test set for the new op stream as well.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  the default `DIALOG_GCD_WIDTH_MARGIN` goes from 25 to 18. Nothing else
  changes, and `DIALOG_TAIL_NONCE` stays `141744616447148`.
- **Where it is read.** `dialog_gcd_tobitvector_active_width(step)` returns
  `256 − 0.95·step + margin`, rounded up to an even number and clamped to
  [1, 256], over `DIALOG_GCD_ACTIVE_ITERATIONS = 259` steps.
- **What the width bounds** in each forward step, with the reverse step
  doing the mirror:
  - the branch `cswap(b0_and_b1, u_i, v_i)` loop, 1 Toffoli per bit;
  - the gated load `ccx(ctrl, u[i], gated[i])` in
    `dialog_gcd_controlled_sub_selected`, 1 Toffoli per bit;
  - the subtract body, about 1 Toffoli per bit, with carries erased by
    measurement;
  - the K=2 conditional second shift, a `cswap(s2, v[i], v[i+1])` cascade
    over `active_width − 1` bits, 1 Toffoli per bit;
  - the cap on the branch comparator, `min(DIALOG_GCD_COMPARE_BITS = 74, active_width)`.
    The per-step schedule is off on this tree.
- **The count.** Replaying the formula, the summed width per walk goes from
  40,922 to 39,280 bits (−1,642). 7 of the 29 steps that were clamped at 256
  are now below it. The summed comparator width goes from 18,422 to 18,118
  (−304). Per walk that is 4 × 1,642 + 304 = 6,872 Toffoli, and the four walks
  (forward and reverse in each of the two divisions) give 27,488. That is
  exactly the measured drop.
- **Qubits.** The narrower envelope also lets
  `dialog_gcd_runway_layout()` park 8 more transcript bits on high `u` lanes:
  the fresh allocation goes from 488 to 480 bits. The peak, however, is set by
  the apply-phase chunked add (see [a772a45](a772a45.md)), so it stays at 1390.

## Why it is still correct, and what it risks

The envelope is a fit, not a bound. Bits above `active_width` are dropped
from the swap, the subtract and the second shift, on the assumption that `u`
and `v` are already zero there. An input that shrinks more slowly than
`0.95·step − 18` bits keeps a live bit in the dropped band. Its walk then goes
wrong: the reverse walk cannot restore `u` and `v`, and the output point is
wrong. That shows as a classical mismatch and ancilla garbage. The narrower
envelope also puts more of the transcript on high `u` lanes that are only
assumed to be zero. A 7-bit cut is a large step: the margin now sits much
closer to the observed spread of GCD shrink rates.

The op stream changed, so the 9,024 test inputs changed too, but the nonce
was kept. The author reports 0 classical, 0 phase and 0 ancilla failures over
all 9,024 shots with the inherited nonce `141744616447148`. So the new draw
happened to be clean as well, which says the failure rate at margin 18 is
still low. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A narrower per-step register width is comparator/width truncation. No gates
were removed as dead. Like [412312f](412312f.md), this is the census's broad
"drop unneeded work" family.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a772a45 -- src/point_add`.
   - Do not start from the git parent `9d30eb7`. That is johnbxx's tree.
   - Against the parent, the diff would also undo johnbxx's changes: the
     `KAL_DOUBLE_CARRY_TRUNC_W` and `KAL_FOLD_CARRY_TRUNC_W` windows would go
     from 20 back to 24, `CUT` and `CUT2` from 56/112 to 58/114, and the nonce
     from 25 to 141744616447148. None of that is part of this commit's change.
   - Against `a772a45`, `git diff --ignore-cr-at-eol a772a45 01260e8 -- src/point_add`
     is 2 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 01260e8 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,602,999 average Toffoli (rounded)
   - score 2,228,168,610
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=141744616447148` and an
identical op stream. Any other change needs a new nonce hunt.

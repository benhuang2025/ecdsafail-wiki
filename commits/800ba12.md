## Summary

All edits are in `src/point_add/mod.rs`, and there are three of them on top of
sky5.

1. It switches on `HEO_MB_SKIP2`, a knob that has existed since
   [`8ee337c`](8ee337c.md) but was never set. It drops the multiply batch's
   payload route at tick `R − 2`, a 256-CCX controlled swap. That swap only acts
   on two equal registers, unless the walk parks exactly at the last tick.
2. It makes the chunk-boundary compare one bit narrower in the narrowest
   walk-width band.
3. It deletes the `SKY_REWRITE` post-pass. Its 57 fixed-position rows no longer
   match the changed op stream, so this gives back 57 Toffoli.

Qubits stay at 1174. The net is −375 Toffoli against sky5.

## What changed and why it saves Toffoli

1. **`("HEO_MB_SKIP2", "1")`** added to `install_skywalk_submission_recipe()`.
   - In `heo_carry.rs`, `multiply()`, the trailing batch runs `t` from `R − 1`
     down to `r2m = 370`. At each `t` it runs `route(s_t, Sig, Del)` (256
     `cswap`s, each one CCX) and then the inverse cell `cell_mul`.
   - With the knob on, the guard `if !(k.mb_skip2 && t + 2 == r)` skips the
     route at `t = R − 2`, here tick 390 of the 392-tick multiply leg.
   - Why it is near-identity: the batch starts from the copy `(Sig, Del) =
     (y, y)`. A tick after the walk has parked maps the duplicate pair to itself.
     So for a walk that parked before tick `R − 1`, the pair is still a duplicate
     when the route at `R − 2` runs, and swapping two equal registers does
     nothing. (The route at `R − 1` always sees the fresh copy. The code
     comment says the product simplifier already removes it.)
   - Only a walk that is still active at tick `R − 1`, that is, one that parks
     exactly at tick `R`, with `s_{R−2} = 1`, needs this swap.
   - This mirrors `HEO_DB_SKIP2`, which 8ee337c already uses on the divide
     batch. The saving is up to 256 CCX per shot. Whether the simplifier passes
     had already removed some of those CCX is not stated anywhere.
2. **`HEO_PIN_PP_CHUNK_SHAPE`: `64:0,38:1,25:-3,0:-4` → `64:0,38:1,25:-3,0:-5`.**
   - This pins ping-pong's `PP_CHUNK_SHAPE`, read by `chunk_compare(round)` in
     `pingpong.rs`. Bands are `from_width:offset`, and `band_at` takes the first
     band with `policy_width(round) ≥ from_width`.
   - The compare width is `PP_REPLAY_CHUNK_COMPARE` (21) plus that offset, plus
     the per-cell `dB` shift from `HEO_CELL_WINDOWS`, plus any `GO_CHUNK`
     slice.
   - The last band covers proxy rounds whose policy width is below 25, the
     late, narrow-rail Skywalk ticks. Its base width goes from 21 − 4 = 17 to
     21 − 5 = 16 bits before the per-cell shifts.
   - `chunk_layout` reads `replay_chunk_compare()` directly, so the chunk
     boundaries do not move. Only the compare gets narrower.
   - That compare erases a chunk's carry-out in `chunked_add`:
     `erase_with_compare` measures the carry out with `hmr` and then runs
     `cmp_lt_phase` over the top `k` bits of the chunk, conditioned on the
     outcome. It repairs the phase and does not recompute the carry. Because it
     runs only when the outcome is 1, about half the shots, one bit saves about
     0.5 Toffoli per boundary on average.
3. **The `SKY_REWRITE` block in `build()` is removed**, replaced by the comment
   "Preserve original CCX operations: fixed-index sky5 rows do not match this
   candidate".
   - The block applies `sky5_ycd_rewrite.txt` only under one rigid shift of the
     whole op stream, and it asserts that this shift is unique.
   - Removing a route and narrowing compares shifts the ops non-rigidly, so the
     assert would fail. The author chose to emit the original 57 CCX rather
     than re-derive new rows, which costs +57 T exactly.
   - The table file stays in the tree, unused.
4. **`TAIL_NONCE`**: 5000500937876 → 120000004242367.

Toffoli accounting:
- The official runs give 945,923.877 for sky5 and 945,548.543 here, −375.3.
- The note's 32-nonce means are 945,927.0 and 945,545.5, −381.5.
- If the skipped route removes all 256 CCX, then after the +57 from the rows the
  chunk-shape change accounts for about −180 T. This split is my arithmetic;
  the note gives none.

## Why it is still correct, and what it risks

- **`HEO_MB_SKIP2` is probabilistic.** It is exact on every walk except those
  that park exactly at the last multiply tick with `s_{R−2} = 1`. On those, the
  product is wrong, which shows up as a classical failure.
- **The chunk-shape change is probabilistic.** With one bit fewer, the
  truncated compare is wrong about twice as often when the compared top bits of
  sum and addend agree. A wrong repair leaves a phase error. The code comment
  says the late band's boundary error rate is about 0.04 of the wide-walk rate,
  which is why the late band had slack.
- **Dropping the rewrites is exact.** It only puts back gates that were proved
  redundant.
- **Lambda.** The note measured a mean of 19.52 failing batches per draw over
  128 random nonces. None of those 128 nonces was clean. That is at
  mochimodev's limit of 19.5 and above the 18 that dysnasia kept. A wider
  `25:-2` variant cost about 130 T more, and its Lambda reduction was not
  significant.
- The shipped nonce `120000004242367` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. It was the only full pass
  among 3,247 GPU-filter survivors out of 48.4 M scanned nonces. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The largest lever removes a block of gates that is the identity on almost
every input: up to 256 CCX, against about 180 for the compare. That is an
approximate dead-gate/self-inverse removal. The chunk-shape change is a
secondary comparator/width truncation. If the skipped route turns out to be
worth less than about 216 T, the truncation would be the larger part. The note
gives no split, so this call is not certain.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 82c849b -- src/point_add`.
   - Do not start from the git parent `4ea960f`. That is dysnasia's sky8 tree,
     and this commit was not built on it.
   - Against the parent, the diff is 233 lines in 7 files. It would revert
     sky8: `HEO_SPLIT_K=21`, `GO_CELLB` / `GO_CELLF` and their `go_cell_delta`
     code in `heo_carry.rs`, `HEO_PIN_PP_FOLD_WIDEN` 68 → 64, and the iA.100
     envelopes. It would also delete sky8's 67-row `sky8_p7f_rewrite.txt` and
     restore `sky5_ycd_rewrite.txt`.
   - Against `82c849b`, `git diff --ignore-cr-at-eol 82c849b 800ba12 -- src/point_add`
     is 41 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 800ba12 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment, but keep `SUB4_*`, `PP_*`, `HEO_*`, `GO_*` and
   `SKY_*` unset anyway. Expect:
   - 1174 qubits
   - 945,549 average Toffoli (945,548.543 before rounding)
   - score 1,110,074,526
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `120000004242367` and an identical op
stream. Any other change needs a new nonce hunt.

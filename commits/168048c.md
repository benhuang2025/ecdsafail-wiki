## Summary

The fast modular add and subtract reduce mod p by adding or subtracting the
small constant `c = 2^256 − p = 2^32 + 977`. Before this commit they did that
by writing `c` (or `flag ? c : 0`) into a fresh 257-qubit register and running
a full quantum-quantum Cuccaro adder against it. This commit routes those
steps to a "direct" constant adder that reads the constant's bits classically,
so the 257-qubit addend register is never allocated. Only the carry bank is
live.

This lowers the peak by 2 qubits. It costs a little Toffoli, +756 on average,
because a carry position where the constant bit is 1 needs three Toffolis
instead of one. At about 1,450 Toffoli of score per qubit, the trade pays.

## What changed and why it saves qubits

All edits are in `src/point_add/mod.rs`.

- **New switch `direct_const_modred_enabled()`**, reading
  `KAL_DIRECT_CONST_MODRED`, default **on**. It is checked after the existing
  `KAL_VENT_MODADD` venting path, which is off by default.
- **New helper `add_nbit_const_direct_fast(acc, c)`**: an unconditional
  constant add. It allocates one control qubit, sets it to |1⟩, calls the
  existing `cadd_nbit_const_direct_fast(acc, c, ctrl)`, and resets the
  control.
- **Five call sites switch to the direct adders** when the switch is on:
  - `mod_sub_qq_fast`: the underflow correction `csub c` (controlled by the
    borrow flag) now calls `csub_nbit_const_direct_fast` instead of
    `csub_nbit_const_fast`.
  - `mod_add_qq_fast` and `mod_add_qq_fast_from_zero`: the "add `c`" step now
    calls `add_nbit_const_direct_fast` instead of `load_const` + `add_nbit_qq_fast`
    + `unload_const`. The "if no reduction, subtract `c` back" step now calls
    `csub_nbit_const_direct_fast` instead of building `flag ? c : 0` in a
    fresh register and running `sub_nbit_qq_fast`.

These three functions are the fast modular add/sub used throughout the circuit.
They follow the Solinas pattern described in
[modular-fold](../concepts/modular-fold.md): add, then add `c`, test the top
bit, and conditionally undo.

**Old path.** `add_nbit_qq_fast` is a Cuccaro ripple adder whose carries are
erased by measurement (`cuccaro_add_fast`). For a 257-bit add it holds the
257-qubit addend register, 256 carry wires and a carry-in, and costs one CCX
per carry position (the MAJ gate can XOR into the addend qubit, so the
majority costs one Toffoli).

**New path.** `cadd_nbit_const_direct_fast` / `csub_nbit_const_direct_fast`
compute each carry (or borrow) as `majority(acc_i, k_i, carry_i)`, where
`k_i = ctrl` if bit `i` of `c` is 1 and `k_i = 0` otherwise:
- where `c_i = 0` the majority is `acc_i AND carry_i`, one CCX;
- where `c_i = 1` it is computed as three CCXs, `(acc_i·carry_i) ⊕ (ctrl·acc_i) ⊕ (ctrl·carry_i)`,
  because the shared `ctrl` wire cannot be overwritten the way a Cuccaro MAJ
  overwrites its addend bit;
- the carries are then erased by `hmr` plus `cz_if` phase fixes, with no
  Toffoli. See [measurement-uncompute](../concepts/measurement-uncompute.md)
  and [adders-and-carries](../concepts/adders-and-carries.md).

`c = 2^32 + 977` has 1-bits at positions 0, 4, 6, 7, 8, 9 and 32. Position 0
needs only one CCX, so each direct call costs 2 × 6 = 12 Toffoli more than the
Cuccaro call it replaces. The measured +756 average Toffoli corresponds to
about 63 such calls per point addition.

**Why the peak falls.** Each replaced step no longer holds a 257-qubit addend
register. The comment in the new code calls that register "early and
long-lived across reduction sub-stages". The leaderboard peak falls by only 2,
from 2715 to 2713. The phases that use these adds were therefore only just
above the next-highest phase, which now sets the peak. See
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

## Why it is still correct, and what it risks

The change is exact on every input.
- The direct adders compute the same sum or difference as the Cuccaro adders,
  bit for bit. The majority recurrence is the standard carry rule.
- The measured erase is exact. After the sum is written, the carry out of
  position `i` equals `majority(NOT s_i, k_i, carry_i)` for an add, and
  `majority(s_i, k_i, borrow_i)` for a subtract, where `s_i` is the final sum
  bit. The `cz_if` gates apply `(-1)` to the power of that majority as three
  pairwise CZs, because `maj(a,b,c) = ab ⊕ ac ⊕ bc`. That exactly cancels the
  phase the `hmr` can leave. A wrong fix would show up as a phase failure.

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed, but the arithmetic is exact and the run
passed with 0 classical, 0 phase and 0 ancilla failures.

## Classification rationale

The census files this as Strength Reduction → fast-adder reroute, because the
constant adds are rerouted to a different adder. The effect of the reroute is
not a cheaper gate count, though: Toffoli rises by 756. What it saves is a
257-qubit scratch register, and with it 2 peak qubits. By its effect, the diff
fits Register and Scratch Allocation (scratch removal) better.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f43a73e -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol f43a73e 168048c -- src/point_add` is 31 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 168048c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_DIRECT_CONST_MODRED`, `KAL_VENT_MODADD`, `DUMMY_TOFFOLIS` or other
   environment overrides set. Expect:
   - 2713 qubits
   - 3,943,509 average Toffoli (rounded)
   - score 10,698,739,917
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score only reproduces with an identical op stream.

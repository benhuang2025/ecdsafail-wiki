## Summary

johnbxx's fold fusion [`8a47cf5`](8a47cf5.md) had widened two comparators to
make a clean nonce easier to find. This commit takes one of those bits back.
The truncated comparator that clears the overflow flag after each controlled
modular add in the GCD apply now looks at the top 23 bits instead of 24. It
runs about 518 times per shot at one Toffoli per bit, so the saving is exactly
518 average Toffoli. Qubits are unchanged. The author re-hunted the tail
nonce with a CPU prefilter.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 24 → 23.**
   - Read by `dialog_gcd_apply_clean_compare_bits()`. Each step of the GCD
     apply loop adds `x` into `y` mod p under the step's branch control. The
     add is `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`, and the
     reverse apply uses the matching `..._sub_...` routine.
   - The add has three parts. A raw add writes its carry-out into an
     extension wire `acc_ovf`. A Solinas fold adds `c = 2^32 + 977` into the
     low bits when `acc_ovf` is set (see [modular-fold](../concepts/modular-fold.md)).
     Then `acc_ovf` is erased.
   - The erase uses the fact that an overflow happened exactly when the
     result is below the addend. It computes that with
     `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)` on only the
     top `k` bits. The subtract side uses `dialog_gcd_clean_truncated_underflow`
     with the same `k`.
   - Each compared bit costs one Toffoli. With 259 steps and two apply passes
     (forward add and reverse sub) there are 518 such erases per shot, which
     matches the measured −518.
2. **`DIALOG_TAIL_NONCE`: 172380 → 43950001112.** The 48 identity `X;X`
   pairs at the end of `build_builder()` encode the nonce. They change only
   the op-stream hash and so the 9,024 test inputs.

## Why it is still correct, and what it risks

The truncated erase is exact unless the top 23 bits of the result and the
addend are equal, which happens about 2^−23 of the time per call for a random
`y`. Then the flag is not cleared, so the erase fails. That leaves a dirty
`acc_ovf`, which shows up as ancilla or phase garbage, or as a wrong
`y` if the flag is later used. One bit less doubles that per-call rate.
The author found nonce `43950001112` with a CPU prefilter for the classical
channel. The trusted evaluation confirmed it is also phase-clean: 9,024 of
9,024 shots, with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

One comparator is narrowed by one bit, which is comparator/width truncation.
The nonce comes with every op-stream change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8a47cf5 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 8a47cf5 2f1f175 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 2f1f175 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*` or `DIALOG_*` environment variables set. Expect:
   - 1313 qubits
   - 1,518,002 average Toffoli (rounded)
   - score 1,993,136,626
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=43950001112` and an
identical op stream. Any other change needs a new nonce hunt.

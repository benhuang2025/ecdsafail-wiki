## Summary

The third one-bit step on the same comparator, after [88079e6](88079e6.md)
(23 → 22) and [b55ede3](b55ede3.md) (22 → 21). Each of the 258 steps of each
dialog-GCD apply pass does one controlled modular add or subtract, and its
overflow bit is cleared by a comparison on the top `k` bits of the result and
the addend. This commit makes `k` 20. One comparator bit is one Toffoli, so
the saving is 258 × 2 divisions = 516 Toffoli, exactly the measured drop.
Qubits are unchanged, and the tail nonce was re-hunted.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 21 → 20.**
   - `dialog_gcd_apply_clean_compare_bits()` sets `compare_start = N − k` for
     the overflow clean.
   - In the multiply-type division's apply pass, the clean is
     `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)` in
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`.
   - In the quotient division's reverse-exact pass, it is the subtract twin
     `dialog_gcd_clean_truncated_underflow`.
   - About one Toffoli per compared bit, once per apply step: 2 × 258 × 1 = 516.
   - [88079e6](88079e6.md) explains why `ctrl AND (acc < a)` recovers the
     overflow bit of a modular add.
2. **`DIALOG_TAIL_NONCE`: 431581 → 721381**, the fixed 48-pair `X;X`
   identity tail that reseeds the 9,024 test inputs.
3. The comments are updated with the new Toffoli count and nonce.

## Why it is still correct, and what it risks

The overflow clean is a truncated comparison. It can be wrong when the result
and the addend agree on all top 20 bits. Then the overflow bit stays dirty and
the wrong correction spreads into later apply steps. That shows up as classical
and phase failures, as [b55ede3](b55ede3.md) observed when it re-used an old
nonce at 21 bits. Each bit dropped roughly doubles the per-call failure chance.
The code comment's "the dropped high bit is 0 there" is not a proof. It only
means the shipped test set avoids the hazard.

The shipped nonce `721381` draws a test set with 0 classical, 0 phase and
0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A one-bit narrowing of a comparator window is comparator/width truncation. The
nonce change comes with every circuit change and is not a separate lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b55ede3 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol b55ede3 3033d01 -- src/point_add` is
   19 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 3033d01 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1309 qubits
   - 1,503,355 average Toffoli (rounded)
   - score 1,967,891,695
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=721381` and an identical op
stream. Any other change needs a new nonce hunt.

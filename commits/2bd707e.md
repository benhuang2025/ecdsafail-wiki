## Summary

The circuit change is one constant. Each dialog-GCD step decides `u > v` from
only the top bits of `u` and `v`. The per-step width is
`min(schedule + 5, active_width, cap)`, and this commit lowers the cap from
57 to 56. On the 261 steps where the cap binds, the comparator loses one bit.
It runs four times per step at one Toffoli per bit, so the saving is
4 × 261 = 1,044 Toffoli, exactly the measured change. Qubits are unchanged.

The author found a clean island with a very large reroll pair (694,534 and
579,110 identity pairs). The commit also adds 209 macOS `._*` metadata files
next to the source files. They do not affect the build.

## What changed and why it saves Toffoli

1. **`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
   `DIALOG_GCD_COMPARE_BITS` 57 → 56.**
   - `dialog_gcd_compare_bits_for_step(step, active_width)` returns
     `min(DIALOG_GCD_PA9024_COMPARE_SCHEDULE[step] + 5, active_width, DIALOG_GCD_COMPARE_BITS)`.
   - Recomputing the table over this tree's 395 steps (width margin 26), the
     56 cap binds on 261 steps (steps 53 to 319). The summed compare width
     drops from 19,431 to 19,170 bits.
   - The comparator is the hosted branch-bit
     `ccx_cmp_lt_into_fast_borrowed_carries`, one Toffoli per bit, with
     measured carry cleanup. It runs in the forward and reverse transcript
     passes of both GCD passes: 4 × 261 = 1,044 Toffoli.
   - See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
2. **Reroll pair: `DIALOG_REROLL` 1,844 → 694,534, `DIALOG_POST_SUB_REROLL`
   3,532 → 579,110.** `build_builder()` emits that many `X;X` pairs on two
   data qubits. They are exact identities, add no Toffoli and no qubits, and
   only re-draw the 9,024 test inputs. As in the author's
   [`339fe8d`](339fe8d.md), the search range was far larger than other
   contestants used.
3. **209 new files `src/point_add/._<name>`**, one for each existing file
   except the `._mod.rs` that `339fe8d` already added. All have the same
   4,096-byte content. They are AppleDouble extended-attribute files that
   macOS writes when copying to a non-Apple filesystem. Cargo ignores them,
   and they stay in the tree in later commits.

## Why it is still correct, and what it risks

The truncated comparison is approximate. When `u` and `v` agree on their top
56 compared bits it can return the wrong `u > v`. The step then takes the
wrong GCD branch, which shows up as a classical failure, or as phase or
ancilla garbage when the reverse pass no longer mirrors the forward pass. One
bit fewer roughly doubles the per-step risk on the 261 affected steps.

The reroll pair (694,534, 579,110) draws a clean set: 9,024 of 9,024 shots
pass with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows an approximate comparator, so
comparator/width truncation fits.

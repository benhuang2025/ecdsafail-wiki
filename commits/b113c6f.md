## Summary

The circuit's qubit peak (1567) sat in the x-tail square, in the step that
reduces `hi·2^32` modulo p. That step multiplied `hi` by 2^22 with a
"shift-by-22" that parks 24 helper qubits for the whole step. This commit
computes the same value with 22 modular doublings in place, then the
subtraction, then 22 modular halvings. The doublings need no parked qubits,
so the square's peak drops and the global peak falls to 1558. The extra
doublings cost about 4,788 Toffoli.

The new op stream had no clean test set at the base's comparator cap of 58
bits, so the author raised it back to 59 (+952 Toffoli) and re-searched the
reroll pair. Net: −9 qubits for +5,740 Toffoli, a 0.24% score gain.

## What changed and why it saves qubits

1. **`squaring_sub_from_acc_karatsuba()`** in `src/point_add/mod.rs`, the
   Karatsuba square used by the x-tail (`ROUND84_XTAIL_KARATSUBA=1`).
   - After the square, the 512-bit result is split as `lo + hi·2^256`. The
     Solinas reduction subtracts `lo + hi·c` from `acc`, with
     `c = 2^256 − p = 2^32 + 977 = 2^32 + 2^10 − 2^6 + 2^4 + 1`. It does this
     by doubling `hi` in place mod p and subtracting at each set position:
     `·1`, then 4 doublings to `·16`, 2 more to `·64` (added, since that term
     is negative), 4 more to `·1024`, and finally the `·2^32` term. At the end,
     32 halvings restore `hi`. See [modular-fold](../concepts/modular-fold.md).
   - **Old 2^32 term:** `mod_shift_left_by_k(hi, 22)`, then `mod_sub_qq`, then
     `mod_shift_right_by_k`. The shift allocates `spill` (22 qubits) plus
     `ovf` and `flag_inv`. It keeps those 24 qubits live from the left shift to
     the right shift, so they sit under the mid subtraction's own scratch. That
     sum was the global peak, 1567.
   - **New 2^32 term** (when `KARA_SOL_SHIFT22_DOUBLES=1`): 22 × `mod_dbl(hi)`,
     then `mod_sub(acc, hi)`, then 22 × `mod_hlv(hi)`. By default `mod_dbl` and
     `mod_hlv` are `mod_double_inplace_direct_const_fast` and
     `mod_halve_inplace_direct_const_fast`. Each one is a free wire rotation
     plus a controlled add or subtract of the constant `c`, controlled by one
     overflow qubit that is freed at once. Nothing stays live across the
     subtraction.
   - Doubling 22 times mod p equals multiplying by 2^22 mod p, so `acc` gets
     the same value. The old code path stays behind `KARA_SOL_SHIFT22_DOUBLES=0`.
   - The 44 extra constant adds cost about +4,788 Toffoli. The author's
     TRACE_PEAK run puts the new peak, 1558, in the dialog-GCD apply phases
     (`materialized_special_chunked_raw_sum` / `_raw_difference`), which now
     bind together.
2. **`configure_ecdsafail_submission_route()`**:
   - New pin `KARA_SOL_SHIFT22_DOUBLES=1`.
   - `DIALOG_GCD_COMPARE_BITS`: 58 → 59. This is the global cap on the GCD
     branch comparator (see [`ecbf87b`](ecbf87b.md)). One more bit costs
     +952 Toffoli, the gap between [`ecbf87b`](ecbf87b.md) and
     [`1207861`](1207861.md). The comment says a 96-cell reroll scan at 58
     found no clean test set for this op stream.
   - `DIALOG_REROLL`: 1 → 13. `DIALOG_POST_SUB_REROLL` stays 14. These are
     counts of identity `X;X` pairs that re-draw the test set.

Accounting: +4,788 (doublings) + 952 (one more comparator bit) = +5,740
Toffoli, which matches the measured change.

## Why it is still correct, and what it risks

The doubling path is exact. `mod_double_inplace_direct_const_fast` computes
`2v mod p` (except for the ~2^31 inputs `p/2 ≤ v < 2^255`, where it leaves the
congruent `2v ≥ p` unreduced), using the shifted-out top bit as the overflow
flag and clearing it from the result's parity. `mod_halve_inplace_direct_const_fast`
is its exact inverse. So `hi·2^22` is formed exactly, and the 22 halvings
return `hi` to its previous value.

Relaxing the comparator from 58 to 59 bits makes the GCD more accurate, not
less. The only probabilistic parts are the ones the base already had (the
truncated comparator, the width schedule and the fold windows). The reroll
pair (13, 14) draws a test set on which they all succeed: 9,024 of 9,024
shots, 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The qubit cut comes from computing `hi·2^22` in place in `hi` instead of
spilling 22 bits into a side register, so in-place mutation fits. A runner-up
would be ancilla-lifetime / venting, since the gain is that 24 qubits are no
longer held across the subtraction. The comparator change is a forced
give-back, not a lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 1207861 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 1207861 b113c6f -- src/point_add` is 52 lines
   changed in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b113c6f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1558 qubits
   - 1,688,703 average Toffoli (rounded)
   - score 2,630,999,274
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=13`,
`DIALOG_POST_SUB_REROLL=14` and an identical op stream. Any other change needs
a new reroll search.

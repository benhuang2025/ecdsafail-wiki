## Summary

The author had made two separate one-bit tightenings of the dialog-GCD walk,
each on top of `1fd942d`: the branch-comparator margin in [8316db1](8316db1.md)
and the register-width margin in [412312f](412312f.md). This commit combines
them. It applies the comparator change (margin 6 → 5) to the 412312f tree and
rescans the reroll. The saving is again 716 Toffoli, the same as in 8316db1,
because the two knobs act on different operations. Qubits are unchanged.

## What changed and why it saves Toffoli

Background on the walk is in [8316db1](8316db1.md).

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `DIALOG_GCD_PA9024_COMPARE_SCHEDULE_MARGIN` default 6 → 5.
  - `dialog_gcd_compare_bits_for_step(step, active_width)` returns
    `min(SCHEDULE[step] + margin, active_width, 63)`. That is the number of top
    bits of `u` and `v` that the fused branch comparator
    (`dialog_gcd_ccx_cmp_gt_truncated_into_width`) looks at in each walk step,
    at one Toffoli per bit.
  - With `WIDTH_MARGIN = 27`, the summed comparator width per walk drops from
    20,879 to 20,700 bits. Again 179 steps lose a bit; the rest are capped by
    the 63-bit limit or by `active_width`. Four walks give 4 × 179 = 716
    Toffoli, the measured drop.
  - The two margins are close to independent: `WIDTH_MARGIN` sets the swap and
    subtract width, and only touches the comparator on the late steps where
    `active_width` is the cap.
- `DIALOG_REROLL` default 2 → 0. The reroll loop in `build()` only runs for
  `k > 0`, so 0 means no `X;X` pairs at all. The test inputs are re-seeded by
  the change in the op stream itself, and that draw happened to be clean.

## Why it is still correct, and what it risks

The narrower comparator gives the wrong branch when `u` and `v` tie on all of
the compared bits, about twice as often as before on the 179 affected steps.
It is probabilistic, as in 8316db1. The narrower width envelope from 412312f is
also still in force. A failure would show as a classical mismatch, usually
with ancilla garbage from the reverse walk. The shipped stream (reroll 0) draws
0 classical, 0 phase and 0 ancilla failures. The author reports that margin 4
and a carry window of 18 for `KAL_DOUBLE/FOLD_CARRY_TRUNC_W` failed on every
reroll they screened. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A narrower truncated comparator is comparator/width truncation, exactly like
8316db1.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 412312f -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 412312f 4b68e94 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 4b68e94 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set. Expect:
   - 1698 qubits
   - 1,662,249 average Toffoli (rounded)
   - score 2,822,498,802
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 0` and an identical op
stream. Any other change needs a new reroll scan.

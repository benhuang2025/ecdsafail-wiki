## Summary

At 1221 qubits the peak was shared by two phases of the round84 λ² square: the
row-windowed square itself and the in-place Solinas fold/unfold around it. This
commit lowers both by one qubit and trims Toffoli at the same time.

- **Fold/unfold.** The fold computes the 66-bit product `q · c` of the
  33-bit quotient `q` and `c = 2^32 + 977`. It used to uncompute the product
  at the end of the fold and recompute it at the start of the unfold. Now the
  product stays live through the subtraction in between. That removes one
  uncompute and one recompute, and with them the transient pad wires of the
  recompute.
- **Square.** One more square row is windowed (`SQUARE_ROW_MAX_SEG` 194 → 193).
- **Square cleanup.** The boundary-carry cleanup compare of
  [`1a5e620`](1a5e620.md) is narrowed from 22 to 18 bits, which saves Toffoli
  but is probabilistic.

The net is −1 qubit and −1,348 Toffoli.

## What changed and why it saves qubits and Toffoli

1. **`ROUND84_KEEP_QUOTIENT_PRODUCT=1` (`src/point_add/arith/multiply.rs`).**
   - **Context.** `squaring_sub_from_acc_schoolbook_lowq_shift22` computes
     `acc −= x² mod p` in phases:
     1. square into `tmp_ext`;
     2. `round84_fold_hi_into_lo_aggregate`, which folds the high half into the
        low half;
     3. `mod_sub_qq_vent(acc, lo)`, the middle subtraction;
     4. `round84_unfold_hi_from_lo_aggregate`;
     5. inverse square.
   - **Before.** The fold built `product = q · c` with
     `round84_compute_quotient_c_product`, using four NAF shifted adds, each
     with a zero pad allocated for the shorter source. It added the narrow
     correction to `lo`, then uncomputed `product`. The unfold recomputed
     `product`, subtracted the correction, and uncomputed it again.
   - **After.** With the switch on, the fold returns the product in the
     `Round84AggregateFold` state (new field `product: Option<Vec<QubitId>>`).
     The unfold uses it instead of recomputing it, via
     `state.product.unwrap_or_else(...)`.
   - **Toffoli.** One compute and one uncompute of the product are gone, each
     four measured adds of about 34–62 bits, so a few hundred Toffoli per shot.
   - **Qubits.** The 66 product wires are now also live during the middle
     subtraction, but that phase has room for them. The recompute at the start
     of the unfold, with its pad wires on top of the live correction-wrap bit,
     no longer happens. The author reports that this takes the fold/unfold
     co-binder from 1221 to 1220; I did not trace the per-phase peaks.
   - Also added, but not pinned: `ROUND84_CORRECTION_WRAP_BORROW_QUOTIENT_TOP`,
     which would borrow `quotient[33]` as the correction-wrap bit
     (`round84_add_narrow_correction` and `round84_sub_narrow_correction` gain
     a borrowed-wrap argument and an `owned_wrap` flag). It is off on this
     route.
2. **`SQUARE_ROW_MAX_SEG`: 194 → 193.** In `square_row_windowed_apply`, rows
   wider than 193 bits are split into two windows. Row `i` has width
   `257 − i`, so row 63 (width 194) is now windowed too. This narrows the
   square's largest transient source register by one, which takes the other
   co-binder to 1220.
3. **`SQUARE_ROW_WINDOW_CLEAN_COMPARE_BITS`: 22 → 18.** The interior-window
   carry cleanup compares only the top 18 bits of the segment. That saves
   about 2 Toffoli per bit (the segment rebuild and the compare), for each
   windowed row in the square and its inverse: about 64 × 2 × 2 × 4 ≈ 1,000.
4. **`DIALOG_GCD_FOLD_CARRY_TRUNC_W=19` (new pin).** This sets the fused
   double/halve fold's own carry window. It has the same value as the inherited
   `KAL_DOUBLE_CARRY_TRUNC_W=19`, so it does not change the circuit.
5. **`DIALOG_TAIL_NONCE`**: 7700044727491 → 5200018704193. This is the
   top-of-route pin, which wins over the stale pin further down.
6. **Instrumentation only (`src/point_add/mod.rs`).**
   - `B` and `build_builder` become `pub`.
   - `B` gains `active_timeline`, which `record_active_timeline()` fills on
     every qubit allocation and free when `PROFILE_ACTIVE_TIMELINE` is set.
   - This emits no ops.

## Why it is still correct, and what it risks

- **Keeping the product is exact.** The middle subtraction reads `lo` and
  writes `acc`. It does not touch the product or the quotient, so the kept
  product is still `q · c` when the unfold uses it, and the unfold uncomputes
  it exactly as before.
- **Windowing one more row is exact.**
- **The 18-bit cleanup compare is probabilistic.** It leaves the boundary
  carry dirty when the partial sum and the segment tie on their top 18 bits,
  about 2^−18 per windowed row, 16 times the rate at 22. A dirty carry is an
  ancilla failure, and it can leak phase.
- The shipped nonce `5200018704193` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The qubit comes from rescheduling a value's lifetime. The product is kept live
instead of being uncomputed and recomputed, so the recompute's scratch is not
needed at the unfold. That is filed as scratch/ancilla reuse.
Ancilla-lifetime / venting would also fit. The compare narrowing is a
secondary comparator/width truncation that pays for part of the hunt.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 1a5e620 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 1a5e620 997dbd6 -- src/point_add` is 77 lines
   in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 997dbd6 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `ROUND84_*`, `R84_*`, `SQUARE_*` or `MOD_*`
   environment variables set, because they override the route defaults.
   Expect:
   - 1220 qubits
   - 1,404,200 average Toffoli (rounded)
   - score 1,713,124,000
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=5200018704193` and an
identical op stream. Any other change needs a new nonce hunt.

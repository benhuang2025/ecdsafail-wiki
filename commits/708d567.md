## Summary

Each divide replay round reduces its sum mod p by adding one of
{−f, 0, +f, +2f} into only the low `SUB4_PP_REPLAY_FOLD_WINDOW` bits of the
target. Any carry that runs past the window is dropped. This commit pins that
window at 53 instead of 54, which removes one carry position from the fold in
every divide replay round. The multiply traversal already used 53.

In the same commit, the replay ladder budget `SUB4_PP_PEAK` goes back from
1268 to 1267, undoing half of [`79e7afa`](79e7afa.md). That gives some
interleaved replay rounds one fewer ladder qubit, which costs Toffoli. The net
of the two is −90 average Toffoli at the same 1264 qubits. The commit does not
record the split between them or the reason for the budget change.

## What changed and why it saves Toffoli

All circuit changes are `set_default_env` pins in `build()`,
`src/point_add/mod.rs`.

1. **`SUB4_PP_REPLAY_FOLD_WINDOW` 54 → 53.** Read by `replay_fold_window()`
   in `pingpong_div.rs`. In this generation of the code it is an absolute
   slice length: the fold works on `target[..window]`. It is used by:
   - **The divide replay cell** `signed_mod_add_pm_halve_fused`, once per
     divide replay round.
     - After the chunked add, the cell builds the selectors `minus_f` and
       `plus_2f` (and `plus_f` parked in the parity wire) from the sign, the
       parity and the overflow bit.
     - `fused_fold_maskfree(b, &target[..window], f, …)` then adds the
       selected multiple of `f` with one ripple over those bits.
     - One bit less is one fewer carry position on every divide round. See
       [modular-fold](../concepts/modular-fold.md), section "The replay
       cell".
   - **`conditional_mod_negate` and `mod_halve_pm`**, through
     `replay_fold_target`, which slices to the same window because
     `SUB4_PINGPONG_LOW56_FOLD` is set.
   - **The round-0 lift chains** `mux_round0_correction_forward_sparse` and
     `fused_lift_round0_reverse_sparse`, which use `window − 2`, so 52 → 51.
   - The multiply cell reads `SUB4_PP_REPLAY_FOLD_WINDOW_MUL`, which is
     already pinned at 53 and does not change.
2. **`SUB4_PP_PEAK` 1268 → 1267.**
   - This is the budget that `plan()` uses to size each interleaved replay
     round's chunk ladder: `allowance = peak − (tape_len + 2·256 + 2·walk_width)`.
   - One less unit means some rounds pick a narrower ladder with one more
     approximate chunk boundary, which costs Toffoli. 79e7afa's comment
     credited the opposite move with −952 CCX on its tree.
   - The realised peak stays 1264, below both budgets. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - The net −90 means the fold cut saved more than this gave back. The
     commit does not say why the budget was lowered.
3. **Tail nonce:** `SUB4_PINGPONG_TAIL_NONCE` default 97212983354114 →
   25000185239798.
4. **`src/point_add/mod.rs.bak`** (uncompiled backup) is refreshed to a copy
   of the base's `mod.rs`. No circuit effect.

## Why it is still correct, and what it risks

- **The fold window is probabilistic.** The fold drops a carry that would
  leave the 53-bit slice. For random data that has probability about
  `k·f / 2^53` per call for the selected multiple `k·f`, so 2^-21 to 2^-20.
  That is double what it was at 54. A dropped carry leaves a wrong field element, so the failure is classical. With one call
  per divide round, this is a real λ cost, and every bit off doubles it.
- **The budget change is exact.** It only changes chunk layouts. More
  approximate chunk boundaries add phase-channel exposure, a little.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from shortening the replay fold's carry window, which is
fold/carry truncation. The budget change costs Toffoli and is not the lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 716e359 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 716e359 708d567 -- src/point_add` is
   20 lines in 2 files, of which 14 are in the backup `mod.rs.bak`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 708d567 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1264 qubits
   - 903,381 average Toffoli (rounded)
   - score 1,141,873,584
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `25000185239798` and an identical op
stream. Any other change needs a new nonce hunt.

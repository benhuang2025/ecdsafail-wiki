## Summary

The replay's fused correction fold adds a multiple of `f` into only the low
"window" bits of the coefficient. This commit makes that window one bit
narrower on every round where the walk register is narrower than 38 bits,
which is the last 80 rounds. The fold in the trailing replay batch is what
sets the circuit's peak, so the narrower window lets the qubit cap
`PP_WALK_MAX_QUBITS` drop from 1259 to 1258.

With one fewer qubit, the chunked adders and split walk adds have to fit
narrower carry ladders, so Toffoli rises by 674. The score still falls by
55,542. To win back some of the λ the narrower windows cost, the commit also
switches on the multiply side's borrow predictors at every round instead of
only the wide ones. That costs no Toffoli.

## What changed and why it saves qubits

1. **`PP_FOLD_PROFILE`: `38:0,32:-1,19:-4,0:-4` → `38:0,32:-2,19:-5,0:-5`**
   (`build()`, `src/point_add/mod.rs`).
   - This is a `width:offset` band table. `pingpong::fold_offset(round)` looks up
     the band for `value_width(round)`, the walk register width at that round, and
     adds `+1` if `round < PP_FOLD_WIDEN` (242). `Plan::fold_window(round)` adds
     the result to the base window: `PP_REPLAY_FOLD_WINDOW = 53` for divide and
     `PP_REPLAY_FOLD_WINDOW_MUL = 54` for multiply.
   - The fold window is how many low bits of the replay target the fused
     `±f / +2f` correction (`fold_selected` in `replay_add_halve` and
     `replay_double_add`) ripples through. A carry that leaves the window is
     dropped. See [modular-fold](../concepts/modular-fold.md).
   - With the shipped `PP_WIDTH_SCHEDULE`, the width falls below 38 at round 616
     and below 32 at round 632. So:
     - rounds 616..631: offset −1 → −2, windows 52/53 → 51/52 (divide/multiply);
     - rounds 632 to the end: offset −4 → −5, windows 49/50 → 48/49.
   - Each bit less is one fewer ripple position, so about one Toffoli fewer per
     affected fold. The comment above `fold_shape()` gives the measured reason
     the late rounds can take it: the rate at which the fold's dropped carry
     matters collapses once the walk is narrow (0.46 of the flat rate at width
     35, 0.07 at width 21).
2. **`PP_WALK_MAX_QUBITS`: 1259 → 1258** (`build()`, `mod.rs`).
   - This is the single qubit cap. The walk's split adds (`walk_low_chunk`), the
     replay's chunked adds (`chunked_add`) and the square's `peak_fitted_add`
     all size their carry ladders as `cap − live qubits`. The head batch
     boundary (`head_boundary`) checks a modelled footprint against the same cap. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - The trailing replay batch (rounds above `PP_R2 = 648`) runs with the tape at
     full length and both walk registers collapsed. Its widest fold is the widest
     thing alive anywhere. The `PP_R2` comment in `mod.rs` puts the peak floor at
     `1210 + window` for the divide's first trailing round. Round 649 has walk
     width 24, so the window there drops from 49 to 48, and the floor from 1259 to
     1258. That is what makes the lower cap reachable.
   - The cost is the +674 Toffoli. With one less wire of room, some chunked adds
     and walk splits must use narrower ladders, which means more chunks and more
     boundary repairs. That outweighs the fold bits saved.
3. **Borrow predictors on every round** (`src/point_add/pingpong.rs`).
   - In `replay_double_add` (the multiply replay's overflow-flag "F" erase):
     `let wide = value_width(round) >= 38;` → `>= 0`.
   - In `chunked_add` (the chunk-boundary "B" erase, multiply only):
     `multiply && value_width(round) >= 38 && …` → `>= 0`.
   - `value_width` returns `usize`, so `>= 0` is always true. The effect is that
     the default `A5_REPAIR = mul-fb-seed` policy now applies on all rounds, not
     only rounds 0..615.
   - With the predictor, `erase_with_compare` passes `borrow_in = Some(bit)`,
     where `bit` is the addend bit just below the compared top-`k` window
     (`source[N-k-1]` or `addend[phi-compare-1]`). `cmp_lt_phase` uses it as the
     borrow into the window instead of assuming 0. It replaces `u[0]` as the
     first Toffoli control and adds two CNOTs, so the Toffoli count is the same.
   - Why it helps: the truncated compare is wrong only when the two windows tie.
     In a tie, the true answer is `low part of sum < low part of addend`. For
     uniform low bits, the addend's top low bit guesses that right about 3/4 of
     the time, where a fixed 0 is right 1/2 of the time. So ties fail about half
     as often, roughly one free bit of compare width. See
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
4. **Tail nonce** (`TAIL_NONCE` default in `build()`): 2886213855485 →
   230915643996243.

The comments in `mod.rs` above the cap and `PP_R2` still quote the older values
(peak 1260, windows 49 and 50). Only the pinned values changed.

## Why it is still correct, and what it risks

- **The fold narrowing is probabilistic.** On a rare input, the fold's carry
  escapes the 48-bit window, the coefficient comes out wrong by a multiple of
  `2^48`, and the run fails classically. This adds λ.
- **The predictors are probabilistic too.** They change which ties the
  compares get wrong, not whether they can be wrong. A wrong compare leaves a
  phase error, which the phase channel catches. The commit relies on them
  lowering λ overall; the code does not prove it.
- **The cap move is exact.** It only changes how adds are chunked. New chunk
  boundaries do bring new approximate boundary repairs, which add a little λ.
- The shipped nonce draws a clean test set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The qubit comes from narrowing the replay fold's truncation window on the
rounds that set the peak, which is fold/carry truncation. The cap move only
collects the qubit, and the predictors only pay back λ. The runner-up was
comparator/width truncation, because the predictors act on the truncated
compares, but they save no Toffoli and no qubits on their own.

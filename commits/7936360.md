## Summary

`build()` already ran an exact peephole, `single_ccx_fanout`, before the
dead-gate strip. It turns the pattern "CCX into `t`, copy `t` into `u`, CCX
into `t` again" into one copy plus one CCX into `u`. Deleting and downgrading
gates in the strip creates new instances of this pattern. This commit runs the
rewrite again, to a fixed point, after the strip. It finds 9 instances, so 9
unconditional CCX disappear and the emitted op count drops by 9 (9,063,839 →
9,063,830).

The measured average falls by 26 Toffoli. Only about 9 of that comes from the
circuit. The rest is the new nonce drawing a slightly cheaper test set, which
moves the average by roughly ±10–15 Toffoli. Qubits are unchanged.

## What changed and why it saves Toffoli

- **`src/point_add/mod.rs`, `build()`:** after `apply_deep_strip_identity`,
  while the strip is on (`SUB4_APPLY_STRIP` ≠ 0), loop
  `single_ccx_fanout::rewrite_first_target_fanout(ops, 96)` until it returns
  `Err`. Each pass logs a witness line. The build then asserts exactly 9 passes
  (`assert_eq!(post_strip_fanout_passes, 9, …)`), so a different op stream
  aborts the build instead of silently changing.
- **The rewrite** (existing `src/point_add/single_ccx_fanout.rs`, unchanged):
  - It looks for two unconditional `CCX(a, b → t)` with the same operands. In
    between, exactly one gate may use `t` as a control, and it must be a
    `CX(t → u)` with `u ∉ {a, b, t}`. Nothing in between may write `a` or `b`,
    touch `t` with Z/CZ/CCZ, touch any of the three with R, Hmr or a swap, or
    push or pop a condition.
  - The identity: `CCX(a,b→t); CX(t→u); CCX(a,b→t)` leaves `t` unchanged and
    does `u ^= t ⊕ ab`. That equals `CX(t→u); CCX(a,b→u)`. So both CCX are
    deleted, and one `CCX(a, b → u)`, with the CX's classical condition, is
    inserted right after the CX.
  - It leaves the last 96 ops alone (the nonce tail) and checks that they are
    unchanged.
  - Two Toffoli become one, which saves 1 per shot per rewrite (more if the CX
    was conditioned, since the new CCX then runs only under that condition). See [dead-gate-strip](../concepts/dead-gate-strip.md),
    which lists this pass under exact removals.
- **Tail nonce:** `SUB4_TAIL_NONCE` default 30008006160 → 104917482.

## Why it is still correct, and what it risks

- **The rewrite is exact.** It is a gate identity that holds on every input,
  so it adds no hard inputs.
- It does change the op stream, so the Fiat–Shamir test set changes. The new
  nonce `104917482` draws a clean set: 9,024 of 9,024 shots, 0 classical, 0
  phase and 0 ancilla failures.
- The circuit still contains the base's approximations (truncated widths and
  the census strip). λ, the expected number of failing shots per draw, is the
  base's. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
- Score accounting: 9 fewer emitted CCX, and the rest of the −26 is island
  luck. See [scoring-and-validation](../concepts/scoring-and-validation.md).

## Classification rationale

Two Toffolis around a fanout CX merge into one. That is gate/op fusion, the
class the census used when this pass was first introduced.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout d9ef3e9 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol d9ef3e9 7936360 -- src/point_add` is 44 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7936360 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `TLM_*` or
   `SUB4_*` overrides set. Expect:
   - 1154 qubits
   - 1,294,261 average Toffoli (1,294,261.151 before rounding)
   - score 1,493,577,194
   - 0 classical, 0 phase and 0 ancilla failures
5. **Nonce caveat.** The score only reproduces with the nonce `104917482` and an
   identical op stream. Any other change needs a new nonce hunt, and the
   9-pass assertion will fail if the stream changes.

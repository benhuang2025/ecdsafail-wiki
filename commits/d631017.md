## Summary

This commit changes one constant on benhuang2025's [`8d7051b`](8d7051b.md).
Each fused replay cell of the ping-pong divider ends with an overflow flag.
The circuit measures that flag out with `hmr` and then repairs the phase the
measurement left with a comparison of only the top `k` bits of the target and
source registers. This commit takes `k` from 24 to 20. Each compare bit is one
Toffoli on the roughly half of shots where the repair runs, so 4 bits on about
1,394 cells save 2,793 average Toffoli. Qubits are unchanged. The tail nonce
was re-hunted.

## What changed and why it saves Toffoli

1. **`replay_flag_compare()` default: 24 → 20** in
   `src/point_add/pingpong_div.rs` (`SUB4_PP_REPLAY_FLAG_COMPARE`).
   - It is used in the fused replay cells: `signed_mod_add_pm_halve_fused`
     (Divide) and `signed_mod_double_add_pm_fused` (Multiply). The unfused
     fallback `signed_mod_add_pm` also uses it, but it is off by default.
   - In each cell the add leaves an overflow bit, which first selects the
     fold correction. Then:
     ```
     hmr(overflow, phase)                       # erase the flag; outcome bit = phase
     cmp_lt_phase_conditioned(&target[N-20..], &source[N-20..], phase)
     free(overflow)
     ```
   - The overflow of `target + source` equals `[sum < source]`. Applying that
     comparison as a phase, only when `phase` = 1, cancels the kickback of the
     X-basis measurement. The flag value is never recomputed.
   - The compare costs `k` CCX forward and an `hmr`/`cz_if` inverse with no
     Toffoli, under `push_condition(phase)`. With the divide at 700 rounds and
     the multiply at `rounds() − 2` = 698, about 698 + 696 = 1,394 cells run.
     So 4 × 0.5 × 1,394 ≈ 2,788 Toffoli, against the measured −2,793. See
     [measurement-uncompute](../concepts/measurement-uncompute.md) and
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
   - The compare's carries are allocated only for the duration of the repair
     and are not at the peak, so qubits stay at 1278.
2. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 800188000096 → 31163008.

## Why it is still correct, and what it risks

The values are unchanged. Only the phase repair is approximate: when the top
20 bits of the sum and the source tie, the truncated compare can give the
wrong answer, and that shot keeps a stray phase. This happens about 2^−20
times per cell, 16 times as often as at 24 bits, and shows up as a **phase**
failure. So λ rises. The shipped nonce `31163008` draws a clean set:
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a truncated comparator, which is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8d7051b -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 8d7051b d631017 -- src/point_add` is
   4 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol d631017 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1278 qubits
   - 927,936 average Toffoli (rounded)
   - score 1,185,902,208
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `31163008` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

The trailmix circuit adds a 256-bit register into another, under a control, in
every apply step. The adder is cut into chunks so that its carry wires fit in
the qubit headroom `k` that the baked schedule gives that call. The base always
used chunks of width ⌊√n⌋ = 16 and then made the unchunked top part as long as
the headroom allowed. That is a heuristic, not the cheapest layout.

This commit tries every chunk width `c` and every top-part length for each
call. It keeps the layout with the lowest Toffoli count that still fits in
`k − 1` wires. It does this for the apply carry-out adder (516 calls) and for
the 48 GCD subtracts that the schedule sends to the "adaptive" branch. The
adder is still exact. It just has fewer, wider chunks. Each chunk boundary
costs a Toffoli and each chunked bit costs a conditional compare Toffoli, so
fewer chunked bits and fewer boundaries save Toffoli. Average Toffoli drops by
6,460 and peak qubits stay at 1166. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

### The adder being re-laid-out

`src/point_add/trailmix_ludicrous/gidney.rs` builds `ctrl ? (a += b)` from three
pieces. The emitted Toffoli costs below come from the code:

- **Chunks.** The low `chunked_len` bits are cut into chunks of width `c`. Each chunk
  runs `controlled_clean_add_threaded(..., cin, Some(&cy), hi − lo)`.
  - It costs 1 CCX per bit for the forward carry (MAJ) and 1 CCX per bit for the gated sum.
    The internal carries are erased by `hmr` plus `cz_if_bit`, which costs no Toffoli.
  - It costs 1 CCX per chunk for the gated boundary carry `cy = ctrl AND c_top`.
  - The chunk holds its `c` internal carry wires live at once, plus all earlier boundary carries.
- **Top part.** The remaining `plain_len` bits run as one threaded add with the last
  boundary carry as carry-in. It costs 2 CCX per bit, and holds `plain_len` carry wires plus
  the boundary carries.
- **Erasing the boundary carries.** After the top part, each boundary carry is
  erased by `controlled_erase_carry_gated`.
  - It measures the carry with `hmr`, then recomputes the comparison
    `compare_geq_cin_middle` over the chunk under `push_condition` on the outcome.
  - That costs `c` Toffoli per chunk (c − 1 CCX plus one CCZ). They are emitted, but
    they only execute when the outcome is 1, which is about half of the shots. See
    [measurement-uncompute](../concepts/measurement-uncompute.md).

The emitted cost is therefore about `2n + chunked_len + nchunks (+1 for the
carry-out)`. The executed cost is about `2n + chunked_len/2 + nchunks (+1)`. So the
fewer bits sit in chunks, and the fewer chunks there are, the cheaper the add.
The headroom limits both. The top part and the widest chunk must each fit
alongside the boundary carries. See [adders-and-carries](../concepts/adders-and-carries.md)
for chunked adders in general, and [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md)
for headroom caps.

### Old layout (base)

`adaptive_layout(n, k)` fixes `c = ⌊√n⌋`, which is 16 for n = 256. It then grows
`plain_len` while `nchunks + plain_len ≤ k`. The two callers also had special
cases:

- `controlled_hybrid_add_cout_refs` falls back to a plain Gidney add with a zero pad when
  `k < ⌈n/c⌉ + c + ADAPTIVE_RES`, `k + 2c ≥ n`, or `plain_len = 0`. It uses
  `controlled_chunked_then_cuccaro` when the headroom is tight.
- `controlled_hybrid_add_adaptive_refs` uses a plain Gidney add when `n ≤ 4` or
  `k + 2c ≥ n`. Under tight headroom it uses a shrinking staircase of chunks or chunked-then-Cuccaro.

### New layout search

The new functions are in `gidney.rs`:

1. **`searched_cout_layout(n, k)`**. It is enabled by `TLM_COUT_LAYOUT_SEARCH`, with
   margin `TLM_COUT_LAYOUT_MARGIN`, default 1.
   - It loops `c = 1..=n` and `plain_len = 1..=n`, with `chunked_len = n − plain_len` and
     `nchunks = ⌈chunked_len / c⌉`.
   - It rejects a layout unless `nchunks + plain_len + margin ≤ k` (the top part fits) and
     `nchunks + min(c, chunked_len) + margin ≤ k` (the widest chunk fits).
   - It keeps the first layout with the lowest `2n + chunked_len + nchunks + 1`.
   - `controlled_hybrid_add_cout_refs` now calls it first. If a layout is found,
     `emit_cout_layout` builds it with the same three pieces and the same erase as the
     base's chunked path, and the function returns. Otherwise the old code runs unchanged.
2. **`searched_gcd_adaptive_layout(n, k)`**. It is enabled by `TLM_GCD_ADAPTIVE_LAYOUT_SEARCH`,
   with margin `TLM_GCD_ADAPTIVE_LAYOUT_MARGIN`, default 1.
   - It is the same search, with cost `2n + chunked_len + nchunks − 1`, because there is no carry-out.
   - `controlled_hybrid_add_adaptive_refs` calls it first and builds the result with
     `emit_adaptive_layout_no_cout`, which threads a zero `cin0`.
   - The GCD subtract only reaches this function when the baked `GCD_BRANCH` entry is
     2. That is 48 of 1,032 calls; 640 are branch 0 (plain) and 344 are branch 1 (varchunk),
     and neither of those is touched.
3. **`adaptive_chunk_size(n)`**. It reads `TLM_ADAPTIVE_CHUNK` and otherwise returns ⌊√n⌋.
   Only the cout fallback path uses it. Nothing sets that variable, so this edit
   has no effect.

`src/point_add/mod.rs`, `build()`: three new `set_default_env` lines,
`TLM_COUT_LAYOUT_SEARCH=1`, `TLM_COUT_LAYOUT_MARGIN=1` and
`TLM_GCD_ADAPTIVE_LAYOUT_SEARCH=1`. They bake the search into the env-less grader
build.

**Worked example** (apply add, n = 256, k = 78; `APPLY_COUT_K` has twelve entries
with this value). The arithmetic is mine:

- Old: c = 16, with `plain_len` 66, `chunked_len` 190 and 12 chunks. The chunk part
  costs `190 + 12 = 202` emitted and `95 + 12 = 107` executed Toffoli.
- New: c = 61, with `plain_len` 74, `chunked_len` 182 and 3 chunks (61, 61, 60).
  It needs `3 + 74 + 1 = 78 ≤ k`. The chunk part costs `182 + 3 = 185` emitted and
  `91 + 3 = 94` executed Toffoli.
- That is 13 executed Toffoli saved on this one call. Similar savings over the 516
  apply calls account for most of the −6,460.

**Tail nonce.** The default `DIALOG_TAIL_NONCE` in `build()` goes from 40003939 to
100000004549. Two more copies change in `configure_ecdsafail_submission_route()`,
but that function is only reached from the old dialog entry `build_builder()`,
so those edits are dead.

## Why it is still correct, and what it risks

The new layouts are exact. Every boundary carry is erased with a full-width
comparison over its chunk, `controlled_erase_carry_gated` and not the `_capped`
variant. The internal carries are erased by measurement plus a phase fix, as in
the base. So the adder computes `a += ctrl·b` with the right carry-out on every
input, and the measured erases leave no phase garbage.

The risk is peak qubits. The search trusts that the scheduled `k` really is the
free headroom at that call. The margin of 1 keeps one wire spare. The measured
peak is 1166, the same as the base, so the layouts fit.

There is one side effect I could not quantify without running the build. The
plain Gidney path, `controlled_hybrid_add_refs`, reads one entry of the baked
`HYB_V` vent-count list each time it runs. Any call that used to fall through to
that path, and now takes a searched layout, no longer advances the cursor. Every
later plain call then reads a shifted vent count. That does not affect the value,
since a vent count only chooses between a measured erase and a re-Toffoli, but it
changes Toffoli and wire use slightly.

The circuit's approximations are the usual trailmix ones: `ITERS`, `SCHED_J2`,
`GAP_J2` and the truncated folds. This commit does not change them. Because the
op stream changed, the nonce was re-hunted. The shipped nonce 100000004549 draws
a clean set: 0 classical, 0 phase and 0 ancilla failures over 9,024 shots. A bad
erase would show up as a phase or ancilla failure. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as fold/carry truncation, but nothing is truncated.
Every carry is still computed and erased exactly. The change re-chooses the
chunk geometry of an exact chunked adder per call, under a qubit cap. That fits
**Windowing → windowed carry/shift blocks** better, with Strength Reduction →
fast-adder reroute as the runner-up. The header keeps the published label.

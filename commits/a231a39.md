## Summary

The package is called "r6a_dpark" in `mod.rs`. It has three parts.

1. **Square-side fold fusions** (`PP_J_WCIN`, `PP_J_WCIN_B0LAST`,
   `PP_J_BMERGE`, `PP_J_SFUSE_B`).
   - The square `x −= y²` folds its high limbs with `f`, which is written as
     the five NAF terms `1 + 2^4 − 2^6 + 2^10 + 2^32`.
   - The rotated folds stop folding their own carry with a separate 58-bit `f`
     ladder. The carry rides as carry-in on the NAF windows instead.
   - The B branch's four shifted folds share one set of windows.
   - The B branch's last subtract hands its borrow to the multiply walk's
     round-0 lift, which absorbs it the way `PP_J_XFUSE` did for `coord_x_sub`
     in [`b2d9103`](b2d9103.md).
2. **`PP_U_DPARK`.** The multiply replay's doubling cell shifts one bit off the
   top. That bit now waits in `target[0]` instead of on a fresh wire, so every
   chunk ladder of the cell has one more wire of room.
3. **A re-derivation of the schedule pins** for the new circuit: the width
   schedule, `I41_ROUNDS`, `PP_N_BADJ`, the I12 batch profiles, the I35 bridge
   profile, `PP_HEAD_MUL` and `PP_FOLD_PROFILE`.

The net effect is 859 fewer average Toffoli at the same 1250 qubits.

## What changed and why it saves Toffoli

### 1. Square fold fusions (`src/point_add/square.rs`, `j_fuse.rs`)

Background: [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md)
and the NAF-fold section of [modular-fold](../concepts/modular-fold.md).

`sub_square` computes `x −= y²` with Karatsuba: `y = a + b·2^128`, and
`A = a²`, `B = b²` and `C = (a+b)²` are each built by `with_square`. Each
branch's product is folded into `x`.

- `fold_rotated(low, high)` handles a product whose high limb wraps past
  2^256. It rotates the limb into the low positions and runs a full
  `mod_addsub`, which is a ripple, an `f` fold of the carry over `f_slice = 58`
  bits, and a 24-bit erase compare. Then it runs four `window_add`s of `high`
  at shifts 4, 6, 10 and 32 for the remaining `(f − 1)·high`.

**`PP_J_WCIN`: the carry rides the windows** (`fold_rotated_wcin`)
- `wcin_ripple` does the add (`peak_fitted_add`) and keeps the carry `c` live.
  The value is then `D ± c·f`.
- `wcin_windows` runs the four NAF window adds with `c` as their carry-in.
  A carry-in at shift `s` adds `c·2^s`, so the four windows together add
  `c·(2^4 − 2^6 + 2^10 + 2^32) = c·(f − 1)` at no extra cost. If the room
  under the cap is one wire short of the window's owned carries, position 0
  uses an in-place Cuccaro MAJ/UMA pair instead: one extra CCX for one fewer
  wire.
- `wcin_finish` adds the remaining unit term `c·1` with a narrow increment of
  `PP_J_WCIN_W` bits. That pin is unset, so the default `FOLD_GUARD + 1 = 26`
  bits applies. Then it erases `c` with the unchanged 24-bit top compare. An
  assert makes sure that no window reaches those 24 bits.
- So a 58-bit `f` ladder becomes a 26-bit increment. This applies to every
  rotated fold: A's and B's `2^128` folds, C's fold, and the `2^32` fold below.

**`PP_J_SFUSE_B` with `PP_J_WCIN_B0LAST`: B runs last and hands its borrow to the multiply**
- `sub_square` now runs A, then C, then B. Before it ran A, B, C.
- Inside B's `with_square`, the order is:
  1. The `2^128` fold.
  2. The four shifted folds of `B·f` (see BMERGE below).
  3. Last, the plain shift-0 subtract `x −= B`, through `sub_keep_borrow_q`.
     That subtract keeps its borrow `c` and does not fold it.
- `pingpong::j_pre_round0` then runs the multiply walk's round 0 right there,
  inside the square. It uses `round0_forward_fused` (from `b2d9103`), whose
  lift arms absorb the borrow's `−f`. Then `erase_q_carry` erases `c` against
  `b2`'s top 24 bits, which are still live inside `with_square`.
- The three envelope wires and `a0` are stashed in `PRE_R0` and `PRE_A0`. The
  multiply's `pingpong` and `walk_round_phase(0)` pick them up instead of
  running round 0 again.
- `Builder::set_avoid` makes the early round 0's fresh allocations skip the
  wires `with_square` has lent out (`SQ_LOANS`), because those must come back
  with the same identity. The comment says B's inverse has room for the four
  wires the early round 0 leaves standing.
- Saving: B's last `f` ladder disappears into the lift.

**`PP_J_BMERGE`: one window set for B's four shifted folds** (`b_merged_folds`)
- `B·2^256 = B·f` needs folds of B at shifts 0, 4, 6, 10 and 32. The base ran
  each shifted fold as a `fold_rotated`, and each one ran its own four windows
  of `(f−1)·high_s`, where `high_s` is B's top `s` bits.
- The `high_s` are nested prefixes of the same top bits, and their window
  terms all carry sign `−`, except the `2^6` one. So together they are
  `−(f−1)·R` with `R = high32 + high10 − high6 + high4`, where
  `0 ≤ R < 2^33`.
- The new code works in four steps:
  1. It runs the three small folds' unit terms as plain `mod_addsub`s of
     `rotate_by(b2, s)`. These keep their own carry fold.
  2. It runs the `2^32` fold's ripple through `wcin_ripple`.
  3. It builds `R` in scratch: 11 wires for `high10 − high6 + high4`, then 33
     wires for `R`. Then it runs one set of four windows over `R`, with the
     `2^32` carry riding in.
  4. It unbuilds `R`, then runs `wcin_finish`.
- So 16 window adds become 4, at the cost of building and unbuilding a 33-bit
  `R`.

### 2. `PP_U_DPARK`: park the doubled-out bit (`pingpong.rs`, `joint_lowfold.rs`)

- **Before:** `replay_double_add_impl` (the multiply replay cell,
  `T ← 2T ± S mod p`) began with `start_doubling`. That moves the top bit to a
  fresh wire `doubled_out`, which stays live across the whole chunked add.
- **After:** with `PP_U_DPARK = 1`, the code only runs `rotate_up`, so the top
  bit lands in the vacated `target[0]`.
  - After `cx_all(sign, target)` that wire holds `d XOR sign`. The prebias add
    then also XORs `source[0]` into it, giving `d XOR sign XOR source[0]`. The
    prebias add never reads bit 0 as an operand.
  - At the fold, `joint_lowfold::try_replay` takes `d` back out onto its own
    wire with three CX.
  - In the fallback path, it is taken out before the add when there is no
    prebias, or after the add when there is.
- **Why it saves Toffoli:** one wire fewer is live during every chunk ladder
  of the doubling cell, at the same cap. The ladder planners (`plan`,
  `composition_bounds`, `retained_rebalance`, `drop_exact_lead`) can then pick
  wider chunks, which means fewer or cheaper approximate boundary repairs. The
  planners reserve one wire for re-extracting `d` at the fold.
- **`PP_U_DPARK_BEST`:** the code also plans a "shadow" layout, made as if `d`
  still held a wire (`DSHADOW`). It keeps whichever layout is cheaper, where
  the cost is the sum of `(k − 1)/2` over the boundary compares minus the fold
  saving.
- **`PP_U_C0WIDE`:** this needs `PP_PREBIAS_DOUBLE`, which is pinned on. Chunk
  0 then has no carry-in and one wire of slack, so the code also tries a
  candidate with every inner boundary moved up one bit, and keeps the cheapest
  candidate.

### 3. Re-derived pins (`src/point_add/mod.rs`, new "r6a_dpark" block)

The old arms are deleted from earlier blocks so that no key appears twice.

- **`PP_WIDTH_SCHEDULE`:** 37 rounds change. 31 get one bit narrower and 6 get
  one bit wider, a net −25 bit-rounds.
- **`I41_ROUNDS`:** still 62 rounds, 14 of them replaced. Ten move up by two
  rounds (43→45, 50→52, 72→74, …, 536→538) and 629 moves to 633. 158, 513 and
  518 are new, and 516, 599 and 624 are gone.
- **`PP_N_BADJ`:** three widening rules are added. `400-449:d:+2` is placed
  first, so it beats the existing `350-553:d:+1` on those rounds. The other two
  are `250-349:d:+1` and `350-399:m:+1`. All three are λ buy-backs: wider
  boundary compares.
- **`PP_FOLD_PROFILE`:** `19:-4 → 19:-3`. Replay rounds whose walk width is
  19–31 get one more fold-window bit, which is another buy-back.
- **`PP_HEAD_MUL`:** 403 → 413. The multiply's leading replay batch covers 10
  more rounds.
- **`I12_DIV_PROFILE`, `I12_MUL_PROFILE`:** these choose which mid rounds
  batch their walks before their replays, and they are re-derived.
  **`I35_PROFILE`:** the per-(round, direction) bridge budget goes from 83 to
  82 entries, with a new placement.
- `TAIL_NONCE`: 28949644005 → 29190082163.
- Smaller edits: `modular::peak_fitted_add` becomes `pub(super)`, and
  `Builder` gains `avoid_ids` and `set_avoid`.

## Why it is still correct, and what it risks

- **The fusions are exact rewrites up to the existing fold truncation.**
  - WCIN adds exactly `c·f`, split across carry-ins and the unit increment.
  - BMERGE adds exactly `−(f−1)·R`, and `R` is rebuilt and unbuilt exactly.
  - SFUSE_B moves an exact identity, `a = D − c·f`, into the lift.
  - The remaining approximations are of the same kind as before. The windows
    keep `FOLD_GUARD` headroom. The unit increment is truncated at 26 bits, so
    a carry escapes with probability about 2^-26, where the 58-bit ladder it
    replaces lost one with about 2^-25. The erase compares read the same top
    24 bits, which the asserts keep clear of every window.
- **DPARK is exact.** The bit is stored XOR-masked by wires whose values are
  known, and it is extracted with CX gates.
- **The layout changes (DPARK, C0WIDE, I35, I12) are probabilistic.** They move
  which approximate chunk-boundary compares exist.
- **The schedule and BADJ narrowings are probabilistic.** The BADJ and fold
  widenings buy λ back.
- **Measured λ.** The package comment reports λ = 16.336 ± 0.253 on a gate set
  of 256 nonces and 16.590 ± 0.255 on a holdout set of 256. The pooled value is
  16.463 ± 0.179, with a mean T of 889,202.1. The author's gate is
  "estimate + 2 SE ≤ 18".
- **Channels.** A dropped fold carry or a width overflow gives a classical
  failure. A wrong boundary compare gives a phase failure.
- The shipped nonce `29190082163` draws a clean test set: 9,024 of 9,024 shots
  pass, with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The new constructions merge fold ladders and carry chains across operation
boundaries. A carry rides into the next windows, four window sets become one,
and the square's last borrow goes into the multiply's lift. That is gate/op
fusion, the same family as `b2d9103`. DPARK is a parking trick (register
allocation), and the pin re-derivation is truncation tuning. Both are
secondary in the same package. The code does not report how the 859 Toffoli
split between the three parts.

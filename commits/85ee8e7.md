## Summary

Two default constants change. The main one is `KAL_WTRUNC_K0`, the number of
Kaliski iterations that run at full 256-bit width before the fitted width
envelope starts to shrink. It goes from 22 to 21, so from iteration 23 on the
clipped loops of the GCD walk are one bit narrower in two of every three
iterations, in all four Kaliski runs. The second is the shift22 carry-tail
window from [`1b913c5`](1b913c5.md), which goes from 37 to 33 (cut 70 → 66).
It saves only about 48 Toffoli. Its real role is to re-roll the test draw:
`K0 = 21` failed on the old draw and is clean on this one. Together they save
4,442 average Toffoli at the same 2309 qubits.

## What changed and why it saves Toffoli

**Background: Kaliski inversion and W-TRUNC.** This era computes `dx^-1` with
a reversible Kaliski (binary extended GCD) inversion, run four times per point
addition (pair1 and pair2, each forward and backward, about 400 iterations
each). Each iteration tests `v_w == 0` (an OR chain), compares `u > v_w`,
conditionally swaps `(u, v_w)` and `(r, s)`, subtracts, halves and doubles. The
values `u` and `v_w` shrink as the walk proceeds. `kal_wtrunc_width(iter, n)`
in `src/point_add/kaliski_state.rs` therefore clips every Toffoli-bearing
width loop to

```
env(it) = n                           for it < K0
env(it) = n - floor((it - K0) * 2/3)  for it >= K0
width   = min(n, env(it) + MARGIN)    (MARGIN = 0 here)
```

The envelope is fitted to 80k random inputs. The clipped loops are the STEP-0
OR chain, the STEP-2 comparator, the STEP-4 load/subtract/add loops and, since
the CSWAP W-TRUNC lever, the `(u, v_w)` Fredkin swaps. Bits above the width
are assumed zero and are not touched. See [`e739b53`](e739b53.md) for the
first margin cut, and
[kaliski-almost-inverse](../concepts/kaliski-almost-inverse.md) for the inversion.

1. **`kal_wtrunc_k0()`: 22 → 21** (`kaliski_state.rs`).
   - With `x = it − K0`, `floor(2x/3)` grows by 1 at two of every three steps
     of `x`. Shifting `K0` down by one therefore makes `env(it)` one bit
     smaller at about two thirds of the iterations from 23 on, and never wider.
   - The envelope stays below the provable bound (`n` for `it < n`,
     `2n − it` after) for the whole walk, so the narrowing applies through the
     last iteration (399 for pair1, 397 for pair2).
   - About 250 narrower iterations per run, four runs, a few Toffoli per bit
     across the clipped loops: that is the roughly 4,400 Toffoli saved.
2. **`shift22_carrytail_cut()`: `SHIFT22_CARRYTAIL_W` 37 → 33**
   (`src/point_add/solinas.rs`). The carry chain of the four direct `±c`
   steps in each shift22 pair now has 66 positions instead of 70. That is
   4 × 4 = 16 Toffoli per pair, about 48 over the three executed pairs. The
   chain still reaches 33 bits above `c`'s top bit, so in practice it is
   exact.

## Why it is still correct, and what it risks

- **K0 = 21 is probabilistic.** At margin 0 the clip sits exactly on the
  fitted envelope. An input whose `u` or `v_w` is longer than `env(it)` at
  some iteration has its high bits ignored. The comparator can then pick the
  wrong branch or a subtraction can drop a borrow, which gives a wrong
  inverse (classical mismatch) or a dirty register (phase or ancilla failure).
  Starting the decay earlier makes such inputs more likely.
- **The shift22 window is exact in practice.** A carry is dropped only if
  bits 33…66 of the value are all ones, about 2^-34 per call.
- **Island.** There is no tail nonce in this era. The test set is a hash of
  the op stream, so the shift22 window acts as the re-roll knob. The author's
  note says `K0 = 21` was rejected on the `W = 37` draw, and that neighbours
  (`K0 = 20`, carry-tail `W` of 18 or 19, other `R_SMALL` values, shift22
  windows 30 and 35) all fail. The shipped stream is clean: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
- The code comment above `kal_wtrunc_k0()` still describes K0 = 25. Only the
  default literal changed.

## Classification rationale

The saving comes from narrowing the GCD-walk loops to fewer bits, which is
comparator/width truncation. The shift22 window change is a fold/carry
truncation in name, but it saves almost nothing and is there to re-roll the
draw.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 1b913c5 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 1b913c5 85ee8e7 -- src/point_add` is
   4 lines in 2 files.

   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 85ee8e7 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `SHIFT22_*` or `LOWQ_*` environment variables set. Expect:
   - 2309 qubits
   - 2,414,390 average Toffoli (rounded)
   - score 5,574,826,510
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with an identical op stream. There is no nonce in
this era, so any other change draws a different test set.

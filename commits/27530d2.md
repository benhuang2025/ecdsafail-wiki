## Summary

This repeats [`1846bf7`](1846bf7.md)'s one-bit cut on the newer tree. Here
the GCD swap comparator is fused ([`9b6b9d6`](9b6b9d6.md)) and its width
comes from a per-step table ([`f8a36ba`](f8a36ba.md)). The global cap
`DIALOG_GCD_COMPARE_BITS` goes from 63 to 62. The cap now binds only on steps
where the table plus its margin and the register width are both at least 63.
That is 207 of the 399 steps. Each of those steps loses one Toffoli at each of
its 4 fused comparator sites, so the saving is 207 × 4 = 828 Toffoli. Qubits
are unchanged. The reroll goes from 5 to 0.

## What changed and why it saves Toffoli

Both edits are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

- **`DIALOG_GCD_COMPARE_BITS`: 63 → 62.**
- **`DIALOG_REROLL`: 5 → 0.** The number of identity `X;X` pairs on `tx[0]`
  that reseed the test set. The comment above it is rewritten.

`dialog_gcd_compare_bits_for_step` now returns

```
k(step) = max(1, min( min(COMPARE_BITS, w), min(max(table[step] + 8, 1), w) ))
```

where `w = active_width(step)` and `table` is
`DIALOG_GCD_PA9024_COMPARE_SCHEDULE`. Lowering `COMPARE_BITS` changes `k`
only on steps where the other two terms are both at least 63. Those are 207
steps, all between step 54 and step 313. On each of them the table entry is
55 or more and the width is still above 62. Each fused comparator call costs `k + 1`
CCX. The walk runs forward and in reverse in both GCD pairs, which gives 4
calls per step. So the saving is 207 × 4 = 828, exactly the measured drop.

## Why it is still correct, and what it risks

A narrower compare misjudges `u > v` when u and v agree on all of their top
`k` bits. The walk then takes the wrong branch, and the result is a classical
failure. Removing one bit about doubles the chance of that tie on the 207
steps it affects, so Lambda goes up slightly. Reroll 0 draws a clean set for
the new op stream: 0 classical, 0 phase and 0 ancilla failures over 9,024
shots.

## Classification rationale

One comparator-window knob is narrowed, so this is comparator/width
truncation. The reroll is the routine re-seed that comes with every change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f8a36ba -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol f8a36ba 27530d2 -- src/point_add` is
   10 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 27530d2 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1698 qubits
   - 1,703,258 average Toffoli (rounded)
   - score 2,892,132,084
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 0 and an identical op stream.
Any other change needs a new reroll search.

## Summary

The ping-pong divider's endpoint steps add or subtract one of two small
constants under a control: `f = 2^32 + 977` or `f − 1`, where
`p = 2^256 − f`. The ripple carry of such an add starts at bit 0. When the
constant's low bits are 0, or when the caller knows the first carry must be
0, the first few carry wires are 0 on every input. Their Toffolis compute 0
into 0.

This commit adds constant-add helpers that work out, from the constant and
one caller-supplied fact, how many low carries are dead, and simply leave
them out: no ancilla, no CCX, no measured erase. Five endpoint call sites
switch to them, each saving 3–4 Toffoli. The total is −30 Toffoli at 1279
qubits. The change is exact.

## What changed and why it saves Toffoli

### `src/point_add/arith/const_arith.rs` (+181 lines)

- **`dead_low_carry_run(c, last, first_carry_is_zero)`.** The ripple is
  `k[i] = MAJ(a_i, c_i·ctrl, k[i−1])` with `k[−1] = 0`.
  - `k[0]` is identically 0 if the constant's bit 0 is clear, or if the
    caller passes `first_carry_is_zero = true`.
  - Once `k[i−1] = 0`, a clear constant bit gives `k[i] = 0` too.
  - The function returns the length of that run, capped at `last`.
- **`cadd_nbit_const_direct_trunc_fast_dead_low`** and
  **`csub_nbit_const_direct_trunc_fast_dead_low`** are copies of the
  existing truncated constant add and subtract.
  - They allocate carries only for positions `dead..=last`.
  - They treat a carry-in from a dead position as absent.
  - They skip the forward CCX and the `hmr` + `cz_if` erase for every dead
    position.
  - If `dead = 0`, they fall back to the old function.

### `src/point_add/pingpong_div.rs`: five call sites

Bits of the constants: `f = …1111010001` (bits 1–3 clear), and
`f − 1 = …1111010000` (bits 0–3 clear).

| call site | constant | `first_*_is_zero` | why the first carry is 0 | dead positions |
|---|---|---|---|---|
| `conditional_mod_negate` (subtract) | `f − 1` | false | bit 0 of the constant is clear | 4 |
| `mod_halve_pm` (subtract, control `parity`) | `f` | true | `parity` is a CX copy of `target[0]`, so `!a_0·ctrl = 0` | 4 |
| `mod_double_pm` (add, control `overflow`) | `f` | true | the preceding shift leaves `target[0] = 0`, so `a_0·ctrl = 0` | 4 |
| `seed_round_one` (subtract, window 32) | `f − 1` | false | bit 0 clear | 4 |
| `seed_round_one_inverse` (add, window 32) | `f − 1` | false | bit 0 clear | 4 |

For `f − 1`, position 0 had no CCX anyway (clear bit, no carry-in), so 3 CCX
are saved per call. For `f`, 4 are saved. These run once or twice per
traversal at the start and end of the replay (rounds 0–1 and the terminal
negates), about ten calls per point addition. That is roughly 30–35 Toffoli,
executed on every shot. The measured change is −30. The carry ancilla block
of each call also shrinks by 4, but these calls are not where the peak sits
in this tree, so qubits stay at 1279. See
[adders-and-carries](../concepts/adders-and-carries.md) and
[modular-fold](../concepts/modular-fold.md).

### `src/point_add/mod.rs`

The default `SUB4_PINGPONG_TAIL_NONCE` goes from 3004060 (the base) to
320004246.

This is the same elision odinfree shipped in `8910bd1` on an older tree
(`adec6f4`). This commit ports it to the `f3b2f1f` line, which did not have
it.

## Why it is still correct, and what it risks

- **Exact.** Every removed gate writes 0 into a wire that is 0 on every
  basis state.
  - The constant-bit facts are structural.
  - The two call-site facts hold by construction in the code just above each
    call: `b.cx(target[0], parity)` makes the copy, and the shift loop clears
    `target[0]`.
  - The circuit computes the same function on every input, and no hard
    inputs are added.
- The op stream changes, so the test draw is re-rolled. The shipped nonce
  `320004246` draws a clean test set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
- Against the frontier `11f5d9a` the gain is only −6 T, because that commit's
  nonce had already found a draw 24 T cheaper than `f3b2f1f`'s.

## Classification rationale

The removed gates are dead because of facts known when the circuit is built:
the bits of the fixed constants and two operand relations at the call sites.
Specializing the adder on them is host-derived / classical specialization,
not a statistical truncation. The runner-up is dead-gate removal, but nothing
here is census-mined. [dead-gate-strip](../concepts/dead-gate-strip.md) lists
this commit among the exact source-level removals.

   environment variables set. Expect:
   - 1279 qubits

   - score 1,207,502,621
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `320004246` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

The author re-applies their own lever from [`fe29b53`](fe29b53.md) to the new
frontier. Each dialog-GCD step decides `u > v` from only the top few bits of
the two registers, and this commit lowers the global cap on that comparison
from 59 to 58 bits. The cap binds on 238 of the 399 steps, and the comparison
runs four times per step at one Toffoli per bit, so it saves
4 × 238 = 952 Toffoli. Qubits are unchanged. The reroll pair was re-searched
to (14, 4).

`fe29b53` had made the same change on mpjunior92's `40574d3` line. The
frontier then moved to 10d9e's `287595e` and bxue-l2's `df83d16` → `46c3e3a`,
which still had 59, so the lever had to be re-shipped with a new reroll.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_COMPARE_BITS`: 59 → 58.**
   - The branch bit `b0_and_b1 = b0 AND (u > v)` decides each step's
     conditional swap. `u > v` is computed by
     `dialog_gcd_cmp_gt_truncated_into_width` with `ccx_cmp_lt_into_fast` on
     the top `compare_bits` bits of the active registers, at one Toffoli per
     bit (carries cleared by `hmr` + `cz_if`).
   - `dialog_gcd_compare_bits_for_step` returns
     `min(SCHEDULE[step] + 5, active_width, DIALOG_GCD_COMPARE_BITS)`. With the
     baked 399-entry `DIALOG_GCD_PA9024_COMPARE_SCHEDULE`, margin 5 and
     `DIALOG_GCD_WIDTH_MARGIN=27`, the summed widths go from 20,010 to 19,772
     bits: steps 54 to 318, 238 bits in all.
   - The comparison runs in the forward and reverse transcript passes of both
     GCD pairs: 4 × 238 = 952 Toffoli.
2. **Reroll pair: `DIALOG_REROLL` 17 → 14, `DIALOG_POST_SUB_REROLL` 56 → 4.**
   Identity `X;X` counts that re-draw the 9,024 test inputs without changing the
   circuit (see [`ecbf87b`](ecbf87b.md)).

The comments above both knobs and above `KARA_FREE_Z1_TOPBIT` are updated.

## Why it is still correct, and what it risks

The truncated comparison is approximate. When `u` and `v` agree on their top
58 active bits it can give the wrong `u > v`. The step then takes the wrong
branch, the transcript no longer matches the true GCD, and the quotient or
product comes out wrong. That shows as a classical failure, or as phase or
ancilla garbage if the uncompute no longer mirrors the forward pass. One bit
fewer roughly doubles the per-step risk on 238 steps, so λ grows.

The reroll pair (14, 4) draws a clean set: 9,024 of 9,024 shots pass with
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a narrower comparator, so comparator/width
truncation fits. (The same change in `fe29b53` was published as in-place
mutation; this one has the better label.)

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 46c3e3a -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 46c3e3a 47f30d4 -- src/point_add` is 22 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 47f30d4 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1542 qubits
   - 1,681,207 average Toffoli (rounded)
   - score 2,592,421,194
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=14`,
`DIALOG_POST_SUB_REROLL=4` and an identical op stream. Any other change needs
a new reroll search.

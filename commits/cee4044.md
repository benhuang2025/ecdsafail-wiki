## Summary

This commit re-balances four knobs at the same 1309 qubits. One of them is
an exact Toffoli saving. The controlled 257-bit add and subtract in the GCD
apply is split into five chunks, and the carry left at each chunk boundary
is cleared afterwards by a comparison over the whole prefix below it. Moving
the last boundary from bit 190 down to bit 165 shortens that prefix
comparison by 25 bits on each of the 518 apply adds. It also makes the final
chunk 25 bits longer, which gives some of the saving back.

The other three knobs all make the circuit *more* robust and cost Toffoli:

- the GCD gets one step back (258 → 259);
- the apply double/halve carry window is widened by 3 bits (21 → 24);
- the walk's width envelope shrinks a little more slowly (slope 1.014 → 1.013).

These lower λ, so a clean nonce is easier to find. The net is −1,155
average Toffoli.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_APPLY_CHUNKED_F_CUT4`: 190 → 165** (the saving, exact).
   - The apply's controlled modular add and subtract
     (`dialog_gcd_cmod_{add,sub}_materialized_pseudomersenne_chunked`) do
     their raw 257-bit ripple through `dialog_gcd_add_ctrl_chunked_low_to_ext`
     and its subtract mirror. The route has `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS=5`
     and `..._CUSTOM5=1`, so `dialog_gcd_chunk_hi` cuts at `CUT..CUT4` =
     50, 100, 150 and now 165, with a final chunk up to bit 257.
   - Each non-final chunk loads the gated source slice (`ctrl ∧ src[lo..hi]`)
     onto fresh wires, ripples it into `acc` with `cuccaro_add_fast`, clears
     the load with `hmr`, and keeps its carry-out `cout`. Only one chunk's
     load is live at a time, which is what keeps the apply phase below the
     peak.
   - The boundary carries are cleared afterwards in one fused sweep,
     `ccx_cmp_lt_into_fast_prefix_targets_split` (`..._FUSE_BOUNDARY_CLEARS`
     is on by default, split at `DIALOG_GCD_APPLY_BOUNDARY_SPLIT=100`). The
     sweep compares `acc[..p]` with `src[..p]` up to the last boundary
     `p = CUT4`, about one Toffoli per bit, and taps each boundary on the
     way. A smaller `CUT4` makes this sweep 25 bits shorter.
   - The final chunk (`DIALOG_GCD_APPLY_FINAL_WINDOWED_FAST_BLOCKS=2`,
     `cuccaro_add_fast_windowed_low_to_ext`) grows from 67 to 92 bits. It is
     split in two halves, and its internal boundary is cleared by a compare
     over its lower half. That compare grows by about 12 bits.
   - So the net is about −12 Toffoli per apply add or subtract, roughly
     −6,500 over 518 calls. This is an estimate. The prefix compare is
     exact for any cut, as the route's own comments say ("full cuccaro +
     exact [..F_CUT] clear").
2. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 258 → 259.** This reverts
   [`76fdaf2`](76fdaf2.md), which had measured −2,949 for removing the step.
3. **`KAL_DOUBLE_CARRY_TRUNC_W`: 21 → 24.** The fused K=2 apply double and
   halve ([`8a47cf5`](8a47cf5.md)) each truncate their fold ripple at
   `33 + W`. Three more carry positions cost 3 Toffoli per call, about
   +1,550 over 518 calls.
4. **`DIALOG_GCD_WIDTH_SLOPE_X1000`: 1014 → 1013.** The width envelope is
   `active_width(step) = 256 − slope·step + 10`, rounded up to an even
   number. A smaller slope keeps it wider. Replaying the formula, the summed
   width per walk grows by 30 bits, so this costs a few hundred Toffoli over
   the four walks. The new comment says this and the cut "reclaim more
   Toffoli". For the slope that is backwards: it is a loosening.
5. **`DIALOG_TAIL_NONCE`: 264497 → 4596.**

Adding the estimates gives about −6,500 + 2,950 + 1,550 + 400 ≈ −1,600,
against the measured −1,155. The diff does not separate the parts any more
precisely.

## Why it is still correct, and what it risks

- **The cut move is exact.** Any cut gives the same sum, and every boundary
  carry is cleared exactly by the full prefix comparison.
- **The other three changes lower the failure rate.**
  - The 259th step lets inputs that need it converge.
  - The 24-bit window makes a dropped fold carry 8 times rarer than at 21.
  - The wider envelope makes it less likely that a live bit of `u` or `v`
    sits above `active_width`.
- So λ is lower than in the base. The new nonce `4596` draws a clean set:
  9,024 of 9,024 shots, with 0 classical, 0 phase and 0 ancilla failures.
  See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is comparator/width truncation. The only change that
saves Toffoli, though, is an exact move of a chunk boundary, which shortens
a comparator because the chunk layout changed, not because any comparison
was truncated. The two width-type knobs (window and slope) were both
*loosened*. A better fit would be a chunk-layout re-balance, for example
Register and Scratch Allocation, or an "adder chunking" change-type. Within
the existing label set, comparator/width truncation is defensible only
because a comparator became shorter.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 639f12c -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 639f12c cee4044 -- src/point_add` is
   19 lines in 1 file, `mod.rs`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol cee4044 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*` or `DIALOG_*` environment variables set. Expect:
   - 1309 qubits
   - 1,515,788 average Toffoli (rounded)
   - score 1,984,166,492
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=4596` and an identical op
stream. Any other change needs a new nonce hunt.

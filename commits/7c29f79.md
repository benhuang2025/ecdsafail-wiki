## Summary

The dialog GCD runs a fixed number of steps on every input, and the number has
to cover the slowest-converging input in the test draw. This commit cuts that
number from 399 to 398. One GCD step costs 2,056 Toffoli across all the passes
that loop over the steps (the forward and reverse transcript passes and the
apply passes of both GCD pairs), so dropping it saves 2,056 Toffoli. Qubits are
unchanged, because the transcript is stored in 3-step blocks and 398 steps
still need ⌈398/3⌉ = 133 blocks, the same as 399. A new reroll pair, (14, 2),
was found for the changed op stream.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 399 → 398.**
   - `dialog_gcd_active_iterations()` reads it (at most
     `DIALOG_GCD_MAX_ITERATIONS = 402`). Every step loop in the dialog GCD runs
     `for step in 0..dialog_gcd_active_iterations()`, forward or reversed: the
     transcript pass that records the branch bits `b0` and `b0_and_b1` into the
     compressed log, its reverse, and the apply passes that replay the
     transcript on the Bézout registers.
   - The dropped step is the last one, step 398. There the GCD registers are at
     their narrowest (`dialog_gcd_tobitvector_active_width(398)` is 2 bits), so
     its transcript part is cheap. Most of its 2,056 Toffoli are the apply
     pass's full-width controlled modular add and subtract on the Bézout
     registers.
   - **Qubits.** The log is packed by the round763 compressor, which stores
     each group of `DIALOG_GCD_HIGH_TAIL_ALIAS_GROUP_SIZE = 3` steps
     (6 raw bits, 27 reachable codes) in 5 qubits.
     `dialog_gcd_compressed_sidecar_blocks()` is ⌈iterations / 3⌉, which is
     133 at both 399 and 398, so the log keeps its 665 qubits. The last block
     now holds two steps instead of three
     (`dialog_gcd_compressed_sidecar_block_step_range`).
2. **Reroll pair: `DIALOG_REROLL` 15 → 14, `DIALOG_POST_SUB_REROLL` 25 → 2.**
   Identity `X;X` counts that re-draw the 9,024 test inputs without changing the
   circuit (see [`ecbf87b`](ecbf87b.md)).

## Why it is still correct, and what it risks

This is a probabilistic cut. The GCD is correct only for inputs whose pair
`(u, v)` has converged within the active number of steps. An input that still
needs step 399 ends with an unfinished transcript, so the inverse it produces
is wrong. That shows as a classical failure, and possibly as garbage in the
registers the uncompute no longer clears. A fixed iteration count sits in the
tail of the step-count distribution, so each step removed adds a little λ. The
width envelope (`DIALOG_GCD_WIDTH_MARGIN=27`) assumes the same convergence
rate and is unchanged.

The reroll pair (14, 2) draws a test set in which every input converges within
398 steps and every other approximation is right: 9,024 of 9,024 shots pass
with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md) and, for the
same idea in the later trailmix GCD, [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md).

## Classification rationale

The only circuit change is a lower step count for a fixed-iteration loop,
traded against convergence risk. That is iteration/threshold tuning.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 250774e -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 250774e 7c29f79 -- src/point_add` is 13 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7c29f79 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1500 qubits
   - 1,716,661 average Toffoli (rounded)
   - score 2,574,991,500
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=14`,
`DIALOG_POST_SUB_REROLL=2` and an identical op stream. Any other change needs
a new reroll search.

## Summary

This is the same lever as [`404d630`](404d630.md), built a second time on a
different tree. The Kaliski inverse swaps `(u, v_w)` under a control bit in
STEP 3 and STEP 9 of every iteration, at one Toffoli per bit. Those swaps ran
at the provable width while the rest of the iteration already used the
narrower empirical envelope (W-TRUNC). This commit cuts the swaps to the
envelope as well, since swapping two 0 bits does nothing.

There are two differences from `404d630`:
- This one starts from [`d4959a1`](d4959a1.md), which already has the
  constant-adder majority fold and the one-Toffoli frame reset.
- It gives no flat extra bit. An eager swap uses the envelope of its own
  iteration. A merged swap, which also does the previous iteration's deferred
  STEP 9, uses the previous iteration's envelope.

The carry-tail window moves from 36 to 59 to land a clean test island. The
net result is −197,974 Toffoli against its base, 2,084 Toffoli below
`404d630`, at the same 2309 qubits.

## What changed and why it saves Toffoli

1. **Switch**, `src/point_add/kaliski_state.rs`: new
   `kal_cswap_wtrunc_enabled()`, on unless `KAL_CSWAP_WTRUNC=0`. It has no
   margin of its own. It shares `kal_wtrunc_width`, which in this tree is
   `min(n, n − ⌊(iter − 26)·2/3⌋ + 3)` with `n = 256`.
2. **Widths**, `src/point_add/kaliski_walk.rs`. At four sites the swap width
   becomes `min(provable, kal_wtrunc_width(env_iter, n))`:
   - `kaliski_iteration_bulk_prefix3`, STEP 3 (`uv_width_step3`): if the swap
     is merged (`uv_frame_in` is set), `env_iter = iter − 1`. Otherwise
     `env_iter = iter`.
   - `kaliski_iteration_bulk_prefix3`, eager STEP 9 (`uv_width_step9`):
     `env_iter = iter`.
   - `kaliski_iteration_bulk_prefix3_backward`, reverse STEP 9: `env_iter = iter`.
   - `kaliski_iteration_bulk_prefix3_backward`, reverse STEP 3:
     `env_iter = iter − 1` when `uv_merge_in && merge_rs && iter != 0`. This
     is the backward form of the same "merged" condition, so forward and
     backward use the same width.
3. **Why the merged swap needs the previous envelope.** The (u, v_w) boundary
   merge (`kal_cswap_uv_merge_enabled`, for iterations below
   `KAL_CSWAP_UV_MERGE_SAFE_ITERS = 254`) defers STEP 9 of iteration k − 1
   and fuses it with STEP 3 of iteration k into one swap controlled by
   `a_{k−1} ⊕ a_k`. The envelope never grows from one iteration to the next,
   so iteration k − 1's width is the safe one for the fused swap. It is at
   most 1 bit wider than iteration k's. In `404d630`, a flat +1 on every
   swap covers this case. Here only the merged swaps pay for it, and the
   eager swaps after iteration 254 come out 1 bit narrower.
4. **Why it saves Toffoli.** `cswap` is `CX, CCX, CX`. The old width was `n`
   until iteration 256 and `2n − iter` after it. The envelope sits up to
   about 135 bits below that. Before iteration 254 there is one merged swap
   per iteration. After it there are two eager swaps. Over the forward and
   backward runs of both inversions (399 and 397 iterations), this removes
   about 212,000 Toffoli.
5. **Carry-tail window**, `kal_carrytail_w()`: the default becomes 59 when
   `kal_cswap_wtrunc_enabled()` and stays 36 otherwise. This costs 23 more
   borrow bits per `csub_nbit_const_direct_fast` call, about +14,000
   Toffoli. The comment records a full sweep with the swap truncation on:
   W = 59 is clean, while 36, 45, 49, 50, 52, 54, 56 and 70 all fail. The
   failures are island effects, not borrow errors.

## Why it is still correct, and what it risks

A swap of two bits that are both 0 is the identity. So the cut is exact on any
input where `u` and `v_w` fit inside the W-TRUNC width of the iteration. The
STEP-4 subtract already makes that bet on the same registers. The fused swap
uses the wider of its two iterations, so it never drops a bit that the
deferred STEP 9 needs. A failure would leave a high bit unswapped and corrupt
the GCD state, which shows up as a classical mismatch. The forward and
backward widths come from the same flags and iteration index, so the reverse
pass undoes exactly what the forward pass did.

There is no nonce in this era. The carry-tail window was swept until the op
stream drew a clean set: 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from narrowing loops to the empirical width of their
registers, which is comparator/width truncation. The carry-tail change goes
the other way: it is only there to land the island.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout d4959a1 -- src/point_add`.
   - Do not start from the git parent `404d630`. That is the author's other
     tree, with the `kal_uv_cswap_width` (+1 margin) version of this lever and
     without `d4959a1`'s majority folds.
   - Against the parent, the diff is 189 lines in 3 files. It would show
     `404d630`'s swap functions being removed, and the `cuccaro.rs` add-path
     majority fold and the `kaliski_walk.rs` frame-reset select coming in as
     if they were new.
   - Against `d4959a1`, `git diff --ignore-cr-at-eol d4959a1 a25248f -- src/point_add`
     is 104 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a25248f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,613,815 average Toffoli (rounded)
   - score 6,035,298,835
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

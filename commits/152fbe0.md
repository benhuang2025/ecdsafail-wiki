## Summary

After the ping-pong value walk has converged, the two walk registers `u` and
`v` each hold +1 or −1 in 9-bit two's complement. So of their 18 wires, only
the two sign bits carry information: bits 1–7 are copies of the sign and bit
0 is always 1. The coefficient replay, where the qubit peak sits, reads only
the two sign wires. The base lent one of these known wires to the replay as
scratch.

This commit lends all 16. Each is cleared with a CX from its sign (or an X
for bit 0) and freed before the replay, then reacquired and restored after
it. That is −15 qubits for 32 Clifford gates. Two more exact or practically
exact changes remove the next two peak owners, for −1 more. The endpoint
fold window goes from 54 to 40, which shortens the round-0 `mod_halve_pm`
chain from 87 carries to 73. And the chunked add erases each boundary carry
as soon as it is consumed and allocates the carry-out last. The total is
1317 → 1301 qubits and −116 Toffoli, from the shorter endpoint chains.

## What changed and why it saves qubits

The commit ships its own write-up, `src/point_add/memory/07-pingpong-liveness.md`,
which is part of the patch. At the base it measured the peak with an owner
census at the first divide replay round:

```
700 tape + 256 coefficient + 256 numerator + 8 (u, one bit already lent) + 9 (v)
  + 88 (round-0 mod_halve_pm endpoint chain: 87 carries + parity)  = 1317
```

The chunked replay adder sits one below that, at 87 live scratch wires.

### 1. Lend every known terminal wire (`pingpong_mod_mul_div_in_place`, `pingpong_div.rs`)

```rust
for reg in [&u, &v] {
    let sign = reg[reg.len() - 1];
    for i in 1..reg.len() - 1 { b.cx(sign, reg[i]); b.free(reg[i]); loans.push((reg[i], Some(sign))); }
    b.x(reg[0]); b.free(reg[0]); loans.push((reg[0], None));
}
// ... replay ...
for &(q, sign) in loans.iter().rev() { b.reacquire(q); match sign { Some(s) => b.cx(s, q), None => b.x(q) } }
```

- Before the replay, each of the 16 wires is turned into |0⟩ and returned to
  the allocator. The replay's carry ladders then reuse those indices.
- After the replay, the wires are taken back in reverse order and restored,
  so the walk-back sees exactly the registers it would have seen.
- `SUB4_PP_LOAN_ONE=1` restores the base's single loan, for A/B testing.
- The base already lent `u[len−2]`, so the net gain is 15 qubits:
  1317 → 1302. See [venting-and-wire-loans](../concepts/venting-and-wire-loans.md),
  which uses this commit as its "duplicated bit" example.

### 2. `ENDPOINT_FOLD_WINDOW`: 54 → 40 (`endpoint_fold_window()` default)

- The constant add/subtract helpers build carries for positions
  `0..=min(n − 2, highest_set_bit(c) + window)`. For `c = f`
  (`highest_set_bit` 32), 54 gives 87 carries and 40 gives 73.
- The dropped carry is the one out of position `32 + w`. It is non-zero only
  if the accumulator's bits 33 to `32 + w` are all ones (add) or all zeros
  (subtract), which is about `2^−w` per call.
- The note puts this at 2^−40 ≈ 10⁻¹² per call. With about 8 endpoint calls
  per shot and 9,024 shots, λ goes up by only about 10⁻⁷. In the note's
  words, `ENDPOINT_FOLD_WINDOW` "was never a λ knob".
- The round-0 chain drops to 73 carries and is no longer a peak owner. The
  shorter chains in `conditional_mod_negate`, `mod_halve_pm` and
  `mod_double_pm` also give the −116 Toffoli, since each position is one CCX.
  See [modular-fold](../concepts/modular-fold.md).

### 3. Reordered chunked add (`add_chunked_measured_with`)

- New `add_chunked_measured_with(b, addend, acc, carry_out, late_carry_out)`.
  The two fused replay cells call it through
  `add_chunked_measured_late_carry`, which allocates the carry-out only when
  the last chunk starts.
- After chunk `k`'s `chunk_add`, the boundary carry that chunk `k` consumed
  as carry-in is erased at once, with the same `hmr` and
  `REPLAY_CHUNK_COMPARE`-bit `cmp_lt_phase_conditioned` repair as before.
- Live scratch per chunk goes from 87/87/87 to 86/86/86.
- The multiply cell holds one more wire during the add, `doubled_out`, the
  bit shifted out by the doubling. So the divide replay reaches 1300 and the
  multiply replay binds at **1301**, the submitted peak.
- `SUB4_PP_LEGACY_CHUNK_ORDER=1` restores the old order.
- This is the same idea as `8910bd1`, implemented independently on the same
  base. See [measurement-uncompute](../concepts/measurement-uncompute.md)
  for the erase.

### 4. Inert additions

- `rounds_for(direction)` with a new `SUB4_PP_ROUNDS_MUL` knob, defaulting to
  `rounds()` (700) for both directions. Its comment explains the intent: one
  round fewer on the multiply traversal would bring both replays to 1300. The
  note measured that but did not ship it.
- `value_walk` takes the round count as an argument, and `value_walk_back`
  uses `tape.len()`.
- `set_phase` markers (`pp_div_walk`, `pp_div_replay`, …), which emit no ops.
- New `src/point_add/pp_profile.rs`, an env-gated (`PP_PROFILE=1`) 64-lane
  per-phase profiler that emits no ops.
- `product_register.rs::add_full` gains a `SQUARE_CHUNK_MIN` switch, set to
  `usize::MAX` here, so it is inert.

### 5. Tail nonce (`src/point_add/mod.rs`)

`SUB4_PINGPONG_TAIL_NONCE` default 165193 → 1002365. The note reports three
clean nonces in 2,858 draws and picked the cheapest.

## Why it is still correct, and what it risks

- **The loans are exact on every converged walk.** If a walk did not
  converge (`u`, `v` ≠ ±1), the cleared wires are not |0⟩ and `free`'s reset
  scrambles the phase. Such a shot already fails classically, so this adds no
  new hard inputs. The loan's source (the sign wires) is only read during the
  replay, and every borrower returns the wires at |0⟩.
- **The chunk reorder is exact.** The same gates are emitted, and each repair
  reads only bits that are already final.
- **The endpoint window is approximate in principle**, at about 2^−40 per
  call, which is negligible.
- The note puts λ at about 8 expected failures per draw on both the base
  and this stream, and the base's clean probability at about 3×10⁻⁴ per
  draw. On this stream it found three clean nonces in 2,858 draws.
- The shipped nonce `1002365` draws a clean test set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Fifteen of the sixteen qubits come from lending wires whose values are known
across the peak-binding replay and restoring them afterwards. That is
ancilla-lifetime / venting (the census also has scratch/ancilla reuse for
loans; the call is close). The endpoint window cut is a minor fold
truncation.

+## 3. Endpoint fold window 54 → 40: −1 qubit, provably λ-free
+
+`cadd/csub_nbit_const_direct_trunc_fast` builds carries up to position `min(n−2, highest_set_bit(c) + window)`; the
+dropped carry is the one *out of* that position. For `c = f = 2^32 + 977` the carry (or borrow) out of position
+`32 + w` can only be non-zero if the accumulator bits 33..32+w are all ones (addition) or all zeros (subtraction) —
+probability `2^-w` per call. At w = 54 that is 2^-54; at w = 40 it is 2^-40 ≈ 10^-12 per call, times ~8 endpoint
+calls per shot, times 9,024 shots: λ contribution ≈ 10^-7. So unlike the replay windows (`REPLAY_FOLD_WINDOW`,
+`REPLAY_CHUNK_COMPARE`, `REPLAY_FLAG_COMPARE`), which genuinely trade λ, `ENDPOINT_FOLD_WINDOW` was never a λ knob:
+earlier sweeps that saw 2–4 mismatches at w = 32…48 were looking at the parent's own baseline noise (λ ≈ 5–8).

+With w = 40 the round-0 chain holds 73 carries and is no longer the owner; the chunked adder (87) binds → 1,301.

+interior boundary carries only after the last chunk. Two reorderings, both exact:

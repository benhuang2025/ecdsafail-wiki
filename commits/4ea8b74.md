## Summary

The square step computes `out −= λ² mod p`. At this point in the competition
it builds the full 512-bit product `prod = λ²` with a schoolbook square and
reduces it as `lo + f·hi`, where `lo = prod[0..256]`, `hi = prod[256..512]`
and `f = 2^32 + 977`. The base computed `f·hi` by doubling `hi` in place
modulo p, one bit at a time, up to `hi·2^32`, subtracting a copy at each of the
7 set bits of `f`, and then halving it 32 times to restore it. That is 64
modular doublings/halvings and 7 full-width modular subtractions.

This commit writes `f` in signed-digit (NAF) form,
`f = 2^32 + 2^10 − 2^6 + 2^4 + 1`, so only 5 terms are needed. Each term
`±hi·2^j` is applied without touching `hi`: the low `256 − j` bits of `hi` are
added at bit offset `j` with a modular add or subtract, and the `j` top bits of
`hi` that would spill past bit 256 are folded back one by one as a gated
`±f·2^t` window. The fold windows drop from 64 to 52, and two full 256-bit
modular subtractions disappear. Average Toffoli falls by 1,738; qubits stay at
1164. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All circuit changes are in `src/point_add/trailmix_ludicrous/` (the trailmix
"ludicrous" route; see [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md)
for the shell around it).

**Background: the base reduce.** `square.rs::mod_square_sub_pm_secp256k1_symmetric`
had three stages: build `prod = λ²` (`symmetric_square_into_prod`), reduce,
and unbuild `prod`. The reduce was:

1. `mod_sub(prod[0..256], out)`: subtract `lo`.
2. Append one zero pad to `hi` (`hi_ext`, 257 bits). For each `j` in
   `F_BITS = [0, 4, 6, 7, 8, 9, 32]` (the set bits of `f`), call
   `arith::mod_double(hi_ext)` until `hi_ext` holds `hi·2^j mod p`, then
   `mod_sub(hi_ext[0..256], out)`.
3. Undo the 32 doublings with 32 `mod_double_reverse` calls.

`mod_double` is a free swap-chain shift plus `add_f_window` over
`LSBS = PAD + 33 = 54` bits, gated on the bit that shifted out. A clean
54-bit window costs 53 CCX (the carries are erased by `hmr`, see
[measurement-uncompute](../concepts/measurement-uncompute.md)). So the ramp
cost about 64 × 53 = 3,392 Toffoli, plus 7 `mod_sub`, each an uncontrolled
256-bit Cuccaro (about 2 Toffoli per bit), a `-f` window and a 21-bit
measured borrow clean. See [modular-fold](../concepts/modular-fold.md).

**The change.**

- `square.rs`: `F_BITS` is replaced by
  `F_NAF_TERMS = [(0,Sub), (4,Sub), (6,Add), (10,Sub), (32,Sub)]` and a
  `ShiftOp {Add, Sub}` enum. Subtracting `f·hi` means subtracting
  `hi·(2^32 + 2^10 + 2^4 + 1)` and adding `hi·2^6`.
- `square.rs`, new `apply_shifted_hi_term(hi, out, j, op)` applies one term
  `±hi·2^j` with `hi` read-only:
  - The low part `hi[0..256−j]` goes in at bit `j` through the new
    `arith::mod_add_shifted_low` or `arith::mod_sub_shifted_low` (for `j = 0`,
    plain `mod_sub`).
  - Each of the top `j` bits, `hi[256−j+t]` for `t = 0..j`, has weight
    `2^(256+t) ≡ f·2^t (mod p)` after the shift. It is folded back with
    `add_f_window_shifted` / `sub_f_window_shifted`: a 54-bit `+f` window on
    `out[t..t+54]` controlled by that bit (the sub form X-sandwiches the
    window). These call `arith::add_f_window_pub` with `g_sched = None`, the
    headroom-adaptive window.
  - `mod_square_sub_pm_secp256k1_symmetric` now runs `mod_sub(lo)` and then
    `apply_shifted_hi_term` for the 5 NAF terms. The `pad_hi` qubit,
    `mod_double` and `mod_double_reverse` are no longer used here.
- `arith.rs`, two new primitives, copies of `mod_add` / `mod_sub` with
  implicit low zeros:
  - `mod_add_shifted_low(x, y, shift)`: `cuccaro_carry` of `x` (length
    `256 − shift`) into `y[shift..]` with the carry-out on an ancilla, a
    gated `+f` window on `y[0..54]` (`g = LSBS − 1`, the clean path), and the
    usual top-`MSBS` (21-bit) measured compare `controlled_lt_msbs_conditional`.
  - `mod_sub_shifted_low(x, y, shift)`: the same with an X-sandwich on
    `y[shift..]`, a `sub_f_window`, and `controlled_add_carry_msbs_conditional`
    for the borrow.
  - The shifted view needs no pad qubits, and the register adder is
    `256 − shift` bits wide instead of 256.

**Why it is cheaper.** The fold-window count falls from 64 (32 doublings and
32 halvings) to 52 (the sum of the NAF shifts, 0 + 4 + 6 + 10 + 32). With the
plain binary digits of `f` it would have been 66, so the NAF form is what makes
the direct approach pay. The 7 full modular subtractions become 5 modular
adds/subs, four of them narrower by `j` bits. A rough count gives about
7,400 Toffoli before and 5,500 after; the measured average fell by 1,738.

**Tail nonce.** `src/point_add/mod.rs`, `build()`: the `DIALOG_TAIL_NONCE`
default goes from 800006524 to 800447829. The trailmix builder appends the
nonce as an identity `X;X` tail, so it changes only which test inputs are
drawn. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

- **Same arithmetic identity.** `λ² ≡ lo + f·hi (mod p)` and
  `f = 2^32 + 2^10 − 2^6 + 2^4 + 1` are exact. Each term is
  `hi_low·2^j + Σ_t hi[256−j+t]·2^(256+t)`, and `2^(256+t) ≡ f·2^t`, so the
  sum of the shifted add and the `j` gated windows is exactly `±hi·2^j mod p`
  up to the windows' carry handling.
- **Probabilistic parts.** Both the old and the new route are built from the
  same windowed `+f` fold. A window adds `f·2^t` only into 54 bits and drops a
  carry beyond them, which is wrong with probability about `2^-PAD = 2^-21`
  per firing window (the input must have about 21 ones above the folded
  bits). The overflow and borrow flags are cleared with the usual 21-bit
  truncated compares. The new route has 52 windows that fire about half the
  time (they are gated on bits of `hi`) instead of 64 that fire only on a
  doubling overflow, so the failure rate is of the same order as the base's.
- **Which channel catches it.** A dropped window carry gives a wrong `x`
  coordinate, a classical failure. A wrong truncated compare leaves a phase
  error.
- The shipped nonce 800447829 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures, per the author's run.

## Classification rationale

The commit changes how the Solinas fold by `f` is applied: `f` is rewritten in
NAF, and each term becomes a shifted add with direct spill folds instead of a
modular-doubling chain. That is strength reduction of the NAF fold, the
published label. The runner-up would be ancilla/scratch work, since `hi` is
no longer mutated and its pad qubit is gone, but qubits did not change.

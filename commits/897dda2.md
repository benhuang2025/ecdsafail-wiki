## Summary

Point addition needs `λ = (y2 − y1) / (x2 − x1) mod p`, and the division
dominates the circuit's cost. Before this commit, the frontier computed the
division as "invert, then multiply", using the trailmix jump-GCD.

This commit replaces both division-related calls in the affine-add shell with
a new primitive: fixed-depth ping-pong binary division, which computes
`numerator × denominator^-1` directly in 704 rounds. It also replaces the
squarer with a product-register Karatsuba square.

The new circuit is much wider, 1321 qubits against 1150, but it uses about a
quarter fewer Toffoli. The score multiplies by 1321/1150 = 1.149 for the
qubits and by 952,707/1,284,776 = 0.742 for the Toffoli, a net 0.852. That is
the 14.8% drop. All later ping-pong commits (21 August to 29 September) build
on this file.

## What changed and why it is cheaper

### New file `src/point_add/pingpong_div.rs` (1,551 lines)

Entry point: `pingpong_mod_mul_div_in_place(b, denominator, numerator, direction)`.
`Divide` computes `numerator *= denominator^-1`. `Multiply` computes
`numerator *= denominator`, which is the same machine run backwards. Both
restore `denominator` exactly. The steps are:

1. **Setup.** `u = p` (loaded constant) and `v = denominator`, both widened to
   `VALUE_WIDTH = N + 3 = 259` bits. The recurrence needs both values odd. An
   even denominator is lifted to the congruent negative `a − p`. With the
   fused round-0 lift, this is the first tape bit.
2. **Value walk** (`value_walk`), `ROUNDS = 704` rounds.
   - Each round alternates which of `u` and `v` is the source.
   - It computes a sign bit from bit 1 of both values (`b.cx(target[1], sign); b.cx(source[1], sign)`),
     does a signed add or subtract of the source into the target
     (`signed_add_wrapping`), and pushes the sign onto the tape.
   - It then halves the target by rotating its wires with a SWAP chain, which costs no Toffoli.
   - The widths shrink by the schedule `value_width(round)`. Wires freed by the
     shrink are reused as tape.
3. **Coefficient replay** (`replay_halving` for Divide, `replay_doubling_inverse`
   for Multiply).
   - It replays the tape on a fresh 256-bit `coefficient` register and
     `numerator` mod p, with fused cells `signed_mod_add_pm_halve_fused` and
     `signed_mod_double_add_pm_fused`.
   - Carries are chunked: `REPLAY_CHUNK = 96`, with erases truncated to
     `REPLAY_CHUNK_COMPARE = 26` bits. Fold corrections are truncated to
     `REPLAY_FOLD_WINDOW = 56`, and overflow flags are measured out with
     `REPLAY_FLAG_COMPARE = 28`-bit phase repairs.
   - At the end, both registers hold `±c/a`. They are canonicalised by
     `conditional_mod_negate`, and the duplicate is cleared with CNOTs.
4. **Walk-back** (`value_walk_back`). It runs the walk in reverse to restore `v`
   to the denominator and to clear the tape. `restore_wire_layout` then puts
   the bits back on the caller's original wires.

Why it is cheaper: each round is one add on a register that shrinks over time,
plus one modular half-add on the coefficient. The jump-GCD needed a forward and
an inverse GCD pass, a transcript codec, and a separate multiplication. Why it
is wider: the tape (one qubit per round) and the 256-bit coefficient register
are live together during the replay. See
[pingpong-division](../concepts/pingpong-division.md), which works a full toy
example (u = 13, v = 5).

`build_pingpong_point_add()` builds the whole point addition on top of this. It
calls `trailmix_ludicrous::load_schedule()`, allocates `x`, `y`, `ox` and `oy`,
and calls `ec_add_with_division` with a closure that maps
`inverse = true → Divide` and `false → Multiply`. It also asserts that the
caller's `x` wires come back unchanged.

### New file `src/point_add/trailmix_ludicrous/square/product_register.rs` (419 lines)

This is a product-register Karatsuba square. It accumulates three half-width
triangular squares (`tri_square`, with the correction `tri_corr`) in plain
product registers, then reduces mod p with signed shifted adds (`window_add`,
`apply_f`, `apply_shift_half`, `apply_shift_full`). It reuses the legacy
builder's clean add, fold, comparator and measured-erase primitives. See
[squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).

  - `mod_square_sub_pm_secp256k1_symmetric` dispatches to

  and makes `load_schedule()` `pub(crate)`.

## Why it is still correct, and what it risks

- **Exact parts.** The recurrence itself is exact. After 704 rounds the walk
  has reached its terminal state for any input that converges within that
  many rounds. The coefficient replay is a fixed function of the tape, and the
  walk-back is the exact inverse of the walk.
- **Probabilistic parts.**
  - A fixed depth of 704 rounds: a slow-converging input would not be finished.
  - The width schedule: a value that does not shrink as fast as scheduled
    overflows its register.
  - The truncated chunk, fold and flag compares in the replay.
- These are the knobs that every later ping-pong commit tightens. See
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md)
  and [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
- The shipped nonce `82` draws a clean test set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures.
- The legacy circuits are still in the tree behind `SUB4_LEGACY_POINT_ADD` and
  `SUB4_LEGACY_SQUARE`. They are unused in the shipped build.

## Classification rationale

The division primitive itself is replaced by a different algorithm, while the
affine-add shell stays the same. That is Algorithmic Substitution. The census
had no change-type for an inversion swap, so a new one is used:
"inversion/division algorithm swap", shared with the GCD Skywalk
[`8ee337c`](8ee337c.md). The squarer swap in the same commit is a secondary
instance of the existing "multiplier/squarer swap" type.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 31f9c58 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 31f9c58 897dda2 -- src/point_add` is 2,038
   lines in 6 files. Two of the files are new, and they make up 1,970 of those
   lines.
2. **Copy the two new files from the commit:**
   `git checkout 897dda2 -- src/point_add/pingpong_div.rs src/point_add/trailmix_ludicrous/square/product_register.rs`.
   These are hand-written, not generated. They are copied because they are too
   large to inline. The section above describes what they contain.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It covers the
   four edited files.
4. **Check the tree.** `git diff --ignore-cr-at-eol 897dda2 -- src/point_add`
   should print nothing.
5. **Optional quick self-tests**, each a 64-input bit-parallel run that returns
   no ops:
   - `SUB4_PINGPONG_POINT_ADD_SELFTEST=1 cargo run --release --bin build_circuit`
   - `SUB4_PRODUCT_SQUARE_SELFTEST=1 cargo run --release --bin build_circuit`
6. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   or `TLM_*` overrides set. Expect:
   - 1321 qubits
   - 952,707 average Toffoli (rounded)
   - score 1,258,525,947
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `82` and an identical op stream. Any
other change needs a new nonce hunt.

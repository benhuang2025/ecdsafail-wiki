## Summary

[11ceae2](11ceae2.md) set the dialog-GCD length to 262 steps.
[f37a0bc](f37a0bc.md) and [a6a92a4](a6a92a4.md) then lowered it to 261 and 260.
This commit edits the 262-step tree directly and sets
`DIALOG_GCD_ACTIVE_ITERATIONS` to 259. Every walk, apply pass and reverse walk
loses three steps against its base. That saves 8,583 Toffoli, about 2,860 per
step, and qubits are unchanged. Fewer steps means more inputs that do not
finish in time. A GPU port of the classical pre-filter found a nonce whose test
set avoids them all.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 262 → 259.**
   - `dialog_gcd_active_iterations()` is the loop bound for every walk, apply
     and reverse-walk emitter in `rounds/dialog/` (background in
     [8316db1](8316db1.md)).
   - The dropped steps 259 to 261 have `active_width` 2 to 4, so their walk
     steps are nearly free. The cost is in the two apply passes. Each apply
     step is a modular double or halve of `y`, a controlled 256-bit modular add
     or subtract with its overflow clean, and a 256-wide controlled swap.
   - The measured ladder is 262 → 261 → 260 → 259 = 1,497,795 → 1,494,942 →
     1,492,097 → 1,489,212 Toffoli.
   - The body band trim `"0,1"` now has band size `ceil(259 / 2) = 130`, so
     it trims steps 130 to 258.
2. **`DIALOG_TAIL_NONCE`: 2432 → 78338**, the fixed 48-pair `X;X` identity
   tail that reseeds the 9,024 test inputs.
3. The comments are not updated. The comment above the iteration knob still
   says "258 -> 262", and the one above the nonce still names `2432`.

## Why it is still correct, and what it risks

An input whose K2 GCD needs more than 259 steps does not reach its terminal
state. It gives a wrong slope, and so a wrong output point (a classical
failure) and leftover garbage after the reverse walk (an ancilla or phase
failure). The submission note puts it well: on this test set, all 18,048 GCD
inputs (`dx = Px − Qx` and `c = Qx − Rx` for each of the 9,024 shots) converge
within 259 steps, so steps 259 to 261 would have been no-ops. That is a
property of the drawn test set, not of all inputs.

The nonce was found with a CUDA port of the classical pre-filter from
[88079e6](88079e6.md), at about 1,700 nonces per second per A100. Survivors
were confirmed with the full simulator. All other truncations are unchanged.
The shipped nonce `78338` draws a test set with 0 classical, 0 phase and
0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a loop count, so iteration/threshold tuning fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 11ceae2 -- src/point_add`.
   - Do not diff against the git parent `a6a92a4`. That tree has the 260-step
     setting and nonce `58134` from [f37a0bc](f37a0bc.md) and
     [a6a92a4](a6a92a4.md). This commit was made on `11ceae2` and keeps its
     comments.
   - Against the parent, the diff is 17 lines. It also reverts those two
     commits' comment edits.
   - Against `11ceae2`, `git diff --ignore-cr-at-eol 11ceae2 f5f0f61 -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f5f0f61 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1309 qubits
   - 1,489,212 average Toffoli (rounded)
   - score 1,949,378,508
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=78338` and an identical op
stream. Any other change needs a new nonce hunt.

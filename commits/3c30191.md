## Summary

The dialog-GCD branch compare (see [`cddd5df`](cddd5df.md)) looks at only the
top `DIALOG_GCD_COMPARE_BITS` bits of each step's live slices. On this line of
trees (`8cb350c` → `6447611` → `c813ee5`) the window was still at its original
75. The separate chain `541bd85` → `564c4c3` had already narrowed it to 68.
This commit lowers it to 63. The compare already costs 1 Toffoli per bit
(after [`6447611`](6447611.md)), so this saves 29,352 average Toffoli at the
same 1698 qubits. The reroll `DIALOG_REROLL` goes from 1 to 5.

## What changed and why it saves Toffoli

- **`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `DIALOG_GCD_COMPARE_BITS` 75 → 63.**
  - The compare is `cmp_lt_into_fast` on the top `min(k, w(s))` bits of the
    width-`w(s)` slices of `u` and `v`. It costs 1 Toffoli per bit, and it is
    computed and uncomputed in every step of the four GCD passes. So it costs
    `8·Σ min(k, w(s))` per shot.
  - With the margin-28 width schedule, `Σ min(k, w(s))` falls by 3,669 when `k`
    goes from 75 to 63. 8 × 3,669 = 29,352, exactly the measured saving.
- **`DIALOG_REROLL` 1 → 5.** This is the count of identity `X(tx[0]); X(tx[0])`
  pairs emitted before the point addition. It selects the 9,024-shot test
  draw. The comment in the source records the change.

## Why it is still correct, and what it risks

- The compare is a truncation. Two slices that agree on their top 63 bits can
  get the wrong swap decision, and then `v −= u` goes negative and the GCD
  does not end at `(1, 0)`. That would show as a classical mismatch with
  garbage.
- The width margin is now 28, so a 63-bit window covers roughly 35
  significant bits.
- The author's note says 63 fails at the default reroll and passes at reroll
  5. A 63-bit island was also confirmed clean on the previous tree at reroll
  8. With `DIALOG_REROLL = 5`, the full benchmark gives 0 classical, 0 phase
  and 0 ancilla failures over 9,024 shots.
- The note is open about the method: tightening a window and rerolling until
  the hash-chosen sample is lenient "shops for a lenient sample rather than
  proving arithmetic exactness". See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A comparator window is narrowed, so this is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout c813ee5 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol c813ee5 3c30191 -- src/point_add` is 10 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 3c30191 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `ROUND*` environment variables set. Expect:
   - 1698 qubits
   - 1,952,382 average Toffoli (rounded)
   - score 3,315,144,636
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 5` and an identical op stream.
Any other change needs a new reroll search.

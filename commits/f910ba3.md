## Summary

[`36a2989`](36a2989.md) fused each bulk Kaliski iteration's closing
`(u, v_w)` swap with the next iteration's opening swap, but only for the first
254 iterations of every run. This commit turns that single limit into a
per-pair, per-direction cap, and raises pair2's cap to 255 while pair1 stays at
254. Pair2's forward and backward runs each merge one more boundary. That
removes two 256-wide controlled swaps (512 Toffoli) and adds 4 fix-up CCX:
−508 Toffoli. Qubits are unchanged.

## What changed and why it saves Toffoli

1. **`src/point_add/kaliski_state.rs`.**
   - `kal_cswap_uv_merge_safe_iters()` becomes
     `kal_cswap_uv_merge_safe_caps(pair) -> (forward, backward)`.
   - Defaults: `KalPair::Pair2 => 255`, `KalPair::Pair1` and
     `KalPair::Default => 254`.
   - It is overridable by `KAL_CSWAP_UV_MERGE_SAFE_ITERS`, then
     `..._FWD_` / `..._BK_`, then pair-specific
     `KAL_PAIR{1,2}_CSWAP_UV_MERGE_{,FWD_,BK_}SAFE_ITERS`. This is the same
     override ladder as the bulk-prefix caps.
   - `BulkPrefixCaps` gains `uv_forward` and `uv_backward`, filled by
     `bulk_prefix_caps(pair)` and `cleanup_bulk_prefix_caps(pair)`.
2. **`src/point_add/kaliski_walk.rs`.** `kaliski_iteration_bulk_prefix3` and
   `kaliski_iteration_bulk_prefix3_backward` take a new `uv_safe_iters`
   argument instead of reading the global function. The merge rules are
   unchanged:
   - `uv_merge_out = iter_idx + 1 < uv_safe_iters` (and not last) skips
     STEP 9's `(u, v_w)` swap;
   - `uv_merge_in = iter_idx < uv_safe_iters` applies the STEP 1 / STEP 2
     fix-ups and the merged STEP 3 swap.
3. **`src/point_add/kaliski_inv.rs`.** Every caller passes
   `bulk_caps.uv_forward` or `bulk_caps.uv_backward`. The default-off
   prescaled paths now read `bulk_prefix_caps(KalPair::Default)` instead of
   `bulk_prefix_safe_iters()`. This is the same value unless
   `KAL_BULK3_FWD_ITERS` or `KAL_BULK3_BK_ITERS` is set.

With pair2 at 255, iteration 253's STEP 9 swap is now deferred and merged into
iteration 254's STEP 3, in both the forward and the backward pair2 run. Each
merge removes a 256-wide cswap (256 Toffoli) and adds the 2-CCX STEP 1 fix-up:
2 × (256 − 2) = 508.

## Why it is still correct, and what it risks

The merge is exact as long as `u ≠ v_w` at every iteration that takes the
STEP 2 fix-up `l_gt ^= frame`. See [`36a2989`](36a2989.md).

- **Equality cannot occur here.** `gcd(u, v_w) = 1` throughout, so equality
  means `(1, 1)`, a sum of 2. `u + v_w` at most halves per iteration from
  above 2^255, so at iteration 254 it is still above 2. For the record, a
  plain-Python run of the textbook Kaliski loop on 20,000 random inputs
  (scratch check, not part of the repo) found the first `u = v` no earlier
  than step 322, and termination between steps 323 and 397.
- **So "pair1 at 255 is invalid" is not an equality failure.** The author
  reports that cap failing, and that is why pair1 stays at 254. Raising
  pair1's cap changes the op stream and so the hashed test draw, and that
  draw most likely contains an input that trips one of the empirical knobs:
  the iteration counts, `BULK_PREFIX_SAFE_ITERS` or `R_SMALL_THRESHOLD`.
- There is no tail nonce in this era. The shipped stream's draw is clean:
  0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit moves a cap on how many iterations take a fused path, per pair.
That is iteration/threshold tuning. The runner-up is Fusion → boundary
cswap-merge, since what the cap controls is the merge from `36a2989`. The code
change itself is plumbing.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a428a8c -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol a428a8c f910ba3 -- src/point_add` is
   86 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f910ba3 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `POINT_ADD_*` or `BY_*` environment variables set. Expect:
   - 2310 qubits
   - 3,357,772 average Toffoli (rounded)
   - score 7,756,453,320
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era: the test set is a hash of the op stream,
so the score only reproduces with an identical op stream.

## Summary

Sky18 changes three pins, and each one removes one bit:

| knob | change | sites | direction |
| --- | --- | --- | --- |
| `HEO_PIN_PP_FOLD_PROFILE` | top band `44:0` → `56:0`, so walk widths 44–55 go from offset 0 to −1 | cells at ticks 319–336, both legs (18 per leg) | fold sell, 1 bit |
| `HEO_PIN_PP_FOLD_WIDEN` | 144 → 128: proxy rounds 128–143 lose their +1 | cells at ticks 70–76, both legs (7 per leg) | fold sell, 1 bit |
| `HEO_PIN_ERASE_COMPARE` | 21 → 20 | overflow-carry erase of each shell modular add/sub | compare sell, 1 bit |

The SAT rewrite table is re-proved on the new op stream (62 → 56 rows). The
net is −54 Toffoli at 1174 qubits, and the author reports λ up 0.009.

The submission note calls the `56:0` band a buy that "buys part of their
error back". In the code it is a sell. `band_at` returns the offset of the
first band whose width is at or below the walk width. Under `44:0,38:-1,…` a
cell at width 44–55 gets 0. Under `56:0,38:-1,…` it gets −1.

## What changed and why it saves Toffoli

All circuit changes are pins in `install_skywalk_submission_recipe()`,
`src/point_add/mod.rs`. The tick ranges are my mapping through the proxy
envelope (`env_front07_R393_clamp.txt`) and the pinned
`HEO_PIN_PP_WIDTH_SCHEDULE`, the same mapping the sky14 and sky15 notes use.

1. **`HEO_PIN_PP_FOLD_PROFILE`: `44:0,38:-1,32:-1,25:-5,19:-4,0:-5` →
   `56:0,38:-1,32:-1,25:-5,19:-4,0:-5`.**
   - A payload cell's fold window is the base window plus
     `fold_offset(proxy) = band_at(fold_shape(), policy_width(proxy)) + [proxy < PP_FOLD_WIDEN]`.
   - Walk widths 44–55 (ticks 319–336) go from offset 0 to −1, so their
     window loses one bit. Every other width keeps its offset.
   - A window bit is one stage of the fold's truncated carry chain, about one
     Toffoli per cell. Over both legs that is about 36 cell-bits. See
     [modular-fold](../concepts/modular-fold.md) and the sky14 note
     [`cc530e2`](cc530e2.md).
2. **`HEO_PIN_PP_FOLD_WIDEN`: 144 → 128.**
   - `fold_widen()` gives +1 to every proxy round below it. Rounds 128–143
     lose that bit. On the proxy envelope they are ticks 70–76 (rounds
     129–142 occur), about 14 cell-bits over both legs.
   - Sky15 ([`9556f90`](9556f90.md)) had raised it from 112 to 144. This
     returns half of that buy.
3. **`HEO_PIN_ERASE_COMPARE`: 21 → 20.**
   - `modular::erase_compare()` is the width of the measured overflow-carry
     erase in `mod_addsub_with` and its fused relatives (`j_fuse.rs`,
     `classical.rs`, the FD coordinate ops in `heo_carry.rs`).
   - The erase measures the carry with `hmr`. Only on outcome 1 does it run a
     phase compare of the top `k` bits, so one bit is about 0.5 executed
     Toffoli per site. See
     [measurement-uncompute](../concepts/measurement-uncompute.md) and
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
   - The submission note describes it as "the compare width used when the
     walk history is erased". The code says otherwise: it is the coordinate
     shell's modular add/sub erase.
4. **SAT rewrite rows: `sky16_rewrite.txt` (62 rows) → `sky18_rewrite.txt`
   (56 rows).**
   - The commit comment says "56 SAT-proven rows re-proved on this op stream".
   - The fold and erase changes alter ops before the square, so the sky16
     rows no longer sit where they were proved.
   - The author mapped each row onto the new stream, screened it, and proved
     it again by SAT, anchored at the new square entry. Only the 56 that
     finished inside the time budget are kept.
   - All 56 lie in the square (ops 4.60M–5.17M). Six fewer rows cost about
     +6 Toffoli on every shot.
   - The loader, with its unique-shift search, is unchanged. See
     [dead-gate-strip](../concepts/dead-gate-strip.md). `sky16_rewrite.txt`
     stays in the tree, unused.
5. **Tail nonce**: `TAIL_NONCE` goes from 17001330283497 to 18000451506351.

The diff alone does not fix how the −54 Toffoli splits among the levers. The
fold sells are the largest countable part, about 50 cell-bits.

## Why it is still correct, and what it risks

All three pin changes are probabilistic:

- **The fold sells** about double the escape rate of the affected cells'
  folds. A dropped carry leaves a wrong field element, which shows up as a
  **classical** failure. The `fold_shape` doc comment measures the escape rate
  at walk width 54 and 47 close to the flat region, so the 44–55 band is not
  one of the cheap late bands.
- **The ERASE_COMPARE cut** doubles the tie error of each shell erase. A wrong
  compare leaves a wrong phase, which shows up as a **phase** failure.
- The submission note gives λ 19.212 ± 0.032 on 16,384 nonces (est + 2 SE
  19.276), against 19.203 for sky17, inside the 19.5 limit that the code
  comment cites.
- The rewrite rows are exact on reachable states if their proofs hold. The
  build asserts only that each row still names its CCX.
- The shipped nonce `18000451506351` draws a clean island: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Two of the three levers narrow the payload cells' fold windows, and they are
the larger share (about 50 cell-bits): fold/carry truncation, like sky14 and
sky15. The runner-up was comparator/width truncation, for `ERASE_COMPARE`.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 284e2b0 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 284e2b0 f79a8d1 -- src/point_add` is
   70 lines in 2 files.
2. **Copy the new rewrite table from the commit:**
   `git checkout f79a8d1 -- src/point_add/skywalk_data/sky18_rewrite.txt`.
   It holds the 56 SAT rows described above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `mod.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol f79a8d1 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `PP_*`, `TLM_*` and `SUB4_*` overrides have no effect. Do
   not set them anyway. Expect:
   - 1174 qubits
   - 943,921 average Toffoli (rounded)
   - score 1,108,163,254
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `18000451506351` and an identical op
stream. [`d1608a3`](d1608a3.md) keeps this circuit and only re-rolls the
nonce.

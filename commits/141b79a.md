## Summary

Four constants change, all approximation knobs of the Kaliski inverse and
its constant subtractor:
- the W-TRUNC margin goes from 3 to 0;
- the W-TRUNC start `K0` goes from 26 to 25;
- the constant-subtract carry-tail window goes from 59 to 26 bits;
- `R_SMALL_THRESHOLD` goes from 326 to 325.

The first three narrow loops and carry chains and save Toffoli. The fourth
costs a little and is there to land a clean test island. Net: −43,400 average
Toffoli at the same 2309 qubits.

This is the same kind of re-tune that anupsv did on the other line in
[`9fa5a56`](9fa5a56.md) (`K0 = 24`, margin 0, `R_SMALL = 325`). Here it is
done on [`a25248f`](a25248f.md), which has the majority folds and the
merge-aware swap truncation, and it also tightens the carry-tail.

## What changed and why it saves Toffoli

All four are in `src/point_add/kaliski_state.rs`, with comments recording the
sweep:

1. **`kal_wtrunc_margin()`: 3 → 0.**
   - `kal_wtrunc_width(it, n) = min(n, n − ⌊(it − K0)·2/3⌋ + margin)` for
     `it ≥ K0`, with `n = 256`.
   - With margin 0, every W-TRUNC loop runs at the bare fitted envelope,
     3 bits narrower than before.
   - In this tree the loops are the STEP-0 OR chain, the STEP-2 comparator,
     the STEP-4 load and subtract, and, since `a25248f`, the STEP-3 and
     STEP-9 (u, v_w) swaps (`kal_cswap_wtrunc_enabled`, no extra margin).
     The swaps are the biggest of these.
2. **`kal_wtrunc_k0()`: 26 → 25.** The envelope starts one iteration earlier.
   After that it is 0 or 1 bit lower at each iteration, 2/3 bit on average.
3. **`kal_carrytail_w()`: 59 → 26**, on the branch where the swap
   truncation is on. The branch where it is off stays at 36.
   - `csub_nbit_const_direct_fast` now computes borrows only up to bit
     `33 + 26 = 59`. That is 33 fewer borrow positions per call, at one
     Toffoli each.
   - With about 611 calls per point addition (see [`a97b4e9`](a97b4e9.md)),
     this is roughly 20,000 Toffoli.
4. **`R_SMALL_THRESHOLD`: 326 → 325.**
   - Kaliski iteration 325 now doubles `r` with the full modular double
     (shift plus controlled `+c`) instead of the Toffoli-free shift.
   - This adds Toffoli and is the more conservative setting. The comment
     says `K0 = 25` is clean only with this re-roll, while `R_SMALL` 324, 326
     and 327 fail.

The rough split is about 23,000 from the narrower W-TRUNC loops and about
20,000 from the carry-tail, minus a few hundred for `R_SMALL`.

## Why it is still correct, and what it risks

- **Carry-tail, `W = 26`.** This is still exact in practice. A 3M-trial Monte
  Carlo found the longest borrow run above bit 32 is 19 bits, which reaches
  bit 51. The chain now reaches bit 59, so about 7 bits of slack are left,
  down from about 40. A dropped borrow would give a classical mismatch.
- **W-TRUNC at margin 0 and `K0 = 25`.** This is the real bet. The loops now
  run at the fitted envelope with no slack beyond the 1 to 7 bits it had over
  its 80k-sample maximum. An input that converges slowly breaks a comparison,
  subtraction or swap, and the run shows a classical mismatch, often with
  phase garbage too.
- **`R_SMALL = 325`** is safer than 326.

There is no nonce in this era. Each setting draws its own 9,024-shot set. The
comments record the search:
- margin 0 alone was clean only after the carry-tail moved to `W = 26`,
  which scored 2,574,129 Toffoli;
- `W` in {24, 25, 27, 30, 32, 40, 45} failed;
- `W = 23`, and `W = 26` with `K0 = 25`, each missed by one shot;
- `K0 = 25` became clean with the `R_SMALL = 325` re-roll, which gave
  2,570,415 Toffoli;
- `K0 = 24` failed.

This draw is clean: 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Most of the saving comes from narrowing GCD-walk loops (W-TRUNC margin and
`K0`), so comparator/width truncation fits. The carry-tail cut is close
behind and would be fold/carry truncation on its own. `R_SMALL` is an island
knob.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a25248f -- src/point_add`.
   - Do not start from the git parent `330186c`. That is anupsv's tree on the
     `404d630` line. It has the `kal_uv_cswap_width` (+1) swap truncation,
     no add-path majority fold, no one-Toffoli frame reset, and `K0 = 24`.
   - Against the parent, the diff is 215 lines in 3 files. It would show
     `a25248f`'s whole swap-width rewrite and `d4959a1`'s folds as if they
     were new.
   - Against `a25248f`, `git diff --ignore-cr-at-eol a25248f 141b79a -- src/point_add`
     is 30 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 141b79a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,570,415 average Toffoli (rounded)
   - score 5,935,088,235
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

## Summary

This is a sell/buy package on the GCD Skywalk circuit. First it buys back
error: the two rail envelopes (the per-tick widths of the Skywalk rails) get
one extra bit on 15 division rows and 21 multiply rows. That costs a few dozen
Toffoli and makes rare overflowing inputs less likely. It then sells that
margin on cheaper compares:

- the boundary-carry erase of the split rail add in the multiply walk-back
  goes from a 24-bit window to 21 bits (`HEO_SPLIT_K`);
- the payload cells at division ticks 150–155 lose one bit of their
  chunk-boundary compare (`GO_CELLB`).

Two small buys go with it. The multiply cells at ticks 225–344 get one more
flag-compare bit (`GO_CELLF`), and one more cell tick gets the wide fold window
(`FOLD_WIDEN` 64 → 68). The SAT rewrite table is replaced by a new 67-row
table for the new op stream (the base had 57 rows). The net is −96 Toffoli at
the same 1174 qubits.

## What changed and why it saves Toffoli

1. **`HEO_SPLIT_K`: 24 (the default) → 21**, set in
   `install_skywalk_submission_recipe()`, `src/point_add/mod.rs`.
   - It is read as `carry_cfg().split_k` in `src/point_add/heo_carry.rs`. It
     is used by the two rail adders, `rail_add_inner()` and `fama_add()`, and
     only in their `SplitMode::Approx` branch.
   - **What "split" means.** A rail add `b += a + cin` is a ripple adder that
     needs about `w − 1` carry wires. Near the qubit cap
     (`HEO_PIN_PP_WALK_MAX_QUBITS = 1174`) there may not be that many free
     wires. Then `split_sizes()` / `split_sizes_a()` cut the add into chunks
     that each fit in the free room. Each chunk ripples on its own and vents
     its carry-out onto a fresh *boundary* wire, which is the carry-in of the
     next chunk. The chunk's inner carries are unwound at once, so only the
     boundary wires stay alive.
   - **The repair.** In `Approx` mode, each boundary wire is erased as soon as
     the next chunk has consumed it. `erase_with_compare` measures it out with
     `hmr`. Only when the outcome is 1, it runs a phase compare
     `cmp_lt_phase(sum, addend)` over a window of the chunk. This works because
     the carry-out of a chunk equals `[sum < addend]`. The window rule is:
     - The lowest chunk (the one starting at bit 0) is compared **exactly**,
       over its whole width and with the add's real carry-in as borrow-in, if
       it is at most K bits wide.
     - Every other chunk, and a lowest chunk wider than K, is compared on its
       **top `min(K, size)` bits only**, with no borrow-in. This is the
       approximation.
   - **Where it applies.**
     - `Approx` is the default of `HEO_SPLIT_MUL`. Only the multiply leg's
       fused walk-back ticks pass it ("mul fused rail", ticks
       `HEO_R1M = 190` to `HEO_R2M − 1 = 369`).
     - Those ticks run their payload cell inside the reverse tick
       (`HEO_CELL_INSIDE=1`), so free room is tight and the inverse rail add
       may have to split.
     - The other ticks do not read K. The forward ticks use `Defer`. The
       division walk-back uses `Apply`, the unsplit mirror pass that repairs
       `Defer`'s phases. The other multiply reverse ticks use `Exact`.
     - K also feeds a bridge cost estimate, but that code is off here
       (`HEO_RAIL_BRIDGE` is unset).
   - **What 24 → 21 changes.**
     - Each windowed boundary erase compares 3 fewer bits when its chunk is
       wider than 21.
     - A lowest chunk of 22–24 bits now gets the top-21 window instead of an
       exact compare.
     - The code's cost note gives (n − 1)/2 expected Toffoli for an n-bit
       coin-gated compare. So each such boundary saves about 1.5 executed
       Toffoli.
     - This is a narrower (looser) window, so it is a sell.
2. **`GO_CELLB = "div:150-155:-1"`** and **`GO_CELLF = "mul:225-344:1"`**. Both
   are new, and both go through a new hook in `heo_carry.rs`.
   - `cell_shift(mul, t)` returns `(dB, dF, dX)` for the payload cell of leg
     `mul` at tick `t`. Before this commit it read only the `HEO_CELL_WINDOWS`
     table. Now it adds `go_cell_delta("GO_CELLB", mul, t)` to dB and
     `go_cell_delta("GO_CELLF", mul, t)` to dF.
   - `go_cell_delta` parses `leg:lo-hi:delta,...`. The leg is `div`, `mul`, or
     anything else for both legs. It **sums** the deltas of every entry whose
     inclusive tick range holds `t`.
   - `cell_div` and `cell_mul` run the cell inside
     `h7::with_cmp_shift((dB, dF))`. That sets a thread-local, which
     `pingpong.rs` adds to two widths:
     - `chunk_compare(round)`: the width of each **chunk-boundary carry
       erase** inside the cell's chunked 256-bit add (the "B" sites).
     - `flag_compare(round)`: the width of the cell's **overflow-flag erase**
       (the "F" sites).
   - Both sites use the same pattern: `hmr`, then a phase-conditioned top-k
     compare. A −1 removes one compare bit, which is narrower, cheaper and
     less accurate. A +1 adds one bit, which is wider, dearer and more
     accurate.
   - So the six division cells at ticks 150–155 lose one bit at every chunk
     boundary (a sell), and the 120 multiply cells at ticks 225–344 gain one
     flag-compare bit (a buy).
3. **`HEO_PIN_PP_FOLD_WIDEN`: 64 → 68** (mod.rs).
   - `fold_offset(round)` in `pingpong.rs` adds 1 to the cell's fold window
     when `round < PP_FOLD_WIDEN`.
   - For Skywalk cells, `round` is the cell's *proxy round*. `proxy_round(esw)`
     is the first ping-pong round whose `PP_WIDTH_SCHEDULE` width is at most
     the tick's width. The width is read from the fixed proxy envelope
     `env_front07_R393_clamp.txt`.
   - Proxy rounds 64–67 occur only at tick 36 (proxy round 66). So this
     widens the fold window by one bit on the tick-36 cell of each leg. It is
     a small buy.
4. **New rail envelopes** (`HEO_ENVELOPE`, `HEO_ENVELOPE_MUL`).
   - `config()` and `config_mul()` in `heo.rs` now `include_str!`
     `sky8_env_div_iA.d.100.txt` and `sky8_env_mul_iA.m.100.txt`. Before, they
     read the sky5 files `gN.d.35` and `gN.m.35`. The env-var paths are only
     checked for presence.
   - Each line is `esw ead`: the swap width and the add width of one tick.
     Comparing row by row:
     - Division (393 ticks): 15 rows change, all by +1, at ticks 16–18, 40–41,
       63–64, 159 and 251–258. In total esw gains 8 bits and ead gains 8.
     - Multiply (392 ticks): 22 rows change, at ticks 18–19, 50, 66–67,
       184–185, 193–194, 210, 230, 246–256 and 280–281. esw gains 10 bits net
       (eleven +1 and one −1 at tick 230), and ead gains 11.
   - **The new envelope is wider.** For example, division tick 18 goes from
     (256, 255) to (256, 256), and multiply tick 255 goes from (98, 98) to
     (99, 99).
   - A tick costs `(esw − 1) + (ead − 1)` CCX, paid once on the forward walk
     and once on the walk-back. So the widening costs roughly 2 × 37 ≈ 75
     Toffoli (my estimate). It buys a lower chance that a slow input outgrows
     its rail and gets truncated by `resize`.
   - The cell windows do not move, because `HEO_PROXY_ENVELOPE` pins the proxy
     rounds to a fixed envelope.
5. **SAT rewrite rows.** `build()` now loads `sky8_p7f_rewrite.txt` (67 rows)
   instead of `sky5_ycd_rewrite.txt` (57 rows), which is deleted.
   - Each row `widx c1 c2 t cst w1,w2,..|-` names one unconditioned CCX at op
     index `widx`. It replaces that CCX with CXs from the listed wires into
     `t`, plus an X if `cst = 1`.
   - The loader searches for the unique global index shift under which every
     row names a matching CCX, and asserts that the shift is unique. It does
     not re-check the SAT proof.
   - The table is new. Only 3 of its rows match a sky5 row's wires (at an
     index shift of +325). The other rows name different wires, so they were
     mined again for this op stream.
   - Each row removes one Toffoli that runs on every shot, so 10 more rows
     than the base is worth about −10 Toffoli.
6. **Tail nonce**: `TAIL_NONCE` in `env_raw()` goes from 5000500937876 to
   8000042289598.

## Why it is still correct, and what it risks

- **Exact parts.** The fold-window and flag-compare buys only remove error.
  The rewrite rows are exact on reachable states if their offline SAT proofs
  hold. The build only checks that each row still names its CCX.
- **Probabilistic parts.**
  - The K = 21 boundary erase is wrong when the compared top bits of a chunk's
    sum and addend tie. That happens with probability about 2^-21 per
    boundary, against 2^-24 before. This now also covers lowest chunks of
    22–24 bits, which were exact before.
  - The six division cells' boundary compares are one bit shorter, so each
    of those boundaries has twice the tie error.
  - A wrong compare leaves a wrong phase, so it shows up as a **phase**
    failure.
- **The envelope.** The envelope is still a fitted promise, not a proof. The
  widened rows make **classical** or ancilla failures less likely. Those are
  the failures where `resize` cuts off part of a rail value.
- **λ.** The package spends the λ that the envelope buys back. The shipped
  nonce `8000042289598` draws a clean island: 0 classical, 0 phase and
  0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from narrower compare windows: the split-add boundary erase
and the division cells' boundary compares. The buys (envelope, flag and fold
bits) are width changes in the other direction, paid for in λ. That is
comparator/width truncation. The new rewrite table is host-derived
specialization, and it is a small part of the saving, about 10 Toffoli.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 82c849b -- src/point_add`.
   - The git parent `0642f52` is the author's sky6. It differs from `82c849b`
     only by a new nonce and by a 68-row `sky6_z11_rewrite.txt` that replaces
     `sky5_ycd_rewrite.txt`. This commit replaces that table anyway.
   - Against the parent, the diff is 209 lines in 7 files. It deletes the sky6
     table instead of the sky5 one, and reverts nothing else.
   - Against `82c849b`, `git diff --ignore-cr-at-eol 82c849b 4ea960f -- src/point_add`
     is 198 lines in 7 files. The two envelope files show up as renames with
     15 and 22 changed rows.

   `git checkout 4ea960f -- src/point_add/skywalk_data/sky8_env_div_iA.d.100.txt src/point_add/skywalk_data/sky8_env_mul_iA.m.100.txt src/point_add/skywalk_data/sky8_p7f_rewrite.txt`.
   These are the two widened envelopes and the 67-row rewrite table described
   above.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It covers `heo.rs`, `heo_carry.rs` and `mod.rs`. It also deletes
   the replaced sky5 envelopes and the sky5 rewrite table.
4. **Check the tree.** `git diff --ignore-cr-at-eol 4ea960f -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. `build()` clears
   the process environment and then installs the pinned recipe, so `HEO_*`,
   `GO_*`, `SKY_*`, `PP_*` and `SUB4_*` overrides have no effect. Do not set
   them anyway. Expect:
   - 1174 qubits
   - 945,828 average Toffoli (rounded)
   - score 1,110,402,072
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `8000042289598` and an identical op
stream. Any other change needs a new nonce hunt. If the stream shifts, the
rewrite rows must also be re-keyed.

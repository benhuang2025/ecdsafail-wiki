## Summary

In the dialog GCD of [`cddd5df`](cddd5df.md), every step works only on the low
`w(s)` bits of `u` and `v`. Here `w(s) = 256 − 0.7075·s + margin`, rounded up to
even and clamped to 256. It is an empirical envelope of the shrinking bit
length, plus a safety margin. This commit lowers the margin from 37 to 28 bits.
Every step from step 43 onward then runs its swap, controlled subtract and,
late in the walk, its compare on up to 10 fewer bits (9 before rounding
to even). That saves 51,688 average
Toffoli at the same 1698 qubits, because the peak is set in the early
full-width steps.

The commit also adds a new reroll knob, `DIALOG_REROLL`, set to 8. It adds a
`DIALOG_GCD_HOST_GATED` option too, but leaves it off.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`.

1. **`dialog_gcd_tobitvector_active_width()` now reads two new knobs.**
   - `dialog_gcd_width_margin()` reads `DIALOG_GCD_WIDTH_MARGIN`, default 37.0.
   - `dialog_gcd_width_slope()` reads `DIALOG_GCD_WIDTH_SLOPE_X1000`, default
     0.7075.
   - The formula is unchanged:
     `ideal = 256 − s·slope + margin`, rounded up to even and clamped to
     `[1, 256]`.
2. **`configure_ecdsafail_submission_route()` sets `DIALOG_GCD_WIDTH_MARGIN = 28`.**
   - Per GCD step, the width-dependent cost is about `3·w(s)` Toffoli: the
     `w`-bit cswap, the `w` CCX that load `b0·u`, and the `w`-bit fast
     subtract. The `u > v` compare costs `4·min(75, w(s))`.
   - Over the 399 steps, the sum of `w(s)` falls by 3,162. The sum of
     `min(75, w(s))` falls by 859.
   - There are four GCD passes per shot, so the saving is
     `4·(3·3,162) + 16·859 = 51,688`, exactly the measured saving.
   - With margin 28, the width drops below 256 from step 43, instead of step
     56. The peak is reached at the first GCD step, which is still 256 wide,
     so the qubit count does not move.
3. **New reroll `DIALOG_REROLL`, set to `"8"`.** In `build_builder()`, right
   after the four point registers are allocated and before the route runs, the
   builder emits `k` pairs of `X(tx[0]); X(tx[0])` under the phase
   `dialog_reroll`. These change the op-stream hash and therefore the 9,024
   test inputs, with no Toffoli and no qubits. This is a different knob from
   the `DIALOG_GCD_REROLL` that [`541bd85`](541bd85.md) added; this tree does
   not contain that one.
4. **New option `DIALOG_GCD_HOST_GATED`, off by default.** When enabled, the
   `gated = b0·u` load register of `dialog_gcd_controlled_sub_selected` and
   `..._add_selected` would sit on clean future-transcript slots, next to the
   borrowed carries. The future-carry slice functions then request `2w − 1`
   slots instead of `w − 1`. The source comment calls it "peak-neutral->down".
   It is not set in `configure_ecdsafail_submission_route()`, so it does not
   affect this score. With it unset, the two slice functions return exactly
   the old `w − 1` slots.

## Why it is still correct, and what it risks

- The width envelope is a statistical fit, not a bound. An input whose `u` or
  `v` is wider than `w(s)` at some step loses its top bits in the swap and the
  subtract. The GCD then does not end at `(1, 0)`, which shows as a classical
  mismatch with phase and ancilla garbage.
- A margin of 28 leaves 9 fewer bits of slack. The author reports that a
  16-value reroll screen found no clean draw at margin 26 or below. At 28,
  rerolls 8, 9 and 13 were clean.
- With `DIALOG_REROLL = 8`, the full benchmark gives 0 classical, 0 phase and
  0 ancilla failures over 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from narrowing the per-step register widths of the GCD body,
which is comparator/width truncation. The host-gated option is a qubit lever,
but it is not enabled, so it plays no part in this score.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout cddd5df -- src/point_add`.
   - Do not start from the git parent `564c4c3`. This commit was built
     directly on pldallairedemers' tree, not on the compare-width chain
     [`541bd85`](541bd85.md) → [`00e3a20`](00e3a20.md) →
     [`564c4c3`](564c4c3.md).
   - Against the parent, the diff is 177 lines. It would show
     `DIALOG_GCD_COMPARE_BITS` going back from 68 to 75, and the
     `DIALOG_GCD_REROLL` block of `541bd85` being removed. Those are reverts
     of the three commits above.
   - Against `cddd5df`, `git diff --ignore-cr-at-eol cddd5df 8cb350c -- src/point_add`
     is 156 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8cb350c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `ROUND*` environment variables set. Expect:
   - 1698 qubits
   - 2,396,158 average Toffoli (rounded)
   - score 4,068,676,284
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 8` and an identical op stream.
Any other change needs a new reroll search.

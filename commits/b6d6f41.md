## Summary

After the division, the point addition computes `x3` from `λ²` in
`round84_emit_fused_square_xtail`. The base did that square with a schoolbook
squarer. This commit switches to a one-level Karatsuba squarer that was already
in the file but switched off. Karatsuba does three half-size squares instead of
one full-size square, which saves 16,272 Toffoli. Its extra middle-product
register fits under the 1572-qubit peak, which is set by the GCD apply phase,
so qubits are unchanged.

The new op stream needed a new clean test draw. The author could not find one
at anupsv's tighter `WIDTH_MARGIN = 26`, so the margin goes back up to 27. That
gives back 4,672 Toffoli. The net saving is 11,600.

## What changed and why it saves Toffoli

All changes are defaults in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`:

1. **`ROUND84_XTAIL_KARATSUBA = 1`** (new default). The line
   `set_default_env("ROUND84_XTAIL_SCHOOLBOOK", "1")` is removed.
   - `round84_emit_fused_square_xtail(b, tx, lam, ox, p)` computes
     `tx ← −(tx − λ² + 2·ox)`, the affine `x3`. Its dispatcher checks
     `ROUND84_XTAIL_KARATSUBA` first, so the Karatsuba path now wins.
   - `squaring_sub_from_acc_karatsuba(b, acc, x, p)` computes `acc −= x² mod p`.
     It splits `x` into 128-bit halves and computes three symmetric schoolbook
     squares: `z1 = (lo + hi)²` into a 258-qubit `z1_reg`, then
     `z0 = lo²` and `z2 = hi²` into a 512-qubit `tmp_ext`. It forms the middle
     term `z1 − z0 − z2` with non-fast (carry-free) Cuccaro adders, adds it into
     `tmp_ext[128..512]`, and reduces with the Solinas fold before subtracting
     from `acc`.
   - The non-fast adders keep the peak low: `z1_reg` + `tmp_ext` + the two
     point registers come to about 1,280 qubits, and with the squarer's row
     scratch the source comment puts the square phase at about 1,567, just
     under the apply-phase binder at 1572 (see [68e3653](68e3653.md)). The
     author checked this with `TRACE_PEAK`.
   - The saving is −16,272 emitted Toffoli, as measured by the author. See
     [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).
2. **`DIALOG_GCD_WIDTH_MARGIN` 26 → 27**. This undoes half of bb27ddd's
   narrowing of the dialog-GCD walk width (see [412312f](412312f.md) for the
   envelope). Per walk the summed width rises from 56,212 to 56,572 bits
   (+360) and the comparator width from 21,079 to 21,167 (+88).
   3 × 360 + 88 = 1,168 per walk, × 4 walks = +4,672 Toffoli.
3. **`DIALOG_REROLL` 20 → 0**. With 0 the reroll loop in `build()` emits no
   `X;X` pairs.

−16,272 + 4,672 = −11,600, the measured change.

## Why it is still correct, and what it risks

Karatsuba is an exact rearrangement of the same product, so the square adds no
failure mode. The looser width margin lowers the walk's failure rate compared
with bb27ddd. The approximations that remain are the ones the base already had:
the width envelope, the comparator schedule and the truncated fold and clean
windows.

The new op stream draws a new test set, and at margin 26 it was not clean.
The author found that margin 27 with reroll 0, and also margin 28 with reroll
11, give 0 classical, 0 phase and 0 ancilla failures. They shipped the cheaper
of the two. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from replacing the squarer with a different algorithm, so
the label is multiplier/squarer swap. The margin change is the price of a clean
draw and goes the other way.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout bb27ddd -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol bb27ddd b6d6f41 -- src/point_add` is
   22 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b6d6f41 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   Expect:
   - 1572 qubits
   - 1,749,989 average Toffoli (rounded)
   - score 2,750,982,708
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 0` and an identical op
stream. Any other change needs a new reroll scan.

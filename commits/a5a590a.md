## Summary

The circuit inverts with the dialog GCD: 258 steps, each with a branch
comparator, a controlled swap and a controlled subtract (the "body") on the
work registers `u` and `v`, followed by an apply pass that replays the
recorded branch bits as controlled modular adds or subtracts on the
coordinate registers (background in [8316db1](8316db1.md) and
[8e13587](8e13587.md); see [dialog-gcd-early](../concepts/dialog-gcd-early.md)). The qubit peak of
this tree sits at the compressed-block walk step 9, where the body's
composite scratch is largest.

This commit trims 2 more high bits off the body at step 9 only, using the
existing (but unset) binder-notch knob. The scratch at that step shrinks and
the peak drops from 1302 to 1301. The new op stream had no easy clean nonce
at the old, very narrow apply-phase clean comparators (18 bits), so the
commit widens them to 20 bits globally and to 21–23 bits at ten individual
apply steps, through a new per-step override. That costs about 1,033 Toffoli,
but one qubit is worth about 1,118 Toffoli of score here (1,453,867 / 1301),
so the score still falls by 109,934.

## What changed and why it saves qubits

1. **Binder notch at step 9** (pins in `configure_ecdsafail_submission_route()`,
   `src/point_add/mod.rs`): `DIALOG_GCD_BINDER_NOTCH_STEPS=9`,
   `DIALOG_GCD_BINDER_NOTCH_EXTRA=2`. Both knobs already existed in the base
   but were unset.
   - Read by `dialog_gcd_body_carry_trunc_width(active_width, step)` in
     `rounds/dialog/mod.rs`. That function returns the width of the
     materialized controlled sub/add body: `active_width − w`, where `w` is
     the band trim of the step (`DIALOG_GCD_BODY_CARRY_BAND_TRIMS`, whose
     first band, steps 0–9, is 0), plus 2 at the trio-notch step 11, plus,
     now, `NOTCH_EXTRA` at each listed binder step.
   - At step 9 the body therefore loads and ripples only the low 254 of the
     256 active bits (`active_width` is clamped to 256 in the early steps).
   - The body uses a borrowed composite scratch of `2·body_len − 1` wires
     (gated-load copy plus carry lanes). The code comment says trimming the
     body by `k` lowers the owned scratch deficit, and so the step's peak, by
     `k`. Step 9 was the 1302 binder. After the notch the next binder is at
     1301, so the global peak falls by one. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - Toffoli side effect: about −4 per body (2 fewer gated-load CCX and 2
     fewer carry CCX), over the 4 walks (forward and reverse walk of each of
     the two divisions), about −16.
2. **Global apply clean compare: `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` 18 → 20.**
   This is a *widening*.
   - Each apply step does `acc ±= ctrl·a mod p` with the pseudo-Mersenne
     fold (`dialog_gcd_cmod_add_materialized_pseudomersenne_chunked` and its
     `sub` twin). The add writes the overflow into an extension bit
     `acc_ovf`, folds by `c = 2^256 − p` when it is set (see
     [modular-fold](../concepts/modular-fold.md)), and then erases `acc_ovf`
     by recomputing it as `ctrl ∧ (acc < a)` with `ccx_cmp_lt_into_fast` on
     the top `k` bits only (`compare_start = N − k`). The subtract erases its
     underflow bit the same way in `dialog_gcd_clean_truncated_underflow`.
   - The compare costs about one Toffoli per bit and runs once per apply
     step in each of the two divisions: 2 bits × 258 × 2 = +1,032 Toffoli.
3. **New per-step overrides** for the clean width.
   - New `dialog_gcd_special_clean_compare_bits_from_env(step, env)` parses a
     list `step:bits,...` and returns `bits` for a listed step, otherwise the
     global width. It is wrapped as
     `dialog_gcd_special_overflow_clean_compare_bits` and
     `dialog_gcd_special_underflow_clean_compare_bits`.
   - To make the step index available, every materialized add/sub in the
     apply path gets an `_at_step` variant taking `step: Option<usize>`, and
     the callers in `rounds/dialog/compressed.rs` and `rounds/dialog/mod.rs`
     pass `Some(step)`. The old names forward `None`, which means "use the
     global width".
   - Pins: `DIALOG_GCD_SPECIAL_OVERFLOW_CLEAN_STEP_BITS =
     113:21,131:21,142:22,187:23,205:22,210:21` and
     `DIALOG_GCD_SPECIAL_UNDERFLOW_CLEAN_STEP_BITS = 42:22,91:22,118:22,149:21`.
     That is 10 + 7 = 17 extra compare bits, about +17 Toffoli. These are
     the steps where the author's search found the truncated clean failing
     on test inputs.
   - Net Toffoli: +1,032 + 17 − 16 ≈ +1,033, the measured change.
4. **Dormant knob `DIALOG_GCD_TOBITVECTOR_CSWAP_BODY_TRIM`** (new
   `dialog_gcd_tobitvector_cswap_width`). When set to 1 it would shorten the
   controlled swap of each walk step to the body width. The four cswap loops
   in `compressed.rs` now iterate over `u[..cswap_width]`. The route pins it
   to 0, so `cswap_width = active_width` and the loops are byte-identical to
   the old `u_active` loops.
5. **`DIALOG_TAIL_NONCE`: 60009363210 → 38978004**, the fixed `X;X` identity
   tail that reseeds the 9,024 test inputs.

## Why it is still correct, and what it risks

- **The step-9 notch.** The code comment calls it value-exact, on the
  grounds that the realizable bit length of `u` and `v` sits below the
  active width, so the two cut bits of both operands are 0 and no carry
  reaches them. That bound is the same empirical one the band trims rely on
  (their comment says failures are "selected away by the co-tuned reroll"),
  so treat it as probabilistic. A wrong body leaves the walk off its path,
  which shows up as a classical mismatch and ancilla garbage.
- **The cleans.** They are truncated comparisons, and they fail when `acc`
  and `a` agree on all compared top bits, with probability about 2^-k per
  call. The failure leaves `acc_ovf` dirty, which shows up as ancilla or
  phase garbage. Widening from 18 to 20 bits cuts that rate by about 4×, and
  the per-step overrides cut it further at the ten steps that failed in the
  author's search. This is a Lambda purchase, not a saving.
- The dormant cswap knob is off, so it changes nothing.
- The shipped nonce `38978004` draws a clean test set: 9,024 of 9,024
  shots, with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving is one qubit from cutting 2 bits off one step's body width, which
is width truncation. The comparator change goes the other way: it widens
comparators to restore a clean island. So comparator/width truncation fits.
Since the gain is a qubit, Register and Scratch Allocation → scratch/ancilla
reuse is a close runner-up: the notch works by shrinking the composite
scratch at the peak step.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout e321f72 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol e321f72 a5a590a -- src/point_add` is
   239 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a5a590a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because they override the route
   defaults pinned in `configure_ecdsafail_submission_route()`. Expect:
   - 1301 qubits
   - 1,454,900 average Toffoli (rounded)
   - score 1,892,824,900
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `38978004` and an identical op
stream. Any other change needs a new nonce hunt.

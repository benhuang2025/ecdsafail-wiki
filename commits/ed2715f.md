## Summary

This commit stacks two headroom-spending knobs onto the constant-propagation
tree of [`497cc20`](497cc20.md). Both levers spend spare qubit headroom on
cheaper exact layouts:

- **Fold vents.** It re-applies gnuchev's own fold-vent setting from
  [`764afda`](764afda.md), which `497cc20` did not include. The apply `+f` folds with
  a scheduled vent count `g ≥ 18` get two extra clean carries.
- **Cout margin.** It removes the spare-wire margin of the apply carry-out layout search
  from [`bc2334a`](bc2334a.md), setting `TLM_COUT_LAYOUT_MARGIN` 1 → 0.
  - At margin 0 everywhere, the peak rose to 1167.
  - The author traced that to the calls whose scheduled headroom is `k = 129`. A new knob,
    `TLM_COUT_LAYOUT_FORCE_M1_KS=129`, keeps margin 1 for those calls only.

Average Toffoli drops by 396 at 1166 qubits. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

1. **`TLM_COUT_LAYOUT_MARGIN`: 1 → 0** in `build()`, `src/point_add/mod.rs`.
   - `searched_cout_layout(n, k)` in `trailmix_ludicrous/gidney.rs` picks, for each of the
     516 apply cofactor adds, the chunk width `c` and the unchunked top-part length
     `plain_len` with the lowest `2n + chunked_len + nchunks + 1`.
   - A layout must satisfy `nchunks + plain_len + margin ≤ k` and
     `nchunks + min(c, chunked_len) + margin ≤ k`.
   - With margin 0, one more bit can go into the top part, or one chunk can be saved, in
     each call. A bit in the top part costs no boundary-carry compare.
     The compare is the conditional `compare_geq_cin_middle` in
     `controlled_erase_carry_gated`, about one Toffoli per chunked bit, executed on half
     the shots.
   - See [bc2334a](bc2334a.md) for the layout cost model.
2. **New `TLM_COUT_LAYOUT_FORCE_M1_KS`** in `searched_cout_layout()`. If the margin is
   0 and the call's `k` appears in this comma-separated list, the margin is set back
   to 1 for that call.
   - `build()` sets it to `129`. In `schedule::APPLY_COUT_K`, the value 129 occurs at two
     positions, entries 5 and 512 of 516, so the exception covers two calls.
   - The author's note says margin 0 at those calls raised the circuit peak to 1167. The
     note calls this "the single peak-critical call".
3. **`LUD_EXTRA_FOLD_VENTS`: 1 → 2 and `LUD_EXTRA_FOLD_MIN_G`: 24 → 18.**
   - `load_schedule()` maps each baked `FFG_G` entry `x ≥ MIN_G` to `min(x + VENTS, 53)`.
   - `g` is the number of clean measured carries in the 54-bit `+f` fold
     (`add_f_window`). The bits above `g` use the chunked constant adder
     `controlled_add_const_chunked_graduated_off`, which costs more Toffoli.
   - In the `FFG_G` table, 100 entries lie in 24 to 45 and now get +2 instead of +1. Another
     12 entries lie in 18 to 23 and get +2 for the first time.
   - The author keeps `MIN_G` at 18 because the entries below 18 sit at the apply's lowest
     headroom and are peak-critical.
   - The same edit appeared in [`764afda`](764afda.md), on a tree without constant propagation.
4. **Nonce.** The default `DIALOG_TAIL_NONCE` goes from 400002427 to 123000008384. The
   comment block above the knobs is rewritten to describe the stack.

`TLM_GCD_ADAPTIVE_LAYOUT_MARGIN=0` was already in the base, from `916c0e3`.

## Why it is still correct, and what it risks

All three edits are value-exact. They change only how an exact adder is split
into chunks, or how many of a fold adder's carries are measured-vented
instead of chunked. Every boundary carry is still erased by a full comparison.
The fold's existing approximation, which drops the carry out of bit 53, is
unchanged.

The real risk is the peak, and the k = 129 exception shows it is real. A margin
of 0 assumes the schedule's `k` is exactly the free headroom. At those calls the
assumption was off by one, and Q rose to 1167. With the exception, the
measured peak stays 1166. The submission does not explain why those calls are
off by one, and I did not trace it.

The nonce was re-hunted. `123000008384` gives 0 classical, 0 phase and 0
ancilla failures over all 9,024 shots, with an average of 1,414,439.206. The
author puts clean-nonce density at about 1 in 8,000. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is fold/carry truncation. No truncation window moves. The
changes re-budget headroom for exact adder layouts and fold vents, so
**Register and Scratch Allocation → ancilla-lifetime / venting** fits the
mechanism better. The header keeps the published label.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 497cc20 -- src/point_add`.
   The base is the git parent. `git diff --ignore-cr-at-eol 497cc20 ed2715f -- src/point_add` is 44 changed lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol ed2715f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*`
   environment variables set. Expect:
   - 1166 qubits
   - 1,414,439 average Toffoli (rounded; 1,414,439.206 before rounding)
   - score 1,649,235,874
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `123000008384` and an identical op
stream. Any other change needs a new nonce hunt.

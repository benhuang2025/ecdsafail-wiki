## Summary

[`9a81017`](9a81017.md) had widened the dialog-GCD branch comparator back to
46 bits, to make its new 1313-qubit structure easier to land on a clean nonce.
This commit narrows it again to 45 bits, the value of the previous frontier
`91061af`. The cap binds on 219 of the 259 GCD steps, and the comparator runs
in four transcript passes at one Toffoli per bit, so the change saves
4 × 219 = 876 average Toffoli. Qubits stay at 1313.

The commit also adds a jump-depth convergence model to the analysis filter and
two research memos. Neither touches the op stream.

## What changed and why it saves Toffoli

1. **`DIALOG_GCD_COMPARE_BITS`: 46 → 45** in
   `configure_ecdsafail_submission_route()` (`src/point_add/mod.rs`).
   - `b0_and_b1 = v[0] AND (u > v)` is computed by
     `dialog_gcd_ccx_cmp_gt_truncated_into_width_hosted` on the top
     `min(COMPARE_BITS, aw)` bits of the active window (see
     [`e4497a6`](e4497a6.md)).
   - It costs one Toffoli per bit, with its carries cleared by measurement (see
     [measurement-uncompute](../concepts/measurement-uncompute.md)).
   - At slope 1.014 and margin 10, `aw ≥ 46` on 219 steps. Forward and reverse,
     for the two GCD factors, that is 4 × 219 = 876.
2. **`DIALOG_TAIL_NONCE`: 689 → 5005587.** This reseeds the 9,024 test inputs.
   The comment says the nonce was found with the classical prefilter and then
   confirmed quantum. See
   [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).
3. **`src/point_add/dialog_gcd_classical_filter.rs`** (analysis only, see
   [`ec0fa98`](ec0fa98.md)) gains three items:
   - `full_gcd_step_jump`: one binary-GCD step that removes up to `depth`
     trailing zeros. Depth 2 is the deployed K2.
   - `jump_steps_until_zero`.
   - `measure_jump_convergence`, which reports the worst-case and mean step
     count per depth over a set of factors.
4. **Two memos in `src/point_add/memory/`:**
   - `2026-06-05-jump-depth-kj-measured-negative.md` measures the worst-case
     step count over the 18,048 factors of one nonce: 401 at depth 1, 259 at
     K2, 227 at K3. Each extra depth adds an uncompressed shift bit per step,
     so K3's log would be about 20% larger (+140 qubits) for only 12% fewer
     steps. K2 is the optimum.
   - `2026-06-05-ghost-log-pack-tapped.md` records that at the 1319-qubit base
     the peak phase was `dialog_gcd_apply_chunk_sub_final_ripple`, with tx, ty,
     a live slice of the compressed log and the ripple carries co-live. It
     notes that log hosting on the high bits of `u` and block-by-block
     lifecycles are already deployed.

## Why it is still correct, and what it risks

The comment says the comparator "still decides every branch correctly on the
reachable support at 45". In general it is a probabilistic truncation. If `u`
and `v` agree on the top 45 bits of the window, the step can skip a needed
swap and the subtract underflows. That gives classical failures, plus phase or
ancilla garbage when the reverse pass no longer mirrors the forward one. The
narrower comparator raises λ. The shipped nonce 5005587 draws a clean set,
with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots per the
commit comment. The filter and memo additions do not change the circuit.

## Classification rationale

The only circuit change narrows a comparator: comparator/width truncation.

+/// One full-width binary-GCD step that removes up to `depth` trailing zeros of
+/// `v` per recorded step (Stein/jump generalization of K2; `depth=1` is the
+/// plain dialog, `depth=2` is the deployed K2). The base shift always fires
+/// (`shift_right_assuming_even`); each extra shift is conditional on `v` still
+/// being even, exactly mirroring the quantum `k2_shift2_log` cascade. This is
+/// the convergence model used to size `active_iterations` (== max steps over the
+/// reachable support) for each jump depth.
+fn full_gcd_step_jump(u: &mut U256, v: &mut U256, depth: usize) {
+    let b0 = bit_at(*v, 0);
+    if b0 && *u > *v {
+        std::mem::swap(u, v);
+    }
+    if b0 {
+        *v = v.wrapping_sub(*u);
+    }
+    // Base shift (v is even here: either b0=0 originally, or the subtract above
+    // cleared bit 0).
+    *v >>= 1;
+    let mut shifts = 1usize;
+    while shifts < depth && !v.is_zero() && !bit_at(*v, 0) {
+        *v >>= 1;
+        shifts += 1;
+    }
+}

+/// Steps until `v == 0` for jump `depth`, capped at `limit`.
+pub fn jump_steps_until_zero(mut u: U256, mut v: U256, depth: usize, limit: usize) -> usize {

+    }

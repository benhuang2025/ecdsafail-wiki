## Summary

This repeats the lever of [88079e6](88079e6.md) and [b55ede3](b55ede3.md) one
bit further. Each step of each dialog-GCD apply pass does one controlled
modular add or subtract on the Bézout coefficient. Its overflow bit is
cleared by a comparison on the top `k` bits. This commit makes `k` 18
instead of 19. That removes one Toffoli per apply step. The walk now has 259
steps (since `94535d1`), so the saving is 259 × 2 divisions = 518 Toffoli,
exactly the measured drop. Qubits are unchanged at 1306. The tail nonce was
re-hunted.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 19 → 18.**
   - `dialog_gcd_apply_clean_compare_bits()` (`rounds/dialog/config.rs`) sets
     `compare_start = N − k` at the three apply-pass overflow cleans in
     `rounds/dialog/mod.rs`.
   - In the add form, the clean is `ccx_cmp_lt_into_fast(acc[N−k..], a[N−k..], ctrl, acc_ovf)`.
     After a controlled modular add, `ctrl AND (acc < a)` equals the overflow
     bit, so XOR-ing it in clears the bit. See [88079e6](88079e6.md).
   - In the subtract form (`dialog_gcd_clean_truncated_underflow`), it is the
     same comparison with `a` complemented.
   - The comparator costs about one Toffoli per compared bit, with its
     carries erased by measurement. So one bit less saves 1 Toffoli per apply
     step: 259 × 2 = 518.
2. **`DIALOG_TAIL_NONCE`: 202000012549 → 1076489.**

## Why it is still correct, and what it risks

The overflow clean is a truncated comparison. When the result and the addend
agree on all top 18 bits, the dropped low bits decide the comparison, and the
clean can be wrong. The overflow bit then stays dirty and the wrong correction
spreads into the later apply steps. Each bit removed roughly doubles that
per-step error, so λ goes up.

A failure shows up as a classical mismatch and usually as ancilla garbage on
the overflow wire. The classical GCD pre-filter does not model this
comparator, so nonces must be confirmed with the full evaluator. The shipped
nonce `1076489` validated with 0 classical, 0 phase and 0 ancilla failures over
all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a comparator by one bit, so comparator/width
truncation fits. The nonce change comes with every circuit change and is not a
separate lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 82f7a95 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 82f7a95 fc84586 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol fc84586 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1306 qubits
   - 1,463,786 average Toffoli (rounded)
   - score 1,911,704,516
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=1076489` and an identical op
stream. Any other change needs a new nonce hunt.

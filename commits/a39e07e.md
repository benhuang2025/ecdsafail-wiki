## Summary

This is a bundle. The change that moves the score is one bit off the replay
fold window on rounds where the walk register is 19 to 31 bits wide. That
band contains the first round of the trailing replay batch, whose fold sets
the circuit's peak. So the qubit cap `PP_WALK_MAX_QUBITS` can drop from 1260
to 1259. Fitting the same adds under one fewer wire costs Toffoli.

The rest of the bundle trades Toffoli and λ around that move:
- Four exact op-stream simplifier passes delete or weaken Toffolis they can
  prove redundant.
- Two exact layout tricks save Toffoli: a walk carry loan and square low-bit
  identities.
- One extra compare bit on the wide divide rounds buys back λ for about 300
  Toffoli.
- Borrow predictors on the multiply side's truncated compares lower λ at no
  Toffoli cost.

Net: −1 qubit, +596 Toffoli, score −152,474.

## What changed and why it saves qubits

### The qubit: fold profile and cap (`src/point_add/mod.rs`)

1. **`PP_FOLD_PROFILE`: `38:0,32:-1,19:-3,0:-4` → `38:0,32:-1,19:-4,0:-4`.**
   - This is a `width:offset` band table keyed on `value_width(round)`.
     `pingpong::fold_offset` adds the offset (plus 1 below round
     `PP_FOLD_WIDEN = 242`) to the base fold window, 53 for divide and 54 for
     multiply. The fold window is the number of low bits that the replay cell's
     fused `±f / +2f` correction (`fold_selected`) ripples through. Carries past
     it are dropped. See [modular-fold](../concepts/modular-fold.md).
   - Only the 19..31 band moves, from −3 to −4. With the shipped width schedule
     that is rounds 632..662. There the windows go from 50/51 to 49/50
     (divide/multiply), the same as the band below already had.
2. **`PP_WALK_MAX_QUBITS`: 1260 → 1259.**
   - This is the one qubit cap. Every carry ladder that sizes itself, including
     `walk_low_chunk`, `chunked_add` and `peak_fitted_add`, takes
     `cap − live qubits` as its room; `head_boundary` checks a modelled
     footprint against the same cap. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - The trailing replay batch starts at round `PP_R2 + 1 = 649`, which has walk
     width 24. The `PP_R2` comment puts the peak floor at `1210 + window` for the
     divide's first trailing round. The window drops from 50 to 49, so the floor
     drops from 1260 to 1259, and the cap can follow.
   - The cost is Toffoli: one wire less of room means narrower ladders, so more
     chunks and boundary repairs in the walk and replay adds.

### Toffoli savings, all exact

3. **Op-stream simplifier passes** (new files `affine_simplify.rs`,
   `quadratic_simplify.rs`, `truth_simplify.rs`, `product_simplify.rs`, copied in
   Tier B).
   - `build()` now runs them on the finished op stream, before the 96-X tail and
     the nonce are appended. The order comes from `PP_SIMPLIFY =
     product,affine,quadratic,truth`, and `off` disables them.
   - Each pass walks the stream once and keeps a symbolic Boolean value for every
     qubit, classical bit and pushed condition:
     - `affine`: XOR-sums of "atoms" plus a constant. An atom is a fresh unknown,
       such as an input bit, an `hmr` outcome or an unsupported product.
     - `quadratic`: up to 32 degree-2 monomials.
     - `truth`: exact truth tables over at most 6 atoms.
     - `product` (`truth_simplify::simplify_products`, which includes
       `product_simplify.rs`): looks for a live wire whose value equals a CCX's
       control product.
   - For each CCX, a pass:
     - drops it if the condition or either control is provably 0, or the two
       controls are complements;
     - turns it into X if both controls are provably 1;
     - turns it into CX if one control is 1 or both are equal;
     - (product pass only) turns it into CX from a witness wire that already
       holds `c1·c2`, with an X when the witness holds the complement.
   - These are identities on every input, so nothing new can fail. See
     [dead-gate-strip](../concepts/dead-gate-strip.md).
4. **Walk carry loan, `PP_CUT_WALKLOAN = 1`** (`pingpong.rs`).
   - In `walk_add_single` and `walk_add_split`, `target[0]` becomes redundant
     after the bit-1 preamble:
     - on the forward walk it equals `source[0]`, so one CX clears it;
     - on the walk-back it is the constant 1, so one X clears it.
   - `walkloan_park` clears it, and the new `modular::ripple_add_lent` uses it as
     the carry wire at position `width − 3` instead of allocating a fresh one. The
     same gate restores it afterwards. The split path rebuilds the bit-1 sum
     instead.
   - So each walk ripple holds one fewer owned carry. `walk_low_chunk(.., loan)`
     uses that wire: the single ripple now fits up to `low < 5` instead of `low <
     4`, and a split's low chunk is one bit narrower (`low − 1`).
   - The boundary repair `erase_boundary_carry` compares the whole low chunk, so
     it is exact, and one bit narrower costs one Toffoli less under its half-time
     condition. See [venting-and-wire-loans](../concepts/venting-and-wire-loans.md).
5. **Square low-bit identities, `PP_CUT_SQIDENT = 1`** (`square.rs`,
   `modular.rs`).
   - The new `ripple_add_proved(.., c0, c1)` and its wrappers `addsub_full_low` /
     `addsub_wide_low` take build-time facts about the first two carries:
     - `Carry0::IsAddend0`: carry 0 equals addend bit 0, so it costs one CX;
     - `Carry0::Zero`: carry 0 is 0, so it costs no gate;
     - `Carry1::CopiesCarry0`: carry 1 equals carry 0, so it costs CXs only.
   - The facts follow from squares: `x² ≡ x0 (mod 2)` and bit 1 of any square is
     0. They are applied to `diag_correction` and to the three cross-term
     add/subtracts in each of `tri_square_k2r` and `tri_square_k2r_inv`.
   - Each use saves one or two Toffoli per call. The new `a2_square_tests.rs`
     checks the result against simulation.

### λ trades

6. **`PP_FLAG_WIDEN_DIV = 38`** (new pin and `pinned_env!(flag_widen_div)`).
   - In `replay_add_halve` (the divide replay), the overflow-flag compare width
     becomes `flag_compare(round) + [value_width(round) >= 38]`. That is one extra
     bit on rounds 0..615.
   - One more Toffoli under a half-time condition on 616 rounds is roughly +300
     executed Toffoli. It halves the tie error at those sites, which buys back λ.
7. **A5 borrow predictors** (`a5_policy()`, env `A5_REPAIR`, default
   `mul-fb-seed`, not pinned).
   - Multiply side only, on rounds with `value_width(round) >= 38`:
     - the replay flag erase in `replay_double_add` ("F");
     - the chunk-boundary erase in `chunked_add`, which gains a `multiply`
       argument ("B").
   - Both pass `borrow_in = Some(bit just below the compared window)` to
     `erase_with_compare` instead of `None`. `cmp_lt_phase` then uses that bit as
     the borrow into the window. This costs the same number of Toffoli plus two
     CNOTs.
   - On a window tie, it guesses the low-part comparison right about 3/4 of the
     time, against 1/2 for a fixed 0. That is a probabilistic λ reduction, not an
     exact repair. See
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

### No effect on the shipped circuit

- `PP_SPLIT_FOLD = 0`. The new `fold_selected_split` would split the fold ladder
  at bit 32 and drop the carry across it. It is off, and the comment says the
  stream is then byte-identical.
- The tail nonce goes from 4399134209103 to 2886213855485. The comment above it
  calls this a "diagnostic placeholder", but it is the nonce that was validated.

## Why it is still correct, and what it risks

- **Exact:** the simplifier passes, the walk carry loan, the square identities
  and the cap move. Each holds on every input. The cap move only re-chunks adds,
  though new chunk boundaries bring their own truncated repairs.
- **Probabilistic, raises λ:** the narrower fold on rounds 632..662. A fold carry
  that escapes the 49-bit window leaves a wrong coefficient and a classical or
  ancilla failure.
- **Probabilistic, lowers λ:** the wider divide flag compare and the multiply
  borrow predictors. A wrong truncated compare shows up as a phase failure.
- The shipped nonce draws a clean test set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The score moves because the peak drops by one qubit. That comes from narrowing
the fold window band that holds the trailing batch's first round, which is
fold/carry truncation. The runner-up was dead-gate strip, because the
simplifier passes are the most code. But they only shave Toffoli, and net
Toffoli rises.

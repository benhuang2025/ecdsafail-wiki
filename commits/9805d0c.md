## Summary

This is the author's [`0261289`](0261289.md) lever, ported from M3kko's
396-step tree to josusanmartin's 399-step tree. The GCD register u starts as
the odd prime p. A swap only happens when v is odd, so u stays odd at every
step. That makes two kinds of lane-0 gates redundant:

- the lane-0 cswap, which now does nothing, since a swap only fires when both
  values are odd;
- the gated load of `ctrl AND u[0]`, which is just `ctrl` and becomes a CX.

The change saves 8 Toffoli per step. Over 399 steps that is 3,192 Toffoli, and
the result is the same on every input. The reroll stays at the base's 21,
which still draws a clean island for the changed stream.

## What changed and why it saves Toffoli

The code is the same as in [`0261289`](0261289.md), which also gives the proof
that u stays odd. All edits are in `src/point_add/mod.rs`:

- A new `dialog_gcd_odd_u_lowbit_fastpath_enabled()` reads
  `DIALOG_GCD_ODD_U_LOWBIT_FASTPATH`.
- The `materialized_*_load` loops in `dialog_gcd_controlled_sub_selected` and
  `dialog_gcd_controlled_add_selected` change lane 0 from
  `ccx(ctrl, u[0], gated[0])` to `cx(ctrl, gated[0])`.
- The six walk loops skip `cswap` at `i = 0`. These are the raw, sidecar and
  block-lifecycle loops, each forward and reverse.
- `configure_ecdsafail_submission_route()` sets the flag to 1.
- A new memory note, `src/point_add/memory/2026-06-02-f78af41-odd-lowbit-reroll21.md`.

**Count.** Per step there are 2 loads and 2 cswaps, for the forward and
reverse walk, in each of the 2 GCD pairs. That is 8 CCX per step, and
8 × 399 = 3,192. This is exactly the measured drop. The 396-step version
saved 8 × 396.

## Why it is still correct, and what it risks

- **Exact.** The rewrites depend only on u[0] = 1, which holds on every input
  and every path, including the reverse walk.
- **Unchanged risks.** The base's approximations remain: the truncated
  comparators, the carry windows and the 20-bit clean compares.
- **The 396-step cut does not carry over.** The memory note says
  `DIALOG_GCD_ACTIVE_ITERATIONS=396` was also tried on this line. With
  rerolls 0–12 and 21 it "all failed with small classical and/or phase
  errors". That shows how much Lambda the step-count cut in
  [`dd103cd`](dd103cd.md) costs.
- **Seed.** The op stream changed, but the existing reroll 21 still draws a
  clean set: 0 classical, 0 phase and 0 ancilla failures over 9,024 shots.

## Classification rationale

The saving comes from the classical invariant that u is odd, used to delete
the lane-0 cswap and weaken the lane-0 load. That is classical specialization,
the same label as `0261289`.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 985ae0f -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 985ae0f 9805d0c -- src/point_add` is
   85 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9805d0c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or other route environment variables set. Expect:
   - 1698 qubits
   - 1,670,437 average Toffoli (rounded)
   - score 2,836,402,026
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL` = 21 and an identical op
stream. Any other change needs a new reroll search.

## Summary

The square builds `x²` from Karatsuba pieces. Each assembly step adds the
cross term `2ab` into the product register and ripples the carry all the way
to the top of the product. Above the cross word the product holds `b²`, whose
bits are effectively random, so a carry survives `j` bits further with
probability about 2^-j. The last few dozen ripple positions almost never
carry, but each one still costs a Toffoli.

This commit stops that ripple 21 bits past the cross word (`SQ_ASM_TAIL=21`).
It saves about 416 Toffoli and makes `x²` wrong on very rare shots. To keep
the line's error budget, the commit also widens the walk registers by one bit
on rounds 683–686 (`PP_WALK_EXTRA_ROUNDS=683:4:1`), which costs about 34
Toffoli and removes slightly more classical error than the cut adds.

## What changed and why it saves Toffoli

1. **`SQ_ASM_TAIL` = 21**, new, in `add_cross`, `src/point_add/square.rs`.
   - `add_cross` performs `product[lo..] += 2ab` (forward) or `-=` (inverse)
     for one node of the recursive square `tri_square_k2r`. `cross` holds
     `2ab` in `2(hi+1)` bits. `acc = product[lo..]` has `lo + 2·hi` bits, so
     the add runs `lo − 2` positions past the cross word with a zero addend.
     See [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).
   - New code: `acc` is cut to `full[..full.len().min(cross.len()+e)]`.
     Every path below uses the cut slice: the fitted chunked direct add, the
     held-boundary add from [`b788efc`](b788efc.md), and the plain
     `addsub_wide_low`. Only `own_top_zero_bits` still reads the full slice,
     so the zero-wire loans are unchanged.
   - Each zero-addend position of the ripple costs one CCX (carry =
     acc AND previous), and the scorer charges it even if it never fires
     (see [dead-gate-strip](../concepts/dead-gate-strip.md)). The carry is
     dropped at the new top instead.
   - With the shipped policies the cut bites at two node sizes. The three
     top-level 128/129-bit squares split at `lo = 64`, so the tail is 62 bits
     and 41 are cut. The 64/65-bit children split at `lo = 32`, so the tail is
     30 bits and 9 are cut; the one 66-bit child (the sum half of the 129-bit
     square) splits at `lo = 33` and loses 10. That is 3 top nodes and 9
     child nodes, each with a forward and an inverse assembly:
     6 × 41 + 16 × 9 + 2 × 10 = 410 positions, which matches the measured
     −416 Toffoli.
   - Background: the author's per-gate profiler (`ccxprof`) found about 1,170
     Toffoli of square CCX that fired in 0 of 9,024 shots. They were the tails
     of carry chains whose fire counts halve per bit (1953, 1773, 1129, 579,
     308, … 1, 0). These are not exactly dead gates, so cutting them is a
     truncation, not a dead-gate strip.
2. **`PP_WALK_EXTRA_ROUNDS` = `683:4:1`**, new, in `value_width()`,
   `src/point_add/pingpong.rs`.
   - `value_width(round)` is the *physical* width of the two walk registers.
     It already adds the guard bit for schedule widths ≤ 64 (`PP_WALK_GUARD_BITS`,
     from [`cc7f10e`](cc7f10e.md)). Now it also adds `walk_extra(round)`,
     parsed once from `start:len:delta` entries.
   - `683:4:1` adds one bit on rounds 683, 684, 685 and 686, in both
     traversals. The schedule width there is 9, the guard makes it 10, and
     this makes it 11.
   - `policy_width`, which sets fold windows, compare widths and seed
     choices, is unchanged. Only the walk adds in those rounds grow.
   - A wider walk register lets a slowly converging input finish without
     overflowing the narrow end of the schedule. The author's schedule model
     ranked this the cheapest classical "buy" available.
3. **Tail nonce:** `TAIL_NONCE` 14939365091 → 16778008906.

## Why it is still correct, and what it risks

- **The tail cut is probabilistic.** On a shot where the carry would have run
  more than 21 bits past the cross word, it is dropped and `x²` is wrong. The
  forward and inverse assemblies cut identically, and the inverse is an exact
  subtraction mod 2^len on the same slice, so the product register is still
  restored exactly. Only the folds that consume the wrong `x²` see the error.
  It appears as a **classical** mismatch, not as phase or ancilla garbage.
- **The walk bit is protection.** It only adds bits, so it cannot create a new
  failure.
- **Paired pricing.** The author compared variants on identical shots (common
  random numbers), over 256 nonces against the base:
  - E = 21 alone: −415.9 Toffoli, +0.000 mismatches per nonce.
  - E = 21 plus the walk bit: −382.4 Toffoli, −0.016 ± 0.010 mismatches per
    nonce.
  - A first package with E = 18 saved 76 more Toffoli but was rejected. The
    walk bit only rescued about half of what the model predicted, so that
    package could have raised the classical error, which the
    [`cc7f10e`](cc7f10e.md) limiting contract forbids.
- λ is 16.68 ± 0.26 over 256 nonces (base 16.51 ± 0.24), under the contract's
  18.
- The shipped nonce draws a clean set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from cutting a carry chain short and accepting a rare
dropped carry. That is fold/carry truncation. It is not a dead-gate strip,
because the cut gates do fire on rare inputs. The walk-width bit is a small
protective buy, not the source of the gain.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 902ec7b -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 902ec7b 0a06121 -- src/point_add` is
   30 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 0a06121 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. This tree reads
   every knob from the fixed `env_raw` table in `mod.rs` and ignores the
   environment, so `SUB4_*`, `TLM_*`, `PP_*` or `HEO_*` variables have no
   effect. Expect:
   - 1251 qubits
   - 893,491 average Toffoli (893,491.043 before rounding)
   - score 1,117,757,241
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `16778008906` and an identical op
stream. Any other change needs a new nonce hunt. The author's GPU screen model
also needed a port (`GRIND_WALK_EXTRA`) so that it uses the same walk widths
as the circuit.

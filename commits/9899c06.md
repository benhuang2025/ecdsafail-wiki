## Summary

[`233a44c`](233a44c.md) stores most Kaliski history bits `m_hist[j]` in idle
high bits of the GCD register `v_w`, above the W-TRUNC width plus a safety
"slack". This commit lowers the slack from 4 bits to 3. Each slot's lowest
allowed coordinate drops by one, so the slot map can place one more history
bit in `v_w` and one fewer needs its own qubit. The peak is set during pair1's
first multiply, where the Kaliski state (including the dedicated history
qubits) is still live, so it drops from 2025 to 2024. The only gates that
change are swaps, so Toffoli is unchanged. `KAL_REROLL` goes from 254 to 47.

## What changed and why it saves a qubit

1. **`kal_dialog_fold_slack()`: 4 → 3** (`src/point_add/kaliski_state.rs`,
   env `KAL_DIALOG_FOLD_SLACK`). The slack is used in two places:
   - `dialog_fold_shift_width(i) = kal_wtrunc_width(i) + slack`: the STEP-6
     shift `v_w >>= 1` now runs over one bit fewer. Swaps cost no Toffoli.
   - `dialog_fold_vw_slotmap`: `wt_hi(i) = kal_wtrunc_width(i − 1) + slack` is
     the highest bit iteration `i` may touch. Each slot's anchor (the max
     `wt_hi` over the iterations that write or borrow it) drops by one, so the
     greedy matching can place one more slot in `v_w`. One more `m_hist` slot
     becomes `alias_v_w[c]`, and `with_kal_inv_raw_borrow_v_w_pair` allocates
     one fewer dedicated qubit.
   - The binder in [`233a44c`](233a44c.md) was `shift22_step4` inside pair1's
     first multiply (2025). That runs in the body of the pair1 inversion, while
     the dedicated history qubits are live, so it drops to 2024. The affine
     recompute cluster was already at 2024, so the two now bind together.
     See [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
2. **`KAL_REROLL`: 254 → 47** (`src/point_add/mod.rs`): identity `X;X` pairs
   that only re-draw the test inputs.
3. **New file `src/point_add/memory/dialog-fold-slack-3-reroll-47.md`**
   (31 lines): a plain-text log of the validation, not compiled.

## Why it is still correct, and what it risks

- **The slack guards against W-TRUNC excursions.** Per the comment in
  `233a44c`, rare inputs carry a set bit one place above
  `kal_wtrunc_width(i)`, and the shift must cover it so it comes back into
  range. With slack 3, an input whose `v_w` goes three or more bits above the
  envelope can have that bit dropped by the shift, or collide with a folded
  history bit. The GCD is then wrong (classical mismatch) or a history bit is
  corrupted (phase or ancilla garbage). Slack 3 still covers the reported
  one-bit excursions.
- **Island.** The notes file records `rr = 47` as the clean re-roll for
  slack 3. Slack 2 was clean at `rr = 510` but did not lower the
  peak further. Slack 1 and `R_SMALL = 327` had no clean re-roll in 0–511.
  The shipped stream is clean: 0 classical, 0 phase and 0 ancilla failures over
  9,024 shots. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

One more history bit is parked in a provably idle wire instead of a dedicated
qubit, which shortens the dedicated register at the peak. That is
ancilla-lifetime / venting. The slack itself is a safety margin, so
comparator/width truncation is the runner-up reading.

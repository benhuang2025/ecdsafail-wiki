## Summary

The trailmix GCD runs a fixed number of steps, `ITERS`. Every step costs
Toffoli in all four GCD walks and both payload apply passes. This commit
lowers `ITERS` from 261 to 259. Two fewer steps save Toffoli directly, and
they shorten the compressed tape by 5 qubits, because 258 decisions after
step 0 fill exactly 86 base-5 triples and the trailing 5-qubit pair window
disappears.

The commit spends both gains on safety. Fewer steps mean more inputs that do
not converge in time, and the shorter tape frees room under the 1153 cap. So
the `SCHED_J2`/`GAP_J2` width tables are widened again on the tail:
`afcc72e`'s one-bit narrowing on steps 201–260 is undone, and 30 entries end
one bit wider than before `afcc72e`. Per-call reserve tables keyed on call
order are re-indexed for the shorter walk. The cascade allow-list and the
strip table are re-mined. The net result is −2,478 Toffoli at the same 1153
qubits.

## What changed and why it saves Toffoli

### 1. `ITERS`: 261 → 259 (`src/point_add/trailmix_ludicrous/schedule.rs`)

- Each removed step drops one divstep from each of the four walks (compare,
  `u`/`v` cswap, controlled add, halving shifts, codec gates) and one payload
  update from each of the two apply passes (controlled modular add, the
  256-wide apply-cswap where it is not skipped, and the fused doubling). The
  concept page estimates about 3,050 executed Toffoli per step. See
  [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md).
- **Tape.** `jump_dialog_regions(n3 = ITERS / 3, ITERS)` in `codec.rs` lays
  out `ITERS − 1` symbols after `Step0`. At 261 that is 86 `Triple` windows
  (7 qubits each) plus one `Pair` (5 qubits): 2 + 602 + 5 = 609 qubits. At 259
  it is exactly 86 `Triple`s: 604 qubits.
- `BAKED_ITERS` stays 258, so `baked_artifacts_valid()` stays false, as it
  already was at 261.
- The width tables keep 261 entries; entries 259 and 260 are now unused.

### 2. Width tables widened (`schedule.rs`)

`SCHED_J2` and `GAP_J2` change at the same 80 indices by the same amounts,
+84 bits in total relative to the base:

| steps | change vs `afcc72e` | change vs `f735fd7` (before the narrowing) |
|---|---|---|
| 102, 106, 109, 117–121, 125, 135–138, 140, 144, 146–149, 156, 158 | +1 | +1 |
| 201–202, 208, 245 | +2 | +1 |
| 203–207, 209–237, 244, 246–260 | +1 | 0 |
| 238–242 | +1 | +1 |

So relative to the table before `afcc72e`, 30 "hot" entries are one bit
wider and the rest of the tail is back where it was. A wider `SCHED_J2[i]`
means fewer inputs overflow the register at step `i`. A wider `GAP_J2[i]`
means fewer comparator mis-decisions. Both cost Toffoli on every shot,
roughly one per added bit per walk. They buy back λ lost to the shorter walk.
See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

The peak stays at 1153 even though the tail registers are wider again,
presumably because the 5 tape qubits freed by the shorter walk cover the
extra width. The caps are still 1153.

### 3. Call-index tables re-keyed (`src/point_add/mod.rs`, `build()`)

`TLM_TARGET_FOLD_CALL_RESERVE_OVERRIDES`,
`TLM_TARGET_FFG_CALL_RESERVE_OVERRIDES`, `TLM_TARGET_FFG_CALL_RESERVES` and
`TLM_TARGET_FOLD_CALL_RESERVES` map the n-th fold or `add_f_window` call to a
reserved headroom. Two fewer steps mean fewer calls before the later phases,
so the late indices shift down: for example `336:3,338:3,340:3` becomes
`332:3,334:3,336:3`, and `355:10` becomes `351:10`. Entries for calls that
no longer exist are dropped, for example `259:20`. The same physical calls
keep the same reserves. The long `concat!` strings are flattened into single
literals. New trace hooks (`CUR_DIVSTEP`, `set_cur_divstep`,
`TLM_TRACE_CALLS` prints in `arith.rs`, `fused.rs` and `gcd.rs`) log which
step each call belongs to. They emit no ops.

### 4. Affine bridges matched by shape (`mod.rs`, `apply_exact_affine_bridges`)

- The fixed-index patterns become `match_shape` patterns over wire
  variables, which must bind to distinct wires under one shared classical
  condition. The rewrites are the same exact identities as in
  [`9aceb7d`](9aceb7d.md) and [`9b2ce61`](9b2ce61.md).
- Bridge 1 still matches once, so it is still −1 T.
- Bridge 2 (the control-delta form) is searched for generically, but it has
  0 matches at `ITERS = 259`. The comment says its site "lived in the
  ITERS=261 tail divsteps". The function then skips it, so its one Toffoli
  is lost.

### 5. Cascade roots re-measured (`trailmix_ludicrous/constprop.rs`)

`DEFAULT_CASCADE_TRIPLES` becomes 7 triples, labelled "W30x259 accept set":
`(12,272,273)`, `(9,273,274)`, `(530,531,823)`, `(530,531,1152)`,
`(273,274,1097)`, `(530,531,1149)`, `(529,530,1150)`. The admission rule is
at least 250 static CCX removed per unit of λ, and Σλ ≤ 0.5. The doc comment
above the list still shows a fire-count table for an 11-root set from the
`afcc72e` geometry. That table does not describe these 7 entries. Mechanism:
[`f735fd7`](f735fd7.md).

### 6. Strip table re-mined (`src/point_add/deep_strip_keys.rs`, copied)

This is a fresh census against the 259-step stream. Its header reads
"AUTO-GENERATED by census_miner … shots=32000016 … dead=10734
downgrades=2848 … budget=Some(1.0) sum_lambda_accepted=0.9997". That is
13,582 keys, against 14,119 in the base. See
[dead-gate-strip](../concepts/dead-gate-strip.md).

### 7. Tail nonce

`SUB4_TAIL_NONCE` default 865024934 → 11015281151. The comment records avg
1,281,867.368 × 1153.

## Why it is still correct, and what it risks

- **Fewer steps is probabilistic.** An input whose GCD needs more than 259
  steps does not converge, so the quotient is wrong and the tape is not
  erased. That shows as classical and ancilla failures. The concept page
  quotes non-convergence of 2.839×10⁻⁴ of inputs at 258 steps and
  2.86×10⁻⁵ at 261. 259 lies between them, and every shot runs two inversion
  inputs. So this is a real λ cost.
- **The width widening is a λ buy-back.** It makes overflow and comparator
  mis-decisions rarer on the 80 changed steps.
- **The bridges are exact**; bridge 2 simply has no site to rewrite.
- **The cascade roots and strip keys are empirical**, each priced as a small
  λ.
- The re-keyed reserve tables only change which layout a call uses, not what
  it computes.
- The shipped nonce `11015281151` draws a clean test set: 9,024 of 9,024
  shots, with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from cutting the iteration bound `ITERS` against a measured
convergence failure rate, which is iteration/threshold tuning. The width
widening, the re-keyed tables and the re-mined cascade and strip are there to
keep that cut huntable and consistent with the new geometry.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout afcc72e -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol afcc72e 0422437 -- src/point_add` is
   22,955 changed lines in 7 files, 22,686 of them the strip table.
2. **Copy the generated strip table from the commit:**
   `git checkout 0422437 -- src/point_add/deep_strip_keys.rs`. It is
   census-mined data; part 6 above describes it.
3. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It covers `mod.rs` and the five
   `trailmix_ludicrous` files.
4. **Check the tree.** `git diff --ignore-cr-at-eol 0422437 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   or `TLM_*` overrides set. Expect:
   - 1153 qubits
   - 1,281,867 average Toffoli (1,281,867.368 before rounding)
   - score 1,477,992,651
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `11015281151` and an identical op
stream. Any other change needs a new nonce hunt.

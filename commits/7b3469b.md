## Summary

Each point addition runs the ping-pong divider twice: a divide with
`rounds() = 700` rounds and a multiply whose depth is set separately by
`SUB4_PP_ROUNDS_MUL`. In the base the multiply runs `rounds() − 1 = 699`
rounds. jackylee0424's `99d85b5` had already cut it to 698.

This commit sets it to `rounds() − 3 = 697`, two rounds below the base and
one below `99d85b5`. Each removed round drops a walk round, a replay cell and
a walk-back round from the multiply traversal. That is −923 average Toffoli
against the base and −376 against `99d85b5`, at the same 1278 qubits. The
cost is more exposure to inputs whose multiply walk needs those rounds to
converge.

## What changed and why it saves Toffoli

1. **`rounds_for(PingPongDirection::Multiply)`** in
   `src/point_add/pingpong_div.rs`: the default of `SUB4_PP_ROUNDS_MUL` goes
   from `rounds() − 1` to `rounds() − 3`, so 699 → 697 rounds. The divide
   keeps `rounds()`.
   - `pingpong_mod_mul_div_in_place` reads `rounds = rounds_for(direction)`.
     The multiply walk pushes one tape sign per round, and the replay and
     walk-back loops run up to `rounds`. So each removed round deletes one
     full 256-bit replay cell (chunked add, fold, chunk and flag repairs)
     plus a walk add and a walk-back add at the narrowest walk width.
   - Measured: about −547 T for the first round (`e928607` → `99d85b5`) and
     −376 T for the second (`99d85b5` → this commit).
   - **Qubits.** In this tree the replay's carry ladders are sized against
     the cap `SUB4_PP_PEAK = 1278` (`plan()`, with `chunk_layout` and
     `LADDER_TARGET` fitting each ladder to the room left). A shorter tape
     leaves more room under the same cap, but the cap does not move, so Q
     stays 1278. See [pingpong-division](../concepts/pingpong-division.md)
     and [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
2. **Tail nonce** (`src/point_add/mod.rs`): the default
   `SUB4_PINGPONG_TAIL_NONCE` goes from 6215000001 to 12145000000.

## Why it is still correct, and what it risks

- **Depth is a truncation.** An input whose multiply walk has not reached
  `(±1, ±1)` after 697 rounds gives a wrong product and leaves the walk
  registers dirty. That shows as classical and ancilla failures.
- The code comment in `rounds_for` prices one round on one traversal at
  about +0.05 λ, so two rounds add roughly +0.1 λ to the base.
- The shipped nonce `12145000000` draws a clean test set: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Cutting a fixed round count against a measured convergence rate is
iteration/threshold tuning.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout e928607 -- src/point_add`.
   - `git diff --ignore-cr-at-eol e928607 7b3469b -- src/point_add` is 4
     changed lines in 2 files.
   - The git parent `99d85b5` is `e928607` with `rounds() − 2` and another
     nonce. Diffing against it is also 4 lines and shows only the last step,
     −2 → −3. Either base rebuilds the commit.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7b3469b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set (in particular no `SUB4_PP_ROUNDS_MUL`). Expect:
   - 1278 qubits
   - 942,974 average Toffoli (rounded)
   - score 1,205,120,772
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `12145000000` and an identical op
stream. Any other change needs a new nonce hunt.

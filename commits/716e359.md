## Summary

[`5526766`](5526766.md) frees the round-0 lift bit `a0` (tape bit 0) during
the replay and recomputes it at walk-back round 0 with `recompute_a0`. That
routine evaluated a constant comparison through a 55-position truncated carry
chain, 55 CCX per call, once per traversal.

This commit notices that the comparison is decided, on all but a 2^-225
fraction of inputs, by bit 255 of the low word alone. So the recompute
becomes one CX, saving 110 Toffoli, and it is also more accurate than the
truncated chain it replaces. Separately, the endpoint fold window
`SUB4_PP_ENDPOINT_FOLD_WINDOW` goes from 26 to 18, the value REgonLevy had
just shipped in [`edeed3f`](edeed3f.md) on another branch. That shortens the
endpoint carry chains by 8 positions each, for the remaining 33 Toffoli. Q is
unchanged at 1264.

## What changed and why it saves Toffoli

1. **`recompute_a0` short cut**, `src/point_add/pingpong_div.rs`, enabled by
   the new pin `set_default_env("SUB4_PP_A0_TOPBIT", "1")` in `mod.rs`. With
   the pin set, the function allocates one wire, does `b.cx(v[N - 1], out)`,
   and returns. The old chain code stays behind the flag.
   - **What `a0` is.** Round 0 lifts an even denominator to `a − p` so the
     walk starts odd, and `a0` records which of the four lift arms was taken.
     The doc comment of `recompute_a0` derives, with `w` the restored round-0
     output, `s` its sign, `L` its low 256 bits and `h = round1_h() = 2^31 + 488 = (f − 1)/2`:
     - `s = 0`: `a0 = [w ≥ (p+1)/2] = [L ≥ 2^255 − h]`
     - `s = 1`: `a0 = [L ≥ 2^255 + h]`
   - **Why one bit is enough.** Both thresholds sit within `h ≈ 2^31` of
     2^255. Outside the two slices `[2^255 − h, 2^255)` and `[2^255, 2^255 + h)`,
     `[L ≥ threshold]` equals `L[255]`. A random `L` lands in a slice with
     probability about `h / 2^256 ≈ 2^-225`.
   - **What it replaces.** The old code computed `a0 = s ^ carry_256((L ^ s) + K)`
     with `K = 2^255 + h`. Its chain ran over bit positions 3 to
     `round1_window(N) − 1 = 57`, then jumped straight to bit 255, treating
     the carry out of bit 57 as the carry into bit 255. That is 54 chain CCX
     plus one final CCX, 55 per call. It also cost 2 × 256 CX to fold `s` into `L`
     and back, and the chain wires were measured out. The jump was itself a
     truncation, wrong at about 2^-27.
   - `recompute_a0` is called once in each traversal's walk-back round 0 (the
     multiply's `walk_back_round` and the divide's `value_walk_back`), so the
     saving is 2 × 55 = 110 Toffoli on every shot.
2. **`SUB4_PP_ENDPOINT_FOLD_WINDOW` 26 → 18**, a `set_default_env` pin in `mod.rs`.
   - `endpoint_fold_window()` sets how far past `f`'s top bit the endpoint
     constant-add chains run. The doc comment says a chain is
     `min(n − 2, highest_set_bit(c) + window)` positions long.
   - It is used by `conditional_mod_negate` (the terminal sign fixes),
     `signed_mod_add_pm`, `mod_halve_pm`, `mod_double_pm`, the signed-frame
     converters (off in this build), and `round1_window`, which sizes the
     round-1 `h` borrow.
   - Each live call loses 8 chain positions, and so about 8 Toffoli. The
     measured total, net of the 110 above, is about −33. See
     [modular-fold](../concepts/modular-fold.md).
3. **Tail nonce:** `SUB4_PINGPONG_TAIL_NONCE` default 94006560419609 →
   97212983354114.

## Why it is still correct, and what it risks

- **The `a0` short cut lowers λ.** It is wrong only on the 2^-225 slices
  above, which never occur in practice. The chain it replaces failed at about
  2^-27 per call. If the recomputed `a0` were wrong, the walk-back would
  leave the round-0 lift undone, and the shot would show classical and
  ancilla garbage. The `z_if` phase fix of 5526766 still uses the same bit.
- **The fold window is probabilistic.** A carry that would have run more than
  18 positions past `f`'s top bit is dropped, at about 2^-18 per call instead
  of 2^-26. The value is then wrong, so a failure is classical. The sparse
  `h` borrow sized by `round1_window` has the same property. That raises λ a
  little.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The larger saving replaces a truncated constant comparison by its single most
significant bit. That is the extreme case of comparator/width truncation, and
[comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md)
cites it as such. Unusually, it is also more accurate than what it replaces.
The window cut is a secondary fold/carry truncation. The runner-up is
Strength Reduction, since the result is effectively an exact identity.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5526766 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 5526766 716e359 -- src/point_add` is
   13 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 716e359 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1264 qubits
   - 903,471 average Toffoli (rounded)
   - score 1,141,987,344
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `97212983354114` and an identical op
stream. Any other change needs a new nonce hunt.

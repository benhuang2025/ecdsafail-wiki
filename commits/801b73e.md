## Summary

Every Kaliski iteration doubles the Bézout coefficient `r` modulo p. A full
modular double is a shift plus a conditional subtraction of p, and the
subtraction costs Toffoli. While `2r < p` the subtraction never fires, and a
plain bit rotation (0 Toffoli) gives the same result. The circuit uses the
rotation for iterations below `R_SMALL_THRESHOLD`. This commit raises the
threshold from 321 to 327, so six more iterations per walk take the free path.
That saves 1,248 average Toffoli at the same 2002 qubits. The reroll count
changes from 47 to 34.

## What changed and why it saves Toffoli

- **`src/point_add/kaliski_state.rs`: `R_SMALL_THRESHOLD` 321 → 327.**
  - Used through `r_small_threshold()` at four sites in `kaliski_walk.rs`:
    step 7/8 of the forward bulk and generic iterations, and the matching
    halvings in the backward walk.
  - Below the threshold, `r := 2r mod p` is `mod_double_no_corr(b, r)`, a
    chain of `swap`s that rotates the register by one bit (0 Toffoli). Its
    inverse in the backward walk is `mod_halve_no_corr`. Above it, the circuit
    uses a full modular double (`mod_double_inplace_direct` or
    `mod_double_inplace_fast`: a shift plus a conditional constant add of the
    Solinas correction), and the backward walk uses
    `mod_halve_inplace_fast_with_dirty`. Those cost Toffoli.
  - Iterations 321 to 326 now use the rotation in each of the four Kaliski
    walks (forward and backward for `pair1` and `pair2`). The measured saving
    is 1,248 average Toffoli.
- **`src/point_add/mod.rs`, `build()`: the default `KAL_REROLL` goes from 47 to 34.**
  This is the count of identity `X(tx[0]); X(tx[0])` pairs that selects the
  9,024-shot test draw. The author's screen of `rr = 0..127` found 34 clean.

## Why it is still correct, and what it risks

- The rotation equals `2r mod p` only when the top bit of `r` is 0 and
  `2r < p`. The code comment proves `max(r, s) ≤ 2^k` at iteration `k`, which
  guarantees this only for `k` up to about 255.
- For `k` in 321 to 326 that bound proves nothing, so the shortcut is
  empirical. It holds as long as `r` is still below p/2, which is true for most
  inputs at this depth but fails on some that are close to the end of their
  walk. The submission note calls the change "provably safe". That is wrong
  for these iterations.
- A failure leaves `r` wrong, so the inverse and λ are wrong. That would show
  as a classical mismatch, and the backward walk would also leave ancilla
  garbage.
- The author also screened 328 and found no clean draw. On the `rr = 34`
  draw, the full benchmark gives 0 classical, 0 phase and 0 ancilla failures
  over 9,024 shots.

## Classification rationale

The change moves an iteration threshold below which a gate block (the modular
correction) is treated as dead. That matches Dead-Code and Redundancy
Elimination → iteration/threshold tuning. The runner-up would be
comparator/width truncation, since it is an empirical cut like the width
envelope. But no width changes here; a whole correction is skipped.

   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 801b73e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or `AFFINE_*` environment variables set. Expect:
   - 2002 qubits
   - 2,576,303 average Toffoli (rounded)
   - score 5,157,758,606
   - 0 classical, 0 phase and 0 ancilla failures

Any other change needs a new reroll search.

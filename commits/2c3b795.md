## Summary

The author starts from their own 1307-qubit tree [89abe1b](89abe1b.md) and
turns three probabilistic knobs of the dialog-GCD route one notch tighter
(background in [8316db1](8316db1.md)):

| Knob | Old → new | Toffoli |
| --- | --- | --- |
| `DIALOG_GCD_ACTIVE_ITERATIONS` | 259 → 258 | about −2,885 |
| `DIALOG_GCD_BODY_CARRY_BAND_TRIMS` | `0,1` → `0,1,2` | −1,032 |
| `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` | 20 → 19 | −516 |

The total is −4,433, exactly the measured change. The last two knobs are the
same changes as [ace6347](ace6347.md) and [779fc2b](779fc2b.md), which other
contestants made in parallel. The new part is one step fewer of the GCD.
Qubits are unchanged, and one nonce was hunted for the combined stream.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 259 → 258.**
   - `dialog_gcd_active_iterations()` is the loop bound for every walk, apply
     and reverse-walk emitter in `rounds/dialog/`.
   - The dropped step 258 has `active_width` 6, so its walk steps are nearly
     free. Its cost is in the apply pass of each division: a modular double or
     halve of `y`, a controlled 256-bit modular add or subtract with its
     overflow clean, and a 256-wide controlled swap.
   - That is about 2,885 Toffoli, the same as 260 → 259 in [f5f0f61](f5f0f61.md).
2. **`DIALOG_GCD_BODY_CARRY_BAND_TRIMS`: `"0,1"` → `"0,1,2"`.**
   - At 258 steps the bands are `ceil(258 / 3) = 86` steps: steps 0–85 get
     trim 0, steps 86–171 get trim 1, and steps 172–257 get trim 2.
   - Each trimmed bit removes one gated-load CCX and one carry CCX from the
     walk's controlled subtract or add (`dialog_gcd_controlled_{sub,add}_selected`).
     [ace6347](ace6347.md) has the mechanism.
   - Against `0,1` at 258 steps, that is 129 more trimmed bits per walk,
     × 2 Toffoli × 4 walks = 1,032 Toffoli.
3. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 20 → 19.**
   - The apply pass's overflow clean compares one bit fewer, one Toffoli per
     apply step: 2 × 258 = 516 Toffoli.
   - See [88079e6](88079e6.md) for the mechanism.
4. **`DIALOG_TAIL_NONCE`: 201664 → 2667032**, the fixed 48-pair `X;X`
   identity tail that reseeds the 9,024 test inputs.
5. No comments are updated. The comments around the knobs still describe the
   older values.

## Why it is still correct, and what it risks

All three changes are rare-input truncations, and they fail in different ways:

- **258 steps.** An input whose K2 GCD needs 259 or more steps is not finished.
  This gives a wrong slope and output point (classical), plus reverse-walk
  garbage (ancilla or phase).
- **Two-bit body trim from step 172, one-bit from step 86.** An input whose `u`
  or `v` still reaches into the trimmed top bits gets a wrong subtract. The
  GCD then does not converge (classical, usually ancilla too).
- **19-bit apply clean.** A tie on the top 19 bits leaves the overflow bit
  dirty (classical and phase).

The submission note calls the three levers "value-exact". They are not. They
are exact on the drawn test set only. The hard set is about the union of the
three, which is why each was screened separately by other contestants first.
The classical pre-filter models the first two but not the apply-clean
comparator. The shipped nonce `2667032` draws a test set with 0 classical,
0 phase and 0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Three knobs move together. The largest saving, and the only one not already
taken by a parallel commit, is the iteration count, so iteration/threshold
tuning fits. The runner-up is comparator/width truncation, which covers the
other two knobs.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 89abe1b -- src/point_add`.
   - Do not diff against the git parent `779fc2b`. Its knob values for the
     trim and the apply clean are the same, but its comments differ.
   - Against the parent, the diff is 21 lines. It shows only the iteration
     count and the nonce, and it reverts the comment edits of
     [ace6347](ace6347.md) and [779fc2b](779fc2b.md), which this commit never
     had.
   - Against `89abe1b`, `git diff --ignore-cr-at-eol 89abe1b 2c3b795 -- src/point_add`
     is 8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 2c3b795 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `R84_*` environment variables set, because `set_default_env`
   only fills in unset variables. Expect:
   - 1307 qubits
   - 1,484,779 average Toffoli (rounded)
   - score 1,940,606,153
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=2667032` and an identical op
stream. Any other change needs a new nonce hunt.

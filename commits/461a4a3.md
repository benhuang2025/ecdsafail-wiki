## Summary

In the dialog-GCD apply stage, each step does a controlled modular add or
subtract of `x` into `y`, the "materialized special add". It works in two
parts. First a chunked 257-bit ripple adds the raw value. Then a
pseudo-Mersenne fold adds or subtracts `c = 2^32 + 977` into the low 73 bits
if the add overflowed. The ripple is given a few clean scratch qubits
(`inner_scratch`), and they sit idle during the fold. The fold, meanwhile,
allocated its own 51-wire carry lane.

This commit lets the fold borrow its first carry wires from that idle
scratch, so the fold phase holds up to four fewer fresh wires. Three
existing knobs are turned down at the same time, to lower the other phases
that sat at the same peak. The result is 1215 → 1213 qubits for +898 average
Toffoli.

## What changed and why it saves qubits

1. **Borrowed fold carries (new knob `DIALOG_GCD_SPECIAL_FOLD_BORROW_CARRIES=1`).**
   - `src/point_add/arith/const_arith.rs`:
     - `cadd_nbit_const_direct_trunc_fast` and
       `csub_nbit_const_direct_trunc_fast` become thin wrappers over new
       `…_borrowed_carries` variants, which take a `borrowed_carries` slice.
     - The new helper `borrowed_const_fold_carries(b, need, borrowed)` uses up
       to `need` borrowed wires first and allocates only the remainder.
     - At the end, only the owned wires are freed. The borrowed ones come back
       clean, because every carry is erased with `hmr` plus `cz_if`, as before.
   - `src/point_add/rounds/dialog/mod.rs`,
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked` and its `sub`
     twin: when the knob is `1`, the overflow/underflow fold passes
     `inner_scratch` as the borrowed lane.
     - `inner_scratch` is the `clean_scratch` minus its first wire, which is
       used as `c_in`.
     - In this build, `clean_scratch` is the 5 qubits allocated around each
       add (see [`420e0c2`](420e0c2.md)), so `inner_scratch` has 4.
     - By the time the fold runs, `dialog_gcd_add_ctrl_chunked_low_to_ext`
       has finished its boundary-carry sweep and returned those wires to |0⟩.
   - The fold acts on `acc[..73]` (`DIALOG_GCD_SPECIAL_ADD_LSBS`) and stops
     its carry ripple at `last = 32 + KAL_FOLD_CARRY_TRUNC_W`, which is
     32 + 18 = 50. That needs 51 carries, of which 4 are now borrowed. The
     fold phase is the same gate sequence on 4 fewer fresh wires. See
     [venting-and-wire-loans](../concepts/venting-and-wire-loans.md) and
     [modular-fold](../concepts/modular-fold.md).
2. **Co-binder knobs (`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`).**
   - `DIALOG_GCD_FOLD_CARRY_TRUNC_W`: 19 → 18.
     - This is read by `fold_only_carry_trunc_window()`, not by the special
       fold above, which reads `KAL_FOLD_CARRY_TRUNC_W`. It caps the carry
       ripple of the fused fold inside the apply's `double_y` / `halve_y` at
       `hi_delta + W`.
     - The doc comment says lowering it "shrinks the fold high-water
       1-for-1". It also removes one carry position, and its CCX, from each
       of these folds. That is a truncation, in the same 2^-W hazard class as
       the walk's double-carry window.
   - `SQUARE_ROW_MAX_SEG`: 188 → 186. The widest one-piece square row goes
     from 188 to 186 bits, so the square's transient peak drops by 2. Rows of
     width 187 and 188 are now built in two windows. That adds 4 measured
     boundary cleanups with the 21-bit compare (see [`d636d62`](d636d62.md)).
   - `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS`: 12 → 16. The controlled apply ripple
     is split into 16 even chunks of the 257-bit accumulator
     (`dialog_gcd_chunk_hi`). The transient `f = ctrl & a[lo..hi]` register
     shrinks from about 21 to about 16 bits. There are 4 more boundary
     carries, each cleared by the existing conditional boundary replay.
   - `DIALOG_TAIL_NONCE`: 17761178 → 9300018914153.

The net Toffoli change is +898. The one-bit narrower fused-fold window saves
about one carry position per `double_y` / `halve_y`. The extra square
cleanups and the four extra apply chunk boundaries cost Toffoli. I could not
split the +898 between knobs without running the build, and I did not run a
per-phase peak trace. The submission note gives only the list of knobs.

## Why it is still correct, and what it risks

- **The borrowed carry lane is exact.** It runs the same gates on different
  wires. It is correct only if `inner_scratch` is |0⟩ when the fold starts
  and is not touched until the fold ends. If it were not clean, the result
  would be wrong arithmetic (classical) or a dirty scratch wire (ancilla).
- **`CHUNKED_F_BLOCKS = 16` is exact.** The chunked ripple with exact boundary
  clears computes the same value for any chunk count.
- **`SQUARE_ROW_MAX_SEG = 186` is value-exact** but adds 4 truncated
  cleanups. A tie in the top 21 bits gives a phase failure.
- **`DIALOG_GCD_FOLD_CARRY_TRUNC_W = 18` is probabilistic.** A fold carry that
  runs more than 18 bits above bit 33 is dropped. Each `double_y` / `halve_y`
  then gives a wrong `y`, a classical failure, or the halve fails to invert
  the double, which shows as garbage. The rate is roughly 2^-18 per call.
- The shipped nonce `9300018914153` draws a clean set (9,024 shots, 0 / 0 / 0).
  See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The new mechanism reuses idle clean scratch as the fold's carry lane. That is
scratch/ancilla reuse. The other three knobs are standard peak-budget dials,
and they make the remaining co-binders fit under the new peak. The fold
window narrowing could also be filed as comparator/width truncation. Here it
serves the peak.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5a783e4 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 5a783e4 461a4a3 -- src/point_add` is
   80 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 461a4a3 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with none of the
   route's variables (`DIALOG_*`, `SQUARE_*`, `KAL_*`, `KARA_*`, `ROUND84_*`,
   `R84_*`) set, because `set_default_env` only fills unset variables. Expect:
   - 1213 qubits
   - 1,404,013 average Toffoli (rounded)
   - score 1,703,067,769
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `9300018914153` and an identical op
stream. Any other change needs a new nonce hunt.

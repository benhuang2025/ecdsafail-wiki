## Summary

Each step of the dialog GCD decides `u > v` from only the top few bits of the
two registers. This commit lowers the global cap on that comparison from 59 to
58 bits. That removes one bit from each of the 238 steps whose scheduled width
was above 58, and the comparison runs four times per step, so it saves
4 × 238 = 952 Toffoli. Qubits are unchanged. It is the same lever as
[`ecbf87b`](ecbf87b.md) (61 → 59), one bit further.

An earlier attempt at 58 had found no clean reroll island, which is why the
base kept 59. After the F_CUT = 79 change in the base re-seeded the test
stream, the author re-scanned and found the clean pair (10, 7).

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`, which sets the route's knobs with `set_default_env`:

1. **`DIALOG_GCD_COMPARE_BITS`: 59 → 58.**
   - In each transcript step, the branch bit `b0_and_b1 = b0 AND (u > v)`
     decides the conditional swap before `v −= u; v >>= 1`. `u > v` is computed
     by `dialog_gcd_cmp_gt_truncated_into_width` with `ccx_cmp_lt_into_fast` on
     the top `compare_bits` bits of the active registers. It costs one Toffoli
     per bit, because its carries are cleared by measurement (`hmr` + `cz_if`).
   - `dialog_gcd_compare_bits_for_step(step, active_width)` returns
     `min(SCHEDULE[step] + 5, active_width, DIALOG_GCD_COMPARE_BITS)`, where
     `SCHEDULE` is the baked 399-entry `DIALOG_GCD_PA9024_COMPARE_SCHEDULE` and
     `active_width` is `dialog_gcd_tobitvector_active_width(step)`
     (`256 − 0.7075·step + 27`, rounded up to even).
   - Summed over the 399 steps, the per-step widths are 20,010 bits at a cap of
     59 and 19,772 at 58. The cap binds on 238 steps (steps 54 to 318).
   - The comparison runs in the forward and reverse transcript passes of both
     GCD pairs (quotient and product), four times per step:
     4 × 238 = 952 Toffoli, the measured change.
2. **Reroll pair: `DIALOG_REROLL` 0 → 10, `DIALOG_POST_SUB_REROLL` 26 → 7.**
   Identity `X;X` counts emitted in `build_builder()` before and just after
   `Px −= Qx; Py −= Qy`. They change the op-stream bytes, and so the 9,024 test
   inputs, without changing the circuit. This era has no tail nonce; the pair
   plays that role.

The comment above the knob is rewritten to say this.

## Why it is still correct, and what it risks

The truncated comparison is approximate. It can give the wrong `u > v` when
`u` and `v` agree on all of their top 58 active bits. Then the step swaps when
it should not (or the reverse), `v −= u` can go negative, and the transcript
no longer matches the true GCD. The apply pass then computes a wrong quotient
or product, which the evaluator reports as a classical failure, or as phase or
ancilla garbage when the uncompute no longer mirrors the forward pass. One bit
fewer roughly doubles the per-step chance on the 238 affected steps, so λ (the
expected number of failing shots per 9,024-shot draw) grows.

The reroll pair (10, 7) draws a test set with no hard input: 9,024 of 9,024
shots pass with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is in-place mutation (Register and Scratch Allocation),
but nothing is mutated in place and no register changes. The only circuit
change is a narrower comparator, the same lever as `ecbf87b`, which is filed as
Dead-Code and Redundancy Elimination → comparator/width truncation. That label
fits this commit too. The published label is kept in the header.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 40574d3 -- src/point_add`.
   - The git parent is `287595e` (10d9e), which was the frontier when this was
     accepted but is not the tree this commit was built on. Diffing against it
     (132 lines) would revert that commit's `ROUND84_XTAIL_BORROW_CARRIES`
     block back to `KARA_SOL_SHIFT22_DOUBLES`, move F_CUT from 78 back to 79 and
     delete its memory log.
   - `git diff --ignore-cr-at-eol 40574d3 fe29b53 -- src/point_add` is 22 lines
     in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol fe29b53 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1543 qubits
   - 1,694,933 average Toffoli (rounded)
   - score 2,615,281,619
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=10`,
`DIALOG_POST_SUB_REROLL=7` and an identical op stream. Any other change needs
a new reroll search.

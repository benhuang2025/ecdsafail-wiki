## Summary

The dialog GCD writes its branch decisions in blocks of 3 steps. Each block
is first built as 6 raw bits in a scratch register, the `raw_block`, then
compressed to 5 qubits of the transcript. The `raw_block` is |0⟩ again
between blocks, but the base allocated it once and held it for the whole
lifetime: forward GCD, apply replay and reverse GCD. Those 6 qubits sat
under the peak.

This commit allocates no persistent `raw_block`. For each block, the
forward and reverse passes put it on 6 wires that are provably |0⟩ at that
moment and not used by anything else: the far end of the transcript
region that is not written yet (or already erased), or the top of `u` once
the GCD has shrunk below it. The apply replay, which runs while `u` is
released, allocates its own 6 qubits only for that phase. Two chunk cuts of
the apply-phase adder are then moved so that phase also fits under the new
floor. The peak falls by 6 qubits for +2,376 Toffoli, which comes from the
cut move.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`.

### Background: the compressed transcript

Each GCD step writes two bits, `b0` (v is odd) and `b0_and_b1` (v is odd and
u > v, which triggers the swap). Only 3 of the 4 pairs can occur, so 3 steps
have 27 states and fit in 5 qubits. In the block-lifecycle route
(`DIALOG_GCD_COMPRESSED_SIDECAR_LOG=1`, `DIALOG_GCD_COMPRESSED_BLOCK_LIFECYCLE=1`),
`emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle` runs
the 3 steps of a block with their bits in `raw_block[0..6]`, then calls
`emit_dialog_gcd_round763_compressor(raw_block)` and swaps the 5 result
qubits into the block's slot of `compressed_log`. After the swap all 6
`raw_block` wires are |0⟩. The reverse pass does the opposite per block. The
constants are `DIALOG_GCD_HIGH_TAIL_ALIAS_GROUP_SIZE = 3` and
`DIALOG_GCD_HIGH_TAIL_ALIAS_BLOCK_BITS = 5`. [transcript-codecs](../concepts/transcript-codecs.md) covers
this early codec; [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md)
describes its later base-5 successor.

### 1. Per-block hosting of the raw block (`DIALOG_GCD_HOST_REVERSE_RAW_BLOCK=1`)

- **New gate** `dialog_gcd_host_reverse_raw_block_enabled()`, set to `1` in
  `configure_ecdsafail_submission_route()`. Despite the name it covers the
  forward pass too.
- **New `dialog_gcd_forward_raw_block_host(u, compressed_log, block)`.** With
  `aw = active_width(first step of the block)` and `want = 2·aw − 1` (the
  carry plus gated lane that each step's controlled subtract borrows from
  the front of the future transcript,
  `dialog_gcd_compressed_sidecar_future_carry_slice`), it returns:
  1. the last 6 wires of the future transcript `compressed_log[(block+1)·5 ..]`,
     if that region holds at least `want + 6` wires. Those blocks are not
     written yet, so they are |0⟩, and the borrowed lane takes only the first
     `want` of them, so the two do not overlap;
  2. otherwise the top 6 wires of `u` (`u[250..256]`), if
     `256 − aw ≥ want + 6`. Above `aw`, `u` is |0⟩ by the width-truncation
     premise, and the late-step lane borrowing (`DIALOG_GCD_LATE_BORROW_UV_HIGH`)
     uses only `u[aw .. aw + want]`;
  3. otherwise `None`, and the block allocates 6 fresh qubits and frees them
     after its compress-and-swap.
- **New `dialog_gcd_reverse_raw_block_host`** uses the same two sources in
  the other order: top of `u` first, then the far end of
  `compressed_log[(block+1)·5 ..]`. In the reverse pass those later blocks
  have already been decompressed back to |0⟩.
- **Both block-lifecycle emitters** (forward and reverse) now accept an empty
  `raw_block` argument and pick the hosted or owned block per iteration.
- **The two lifecycle wrappers**, `emit_dialog_gcd_compressed_sidecar_ipmul_block_lifecycle`
  (the x-tail product) and `emit_dialog_gcd_compressed_sidecar_quotient_block_lifecycle`
  (the `dy/dx` quotient), no longer allocate `raw_block` up front. Between
  the forward GCD and the reverse GCD they release the terminal `u`
  (`b.free_vec(&u)`) and run the apply replay. That phase now allocates a
  6-qubit `apply_raw_block` just for itself and frees it before `u` is
  reacquired.
- Result: no phase carries a 6-qubit block that does nothing. The terminal-`u`
  and wrapper phases that set the 1434 peak drop by 6.

### 2. Apply chunk cuts: `DIALOG_GCD_APPLY_CHUNKED_F_CUT` 124 → 123, `DIALOG_GCD_APPLY_CHUNKED_F_CUT2` 130 → 133

- `dialog_gcd_add_ctrl_chunked_low_to_ext` (and its subtract twin) adds
  `ctrl · source` into the 257-bit `acc_ext` in three chunks, with
  boundaries from `dialog_gcd_chunk_hi`: `[0, CUT)`, `[CUT, CUT2)`,
  `[CUT2, 257)`. Each chunk loads its slice of the addend into a fresh
  register (`dialog_gcd_load_controlled_slice`), adds it with a fast
  Cuccaro adder (fresh carry lane) and clears the load by `hmr`. Only one
  chunk's load and carry lane are live at a time, so the phase's peak is set
  by the widest chunk.
- Before: chunks of 124, 6 and 127 bits. After: 123, 10 and 124. The widest
  chunk shrinks by 3, which brings the apply phase down to the new 1428
  floor.
- Each boundary leaves a carry-out qubit. The carry-outs are cleared exactly
  by a comparator over the prefix `acc_ext[..p]` vs `source[..p]`
  (`ccx_cmp_lt_into_fast_prefix_targets`, with `p` the last cut). Moving the
  last cut from 130 to 133 makes that comparator 3 bits wider on every apply
  call. That is the likely source of the +2,376 Toffoli; the hosting itself
  adds no gates.

### 3. Reroll pair

`DIALOG_REROLL` 366567 → 164, `DIALOG_POST_SUB_REROLL` 59314 → 100. These
counts of identity `X;X` pairs only re-seed the Fiat–Shamir test inputs.

## Why it is still correct, and what it risks

- **The chunk cuts are exact.** The chunked adder computes the full sum for
  any cut, and the carry-outs are cleared by an exact comparison.
- **The future-transcript host is exact.** Those blocks are not written yet
  in the forward pass, or already erased in the reverse pass, and the
  borrowed carry lane is disjoint. The raw block returns to |0⟩ after each
  compress-and-swap.
- **The `u`-top host adds no new failure mode.** It relies on the same
  premise as the width truncation: above `active_width`, `u` is 0. An input
  that breaks this already fails the truncation. If it did happen, the
  block would start dirty, and the run would show classical or ancilla
  failures.
- The shipped pair (164, 100) is clean: 0 classical, 0 phase and 0 ancilla
  failures over all 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The qubit saving comes from placing a short-lived scratch register on wires
that are already allocated and known to be |0⟩, instead of holding a
dedicated one. That is scratch/ancilla reuse. The cut retune is a peak
rebalance of an exact adder and only follows from the first change.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b27f99c -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol b27f99c dd188f8 -- src/point_add` is
   143 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol dd188f8 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` keeps any
   value already in the environment. Expect:
   - 1428 qubits
   - 1,714,567 average Toffoli (rounded)
   - score 2,448,401,676
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL=164`,
`DIALOG_POST_SUB_REROLL=100` and an identical op stream. Any other change
needs a new reroll search.

## Summary

After `λ` is known, the point addition squares it once into a 512-bit
product register `tmp_ext`. It then needs the reduced value `λ² mod p` for two
things: to build `λ² − 3x1` in a scratch register `breg` for the y update,
and to subtract `λ²` from the x register. The base reduced `tmp_ext` three
times with the full Solinas fold `mod_{add,sub}_solinas_ext_product`: once to
build `breg`, once to clear `breg`, and once more to subtract from `tx`.

This commit notices that `breg`, after `3x1` is added back, holds exactly
`λ² mod p`. It subtracts `breg` from `tx` with one ordinary fast modular
subtract before clearing `breg`. That removes the third fold. The saving is
18,963 Toffoli. Qubits are unchanged, because no new register is needed.

## What changed and why it saves Toffoli

All edits are in `square_tx_and_combined_ty_l2minus3qx`,
`src/point_add/mod.rs`, behind a new switch `AFFINE_R_LIFECYCLE` (default
on; `=0` restores the old order).

Base order, after the y update `ty += λ·breg`:

```
affine_combined_breg_unred:  breg += x1; breg += 2·x1      // breg = λ² mod p
                             breg -= fold(tmp_ext)          // breg = 0, Solinas fold #2
affine_combined_tx_update:   tx   -= fold(tmp_ext)          // Solinas fold #3
                             tx += 2·x1; tx += x1; tx = −tx
```

New order:

```
affine_combined_breg_unred:  breg += x1; breg += 2·x1      // breg = λ² mod p
affine_combined_tx_update:   tx   -= breg                   // mod_sub_qq_fast, one modular subtract
affine_combined_breg_unred:  breg -= fold(tmp_ext)          // breg = 0, Solinas fold #2
affine_combined_tx_update:   tx += 2·x1; tx += x1; tx = −tx
```

Here `x1` is the classical input point's x-coordinate (`ox`). The adds of `x1`
are the classical-constant adders `mod_add_qb` and `mod_add_double_qb`.

**Why it is cheaper.** `mod_sub_solinas_ext_product` reduces a 512-bit
product into a 256-bit register. It adds and subtracts `lo` and several
shifted copies of `hi` (`c = 2^32 + 977`, so `hi·c = hi·(1 + 2^4 − 2^6 + 2^10 + 2^32)`).
That is six modular adds or subtracts (for `lo`, `hi` and the `2^4`, `2^6`,
`2^10` and `2^32` terms; the last one uses the slow carry-free `mod_sub_qq`),
ten in-place modular doublings of `hi`, a 22-bit shift and its inverse, and
ten modular halvings to restore `hi`. A single
`mod_sub_qq_fast` is one 257-bit measured Cuccaro subtract plus its
correction, about 1,000 Toffoli. The swap saves about 19,000 Toffoli. The code
comment records the validated −18,963. See
[modular-fold](../concepts/modular-fold.md) and
[adders-and-carries](../concepts/adders-and-carries.md).

**Why the peak is flat.** `breg` was already alive across this span. The only
new transient is the carry bank of the fast subtract. It fits under the 2708
peak, which is set in another phase.

## Why it is still correct, and what it risks

The change is exact on every input.
- At the point where `tx -= breg` runs, `breg = λ² − 3x1 + x1 + 2x1 = λ² mod p`
  as a canonical residue. The removed fold subtracted `λ²` reduced mod p, the
  same value, so `tx` ends with the same result.
- `breg` is then cleared by the same fold the base used, and it reads
  `tmp_ext`, which is unchanged.
- The constant adds to `tx` commute with the subtract, so moving the
  subtract earlier does not change the result.

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed. The base's probabilistic Kaliski
settings passed on the new draw with 0 classical, 0 phase and 0 ancilla
failures.

## Classification rationale

The census files this as scratch/ancilla reuse: the value already sitting in
the scratch register `breg` is reused for a second purpose. It could equally be
filed under Dead-Code and Redundancy Elimination, as removal of a redundant
recomputation (common-subexpression reuse). The saving is Toffoli, not
qubits.

## Summary

This commit changes one constant. Every round of the ping-pong coefficient
replay ends with a pseudo-Mersenne fold: it adds one of {−f, 0, +f, +2f}
(f = 2³² + 977) into the low bits of the target register and drops any carry
that leaves that low slice. The slice length is `REPLAY_FOLD_WINDOW`. The
author's previous submission `37b0c9f` cut it from 56 to 55; this commit cuts
it again to 54. Each window bit is one carry position, about one Toffoli, in
every replay cell of both traversals, so one bit saves about 1,400 average
Toffoli. Against the base `6ee4d14` (window 56) the saving is 2,810. Qubits
are unchanged. The cost is a higher chance that a fold carry escapes the
window, which gives a wrong value on rare inputs, so the tail nonce was
re-hunted.

## What changed and why it saves Toffoli

1. **`replay_fold_window()` default: 56 → 54** in `src/point_add/pingpong_div.rs`
   (`tuned_window("SUB4_PP_REPLAY_FOLD_WINDOW", &SLOT, …)`). The intermediate
   value 55 is the git parent `37b0c9f`.
   - In this generation of the code the window is an **absolute slice
     length**. Both fused replay cells call
     `fused_fold_maskfree(b, &target[..replay_fold_window()], f, …)`:
     - `signed_mod_add_pm_halve_fused`, the Divide cell (`replay_halving`,
       every round ≥ 2);
     - `signed_mod_double_add_pm_fused`, the Multiply cell
       (`replay_doubling_inverse`, every round > 1).
   - `fused_fold_maskfree` ripples the selected constant through the slice
     with `width − 2` carry wires. Each carry is built with one Toffoli and
     erased by `hmr` + `cz_if`, so the cost is about one Toffoli per window
     position. The carry out of the top position is never computed: that is
     the truncation.
   - About 700 replay rounds run in each of the two traversals, so two fewer
     positions save about 2 × 1,400 = 2,800 Toffoli, matching the measured
     −2,810. The parent's step 56 → 55 alone was −1,393 and this commit's
     55 → 54 is −1,417.
   - The same knob also sizes the sparse endpoint recovery at the walk-back:
     `fused_lift_round0_reverse_sparse` calls
     `cadd_per_position_controls_trunc(…, replay_fold_window() − 2)`, where the
     argument counts positions above f's top bit. That chain also gets two
     positions shorter, but it runs only twice per point add.
   - The window carries are allocated and freed inside the cell and do not
     sit at the peak, so qubits stay at 1320. See
     [modular-fold](../concepts/modular-fold.md) and
     [pingpong-division](../concepts/pingpong-division.md).
2. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 40561 (base) → 30008. The parent had 20026.

## Why it is still correct, and what it risks

The fold is approximate. Adding the 33-bit constant into a 54-bit slice is
wrong only when its carry runs through every bit from about 33 up to the top
of the slice, roughly 2^−(54−33) per call. The register then ends up 2⁵⁴ too
small, which is a wrong field element. That is a **classical** failure (the
value check), and the dirty replay usually also shows up as phase garbage.
Each window bit removed roughly doubles this per-call rate, and it is paid on
about 1,400 calls per shot, so λ rises. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

Everything else is unchanged. The shipped nonce `30008` draws a clean test
set: 0 classical, 0 phase and 0 ancilla failures.

## Classification rationale

The only circuit change is a shorter fold carry window, which is
fold/carry truncation. It is not filed as comparator truncation because the
dropped bit is a value carry, not a phase-repair compare.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 6ee4d14 -- src/point_add`.
   - `git diff --ignore-cr-at-eol 6ee4d14 8e8f047 -- src/point_add` is
     4 lines in 2 files (window 56 → 54 and the nonce).
   - The git parent `37b0c9f` is equally close (also 4 lines). It is the
     author's own 56 → 55 step, so diffing against it shows only 55 → 54 and
     the nonce 20026 → 30008. Either start works; this note uses `6ee4d14`.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8e8f047 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1320 qubits
   - 943,577 average Toffoli (rounded)
   - score 1,245,521,640
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `30008` and an identical op stream.
Any other change needs a new nonce hunt.

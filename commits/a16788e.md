## Summary

In this era the circuit computes `λ = dy / dx` with two runs of the Kaliski
binary almost-inverse ("pair 1" builds `λ`, "pair 2" later erases it). Each
run is a fixed number of iterations followed by its exact mirror. This commit
retunes four of the loop's constants in `src/point_add/mod.rs`:

- pair 1 runs 399 iterations instead of 404, and pair 2 runs 398 instead of 400;
- the cheap "bulk prefix" iteration body, which skips the termination test,
  now covers the first 394 iterations of both runs instead of 378 / 377;
- one more iteration (263 instead of 262) doubles the coefficient `r` with a
  free wire rotation instead of a modular double.

Every removed or simplified iteration is Toffoli the circuit no longer
executes, for −38,741 average Toffoli. Pair 1's history register holds one
qubit per iteration and is live at the peak, so 5 fewer pair-1 iterations
also lower the peak by 5 qubits. All four changes are bets on how fast
Kaliski converges. They hold on the drawn test set, not on every input.

## What changed and why it saves Toffoli and qubits

Background (see [kaliski-almost-inverse](../concepts/kaliski-almost-inverse.md) for this era's inverse). `kaliski_forward_with_coeff_caps`
starts from `(u, v_w, r, s) = (p, dx, 0, 1)` and runs `iters` iterations of
`kaliski_iteration`. Each iteration does, in qrisp's numbering: STEP 0, test
`v_w == 0` and clear the "still running" flag `f` when it is; STEP 1/2, decide
the branch from `u[0]`, `v_w[0]` and `u > v_w`; STEP 3, conditional swap of
`(u, v_w)` and `(r, s)`; STEP 4, `v_w −= u; s += r` under the add flag; STEP 6,
`v_w /= 2` (a swap chain); STEP 7+8, `r := 2r mod p`; STEP 9, swap back. The
branch bit of iteration `i` is kept in `m_hist[i]`, one qubit per iteration, so
`kaliski_backward_caps` can run the loop in reverse. After the forward run,
`with_kal_inv_raw_coeff_caps` frees `v_w` (= 0), `f` (= 0), `u` (= 1) and `s`
(= p) by their known values. `r` then holds `±dx^{-1}·2^{iters}`, and the
caller removes the power of two with `iters` modular halvings (pair 1, phase
`pair1_halve`) or doublings of `λ` (pair 2, phase `pair2_double`).

1. **Loop length: `KAL_PAIR1_ITERS` default 404 → 399; pair-2 default (no
   tagged-validation path) 400 → 398**, in `build_standard_point_add`.
   - Five fewer pair-1 iterations and two fewer pair-2 iterations, each skipped
     once forward and once backward. The skipped iterations are the narrowest
     ones: from iteration 256 on, every loop is clipped to the Kaliski
     envelope `2n − iter_idx` bits (about 110 bits here), but the `(r, s)`
     swaps and the `s += r` adder still run at the full 256 bits. Each skipped
     run of the loop also drops one 256-bit modular halving (pair 1) or
     doubling (pair 2).
   - Qubits: `alloc_kaliski_state(b, n, iters)` allocates `m_hist` with
     exactly `iters` qubits, and pair 1's `m_hist` is live while `λ` is built.
     That phase sets the peak, so 404 → 399 is −5 peak qubits. Pair 2 is not
     the peak phase, so its −2 does not show in the peak.
2. **`BULK_PREFIX_SAFE_ITERS`: 377 → 394**, and the hard-coded pair-1 caps in
   `bulk_prefix_caps(KalPair::Pair1)`: `forward = backward = 378 → 394`.
   - For `i < cap`, the forward and backward loops call
     `kaliski_iteration_bulk_prefix3` and its `_backward` mirror instead of the
     generic body. The bulk body assumes the run has not yet terminated
     (`f = 1`, `v_w ≠ 0`). It drops STEP 0 entirely, which is an OR-chain over
     `2n − i` bits of `v_w` (about 120 Toffoli at these iterations), and it
     drops `f` from the STEP 1, 2 and 4 controls, which saves a few more.
   - Pair 2 uses the global default (`bulk_prefix_caps(KalPair::Pair2)` falls
     through to `BULK_PREFIX_SAFE_ITERS`), so it gains 17 bulk iterations.
     Pair 1 gains 16. With the new loop lengths, only the last 5 (pair 1) and
     4 (pair 2) iterations still run the generic body.
3. **`R_SMALL_THRESHOLD`: 262 → 263**, read by `r_small_threshold()`.
   - In STEP 7+8, for `iter_idx < r_small_threshold()` the code doubles `r`
     with `mod_double_no_corr`, a 0-Toffoli swap rotation that assumes the top
     bit of `r` is 0. From the threshold on it calls `mod_double_inplace_fast`,
     the Solinas double with a carry chain, about 255 Toffoli.
   - Iteration 262 becomes free in all four Kaliski runs (pair 1 and pair 2,
     forward and backward), about 1,000 Toffoli.
4. Two `#[allow(dead_code)]` attributes on `secp256k1_curve` and `alt_seed_xof`.
   They only silence compiler warnings and emit no gates.

By rough per-iteration costs, the shorter loops are the largest part of the
saving (on the order of 20,000 Toffoli, including the dropped halvings and
doublings), the wider bulk prefix is about 8,000, and the threshold is about
1,000. These are estimates. The commit has no submission note.

## Why it is still correct, and what it risks

None of the four changes is exact on every input.

- **Loop length.** Kaliski needs between 256 and 512 iterations, depending on
  the input. The free-by-value step after the forward run (`u = 1`, `s = p`,
  `v_w = 0`, `f = 0`) is only true if the run has terminated within `iters`
  iterations. An input that needs more than 399 (pair 1) or 398 (pair 2)
  iterations leaves the wrong value in `r`, and the freed registers are not
  zero. That shows up as a classical mismatch and ancilla garbage. The code's
  own comment beside the pair-2 default still calls 399 "outside the verified
  safety margin", and this commit goes to 398.
- **Bulk prefix.** The comment above `BULK_PREFIX_SAFE_ITERS` proves that the
  first 256 iterations are non-terminal for every input. Caps above 256 are
  empirical. On an input that terminates inside the prefix, the bulk body
  leaves `(u, v_w, s)` unchanged as the generic body would, but records
  `m_i = 1` instead of 0 and never clears `f`. Only a later generic iteration
  clears `f` (see [`1c400f2`](1c400f2.md) for this reading of the code). The
  code's comments still treat high caps as risky, a rare "phase cliff", so a
  bad cap would most likely show up as phase failures.
- **`R_SMALL_THRESHOLD`.** The comment's bound "`max(r, s) ≤ 2^iter_idx`" is
  only a proof below iteration 256. At iteration 262, the plain rotation is
  correct only while `r < 2^255`. If not, the top bit wraps into bit 0 and the
  result is wrong (classical failure).

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so every change re-rolls the draw. The commit was accepted
with 0 classical, 0 phase and 0 ancilla failures, so the draw for this op
stream contains no input that needs more iterations or a wider prefix. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md) for why a
clean draw is a property of the op stream, and
[scoring-and-validation](../concepts/scoring-and-validation.md) for the three
failure channels.

## Classification rationale

The census files this as dead-gate/self-inverse removal, probably because of
the two `#[allow(dead_code)]` attributes. Those emit nothing. Every gate the
commit saves comes from changing iteration counts and the thresholds at which
cheaper iteration bodies apply. By its effect the diff fits Dead-Code and
Redundancy Elimination → iteration/threshold tuning, the label the census uses
for the same kind of change in [`9bd0748`](9bd0748.md).

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f43a73e -- src/point_add`.
   - Do not start from the git parent `168048c`. That is cryptogakusei's
     direct-constant-adder commit, which this author did not build on.
   - Against the parent the diff is 45 lines. It deletes the
     `direct_const_modred_enabled()` switch and the
     `add_nbit_const_direct_fast` helper and restores the loaded-constant
     Cuccaro path at five call sites.
   - Against `f43a73e`, `git diff --ignore-cr-at-eol f43a73e a16788e -- src/point_add`
     is 14 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a16788e -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `BY_*`, `DUMMY_TOFFOLIS` or other environment overrides set. Expect:
   - 2710 qubits
   - 3,904,012 average Toffoli (rounded)
   - score 10,579,872,520
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score, and the clean draw, only reproduce with an identical
op stream.

## Summary

In the apply phase of the dialog GCD (background in [8316db1](8316db1.md) and
[8a47cf5](8a47cf5.md); see [dialog-gcd-early](../concepts/dialog-gcd-early.md)), each step doubles or
halves the coefficient `y` mod `p` once or twice. The fused cell does the
Solinas correction for both possible doublings as one ripple add of a constant,
where each bit position has its own control qubit. This commit makes two exact
peephole cuts in that cell:

1. Each carry position with its own control used a 3-input majority built
   from 3 CCX. It is now built from 2 CCX and 2 CX, with no ancilla.
2. The helper control `h = a ∧ b` was cleared with a second CCX. It is now
   cleared by measurement (`hmr` plus `cz_if`), which costs no Toffoli.

Together these save about 12 Toffoli per apply step. The author then spent
part of the saving on one more GCD step (`DIALOG_GCD_ACTIVE_ITERATIONS`
258 → 259) so that a clean nonce could be found. The net result is −3,325
Toffoli at the same 1307 qubits.

## What changed and why it saves Toffoli

### 1. Two-CCX majority (`src/point_add/arith/const_arith.rs`)

New knob reader `perpos_maj2_enabled()` (`DIALOG_GCD_PERPOS_MAJ2`, default
off, pinned to 1). It is used in `cadd_per_position_controls_trunc` and
`csub_per_position_controls_trunc`. These add (or subtract) a constant whose
bit `i` is the qubit `kc = kctrl(i)` instead of a fixed 0 or 1. The forward
carry sweep computes `carry_i = maj(acc_i, kc, carry_{i−1})`.

- Old (3 CCX): `ccx(acc, cin, t); ccx(kc, acc, t); ccx(kc, cin, t)`, which
  gives `t ^= acc·cin ⊕ kc·acc ⊕ kc·cin`.
- New (2 CCX): `ccx(acc, cin, t); cx(acc, cin); ccx(kc, cin, t); cx(acc, cin)`.
  This gives `t ^= acc·cin ⊕ kc·(acc ⊕ cin)`, which is the same polynomial.
  `cin` is changed only for the moment between the two CX, and it is restored
  before anything else reads it. The later sum-bit CX and the measured carry
  clear therefore see the same values as before.
- In the subtract, `acc[i]` has already been inverted with an X, so the same
  identity gives `maj(¬acc, bin, kc)`.

The callers are `dialog_gcd_fused_double_y` and `dialog_gcd_fused_halve_y` in
`rounds/dialog/compressed.rs`. They fold `δ = c·e + 2c·d` into `y` with
`c = 2^32 + 977`. The constant's controlled positions are bits 0, 1, 4–11, 32
and 33, with controls `e`, `d`, `e⊕d`, `e∨d`, `¬e∧d` and `h = e∧d`. All of
them except bit 0 have a carry-in, so each call saves one CCX at each of those
11 positions that fall inside the truncated window.

### 2. Measured clear of `h` (`rounds/dialog/compressed.rs`, `rounds/dialog/config.rs`)

New knob reader `dialog_gcd_fused_hclear_measured_enabled()`
(`DIALOG_GCD_FUSED_HCLEAR_MEASURED`, default off, pinned to 1).

- In `dialog_gcd_fused_double_y`, `h` is computed as `ccx(ovf2, d, h)` before
  the fold. It used to be cleared after the fold by the same CCX. With the
  knob on, the clear becomes `hmr(h, m); cz_if(ovf2, d, m)`.
- `dialog_gcd_fused_halve_y` makes the same change for `h = e ∧ d`.
- This is valid because neither control changes between the set and the
  clear. The fold writes only `y` and its own carries, and the derived controls
  are built from `e`, `d` and `h` with CX only. So `h` still equals the AND of
  its controls when it is measured, and `cz_if` cancels exactly the phase the
  X-basis measurement can leave. See
  [measurement-uncompute](../concepts/measurement-uncompute.md).
- This saves one CCX per call.

### 3. One more GCD step (`src/point_add/mod.rs`)

In `configure_ecdsafail_submission_route()`:
- `DIALOG_GCD_ACTIVE_ITERATIONS`: 258 → 259
- `DIALOG_GCD_PERPOS_MAJ2` = `1` (new)
- `DIALOG_GCD_FUSED_HCLEAR_MEASURED` = `1` (new)
- `DIALOG_TAIL_NONCE`: 4009893105 → 25012277

According to the author's note, the two cuts alone were −5,676 and −516
Toffoli. Both totals are multiples of 516 apply calls (11 and 1 per call),
which fits 258 steps × 2 divisions. The extra GCD step gives back the
remainder. It adds one more walk step and apply step to each division, and
it lowers the chance that an input fails to converge in time. That makes the
nonce island easier to hit.

### 4. `src/point_add/dialog_gcd_classical_filter.rs`

`full_gcd_steps_until_zero` becomes `pub(crate)`. No behaviour change.

## Why it is still correct, and what it risks

Both cuts are exact identities. The 2-CCX majority computes the same Boolean
function as the 3-CCX one using only CCX and CX, so it adds no phase. The
measured `h` clear is phase-exact because `h` holds `a ∧ b` deterministically
at the measurement. Neither changes any value or any approximation, so λ is
unaffected by them.

The iteration change does change λ, in the safe direction. One more GCD step
lowers the number of inputs that fail to reach `v = 0` within the step budget.
The op stream changed, so the nonce was re-hunted. Nonce `25012277` validated
with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots. A wrong
majority would give a wrong `y`, which is a classical mismatch. A wrong `h`
clear would show up as a phase failure. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is measurement uncompute, which describes cut 2. Cut 1,
the 2-CCX majority, is the larger saving (−5,676 against −516 by the author's
count). It is an exact gate identity, so Dead-Code and Redundancy Elimination
(an exact peephole) or Strength Reduction would describe the main lever
better. The iteration change is a give-back, not a lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 6bf73fe -- src/point_add`. The author built on
   `6bf73fe`, not on the git parent `3409fbd` (zuiris). Diffing against the
   parent (1,173 lines) would wrongly show this commit reverting all of
   `3409fbd`: the `DIALOG_GCD_TRIO_WIDTH_NOTCH` lever, the clean direct
   constant adders, the K2 state-updating codec and the self-tests.
   `git diff --ignore-cr-at-eol 6bf73fe 94535d1 -- src/point_add` is 92 lines
   in 5 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 94535d1 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1307 qubits
   - 1,467,440 average Toffoli (rounded)
   - score 1,917,944,080
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=25012277` and an identical
op stream. Any other change needs a new nonce hunt.

## Summary

Three constants in `src/point_add/mod.rs`, found by a grid search. The first
Kaliski inversion pair ("pair1", which computes λ) runs 399 iterations instead
of 401. The second pair ("pair2", which uncomputes λ) runs 401 instead of 403.
And the "bulk prefix", the stretch of iterations that use a cheaper iteration
body without the termination test, is extended from the first 394 iterations
to the first 400, for both pairs.

Every iteration that is dropped saves a full Kaliski step forward and backward,
plus one modular halving or doubling of λ. Every iteration moved into the bulk
prefix saves its `v_w == 0` test and its `f`-controlled logic. Together that is
17,329 average Toffoli. Qubits stay at 2310. The iteration count does size
the `m_hist` history register (one qubit per iteration), but the measured peak
does not move, so the high-water mark is not lowered by those two wires. The
cost is a smaller safety margin on rare slow-converging inputs.

## What changed and why it saves Toffoli

**Background: the early inverter.** This era's circuit computes λ with a
reversible Kaliski "almost inverse" (qrisp / Roetteler style), not with the
later GCD walks of [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md). Its
state is `u, v_w` (the GCD pair, starting at `(p, dx)`), `r, s` (the Bézout
pair, starting at `(0, 1)`), a termination flag `f`, and one history qubit
`m_hist[i]` per iteration. Each iteration halves one of `u, v_w` (after a
conditional subtract and swap) and doubles `r` mod p. A run of `iters`
iterations leaves `r = ±dx^-1 · 2^iters`, so the caller then applies `iters`
modular halvings to λ (pair1, `mod_halve_inplace_fast`) or `iters` doublings
(pair2, `mod_double_inplace_fast`) to remove the power of two. Each pair is a
forward Kaliski run, a body that uses `r`, and a backward run that uncomputes
the state. The input-dependent number of steps an input really needs, `k`, is
between 256 and 512. A fixed `iters` is correct only for inputs with `k ≤ iters`;
after termination the extra iterations only double `r`, which the fixed
descaling already accounts for.

The changes, all in `src/point_add/mod.rs`:

1. **`build_standard_point_add()`, `pair1_default`: 401 → 399** on the default
   `stack_2565_enabled()` path (the other branch was already 399, so the
   expression now reads `if stack_2565_enabled() { 399 } else { 399 }`).
   - Pair1 is run through `with_kal_inv_raw_borrow_v_w_pair(..., pair1_iters, KalPair::Pair1, ...)`.
   - Two fewer iterations remove 2 forward and 2 backward Kaliski iterations
     and 2 calls to `mod_halve_inplace_fast` on λ.
2. **`pair2_default`: 403 → 401** on the same path. Pair2 is the in-place-v
   `with_kal_inv_raw_borrow_v_w_pair(..., pair2_iters, KalPair::Pair2, ...)`
   run. Two fewer iterations each way, and 2 fewer `mod_double_inplace_fast`
   calls on λ.
3. **Bulk-prefix cap: `BULK_PREFIX_SAFE_ITERS` 394 → 400**, and the
   Pair1-only override in `bulk_prefix_caps()` that pinned pair1's
   forward and backward caps to 394 is deleted. Both pairs now use 400.
   - In `kaliski_forward_*_caps` and the backward loops, iteration `i` uses
     `kaliski_iteration_bulk_prefix3` (and its `_backward` twin) when
     `i < bulk_caps.forward` (or `.backward`), and the generic
     `kaliski_iteration` otherwise.
   - The bulk body assumes `f = 1` and `v_w != 0`. It drops STEP 0 entirely
     (the OR chain `with_eq_zero_fast` over up to `or_width` bits of `v_w`,
     plus `ccx(f, add_f, m_i)`) and replaces the `f`-controlled Toffolis of
     STEP 1 and STEP 2 with cheaper uncontrolled forms (for example
     `a_f = !u0` by CX instead of `ccx(f, u[0], ...)`).
   - Pair1 now runs entirely in bulk mode (399 < 400). Pair2 runs 400 bulk
     iterations and one generic one.

## Why it is still correct, and what it risks

None of the three knobs is exact.
- **Iteration counts.** An input whose Kaliski run needs more than 399
  (pair1) or 401 (pair2) steps is not finished, so its inverse, λ and the
  output are wrong. The author's grid found pair1 = 398 and pair2 ∈ {400, 402}
  failing, and 399 / 401 clean. Non-monotone results like this are typical
  of the era: each value is a different op stream and so a different draw of
  test inputs.
- **Bulk cap.** The code's own proof (comment above `BULK_PREFIX_SAFE_ITERS`)
  only guarantees that the first 256 iterations are nonterminal, because
  `u + v` at most halves per step and starts above 2^255. Past 256 the cap is
  empirical. The author reports 401 and above failing. A failure shows up as a
  classical mismatch, or as phase or ancilla garbage when the backward run no
  longer mirrors the forward run.

This era has no tail nonce. The 9,024 test inputs are a SHAKE256 hash of the
op stream, so every value tried draws a new test set, and the shipped
combination is one whose draw is clean: 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md)
and [scoring-and-validation](../concepts/scoring-and-validation.md).

## Classification rationale

The commit only lowers loop counts and moves a fixed/guarded boundary, so it
is iteration/threshold tuning. Nothing is structurally removed: the generic
iteration body still exists and is still used for pair2's last iteration.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout d19dbb5 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol d19dbb5 a3ee589 -- src/point_add` is
   25 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol a3ee589 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `POINT_ADD_*` or `BY_*` environment variables set, because they override
   the defaults in the patch. Expect:
   - 2310 qubits
   - 3,638,710 average Toffoli (rounded)
   - score 8,405,420,100
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era: the test set is a hash of the op stream,
so the score only reproduces with an identical op stream. Any other change
draws a new test set that may not be clean.

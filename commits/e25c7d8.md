## Summary

The square step computes `out −= λ² mod p` with one Karatsuba split. One of its
pieces is `A = lo²`, and the high half of `A`, call it `A_hi`, must be folded
back as `f·A_hi` with `f = 2^32 + 977`. The base did that by doubling a copy of
`A_hi` modulo p 32 times and adding it at each of the five signed NAF terms of
`f` (shifts 0, 4, 6, 10, 32), then halving it 32 times to restore it. Each
doubling and each halving pays one 54-bit `+f` fold window, about 53 Toffoli.

`A_hi` has only 128 bits, so `A_hi·2^32` still fits in 256 bits and needs no
reduction. This commit stops the doubling ramp at shift 10 and adds the `2^32`
term as a plain zero-padded operand. That removes 22 doublings and 22 halvings,
44 fold windows, about 44 × 53 = 2,332 Toffoli; the measured saving is 2,342.
Qubits are unchanged. The change is value-exact. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All circuit changes are in `src/point_add/trailmix_ludicrous/square.rs`, in
the trailmix-ludicrous square `mod_square_sub_pm_secp256k1_symmetric`.

**Background: how the base folds a high limb.** The square uses
`λ = hi·2^128 + lo`, `A = lo²`, `B = hi²`, `C = (lo+hi)²` and
`λ² = A + (C − A − B)·2^128 + B·2^256` (see
[squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md)). Each
"×2^128" piece goes through `apply_shifted_128(value, out, op)`: the low 128
bits of `value` are added at bit 128, and the part above bit 256,
`value[128..]`, is worth `value[128..]·2^256 ≡ value[128..]·f`. That part goes
to `apply_f_times_value`, which in the base:

1. copies the limb into a 257-bit register `ext` (zero pads above);
2. walks the NAF table `F_NAF_TERMS = [(0,Sub),(4,Sub),(6,Add),(10,Sub),(32,Sub)]`
   (`f = 2^32 + 2^10 − 2^6 + 2^4 + 1`, signs flipped for an add). Before each
   term it calls `arith::mod_double(ext)` until `ext` holds `limb·2^shift mod p`,
   then does a full-width 256-bit `mod_add_lowpeak` or `mod_sub` of `ext` into `out`;
3. undoes the 32 doublings with `arith::mod_double_reverse`.

`mod_double` is a free swap-chain shift plus `add_f_window` gated on the
shifted-out bit, over `LSBS = PAD + 33 = 54` bits. The clean window costs
`LSBS − 1 = 53` Toffoli (one CCX per carry; the carries are uncomputed by
`hmr`). See [modular-fold](../concepts/modular-fold.md). So the ramp costs
32 + 32 = 64 fold windows, whether or not the fold ever fires.

**The change.**
- New `apply_f_times_value_tagged(…, tag)`, with `apply_shifted_128_tagged`
  passing the Karatsuba lane name: `"c"` for `C`, `"a"` for `A`, `"b"` for
  `B`. The `f·B` fold of the `2^256` term keeps the untagged
  `apply_f_times_value`, which uses the tag `"generic"`.
- New path, taken when `value.len() + 32 ≤ 256` and either
  `TLM_SQUARE_F_RAMP10_DIRECT32=1` or the tag is listed in
  `TLM_SQUARE_F_RAMP10_DIRECT32_TAGS`:
  - the doubling ramp runs the same loop but `continue`s at shift 32, so it
    stops after 10 doublings, applies the terms at shifts 0, 4, 6 and 10, and
    undoes 10 doublings;
  - the `2^32` term is then added by the new `apply_shifted_value_direct(value, out, 32, op)`.
    That builds a 256-bit operand of 32 low zero pads, the limb, and high zero
    pads, and runs the same full-width `mod_add_lowpeak` / `mod_sub` as before.
- `src/point_add/mod.rs`, `build()`: new default
  `TLM_SQUARE_F_RAMP10_DIRECT32_TAGS=a`. Only the `A` lane takes the new path.
  The `A` limb `a_prod[128..]` has 128 bits, so `128 + 32 ≤ 256` holds.
- Effect: 22 fewer `mod_double` and 22 fewer `mod_double_reverse` in the `A`
  lane, 44 × 53 = 2,332 emitted Toffoli. The measured average drops by 2,342.
  The final add is still full width, so its cost is unchanged.
  [`3df690f`](3df690f.md) later removes the ramp from all three lanes.

Smaller edits:
- Three more alternative paths, all off by default:
  - `TLM_SQUARE_F_DIRECT_TAGS`: every NAF term as a direct full-width shifted operand.
  - `TLM_SQUARE_F_SHIFTED_LOW`: every term through the new `apply_shifted_value_low`,
    which calls `mod_add_shifted_low` / `mod_sub_shifted_low` with implicit low
    zeros. This is the path [`3df690f`](3df690f.md) switches on.
  - `TLM_SQUARE_F_DIRECT_SHIFT`: the same as the first, without a tag.
- `circ.set_phase("square_…")` labels around each Karatsuba stage. These are
  trace labels, not ops.
- Tail nonce: the `DIALOG_TAIL_NONCE` default in `build()` goes from 188337 to 2207.
  The trailmix builder reads it in `build_trailmix_ludicrous_ops()` and appends
  48 `X;X` identity pairs, so it changes only which test inputs are drawn.

## Why it is still correct, and what it risks

- **Value-exact.** The limb is below 2^128 and the shift is at most 32, so
  `limb·2^32 < 2^160`. Every doubling in the base ramp up to shift 32 had a
  shifted-out bit of 0, and its `+f` fold never fired. The new operand equals
  the old `ext` value bit for bit. The add into `out` is the same
  `mod_add_lowpeak` / `mod_sub`, with the same `+f` window and the same
  truncated top-`MSBS` overflow compare, so no new approximation is added.
- The removed fold windows could never fire, so they carried no error either.
  The circuit's failure set (Lambda) is the base's. A new nonce was still
  needed because the op stream changed.
- The shipped nonce 2207 draws a clean set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

This is a cheaper way to apply the Solinas fold by `f` written in NAF: one
term becomes a plain shifted add instead of a modular-doubling chain. That is
strength reduction of the NAF fold. The runner-up was dead-gate removal, since
the dropped fold windows never fire, but the code change replaces an
arithmetic route rather than deleting gates.

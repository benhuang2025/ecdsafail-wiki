## Summary

The circuit at this time is the 1170-qubit "dialog GCD" route. Its schoolbook
squarer adds each wide row into the product register in two windows, and the
carry that crosses the window boundary has to be cleaned afterwards with a
comparator. This commit makes the default width of that cleanup comparator 18
bits instead of 19. Each boundary gets one bit cheaper in the forward and in
the inverse square, which saves 273 average Toffoli. Qubits are unchanged.
The cost is a slightly higher chance of a wrong cleanup on rare inputs, so the
tail nonce was re-hunted.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  `SQUARE_ROW_WINDOW_CLEAN_COMPARE_BITS` default goes from `"19"` to `"18"`.
  - This block of `set_default_env` calls comes first in the function, and
    `set_default_env` only sets a variable that is still unset. The later
    "historical fallback" line that sets the same knob to `"21"` therefore has
    no effect.
- How the knob is used (`src/point_add/arith/multiply.rs`):
  - `schoolbook_square_symmetric_lowq_selfhosted_with_clean_supplement()` (and
    its `_inverse` twin) builds row `i` of the square, of width `n − i + 1`
    (doubled cross terms `x_i·x_j`, a gap bit and the diagonal `x_i`), and adds
    it into `tmp_ext[2i ..]`. With `SQUARE_ROW_MAX_SEG = 143`, every row wider
    than 143 bits (rows 0 to 113) goes through `square_row_windowed_apply()`
    with `ceil(width/143) = 2` windows, so each such row has one interior
    window boundary. Windowing keeps only one window's worth of row bits live,
    which is what holds the square under the 1170 peak.
  - The low window's carry-out is captured in an ancilla `cout` and fed into
    the high window as its carry-in. After the add, `cout` still holds that
    carry and must be cleared. With `SQUARE_ROW_WINDOW_MEASURED_CARRY_CLEAR=1`
    it is measured out with `hmr`, and the phase is repaired by
    `cmp_lt_phase_conditioned_with_cin_borrowed_carries()`, which recomputes
    the carry as "partial sum < row segment" under a classical condition on the
    measurement bit. See [measurement-uncompute](../concepts/measurement-uncompute.md).
  - `square_row_window_clean_compare_bits(row, window, reverse)` picks how many
    top bits of the window that comparison looks at: a per-row override from
    `SQUARE_ROW_WINDOW_CLEAN_ROW_BITS` (21 listed rows, at 20 to 22 bits), else
    the default `SQUARE_ROW_WINDOW_CLEAN_COMPARE_BITS`. When it is smaller than
    the window, only the suffix `[hi − k, hi)` of the row segment is rebuilt
    (one CCX per cross-term bit, cleared again by `hmr` for free) and compared.
  - So the default applies to the 93 windowed rows without an override, in both
    the forward square and the inverse square: 186 compares. Dropping one bit
    removes one CCX from the always-executed suffix rebuild and about one CCX
    from the comparator, which runs only when the measurement bit is 1 (about
    half of the shots). That is about 186 × 1.5 ≈ 280 executed Toffoli, in line
    with the measured −273, and about 372 emitted Toffoli as the submission
    note says. See
    [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- `DIALOG_TAIL_NONCE` default: `"11156415"` → `"38047539020"`.
- Non-circuit files: three new agent memory notes in `src/point_add/memory/`
  (`2026-06-07-measured-frontier-leads.md`,
  `2026-06-07-structural-breakthrough-leads.md`,
  `2026-06-08-measured-frontier-optimizations.md`). Git also lists
  `2026-06-13-q1192-wmi-cuda-search.md` as modified, but only in line endings. They are research logs and are not
  compiled.

## Why it is still correct, and what it risks

The square product itself is exact: the windows chain the carry through the
accumulator, so the same value lands in `tmp_ext` regardless of the knob. Only
the cleanup of `cout` is approximate. Comparing only the top `k` bits gives the
true carry unless the top `k` bits of the partial sum and of the segment are
equal, in which case the lower bits would decide and the truncated compare
returns "not less". That happens with probability about 2^-k per boundary, so
going from 19 to 18 bits roughly doubles the per-site error. A wrong recompute
applies the wrong phase correction after the `hmr`, which shows up as a phase
failure.

The re-hunted nonce `38047539020` draws a test set with none of those inputs:
0 classical, 0 phase and 0 ancilla failures over all 9,024 shots (full eval
with `EVAL_FAST_REJECT=0`, per the submission note). See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a comparator window by one bit, so the commit
is comparator/width truncation. The nonce comes with every circuit change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 674d0d8 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 674d0d8 6878ef8 -- src/point_add` is
   551 lines in 4 files, but only 4 of those lines are in `mod.rs`; the rest
   are memory notes.
2. **Copy the memory notes from the commit:**
   `git checkout 6878ef8 -- src/point_add/memory`. These are Markdown research
   logs, not code.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings.
4. **Check the tree.** `git diff --ignore-cr-at-eol 6878ef8 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `SQUARE_*` or `KAL_*` environment variables set, because they
   override the defaults in `mod.rs`. Expect:
   - 1170 qubits
   - 1,434,726 average Toffoli (rounded)
   - score 1,678,629,420
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `38047539020` and an identical op
stream. Any other change needs a new nonce hunt.

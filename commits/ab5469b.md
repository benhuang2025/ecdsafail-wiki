## Summary

Each step of the dialog-GCD walk does a controlled subtract (forward walk) or
add (reverse walk) of `u` into `v`. That body runs on fewer bits than the
step's full active width: the top few bits are assumed to be zero and are cut
off. A per-step map, `DIALOG_GCD_BINDER_NOTCH_MAP`, adds extra cut bits on
chosen steps. This commit adds `14:1` to it, so step 14's body loses one more
top bit: 248 bits instead of 249.

A narrower body has a shorter carry chain and a smaller gated load, so it costs
a few Toffoli less. The step runs once in each of the four walk passes, and the
measured saving is 16 Toffoli. Qubits stay at 1285. The cut bit is only zero
with high probability, so the tail nonce was re-hunted.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_BINDER_NOTCH_MAP`: `11:1,12:1,13:1` → `11:1,12:1,13:1,14:1`.**
   - The body width is `dialog_gcd_body_carry_trunc_width(active_width, step)`
     in `rounds/dialog/mod.rs`. It returns `active_width − w`, where `w` adds
     up the cuts that apply to this step:
     - the band trim from `DIALOG_GCD_BODY_CARRY_BAND_TRIMS` (26 bands of
       ⌈260/26⌉ = 10 steps; step 14 is in band 1, trim 3);
     - the trio notch (step 11 only);
     - the binder-notch steps 8, 9, 10 (+3 each);
     - `dialog_gcd_binder_notch_map_extra(step)`, the value from this map;
     - minus `DIALOG_GCD_BODY_STEP_GIVEBACKS` (step 10 only).
   - At step 14 the active width is `ceil((256 − 14·1.015 + 10)/2)·2 = 252`.
     So the body goes from 252 − 3 = 249 bits to 252 − 4 = 248 bits.
   - The body is the materialized controlled sub/add,
     `dialog_gcd_controlled_sub_selected` in the forward walk and its add
     mirror in the reverse walk. One bit less removes the top stage of its
     gated load and carry ripple, a few Toffoli per call. Step 14 runs in four
     walk passes per shot (forward and reverse walk, for each of the two GCD
     uses), and the measured average drops by 16.
   - The code comment explains why the map is called a "binder notch": the
     walk-step scratch is sized as `2·body_len − 1`, so on a step that sets the
     peak, a narrower body also lowers the peak. Step 14 is not a peak step on
     this tree, so here the cut only saves Toffoli.
2. **`DIALOG_TAIL_NONCE`: 800002627594 → 39354**, with the comment updated to
   record that 39354 validates 0/0/0 at 1285 × 1,381,110.

## Why it is still correct, and what it risks

The cut is a width truncation, not an exact simplification. The body now also ignores
bit 248 of `u` and `v` at step 14, which is right only if both values are
already below 2^248 there. The width envelope assumes their bit length drops
about 1.015 bits per step; a slow input that still has bit 248 set after 14
steps gets a wrong subtraction. The walk then records wrong decisions, the
inverse is wrong, and the run shows a classical mismatch, possibly with phase
or ancilla garbage when the reverse walk fails to clean up.

The code comment calls the notch "value-exact on the reachable GCD support".
That holds only for inputs inside the envelope; it is a probabilistic cut, and
it makes the hard-input set a little larger. The shipped nonce `39354` draws a
clean set: 9,024 of 9,024 shots, with 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit narrows the arithmetic width of one step's add/sub, which is
comparator/width truncation. The name "binder notch" refers to the peak lever
the map was built for, but no qubits change here, so it is not filed under
register allocation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 7822c37 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 7822c37 ab5469b -- src/point_add` is 8 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol ab5469b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or `ROUND84_*` environment variables set, because they
   override the route defaults. Expect:
   - 1285 qubits
   - 1,381,110 average Toffoli (rounded)
   - score 1,774,726,350
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=39354` and an identical op
stream. Any other change needs a new nonce hunt.

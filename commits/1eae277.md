## Summary

This is the author's third width-envelope retune ([01260e8](01260e8.md),
[5b3887b](5b3887b.md)), again starting from robertkodra's `a772a45`. This
time both envelope parameters move toward narrower widths. The dialog-GCD
width `256 − slope·step + margin` gets a steeper slope, 0.984 bits per step
instead of 0.950, and a smaller margin, 10 instead of 25. Unclamped early steps
lose about 16 bits. Late steps lose up to 24, because the steeper slope takes
off another 0.034 bits per step.

Each step-bit costs 4 Toffoli in the K=2 walk, plus capped comparator bits.
The saving is 80,104 Toffoli, exactly what the width formula predicts. Qubits
are unchanged. A new tail nonce was found. The submission note's first line
says "margin 14, slope 986", but the code and the note's own validation lines
say 10 and 984.

## What changed and why it saves Toffoli

`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:

- `DIALOG_GCD_WIDTH_MARGIN`: 25 → 10.
- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 950 → 984.
- `DIALOG_TAIL_NONCE`: 141744616447148 → 65110790329263.

`dialog_gcd_tobitvector_active_width(step)` returns
`256 − slope·step + margin`, rounded up to an even number and clamped to
[1, 256]. The width bounds four loops in each walk step, each about 1 Toffoli
per bit:
- the branch `cswap`;
- the gated load;
- the subtract or add body;
- the K=2 conditional-shift cascade.

It also caps the branch comparator at `min(74, active_width)`. See
[01260e8](01260e8.md).

Replaying the formula over the 259 steps:

| | summed width per walk | summed comparator width | steps clamped at 256 | width at step 258 |
| --- | --- | --- | --- | --- |
| base (25, 0.950) | 40,922 | 18,422 | 29 | 36 |
| this commit (10, 0.984) | 36,208 | 17,252 | 13 | 14 |

Per walk that is 4 × 4,714 + 1,170 = 20,026 Toffoli. The four walks give
80,104, the measured drop. The runway transcript allocation falls from 488 to
464 bits. The peak is set by the apply chunked add, so it stays at 1390.

Compared with johnbxx's margin-7, slope-0.950 tree ([247db26](247db26.md)),
this envelope is wider up to about step 80 and narrower from about step 100 on.
Summed over the walk it is 382 bits narrower.

## Why it is still correct, and what it risks

The envelope is a statistical fit. Bits above `active_width` are assumed to
be zero in `u` and `v` and are left out of the walk, and part of the
transcript is parked on them. A steeper slope assumes the K=2 walk shrinks
`max(bitlen u, bitlen v)` by 0.984 bits per step on average. With a 10-bit
margin, an input that falls behind that line by more than about 10 bits at
any step breaks the walk. The late steps carry the most risk, because the
slope's error accumulates. A failure gives a classical mismatch, and ancilla
garbage after the reverse walk.

The shipped nonce `65110790329263` draws a test set with 0 classical, 0 phase
and 0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as Register and Scratch Allocation → ancilla-lifetime /
venting. The diff does not support that. No wire lifetime changes, the peak
does not move, and the whole saving is narrower per-step register widths. By
the diff, this is Dead-Code and Redundancy Elimination → comparator/width
truncation, the same lever as [01260e8](01260e8.md) and
[5b3887b](5b3887b.md). The published label is kept in the header.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a772a45 -- src/point_add`.
   - Do not start from the git parent `247db26`. That is johnbxx's tree.
   - Against the parent, the diff would also show johnbxx's changes being
     undone: `KAL_DOUBLE/FOLD_CARRY_TRUNC_W` 20 → 24, `CUT` and `CUT2`
     56/112 → 58/114, and margin 7 instead of 25 as the starting point.
   - Against `a772a45`, `git diff --ignore-cr-at-eol a772a45 1eae277 -- src/point_add`
     is 6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1eae277 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,550,383 average Toffoli (rounded)
   - score 2,155,032,370
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=65110790329263` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

In June the modular inverse was the *dialog GCD*. A forward GCD walk records
its branch decisions in a compressed quantum transcript, and an "apply" stage
replays those decisions on the `y` register. With the K2 pair compressor, each
transcript block covers two GCD steps: six raw decision bits stored in five
qubits. Before each block is replayed, the base swapped the five compressed
cells into a separate six-qubit `raw_block` and decoded them there. That
`raw_block` stayed allocated through the whole apply, next to the now-empty
compressed cells.

This commit decodes each block in place, on its own five compressed cells
plus one zero wire. The six-qubit `raw_block` is no longer needed during the
apply, so the apply's narrow phases (the doubling and halving of `y`) lose
five live wires. The chunked add/sub that used to borrow the empty compressed
cells as scratch now allocates five clean qubits only for its own duration.
Three other knobs bring down the next co-binding phases: the square, the apply
ripple chunks and the round-84 fold. Together they reach 1215 qubits. The cost
is +1,146 Toffoli, mostly from switching the round-84 fold's small adders back
to coherent adders.

## What changed and why it saves qubits

**Background: the K2 pair transcript (see
[transcript-codecs](../concepts/transcript-codecs.md); [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) describes its
successor).** Each GCD step records two bits, `b0` and `b0_and_b1`. With
`DIALOG_GCD_K2=1` each step can strip a second factor of two, and it records
a third bit, `shift2`. `DIALOG_GCD_K2_PAIR_COMPRESS=1` groups steps in pairs
(`dialog_gcd_sidecar_group_size() = 2`). The six raw bits of a pair are laid
out as `raw = [b0₀, b0b1₀, b0₁, b0b1₁, s2₀, s2₁]`. The pair has only 30
reachable states (comment on `dialog_gcd_block_bits` in `config.rs`): the
five-wire "core" `[raw0, raw1, raw4, raw2, raw3]` takes only 15 values, so it
compresses to four bits plus a zero. The
encoder `emit_dialog_gcd_k2_pair_core_encoder` uses 3 CCX. `s2₁` stays raw.
A block is therefore 5 qubits (`dialog_gcd_block_bits() = 5`), and
`dialog_gcd_raw_block_len()` is 6.

**1. In-place decode (`src/point_add/rounds/dialog/compressed.rs`, new knob
`DIALOG_GCD_K2_APPLY_INPLACE_RAW_BLOCK=1`).**
- New `dialog_gcd_k2_pair_inplace_raw_frame(compressed_block, raw0)` returns
  the virtual raw block `[raw0, c0, c2, c3, c1, c4]`. This is exactly where
  the base's swap copy (`dialog_gcd_k2_pair_copy_compressed_block_to_raw`)
  moved each compressed cell: `c0→raw1, c1→raw4, c2→raw2, c3→raw3, c4→raw5`.
  The only change is that the cells are not moved.
- New `dialog_gcd_k2_pair_inplace_decompress_block` runs
  `emit_dialog_gcd_k2_pair_core_encoder_inverse` on that frame's core.
  `dialog_gcd_k2_pair_inplace_clear_block` re-encodes it after the block's
  steps. The gate sequence is the same as the base's decode and re-encode, so
  Toffoli is unchanged.
- In `emit_dialog_gcd_compressed_sidecar_apply_bitvector_block_lifecycle`
  (forward apply) and `…_reverse_exact_b…` (reverse apply), one `raw0` wire is
  allocated for the whole loop. The caller passes an empty `raw_block`. Every
  `raw_block[...]` read becomes `raw[...]` from the frame.
- Before this change, with `DIALOG_GCD_APPLY_REPLAY_SWAP_HOST=1`, the
  now-zero compressed cells were passed as `clean_scratch` to
  `dialog_gcd_cmod_{add,sub}_materialized_pseudomersenne_with_clean_scratch_at_step`.
  In place, those cells hold decoded bits. So, around each materialized add
  or sub, the code now allocates `dialog_gcd_block_bits()` = 5 fresh qubits
  and frees them right after.
- In `emit_dialog_gcd_compressed_sidecar_ipmul_block_lifecycle` and
  `…_quotient_block_lifecycle`, the six-qubit `raw_block` that the caller
  holds is freed before the apply and reacquired (`reacquire_vec`) after it.
  It is not given to the apply, and no host `apply_raw_block` is allocated.

The net effect: during the `y` doubling and halving in each apply block, the
live set was 6 raw wires + 5 empty compressed cells. It is now the 5 cells +
1 `raw0`. During the add/sub it is still 11, but now 5 of those are
short-lived. That is a pure lifetime cut. See
[venting-and-wire-loans](../concepts/venting-and-wire-loans.md).

There is also a side edit, inert in this build:
`dialog_gcd_host_reverse_raw_block_enabled` and the two `…_raw_block_host`
searches now size the host by `dialog_gcd_raw_block_len()` instead of a
hard-coded `2 × group_size`. K2 hosting stays off unless the new
`DIALOG_GCD_K2_HOST_RAW_BLOCK=1` is set, and nothing sets it.

**2. Knobs that lower the other co-binders (`src/point_add/mod.rs`,
`configure_ecdsafail_submission_route()`).** See
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md) for why
every phase at the high-water mark must come down together.
- `SQUARE_ROW_MAX_SEG`: 191 → 188. This sets the widest square row that is
  built in one piece. Rows wider than this are split into two windows (see
  [`d636d62`](d636d62.md)). The largest one-piece row register therefore
  shrinks from 191 to 188 bits, which lowers the square's transient peak by
  3. Three more rows (widths 189 to 191) are now windowed, which adds 6
  truncated boundary cleanups.
- `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS`: 11 → 12. The controlled apply add
  `acc += ctrl·a` is split into this many even chunks of the 257-bit extended
  accumulator (`dialog_gcd_chunk_hi`: `(blk+1)·257/blocks`). Each chunk loads
  `ctrl & a[lo..hi]` into a fresh register `f`. Twelve chunks make `f` about
  21 bits instead of about 23, at the cost of one more boundary carry, which
  the existing conditional boundary replay clears.
- `ROUND84_FOLD_FAST_ADD`: 1 → 0. The small adders of the round-84 in-place
  Solinas fold (33-bit quotient·c product, 66-bit correction, ≤34-bit spill)
  go back from the measured fast adder `add_nbit_qq_fast` (about 1 CCX per
  bit, plus a carry wire per bit) to coherent Cuccaro (about 2 CCX per bit,
  no carry wires). This removes up to about 66 transient carry wires from the
  fold phase and costs about one Toffoli per adder bit. The code comment puts
  the fast version's saving at 1,434 Toffoli. That was measured on an older
  tree, and it is the largest part of this commit's +1,146.
- `DIALOG_TAIL_NONCE` (the first of the two `set_default_env` lines; the
  later one never takes effect): 4836419 → 9400000893246.

I did not run a per-phase peak trace. Which of these three knobs was strictly
needed for each of the three qubits is from the submission note, not
measured.

## Why it is still correct, and what it risks

- **The in-place decode is exact.** It runs the same reversible encoder and
  inverse on the same logical bits. Only the physical wires differ, and the
  frame permutation matches the base copy's. The re-encode at block end
  returns the cells to the compressed form, and `raw0` to |0⟩. If the frame
  were wrong, the apply would replay wrong decisions (a classical failure),
  or `raw0` would end dirty (an ancilla failure).
- **The fresh 5-qubit scratch** is allocated clean and returned clean by the
  materialized add/sub, as the borrowed cells were before.
- **`ROUND84_FOLD_FAST_ADD=0` and `CHUNKED_F_BLOCKS=12` are exact.** Both
  coherent Cuccaro and the chunked ripple with exact boundary clears compute
  the same value.
- **`SQUARE_ROW_MAX_SEG=188` adds a little risk.** It is value-exact, but it
  adds six boundary cleanups that use the 22-bit truncated compare. A tie in
  the top 22 bits gives a phase failure.
- The shipped nonce `9400000893246` draws a clean set (9,024 shots, 0 / 0 / 0).
  See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The main lever stops holding a separate decode buffer and reuses the
transcript's own compressed cells as the decoded block. That is scratch
reuse. The other three knobs are standard peak-budget dials, and they trade
Toffoli for width the same way. A runner-up label would be "ancilla-lifetime
/ venting", because the freed `raw_block` in the ipmul and quotient
lifecycles is released and reacquired around the apply.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout d636d62 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol d636d62 420e0c2 -- src/point_add` is
   217 lines in 2 files.

   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 420e0c2 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with none of the
   route's variables (`DIALOG_*`, `SQUARE_*`, `KAL_*`, `KARA_*`, `ROUND84_*`,
   `R84_*`) set, because `set_default_env` only fills unset variables. Expect:
   - 1215 qubits
   - 1,403,338 average Toffoli (rounded)
   - score 1,705,055,670
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `9400000893246` and an identical op
stream. Any other change needs a new nonce hunt.

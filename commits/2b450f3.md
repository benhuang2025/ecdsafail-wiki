## Summary

The ping-pong divider's multiply traversal has its own round count,
`SUB4_PP_ROUNDS_MUL`, separate from the divide's `rounds() = 700`. On
jackylee0424's 1277-qubit tree `ce60e68` it was `rounds() − 3 = 697`. This
commit makes it `rounds() − 4 = 696`.

One round fewer removes one walk round, one 256-bit replay cell and one
walk-back round from the multiply traversal, which saves 362 average Toffoli.
Qubits stay at 1277, because the replay ladders fill the room under a fixed
cap. The cost is a little more exposure to multiply walks that need the
extra round. It is the same step benhuang2025's [`5c23d45`](5c23d45.md) took
on the 1278-qubit tree.

## What changed and why it saves Toffoli

1. **`rounds_for(PingPongDirection::Multiply)`** in
   `src/point_add/pingpong_div.rs`: the default of `SUB4_PP_ROUNDS_MUL` goes
   from `rounds() − 3` to `rounds() − 4`. The divide keeps `rounds()`.
   - The multiply walk, its replay batches and its walk-back all loop to
     `rounds_for(direction)`, so all three lose their last round.
   - That round runs at the narrowest walk width, so most of the −362 T is
     the replay cell: the chunked add, the fold, and the chunk and flag
     repairs.
   - **Qubits.** `plan()` in this tree has checkpoints `r1 = 504`,
     `r2 = 608` and cap `SUB4_PP_PEAK = 1277`. The replay ladders are sized to
     the room left under that cap, so a one-wire shorter tape does not lower
     Q. See [pingpong-division](../concepts/pingpong-division.md) and
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
2. **Tail nonce** (`src/point_add/mod.rs`): the default
   `SUB4_PINGPONG_TAIL_NONCE` goes from 8004485 to 8050074.

## Why it is still correct, and what it risks

- **Depth is a truncation.** An input whose multiply walk needs more than
  696 rounds to reach `(±1, ±1)` gives a wrong product and dirty walk
  registers. That shows as classical and ancilla failures.
- The `rounds_for` comment prices one round on one traversal at about
  +0.05 λ.
- The shipped nonce `8050074` draws a clean test set: 0 classical, 0 phase
  and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Cutting a fixed round count against a measured convergence rate is
iteration/threshold tuning.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ce60e68 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol ce60e68 2b450f3 -- src/point_add` is
   4 changed lines in 2 files.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 2b450f3 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set (in particular no `SUB4_PP_ROUNDS_MUL`). Expect:
   - 1277 qubits
   - 942,944 average Toffoli (rounded)
   - score 1,204,139,488
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `8050074` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

The `square` phase computes `out ← out − y² mod p` with a top-level Karatsuba
split `y = y_lo + y_hi·2^128` into three branches: A = `y_lo²`, B = `y_hi²`
and C = `(y_lo + y_hi)²`. In the base, branch B built `y_hi²` in a 256-qubit
product register with one plain 128-bit triangular square. Branches A and C
never built a product register: `karatsuba_branch` split them one more level
and folded each of the three sub-squares straight into `out`, which took 10
folds for A and 5 for C.

This commit builds all three branches the same new way. Each branch's square is
materialised in a product register by a new routine, `tri_square_k2r`, that
does one in-place Karatsuba split and keeps its scratch alive until the
matching inverse. Branch B's leaf work shrinks from one 128-bit triangle to
two 64-bit and one 65-bit triangle. Branches A and C keep the same leaf sizes,
but each now needs only 2 folds and 1 fold, instead of 10 and 5. The square
gets 4,632 average Toffoli cheaper at the same 1266-qubit peak. Every new
primitive is an exact full-width add.

## What changed and why it saves Toffoli

All logic changes are in `src/point_add/trailmix_ludicrous/square/product_register.rs`.
`mod.rs` only gets a new nonce.

1. **New `tri_square_k2r(circ, x, product, min_width)` and `tri_square_k2r_inv`.**
   For an `m`-bit `x` with `m ≥ min_width` (otherwise it falls back to plain
   `tri_square`), with `lo = m/2`, `a = x[..lo]`, `b = x[lo..]`:
   - Build `a²` into `product[..2lo]` and `b²` into `product[2lo..]`. These are
     disjoint halves of the zeroed product register, so no add is needed.
   - Build `t = a + b` (hi+1 bits) with CXs plus one `add_full`.
   - Build `p_t = t²` in a fresh `2(hi+1)`-qubit register, then subtract the
     two halves with `sub_full`, leaving `p_t = 2ab`. Both intermediates are
     nonnegative, so the frame never wraps.
   - Add `p_t` into `product[lo..]` with one full-width `add_full`. Now
     `product = x²`.
   - Return `t` and `p_t` in a `K2Retained` struct. They stay live across the
     consumer's folds, so the inverse runs the same steps backwards without
     recomputing `t²`. The routine recurses into `a`, `b` and `t` while they
     are still `≥ min_width`.
   - `SUB4_SQUARE_CHUNK_MIN` is pinned to `u64::MAX` in `mod.rs`, so every
     `add_full` here is one unchunked ripple with exact measured carry erasure.
2. **Branch B (`y_hi²`, 128 bits)** in `square_sub`: `tri_square` →
   `tri_square_k2r(…, bk2_min())`. `bk2_min()` defaults to 128, so B is split
   once into triangles of 64, 64 and 65 bits. Triangle rows grow as m², so
   three half-size triangles plus three full adds are cheaper than one
   128-bit triangle. See
   [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md), whose cost
   model puts the break-even near 60 bits.
3. **Branches A and C are materialised.** `a_mat_enabled()` and
   `c_mat_enabled()` default to true, so `square_sub` takes the new arms
   before the old `karatsuba2_enabled()` arm:
   - A: a 256-qubit `product_a` built by `tri_square_k2r(y_lo, …, 128)`, then
     two folds: `mod_add_top` (+A at shift 0) and `apply_shift_half` (−A at
     shift 128).
   - C: a 258-qubit `product_c` for the 129-bit sum, built by
     `tri_square_k2r(sum, …, 128)`, then one `apply_shift_half` fold.
   - The leaf triangles are the same sizes as in `karatsuba_branch`, so the
     saving here is in the folds. `karatsuba_branch` composed each sub-square's
     local coefficients with the parent's, giving 10 narrow folds for A and 5
     for C. Several of them straddle bit 256 and pay a 5-term `apply_f` fold
     on their high part (see [modular-fold](../concepts/modular-fold.md)).
     After the change there are 2 wide folds for A and 1 for C, plus the K2
     assembly adds.
   - The cost is qubits. A and C now hold the product register plus about 195
     and 198 retained qubits across their folds. The square still fits under
     the replay's peak, so Q stays at 1266. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
4. **Unused by default:**
   - `karatsuba_branch`'s own sub-squares also go through `tri_square_k2r`
     with `ack2_min()`, which defaults to `usize::MAX`, meaning plain
     `tri_square`. Branches A and C no longer reach that path anyway.
   - Knobs `SUB4_SQUARE_BK2_MIN`, `SUB4_SQUARE_B_LOCAL_K2`,
     `SUB4_SQUARE_ACK2_MIN`, `SUB4_SQUARE_A_MAT`/`C_MAT` and
     `SUB4_SQUARE_AMAT_MIN`/`CMAT_MIN` allow A/B testing.
   - `selfcheck()` gains a multi-batch mode (`SQ_SELFTEST_BATCHES`) and a
     counting mode (`SQ_SELFTEST_COUNT`).
5. **Tail nonce:** `SUB4_PINGPONG_TAIL_NONCE` default 82505456522172 →
   11024017180859.

## Why it is still correct, and what it risks

- **The new decomposition is exact.** Karatsuba is an identity, and every new
  operation is an unchunked full-width add or subtract. The source comment
  says no truncated compare, windowed fold or measured chunk boundary is
  added.
- **The fold mix changes.** Branches A and C replace 15 composed folds with 3
  wide ones, so the set of approximate fold sites (`window_add` guard bits,
  `apply_f`) changes. That moves λ, and probably lowers it, since there are
  fewer sites. It was not measured in the commit.
- **Retained scratch must be consumed in order.** `tri_square_k2r_inv`
  requires the product register to hold exactly `x²` again, so every
  consumer fold is undone first. The code does this inside each branch.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. Any slip in the inverse would show up as ancilla or phase garbage
  on every shot, so a clean run also checks the bookkeeping.

## Classification rationale

The saving comes from a different decomposition of the squarer: a deeper,
materialised in-place Karatsuba in place of the composed-fold branch. That is
a multiplier/squarer swap. It is not a fold truncation, because no window
narrows; the fold count drops because the products are built in a different
shape.

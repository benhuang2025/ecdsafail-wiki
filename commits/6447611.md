## Summary

This commit makes two exact changes to the dialog-GCD route of
[`cddd5df`](cddd5df.md), on Gajesh2007's margin-28 tree
[`8cb350c`](8cb350c.md). Both replace Toffoli-costed uncomputes with X-basis
measurement plus a CZ fix-up.

1. **GCD branch compare.** The compare now uses the existing
   `cmp_lt_into_fast`, which costs `k` Toffoli instead of `2k`. This is the
   same idea as [`7e660f9`](7e660f9.md), which was promoted in parallel on a
   different tree. It saves 210,136.
2. **Replay subtract.** In the divide replay, the controlled subtract cleared
   its 256-bit `f = ctrl·a` load register with 256 CCX per step. It now clears
   it by measurement, as the add already did. That saves 102,144.

Together they save 312,280 average Toffoli at the same 1698 qubits. The reroll
`DIALOG_REROLL` goes from 8 to 2.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`.

1. **`dialog_gcd_cmp_gt_truncated_into_width()`: `cmp_lt_into` → `cmp_lt_into_fast`.**
   - `cmp_lt_into_fast` (line 2662) was already in the file. It runs a
     forward carry sweep with an `n`-qubit carry register, copies the top
     carry into `flag`, then undoes the carries with `hmr` and
     `cz_if(u[i−1], v[i], m)`, so it costs `n` Toffoli instead of `2n`.
     (When `kal_vent_modadd_enabled()` is set it falls back to `cmp_lt_into`.
     That option is not set on this route.)
   - The compare runs twice per step, on `min(75, w(s))` bits, in four GCD
     passes. With margin 28, `Σ min(75, w(s)) = 26,267`, and halving the cost
     saves 8 × 26,267 = 210,136.
2. **`dialog_gcd_cmod_sub_materialized_pseudomersenne()`: clear `f` by measurement.**
   - This is the controlled modular subtract `y -= ctrl·a` used in every step
     of the divide replay (`..._apply_bitvector_reverse_exact_block_lifecycle`).
   - It first loads `f[i] = ctrl AND a[i]` with 256 CCX. The old code cleared
     `f` with the same 256 CCX again. The new loop does
     `hmr(f[i], m); cz_if(ctrl, a[i], m)` for each bit, at 0 Toffoli. The
     sibling add `dialog_gcd_cmod_add_materialized_pseudomersenne` already
     did this.
   - That saves 256 Toffoli × 399 steps = 102,144.
   - Total: 210,136 + 102,144 = 312,280, exactly the measured saving.
3. **`configure_ecdsafail_submission_route()`: `DIALOG_REROLL` 8 → 2.** This is
   the count of identity `X(tx[0]); X(tx[0])` pairs emitted before the point
   addition. It selects the 9,024-shot test draw.

## Why it is still correct, and what it risks

- Both changes are exact. A measured uncompute of an AND (`f = ctrl ∧ a` or a
  carry `u ∧ v`) is right as long as the two controls still hold their
  compute-time values at the `cz_if`. Here they do: `ctrl` and `a` are
  untouched between the load and the clear, and the compare's backward sweep
  is the exact gate-reverse of the forward sweep. A mistake would show as phase
  garbage.
- The probabilistic parts are those of the base: the margin-28 width
  envelope, the 75-bit compare window, 399 steps, and the 20-bit overflow
  clear. The new op stream redraws the inputs, and `DIALOG_REROLL = 2` gives a
  clean draw: 0 classical, 0 phase and 0 ancilla failures over 9,024 shots.
  See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is Dead-Code and Redundancy Elimination →
comparator/width truncation. No width is narrowed here. Both changes replace a
Toffoli uncompute with a measurement plus a classically controlled CZ, which is
**Uncompute Strategy → measurement uncompute**, the label the census gives the
same compare lever in [`7e660f9`](7e660f9.md) and the subtract lever in
[`c813ee5`](c813ee5.md).

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8cb350c -- src/point_add`.
   - Do not start from the git parent `7e660f9`. That is saucegodbased's
     tree, without the margin-28 change.
   - Against the parent, the diff is 271 lines. It would show
     `cmp_lt_into_measured` and the `DIALOG_GCD_MEASURED_CMP` switch being
     removed, the compare width going from 72 back to 75, and the
     `DIALOG_GCD_REROLL` block being dropped. Those are reverts of
     [`7e660f9`](7e660f9.md), [`541bd85`](541bd85.md) and
     [`00e3a20`](00e3a20.md).
   - Against `8cb350c`, `git diff --ignore-cr-at-eol 8cb350c 6447611 -- src/point_add`
     is 10 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 6447611 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or `ROUND*` environment variables set. Expect:
   - 1698 qubits
   - 2,083,878 average Toffoli (rounded)
   - score 3,538,424,844
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 2` and an identical op stream.
Any other change needs a new reroll search.

## Summary

This is the same one-knob change as the author's [`bdfc7df`](bdfc7df.md),
re-applied on top of [`fb83e6c`](fb83e6c.md). That commit added the
measured-uncompute `z2` square but went back to the older tree's width margin
of 26. Here the margin of the dialog GCD's per-step width envelope drops from
26 to 25 again. Because the width is rounded up to an even number, 179 of the
396 steps lose 2 bits, and their controlled swaps and controlled subtracts
get cheaper. That saves 4,616 average Toffoli at the unchanged 1434-qubit
peak. The reroll pair was re-searched for the new op stream.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_WIDTH_MARGIN`: 26 → 25.**
   - `dialog_gcd_tobitvector_active_width(step)` computes
     `ideal = 256 − step × 0.7075 + margin`, rounds it **up** to an even
     number and clamps it to [1, 256]. Each GCD transcript step works only on
     `u[..active_width]` and `v[..active_width]`: the controlled swap (one CCX
     per bit), the gated load and the controlled subtract
     (`dialog_gcd_controlled_sub_selected`). The branch comparator has its own
     cap (`DIALOG_GCD_COMPARE_BITS = 58` here) but is also clamped to
     `active_width`, so on the 40 late steps (319 to 395) where the width
     binds it loses 2 bits as well: 80 compare bits.
   - With 396 active steps (`DIALOG_GCD_ACTIVE_ITERATIONS=396` in this tree,
     one more than in `bdfc7df`), the summed per-step width goes from 56,206
     to 55,848 bits: 179 steps lose 2 bits each. 4,616 is exactly
     12 × 358 + 4 × 80, the same split as in `bdfc7df`: about 3 Toffoli per
     removed bit plus one per removed compare bit, in each of the four
     transcript passes (forward and reverse, for each of the two GCD calls).
   - Early steps clamp at 256 bits, so the peak does not move.
2. **Reroll pair: `DIALOG_REROLL` 102 → 366567,
   `DIALOG_POST_SUB_REROLL` 100 → 59314.** These are counts of identity
   `X;X` pairs emitted before and after the input subtraction. They change the
   op-stream hash, and so the 9,024 Fiat–Shamir test inputs, without changing
   what the circuit computes. See
   [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

The width truncation is probabilistic. It assumes that at step `s` both `u`
and `v` fit in `active_width(s)` bits. An input whose GCD converges more
slowly than the envelope has a nonzero bit above the cut. The step then
ignores it, the transcript decisions go wrong, and the run shows classical
failures (and phase or ancilla garbage when the reverse pass no longer
mirrors the forward one). One bit less margin raises λ, the expected number
of failing shots per 9,024-shot draw. The parent had given back several
tightenings to lower λ, which left room to take this one again.

The shipped pair (366567, 59314) draws a clean set: the author reports 0
classical, 0 phase and 0 ancilla failures over all 9,024 shots. See
[comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md)
and [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) for the dialog GCD
lineage.

## Classification rationale

The only circuit change narrows the registers each GCD step operates on,
which is comparator/width truncation. The reroll change is the usual
companion of any circuit change in this era.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout fb83e6c -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol fb83e6c b27f99c -- src/point_add` is
   6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol b27f99c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` keeps any
   value already in the environment. Expect:
   - 1434 qubits
   - 1,712,191 average Toffoli (rounded)
   - score 2,455,281,894
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL=366567`,
`DIALOG_POST_SUB_REROLL=59314` and an identical op stream. Any other change
needs a new reroll search.

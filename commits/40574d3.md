## Summary

This redoes [`7787f81`](7787f81.md) with a better split point. The GCD apply
pass adds a gated 256-bit register in two chunks, and the upper chunk holds
2 scratch qubits per bit (the gated addend and the carry lane). At the base's
split, bit 70, the upper chunk set the global peak of 1558. `7787f81` moved
the split to bit 82. This commit moves it only to bit 79: 2 × 9 = 18 fewer
qubits puts the apply phase at 1540, just under the x-tail square's 1543,
which becomes the global peak.

The price of a higher split is a wider exact compare that clears the carry
between the chunks: +9 bits × 2 calls per step × 399 steps = +7,182 Toffoli.
That is 2,394 Toffoli cheaper than the cut at 82, at the same 1543 qubits.

## What changed and why it saves qubits

1. **`DIALOG_GCD_APPLY_CHUNKED_F_CUT`: 70 → 79** in
   `configure_ecdsafail_submission_route()`, `src/point_add/mod.rs`.
   - With `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS=2`, the controlled modular add
     and subtract of the apply pass (`dialog_gcd_add_ctrl_chunked_low_to_ext`
     and `dialog_gcd_sub_ctrl_chunked_low_to_ext`) split the 257-bit extended
     accumulator at `F_CUT`.
   - Chunk 0, `[0, F_CUT)`, loads `ctrl & a[0..F_CUT]` and adds it with a
     fresh carry-out bit. Chunk 1, `[F_CUT, 257)`, loads
     `ctrl & a[F_CUT..256]` and adds it with `cuccaro_add_fast_low_to_ext`,
     which allocates one carry qubit per bit. So the upper chunk holds
     2 × (256 − F_CUT) scratch qubits: 372 at 70 and 354 at 79.
   - 18 fewer qubits takes the apply phase from 1558 to 1540. The new global
     peak, 1543, is in `round84_fused_square_xtail_dx_sub_lam_square_lowq`
     (the author's run output). Any cut from 78 up gives that same peak
     ([`287595e`](287595e.md) reaches 1543 at 78 with the same ops), but 78 had
     no clean reroll pair (see below), so 79 is the cheapest cut that validated.
   - **Cost.** The carry out of chunk 0 is cleared by an exact compare of the
     low `F_CUT` bits (`ccx_cmp_lt_into_fast(acc_ext[..F_CUT], a[..F_CUT], ctrl, cout)`
     for the add, and the mirrored compare for the subtract). It costs about
     one Toffoli per bit. It runs once per GCD step in each pair's apply pass
     (the product pair adds, the quotient pair subtracts):
     9 × 2 × 399 = 7,182 Toffoli, exactly the measured change.
2. **Reroll pair: `DIALOG_REROLL` 13 → 0, `DIALOG_POST_SUB_REROLL` 14 → 26.**
   Identity `X;X` counts that re-draw the 9,024 test inputs (see
   [`ecbf87b`](ecbf87b.md)). The comment says a 250-cell grid found no clean
   pair for F_CUT = 78.

## Why it is still correct, and what it risks

The change is exact. The two chunk adds plus the boundary carry compute the
full 257-bit sum for every input wherever the split is, and the boundary
compare is a full compare of the low bits. Only the test set changes, and the
existing approximations (truncated GCD comparator and widths, fold windows,
19-bit overflow-clean compare) are all right on the new draw: 9,024 of 9,024
shots, 0 classical, 0 phase and 0 ancilla failures with reroll pair (0, 26).
The author's note reports that F_CUT = 78 only ever reached a single
phase-garbage batch (0/1/0) across about 250 pairs. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is fold/carry truncation, but nothing is truncated. The
lever moves a chunk boundary to lower the live scratch at the peak, at the cost
of a wider exact compare. Ancilla-lifetime / venting (Register and Scratch
Allocation) describes it better. The label is kept as published.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b113c6f -- src/point_add`.
   - The git parent is `7787f81`, the same author's F_CUT = 82 submission.
     Diffing against it (29 lines) shows the same knob as 82 → 79 and swaps
     its comment; this commit was built on `b113c6f`.
   - `git diff --ignore-cr-at-eol b113c6f 40574d3 -- src/point_add` is 21
     lines changed in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 40574d3 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1543 qubits
   - 1,695,885 average Toffoli (rounded)
   - score 2,616,750,555
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=0`,
`DIALOG_POST_SUB_REROLL=26` and an identical op stream. Any other change needs
a new reroll search.

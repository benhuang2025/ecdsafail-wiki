## Summary

Each dialog-GCD apply step does a 256-bit controlled add (forward apply) or
subtract (reverse apply) of `x` into `y`. If it overflows, it folds the
constant `c = 2^32 + 977` back into the low bits of `y`. `KAL_FOLD_CARRY_TRUNC_W`
caps how far that fold's carry ripples above bit 32. This commit lowers the cap
from 22 to 21. That saves one Toffoli in each of the 518 apply calls (259 adds
and 259 subtracts): −518 average Toffoli at 1313 qubits. It is the sibling of
the `KAL_DOUBLE` cut in the parent [`4ef0046`](4ef0046.md). The tail nonce was
re-hunted.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`.

1. **`KAL_FOLD_CARRY_TRUNC_W`: 22 → 21.**
   - `fold_carry_trunc_window()` is read by the overflow fold of
     `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked` and the
     underflow fold of `..._cmod_sub_..._chunked`. These run
     `cadd_nbit_const_direct_trunc_fast` or `csub_nbit_const_direct_trunc_fast`
     on `y[..73]` (`DIALOG_GCD_SPECIAL_ADD_LSBS`), controlled on the overflow
     bit.
   - The ripple stops `w` positions above the constant's top set bit (bit 32).
     Each position is one Toffoli, and the carries are erased by measurement.
     One position less is −1 per call, × 518 calls.
   - See [`83da96f`](83da96f.md) for the 24 → 22 step and
     [modular-fold](../concepts/modular-fold.md) for the fold itself.
2. **`DIALOG_TAIL_NONCE`: 1000001157 → 1080.** This reseeds the 9,024 test
   inputs. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

The truncated fold is probabilistic. It is wrong when the carry out of bit 32
runs through more than `w` consecutive ones of `y` above it, about 2^−(w+1)
per call for a random `y`. One bit less doubles that rate. A wrong fold leaves
the high bits of `y` wrong. That gives a classical failure, and garbage when
the reverse apply, which uses the same window, does not undo it. The carry
wires still return to |0⟩.

λ rises a little. The shipped nonce 1080 draws a clean set, with 0 classical,
0 phase and 0 ancilla failures over all 9,024 shots per the commit comment.

## Classification rationale

The census files it as comparator/width truncation. The change is a carry
window inside the modular fold, which fits fold/carry truncation more exactly.
Both are truncations to fewer bits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 4ef0046 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 4ef0046 587b6d8 -- src/point_add` is 17 lines in
   1 file. The base keeps `DIALOG_GCD_COMPARE_BITS=46`. It does not have
   `02049b8`'s 45.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 587b6d8 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because `set_default_env`
   keeps any value already in the environment. Expect:
   - 1313 qubits
   - 1,535,367 average Toffoli (rounded)
   - score 2,015,936,871
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=1080` and an identical op
stream. Any other change needs a new nonce hunt.

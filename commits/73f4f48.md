## Summary

The previous commit, [a5a590a](a5a590a.md), cut 2 high bits off the dialog-GCD
walk body at step 9, which was the only step at the 1302-qubit peak. After
that, step 8 became the binder at 1301. This commit applies the same 2-bit
notch to step 8 as well, so the peak drops to 1300. The narrower body also
saves 4 Toffoli per walk step, 16 in total. The tail nonce was re-hunted.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_BINDER_NOTCH_STEPS`: `9` → `8,9`**, with
   `DIALOG_GCD_BINDER_NOTCH_EXTRA` still 2.
   - `dialog_gcd_body_carry_trunc_width(active_width, step)` in
     `rounds/dialog/mod.rs` adds `NOTCH_EXTRA` to the trim `w` of every listed
     step. Step 8 is in the first trim band (trim 0) and `active_width` is
     clamped to 256 there, so its controlled sub/add body now covers 254
     bits instead of 256.
   - The body's composite scratch is `2·body_len − 1` wires. The code
     comment says a trim of `k` lowers that step's owned scratch deficit, and
     so its peak, by `k`. Step 8 was the 1301 binder after
     [a5a590a](a5a590a.md), and the next binder sits at 1300. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - Toffoli: 2 fewer gated-load CCX and 2 fewer carry CCX per body, over
     the 4 walks (forward and reverse walk of both divisions): −16, exactly
     the measured change.
2. **`DIALOG_TAIL_NONCE`: 38978004 → 169924627**, the fixed `X;X` identity
   tail that reseeds the 9,024 test inputs. The comment is updated.

The rest of the route (apply clean compare 20 bits, the per-step overflow and
underflow overrides, the dormant cswap trim) is unchanged from
[a5a590a](a5a590a.md). The submission note repeats those items as if they
were new. They are not part of this diff.

## Why it is still correct, and what it risks

The notch relies on the top 2 bits of `u` and `v` being 0 at step 8 and on
no carry reaching them. The code comment calls this value-exact on the
reachable GCD support. The bound behind it is empirical, the same one the
band trims use, so treat it as probabilistic. If an input breaks it, the
walk goes off its path, and the run shows a classical mismatch and ancilla
garbage.

The author's note says GPU lanes also tried steps `8,9,10`, a 23-bit apply
clean and the cswap trim, and only this route produced a clean nonce. The
shipped nonce `169924627` draws a test set with 0 classical, 0 phase and 0
ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows the body width at one more step, which is
width truncation. Its purpose is the qubit, so Register and Scratch
Allocation → scratch/ancilla reuse would also fit.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout a5a590a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol a5a590a 73f4f48 -- src/point_add` is
   7 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 73f4f48 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set. Expect:
   - 1300 qubits
   - 1,454,884 average Toffoli (rounded)
   - score 1,891,349,200
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `169924627` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

The author's previous submission [`b5796ce`](b5796ce.md) replaced the linear
walk-width formula with a fitted 700-entry `WIDTH_SCHEDULE` and spent part
of the saving on λ, mainly six extra multiply rounds (696 → 702).
This commit spends some of that λ on depth. The divide walk goes from 700 to
698 rounds and the multiply walk from 702 to 700. Four rounds' walk adds,
walk-back adds and replay cells disappear, which saves 1,905 average Toffoli
at the same 1278 qubits.

The author's updated notes put the cost in nonce-search terms. The λ of the
walk alone rises from 7.46 to 8.79 and the rest from about 3.5 to 4.2, so a
clean nonce takes about 440,000 draws instead of 55,000. The notes estimate
that each further pair of rounds would cost about ten times more search for
about 1,900 Toffoli.

## What changed and why it saves Toffoli

All in `src/point_add/pingpong_div.rs`, plus notes.

1. **`rounds()` default: 700 → 698** (`SUB4_PP_ROUNDS`). This is the divide
   traversal's depth: the walk records 698 tape signs, and the replay and
   walk-back each run 698 steps.
2. **`rounds_for(Multiply)` default: `rounds() + 2` → `700`**
   (`SUB4_PP_ROUNDS_MUL`). The base ran the multiply walk 2 rounds *longer*
   than the divide, 702 rounds; `b5796ce` had bought that λ back. Now it is
   pinned at an absolute 700, two fewer. Writing 700 instead of
   `rounds() + 2` keeps the multiply depth fixed if `SUB4_PP_ROUNDS` is
   changed.
3. **Why it saves Toffoli.** Each removed round deletes one walk add, one
   walk-back add and one fused replay cell. The removed rounds are the last
   ones, where the walk registers are at the schedule's narrow floor, so the
   replay cell (a 256-bit chunked add, the fold, and the measured-erase
   repairs) is most of the cost: about 476 Toffoli per round here.
   - The two tapes get two wires shorter. Qubits stay at 1278 because the
     replay ladders are sized to the `SUB4_PP_PEAK` budget, which is
     unchanged.
   - The width table has 700 entries, so all 700 multiply rounds still read
     a fitted width.
4. **`sched_bias()`: `usize` → `i32`.** `SUB4_PP_SCHED_BIAS` can now narrow
   the whole schedule as well as widen it, with the result floored at 8. The
   default is 0, so the op stream is unaffected.
   - The notes record why it stays at 0: the fitted schedule "sits exactly on
     the deterministic shrink envelope". A uniform −1 bit fails 75% of shots
     (λ_walk 10 → 6,769), so "the schedule is a cliff, not a dial; depth is
     the only smooth lever". See
     [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
5. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 400013729 → 950027083.
6. **`memory/11-lambda-walk-and-local-gpu-search.md`** is updated with the new
   score, the λ figures above, and a corrected row of the T-per-λ table:
   `ROUNDS_MUL` 696 → 700 is +1,752 Toffoli for −2.0 λ, about 880 T/λ.

## Why it is still correct, and what it risks

Depth is a truncation. An input whose walk needs more than 698 rounds (divide)
or 700 (multiply) to reach the (±1, ±1) fixed point ends with a wrong result
and dirty walk registers. That is a **classical** failure, and it usually
also shows up as phase and ancilla garbage. The arithmetic itself is
unchanged.

The author's model says both λ terms rise (λ_walk 7.46 → 8.79, residual
3.5 → 4.2). The nonce was found with the author's two-stage local search: an
exact classical model of the walk on the laptop GPU, then the full simulator.
The shipped nonce `950027083` draws a clean set: 9,024 of 9,024 shots, with
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Removing walk iterations from both traversals is iteration/threshold tuning.
The `sched_bias` type change is dormant.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout b5796ce -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol b5796ce 7ca0559 -- src/point_add` is
   32 lines in 3 files, including the notes file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 7ca0559 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set (in particular not `SUB4_PP_ROUNDS`,
   `SUB4_PP_ROUNDS_MUL` or `SUB4_PP_SCHED_BIAS`). Expect:
   - 1278 qubits
   - 921,558 average Toffoli (rounded)
   - score 1,177,751,124
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `950027083` and an identical op
stream. Any other change needs a new nonce hunt.

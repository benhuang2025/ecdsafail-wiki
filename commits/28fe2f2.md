## Summary

The square step computes `out −= λ² mod p`. The base built the full 512-bit
integer `λ²` with a 256-bit symmetric schoolbook square, reduced it into
`out`, and unbuilt it. This commit splits `λ = hi·2^128 + lo` and uses one
level of Karatsuba: `λ² = A + (C − A − B)·2^128 + B·2^256` with `A = lo²`,
`B = hi²` and `C = (lo + hi)²`. Each half-square is built, folded into `out`
modulo p, and unbuilt before the next is built, so only one half-product is
live at a time.

Three squares of about 128 bits cost about 3/4 of one 256-bit square, both in
cross-product ANDs and in row additions. The recombination is more expensive
than the old single reduce: it needs 24 full-width modular adds/subs and four
`f`-fold doubling ramps, instead of six modular adds/subs and 52 gated fold
windows. The net saving
is 19,229 average Toffoli, the largest single drop of the day. Qubits stay at
1164 because the square is not the peak phase. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All circuit changes are in `src/point_add/trailmix_ludicrous/square.rs` and
`arith.rs`, the square used by the trailmix shell
(`ec_add.rs` calls `mod_square_sub_pm_secp256k1_symmetric(y2, x2)`; see
[trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md)).

**Background: the base square.** `symmetric_square_into_prod(x, prod)` builds
`prod = x²` row by row. Row `i` holds the diagonal bit `x_i` (a CX) and the
`n − 1 − i` cross ANDs `x_i·x_j`, `j > i` (one CCX each). It is added into
`prod[2i..]` with `hybrid_add_adaptive`, and the ANDs are then cleared with
`clear_and` (`hmr` plus a conditional CZ, no Toffoli). The reverse,
`symmetric_square_into_prod_reverse`, rebuilds each row and subtracts it. Both
cost about `n²/2` CCX for the ANDs plus row adds of total width about `n²/2`,
so the work grows as `n²`. In the base `n = 256`, and the reduce was
`mod_sub(lo)` plus the five NAF terms of `f·hi` from [`4ea8b74`](4ea8b74.md).
See [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).

**The change: `mod_square_sub_pm_secp256k1_symmetric` is rewritten as**

1. `sum = build_sum_hi_lo(λ)`: a 129-bit register `lo + hi`, made by
   CX-copying `lo` and an uncontrolled `cuccaro_carry` of `hi` with the
   carry-out in `sum[128]`.
2. `C = sum²` (129-bit square, 258-bit product).
   `apply_shifted_128(C, out, Sub)`, then unbuild `C`.
3. `A = lo²` (128-bit square, 256 bits). `apply_unshifted_value(A, out, Sub)`,
   then `apply_shifted_128(A, out, Add)`, then unbuild `A`.
4. `B = hi²` (128-bit square, 256 bits). `apply_shifted_128(B, out, Add)`, then
   `apply_f_times_value(B, out, Sub)` for the `B·2^256 ≡ f·B` term, then
   unbuild `B`.
5. `unbuild_sum_hi_lo(λ, sum)`: subtract `hi` again (X-sandwiched Cuccaro over
   129 bits with a zero pad), un-copy `lo`, free `sum`.

The signs give `out −= A + (C − A − B)·2^128 + f·B`, which is `λ² mod p`.

**New helpers in `square.rs`:**

- `apply_full_width(operand, out, op)`: a 256-bit modular add
  (`mod_add_lowpeak`) or subtract (`mod_sub`).
- `apply_unshifted_value`: zero-pads a value to 256 bits and calls
  `apply_full_width`.
- `apply_shifted_128(value, out, op)`: adds `value·2^128 mod p`. The low 128
  bits of `value` go in as a 256-bit operand of 128 low zero pads, the bits and
  high zero pads. The bits above 128, `value[128..]`, are worth
  `value[128..]·2^256 ≡ f·value[128..]` and go to `apply_f_times_value`.
- `apply_f_times_value(value, out, op)`: copies the limb into a 257-bit
  register `ext` with zero pads and walks
  `F_NAF_TERMS = [(0,Sub),(4,Sub),(6,Add),(10,Sub),(32,Sub)]`. Before each
  term it calls `arith::mod_double(ext)` until `ext = limb·2^shift mod p`, then
  applies `ext` to `out` full width, with the sign flipped for an add. At the
  end it runs 32 `mod_double_reverse` to restore `ext`. This is the old
  modular-doubling ramp: 64 fold windows of 53 Toffoli, about 3,400 per call
  (see [modular-fold](../concepts/modular-fold.md)). It is called four times
  (for `C[128..]`, `A[128..]`, `B[128..]` and `B`).
- `alloc_zeroes`, `free_zeroes`, `flipped`.

**New primitive in `arith.rs`:** `mod_add_lowpeak(x, y)`. It is `mod_add`
with the register add done by the single-ancilla uncontrolled `cuccaro_carry`
(about 2 Toffoli per bit) instead of the vented `hybrid_add_plain` (about 1 per
bit, but it needs a full set of clean carry wires). The fold window uses the
headroom-adaptive `g = None`. The comment calls it the low-peak modular add for
off-peak recombination: it keeps the square's live set small.

**Why it is cheaper.** Each 128-bit square costs about a quarter of a 256-bit
one, so the three squares save about a quarter of the build and unbuild work:
roughly 16,000 fewer cross-product CCX and a similar cut in row-add width. The
recombination costs more. There are four `apply_f_times_value` calls, each a
64-window doubling ramp (about 3,400 Toffoli) plus five full-width modular
adds/subs, and four more direct full-width adds/subs: 24 modular adds/subs of
roughly 550–600 Toffoli each. The base needed `mod_sub(lo)`, five shifted NAF
terms and 52 gated windows. The measured net is −19,229. Later commits cut the ramp cost:
[`e25c7d8`](e25c7d8.md) and [`3df690f`](3df690f.md).

The old helpers `apply_shifted_hi_term`, `add_f_window_shifted` and
`sub_f_window_shifted` stay in the file but are no longer called.

**Peak.** With only one half-product live (at most 258 + 129 bits instead of
512), the square stays off the global peak, and qubits are unchanged at 1164.

**Tail nonce.** `src/point_add/mod.rs`: the `DIALOG_TAIL_NONCE` default goes to
800457469 in four places. The live one is in `build()` (600002572 → 800457469),
which calls `trailmix_ludicrous::build_trailmix_ludicrous_ops()` directly. The
other three are in `configure_ecdsafail_submission_route()`, which only the
older dialog route calls through `build_builder()`. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Why it is still correct, and what it risks

- **The identity is exact.** `λ² = A + (C − A − B)·2^128 + B·2^256` holds as
  integers, and `2^256 ≡ f (mod p)`. `sum = lo + hi` is exact (129 bits, carry
  kept), and the three integer squares are exact.
- **Probabilistic parts.** Every modular add/sub and every doubling uses the
  windowed `+f` fold over `LSBS = 54` bits, which drops a carry with
  probability about `2^-21` per firing window, and a 21-bit truncated compare
  to clear its overflow flag. The new square has more of these operations than
  the base (four doubling ramps, 256 windows, instead of 52 gated windows; 24
  modular adds/subs instead of six), so its failure set is somewhat larger. Intermediate values of `out`
  can pass through any residue, which is fine for modular arithmetic.
- **Which channel catches it.** A dropped carry gives a wrong `x` coordinate,
  a classical failure. A wrong truncated compare leaves a phase error. A
  non-zero zero-pad at `free_zeroes` would show as an ancilla failure.
- The shipped nonce 800457469 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures (avg executed Toffoli
  1,391,013.462 per the author's `nonce_hunter` confirm).

## Classification rationale

The square algorithm is replaced: a 256-bit schoolbook square becomes a
one-level Karatsuba over three 128-bit squares. That is a multiplier/squarer
swap. Nothing else changes except the nonce.

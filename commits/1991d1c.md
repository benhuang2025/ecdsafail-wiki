## Summary

This is the author's next width-envelope retune, after [1eae277](1eae277.md)
and [7c82c3c](7c82c3c.md). The dialog-GCD width `256 − slope·step + margin`
gets a slope of 1.004 bits per step, up from 0.990, and a margin of 9, down
from 10. Both make the envelope narrower. The slope change adds up to about
3.6 bits by the last step, so the late steps lose the most: the last step goes
from 12 bits to 6.

Each step-bit costs 4 Toffoli in the K=2 walk, plus capped comparator bits.
The saving is 12,608 Toffoli, exactly what the width formula predicts. Qubits
are unchanged. A new tail nonce was found.

## What changed and why it saves Toffoli

`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:

- `DIALOG_GCD_WIDTH_MARGIN`: 10 → 9.
- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 990 → 1004.
- `DIALOG_TAIL_NONCE`: 16096474301152 → 86945645753965.

`dialog_gcd_tobitvector_active_width(step)` returns
`256 − slope·step + margin`, rounded up to an even number and clamped to
[1, 256]. The width bounds four loops in each walk step, each about 1 Toffoli
per bit: the branch `cswap`, the gated load, the subtract or add body, and the
K=2 conditional-shift cascade. It also caps the branch comparator at
`min(74, active_width)`. See [01260e8](01260e8.md).

Replaying the formula over the 259 steps:

| | summed width per walk | summed comparator width | steps clamped at 256 | width at step 258 |
| --- | --- | --- | --- | --- |
| base (10, 0.990) | 36,016 | 17,176 | 13 | 12 |
| this commit (9, 1.004) | 35,294 | 16,912 | 11 | 6 |

Per walk that is 4 × 722 + 264 = 3,152 Toffoli. The four walks give 12,608,
the measured drop. The runway transcript allocation falls from 464 to 456
bits. The peak is set by the apply chunked add, so it stays at 1390.

## Why it is still correct, and what it risks

A slope above 1 bit per step assumes that the K=2 walk, which strips one or
two zeros per step, shrinks the larger operand by more than a bit per step on
average. The last steps now work on only 6 to 8 bits. Any input that has not
almost converged by then loses live high bits. Its walk fails: a classical
mismatch, and ancilla garbage after the reverse walk.

The shipped nonce `86945645753965` draws a test set with 0 classical, 0 phase
and 0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

The submission note's first line again repeats the stale "margin 14 /
slope 986" text. Its validation line gives the real values, 9 and 1004.

## Classification rationale

A narrower per-step register width is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 7c82c3c -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 7c82c3c 1991d1c -- src/point_add` is
   6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1991d1c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because
   `set_default_env` only fills in unset variables. Expect:
   - 1390 qubits
   - 1,534,399 average Toffoli (rounded)
   - score 2,132,814,610
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=86945645753965` and an
identical op stream. Any other change needs a new nonce hunt.

## Summary

The binary GCD that does the division only works on the low `active_width(step)`
bits of its two registers. That width follows a straight line that falls with
the step number. This commit makes the line fall a little faster: 1.005 bits per
step instead of 1.004. Because the width is rounded up to an even number, the
change only bites on 24 late steps (202 to 248), where the window becomes 2 bits
narrower. Each bit removed there saves about 20 executed Toffoli across the
circuit, so the total is 960 Toffoli. Qubits are unchanged. The tail nonce was
re-hunted.

The frontier at the time, `4527ae1`, had cut the branch comparator from 74 to 73
bits. The author started from it but put the comparator back to 74, so the tree
equals `5174a69` plus this slope change. The net gain over `4527ae1` is only
188 Toffoli.

## What changed and why it saves Toffoli

**Background: the dialog-GCD route.** In early June the shipped circuit is
`emit_dialog_gcd_raw_pa` in `src/point_add/mod.rs`, a file of about 31,000
lines. It computes the slope dy/dx with `emit_dialog_gcd_raw_quotient`, and
later multiplies by c = ox − Rx with `emit_dialog_gcd_raw_ipmul`. Both calls run
the same reversible binary GCD on (u, v) = (p, factor) in three passes:

- a forward pass of `DIALOG_GCD_ACTIVE_ITERATIONS` steps that records branch bits;
- an *apply* pass that replays those bits on a second register pair;
- a reverse pass that runs the GCD backwards and erases the record.

One forward step (`emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle`)
does this:

```
b0        = v[0]                        # is v odd?
b0_and_b1 = b0 AND (u > v)              # truncated comparator on the top COMPARE_BITS of the window
cswap(u, v) if b0_and_b1                # afterwards v >= u whenever v is odd
v        -= b0 * u                      # controlled subtract (gated load + ripple); v is now even
v       >>= 1                           # free: a wire relabel
s2 = NOT v[0];  v >>= 1 if s2           # K=2: a second, conditional halving (cswap cascade)
```

Every line acts only on `u[..active_width(step)]` and `v[..active_width(step)]`.
The 9 branch bits of three steps are packed into 8 qubits of a compressed log
(`DIALOG_GCD_K2=1`). The reverse pass undoes each line in the opposite order,
and recomputes the comparator to erase `b0_and_b1`. [dialog-gcd-early](../concepts/dialog-gcd-early.md) covers this
route; [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) describes its
later descendant.

**The width envelope.** `dialog_gcd_tobitvector_active_width(step)` computes

```
ideal = 256 − step · DIALOG_GCD_WIDTH_SLOPE_X1000 / 1000 + DIALOG_GCD_WIDTH_MARGIN
width = clamp(2 · ceil(ideal / 2), 1, 256)
```

The margin is 9 in this tree.

**The change.** In `configure_ecdsafail_submission_route()`:

- `DIALOG_GCD_WIDTH_SLOPE_X1000`: 1004 → 1005.
  - With margin 9, the width differs only at the even steps 202, 204, …, 248,
    by 2 bits each (for example 64 → 62 at step 202, 18 → 16 at step 248). That
    is 48 bit-steps in all.
  - In each pass, one bit of window costs about 5 Toffoli: 1 in the comparator
    (at these steps the window is narrower than the 74-bit comparator cap, so the
    comparator covers all of it), 1 in the cswap, 2 in the controlled subtract or
    add, and 1 in the K=2 halving cascade.
  - There are four passes: forward and reverse, in each of the two GCD calls.
    That gives about 20 Toffoli per bit-step, and 48 × 20 = 960, which matches
    the measured saving exactly.
- `DIALOG_TAIL_NONCE`: 7046 → 258272621018023. The nonce drives a fixed-length
  tail of 48 `X;X` pairs on `tx[0]` or `tx[1]` at the end of `build_builder()`.
  It changes the Fiat–Shamir test set, not the circuit. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

The comment block above the knob still describes an older 707.5 → 708 step. It
was not updated.

## Why it is still correct, and what it risks

The envelope is an empirical bound on max(bitlen(u), bitlen(v)) plus a margin.
If an input's GCD registers are still wider than the window at some step, their
top bits are cut off. The GCD then goes wrong, the output is wrong, and the run
shows a classical failure, usually with ancilla garbage after it. A steeper slope
moves the window closer to the real bit length on late steps, so slightly more
rare inputs become hard and λ rises. On the near-identical `dda7bfd` tree,
10d9e measured that this same notch breaks 13 test inputs at the inherited
nonce (`memory/2026-06-05-kalfold23-island-3155.md`, added in `bc858e8`).

Everything else is exact. The shipped nonce `258272621018023` draws a clean set:
0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.

## Classification rationale

The only circuit change narrows the GCD registers' working width, which is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5174a69 -- src/point_add`.
   - The git parent is `4527ae1`, PhantasticUniverse's tree with
     `DIALOG_GCD_COMPARE_BITS` 73. Against it, the diff also sets the
     comparator back from 73 to 74. The author's note says this was deliberate,
     but it is a revert of `4527ae1`'s lever, not part of this change.
   - Against `5174a69`, `git diff --ignore-cr-at-eol 5174a69 98416e4 -- src/point_add`
     is 4 changed lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 98416e4 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   `set_default_env` only fills variables that are unset, so any override wins
   over the defaults in the patch. Expect:
   - 1390 qubits
   - 1,532,455 average Toffoli (rounded)
   - score 2,130,112,450
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `258272621018023` and an identical op
stream. Any other change needs a new nonce hunt.

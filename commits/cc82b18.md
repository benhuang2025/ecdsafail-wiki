## Summary

In the interleave plan of [`f3b2f1f`](f3b2f1f.md) and
[`e928607`](e928607.md), rounds below `r1 = 509` are batch-replayed at
round 509. `r1` could not be earlier for one reason. An interleaved walk round
runs its add with a full `width − 1` carry ladder while the coefficient
registers are live, and before round 509 the walk is too wide for that to fit
under 1278.

This commit adds an exact two-chunk walk add for those rounds. It keeps one
boundary carry between a low chunk and a high chunk, and repairs it by
comparing the *whole* low chunk. That compare is an identity, so the split
adds no approximation.

With the walk no longer binding, the batch checkpoint moves to `r1 = 298`.
There the tape is 211 wires shorter. The walk registers are wider, but they
cost less than the tape saves. The replay's chunk-ladder budget at the batch
rises from 87 to 130, so each of the ~298 batch rounds per traversal needs one
truncated boundary repair instead of two. The rounds that are now interleaved
need one to three. The net result is −2,821 Toffoli at the same 1278 qubits,
with fewer truncated repairs per shot.

## What changed and why it saves Toffoli

All edits are in `src/point_add/pingpong_div.rs`, apart from the nonce.

### 1. The walk budget (`WALK_PEAK`, `walk_low_chunk`)

- A thread-local `WALK_PEAK` holds a total width budget for walk rounds that
  run while `coefficient` is live. It is set to `plan.peak` by
  `set_walk_peak` and cleared by `clear_walk_peak`.
  - **Divide:** it is set right after `coefficient` is allocated, before the
    batch replay. It is cleared after `coefficient` is freed. It therefore
    covers the interleaved walk rounds and the tail walk rounds.
  - **Multiply:** it is set before the tail walk-back rounds and cleared after
    `coefficient` is freed. It therefore covers the tail and interleaved
    walk-back rounds.
- `walk_low_chunk(round, width)` computes
  `ladder = peak − ((round + 1) + 512 + 2·width)`.
  - It returns `None`, meaning the stock single-ladder add, if
    `ladder ≥ width − 1`, if `width < 12`, or if `SUB4_PP_NO_WALK_SPLIT` is
    set.
  - Otherwise it returns `low = max(width − ladder, 3)`, provided that
    `low + 2 ≤ width` and `2·low ≤ width`.
- `walk_round` and `walk_back_round` call the split add when
  `walk_low_chunk` returns `Some(low)`.

### 2. The exact split add (`signed_add_wrapping_sigma_split`)

This is a two-chunk form of the walk's sigma add. Like the stock form, it
supplies the first two carries linearly from `sign` and the operands' odd low
bits.

1. **Low chunk** (positions `0..low`). It builds the Gidney carries `c_lo`.
   It keeps `c_lo[low−1]` as the boundary. Every lower carry is uncomputed by
   `hmr` plus `cz_if`, and the wires are freed *before* the high chunk
   allocates its own.
2. **High chunk** (positions `low..n`). It builds `n − 1 − low` carries, with
   the boundary as carry-in. It writes the top bit and unwinds the same way.
3. **Boundary.** It measures the boundary out with `hmr` and repairs the phase
   with `cmp_lt_phase_conditioned(target[..low], source[..low])`. The walk
   add has no carry into the low chunk, so `sum_low < addend_low` *is* the
   boundary carry. The repair is exact, and the walk arithmetic is bit-for-bit
   the same as the single-ladder form.

- The live ladder is `max(low, n − low)` instead of `n − 1`. With
  `low = width − ladder`, the high chunk exactly fills the budget.
- The cost is the extra `low`-bit conditioned compare, about `low` emitted
  Toffoli per split add.
- By the code's formula, the split is used in walk rounds 298..~506 of each
  traversal, 205 adds in all, with `low` falling from 40 to 3. From about
  round 509 the full ladder fits again. That is why `r1 = 509` with the split
  enabled reproduces the old stream.

### 3. The plan: `SUB4_PP_R1` 509 → 298, `SUB4_PP_R2` 610 → 613

`SUB4_PP_PEAK` stays at 1278.

- **Batch** (rounds 0..297). By the code's formula, `value_width(298) = 169`.
  The ladder budget is `1278 − 298 − 512 − 2·169 = 130`. `chunk_layout`
  returns [128, 128], which needs 129, so the batch has **one** approximate
  boundary per add. At `r1 = 509` the budget was 87 and the layout was
  [86, 85, 85], with two.
- **Interleaved band** (rounds 298..613). By the same formula, 54 rounds get 1
  approximate boundary, 195 get 2 and 67 get 3. Before this commit, rounds
  below 509 all had 2 in the batch.
- **Tail** (rounds 614..699). The budget is unchanged, with 3 approximate
  boundaries per add.
- Recomputed from the code's formula, the approximate repairs per point add
  go from about 3,100 to about 2,400. The author's code comment gives
  3,100 → 2,405 and −2,848 executed Toffoli.
- The comment also says that `SUB4_PP_R1=509 SUB4_PP_R2=610` restores the
  previous op stream byte for byte, because at r1 = 509 no walk round is over
  budget.

### 4. Nonce

`src/point_add/mod.rs`: the tail nonce goes from 23188000022 to 45448000021.

**Why the trade pays.**
- Moving `r1` down by 211 rounds takes 211 tape wires off the batch moment. It
  puts back only `2·(169 − 85) = 168` walk wires, so the batch's ladder budget
  grows by 43.
- Each removed 23-bit truncated repair saves about 11 executed Toffoli. The
  split walk adds give back roughly `Σ low` emitted Toffoli over 205 rounds
  per traversal. The repair savings are larger.

## Why it is still correct, and what it risks

- **Exact parts.**
  - The split walk add is an exact rewrite of the single-ladder add. Its
    boundary repair compares the whole low chunk, which has no carry-in.
  - Its in-chunk carries are uncomputed by `hmr` plus `cz_if`. See
    [measurement-uncompute](../concepts/measurement-uncompute.md).
  - The walk values, and so convergence, are unchanged.
  - The new schedule only reorders replay rounds, as in
    [`f3b2f1f`](f3b2f1f.md).
- **Probabilistic parts.** There are no new ones. The replay still uses the
  23-bit truncated boundary compare, but fewer times per shot (about 700 fewer
  by the author's count), so λ should go down. See
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- **What to watch.** If `walk_low_chunk` returns `None` because `low` would
  exceed half the width, the round falls back to the full ladder and can
  exceed the target peak. At the defaults this does not happen.
- The shipped nonce `45448000021` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit reshapes which registers coexist at the batch moment, a shorter
tape against wider walk registers. It uses the freed space as carry-ladder
budget, and the exact split add is what makes the new checkpoint fit. That is
a ladder and lifetime budget move, ancilla-lifetime / venting, like the rest of
the interleave-plan chain. The Toffoli saving comes from *fewer* truncated
repairs, not narrower ones, so it is not comparator/width truncation.

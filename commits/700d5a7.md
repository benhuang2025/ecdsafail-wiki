## Summary

The Kaliski walk's Toffoli-bearing loops are sized by an empirical
bit-length envelope. The envelope is full width for the first `K0`
iterations, then shrinks by 2 bits every 3 iterations. This commit lowers
`K0` from 21 to 20, so the shrink starts one iteration earlier. From
iteration 22 on, about two out of every three iterations become one bit
narrower in every loop that uses the envelope. That saves 4,400 average
Toffoli at the same 2002 qubits. The reroll count changes from 34 to 13.

## What changed and why it saves Toffoli

- **`src/point_add/kaliski_state.rs`, `kal_wtrunc_k0()`: the default goes from 21 to 20.**
  - `kal_wtrunc_width(k, n)` returns `n` for `k < K0`, else
    `max(n − ⌊(k − K0)·2/3⌋, 3) + margin`, capped at `n`. The margin is 0 in
    this tree. The envelope comes from a fit to the largest
    `max(bitlen(u), bitlen(v_w))` seen at each iteration over 80,000 random
    inputs (source comment).
  - It caps the widths of the step-0 zero-test OR chain, the step-2
    `u > v_w` comparator, the step-3 and step-9 `(u, v_w)` cswaps, and the
    step-4 load, subtract and add loops. Each of these costs about one Toffoli
    per bit.
  - With `K0 = 20`, `⌊(k − 20)·2/3⌋` is one more than `⌊(k − 21)·2/3⌋` for
    two out of every three `k`, so those iterations lose one bit in each of
    those loops. This applies to all four Kaliski walks (forward and backward
    for `pair1` and `pair2`). The measured saving is 4,400 average Toffoli.
  - The same envelope also sets the dialog-fold anchors and the step-6 shift
    width. Here the peak did not change.
- **`src/point_add/mod.rs`, `build()`: the default `KAL_REROLL` goes from 34 to 13.**
  The count of identity `X(tx[0]); X(tx[0])` pairs selects the 9,024-shot
  test draw. The base's comments record that `K0 = 20` had no clean draw for
  `rr = 0..80` on the earlier stream. After the `R_SMALL = 327` change in
  [`801b73e`](801b73e.md), the author's screen of `rr = 0..127` found 13
  clean.

## Why it is still correct, and what it risks

- The envelope is a statistical fit, not a bound. An input whose `u` or `v_w`
  is still wider than the envelope at some iteration loses its top bits in the
  comparator or the adds, and the walk takes a wrong branch. That would show
  as a classical mismatch, and usually also as phase or ancilla garbage.
- Moving K0 earlier makes the envelope tighter everywhere, so more inputs fail
  and clean draws become rarer. The earlier stream had none in 81 tries.
- On the `rr = 13` draw, the full benchmark gives 0 classical, 0 phase and 0
  ancilla failures over 9,024 shots. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change narrows the comparator, swap and adder widths by tightening an
empirical width envelope. That is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 801b73e -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 801b73e 700d5a7 -- src/point_add` is 23 lines
   in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 700d5a7 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or `AFFINE_*` environment variables set. Expect:
   - 2002 qubits
   - 2,571,903 average Toffoli (rounded)
   - score 5,148,949,806
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `KAL_REROLL = 13` and an identical op stream.
Any other change needs a new reroll search.

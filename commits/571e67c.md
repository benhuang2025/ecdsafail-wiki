## Summary

At 1309 qubits, two kinds of phase shared the peak. One was the dialog-GCD
walk steps (`tobitvector`), whose controlled add/sub body needs a carry wire
per bit. The other was the "round84" x-tail square, `X ← X − λ²`, which
reduces the 512-bit square with constant adds that need a clean 257-wire
register for the constant. This commit lowers both by 24 qubits:

- **GCD body.** The author's own 4-stage self-hosting
  ([`639f12c`](639f12c.md)) is extended to 28 stages. The top 28 carry stages
  of the walk's controlled add/sub run as in-place Cuccaro, which needs no
  carry wire but costs one more Toffoli per stage.
- **Square.** The four constant corrections of the shift-by-22 step, and the
  final modular subtract, now use Gidney's dirty-ancilla ("vented") constant
  adder. It needs only 2 clean wires and borrows the `acc` register as dirty
  scratch.

This costs about +23,400 Toffoli in the GCD body and a few thousand in the
square. The author got back about 4,700 by narrowing two comparators: the
branch comparator from 50 to 47 bits and the apply clean comparator from 23
to 19. The net is +22,712 Toffoli. That is +1.5%, against −1.8% in qubits,
so the score drops by 7.2 M.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`.

1. **`DIALOG_GCD_SELECTED_BODY_GATE_SUFFIX_CARRIES`: 4 → 28.**
   - This is the mechanism of [`639f12c`](639f12c.md).
     `cuccaro_{add,sub}_fast_borrowed_carries_no_cin` keep borrowed,
     measured-erased carry wires for stages `1..n−1−suffix`. The top
     `suffix` stages use `maj`/`uma` (subtract: `inv_uma`/`inv_maj`) in
     place on the gated source wires.
   - `dialog_gcd_selected_body_nocin_scratch_need(len) = len + (len − 1 − suffix)`
     sizes the walk step's composite scratch, so 24 more stages means
     24 fewer scratch wires on every step whose body is wide enough.
   - Each self-hosted stage costs 2 Toffoli instead of 1. That is +24
     Toffoli per wide body, fewer on the narrow late steps where the suffix
     is clamped to `n − 2`. Replaying the body widths over 258 steps × 4
     walks gives 5,856 extra stages per walk, about +23,400.
2. **Vented constants in the x-tail square** (`squaring_sub_from_acc_schoolbook_lowq_shift22`).
   - This routine computes `acc −= x² mod p`. It builds the 512-bit schoolbook
     square in `tmp_ext`. It subtracts the low half, then folds the high half
     in as `hi·c` with `c = 2^256 − p = 2^32 + 977`. That is done as a ladder
     of modular doublings and adds/subtracts of `hi`, ending with a
     modular left shift of `hi` by 22 bits and a last `acc −= hi`.
   - New `ROUND84_XTAIL_SCHOOLBOOK_SHIFT_DIRTY=1`: the shift calls the
     existing `mod_shift_left_by_k_lowq_with_dirty` /
     `mod_shift_right_by_k_lowq_with_dirty`, passing `acc` as the dirty
     source, instead of the clean-only versions.
   - New `ROUND84_XTAIL_SCHOOLBOOK_SHIFT_CONST_VENT=1`: inside those two
     functions, the four constant corrections (`add_nbit_const`,
     `csub_nbit_const`, `cadd_nbit_const`, `sub_nbit_const` on the 257-bit
     `v_ext`) are replaced by `venting::iadd_dirty_2clean_classical`,
     `cisub_dirty_2clean_classical` and `ciadd_dirty_2clean_classical`. The
     uncontrolled subtract is written as `~(~x + c)`. The old versions load
     `c` into a freshly allocated 257-wire register and do a quantum-quantum
     add. The vented versions are Gidney's adder with 2 clean and n − 2 dirty
     wires. They borrow 255 wires of `acc`, restore them, and cost about 3n
     CCX (see [venting-and-wire-loans](../concepts/venting-and-wire-loans.md)
     and [adders-and-carries](../concepts/adders-and-carries.md)).
   - New `ROUND84_XTAIL_SCHOOLBOOK_FINAL_SUB=vent`: the final `acc −= hi` uses
     the existing `mod_sub_qq_vent`. That routine does its `±c` correction
     with `ciadd_dirty_2clean_classical`, borrowing `hi` as dirty scratch.
     The other allowed values are `fast`, and the default `mod_sub_qq`.
3. **Comparator retune** (λ budget and Toffoli):
   - `DIALOG_GCD_COMPARE_BITS` 50 → 47. Replaying `min(cap, active_width)`
     at slope 1.014 over 258 steps gives 647 bits per walk × 4 walks, about
     −2,600.
   - `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` 23 → 19. That is 4 bits × 516 apply
     erases (258 steps × 2 divisions) = −2,064.
4. **`DIALOG_TAIL_NONCE`**: 264497 → 393525, found with the author's GPU K=2
   island scan.

**Why the peak falls by exactly 24.** The new comment says the change "moves
the GCD tobitvector and round84 binders down to the raw-PA 1285q floor". So
both phase families were co-binders at 1309, and both had to come down
together. A third phase family sits at 1285, so 28 is the smallest suffix
that reaches it. See
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

**Toffoli bookkeeping.** About +23,400 (suffix) − 2,600 (compare) − 2,064
(apply clean) ≈ +18,800. The remaining +3,900 or so of the measured +22,712 is
the vented adders in the square, which are about 3n CCX each, where the clean
adders were cheaper. This split is an estimate.

## Why it is still correct, and what it risks

- **Exact parts.** The self-hosted stages and the vented adders are exact.
  In-place Cuccaro gives the same sum as the measured-carry adder. Gidney's
  dirty-wire adder restores the borrowed wires and leaves no phase on any
  input. Its doc comment in `venting.rs` still carries an old "STATUS:
  correctness is INCOMPLETE ... LEAKS PHASE" warning about a version that did
  the carry-xor separately. The code now merges the carry-xor
  (`add_vented_2clean_classical_cxt`), and this submission's 0-phase result
  suggests the warning is stale. A phase leak there would show up as phase
  garbage.
- **Probabilistic parts.** The two comparators are narrower.
  - The branch comparator at 47 bits fails on a top-47-bit tie between `u`
    and `v`, which gives a classical mismatch.
  - The apply clean compare at 19 bits fails on a top-19-bit tie between the
    sum and the addend, about 2^−19 per call. That leaves a dirty flag, which
    shows up as ancilla or phase garbage.
- The shipped nonce `393525` draws a clean test set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit is about peak qubits, and it gets them by borrowing wires: dirty
`acc` lanes for the constant adders, and the gated source lanes for the top
carries. That is the ancilla-lifetime / venting type in Register and Scratch
Allocation. The comparator retune is a side trade to pay part of the extra
Toffoli back.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 639f12c -- src/point_add`.
   - Do not start from the git parent `7f656bd`. That tree has odinfree's
     `cee4044`/`1121d80` re-balance and zuiris's top-of-route overrides
     (compare 46, apply clean 18, double window 22, slope 1.008).
   - Diffing against the parent would wrongly show this commit deleting
     those overrides and putting back the chunk cut 190, 258 steps, slope
     1.014 and double window 21.
   - Against `639f12c`, `git diff --ignore-cr-at-eol 639f12c 571e67c -- src/point_add`
     is 131 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 571e67c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*`, `DIALOG_*` or `ROUND84_*` environment variables set. Expect:
   - 1285 qubits
   - 1,539,655 average Toffoli (rounded)
   - score 1,978,456,675
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=393525` and an identical
op stream. Any other change needs a new nonce hunt.

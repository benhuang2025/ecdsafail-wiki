## Summary

`mod_add_solinas_ext_product` reduces the 512-bit square `λ²` into the
freshly allocated, all-zero register `breg`. Its first step adds the low limb
into `breg` with a full 257-bit modular add. This commit replaces that step
with the from-zero variant, which CX-copies the limb and saves the 256-Toffoli
ripple adder. It also switches that step and the next three positive fold
adds from `mod_add_qq_fast` to the low-scratch versions of
[`bc9728a`](bc9728a.md). Those add `c = 2^32 + 977` without a loaded constant
register, and each costs 24 Toffoli more on this line. Net: −256 + 4 × 24 =
−160 Toffoli. The peak is not in this phase, so qubits are unchanged.

The same edit is applied to the low-qubit Karatsuba multiply-add, but that
routine does not run in the default circuit.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`.

- **`mod_add_solinas_ext_product(acc, tmp_ext)`**, run once per point addition
  from `square_tx_and_combined_ty_l2minus3qx` (phase
  `affine_combined_breg_red`) with `acc = breg` just allocated:
  - `mod_add_qq_fast(acc, lo)` → `mod_add_qq_fast_from_zero_lowscratch(acc, lo)`.
    Because `acc = 0`, the operand add `acc += lo` is done as 256 CX instead of
    `add_nbit_qq_fast`, a 257-bit measured Cuccaro add of 256 CCX.
  - `mod_add_qq_fast(acc, hi)`, and the adds of `hi·2^4` and `hi·2^10` →
    `mod_add_qq_fast_lowscratch`.
  - The `−hi·2^6` subtract (`mod_sub_qq_fast`) and the `hi·2^32` add
    (`mod_add_qq`) are unchanged.
- **`mod_mul_add_into_acc_karatsuba_lowq_with_tmp_ext`**: its `lo`, `hi`,
  `hi·2^4` and `hi·2^10` adds also become `mod_add_qq_fast_lowscratch`. This
  routine is only reached through env-gated paths in this tree, so the edit
  does not change the default op count.
- Two `///` comments are added inside function bodies. They have no effect.

**Why each low-scratch call costs 24 more here.** The low-scratch adds do
`+c` and the conditional `−c` with the direct constant adders. In this line
the unconditional `+c` still goes through `cadd_nbit_const_direct_fast` with
a `|1⟩` control, because Gajesh2007's known-1 specialisation
[`8631b04`](8631b04.md) was not merged. Each of `c`'s six 1-bits that have a
carry-in then costs three CCX instead of one, in both the add and the subtract:
2 × 2 × 6 = 24. See [adders-and-carries](../concepts/adders-and-carries.md).

**Qubits.** The low-scratch adds avoid holding a 257-qubit loaded constant
during each call. The `λ²` reduction does not set the 2708 peak, though, so
the peak is unchanged. See
[peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

## Why it is still correct, and what it risks

The change is exact on every input.
- The from-zero variant relies on `breg = 0` on entry. The only caller
  allocates `breg` immediately before the call.
- The low-scratch adds compute the same modular sum as `mod_add_qq_fast`, and
  their measured carry erase is exact. A wrong fix would show up as a phase
  failure.

There is no tail nonce in this era. The 9,024 test inputs are a SHAKE256 hash
of the op stream, so the draw changed. The base's probabilistic Kaliski
settings passed on the new draw with 0 classical, 0 phase and 0 ancilla
failures. The submission note reads only "v6 AdaEvolve: 160 fewer Toffoli".

## Classification rationale

The census files this as Register and Scratch Allocation → ancilla-lifetime /
venting, probably after the code comments about scratch. The scratch removed
here does not lower the peak, and the low-scratch swaps cost Toffoli. The
whole saving comes from a known-zero accumulator turning an adder into a CX
copy. That is Constant Propagation and Classical Specialization →
host-derived / classical specialization. [`81ff75b`](81ff75b.md) made the same
from-zero edit on a sibling line.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 9bcc27d -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 9bcc27d 74a1a8b -- src/point_add` is
   28 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 74a1a8b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`,
   `AFFINE_*`, `DUMMY_TOFFOLIS` or other environment overrides set. Expect:
   - 2708 qubits
   - 3,546,494 average Toffoli (rounded)
   - score 9,603,905,752
   - 0 classical, 0 phase and 0 ancilla failures

There is no tail nonce in this era. The 9,024 test inputs are a hash of the
op stream, so the score only reproduces with an identical op stream.

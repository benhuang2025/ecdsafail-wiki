## Summary

This commit changes four constants and the tail nonce. Three of the changes
make truncated arithmetic narrower and save Toffoli. The fourth goes the other
way: it adds four rounds back to the multiply traversal. That costs a little
Toffoli but lowers Lambda, the expected number of failing test shots, which
makes a clean nonce about 10 times easier to find. The net saving is 8,215
average Toffoli at the same 1278 qubits.

The author's submission note measured each knob's Toffoli saving per unit of
Lambda. Lambda is the scarce resource, so the note spends it on the knobs with
the best ratio. Many earlier commits had been cutting multiply depth instead.

## What changed and why it saves Toffoli

1. **`SLOPE_2`: 33 → 34** in `value_width()`, `src/point_add/pingpong_div.rs`.
   - `value_width(round)` is the width of the ping-pong walk registers in a
     given round, in bits. It is a piecewise-linear schedule:
     `width = start − SLOPE × rounds_elapsed / 100`, where `start = 256 + MARGIN`.
   - `SLOPE_2` sets how fast the width shrinks between `BREAK_1 = 40` and
     `BREAK_2 = 304`. At 34, the registers are 2 bits narrower from round 304 on
     (⌊34·264/100⌋ = 89 against 87), and up to 2 bits narrower inside the band.
   - Every walk, walk-back and replay add in those rounds gets cheaper. The
     note says this is the largest piece, about 6,700 executed Toffoli.
   - The risk is that a slow-converging input still needs those bits and the
     register overflows. See [pingpong-division](../concepts/pingpong-division.md)
     and [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
2. **`GUARD`: 44 → 24** in `src/point_add/trailmix_ludicrous/square/product_register.rs`.
   - This is the truncation margin of `window_add` in the product-register
     squarer. Its failure rate is about 2^-g per operation, so 44 bits was far
     more margin than needed.
   - The author's sub-agent swept it against the 64-shot self-test: it passes
     at 10 and fails at 8. 24 keeps a large margin and saves about 700 emitted
     Toffoli. See [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).
3. **`SUB4_PP_REPLAY_CHUNK_COMPARE`: 23 → 21** in `replay_chunk_compare()`,
   `pingpong_div.rs`. This is the truncated compare that erases the carry at
   each replay chunk boundary (the chunk widths come from the ladder budget
   via `chunk_layout`; the 96-bit `SUB4_PP_REPLAY_CHUNK` is only the
   no-budget fallback). Two fewer bits per boundary means fewer Toffoli.
4. **`SUB4_PP_ROUNDS_MUL`: `rounds() − 6` → `rounds() − 2`** in `rounds_for()`,
   `pingpong_div.rs`.
   - This sets the depth of the multiply traversal only. The base had cut it
     to 6 rounds below the divide depth. This commit puts 4 rounds back, which
     costs about 1,470 Toffoli.
   - The note measured, with the other three constants fixed, that `−6` gives
     Lambda 11.30 (about 1 clean nonce per 115,600 draws) and `−2` gives Lambda
     8.94 (about 1 per 10,900 draws).
5. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 810000185473 → 800188000096. The nonce was found
   on about draw 19,000 with 200 workers.

## Why it is still correct, and what it risks

All three tightenings are probabilistic. Each one raises the chance that a
rare input overflows a register or gets a wrong comparison. Together,
`GUARD` and `SLOPE_2` add about 0.46 to Lambda for about 9.3 M of score.
Validation passes because the shipped nonce draws a test set with no failing
input: 9,024 of 9,024 shots pass, with 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

When you tune these knobs, check both failure channels. The note found that
classical failures stayed flat as the chunk compare went from 23 down to 1,
which made it look free. Phase failures, however, saturated at 141 of 141
batches below about 12, so no clean nonce exists there. The usable range is 20
or more.

## Classification rationale

The three changes that save Toffoli all narrow operations to fewer bits: the
walk width schedule, the squarer guard window and the chunk compare window.
That is comparator/width truncation. The `ROUNDS_MUL` change goes the other
way. It is a choice about how to spend Lambda, not a saving.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout d1bb787 -- src/point_add`.
   - Do not start from the git parent `0440b62`. That is jackylee0424's
     1272-qubit tree, and this commit was not built on it.
   - Against the parent, the diff is 417 lines in 4 files. It deletes that
     line's segmented fold and dead-low adders from `arith/const_arith.rs` and
     `pingpong_div.rs`, and restores this author's 1278-qubit replay plan.
   - Against `d1bb787`, `git diff --ignore-cr-at-eol d1bb787 8d7051b -- src/point_add`
     is 10 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8d7051b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1278 qubits
   - 930,729 average Toffoli (930,728.593 before rounding)
   - score 1,189,471,662
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `800188000096` and an identical op
stream. Any other change needs a new nonce hunt.

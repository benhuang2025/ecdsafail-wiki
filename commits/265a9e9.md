## Summary

The ping-pong walk stores one sign bit per round on a tape. Earlier commits
already free the round-0 and round-1 tape wires early and rebuild them later
(see [`5526766`](5526766.md)). This commit adds `PP_N_HOLE2`, which does the
same for the round-2 sign in both the divide and the multiply traversal. The
rebuild uses only X and CX gates. It works because the walk's low bits obey a
second linear relation that no earlier commit used: `b2(z_k) XOR b1(z_{k+1})`
has the same value at every round `k`, and that value is round 1's sign.

With one fewer tape wire live where the peak sits, the cap
`PP_WALK_MAX_QUBITS` drops from 1251 to 1250. The carry ladders size themselves
to that cap, so the peak follows it down. The same package also re-tunes the
width schedule and the `I41_ROUNDS` list. It also adds `PP_N_BADJ`, which
shifts the seeded chunk-boundary compare widths by ±1 bit on chosen round
bands. The whole package also saves 566 average Toffoli. Most of the score gain
is the qubit, though: at this size one qubit is worth about 891k of score.

## What changed and why it saves qubits and Toffoli

### 1. `PP_N_HOLE2`: free `tape[2]` and rebuild it with Cliffords (`src/point_add/pingpong.rs`)

**The invariant.** Write the walk values as `z_0 = p` and `z_1 = w` (round 0's
output). For round `r ≥ 1`:

```
sigma_r = b1(z_{r-1}) XOR b1(z_r)              # the tape bit of round r
z_{r+1} = (z_{r-1} + (-1)^sigma_r * z_r) / 2
```

Here `b1` and `b2` are bits 1 and 2 of a value. Reading the step backwards
mod 8, `z_{r-1} = 2 z_{r+1} ∓ z_r`, gives two identities at every round:

```
b1(z_{r-1}) = sigma_r XOR b1(z_r)                       # the definition
b2(z_{r-1}) = b1(z_r) XOR b2(z_r) XOR b1(z_{r+1})       # the new one
```

The first one telescopes to `sigma_1 XOR … XOR sigma_k = 1 XOR b1(z_k)`. Older
code already used it (`recompute_bchain_sign`, and round 1's `NOT v[1]`). The
second one says `b2(z_k) XOR b1(z_{k+1})` does not depend on `k`. At `k = 0` it
is `b2(p) XOR b1(z_1) = sigma_1`. So at any walk state,
`sigma_1 = b2(z_k) XOR b1(z_{k+1})`, and the tape is not needed to get it. With
two linear relations, two tape wires can be rebuilt for free instead of one.
The doc comment on `n_hole2()` says this, and says that a search found no
third relation. I checked the second identity on 100,000 random pairs of odd
values, and it held every time.

**Divide traversal** (`divide_traversal`):
- In the head batch, right after round 2's own replay, the code runs
  `sign2_fix = Some(free_sign_bit(circ, tape[2]))`. `free_sign_bit` runs `hmr`
  (measure in the X basis and reset) and frees the wire. The code asserts
  that round 2 has no quarter-step record and is not a C2-shed round.
- At walk-back round 2, `walk_back_round_phase` has a new arm for
  `round == 2 && n_hole2()`. At that point the registers hold the
  post-round-2 pair: `source = z_2` and `target = z_3`. Both are stored
  without bit 0, so index 0 is bit 1.
  - The arm builds `s = 1 XOR source[0] XOR source[1] XOR target[0]`, which is
    `1 XOR b1(z_2) XOR b2(z_2) XOR b1(z_3) = sigma_2`. That takes one X and
    three CX.
  - Then `z_if(s, c)` cancels the phase that the measurement left.

**Multiply traversal** (`multiply_traversal`):
- After the full walk, `tape[0]` and `tape[1]` were already freed (`a0_fix`,
  `bchain_fix`). Now `hole2_fix` frees `tape[2]` too. It requires that
  `bchain_fix` exists, that `2 < r1`, and that round 2 has no quarter-step
  record.
- The head replay runs from `r1 − 1` down to 0. During it, the walk registers
  sit at the pre-round-`r1` state `(z_{r1-1}, z_{r1})`, which the new
  `round_pair` helper returns.
  - At `r == 2`, the new `recompute_hole2_sign` builds
    `sigma_2 = 1 XOR b1(z_{r1-1}) XOR sigma_1 XOR parity(tape[3..r1])`.
    It takes `sigma_1` from the new invariant, `b2(z_{r1-1}) XOR b1(z_{r1})`,
    so it never reads the freed `tape[1]`. The gates are one X, CX from
    `t[1]`, `t[2]` and `src[1]`, one CX per live tape wire in `3..r1`, and
    then `z_if`.
  - At `r == 1`, `tape[1]` is rebuilt by the new `recompute_sign1_invariant`
    (two CX plus `z_if`). The old `recompute_bchain_sign` is no longer used
    here, because it reads every tape wire below `r1`, including the
    now-freed `tape[2]`.

See [measurement-uncompute](../concepts/measurement-uncompute.md) for why `hmr`
followed later by `z_if` is a valid uncompute, and
[venting-and-wire-loans](../concepts/venting-and-wire-loans.md) for the
free-then-recompute pattern.

### 2. The cap: `PP_WALK_MAX_QUBITS` 1251 → 1250 (`src/point_add/mod.rs`)

`PP_WALK_MAX_QUBITS` is this tree's one width knob. The walk's split adds and
the replay's chunked adds size their carry ladders against the builder's live
count, so each one lands exactly on this many qubits.

Freeing `tape[2]` gives later ladders one more wire of room. In the divide,
that is the rest of the head batch and all later batches. In the multiply, it
is the tail and mid replays and the head replay down to round 2. Lowering the cap by one spends that wire on a lower peak instead
of a wider ladder. See [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).

The old pins for `PP_WALK_MAX_QUBITS`, `PP_WIDTH_SCHEDULE` and `I41_ROUNDS` are
deleted from the alphabetical list and re-pinned in a new "pkgN2" block. In
`env_raw` the first matching arm wins, so a key must never appear twice.

### 3. Re-tuned schedules (`src/point_add/mod.rs`)

- **`PP_WIDTH_SCHEDULE`**: still 699 rounds long.
  - 183 rounds change width: 109 get narrower (93 by one bit, 16 by two)
    and 74 get one bit wider.
  - The sum of the widths drops from 97,658 to 97,607 bit-rounds.
  - A narrower round makes every walk add on `u` and `v` in that round cheaper.
    See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- **`I41_ROUNDS`**: this is the list of walk rounds that use `average.rs`'s
  exact signed half-step. That routine's number of in-place bridge stages is
  set by the room left under the cap (`i41_bridges`).
  - The list grows from 37 to 62 rounds.
  - Rounds 20, 165, 512 and 616 are removed. 29 rounds are added (36, 43, 50,
    …, 629).

### 4. `PP_N_BADJ`: shift the seeded boundary compare on chosen bands (new)

- New function `e_badj(round, multiply, k, phi, floor)` in `pingpong.rs`.
  - It is called at the B (chunk-boundary) erase site in `joint_lowfold.rs`,
    `joint_prebias.rs` and `retained_prebias.rs`.
  - It only applies to a seeded boundary compare that is not on the first
    chunk (`seeded && plo > 0`).
- The pin is a list of `lo-hi:dir:delta` rules.
  - `dir` is `d` (divide), `m` (multiply) or `a` (all).
  - The first rule that matches the round wins.
  - The compare width `k` becomes `k + delta`. It stays at least 2 and at most
    `phi − 1 − floor`.
  - Only the erase site moves. The chunk-layout planning still uses the
    unshifted width.
- The pinned value is
  `649-699:a:-1, 554-615:m:-1, 589-615:d:-1, 616-648:m:+1, 350-553:d:+1`.
  - The late rounds 649–699, multiply 554–615 and divide 589–615 lose one
    compare bit. These are "sells": they save Toffoli and spend λ.
  - Multiply 616–648 and divide 350–553 gain one bit. These are "buys".
  - A boundary compare bit costs about half an executed Toffoli, because the
    compare only runs when the measurement outcome is 1.

### 5. Nonce

`TAIL_NONCE` goes from 26225815260 to 29130632960.

## Why it is still correct, and what it risks

- **The HOLE2 rebuild is exact.**
  - Both identities hold on every input.
  - They read only the low bits of the walk registers. No truncation touches
    those bits, and at the rebuild point the walk-back has restored those
    registers exactly.
  - A wrong rebuilt bit would leave the walk-back with garbage, which shows up
    as a classical or ancilla failure. A missing `z_if` would leave phase
    garbage.
- **The cap change is exact.** It only changes how the ladders are laid out.
- **The schedule, `I41_ROUNDS` and `PP_N_BADJ` changes are probabilistic.**
  - A narrower walk round can overflow on a slow input, which is a classical
    failure.
  - A narrower boundary compare is wrong when the compared top bits tie. That
    corrupts the phase, which is a phase failure.
  - The package comment in `mod.rs` gives the measured λ as 16.30 ± 0.18 over
    512 nonces. The author's gate is "estimate + 2 SE ≤ 18".
- The shipped nonce `29130632960` draws a clean test set: 9,024 of 9,024 shots
  pass, with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Most of the score gain is the one qubit: about 891k of the 1.60M. That qubit
comes from ending a tape wire's lifetime early and rebuilding it exactly later,
which is ancilla-lifetime / venting, the same as `5526766`. Measurement is only
the tool that erases the wire. The schedule, `I41_ROUNDS` and `BADJ` changes
are a smaller comparator/width-truncation retune inside the same package.

## Summary

[`cea9f5f`](cea9f5f.md) saved a qubit by lending the wire `u[0]` while its
value is known. This commit applies the same trick to two more wires of the
jump-GCD walk, at the moments when their values are known.

- **`v[0]`.** It is always 0 after the step's subtract. It is lent while the fused
  apply step runs.
- **`v[0]` again, inside the subtract.** In the controlled subtract the target's
  bit 0 is handled separately and is known: 1 after its CX in the forward walk, and 0
  before its CX in the reverse walk. It is lent while the high-bit adder runs.

With both loans, the peak drops from 1165 to 1164. Each loan costs at most two X
gates and adds no Toffoli. The +23 average Toffoli is nonce noise. This tree
does not include the enhanced constant propagation of the git parent.

## What changed and why it saves a qubit

All circuit changes are in `src/point_add/trailmix_ludicrous/gcd.rs`. They use
`BExt::loan_zero_qubit` / `reclaim_zero_qubit` from `cea9f5f`:

- `loan_zero_qubit` pushes the wire onto the free list without emitting `R`.
- `reclaim_zero_qubit` calls `reacquire`, which takes that exact id back and panics if
  it is still in use.

See [venting-and-wire-loans](../concepts/venting-and-wire-loans.md).

### 1. Even-`v[0]` loan around the fused apply step

- **New helpers.** `park_known_zero(q)` loans the wire if `TLM_LOAN_EVEN_V0=1`, and
  otherwise frees it with `R`. `restore_known_zero` takes it back. No X is needed,
  since the value is already 0.
- **`forward_gcd_jump`.** When `apply_inv` is set, which is the λ walk of `tlm_inverse`,
  `v[0]` is lent right before `apply_step_reverse` and taken back right after it.
- **`reverse_gcd_jump`.** When `apply_fwd` is set, which is the multiply walk,
  `v[0]` is lent around `apply_step_forward`.
- **Why `v[0] = 0` there.** Each step halves `v`, and halves it again if it is still
  even, then sets `b = v[0]`.
  - If `b = 1`, `v` (odd, and still odd after the swap) has `u` (odd) subtracted, so
    the result is even.
  - If `b = 0`, `v` is already even and nothing is subtracted.
  - So after step 5, `v` is even on every input. This is the invariant
    in [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) that each macro-step
    ends with `v` even.
  - The reverse walk visits the same point from the other side: the apply runs before
    the inverse subtract, while `v` still holds the even post-subtract value.
- **Why it is safe.** The apply steps act on the payload registers and the symbol bits,
  and never read `v`. The `u[0]` loan is still open at the same time, so two GCD
  wires are lent during the apply step.

### 2. GCD `y[0]` loan inside `controlled_add_active`

`controlled_add_active` gains a `GcdBit0Mode` argument. The forward walk
passes `ForwardKnownOneAfterCx` and the reverse walk passes
`ReverseKnownZeroBeforeCx`. Bit 0 of the add was already special: because
`x[0] = u[0] = 1`, its sum is `cx(ctrl, y[0])`, and no carry goes into bit 1. The
adder `controlled_hybrid_add_capped_branch` then runs on bits `1..` only. With
`TLM_LOAN_GCD_Y0=1`, the two modes work as follows.

- **Forward subtract.** The subtract runs inside an X-sandwich, so `y = NOT v`.
  - After `cx(ctrl, y[0])`, `y[0] = 1` on every input. If `ctrl = 1`, `v` was odd
    and `y[0]` goes 0 → 1. If `ctrl = 0`, `v` was even and `y[0]` stays 1.
  - The commit runs `x(y[0])`, lends the wire during the high-bit adder, then takes it
    back and runs `x` again.
- **Reverse add `v += subtracted·u`.** The add starts from the even post-subtract `v`,
  so `y[0] = 0`.
  - The wire is lent first, the high-bit adder runs, and the wire is taken back.
  - Only then is the bit-0 `cx(ctrl, y[0])` emitted. Moving that CNOT is safe because
    bit 0 sends no carry into bit 1.

### 3. `src/point_add/mod.rs`

- `build()` bakes `TLM_PARK_EVEN_V0=1`, `TLM_LOAN_EVEN_V0=1` and `TLM_LOAN_GCD_Y0=1`.
- The default `DIALOG_TAIL_NONCE` goes from 2686 to 100000025120.

**Why the peak drops.** The free list is LIFO, so the next allocation inside
the window, a carry or apply scratch wire, reuses the lent index. The high-water
marks inside the subtract and inside the apply step are each one wire lower,
and the measured peak is 1164.

## Why it is still correct, and what it risks

The loans are exact, provided the invariants hold on every input: `v` is even
after each subtract, `y[0]` takes the stated value at the stated point, and
nothing inside each window reads the lent wire. If an invariant failed, a lent
wire would come back with the wrong value. The reused carry would start dirty,
and validation would report classical or ancilla failures. `reacquire` also
checks that the wire is free when it is taken back.

No Toffoli was added or removed. The +23 is the difference between two nonce
draws. The new nonce `100000025120` gives 0 classical, 0 phase and 0 ancilla
failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both edits shorten the lifetime of a wire whose value is known, and lend it to
the peak-binding code. That is ancilla-lifetime / venting, the same family as
the `u[0]` loan it extends.

3. **Check the tree.** `git diff --ignore-cr-at-eol f8d23a9 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*`
   environment variables set. Expect:
   - 1164 qubits
   - 1,413,462 average Toffoli (rounded; 1,413,461.694 before rounding)
   - score 1,645,269,768
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `100000025120` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

Each step of the trailmix jump-GCD decides whether to swap `u` and `v` by
comparing only the top `GAP_J2[i]` bits of their active width, not all of it.
`GAP_J2` is a baked table with one width per GCD step (258 steps). This commit
lowers every entry by 1 bit, and by 2 bits where the entry is 48 or more
(98 of the 258 steps, the middle of the GCD). In total the windows are 356 bits
narrower. Each compare bit costs about one Toffoli, and the compare runs in
both GCD passes, so the saving is 1,152 average Toffoli at the same 1159
qubits. The narrower windows mis-decide the swap more often, which raises
Lambda; the tail nonce was re-hunted.

## What changed and why it saves Toffoli

- `src/point_add/trailmix_ludicrous/schedule.rs`, `GAP_J2` (258 entries):
  - entries below 48: −1 (160 steps; for example the first, 24 → 23, and the
    last, 13 → 12);
  - entries of 48 or more: −2 (98 steps, indices 112–218, for example the
    maximum 56 → 54).
  - The submission note calls this "grad48".
- `src/point_add/mod.rs`, `build()`: `DIALOG_TAIL_NONCE` 700001365225 →
  800001625921.

**What `GAP_J2` controls.** In `trailmix_ludicrous/gcd.rs`, both
`forward_gcd_jump` and `reverse_gcd_jump` set
`cmp_eff = min(GAP_J2[i], SCHED_J2[i])` at step `i`. `SCHED_J2[i]` is the active
register width at that step. The swap decision then compares only the top
`cmp_eff` bits of `u` and `v`:

- forward: `comparator::controlled_swap_decision_lt_truncated` computes
  `swap ^= subtracted ∧ (v_top < u_top)` with the chunked comparator
  `compare_geq_chunked_middle_direct`, about one Toffoli per compared bit;
- reverse: `swap_decision_uncompute_vented` measures the flag out with `hmr`
  and, on the shots where the outcome is 1, recomputes the same truncated
  compare as a phase repair (see
  [measurement-uncompute](../concepts/measurement-uncompute.md)).

The point addition runs the jump-GCD twice: once for the inverse
(`tlm_inverse`) and once for the forward multiply. So each bit removed from
`GAP_J2[i]` saves roughly `2 × (1 + ½) ≈ 3` Toffoli. 356 bits × about 3.2 gives
the measured 1,152. See
[trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) and
[comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

## Why it is still correct, and what it risks

- **Probabilistic.** The comment above `GAP_J2` states the failure condition:
  the compare mis-decides the swap iff
  `SCHED_J2[i] − bitlen(u ⊕ v) ≥ GAP_J2[i]`, that is, iff `u` and `v` agree on
  every bit of the window. One bit less roughly doubles the chance of that at
  each step. The largest windows sit in the middle of the GCD, where the
  baked table had the most slack, and those were cut by 2.
- A wrong swap sends the GCD down the wrong path, so the inverse or product is
  wrong, a classical failure. A mis-decided phase repair in the reverse pass
  would be a phase failure. The cut raises Lambda, the expected number of
  failing shots in a 9,024-shot draw.
- The shipped nonce 800001625921 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures, per the author's stock
  `./benchmark.sh` run.
- [`5f3a0e3`](5f3a0e3.md), by the same author 19 minutes later, applies a
  stronger version of this cut (−3 on the wide entries) to `d11bdbb`.

## Classification rationale

The published label is iteration/threshold tuning, since `GAP_J2` is a
per-iteration schedule of thresholds. The change itself narrows a truncated
comparator by one or two bits per step, so comparator/width truncation fits
at least as well and is the runner-up. Both are in the same family.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 662e267 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 662e267 f0c1c42 -- src/point_add` is
   24 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol f0c1c42 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*`, `CONSTPROP_*` or `TRACE_*` environment
   variables set, because they override the defaults in `build()`. Expect:
   - 1159 qubits
   - 1,379,396 average Toffoli (rounded)
   - score 1,598,719,964
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `800001625921` and an identical op
stream. Any other change needs a new nonce hunt.

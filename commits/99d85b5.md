## Summary

The ping-pong divider runs twice per point add: once to divide (`divide`
phase) and once, in reverse form, to multiply (`multiply` phase). Each
traversal runs a fixed number of walk rounds, and every round costs a walk
add, a walk-back add and a replay cell. The base already ran the multiply
traversal one round shorter than the divide traversal (`rounds() − 1` = 699
against 700). This commit takes it to `rounds() − 2` = 698. That removes one
round's work from the multiply traversal and saves 547 average Toffoli at the
same 1278 qubits. The cost is a slightly higher chance that a multiply walk
has not converged by its last round. The author had used the same lever on an
earlier tree (`1f6b836`); this re-applies it to benhuang2025's 1278-qubit
base.

## What changed and why it saves Toffoli

1. **`rounds_for(Multiply)` default: `rounds() − 1` → `rounds() − 2`** in
   `src/point_add/pingpong_div.rs` (`tuned_window("SUB4_PP_ROUNDS_MUL", …)`).
   With `rounds()` = 700 (`SUB4_PP_ROUNDS`), the multiply depth goes from 699
   to 698. The divide traversal stays at 700.
   - The multiply traversal walks `u = p`, `v = x` for 698 rounds, writing one
     sign per round to the tape. The replay (`replay_doubling_inverse`, here
     driven by the interleave `plan()`) runs one fused cell per tape bit, and
     the walk-back undoes each walk round.
   - One fewer round deletes the last walk add and walk-back add, which run at
     the narrow terminal width and are cheap, plus one full replay cell (a
     256-bit chunked add, the mask-free fold, and its measured-erase repairs).
     The replay cell is most of the 547 Toffoli.
   - The tape is one wire shorter. Q stays at 1278 because the interleave
     plan sizes its chunk ladders against `SUB4_PP_PEAK = 1278`
     (`allowance = peak − tape_len − 2·N − 2·walk_width`); the freed wire goes
     to the ladder budget instead of lowering the peak. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
   - The code comment next to the knob prices the convergence exposure of one
     round on one traversal at about +0.05 λ.
2. **Tail nonce** (`SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`): 6215000001 → 7002105.

## Why it is still correct, and what it risks

Depth is a truncation. The walk is correct only for inputs that reach the
terminal (±1, ±1) state within the fixed number of rounds. A multiply input
that needs its 699th round now ends with a wrong product and dirty walk
registers, which shows up as a **classical** failure (and usually ancilla or
phase garbage as well). The replay arithmetic itself is unchanged. See
[pingpong-division](../concepts/pingpong-division.md) (Depth). The shipped
nonce `7002105` draws a clean set: 0 classical, 0 phase and 0 ancilla
failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only change is the iteration count of the multiply walk, which is
iteration/threshold tuning.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout e928607 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol e928607 99d85b5 -- src/point_add` is
   4 lines in 2 files. (Without `--ignore-cr-at-eol` the raw diff looks huge,
   because the commit also rewrote line endings.)
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 99d85b5 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1278 qubits
   - 943,350 average Toffoli (rounded)
   - score 1,205,601,300
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `7002105` and an identical op stream.
Any other change needs a new nonce hunt.

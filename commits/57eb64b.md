## Summary

The parent [`ba3efc1`](ba3efc1.md) added code that can trim the top bits off
the vented GCD-step subtract (`v −= b0·u`) and its mirror add, but left it
switched off. This commit switches it on, with the trim capped at 2 bits. The
GCD registers are sized by an envelope with a 10-bit safety margin, so their
top 2 bits are almost always zero, and the adder can skip them. That saves
2,621 average Toffoli at the same 1168 qubits, with no measurable change in
the number of hard inputs. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.
They are new first lines, so they take effect:

- `DIALOG_GCD_VENTED_BODY_BAND_TRIM = "1"`;
- `DIALOG_GCD_VENTED_BODY_TRIM_CAP = "2"`;
- `DIALOG_TAIL_NONCE`: `"200005858317"` → `"3168228961"`, in all three places.

How the knobs act, in `src/point_add/rounds/dialog/mod.rs` (unchanged code
from ba3efc1):

- In `dialog_gcd_controlled_sub_selected()` and `_add_selected()`, the vented
  branch runs `cuccaro_{sub,add}_ctrl_vented` over bits `[1..bw)`. Bit 0 is
  the CNOT shortcut from ba3efc1. Here `bw = dialog_gcd_vented_body_width(n, step)`
  and `n` is the step's active width.
- With `BAND_TRIM` on, `bw` starts from
  `dialog_gcd_body_carry_trunc_width(n, step)`. That is the trim schedule the
  materialized body path already used:
  - `DIALOG_GCD_BODY_CARRY_BAND_TRIMS = "0,3,3,3,3,3,1,…,1,3,3,3"`: 26 bands
    of 10 steps;
  - the binder notch, +3 at steps 8 to 10 and +1 at steps 11 to 13.
- `TRIM_CAP = 2` then enforces `bw ≥ n − 2`. The effective trim per step is:

  | Steps | Trim |
  | --- | --- |
  | 0–7 | 0 bits |
  | 8–59 | 2 bits |
  | 60–229 | 1 bit |
  | 230–257 | 2 bits |

- Each trimmed bit drops one controlled ripple cell and its vent from the GCD
  step's subtract and from the reverse add. The trim applies in every GCD pass,
  always executed, so it is a large saving. See
  [adders-and-carries](../concepts/adders-and-carries.md).
- The submission note screened uniform trims as well. With
  `DIALOG_GCD_VENTED_BODY_UNIFORM_TRIM ≥ 2` the phase-failure density
  exploded, so `TRIM_CAP = 2` on the schedule was chosen.

## Why it is still correct, and what it risks

- **Why skipping the top bits works.** The skipped top cells of `u` and `v`
  are 0 whenever both values are at least 2 bits shorter than the active width
  `dialog_gcd_tobitvector_active_width(step) = 256 − 1.015·step + 10` (rounded
  up to even). Before the subtract, the cswap has put the larger value in `v`,
  so the difference does not borrow past the top of `u`. With those top bits
  zero, the trimmed adder gives exactly the same result.
- **What could break it.** It relies on how much a real input's bit length can
  overshoot the envelope. The submission note reports at most 8 bits, less than
  the 10-bit margin, so a 2-bit cap stays inside it. This is an empirical
  bound, not a proof. An input that overshot by more than 8 would get a wrong
  `v`, which is a classical failure.
- **Lambda unchanged.** The note measured the hard-input rate before hunting:
  phase-fail λ ≈ 10.8, unchanged from the base. Failing shots also barely
  overlapped from one nonce to the next. So the trim added no new hard inputs
  in practice.
- **Nonce.** Nonce `3168228961`, found with the GPU prefilter and then an exact
  op-loop check, is clean: 0 classical, 0 phase and 0 ancilla failures over all
  9,024 shots. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change narrows a ripple adder to fewer bits, relying on the high bits
being zero. That is comparator/width truncation. One could argue for dead-gate
removal, since the cells are zero on the sampled inputs, but the guarantee
rests on an empirical bound and not on an invariant.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ba3efc1 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol ba3efc1 57eb64b -- src/point_add` is
   8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol 57eb64b -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `SQUARE_*`, `MOD_*` or `KAL_*` environment variables set. Expect:
   - 1168 qubits
   - 1,429,000 average Toffoli (rounded)
   - score 1,669,072,000
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `3168228961` and an identical op
stream. Any other change needs a new nonce hunt.

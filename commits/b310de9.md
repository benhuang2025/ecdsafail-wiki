## Summary

The trailmix circuit reads its per-call qubit headroom from baked tables in
`schedule.rs`. This commit lowers the qubit peak by one in two ways:

- It **narrows the probabilistic padding windows.**
  - `arith::PAD` goes from 21 to 19. Every `+f`/`−f` fold window shrinks from 54 to 52
    bits, and the top-k overflow comparator shrinks from 21 to 19 bits.
  - `schedule::PAD`, the cap on the GCD subtract's boundary-carry erase, goes from 21 to 20.
- It **gives each scheduled adder slightly less headroom**, through new env "delta" knobs.
  These remove the two extra fold vents and subtract 1 or 2 from the cout, fold, `+f`
  and plain-adder vent tables. They also take one wire from the GCD subtract in steps
  172 to 195.

The narrower windows save Toffoli and wires. The smaller budgets cost Toffoli
and save wires. The net is 1163 qubits and +419 average Toffoli. At about
1,214 Toffoli per qubit (1,412,402 / 1163), the trade pays.

## What changed and why it saves qubits

### Padding windows (probabilistic)

- **`trailmix_ludicrous/arith.rs`: `PAD` 21 → 19.** This sets the following.
  - **`LSBS = PAD + bitlen(f)`, 54 → 52.** This is the width of every pseudo-Mersenne
    `+f` / `−f` fold window: `add_f_window`, `sub_f_window`, and the fused doubling fold
    in `fused.rs`. A fold carry that runs past bit 51 is dropped. That happens with
    probability about 2^-PAD per fold, now 2^-19 instead of 2^-21. Each fold has two
    fewer bits, so it needs two fewer carry wires and about two fewer Toffoli.
    See [modular-fold](../concepts/modular-fold.md).
  - **`MSBS = PAD`, 21 → 19.** This is the width of the truncated less-than
    comparators that erase the overflow ancilla after a modular add or sub
    (`controlled_lt_msbs_conditional`, `controlled_add_carry_msbs_conditional`). Each
    one costs about `MSBS` Toffoli. It mis-decides with probability about 2^-MSBS. See
    [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- **`trailmix_ludicrous/schedule.rs`: `PAD` 21 → 20.** This is the constant that
  `trailmix_ludicrous::PAD` re-exports. `controlled_add_active` passes it as `cap` to
  `controlled_hybrid_add_capped_branch`.
  - In the varchunk branch, `controlled_erase_carry_gated_capped` erases each
    boundary carry by recomputing the compare on only the top `cap` bits of a chunk,
    with a zero carry-in. So the GCD subtract's erase compare loses one more bit.

### Headroom deltas (exact; they cost Toffoli)

These are new reader wrappers in `trailmix_ludicrous/mod.rs`. `env_delta(name)`
parses a `usize`, and `sub_delta` subtracts it, saturating, from every table
entry except the `usize::MAX` sentinel. Each fewer unit of headroom means one
fewer live wire in that call, at a cost of some extra Toffoli.

| knob (baked in `build()`) | table and reader | effect |
| --- | --- | --- |
| `LUD_EXTRA_FOLD_VENTS` 2 → 0, `MIN_G` 16 → 0, new `MAX_G=999` | `FFG_G` via `load_schedule()` | drops the +2 extra fold vents of [`764afda`](764afda.md) / [`f265bb1`](f265bb1.md) |
| `TLM_FFG_DELTA=2` | `next_ffg()` | each apply `+f` fold gets `g − 2` clean vents. The window is 2 bits shorter, so the dirty/chunked suffix keeps its length and only the measured prefix shrinks. |
| `TLM_COUT_K_DELTA=1` | `next_cout_k()` | the apply carry-out layout search ([`bc2334a`](bc2334a.md)) runs with `k − 1` |
| `TLM_FOLD_DELTA=1` | `next_fold()` | lowers each non-negative `FOLD_SCHED` code by 1. With the fold window now 52 bits, codes 53 and 52 (390 entries) still select the full-clean fold, so only the 12 dirty-gradual folds (codes 17 to 20) lose a clean vent. Negative codes, which select the chunked fold, are unchanged. |
| `TLM_HYB_V_DELTA=2` | `next_hyb_v()` | each plain Gidney add (`controlled_hybrid_add_refs`) vents 2 fewer carries. The 2 unvented carries are uncomputed with a second CCX instead of `hmr`. |
| `TLM_GCD_K_ADJUST=-1`, `_AFTER=172`, `_BEFORE=196` | new `maybe_adjust_late_gcd_k(i, k)` in `gcd.rs` | the GCD subtract's `k` drops by 1 for steps 172 ≤ i < 196, in every walk. `controlled_add_active` gains the step index `i` for this. |

**Side effect on the `k = 129` exception.** `TLM_COUT_K_DELTA=1` interacts with
the existing `TLM_COUT_LAYOUT_FORCE_M1_KS=129` exception from
[`ed2715f`](ed2715f.md), which matches on the *shifted* `k`.

- The two calls with raw `k = 130` (`APPLY_COUT_K` positions 4 and 513) now see 129.
  They get margin 1, a budget of 128.
- The two raw-129 calls (positions 5 and 512) now see 128 at margin 0, also a budget of 128.

**Nonce.** The default `DIALOG_TAIL_NONCE` goes from 43158 to 100000688994.

The submission does not break down the −1 qubit and +419 Toffoli by knob. The
`build()` comment calls it a "1163 hunt row", which suggests the combination
was picked from a sweep.

## Why it is still correct, and what it risks

The headroom deltas are exact. They only change how exact adders and folds
split their carries between measured wires, chunks and recomputation.

The three PAD changes are approximations, and each one raises the rate of rare
failures:

- **Fold window.** About 2^-19 instead of 2^-21 per fold for a dropped carry, which
  gives a wrong value: a classical mismatch.
- **Overflow comparator.** About 2^-19 instead of 2^-21 per call for a mis-cleared
  ancilla, which shows up as ancilla or phase garbage.
- **GCD erase cap.** About 2^-20 instead of 2^-21 per capped erase, which leaves a phase error.

There are hundreds of mod-adds per point addition, so these raise Lambda, the
expected number of failing shots per draw, and make clean nonces rarer. The
shipped nonce `100000688994` draws a clean set: 0 classical, 0 phase and 0
ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The goal and result are one fewer qubit. Most of the knobs trade Toffoli for
fewer live scratch wires, which is ancilla-lifetime / venting. A close
runner-up is **Dead-Code and Redundancy Elimination → comparator/width
truncation**, because the PAD cuts are what save Toffoli and also free wires.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 6a9db88 -- src/point_add`.
   The base is the git parent. `git diff --ignore-cr-at-eol 6a9db88 b310de9 -- src/point_add` is about 80 changed lines in 5 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol b310de9 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*`
   environment variables set. Expect:
   - 1163 qubits
   - 1,412,402 average Toffoli (rounded; 1,412,401.873 before rounding)
   - score 1,642,623,526
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `100000688994` and an identical op
stream. Any other change needs a new nonce hunt.

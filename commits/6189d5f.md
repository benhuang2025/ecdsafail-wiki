## Summary

On `fd8e712` the 1466 peak was a four-way tie: the two apply-pass modular
add/sub phases and the two GCD-body add/sub phases. This commit reaches 1446
by a different route than pldallairedemers' [`8ab5f90`](8ab5f90.md), which
landed at the same width from the same base an hour earlier.

Two exact wire reclaims lower the GCD body. First, the body's Cuccaro adder
allocated a fresh carry-in qubit even though its carry lane was borrowed. The
carry-in now sits on `gated[0]`, a wire that the odd-u fast path never
touches. Second, in late steps where the unwritten transcript log is too short
to host the body's scratch, the scratch is taken from the high bits of `u`,
which are zero by the same premise the width truncation already relies on.
With the body out of the way, the apply split `F_CUT` moves from 116 to 126,
which frees 20 apply-pass wires. The peak drops to 1446.

The split costs about 7,940 Toffoli. To pay part of it back, the GCD runs 397
steps instead of 398, which saves about 2,100 Toffoli and is probabilistic.
Net: −20 qubits for +5,818 Toffoli, about 290 Toffoli per qubit, far below the
~1,200 Toffoli a qubit is worth at this size.

## What changed and why it saves qubits

All circuit changes are in `src/point_add/mod.rs`. A new memory file,
`src/point_add/memory/2026-06-03-peak-1446-body-cin-uvhigh.md` (44 lines),
records the author's reasoning and is not compiled.

Background (see [dialog-gcd-early](../concepts/dialog-gcd-early.md)): the dialog GCD runs
`DIALOG_GCD_ACTIVE_ITERATIONS` steps on `(u, v)`, both 256-bit registers. Each
step computes two branch bits (`b0` = "v is odd", `b0_and_b1` = "v odd and
u > v"), conditionally swaps, does `v −= b0 · u` on the first
`active_width` bits, and halves `v`. Steps are grouped by 3, and each group's
6 raw branch bits are compressed into a 5-qubit block of the "compressed
sidecar log" (133 blocks). A later apply pass replays the log on 257-bit
coefficient registers. [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md)
describes the later descendant of this design.

The body subtract (`dialog_gcd_controlled_sub_selected`) and its reverse-pass
add (`dialog_gcd_controlled_add_selected`) work like this:
- They load `gated[i] = b0 & u[i]` with CCX, for `i` from `body_start` up.
  With `DIALOG_GCD_ODD_U_LOWBIT_FASTPATH=1`, `body_start = 1`, because bit 0
  is handled with one CX.
- They add or subtract `gated` into `v` with a measurement-based Cuccaro
  adder whose `n − 1` carries are borrowed from the future part of the log
  (`dialog_gcd_compressed_sidecar_future_carry_slice`, up to `2n − 1` wires
  when `DIALOG_GCD_HOST_GATED=1`, so `gated` can be hosted there too).
- They clear `gated` with `hmr` + `cz_if`, which costs no Toffoli.

The levers:

1. **`DIALOG_GCD_BODY_HOST_CIN=1`** (new `dialog_gcd_body_host_cin_enabled`).
   - Old: `sub_nbit_qq_fast_borrowed_carries` / `add_nbit_qq_fast_borrowed_carries`,
     which do `c_in = b.alloc_qubit()` around the borrowed-carry Cuccaro. That
     one fresh wire put the body phases at 1466.
   - New: when `body_start ≥ 1`, call `cuccaro_sub_fast_borrowed_carries` /
     `cuccaro_add_fast_borrowed_carries` directly, with `gated[0]` as the
     carry-in. `gated[0]` is never loaded or cleared on this path, so it is
     |0⟩ throughout. It is not one of the operand or carry wires, and it is
     already allocated. The gates are the same, so Toffoli is unchanged.
2. **`DIALOG_GCD_LATE_BORROW_UV_HIGH=1`** (new
   `dialog_gcd_pick_borrow_slice(future, u, active_width)`, used in both
   `emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle` and
   its `_reverse_` twin).
   - In late steps the future log region is shorter than `2n − 1`
     (`n = active_width`). The old code then allocated a fresh `gated`
     register, or a fresh carry lane too when even `n − 1` did not fit. That
     made a 1465 tier in the `tobitvector_subtract` / `_reverse_add` phases.
   - New: if the future slice is missing or shorter than `2n − 1`, and
     `u.len() ≥ n + 2n − 1`, return `u[n .. 3n − 1]` instead. The width
     envelope already assumes `u < 2^n` at this step, so those wires are |0⟩.
     They are already allocated and are disjoint from `u[..n]` and from `v`.
     Peak-neutral reuse, no Toffoli change.
   - See [venting-and-wire-loans](../concepts/venting-and-wire-loans.md) for
     the general pattern of borrowing provably-zero wires.
3. **`DIALOG_GCD_APPLY_CHUNKED_F_CUT`: 116 → 126.** The apply pass's add and
   subtract split the 257-bit accumulator into two blocks at `F_CUT`. The
   upper block's scratch is about 2 × (257 − F_CUT) wires, so 10 more bits in
   the lower block free 20 qubits. The exact compare that clears the lower
   block's carry grows by 10 bits, in both the add and the subtract, on each
   of the 397 steps: about 10 × 2 × 397 = 7,940 Toffoli. See
   [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md).
4. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 398 → 397.** One fewer GCD step, in both
   the walk and the apply pass, saves about 2,100 Toffoli. The log still has
   133 blocks (`ceil(397 / 3)`), so no wires change. The comment says
   "399 → 397", but the base value was 398.
5. **Reroll pair: `DIALOG_REROLL` 52 → 37, `DIALOG_POST_SUB_REROLL` 28 → 1.**
   These are the counts of identity `X;X` pairs that `build_builder()` emits
   on `tx[0]` before the first subtraction and on `tx[1]` after it. They only
   re-draw the 9,024 test inputs.
6. **`DIALOG_GCD_COMPARE_BITS` stays 58.** A new comment says "59 → 58
   (−952)", but the base was already at 58, so nothing changes there.

Accounting: +7,940 (split) − ~2,120 (one step) ≈ +5,818, the measured change.

## Why it is still correct, and what it risks

- **Exact:** the hosted carry-in and the F_CUT move. `gated[0]` is |0⟩ on
  entry and the Cuccaro returns its carry-in to |0⟩. The chunked apply is
  exact at any cut.
- **No new risk:** the u-high borrow. It is only wrong on inputs where
  `u ≥ 2^active_width`, and those inputs already break the width truncation.
  If the premise failed, the borrowed wires would not be clean and the run
  would show ancilla or phase garbage.
- **Probabilistic:** the 397-step cut. An input whose binary GCD needs all
  398 steps is not finished, and gives a classical failure.
- The reroll pair (37, 1) draws a clean set: 9,024 of 9,024 shots pass with
  0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The qubit saving comes from reusing wires that are idle and |0⟩ (`gated[0]`,
the high bits of `u`) instead of allocating fresh scratch, so scratch/ancilla
reuse fits. The iteration cut is a secondary Toffoli lever, iteration/threshold
tuning, bundled in to pay for the split.

## Summary

Every round of the ping-pong coefficient replay leaves two kinds of scratch
bit that the circuit measures out instead of uncomputing: the carries at the
two chunk boundaries of the 256-bit add, and the cell's overflow flag. Each
measurement can leave a sign error. A comparison of the top `k` bits of two
registers recomputes the measured bit's value and repairs the phase, but only
on shots where the measurement outcome was 1.

This commit compares one bit fewer in both repairs: 23 instead of 24 for the
chunk boundaries and 25 instead of 26 for the flag. A comparator bit costs one
Toffoli and runs on about half the shots. Over the two 704-round replays,
with two boundaries and one flag per round, that is about 2,100 average
Toffoli, measured at −2,114. Qubits are unchanged. The cost is a roughly
doubled tie probability in each compare, which adds hard inputs.

## What changed and why it saves Toffoli

1. **`replay_chunk_compare()`** in `src/point_add/pingpong_div.rs`: the
   default of `SUB4_PP_REPLAY_CHUNK_COMPARE` goes from 24 to 23.
   - It is used in `add_chunked_measured`, the chunked adder inside each
     replay cell. With `replay_chunk() = 96`, `chunk_bounds` splits a 256-bit add into
     three balanced chunks, [0,86), [86,171) and [171,256), so there are two boundary carries.
   - For each boundary the code runs `b.hmr(carry, phase)` and then
     `cmp_lt_phase_conditioned(b, &acc[hi − k..hi], &addend[hi − k..hi], phase)`
     with `k = min(23, chunk width)`. Since the boundary carry equals
     `[sum < addend]` for the chunk, the compare reproduces it and applies
     the phase `(−1)^carry` that the measurement left.
2. **`replay_flag_compare()`**: the default of `SUB4_PP_REPLAY_FLAG_COMPARE`
   goes from 26 to 25.
   - It is used after the add-and-halve cell (`signed_mod_add_pm_halve_fused`),
     after the double-and-add cell (`signed_mod_double_add_pm_fused`) and in
     the unfused `signed_mod_add_pm` (only reached when
     `SUB4_PINGPONG_UNFUSED_INVERSE` is set).
   - Each site runs `b.hmr(flag, phase)` on the overflow flag, then
     `cmp_lt_phase_conditioned(b, &target[N − k..], &source[N − k..], phase)`.
     The flag is measured out, not derived. The truncated compare recomputes
     its value from the top `k` bits only to repair the phase.
3. **Tail nonce** (`src/point_add/mod.rs`): the default
   `SUB4_PINGPONG_TAIL_NONCE` goes from 20136 to 40561.

**Cost of one bit.** `cmp_lt_phase_conditioned` in `arith/compare.rs` runs
inside `push_condition(phase)`. It computes a `k`-bit borrow chain with one
CCX per bit, applies a CZ, and unwinds the chain with `hmr` plus `cz_if`, at
no Toffoli cost. So it costs `k` Toffoli on shots where `phase = 1`, about
half of them. One bit less saves about 0.5 executed Toffoli per site. Each
point addition runs two replays (divide and multiply) of about 704 cells,
each with two chunk boundaries and one flag. That is about 2 × 704 × 3 × 0.5
≈ 2,100 Toffoli. See
[measurement-uncompute](../concepts/measurement-uncompute.md) and
[comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

## Why it is still correct, and what it risks

- **The value is exact; only the phase repair is approximate.** The compare
  is wrong when the two `k`-bit top slices are equal, but the lower bits would
  have decided the comparison. That happens with probability about 2^−k per
  call. One bit less roughly doubles it, for each of the three repairs per
  round.
- A wrong repair leaves a stray phase on that shot, which the validator
  reports as phase garbage. These are new hard inputs, and they raise λ.
- The shipped nonce `40561` draws a clean test set: 0 classical, 0 phase and
  0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both changes narrow a comparator window, which is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 920c5bb -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 920c5bb 6ee4d14 -- src/point_add` is
   6 changed lines in 2 files.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 6ee4d14 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set, because they override the defaults in the patch.
   Expect:
   - 1320 qubits
   - 946,387 average Toffoli (rounded)
   - score 1,249,230,840
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `40561` and an identical op stream.
Any other change needs a new nonce hunt.

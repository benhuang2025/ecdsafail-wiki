## Summary

The `square` phase computes `out −= y² (mod p)` with Karatsuba. The top level
splits the 256-bit `y` into three half-squares of 128, 128 and 129 bits. Each
of those is built by `tri_square_k2r`, which splits once more into three
children of about 64 bits that are squared triangularly. This commit splits two
of those children, the low half and the sum half, one level deeper again.
Triangular squaring costs about m²/2 Toffoli, so splitting a 64-bit child
saves roughly 100 to 130 Toffoli each time.

A deeper split keeps more scratch live, and the peak has no room for it. So the
commit also frees qubits inside the square. The sum `t = a + b` is built in
place in `b`'s own wires plus one carry, instead of in a fresh 65-bit
register. Narrow adds no longer allocate zero pads. A guard splits the modular
add's carry ladder if it would ever exceed the cap. All of it is exact. Net:
−1,211 Toffoli at the same 1260 qubits.

## What changed and why it saves Toffoli

1. **Recursive split in `tri_square_k2r`** (`src/point_add/square.rs`).
   - New helpers `square_half(x, product, min)` and `square_half_inv`. A half of
     at least `min` bits goes through `tri_square_k2r` again. A smaller one goes
     to `tri_square`.
   - `K2Retained` changes from a `(t, p_t)` tuple to a struct
     `{ carry, cross, low, sum }`. `low` and `sum` hold the child splits'
     retained scratch, so the inverse can undo them exactly without
     recomputing.
   - New pins in `build()` (`mod.rs`):
     - `SQ_SPLIT_LOW_MIN = 64`: the low half `a` is split again if it is at least
       64 bits. In all three calls `a` is 64 bits, so it is split.
     - `SQ_SPLIT_SUM_MIN = 65`: the sum half `t` is split again if it is at least
       65 bits. Here `t` is 65, 65 and 66 bits, so it is split.
     - The high half `b` (64, 64 or 65 bits) is always squared triangularly, as
       before.
   - The grandchildren are 32 to 34 bits, below both thresholds, so the
     recursion stops there.
   - The code comment gives the cost model. A triangular square costs
     `B(m) = m(m−1)/2 + 4m − 3`. One split costs
     `K(m) = B(a) + B(b) + B(b+1) + a + 7b + 1`. Break-even is near 60 bits.
     - Splitting `a` at 64 saves 113 per call.
     - Splitting `t` saves 101 at 65 and 133 at 66.
     - Over the three half-squares, forward and inverse, that is about 1,350
       emitted Toffoli. The measured average drop is 1,211. Some of the gap is
       likely the `peak_fitted_add` repairs below, but this was not measured.
   - Order matters. `b²` is built first from the pristine `b`. Then `b` becomes
     `t`. Only then is `a` split, because a split leaves its input modified until
     the inverse.
   - See [squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md).

### What changed to keep the peak at 1260

2. **In-place sum.**
   - Before, `tri_square_k2r` allocated `t = a + b` as a new `bs.len() + 1`-bit
     register: copy `a`, then `add_wide(bs, t)`.
   - Now it allocates one `carry` wire, uses `t = bs ++ [carry]`, and runs
     `add_wide(a, t)`. That is 64 or 65 fewer live qubits per split.
   - The inverse restores `b` with `sub_wide(a, t)`. That is exact, because
     `t − a = b < 2^|b|`, so the carry returns to 0. Only then does it clear `b²`.
   - The top-level `sub_square` already did this with `y_hi`.
3. **Pad-free narrow adds** (`src/point_add/modular.rs`).
   - `ripple_add` now accepts an addend of `k ≤ acc.len()` bits. Each position
     `i ≥ k` is a zero-addend stage, `carry = acc AND previous`, which is one
     Toffoli: the same as the old zero pad cost.
   - `terminal_step` and the new `unwind_zero_step` handle those positions. The
     unwind is an `hmr` erase plus a `cz_if` phase repair, so it costs no
     Toffoli.
   - `addsub_wide` no longer allocates `acc.len() − value.len()` pad qubits. The
     comment says those pads were what let the square's cross-term add set the
     peak.
4. **`peak_fitted_add`** (new, `modular.rs`, used by `mod_addsub`).
   - When `cap − live` is too small for the 256-bit ripple's `width − 1`
     carries, the add is cut in two. The leading `low` bits ripple into a `mid`
     wire, the high chunk ripples on from `mid`, and `mid` is erased by
     `erase_with_compare` over the whole leading chunk.
   - Comparing the whole chunk is exact, because chunk 0 has no carry-in. It
     costs one Toffoli per leading bit under a half-time condition.
   - Where the plain ladder fits, the emitted ops are unchanged.
   - To read the cap from `modular.rs`, `pinned_env!` gains a visibility
     argument and `walk_max_qubits` becomes `pub(super)`.
5. **Tail nonce** (`TAIL_NONCE` default): 2977985437 → 4399134209103.

## Why it is still correct, and what it risks

- **All arithmetic changes are exact.** Karatsuba is an identity, every add and
  subtract here is full-width, and the in-place sum is restored exactly. The
  zero-addend stages compute the same carries the pads did. The only new
  compare (`peak_fitted_add`) covers its whole chunk. The `mod.rs` comment
  says it: "Exact arithmetic only: no failure sites move."
- So λ is unchanged in kind. A new nonce was still needed, because the op
  stream changed and the test shots are re-drawn.
- A bug here would show up as a classical failure (wrong `x`), or as an ancilla
  failure if `t`'s carry or a child's `cross` register were not returned to 0.
- The shipped nonce draws a clean test set: 9,024 of 9,024 shots, with 0
  classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The Toffoli saving comes from a deeper Karatsuba recursion in the squarer, a
different squaring algorithm for the same product. That is multiplier/squarer
swap. The in-place sum, pad removal and peak-fitted add are the qubit room that
lets it fit under the unchanged cap. The runner-up was ancilla-lifetime /
venting, for those enablers, but they do not move the score on their own.

## Summary

This commit takes back one of the comparator bits that [`8a47cf5`](8a47cf5.md)
had spent. The dialog-GCD walk decides each step's branch by comparing the
top bits of `u` and `v`. That compare now uses at most 51 bits instead of 52.
The cap binds on 214 steps of each of the four walks, and one bit costs one
Toffoli, so the saving is 4 × 214 = 856 average Toffoli. Qubits are
unchanged. The tail nonce was re-hunted.

The author ran this in parallel with the apply-clean cut [`2f1f175`](2f1f175.md).
Both are built on `8a47cf5`, and this one does not contain the other. The
two were stacked next, in [`373fb4d`](373fb4d.md).

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_COMPARE_BITS`: 52 → 51.**
   - Read by `dialog_gcd_compare_bits()`. The route sets
     `DIALOG_GCD_PA9024_COMPARE_SCHEDULE=0`, so
     `dialog_gcd_compare_bits_for_step(step, active_width)` is
     `min(COMPARE_BITS, active_width)`.
   - That width is the size of the truncated "is u > v" comparator
     (`dialog_gcd_cmp_gt_truncated_into_width` and its controlled form). It
     compares only the top bits of the two width-`active_width` registers
     and picks the step's subtract direction.
   - `active_width(step)` is `256 − 1.014·step + 10`, rounded up to an even
     number. The slope is `DIALOG_GCD_WIDTH_SLOPE_X1000 = 1014` and the
     margin is `DIALOG_GCD_WIDTH_MARGIN = 10`. It is at least 52 for steps
     0 to 213. On those 214 steps the comparator loses one bit. On narrower
     steps the cap did not bind.
   - The comparator runs in the forward and reverse walk of each of the two
     dialog-GCD divisions, so 4 × 214 = 856 Toffoli. That is exactly the
     measured saving.
2. **`DIALOG_TAIL_NONCE`: 172380 → 43780000903.**

## Why it is still correct, and what it risks

A truncated comparator is wrong when `u` and `v` agree on all 51 compared
top bits but differ below. The walk then takes the wrong branch, the
transcript records it, and the reverse walk and the apply use it too. The
result is usually a classical mismatch. One bit less roughly doubles this
per-step risk, but it is still tiny on the wide steps: the top ~10 window
bits are margin and usually zero in both registers, so the compare sees about
41 significant bits, roughly 2^−41 per step. The
note on [`8a47cf5`](8a47cf5.md) explains that the 52-bit setting was chosen
mainly to make nonce screening easier. The author found nonce `43780000903`
with a CPU prefilter, and the trusted evaluation confirmed it clean: 9,024 of
9,024 shots, with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

One comparator is narrowed by one bit, which is comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8a47cf5 -- src/point_add`.
   - Do not start from the git parent `2f1f175`. That is the author's
     parallel apply-clean cut. Diffing against it would wrongly show this
     commit putting `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` back from 23 to 24.
   - Against `8a47cf5`, `git diff --ignore-cr-at-eol 8a47cf5 9906ec0 -- src/point_add`
     is 4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9906ec0 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*` or `DIALOG_*` environment variables set. Expect:
   - 1313 qubits
   - 1,517,664 average Toffoli (rounded)
   - score 1,992,692,832
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=43780000903` and an
identical op stream. Any other change needs a new nonce hunt.

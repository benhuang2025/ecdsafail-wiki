## Summary

Two changes.

1. **CARRY-TAIL.** The register-free controlled constant subtractor
   `csub_nbit_const_direct_fast` computes one borrow bit per position, at one
   Toffoli each, up to bit 255. For the Solinas constant `c = 2^32 + 977`, the
   constant has no set bits above bit 32. Above that, the borrow only
   propagates through runs of zero bits of the accumulator, and such a run is
   almost never long. The chain is now cut at bit 129 (`k0 = 33` plus a window
   `W = 96`). About 126 borrow Toffolis are saved per call, and the
   subtractor is called hundreds of times per shot: in every modular halving
   and in the low-scratch Solinas adds.
2. **W-TRUNC margin 20 → 4.** The Kaliski width-loop margin from
   [`36e8578`](36e8578.md) goes from 20 to 4. The base tree had margin 20; the
   frontier `13ac8da` had 0.

Together: −144,963 Toffoli at 2309 qubits. The two earlier margin commits cost
about 4,200 to 4,400 Toffoli per margin bit, so the 16-bit margin cut is worth
roughly 65,000 to 70,000 of that. The carry tail gives the remaining roughly
75,000 to 80,000.

## What changed and why it saves Toffoli

### 1. Truncated borrow chain (`src/point_add/cuccaro.rs`, `kaliski_state.rs`)

`csub_nbit_const_direct_fast(b, acc, c, ctrl)` computes `acc −= ctrl · c`
without loading the constant into a register.
- **Forward sweep.** It computes `borrow_{i+1} = majority(!acc_i, ctrl·c_i, borrow_i)`
  into a fresh borrow register. That is 1 CCX per position where `c_i = 0`,
  and 3 where `c_i = 1`.
- **XOR.** It XORs `ctrl·c_i ⊕ borrow_i` into each `acc_i`.
- **Erase.** It measures every borrow away with `hmr`, repairing the phase
  with `cz_if` on the post-subtraction majority identity. That costs no
  Toffoli (see [measurement-uncompute](../concepts/measurement-uncompute.md)).

New: `let cut = kal_carrytail_count(n, kal_carrytail_sub_enabled())`, and
`borrows = alloc(cut)`. The same `cut` bounds all three loops:
- the forward sweep runs `for i in 0..cut`;
- the XOR applies `borrows[i−1]` only `if i − 1 < cut`;
- the erase runs `for i in (0..cut).rev()`.

So the forward and the erase always touch the same wires.

`kal_carrytail_count(n, enabled)` returns `n − 1` (the full chain) when
disabled, else `min(n − 1, k0 + W)`.
- `k0` is `KAL_CARRYTAIL_K0`, default 33, one above the constant's top set
  bit.
- `W` is `KAL_CARRYTAIL_W`, default 96.
- For a 257-bit extended accumulator the chain drops from 256 borrows to 129.
  For a 256-bit one it drops from 255 to 129.
- All the dropped positions have `c_i = 0`, so each was 1 CCX.

The mode is set by `KAL_CARRYTAIL_TRUNC`: `sub` (the default), `add`, `both`
or `off`. The code also adds the same truncation to the adder
`cadd_nbit_const_direct_fast`, but its default mode leaves it off. The comment
says the add path's reverse sweep, which uses `!acc_i_final`, leaked phase
under truncation: 141 phase-garbage batches.

Callers of the subtractor, which all get the shorter chain:
- **Halvings.** `mod_halve_inplace_fast_with_dirty` (behind
  `mod_halve_inplace_fast`) uses it to subtract `c` when the value is odd,
  before the right shift. That covers:
  - every backward Kaliski iteration at or past `R_SMALL_THRESHOLD`, which
    halves `r`;
  - the 399 halvings of λ in pair1.
- **Low-scratch Solinas adds.** `mod_add_qq_lowq_lowscratch` and
  `mod_sub_qq_lowq_lowscratch` use it for the conditional `−c` undo. So do
  `mod_add_qq_fast_lowscratch` and `mod_add_qq_fast_from_zero_lowscratch`.
  See [modular-fold](../concepts/modular-fold.md).
- **Two controlled decrements** with `c = 1`: one in `mul_schoolbook.rs`, and
  one in the short-window branch of `shift22_spill_op_dirty`. The same
  129-bit cut applies to them.

### 2. W-TRUNC margin (`kaliski_state.rs`)

`kal_wtrunc_margin()`: the default goes from 20 (in this base) to 4. The
comment says margin 4, not 0, was needed to land a clean draw together with
the carry-tail change. Each margin bit removes about one Toffoli from each
clipped Kaliski width loop (OR chain, comparator, STEP 4 load/subtract), in
every iteration from 35 on. See [`36e8578`](36e8578.md) and
[`b86e789`](b86e789.md).

## Why it is still correct, and what it risks

- **Carry-tail truncation is probabilistic.** Above bit 32 the constant is
  zero, so a borrow out of bit 32 travels upward through the accumulator's
  zero bits and stops at the first 1. With the chain cut at bit 129, the
  result is wrong only if bits 33 to 128 are all zero while a borrow arrives.
  For a value that looks uniformly random that has probability about 2^-96
  per call. The author's 3-million-trial Monte Carlo found a longest run
  above bit 32 of 19 for the subtract path (28 for add).
  - Values that are structurally small or close to `p` would break it. For
    example, a halving of an odd value below 2^129, or a Solinas undo on a sum
    just below `p`, whose bits 33 and up are all ones. The circuit's values
    are field elements that look random, so that is not expected.
  - The failure would show as a classical mismatch, or as phase garbage,
    because the erase sweep's phase repair assumes the borrows it measures.
  - The comment's cliff, "W=80 m=4 gives 2 mismatches / 1 phase failure", is
    probably a draw effect rather than a real 80-bit run. As with the
    W-TRUNC margins, each W is a different hashed test draw.
- **Margin 4** is the empirical W-TRUNC risk discussed in
  [`13ac8da`](13ac8da.md) and [`b86e789`](b86e789.md), with 4 bits of slack
  above the fitted envelope.
- There is no tail nonce in this era. The test set is a hash of the op stream,
  and this stream's draw is clean: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The main new lever cuts a carry/borrow chain short on an empirical run-length
bound: fold/carry truncation. The margin change is comparator/width
truncation, but it is a retune of an existing knob.

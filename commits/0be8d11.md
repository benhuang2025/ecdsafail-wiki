## Summary

Three changes, all at 2309 qubits. The main one is a gate identity in the
register-free controlled constant subtractor `csub_nbit_const_direct_fast`. Its
borrow chain computes `borrow_{i+1} = MAJ(!acc_i, ctrl, borrow_i)` with three
Toffoli at every bit where the constant has a 1. The commit rewrites that
majority with the borrow-in as a pivot, so it costs one Toffoli plus free CNOTs.
The value is identical, so nothing else in the adder changes. The author counts
7,332 fewer emitted Toffoli from this.

The other two changes are truncation knobs, both picked by an island sweep: the
carry-tail window of the same subtractor goes from 59 to 49 bits, and the
W-TRUNC full-width prefix `K0` goes from 27 to 26. Together the three save
16,400 average Toffoli against the author's previous tree.

## What changed and why it saves Toffoli

**Background: the direct constant subtractor.** For p = 2^256 − c with
c = 2^32 + 977, many modular steps subtract `c` under a control: the Kaliski
`mod_halve` used for the 399 pair1 halvings (`modular.rs`, `ovf` = the odd bit),
the low-scratch modular adders (`mod_add_qq_fast_lowscratch` and relatives) and
the Solinas fold (`solinas.rs`). `csub_nbit_const_direct_fast` in
`src/point_add/cuccaro.rs` does this without loading `c` into a register: it
computes a borrow chain `borrows[0..cut]` with Toffoli, XORs the difference bits
with CNOTs, and then erases each borrow by `hmr` plus `cz_if` phase fixes
(see [measurement-uncompute](../concepts/measurement-uncompute.md)). At a bit
where `c_i = 1` the borrow is `MAJ(!acc_i, ctrl, borrow_i)`. At a bit where
`c_i = 0` it is `!acc_i AND borrow_i`, one Toffoli.

1. **MAJ-fold, `cuccaro.rs`, `csub_nbit_const_direct_fast`.** The old code was
   three Toffoli into the fresh `target`:
   `ccx(acc,bi,t); ccx(ctrl,acc,t); ccx(ctrl,bi,t)`. The new code uses
   `MAJ(a,b,d) = d ^ ((a^d) & (b^d))` with `d = bi`:
   ```
   cx(bi, acc[i]); cx(bi, ctrl);       // a^d, b^d
   ccx(acc[i], ctrl, target);          // (a^d)&(b^d)
   cx(bi, target);                     // ^ d
   cx(bi, ctrl); cx(bi, acc[i]);       // restore
   ```
   (`acc[i]` already holds `!acc_i` from the surrounding `x`.) This is one
   Toffoli instead of three. In c = 2^32 + 977 the set bits with a borrow-in are
   bits 4, 6, 7, 8, 9 and 32, so each call saves 12 Toffoli. The reverse
   `hmr`/`cz_if` sweep is unchanged because the borrow values are the same.
   A new switch `majfold_sub_enabled()` in `kaliski_state.rs` reads
   `KAL_MAJFOLD_SUB` and defaults to on.
2. **Carry-tail window, `kal_carrytail_w()` in `kaliski_state.rs`: 59 → 49.**
   The subtractor only computes `cut = min(n−1, K0 + W)` borrows, with
   `K0 = 33` (one above c's top set bit). Above bit 32 the borrow can only
   propagate, and a 3M-trial Monte Carlo found the longest run to be 19 bits. So
   the chain now has 82 borrow bits instead of 92. That removes 10 one-Toffoli
   borrow positions per call. The comment lists the clean islands the sweep
   found at margin 3: W ∈ {82, 75, 69, 59, 49}.
3. **W-TRUNC prefix, `kal_wtrunc_k0()`: 27 → 26.** The Kaliski width envelope
   `env(it) = n − ⌊(it − K0)·2/3⌋` now starts shrinking one iteration earlier,
   so the clipped OR-chain, comparator and STEP-4 loops in every later iteration
   are up to one bit narrower. The margin stays at 3. See
   [`e739b53`](e739b53.md) for what W-TRUNC clips.

## Why it is still correct, and what it risks

- **MAJ-fold is exact.** The identity holds for all inputs, and the borrow
  register ends in the same state, so the measured uncompute still matches.
  The author reports it is also 9,024-clean with all truncations switched off.
- **The carry-tail window is approximate but very safe.** A borrow that
  propagates more than 49 bits above bit 32 is dropped, giving a wrong
  difference (a classical mismatch). The longest observed run is 19, so in
  practice this window is exact on the test set. The value 49 was chosen
  because its op stream lands on a clean island, not for the arithmetic.
- **W-TRUNC `K0 = 26` is probabilistic.** An input whose GCD registers shrink
  slower than the envelope fails as a classical mismatch or phase garbage.
- There is no nonce in this era. The test set is a hash of the op stream, and
  this stream's draw is clean: 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The largest piece is the MAJ-fold, which replaces a 3-Toffoli majority with a
1-Toffoli form of the same function. That is Strength Reduction. The published
change-type "fast-adder reroute" is loose: no adder is rerouted. A closer name
is "majority-gate fold". The two other knobs are truncations (carry-tail is
fold/carry truncation, `K0` is comparator/width truncation) and are the runner-up
reading.

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 2abe7f4 -- src/point_add`.
   - Do not start from the git parent `e739b53`. That is anupsv's tree, which
     had lowered W-TRUNC to `K0 = 25` and margin 2 (via `179ab10`).
   - Against the parent, the diff is 64 lines in 2 files. It would show this
     commit raising `K0` from 25 to 26 and the margin from 2 to 3, which are
     anupsv's changes being dropped, not part of this optimization.
   - Against `2abe7f4`, `git diff --ignore-cr-at-eol 2abe7f4 0be8d11 -- src/point_add`
     is 41 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 0be8d11 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,826,543 average Toffoli (rounded)
   - score 6,526,487,787
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

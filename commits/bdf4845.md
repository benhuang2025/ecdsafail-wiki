## Summary

The ping-pong walk registers `u` and `v` shrink round by round. The width
they get in each round comes from a 700-entry table, `WIDTH_SCHEDULE`, that
[`b5796ce`](b5796ce.md) fitted from sampled walks. This commit replaces it
with a new fitted table, `GREEDY_M1000_WIDTH_SCHEDULE`, named "greedy minus
1000"; its header credits the census tool `ecdsa-ops/pp-width-census-rl`.

The new table is narrower in 534 rounds and wider in 79, mostly late ones.
Over the rounds actually run, the two traversals use 1,492 fewer bit-rounds
(196,430 → 194,938). Every walk add and walk-back add in a narrowed round
gets cheaper, which saves 3,846 average Toffoli at the same 1278 qubits. Some
inputs now overflow a narrowed register, so λ rises, and a new nonce was
hunted.

## What changed and why it saves Toffoli

1. **New file `src/point_add/greedy_m1000_width_schedule.rs`** (40 lines,
   generated data). It is a bare Rust array expression of 700 widths, labelled
   "Exact greedy-minus-1000 table from ecdsa-ops/pp-width-census-rl".
   - It starts at 259 and falls to 9 at index 699. The old table started at
     258 and ended with seven 8s.
   - It sums to 97,756 bit-rounds against 98,497 for the old table. Its
     differences per index range: 0–99: −107, 100–299: −365, 300–499: −344,
     500–649: −37, 650–699: +112.
   - So it is tighter through the long middle of the walk and gives back a
     little width in the last 50 rounds, where the old table had hit its
     floor of 8.
2. **`src/point_add/pingpong_div.rs`**
   - `const GREEDY_M1000_WIDTH_SCHEDULE: [u16; 700] = include!("greedy_m1000_width_schedule.rs");`
   - `value_width(round)` now indexes this table, unless
     `SUB4_PP_G1000_DISABLE` is set, which selects the old `WIDTH_SCHEDULE`.
     The clamp to `[8, 259]` and `SUB4_PP_SCHED_BIAS` work as before.
   - In this tree `width_round_index` is the identity (rescale off), so
     table index = round. The divide runs 698 rounds and the multiply 696.
     Round 0 always uses the full 259-bit envelope.
   - Over rounds 1..697 (divide) and 1..695 (multiply), the bit-round total
     goes from 196,430 to 194,938. Each walk round's signed add, and its
     mirror in the walk-back, is as wide as `value_width(round)`. Narrower
     registers also change the interleaved replay footprint the ladder budget
     sees. See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md),
     section "Width schedules".
   - A comment on `SUB4_PP_ROUNDS_MUL` notes that setting it to 700 recovers
     the older `7ca0559` traversal. The default stays 696.
3. **Tail nonce** in `src/point_add/mod.rs`: 48000070891 → 135608492183
   ("Exact g1000 island").

## Why it is still correct, and what it risks

- **Probabilistic.** A width table is not a proof. Trimming a register's top
  wire is valid only if that bit is a copy of the sign bit below it. On an
  input whose walk value has not shrunk as fast as the table assumes, the
  trimmed bit holds real data. The walk-back then leaves garbage, which is a
  classical failure, usually with phase and ancilla garbage too.
- The new table removes width in 534 rounds, so it exposes more inputs. It
  adds width back in the late rounds, where the old floor of 8 was the
  tightest point.
- Its fit target is not recorded in the tree, beyond the name. The shipped
  nonce draws a clean set: 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from narrower per-round walk registers, which is width
truncation priced in λ.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 36f6ca0 -- src/point_add`.
   - Do not start from the git parent `087cafa`. That is the author's own
     1275-qubit trade, which this commit does not build on.
   - Against the parent, the diff is 265 lines in 5 files. It deletes
     087cafa's `*_dead_low` constant adders from `arith/const_arith.rs`
     (181 lines). It also resets the plan from `SUB4_PP_R1` 342 /
     `SUB4_PP_PEAK` 1275 to 356 / 1278, `SQUARE_LADDER` from 245 to 248, and
     the chunk compare from 20 to 22. All of that is just the older tree.
   - Against `36f6ca0`, `git diff --ignore-cr-at-eol 36f6ca0 bdf4845 -- src/point_add`
     is 59 lines in 3 files.
2. **Copy the generated table from the commit:**
   `git checkout bdf4845 -- src/point_add/greedy_m1000_width_schedule.rs`.
3. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It covers `mod.rs` and `pingpong_div.rs`.
4. **Check the tree.** `git diff --ignore-cr-at-eol bdf4845 -- src/point_add`
   should print nothing.
5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. Expect:
   - 1278 qubits
   - 915,947 average Toffoli (rounded)
   - score 1,170,580,266
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `135608492183` and an identical op
stream. Any other change needs a new nonce hunt.

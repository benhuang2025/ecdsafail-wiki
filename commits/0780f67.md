## Summary

The dialog GCD (background in [8316db1](8316db1.md); see
[dialog-gcd-early](../concepts/dialog-gcd-early.md)) is a fixed-length binary GCD walk. Each step does at most one
subtract and then exactly one halving of `v`. A matching "apply" pass replays
the recorded branch bits on a 256-bit coefficient `y`. Each apply step doubles
`y` and does a controlled 256-bit modular add, which makes it the expensive
part.

This commit makes every step strip up to **two** trailing zeros of `v` ("K=2
bounded shift"). After the usual free halving, the step checks whether `v` is
still even. If it is, it halves `v` again with a controlled shift and records
that bit, `shift2`, in the transcript. The apply pass mirrors it with a
controlled second doubling (or halving) of `y`. `v` now shrinks by about 0.95
bits per step instead of 0.71, so the walk needs only 259 steps instead of 393.

The two apply passes lose 134 expensive steps each and gain 259 cheaper
conditional doublings. Toffoli falls by 134,536 (−7.6%). The transcript needs
one more bit per step, and the raw-block scratch can no longer be hosted, so
the peak rises by 44 qubits (+3.3%). Net score −4.6%. Several truncation knobs
were re-tuned for the new walk, and a new tail nonce was found.

## What changed and why it saves Toffoli

All circuit changes are in `src/point_add/mod.rs`. A classical reference
function was added to `src/point_add/kaliski_classical_replay.rs`.

### The K=2 step (switch `DIALOG_GCD_K2`, set to `1`)

`dialog_gcd_k2_enabled()` reads the switch.

1. **Forward walk**, in
   `emit_dialog_gcd_compressed_sidecar_tobitvector_steps_block_lifecycle`.
   After the usual step (fused comparator → `cswap` → controlled `v −= u` →
   free `dialog_gcd_shift_right_assuming_even` relabel), it adds:
   ```
   s2 = raw_block[6 + slot]          // the step's shift2 bit, |0⟩
   cx(v_active[0], s2); x(s2)        // s2 = NOT v[0]: v still even
   for i in 0..len-1: cswap(s2, v_active[i], v_active[i+1])   // v >>= 1 if s2
   ```
   The cascade is a controlled right rotation. When `s2 = 1` the bit that
   wraps to the top is the 0 from `v[0]`, so it is an exact halving. It costs
   about `active_width − 1` Toffoli per step.
2. **Reverse walk**, in `..._steps_reverse_block_lifecycle`. It runs the
   cascade in reverse order, then `x(s2); cx(v_active[0], s2)`. After the
   un-shift `v[0]` is back to the value `s2` was computed from, so `s2`
   returns to |0⟩ exactly.
3. **Apply passes**: `..._apply_bitvector_block_lifecycle` (used by the
   multiply, `ipmul`) and `..._apply_bitvector_reverse_exact_block_lifecycle`
   (used by the quotient).
   - After the unconditional `mod_double_inplace_fast(y)`, or
     `mod_halve_inplace_fast(y)` in the reverse-exact pass, they call the new
     `cmod_double_inplace_lazy(y, p, s2)`, or `cmod_halve_inplace_lazy`.
   - These are controlled versions of the lazy Solinas double. A `cswap`
     cascade (256 Toffoli) shifts `y` left into an overflow wire. Then
     `c = 2^256 − p = 2^32 + 977` is added under control of the overflow, with
     the same truncated carry window as the uncontrolled double
     (`cadd_nbit_const_direct_trunc_fast`, window `KAL_DOUBLE_CARRY_TRUNC_W`).
     The overflow is cleared with one `ccx(ctrl, y[0], ovf)`.
   - With `ctrl = 0` they are the identity. Their reduction matches the
     uncontrolled double (same coset representative in [0, 2^256)), so the two
     compose. See [modular-fold](../concepts/modular-fold.md).
   - Debug knobs `DIALOG_GCD_K2_FORCE0` and `DIALOG_GCD_K2_NO_APPLY` can
     disable parts of this. They are unset.
4. **Transcript layout.** A block still covers
   `DIALOG_GCD_HIGH_TAIL_ALIAS_GROUP_SIZE = 3` steps.
   - The new `dialog_gcd_block_bits()` is 5 + 3 = 8. The two branch bits per
     step are still packed 6 → 5 by `emit_dialog_gcd_round763_compressor`. The
     three `shift2` bits are stored raw, uncompressed, after them.
   - The new `dialog_gcd_raw_block_len()` is 9: 6 raw branch bits plus 3
     `shift2` bits.
   - All block indexing now uses these functions instead of the constants:
     `dialog_gcd_compressed_sidecar_bits/_block`, `dialog_gcd_runway_layout`,
     `..._future_carry_slice`, `dialog_gcd_copy_compressed_block_to_raw`,
     `dialog_gcd_clear_raw_block_copy`, and the compress and decompress at
     each block boundary.
5. **Raw-block hosting is turned off under K2.**
   `dialog_gcd_host_reverse_raw_block_enabled()` returns false, because the
   hosts assumed a 6-bit block. Each pass therefore allocates its 9-qubit raw
   block once, up front, in `..._ipmul_block_lifecycle` and
   `..._quotient_block_lifecycle`.
6. **Leftovers that do nothing.** A `k2_shift2_log: Vec<QubitId>` field is
   added to the builder `B`. It is freed if non-empty, but nothing fills it.
   `kaliski_iter_classical_k2` in `kaliski_classical_replay.rs` is a classical
   model of the K=2 step (one conditional extra shift with an extra `r`
   doubling). Nothing in the build calls it.

### Where the Toffoli goes

These numbers come from replaying the width formulas. They are estimates,
and only the total is measured.

- **Walks.** Per walk, the summed `active_width` drops from 55,570 bits
  (393 steps) to 40,922 (259 steps). The comparator sum goes from about 19,050
  to 18,422. The new cascade adds about one Toffoli per bit. Per walk that is
  about 3 × 40,922 + 18,422 + 40,663 ≈ 181,900 Toffoli, against
  3 × 55,570 + 19,050 ≈ 185,800 before. So the four walks save only about
  15,600 Toffoli in total.
- **Apply passes.** The rest, about 119,000, comes from the two apply passes.
  Each pass loses 134 steps of about 1,000 Toffoli each (a lazy double plus a
  controlled 256-bit modular add with folds). It gains 259 conditional doubles
  of about 315 Toffoli each (a 256-bit `cswap` cascade plus a 57-bit truncated
  constant add).

### Where the qubits go

- The transcript grows from 655 bits (131 blocks × 5) to 696 (87 × 8).
- Replaying `dialog_gcd_runway_layout` with the new slope and the 8-bit
  stride, 208 of those bits are parked on high `u` lanes. Before, 245 of 655
  were. So the freshly allocated transcript goes from 410 to 488 bits.
- The raw block is no longer hosted.
- The measured net peak is +44. The commit does not show which phase now
  binds, so the split between these items is not established.

## Why it is still correct, and what it risks

- **The K=2 step is exact.** A second halving of an even `v` is exact. Its
  bit is recorded, the reverse walk uncomputes it exactly, and the apply
  pairs every recorded halving of `v` with one doubling (or halving) of `y`.
  So the Bézout bookkeeping is the same as when two 1-shift steps run in a
  row.
- **What is probabilistic** is the same set of approximations as before, now
  re-tuned for the new walk:
  - the 259-step limit, since an input that needs more steps does not
    converge;
  - the width envelope (slope 0.95, margin 25), which drops bits assumed to
    be zero;
  - the 74-bit truncated branch comparator;
  - the truncated carry windows of the doubles and folds, both widened from
    20 to 24 bits.
  The conditional doubles use the same truncated constant add, so there are
  more truncated adds per pass. That is presumably why the windows were
  widened.
- **How a failure shows.** A non-converged or mis-branched input gives a
  classical mismatch, and usually ancilla garbage after the reverse walk. A
  carry escaping a truncated window gives a wrong coefficient, so a classical
  mismatch.
- The author reports 0 classical, 0 phase and 0 ancilla failures over all
  9,024 shots at `DIALOG_TAIL_NONCE=124`. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The census files this as Windowing → K2 transcript pair-compressor. The diff
does not compress anything new. The branch-bit packer (6 → 5) is unchanged,
and the new `shift2` bits are stored raw (the code comment says "Prototype
stores shift2 UNCOMPRESSED"). The saving comes from changing the GCD step
itself, so that it consumes up to two factors of 2 per step. The walk is a
third shorter, and the apply passes do far fewer modular adds.
"Algorithmic Substitution → GCD step variant (bounded double shift)" would
describe it better. The published label is kept in the header.

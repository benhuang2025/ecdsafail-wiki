## Summary

Step 7 of the trailmix point addition adds `3·ox` to the `x` register, where
`ox` is the classical `x` coordinate of the second point, known per shot as
classical bits. The base did this on qubits: it loaded `ox` into a quantum
register, ran `mod_add`, doubled the register modulo p, ran `mod_add` again,
and halved it back.

Because `ox` is classical, `3·ox mod p` is a classical value too. This commit
computes it with classical-bit operations (`BitStore0`, `BitStore1`,
`BitInvert` under conditions). The scorer counts only Toffoli-class gates, so
that costs nothing. It then loads the result and does one modular add. The
second add, the doubling and the halving disappear. The one remaining add uses
a full-width overflow compare instead of the usual 19-bit one, which takes
back part of the saving. Net −163 average Toffoli at 1159 qubits.

## What changed and why it saves Toffoli

**`trailmix_ludicrous/ec_add.rs`, `coord_add3x(dst, coord)`.**

- Base: a 257-bit temp register loaded with `ox` by `x_if_bit`, then
  `mod_add(temp, dst)`, `mod_double(temp)`, `mod_add(temp, dst)`,
  `mod_double_reverse(temp)`, unload, free. That is two modular adds (vented
  256-bit add, `+f` window, 19-bit measured compare) and two `+f` windows for
  the doubling and halving.
- New:
  1. `three_coord = classical_times3_mod_q(coord)`: 256 classical bits holding
     `3·ox mod p`.
  2. Load them into a 256-bit temp with `x_if_bit`.
  3. `mod_add_exact(temp, dst)`.
  4. Unload and free the temp, then reset the derived bits with `bit_store0`.

**`classical_times3_mod_q`** (new, `ec_add.rs`). All of it is classical-bit
arithmetic run unconditionally on every shot:

1. `s = ox + ox + ox` in a 258-bit classical register, with three calls to
   `classical_add_into`, a ripple-carry add over `BitId`s. The majority carry
   is built with `bit_and_xor_into`, and the sum with `bit_xor_into`.
2. `s = hi·2^256 + lo`, with `hi ∈ {0, 1, 2}`. Since `2^256 ≡ C = 2^32 + 977`,
   the value is `r = lo + hi·C`. The addend `hi·C` is built as a 35-bit
   register from `C` gated on `s[256]` and `2C` gated on `s[257]`.
3. `r < 2^256 + 2C < 2p`, so one conditional subtraction of `p` is enough.
   Compute `tmp = r + C`. Then `r ≥ p` iff `tmp` has bit 256 or 257 set
   (`geflag`). The result is `low256(tmp)` if `geflag`, else `low256(r)`,
   selected bit by bit with conditioned `bit_store1`.
4. All scratch bits are reset to 0.

**`trailmix_ludicrous/arith.rs`, new `mod_add_exact(x, y)`.** Same as
`mod_add` (vented uncontrolled add with carry-out on an ancilla, clean gated
`+f` window), but the overflow flag is cleared by
`controlled_lt_msbs_conditional(…, k = n = 256)`, a full-width measured compare,
instead of the top `MSBS = 19` bits. It still runs only on the shots where
the `hmr` outcome is 1. See
[comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).

**Toffoli count.** The base step had two modular adds and two extra fold
windows. The new step has one add with a 256-bit compare, which costs more
than a 19-bit one on about half the shots. The code comment estimates about
754 → 326 Toffoli. The measured net is −163, so the exact compare and the
other costs used up more of the saving than that estimate assumed.

**Plumbing (`src/point_add/mod.rs`, `trailmix_ludicrous/mod.rs`).**

- New `B` helpers `bit_store0`, `bit_store1`, `bit_invert`, `bit_copy`,
  `bit_xor_into` and `bit_and_xor_into`. They emit the classical op kinds
  `BitStore0`, `BitStore1` and `BitInvert` under the current condition stack.
- `trailmix_ludicrous` and `ec_add` become `pub mod`, and `B::new_for_test` /
  `take_ops` are added, for test builders `build_times3_test`,
  `build_add3x_test` and `build_add3x_test_orig` (the old body kept as
  `coord_add3x_orig`). None of these is called by `build()`.
- The unused imports `mod_double` and `mod_double_reverse` are dropped from
  `ec_add.rs`.
- `DIALOG_TAIL_NONCE`: 200001456973 → 700001365225.

Why classical bits are free: the evaluator charges the Toffoli count only for
CCX and CCZ gates whose condition holds, and classical bit operations are
neither (see [scoring-and-validation](../concepts/scoring-and-validation.md)).
The step runs off the qubit peak, so the peak is unchanged; the temp is now
256 wires instead of 257.

## Why it is still correct, and what it risks

- **The classical part is exact.** `3·ox mod p` is computed with full
  carries, and `ox < p` on every shot, so `r < 2p` and one conditional `−p`
  gives the canonical value.
- **The quantum add.** `dst += t (mod p)` with `t < p`. The full-width compare
  clears the overflow flag correctly on every input. The `+f` window is still
  the usual 52-bit one, so the rare dropped-carry case (about `2^-19` when it
  fires) remains, as in every other modular add. Overall this step has fewer
  approximate parts than before (one window instead of four, no truncated
  compare).
- A wrong result would be a classical failure; a wrong phase repair a phase
  failure; a classical scratch bit left at 1 does not matter to the
  evaluator, but they are all reset anyway.
- The shipped nonce 700001365225 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures (avg 1,380,547.734 Toffoli,
  per the author's run).

## Classification rationale

The saving comes from moving a computation on per-shot classical data
(`3·ox mod p`) out of the quantum circuit into free classical-bit operations.
That is host-derived / classical specialization, the published label.

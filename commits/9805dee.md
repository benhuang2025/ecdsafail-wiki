## Summary

The ping-pong divider has a few constant adds outside the main replay cells.
They add or subtract the fold constant `f = 2^32 + 977`, or `f − 1`, under a
control bit. The adder computes one carry per bit position with a Toffoli. In
these calls the first four carries are always 0, either because of the
constant's low bits or because of a fact the call site knows. This commit adds
adder variants that skip those positions, and switches the five call sites
(ten calls per point addition) to them. The result is the same on every input, so the change
is exact.

The saving is 3 or 4 Toffoli per call, 34 per point addition. The measured
change is −39 against the base and −31 against the git parent. Those two trees
have the same circuit, so the spread is test-draw noise from the new nonce.
Qubits are unchanged.

## What changed and why it saves Toffoli

1. **New helpers in `src/point_add/arith/const_arith.rs`** (181 added lines):
   - `dead_low_carry_run(c, last, first_carry_is_zero)` counts the low carry
     positions that are always 0. Position 0 is dead if bit 0 of `c` is clear,
     or if the caller passes `first_carry_is_zero = true`. Each following clear
     bit of `c` extends the run, because a carry into a position whose constant
     bit is 0 is `acc[i] AND carry_in`, which is 0 when `carry_in` is 0.
   - `cadd_nbit_const_direct_trunc_fast_dead_low(b, acc, c, ctrl, window, first_carry_is_zero)`
     and `csub_nbit_const_direct_trunc_fast_dead_low(..., first_borrow_is_zero)`
     are copies of `cadd/csub_nbit_const_direct_trunc_fast`. They allocate
     carry wires only for positions `dead..=last` and treat the carry into
     position `dead` as absent. The compute, sum-write and `hmr` plus `cz_if`
     uncompute loops all start at `dead`. If the run is 0 they call the old
     function unchanged. See
     [adders-and-carries](../concepts/adders-and-carries.md), "Constant adders
     and dead low carries".
2. **Five call sites in `src/point_add/pingpong_div.rs`** switch to the new
   helpers. Note that `f = 2^32 + 977`, with 977 = `0b11_1101_0001`: bit 0 is
   set and bits 1–3 are clear. `f − 1` has bits 0–3 clear.

   | function | constant | why the first carry is 0 | dead run | Toffoli saved per call |
   | --- | --- | --- | --- | --- |
   | `conditional_mod_negate` (csub) | `f − 1` | bit 0 of `c` clear (`false` passed) | 4 | 3 |
   | `seed_round_one` (csub) | `f − 1` | bit 0 of `c` clear (`false`) | 4 | 3 |
   | `seed_round_one_inverse` (cadd) | `f − 1` | bit 0 of `c` clear (`false`) | 4 | 3 |
   | `mod_halve_pm` (csub) | `f` | the control `parity` is a copy of `target[0]`, so the borrow `NOT target[0] AND parity` is 0 (`true`) | 4 | 4 |
   | `mod_double_pm` (cadd) | `f` | the shift-up rotation leaves `target[0] = 0`, so `target[0] AND overflow` is 0 (`true`) | 4 | 4 |

   - For `f − 1` the old code already emitted nothing at position 0, but it
     still ran a Toffoli at positions 1–3 (`ccx(acc[i], carry[i−1], ...)`) on
     a carry that was always 0. For `f` with a zero first carry, the old code
     also ran the position-0 Toffoli. Each call also allocates 4 fewer carry
     wires.
   - **Per point addition** (divide traversal and multiply traversal):
     `conditional_mod_negate` runs twice per traversal (4 × 3 = 12).
     `seed_round_one` and `seed_round_one_inverse` run once each (2 × 3 = 6).
     `mod_halve_pm` runs at divide replay rounds 0 and 1, and `mod_double_pm`
     at multiply replay rounds 0 and 1 (4 × 4 = 16). Total 34 Toffoli. These
     Toffoli run on every shot (none is under a classical condition), so the
     emitted and executed savings match.
   - The main replay cells (`signed_mod_add_pm_halve_fused`,
     `signed_mod_double_add_pm_fused`) are not touched.
3. **Tail nonce**: the `SUB4_PINGPONG_TAIL_NONCE` default in `build()`,
   `src/point_add/mod.rs`, goes from 48000070891 to 68367898080254.

The same helpers already existed on other lineages, in
[`8910bd1`](8910bd1.md), [`33e2b34`](33e2b34.md) and jackylee0424's `0440b62`.
They were not in odinfree's 1278-qubit line, and this commit brings them over.

## Why it is still correct, and what it risks

- **Exact.** Each skipped Toffoli wrote 0 into a fresh wire on every basis
  state, and its uncompute was an `hmr` of a wire that held 0. Dropping both
  leaves the sum and the phase unchanged. The two call-site facts hold by
  construction: `mod_halve_pm` copies `target[0]` into `parity` just before the
  subtract, and `mod_double_pm` rotates a fresh zero wire into `target[0]`
  just before the add.
- **No new hard inputs.** The truncation windows (`endpoint_fold_window()`,
  and 32 for the seeds) are unchanged, so λ is the base's λ.
- If a call-site fact were false, the carry would be dropped and the output
  would be wrong, which the classical channel would catch.
- The op stream still changed, so the island re-rolls and a new nonce was
  needed. The shipped nonce `68367898080254` draws a clean test set: 9,024 of
  9,024 shots, with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change shortens the low end of fold carry chains, exactly. The census files
this lever as fold/carry truncation, so the classification is kept. Runner-up:
host-derived / classical specialization, as used for `33e2b34`, because the
dead run is derived from the classical constant and from call-site facts.

## Summary

The scorer charges every CCX whose classical condition holds, even if its two
quantum controls are never both 1 at the same time. Such a gate costs a Toffoli
and does nothing. This commit ships a list of 13,873 positions in the final op
stream where the CCX was screened as never firing. `build()` deletes them as a
last pass, after the single-CCX fanout rewrite.

Average executed Toffoli drops by 13,014. That is less than 13,873, because
some of the dropped gates sit under a measurement condition and were only
charged on some shots. Qubits stay at 1159. The tail nonce was re-hunted on
the stripped stream.

This was the first positional dead-CCX strip on the trailmix tree. The next
four commits in this batch extend or regenerate the list:
[`20b9a1d`](20b9a1d.md), [`6c0769f`](6c0769f.md), [`27d4627`](27d4627.md) and
[`985eaec`](985eaec.md).

## What changed and why it saves Toffoli

1. **New data file `src/point_add/drop_dead_robust_13873.idx`** (generated,
   13,873 lines).
   - Each line is one zero-based op index into the post-fanout stream. The
     indices run from 15,148 to 10,116,571, and the stream has about
     10.12 M ops.
   - The loader skips empty lines and lines starting with `idx`, and reads the
     first tab-separated field of the rest. This file has neither, so it is
     just indices.
2. **`src/point_add/mod.rs`, `build()`.**
   - After the `single_ccx_fanout::rewrite_first_target_fanout` loop, a new
     block runs `include_str!("drop_dead_robust_13873.idx")`, collects the
     indices into a `HashSet`, and keeps only the ops whose position is not in
     the set. It prints `DROP_DEAD_ROBUST: removed …`.
   - Nothing switches the block off. Later commits add a
     `DROP_DEAD_ROBUST_DISABLE` switch.
   - `DIALOG_TAIL_NONCE` goes from 200003194569 to 950803143946. The tail sits
     at the very end of the stream, past the last listed index, so changing it
     does not shift the indices.
3. **Why it saves Toffoli.** `src/sim.rs` charges a CCX or CCZ by its condition
   mask before it looks at the controls. A CCX whose controls are never both 1
   is charged but has no effect. Deleting it removes that charge. Many gates in
   this tree are like that, for example carry CCXs into wires that the
   schedule makes zero on typical inputs, which the static constant-propagation
   pass cannot prove zero. See [dead-gate-strip](../concepts/dead-gate-strip.md)
   and [scoring-and-validation](../concepts/scoring-and-validation.md).
4. **How the list was made.** The author's note calls the gates "inert but
   charged (value-neutral)". It says the list came from a "siege screen". The
   screen itself is not in the repo.
   - The follow-up [`20b9a1d`](20b9a1d.md) describes the method for this
     lineage. A bit-sliced simulator records, per CCX, the OR over shots of
     "both controls were 1". A single 9,024-shot pass flags about 49 k gates.
   - Most of those are idle only by coincidence on that one input set. The
     "robust" core is what stays unfired across many independent random input
     sets.
   - So this is an empirical census, not a proof.
5. **`src/point_add/trailmix_ludicrous/square.rs`: inactive code.**
   - The commit adds `kara_square_into_prod`, a second Karatsuba level for the
     square's half-products, and its helpers `add_value_into_prod_span`,
     `build_kara_sum`, `unbuild_kara_sum`, `kara_square_into_prod_reverse`,
     `sub_into_reg` and `add_into_reg`.
   - `mod_square_sub_pm_secp256k1_symmetric` now calls
     `kara_square_into_prod` / `_reverse` in place of
     `symmetric_square_into_prod` / `_reverse`.
   - The new function falls straight back to the old one unless
     `TLM_SQUARE_KARA2=1`, and nothing sets that variable. So the emitted
     stream is the same, and the drop indices match it.

## Why it is still correct, and what it risks

- **Empirical, not exact.** A listed CCX that does fire on some input changes
  that input's result or leaves a phase behind. Each such input is a new hard
  input. Validation catches it as a classical failure, or as a phase failure
  if the gate sat inside a measured-erase recompute. It cannot show up as an
  ancilla failure unless it touches a scratch wire.
- **Positional and fragile.** The indices are tied to this exact stream. Any
  upstream edit, including one to an earlier op count, shifts them, and the
  strip then deletes live gates. That is why every later circuit change in this
  lineage regenerates the list.
- The shipped nonce `950803143946` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. The author found it with a
  CUDA port of the trailmix shot predictor (jump-2 GCD plus the `f`-fold value
  channel, with byte-exact Fiat–Shamir), and confirmed the candidates on CPU.
  See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit deletes gates that do nothing on the screened inputs, so it is
filed as dead-gate removal. The label is right. Note that it is an empirical
strip, the "census" kind on the concept page, not an exact self-inverse
removal.

5. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no

   - 1159 qubits

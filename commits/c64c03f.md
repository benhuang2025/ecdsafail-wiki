## Summary

In early June the circuit computed the slope's division with the
`DIALOG_GCD` route in `src/point_add/mod.rs`: a reversible binary GCD runs a
fixed number of steps on `(u, v)`, records two branch bits per step (plus a
K=2 "second shift" bit), and an "apply" loop replays those decisions on the
Bézout pair `(x, y)`. Each replayed step doubles `y` modulo p, once always and
once more when the K=2 bit is set.

This commit changes two knobs and the tail nonce. The modular double and
halve now stop their carry chain one bit earlier (window 23 → 22), which saves
one Toffoli per call. The GCD runs one step fewer (260 → 259), which removes a
whole step of transcript, apply and reverse work. Together they save 4,154
average Toffoli at the same 1320 qubits. Both are probabilistic cuts. A
re-hunted tail nonce, 335, draws a test set on which neither one fails.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`KAL_DOUBLE_CARRY_TRUNC_W`: 23 → 22.**
   - `double_carry_trunc_window()` returns this value. When it is set,
     `mod_double_inplace_fast_with_dirty`, `mod_halve_inplace_fast_with_dirty`
     and the K=2 controlled forms `cmod_double_inplace_lazy` /
     `cmod_halve_inplace_lazy` use the truncated sparse-constant adders
     `cadd_nbit_const_direct_trunc_fast` and `csub_nbit_const_direct_trunc_fast`.
   - The modular double shifts `v` left by one, so the old top bit lands in
     `ovf`, and then adds `c = 2^256 − p = 2^32 + 977` controlled on `ovf`
     (Solinas reduction). The halve is its exact gate inverse.
   - The truncated adder only makes carry wires `0..=last`, with
     `last = hi + window` and `hi = 32`, the top set bit of `c`. The last carry
     moves from bit 55 to bit 54. `c` has no set bits above 32, so each removed
     carry position costs exactly one CCX (`ccx(acc[i], carry_{i−1}, carry_i)`)
     and its carry wire is erased by `hmr` plus a `cz_if`, which costs no
     Toffoli. See [adders-and-carries](../concepts/adders-and-carries.md) and
     [measurement-uncompute](../concepts/measurement-uncompute.md).
   - So every call saves 1 Toffoli. The apply loop
     (`emit_dialog_gcd_compressed_sidecar_apply_bitvector_*_block_lifecycle`)
     makes two doubling calls per step (the unconditional double and the K=2
     conditional double), and its reverse makes two halvings per step.
2. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 260 → 259.**
   - `dialog_gcd_active_iterations()` sets how many binary-GCD steps every
     loop runs: the forward transcript (`..._tobitvector_steps`), the apply on
     `(x, y)` and their reverses. With `DIALOG_GCD_K2=1` each step strips up to
     two trailing zeros, so 259 steps are enough for almost every input pair.
   - Dropping the last step removes its branch compare, cswap, controlled
     subtract and shift (narrow at that point, because the width envelope is
     near its floor) and, in every apply pass, a full 256-bit step: two modular
     doubles, a controlled modular add `y += x` and a 256-wire cswap.
   - The base author had gone 258 → 260 to remove residual phase failures. This
     commit gives one of those steps back.
3. **`DIALOG_TAIL_NONCE`: 108 → 335.** `build_builder()` ends with 48 `X;X`
   pairs on `tx[0]` or `tx[1]`, chosen by the nonce bits. They are exact
   identities that change only the op-stream hash, and so the 9,024 test
   inputs. Toffoli and qubits do not depend on it.

The author did not measure the two savings separately, but the next commits
give the split. [`229aeed`](229aeed.md) makes the same 260 → 259 cut alone on
a sibling tree and measures −3,116 Toffoli. That leaves 4,154 − 3,116 = 1,038
for the window, which matches the −1,038 the base's comment records for the
previous one-bit step of the same window (24 → 23). So about 1,038 truncated
double/halve calls run per shot.

## Why it is still correct, and what it risks

- **Window.** The truncated adder is wrong only when a carry from the low 33
  bits runs through every bit above 32 up to the window edge, that is, a run
  of about 23 ones in `y` just above bit 32. That is about 2^−23 per call,
  twice the base's rate, over roughly a thousand calls per shot. Forward and
  inverse use the same window, so double and halve stay exact inverses
  whenever no truncation fires. A trigger corrupts the high bits of `y`, which
  shows up as a classical mismatch (and can leave ancilla garbage downstream).
- **Iterations.** An input whose GCD needs all 260 steps no longer reaches
  `v = 0`. The transcript is then incomplete and the result is wrong, which
  shows up as a classical failure, or as phase garbage when the unfinished
  registers are uncomputed.
- The author's comment says the window cut by itself leaves "a small dirty
  island", and that stacked with the 259 cut it validates. The new nonce 335 draws a clean test set: 9,024 of 9,024 shots, with
  0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is iteration/threshold tuning, which fits the step-count
cut from 260 to 259. The other knob is a carry-window truncation, so
comparator/width truncation was the close runner-up. Both remove work that
almost never matters.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 06b07ee -- src/point_add`.
   - Do not start from the git parent `a92d098`. That is newjordan's tree, which
     also narrows `KAL_FOLD_CARRY_TRUNC_W` from 23 to 22 and changes
     `DIALOG_POST_SUB_REROLL` (503292 → 631921) and the nonce. Diffing against
     the parent would wrongly show this commit putting the fold window back to
     23 and the reroll back to 503292.
   - Against `06b07ee`, `git diff --ignore-cr-at-eol 06b07ee c64c03f -- src/point_add`
     is 24 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol c64c03f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `KAL_*`, `DIALOG_*` or `SUB4_*` environment variables set, because they
   override the defaults. Expect:
   - 1320 qubits
   - 1,561,263 average Toffoli (rounded)
   - score 2,060,867,160
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `335` and an identical op stream.
Any other change needs a new nonce hunt.

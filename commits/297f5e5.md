## Summary

Two constants change in `src/point_add/kaliski_state.rs`:
- the carry-tail window `W` of the truncated direct constant adder and
  subtractor goes from 36 to 23 bits;
- `R_SMALL_THRESHOLD` goes from 325 to 319.

The window cut saves Toffoli: about 1,250 truncated constant add and subtract
calls each compute 13 fewer carry positions. The threshold change costs
Toffoli. Six more Kaliski iterations now do a full modular doubling of `r`
instead of a free shift. That change is there only because it draws a test
set on which the small windows are clean. Net: −14,607 average Toffoli at
the same 2309 qubits.

The submission note gives the score as 5,651,540,863. That is an arithmetic
slip. 2309 × 2,448,307 = 5,653,140,863, which is the leaderboard figure.

## What changed and why it saves Toffoli

1. **`kal_carrytail_w()`: 36 → 23**, on the default branch where the add path
   is truncated.
   - `kal_carrytail_count_c` gives `cut = max(33, c.bit_len()) + W`. For the
     sparse constant `c = 2^32 + 977` that is 56 instead of 69.
   - The adder `cadd_nbit_const_direct_fast` and the subtractor
     `csub_nbit_const_direct_fast` (`cuccaro.rs`) compute carries or borrows
     only up to that point. Each position above bit 32 is one CCX.
   - The author's sweep at R = 319 drops 2,502 Toffoli per 2 bits of `W`
     (W = 35: 2,463,319; 33: 2,460,817; …; 23: 2,448,307). So about 1,251
     calls per point addition use the window. These are the Kaliski `r`
     doublings past the threshold, the `mod_double_inplace_fast` doublings
     (mainly pair2's `lam` doublings) routed through the direct adder by
     [`ba05d3a`](ba05d3a.md), the pair1
     halvings, and the low-scratch modular adders and Solinas folds.
2. **`R_SMALL_THRESHOLD`: 325 → 319.**
   - Below the threshold, Kaliski STEP 6–8 doubles `r` with
     `mod_double_no_corr`, a Toffoli-free rotate. From the threshold on, it
     uses the full double with a `+c` correction.
   - Iterations 319 to 324 now pay for the full double. At W = 36 that costs
     1,656 Toffoli (2,464,570 at R = 319 against 2,462,914 at R = 325).
   - It is also the more conservative setting.
3. The comments are rewritten with the sweep. `K0` stays 25, since 24 and
   below fail on this island.

## Why it is still correct, and what it risks

- **R_SMALL at 319** is safer than 325. The no-correction rotate is wrong
  only if `r`'s top bit is already 1, and that bet now ends six iterations
  earlier.
- **The 23-bit window is the risky part, and it is risky on the ADD side.**
  A carry above bit 32 survives only through a run of 1-bits of the
  accumulator (for adds) or of 0-bits (for subtracts). The 3M-trial Monte
  Carlo in the comments found runs of up to 19 bits for subtracts and up to
  28 bits for adds.
  - The note cites only the 19-bit subtract figure ("4 bits above … →
    arithmetically exact").
  - A 23-bit window is **below** the 28-bit run seen for adds. So the add
    path is now truly probabilistic. A run of 23 or more 1-bits happens with
    probability about 2^-23 per call that has a carry out of bit 32.
  - Over about 9,024 shots × hundreds of add calls, that is on the order of
    one expected failure per test set. A dropped carry gives a wrong modular
    double or sum, and so a classical mismatch.
- **Island.** There is no nonce in this era. The window and threshold were
  swept together with the full 9,024-shot evaluator:
  - At R = 325, no window below 36 was clean.
  - At R = 319, windows 35, 33, 29, 27, 25 and 23 were clean, and 22, 21
    and 20 failed.
  - Other thresholds (318, 316, 315, 310, 308, 306, 305) failed at W = 23,
    or were clean but more expensive (314, 313, 311, 307).
  - The note reports that `KAL_UV_CSWAP_MARGIN` 0 to 3 gives the same
    count. That is expected: this tree never reads that variable. It is
    on the `a25248f` line, which truncates the swaps through
    `kal_cswap_wtrunc_enabled`, not `404d630`'s `kal_uv_cswap_width`.

  This draw is clean: 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The published label is iteration/threshold tuning, after the
`R_SMALL_THRESHOLD` change. But that change costs Toffoli and only serves the
island. All of the saving comes from cutting the constant-adder carry chains
further, so the diff fits Dead-Code and Redundancy Elimination → fold/carry
truncation better. The header keeps the published label.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout ba05d3a -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol ba05d3a 297f5e5 -- src/point_add` is
   27 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 297f5e5 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,448,307 average Toffoli (rounded)
   - score 5,653,140,863
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

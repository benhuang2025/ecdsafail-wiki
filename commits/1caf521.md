## Summary

This commit changes two constants, both of which make truncated arithmetic
narrower. The apply-phase overflow/underflow clean compare goes from 19 to 18
bits. The dialog GCD's per-step register width now shrinks a little faster
(slope 1.017 instead of 1.015 bits per step), which makes 35 of the 258 GCD
steps 2 bits narrower. Together they save 1,344 average Toffoli at 1168
qubits. The tail nonce was re-hunted.

## What changed and why it saves Toffoli

All edits are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: `"19"` → `"18"`.** It is set in two
   places, and the first one wins.
   - This is the default width of the top-bit comparison that clears the
     overflow (or underflow) flag after each controlled modular add (or
     subtract) in the apply phase. Steps listed in
     `DIALOG_GCD_SPECIAL_{OVERFLOW,UNDERFLOW}_CLEAN_STEP_BITS` keep their own
     20- to 26-bit widths.
   - The compare runs as a phase repair after an `hmr`, on about half of the
     shots. One bit less saves about one Toffoli per default-width site.
   - See [`f50ae3b`](f50ae3b.md) for the mechanism and
     [measurement-uncompute](../concepts/measurement-uncompute.md).
2. **`DIALOG_GCD_WIDTH_SLOPE_X1000`: `"1015"` → `"1017"`.** It is set in two
   places, and the first one wins.
   - `dialog_gcd_width_slope()` (`rounds/dialog/mod.rs`) returns it divided by
     1000.
   - `dialog_gcd_tobitvector_active_width(step)` sets the width of the GCD
     work registers at each step as `256 − step·slope + DIALOG_GCD_WIDTH_MARGIN (10)`.
     It rounds up to an even number, adds any per-step bump and clamps to 256.
   - Every GCD-body op runs at that width: the swap, the subtract and the
     compares.
   - With the steeper slope, the rounded width drops by 2 bits at 35 of the 258
     steps (for example step 59: 208 → 206, step 256: 8 → 6) and is unchanged
     elsewhere. Each narrower step drops a few Toffoli from each body op.
   - See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
3. **`DIALOG_TAIL_NONCE`**: `"18100027017098"` → `"2150000021998006"`, in all
   three places.

## Why it is still correct, and what it risks

The submission note calls both cuts "value-exact". They are not: both are
probabilistic truncations.

- **The 18-bit compare** is wrong when the top 18 bits of the two registers tie.
  That happens with probability about 2^-18 per site, and it shows up as a
  phase failure.
- **The width envelope** assumes that `max(bitlen(u), bitlen(v))` shrinks by
  at least 1.017 bits per step on average, with a 10-bit margin. An input
  whose GCD shrinks more slowly overflows the narrowed register. Its high bits
  are then dropped, which gives a classical failure.

Both raise Lambda a little. Nonce `2150000021998006` draws a test set with no
such input: 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.
See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both changes narrow a truncated comparator or register width, which is
comparator/width truncation.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 35ceb01 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 35ceb01 1caf521 -- src/point_add` is
   14 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings.
3. **Check the tree.** `git diff --ignore-cr-at-eol 1caf521 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `SQUARE_*`, `MOD_*` or `KAL_*` environment variables set. Expect:
   - 1168 qubits
   - 1,432,332 average Toffoli (rounded)
   - score 1,672,963,776
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `2150000021998006` and an identical
op stream. Any other change needs a new nonce hunt.

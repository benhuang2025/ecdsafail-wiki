## Summary

This is the fourth time the same 58 → 57 cut lands on a new tree, after
[`975b73f`](975b73f.md), [`14b84f1`](14b84f1.md) and [`d2b4bcf`](d2b4bcf.md).
All three were dropped when later frontier commits were built on older trees. Each
dialog-GCD step decides `u > v` from only the top bits of the two registers.
The per-step width comes from a schedule plus a margin and is capped by
`DIALOG_GCD_COMPARE_BITS`. Lowering the cap from 58 to 57 removes one bit on
the 266 steps where the cap binds. The comparator runs four times per step
at one Toffoli per bit: 4 × 266 = 1,064 Toffoli, exactly the measured change.
Qubits are unchanged. The reroll pair was re-searched.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`:

1. **`DIALOG_GCD_COMPARE_BITS`: 58 → 57.**
   - `dialog_gcd_compare_bits_for_step(step, active_width)` returns
     `min(DIALOG_GCD_PA9024_COMPARE_SCHEDULE[step] + MARGIN, active_width, DIALOG_GCD_COMPARE_BITS)`.
     On this tree the margin is 7, the width margin is 26, and there are 395
     steps.
   - Recomputing the table, the 57 cap binds on 266 steps (steps 48 to 319).
     The summed compare width drops from 19,810 to 19,544 bits. That is more
     steps than the 254 in `d2b4bcf`, because the schedule margin is now 7
     instead of 5, so `schedule + margin` exceeds 57 more often.
   - The comparator is the hosted branch-bit
     `ccx_cmp_lt_into_fast_borrowed_carries`, one Toffoli per bit, with
     carries cleared by `hmr` + `cz_if` (see
     [measurement-uncompute](../concepts/measurement-uncompute.md)). It runs in
     the forward and reverse transcript passes of both GCD passes:
     4 × 266 = 1,064 Toffoli.
2. **Reroll pair: `DIALOG_REROLL` 745,048 → 4,959, `DIALOG_POST_SUB_REROLL`
   679,742 → 5,983.** These are the identity `X;X` counts that only re-draw
   the 9,024 test inputs.

## Why it is still correct, and what it risks

The truncated comparison is approximate. When `u` and `v` agree on their top
57 compared bits it can return the wrong `u > v`. The step then takes the
wrong GCD branch, which shows up as a classical failure, or as phase or
ancilla garbage when the reverse pass no longer mirrors the forward pass. One
bit fewer roughly doubles the per-step risk on the 266 affected steps.

The reroll pair (4,959, 5,983) draws a clean set: 9,024 of 9,024 shots pass
with 0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows an approximate comparator, so
comparator/width truncation fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 339fe8d -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 339fe8d 238d366 -- src/point_add` is
   8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 238d366 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1434 qubits
   - 1,730,355 average Toffoli (rounded)
   - score 2,481,329,070
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=4959`,
`DIALOG_POST_SUB_REROLL=5983` and an identical op stream. Any other change
needs a new reroll search.

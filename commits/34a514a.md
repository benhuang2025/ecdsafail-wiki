## Summary

This changes one constant. After every modular add or subtract in the dialog
GCD's apply pass, an overflow flag has to be erased. The circuit erases it by
recomputing it from only the top `k` bits of the result and the addend. This
commit makes `k` 19 instead of 20, which puts back the value it had before
[`f42ce5c`](f42ce5c.md) widened it. One bit less costs one Toffoli less per
call, and there are 792 calls (an add and a subtract on each of the 396
steps), so the saving is exactly 792 Toffoli. Qubits are unchanged. The
reroll pair was re-searched.

## What changed and why it saves Toffoli

Both changes are in `configure_ecdsafail_submission_route()` in
`src/point_add/mod.rs`.

1. **`DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`: 20 → 19.**
   - Context: the apply pass does `acc = acc ± ctrl·a (mod p)`, one add or
     subtract per step. `dialog_gcd_cmod_add_materialized_pseudomersenne_chunked`
     first does the raw 257-bit add, whose top bit `acc_ovf` is the overflow.
     It then folds the overflow back with `c = 2^256 − p` (a pseudo-Mersenne
     fold, see [modular-fold](../concepts/modular-fold.md)). The flag
     `acc_ovf` still holds the overflow bit and must be returned to |0⟩.
   - After a modular add, overflow happened exactly when the reduced result
     is smaller than the addend. The circuit recomputes that from the top
     `k = APPLY_CLEAN_COMPARE_BITS` bits only:
     `ccx_cmp_lt_into_fast(acc[256−k..], a[256−k..], ctrl, acc_ovf)`. That
     costs `k + 1` Toffoli, with measured carry cleanup. The subtract does the
     mirror image in `dialog_gcd_clean_truncated_underflow`.
   - One bit less at each of the 2 × 396 = 792 calls is −792 Toffoli, the
     measured change.
2. **Reroll pair: `DIALOG_REROLL` 0 → 11, `DIALOG_POST_SUB_REROLL` 44 → 84.**
   These are the identity `X;X` counts that only re-draw the 9,024 test
   inputs. The comment above them was updated to list the new island.

## Why it is still correct, and what it risks

The truncated compare is an approximation. If the result and the addend agree
on all of their top 19 bits, the compare cannot tell which is smaller. The
flag is then erased wrongly, which leaves a dirty or phase-marked ancilla, and
the run shows ancilla or phase garbage. Going from 20 to 19 bits roughly
doubles that per-call chance. Since the operands are essentially random mod
p, it is about 2^-19 per call.

The reroll pair (11, 84) draws a clean set: 9,024 of 9,024 shots pass with
0 classical, 0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change narrows a truncated comparator, so
comparator/width truncation fits.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5a2d910 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 5a2d910 34a514a -- src/point_add` is
   10 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 34a514a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `DIALOG_*`,
   `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set, because
   `set_default_env` keeps any value already in the environment. Expect:
   - 1434 qubits
   - 1,732,781 average Toffoli (rounded)
   - score 2,484,807,954
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the reroll pair `DIALOG_REROLL=11`,
`DIALOG_POST_SUB_REROLL=84` and an identical op stream. Any other change
needs a new reroll search.

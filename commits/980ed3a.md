## Summary

Each apply step of each dialog-GCD division does two Solinas folds. Each
fold adds a multiple of `c = 2^256 − p = 2^32 + 977` into the low bits of a
register, with a carry chain cut off `w` bits above the constant's top bit:

- one fold after the K2 doubling or halving of `y`, with window
  `KAL_DOUBLE_CARRY_TRUNC_W`;
- one fold after the controlled modular add or subtract, with window
  `KAL_FOLD_CARRY_TRUNC_W`.

This commit lowers both windows by one bit. Above the constant's top bit
each carry position is one CCX, so each fold loses one Toffoli. That is
about 2 × 516 = 1,032 emitted Toffoli. The measured average fell by 1,001;
the 31 difference is draw variance in the conditioned Toffoli. Qubits are
unchanged.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`KAL_DOUBLE_CARRY_TRUNC_W`: 21 → 20.**
   - Read by `double_carry_trunc_window()` in `arith/const_arith.rs`. On
     this route it sets `last = min(n − 2, 33 + w)` in
     `dialog_gcd_fused_double_y` (forward apply) and
     `dialog_gcd_fused_halve_y` (reverse apply) in
     `rounds/dialog/compressed.rs`.
   - Those functions double or halve `y` by `2^(1+s2)` (the K2 pair step)
     and fold the overflow back as one combined constant `c·e + 2c·d`. That
     constant has set bits up to 33, and its add is done by
     `cadd_per_position_controls_trunc` / `csub_per_position_controls_trunc`.
   - Above bit 33 there are no constant bits, so each further carry
     position is one CCX, `carry ∧ y_i`. One position fewer is −1 Toffoli
     per call, over 258 steps × 2 divisions.
   - The same window is also read by the generic modular doublers in
     `arith/modular.rs`.
2. **`KAL_FOLD_CARRY_TRUNC_W`: 20 → 19.** This is the overflow fold
   `cadd_nbit_const_direct_trunc_fast(acc[..73], c, acc_ovf, w)` of the
   apply add, and its subtract twin. [da55bbb](da55bbb.md) made the
   previous one-bit cut on this window, 21 → 20, and explains it in detail.
   −1 CCX per call, 516 calls.
3. **`DIALOG_TAIL_NONCE`: 9300021269076 → 92428802.**

The emitted op count drops from 9,831,654 (see [da398df](da398df.md)) to
9,824,416. See [modular-fold](../concepts/modular-fold.md).

## Why it is still correct, and what it risks

Both cuts are probabilistic. A truncated carry chain gives a wrong sum when
a carry would have run through every bit of the window. That happens when
the register's `w + 1` bits above the constant's top bit are all 1, roughly
2^-21 (doubling fold, `w = 20`) or 2^-20 (add fold, `w = 19`) per call.
Each cut about doubles that rate. The route comments call the dropped carry
bits "0 on the reachable support" and say residual failures are dodged by
the nonce. A wrong fold corrupts `y` or the accumulator. That shows up as a
classical mismatch, and as phase or ancilla garbage when the later clean
misfires.

The shipped nonce `92428802` draws a test set with 0 classical, 0 phase and
0 ancilla failures over all 9,024 shots. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both changes narrow truncated carry windows by one bit, which is
comparator/width truncation. Strength Reduction → solinas / NAF fold is the
runner-up, because both windows belong to Solinas folds, but neither fold
changes structure.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout da398df -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol da398df 980ed3a -- src/point_add` is
   6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 980ed3a -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or `MOD_*` environment variables set. Expect:
   - 1285 qubits
   - 1,389,531 average Toffoli (1,389,531.214 before rounding)
   - score 1,785,547,335
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `92428802` and an identical op
stream. Any other change needs a new nonce hunt.

## Summary

This is the next step of the same sweep as [`7b3469b`](7b3469b.md). The
ping-pong multiply traversal's depth `SUB4_PP_ROUNDS_MUL` goes to
`rounds() − 4 = 696` rounds, while the divide stays at 700. Against the base
`e928607` (699 rounds) that is three rounds fewer, −1,300 average Toffoli.
Against the previous frontier `7b3469b` (697 rounds) it is one round fewer,
−377 Toffoli. Qubits stay at 1278. Each round cut adds a little convergence
risk to the multiply walk.

## What changed and why it saves Toffoli

1. **`rounds_for(PingPongDirection::Multiply)`** in
   `src/point_add/pingpong_div.rs`: the default of `SUB4_PP_ROUNDS_MUL` goes
   from `rounds() − 1` to `rounds() − 4`, so 699 → 696 rounds.
   - Every stage of the multiply traversal loops to `rounds_for(direction)`:
     the walk, the replay batches and the walk-back. Each removed round
     deletes one 256-bit replay cell plus a walk add and a walk-back add at
     the narrowest walk width.
   - The three steps from 699 measured −547, −376 and −377 Toffoli
     (`99d85b5`, `7b3469b`, this commit).
   - **Qubits.** The replay ladders fill the room under the cap
     `SUB4_PP_PEAK = 1278`, so a shorter tape does not lower Q. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md) and
     [pingpong-division](../concepts/pingpong-division.md) ("Depth").
2. **Tail nonce** (`src/point_add/mod.rs`): the default
   `SUB4_PINGPONG_TAIL_NONCE` goes from 6215000001 to 23188000022.

## Why it is still correct, and what it risks

- **Depth is a truncation.** An input whose multiply walk needs more than
  696 rounds to reach `(±1, ±1)` now gives a wrong product and dirty walk
  registers. That shows as classical and ancilla failures.
- At about +0.05 λ per round on one traversal (the `rounds_for` comment),
  the three-round cut adds roughly +0.15 λ to the base.
- The multiply walk tolerates more cutting than the divide. The concept page
  notes it "converges in slightly fewer rounds". Later trees go as far as
  `rounds() − 7` (`84a93cd`).
- The shipped nonce `23188000022` draws a clean test set: 0 classical,
  0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Cutting a fixed round count against a measured convergence rate is
iteration/threshold tuning.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout e928607 -- src/point_add`.
   - `git diff --ignore-cr-at-eol e928607 5c23d45 -- src/point_add` is 4
     changed lines in 2 files.
   - The git parent `7b3469b` is `e928607` at `rounds() − 3` with another
     nonce, so diffing against it is also 4 lines and shows only −3 → −4.
     Either base rebuilds the commit.
2. **Apply the patch below** from the repo root with
   `git apply --ignore-whitespace`. The flag lets the patch apply whether the
   files use LF or CRLF line endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 5c23d45 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set (in particular no `SUB4_PP_ROUNDS_MUL`). Expect:
   - 1278 qubits
   - 942,597 average Toffoli (rounded)
   - score 1,204,638,966
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `23188000022` and an identical op
stream. Any other change needs a new nonce hunt.

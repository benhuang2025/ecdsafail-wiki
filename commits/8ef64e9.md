## Summary

In early June the circuit divides with the dialog GCD, a fixed-length binary
GCD walk on `(u, v)` (background in [8316db1](8316db1.md) and
[412312f](412312f.md); see [dialog-gcd-early](../concepts/dialog-gcd-early.md)). Two knobs of that
walk are tightened together. The walk length goes from 394 to 393 steps, and
the safety margin of the per-step width envelope goes from 26 to 25 bits.

Both cut Toffoli: one step less of walk and apply work, and narrower
swap/subtract/compare loops on about half the steps. Together they also cut
the peak by 5 qubits. The walk's transcript is stored in 5-qubit blocks, one
per 3 steps, and part of it is parked on high `u` wires that the envelope says
are already zero. At 393 steps there is one block fewer (131 instead of 132),
and the narrower envelope lets the parked suffix keep its length. So one 5-qubit
block fewer is freshly allocated. Neither change does this alone. Both changes
are probabilistic, so a new tail nonce was hunted.

## What changed and why it saves Toffoli and qubits

All changes are in `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.

1. **`DIALOG_GCD_ACTIVE_ITERATIONS`: 394 → 393.**
   - Read by `dialog_gcd_active_iterations()`. It is the loop bound of every
     forward walk, reverse walk and apply pass of the two dialog-GCD divisions
     (`emit_dialog_gcd_compressed_sidecar_*`). The bound is capped by
     `DIALOG_GCD_MAX_ITERATIONS = 402`.
   - It also sets the transcript size:
     `dialog_gcd_compressed_sidecar_blocks() = ceil(iters / 3)`. Each block packs
     the two branch bits of 3 steps into
     `DIALOG_GCD_HIGH_TAIL_ALIAS_BLOCK_BITS = 5` qubits. 3 reachable symbols per
     step give 27 < 32 codes, so 5 bits suffice. The block count goes 132 → 131,
     and the full transcript 660 → 655 bits.
2. **`DIALOG_GCD_WIDTH_MARGIN`: 26 → 25.**
   - Read by `dialog_gcd_width_margin()` inside
     `dialog_gcd_tobitvector_active_width(step)`. That function returns
     `256 − 0.711·step + margin`, rounded up to an even number and clamped to
     [1, 256]. The slope 0.711 is `DIALOG_GCD_WIDTH_SLOPE_X1000 = 711`.
   - `active_width` is the width of three per-step loops: the branch `cswap`,
     the gated load and the subtract body (about 1 Toffoli per bit each). It
     also caps the truncated branch comparator in
     `dialog_gcd_compare_bits_for_step`.
3. **Why the peak falls by 5.** The route has
   `DIALOG_GCD_COMPRESSED_LOG_U_HIGH_RUNWAY=1` with `..._BLOCKS=999`. Then
   `dialog_gcd_runway_layout()` finds the longest suffix of transcript blocks
   that can be hosted on `u` lanes 249, 248, … down. Each lane must sit at or
   above the largest `active_width` of the 3 steps of its block, because a
   lane above the envelope is assumed to be |0⟩ by the time that block is
   written. Only the remainder,
   `dialog_gcd_allocated_compressed_sidecar_bits()`, is allocated fresh.
   Replaying that function:

   | steps, margin | blocks × 5 | parked on `u` | allocated |
   | --- | --- | --- | --- |
   | 394, 26 (base) | 660 | 245 | 415 |
   | 393, 26 | 655 | 240 | 415 |
   | 394, 25 | 660 | 245 | 415 |
   | 393, 25 (this commit) | 655 | 245 | **410** |

   The parked suffix is limited at its low end. Blocks go to descending
   lanes, so the last block lands on the lowest lanes, and those must still be
   above its steps' widths. In the base, the last block (131) holds only step
   393, which is very narrow, and it sits on lanes 9..5. Dropping step 393
   removes that block, and the parked suffix shrinks with it (blocks 83..130).
   Starting one block earlier would push block 130 down to lanes 9..5, under its
   width of 6. So 393 steps alone removes 5 parked bits, not 5 allocated ones.
   With margin 25 every width is about 1 bit lower, and the suffix can start at
   block 82. The narrower envelope alone does not change the count. Together,
   5 fewer qubits are allocated. That matches the 1355 → 1350 peak, so the
   allocated transcript is live at the peak phase.
4. **Toffoli.** Replaying the width formula, the summed `active_width` per walk
   goes from 55,930 to 55,570 bits (−360, about 3 Toffoli per bit), and the
   summed comparator width from 19,126 to 19,050 (−76). Over the four walks
   that is about 4 × (3 × 360 + 76) ≈ 4,620 Toffoli. The rest of the measured
   −6,824 (about 2,200) is the deleted step 393 in the apply passes, where each
   step costs a full 256-bit controlled modular add on the Bézout registers.
   This split is an estimate. The total is the measured value.
5. **`DIALOG_TAIL_NONCE`: 296434 → 385307.** At the end of `build_builder()`,
   48 identity `X;X` pairs are emitted, each on `tx[0]` or `tx[1]` according to
   one nonce bit. The op count and the action are fixed, and only the op-stream
   hash changes. That hash seeds the 9,024 Fiat–Shamir test inputs.
   `DIALOG_REROLL` and `DIALOG_POST_SUB_REROLL` are unchanged.

## Why it is still correct, and what it risks

Both levers are probabilistic.

- **393 steps.** The walk must bring `(u, v)` to its terminal state within the
  fixed step count. An input whose binary GCD needs 394 steps no longer
  converges. The reverse walk and the terminal-reuse logic then work on a
  wrong state. This shows up as a classical mismatch and usually as ancilla
  garbage.
- **Margin 25.** The envelope is a fitted line, not a bound. An input whose
  `u` or `v` still has a live bit above `active_width` loses it in the swap and
  the subtract. Margin 25 also widens the set of high `u` lanes that hold
  parked transcript bits. If a "zero" lane is in fact live when its block is
  written, both the transcript and `u` are corrupted.

The author notes that the margin cut "raises the circuit's true per-shot
failure rate, so islands are rarer". The shipped nonce `385307` draws a test
set with 0 classical, 0 phase and 0 ancilla failures over all 9,024 shots.
That clean draw is what makes the submission valid. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The main lever is the GCD step count, which is iteration/threshold tuning.
The width margin is a comparator/width truncation knob, and it is the
runner-up label. The peak drop needs both together, so the commit is
reasonably filed under the iteration change. The nonce comes with every
op-stream change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 39134ec -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 39134ec 8ef64e9 -- src/point_add` is
   14 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 8ef64e9 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` only fills
   in unset variables. Expect:
   - 1350 qubits
   - 1,763,987 average Toffoli (rounded)
   - score 2,381,382,450
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=385307` and an identical op
stream. Any other change needs a new nonce hunt.

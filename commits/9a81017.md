## Summary

The dialog GCD records a transcript for each step: two branch bits, plus one
`shift2` bit for the K2 second halving. The transcript must stay alive from
the forward pass, through the apply, to the reverse pass, so it holds qubits at
the peak. The base packed three steps (9 raw bits) into 8 stored bits.

This commit packs two steps (6 raw bits) into 5 stored bits. That works
because consecutive steps are correlated. If step A did not halve twice, then
`v` is odd at step B, so B's `b0` bit is 1. Only 15 of the 32 combinations of
the five bits (A's three bits plus B's two branch bits) can occur. A 6-Toffoli
reversible encoder maps them into 4 bits, and B's `shift2` stays raw. Storage
drops from 2.67 to 2.5 bits per step, and the raw staging block shrinks from 9
to 6 wires. The peak falls from 1319 to 1313.

The cost is +3,408 Toffoli, because the new encoder is run 8 × 129 times
instead of the old 4-Toffoli compressor 8 × 87 times. The commit also gives
back one bit of the apply overflow-clean comparator (19 → 20, +518), which
makes a clean nonce easier to find. The net is +3,926 Toffoli for −6 qubits,
which lowers the score.

## What changed and why it saves qubits

Background (see [transcript-codecs](../concepts/transcript-codecs.md) for the K2 transcript). In this route
(`src/point_add/mod.rs`) each GCD step writes `b0 = v[0]` and
`b0_and_b1 = b0 AND (u > v)` into a raw block, and with `DIALOG_GCD_K2=1` also
`s2 = NOT v[0]` after the first halving (1 = halve again). Blocks are
compressed into the sidecar log `compressed_log`. Each block is decompressed
again for the apply, and later for the reverse pass. The reachable pairs of
`(b0, b0_and_b1)` per step are only (0,0), (1,0) and (1,1), so the base's
`round763` compressor packed a 3-step group's six branch bits into 5 (4 CCX)
and stored the three `s2` bits raw: 8 bits per 3 steps.

All changes are in `src/point_add/mod.rs`:

1. **New switch `DIALOG_GCD_K2_PAIR_COMPRESS=1`** (`dialog_gcd_k2_pair_compress_enabled`,
   requires K2). `dialog_gcd_sidecar_group_size()` returns 2 instead of
   `DIALOG_GCD_HIGH_TAIL_ALIAS_GROUP_SIZE = 3`, and the following use it:
   - `dialog_gcd_compressed_sidecar_blocks` and `..._block_step_range`,
   - `dialog_gcd_compressed_sidecar_block` and `..._future_carry_slice`,
   - the forward and reverse raw-block hosts,
   - the `s2` index `raw_block[2·group + slot]`.
2. **`dialog_gcd_block_bits()` = 5** under pair compression, instead of
   5 + 3 = 8. **`dialog_gcd_raw_block_len()` = 3 × 2 = 6**, instead of 9. With 259
   steps the log goes from 87 × 8 = 696 to 130 × 5 = 650 bits. The raw block is
   freshly allocated in K2 mode (`dialog_gcd_host_reverse_raw_block_enabled`
   returns false), so it is 3 fewer live wires.
3. **The pair code.** The raw block layout is
   `[b0_A, bb_A, b0_B, bb_B, s2_A, s2_B]`.
   - `dialog_gcd_k2_pair_core` picks the five correlated bits
     `(b0_A, bb_A, s2_A, b0_B, bb_B)`.
   - The reachable set is: 3 states for A's branch pair × 2 for `s2_A` × 3 for
     B's pair, minus the cases with `s2_A = 0` and `b0_B = 0`. If A stopped
     after one halving, `v` is odd, so `b0_B = 1`. That leaves 15 states.
   - `emit_dialog_gcd_k2_pair_core_encoder` (6 CCX plus X and CX gates) maps
     those 15 states one-to-one onto states with `core[0] = 0`. I checked
     this by enumerating all 15. `..._encoder_inverse` undoes it.
   - `dialog_gcd_k2_pair_clear_raw_block_copy` encodes, then moves
     `[bb_A, s2_A, b0_B, bb_B, s2_B]` (the four code bits plus raw `s2_B`) into
     the 5-bit block. `dialog_gcd_k2_pair_copy_compressed_block_to_raw` does
     the reverse.
   - A final one-step block just copies its three bits.
   - Both functions use `swap` when `DIALOG_GCD_APPLY_REPLAY_SWAP_HOST` is on,
     as here, and `cx` otherwise.
4. **Call sites.** The forward transcript's `..._compress_block` phase now
   calls the pair encoder instead of `emit_dialog_gcd_round763_compressor` and
   the swaps. The reverse pass's decompress calls the pair decoder.
   `dialog_gcd_copy_compressed_block_to_raw` and
   `dialog_gcd_clear_raw_block_copy`, used by both apply directions, take a new
   `steps` argument and dispatch to the pair versions.
5. **Toffoli cost.** Each block passes through the codec 8 times: encode and
   decode in each factor's transcript (4), and decode plus re-encode in each of
   the two applies (4). Old: 8 × 87 blocks × 4 CCX = 2,784. New:
   8 × 129 full blocks × 6 CCX = 6,192. The difference, +3,408, is exactly the
   Toffoli increase left after item 6.
6. **`configure_ecdsafail_submission_route()`**:
   - Sets `DIALOG_GCD_K2_PAIR_COMPRESS=1`.
   - `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS` goes from 19 (the base) to 20. That
     is one more bit in the overflow-clean comparator of each of the 518 apply
     calls, +518 Toffoli. The comment says 681. It is a give-back, to lower λ.
   - `DIALOG_GCD_COMPARE_BITS` stays at 46, the base value. The comment
     "spends one branch-comparator bit back" is relative to the parent
     `91061af`, which had 45.
   - `DIALOG_TAIL_NONCE` goes from 200000008 to 689.

The commit does not trace which phase sets the new 1313 peak. The two
qubit-saving pieces are the 3-wire smaller raw block and the shorter sidecar
log (see [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md)).
A memo added by the next commit, [`02049b8`](02049b8.md), says that at the
1319-qubit base the peak phase was `dialog_gcd_apply_chunk_sub_final_ripple`,
where tx, ty, a live slice of the compressed log and the ripple carries are
co-live. A shorter log shrinks that slice.

## Why it is still correct, and what it risks

The pair code is exact. The constraint `s2_A = 0 ⇒ b0_B = 1` follows from the
step itself: after the subtract `v` is even, after one halving `s2 = NOT v[0]`,
and `s2 = 0` means `v` is now odd. So every input lands in the 15-state set,
and the encoder is a bijection on it. Nothing new depends on luck. A codec bug
would show up as wrong apply decisions (classical failures) or as leftover
transcript bits (ancilla garbage).

The width, comparator and fold truncations are unchanged from the base, except
that the apply overflow-clean comparator is one bit wider. That slightly
lowers λ. The shipped nonce 689 draws a clean set, with 0 classical, 0 phase
and 0 ancilla failures over all 9,024 shots per the commit comment.

## Classification rationale

The qubit saving comes from a denser code for the step transcript, which the
census calls the K2 transcript pair-compressor. It sits under Windowing because
it changes the grouping window of the transcript blocks, from 3 steps to 2.
Register and Scratch Allocation would be the runner-up, since the gain is a
peak cut.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 5ad4427 -- src/point_add`.
   - The git parent is `91061af` (newjordan), which narrowed
     `DIALOG_GCD_COMPARE_BITS` 46 → 45 and `DIALOG_GCD_APPLY_CLEAN_COMPARE_BITS`
     19 → 18. This commit sets them to 46 and 20.
   - Diffing against the parent (276 lines) would show those values changing
     as well. Against `5ad4427` the diff is 274 lines in 1 file, and only the
     apply-clean value differs, 19 → 20.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9a81017 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `KAL_*` environment variables set, because `set_default_env`
   keeps any value already in the environment. Expect:
   - 1313 qubits
   - 1,536,923 average Toffoli (rounded)
   - score 2,017,979,899
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=689` and an identical op
stream. Any other change needs a new nonce hunt.

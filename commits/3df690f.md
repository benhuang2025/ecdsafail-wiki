## Summary

The Karatsuba square adds three high limbs times `f = 2^32 + 977`:
`C[128..]` (130 bits), `A[128..]` and `B[128..]` (128 bits each), all from
the `×2^128` terms, plus `f·B` for the `2^256` term. The base built each
`f·limb` by doubling a copy of the limb modulo p up to 32 times and adding it
at each NAF term (shifts 0, 4, 6, 10, 32), then halving it back. Only the `A`
lane had the shortcut of [`e25c7d8`](e25c7d8.md).

This commit turns on a path that 0xLucqs had added but left off,
`TLM_SQUARE_F_SHIFTED_LOW=1`. Every NAF term `±limb·2^j` of those three limbs
is added directly at bit offset `j` with `mod_add_shifted_low` /
`mod_sub_shifted_low`. The low `j` bits are implicit zeros, so the adder is
only `256 − j` bits wide, and no doubling or halving is needed. The limbs are
below `2^130`, so `limb·2^32` never reaches `2^256`, and the result is
value-exact. About 148 fold windows (53 Toffoli each) and some adder width
disappear. The commit also caps constprop at 16 sweeps again, which costs a
few hundred Toffoli. Net −7,676 average Toffoli at 1164 qubits.

## What changed and why it saves Toffoli

The only file changed is `src/point_add/mod.rs`, `build()`. The code paths
are already in `trailmix_ludicrous/square.rs` from `e25c7d8`.

- `TLM_SQUARE_F_RAMP10_DIRECT32_TAGS`: `"a"` → `""`. With the empty string,
  `env_tag_enabled` matches no tag, so the `A` lane leaves `e25c7d8`'s
  ramp-to-10-plus-direct-32 path.
- New `TLM_SQUARE_F_SHIFTED_LOW=1`. In
  `apply_f_times_value_tagged(value, out, op, tag)` the checks run in order:
  `RAMP10_DIRECT32` (now off), `TLM_SQUARE_F_DIRECT_TAGS` (unset), then
  `TLM_SQUARE_F_SHIFTED_LOW == 1 && value.len() + 32 ≤ 256`. That branch calls
  `apply_shifted_value_low(value, out, shift, term_op)` for each of
  `F_NAF_TERMS = [(0,Sub),(4,Sub),(6,Add),(10,Sub),(32,Sub)]`, with the sign
  flipped when the caller adds:
  - shift 0: `apply_unshifted_value`, a zero-padded 256-bit `mod_add_lowpeak`
    or `mod_sub`;
  - shift `j > 0`: zero pads up to `256 − j` bits, then
    `arith::mod_add_shifted_low` / `mod_sub_shifted_low(operand, out, j)`.
    These run an uncontrolled Cuccaro over `out[j..256]`, a gated `+f` window
    on the carry-out, and the usual 21-bit measured overflow compare (see
    [`4ea8b74`](4ea8b74.md)).
- Which calls take the path (all in `mod_square_sub_pm_secp256k1_symmetric`):
  - `C` lane, `apply_shifted_128_tagged(c_prod, …, "c")`: limb `c_prod[128..]`
    of 130 bits, 162 ≤ 256. **Yes.**
  - `A` lane, `"a"`: 128 bits. **Yes.**
  - `B` lane `×2^128`, `"b"`: 128 bits. **Yes.**
  - `B` lane `×2^256`, `apply_f_times_value(b_prod, …)`: 256 bits, 288 > 256.
    **No**: it keeps the full doubling ramp.
- **Cost.** Each ramp was 32 doublings plus 32 halvings, each a `+f` window of
  `LSBS − 1 = 53` CCX on this tree (`PAD = 21`), about 3,392 Toffoli. Removing
  the `C` and `B×2^128` ramps saves about 6,800. In the `A` lane the 10 + 10
  remaining doublings of `e25c7d8`'s path go, about 1,060 more. The shifted
  adds are also narrower: the Cuccaro is `256 − j` bits wide, about 2 Toffoli
  per bit, which saves roughly 100 per lane. So about 8,000 by count, against
  a measured −7,676 that also includes the constprop cap below.
- `CONSTPROP_MAX_ITERS`: 256 → 16. The constprop post-pass stops after 16
  sweeps instead of at its fixed point ([`d2643bc`](d2643bc.md) measured 324
  Toffoli for the extra sweeps on its tree). This gives back part of the
  saving. It seems to have been copied from the 1162-qubit trees, which used
  16.
- `DIALOG_TAIL_NONCE`: 2207 → 40000000623 in `build()` (the live one), and the
  three dead-route copies in `configure_ecdsafail_submission_route()` from
  188337 to the same value.

See [modular-fold](../concepts/modular-fold.md),
[squaring-and-karatsuba](../concepts/squaring-and-karatsuba.md) and
[adders-and-carries](../concepts/adders-and-carries.md).

## Why it is still correct, and what it risks

- **Value-exact.** Each limb is below `2^130`, so `limb·2^j < 2^162` for every
  NAF shift `j ≤ 32`. In the old ramp no doubling ever shifted out a 1, so its
  `+f` windows never fired and the ramp value at shift `j` was the plain
  shifted limb. The shifted-low add uses that value directly.
- The removed windows could never fire, so they carried no error. Each
  shifted-low add has the same approximations as the full-width add it
  replaces: one `+f` window (carry dropped past 54 bits, about `2^-21`) and a
  21-bit truncated overflow compare. The failure set is essentially the
  base's. The constprop cap is exact.
- A failure would be classical (wrong coordinate) or phase (wrong compare
  repair).
- The shipped nonce 40000000623 draws a clean set: 9,024 of 9,024 shots pass,
  with 0 classical, 0 phase and 0 ancilla failures, per the author's env-less
  run.
- The submission note describes a different variant (a 1162-qubit
  "direct-shift32 on B and C" route). The code comment in `build()` describes
  this commit's mechanism, though it calls the old `<<32`-only path a "B/C"
  lever (on this base it was the `A` lane) and its figures (−3,287 Toffoli,
  score 1,606,649,412) are not the shipped result.

## Classification rationale

The published label is fold/carry truncation. Nothing is truncated here: the
change replaces the modular-doubling route of the Solinas `f`-fold with direct
shifted adds and is value-exact, the same lever as `e25c7d8` and
[`aacf05c`](aacf05c.md). The diff suggests Strength Reduction → solinas / NAF
fold. A defensible runner-up is dead-gate removal, since the removed windows
never fired.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout e25c7d8 -- src/point_add`.
   - Do not start from the git parent `fed64cf`. That is nasqret's 1159-qubit
     tree, and this commit was built on 0xLucqs's 1164-qubit `e25c7d8`.
   - Against the parent, the diff is 1,958 lines in 12 files. It would revert
     all of `fed64cf` and the 1162-qubit budget trims of `7b7bd12`.
   - Against `e25c7d8`, `git diff --ignore-cr-at-eol e25c7d8 3df690f -- src/point_add`
     is 26 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 3df690f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1164 qubits
   - 1,380,610 average Toffoli (rounded)
   - score 1,607,030,040
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `40000000623` and an identical op
stream. Any other change needs a new nonce hunt.

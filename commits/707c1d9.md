## Summary

This commit changes one constant and the nonce. In the dialog-GCD apply phase,
every controlled modular add and subtract on the 256-bit payload ends with a
fold: when the raw sum overflows 2^256, the constant `c = 2^32 + 977` is added
to the low bits. That fold's carry chain is cut off `w` bits above bit 32.
This commit makes `w` 17 instead of 18, one stage less per fold. There are
2 × 258 folds per shot, and the average drops by 492 Toffoli. Qubits are
unchanged. The cut is probabilistic, so the nonce was re-hunted.

## What changed and why it saves Toffoli

All changes are default pins in `configure_ecdsafail_submission_route()`,
`src/point_add/mod.rs`.

1. **`KAL_FOLD_CARRY_TRUNC_W`: 18 → 17.**
   - Read by `fold_carry_trunc_window()` (`arith/const_arith.rs`). It is used
     in the materialized pseudo-Mersenne apply add and subtract
     (`dialog_gcd_cmod_add_materialized_pseudomersenne_*`,
     `dialog_gcd_cmod_sub_materialized_pseudomersenne_*` in
     `rounds/dialog/mod.rs`), phase `dialog_gcd_materialized_special_overflow_fold`.
   - There, `cadd_nbit_const_direct_trunc_fast(b, &acc[..LSBS], c, acc_ovf, w)`
     adds `c` controlled on the overflow bit. Its carry sweep runs for bit
     positions `0..=last` with `last = min(n − 2, 32 + w)`, because 32 is the
     top set bit of `c`. Above bit 32 the constant is 0, so each further stage
     only propagates a carry through a run of 1s in `acc`.
   - One stage less is about one Toffoli per fold. The forward apply (in-place
     multiply) does one add per step and the reverse apply (division) does one
     subtract per step, 258 steps each, so about 516 folds. The measured average
     falls by 492. See [modular-fold](../concepts/modular-fold.md).
   - The submission note describes the knob as "in the Kaliski/double-halve
     path". In this tree it is the apply-phase add/sub fold; the double/halve
     fold uses the separate `KAL_DOUBLE_CARRY_TRUNC_W`.
2. **`DIALOG_TAIL_NONCE`: 1200069204974 → 3000522316986.**

## Why it is still correct, and what it risks

The truncated fold is wrong when the carry out of bit 32 would run more than
17 further bits, which needs `acc` to have 1s in all of bits 33–50 at that
point, about 2^−18 per fold. Going from 18 to 17 roughly doubles that rate.
A dropped carry gives a wrong payload, which is a classical mismatch, and
because the reverse apply no longer inverts the forward one exactly, it can
also show as phase or ancilla garbage.

The author's note says they measured about 19.4 classical mismatches per random
nonce with this setting (the expected number of failing shots in a draw), so a
clean draw takes about e^19.4 ≈ 3 × 10^8 nonces. They also tried other
one-notch cuts and found them comparable or worse to hunt. The shipped nonce
`3000522316986` draws a clean set: 9,024 of 9,024 shots, with 0 classical,
0 phase and 0 ancilla failures. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a narrower carry window in a constant adder, which
is comparator/width truncation. The fold-specific change-type "fold/carry
truncation" would also fit; the census used the broader label.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 8e0bf4f -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 8e0bf4f 707c1d9 -- src/point_add` is 4 lines in
   1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 707c1d9 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*` or `ROUND84_*` environment variables set, because they
   override the route defaults. Expect:
   - 1285 qubits
   - 1,373,922 average Toffoli (rounded)
   - score 1,765,489,770
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_TAIL_NONCE=3000522316986` and an
identical op stream. Any other change needs a new nonce hunt.

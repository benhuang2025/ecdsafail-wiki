## Summary

The walk-width table `WIDTH_SCHEDULE` has 700 entries, fitted for a 700-round
walk, but this tree's divide walk runs only 698 rounds. Read one entry per
round, the walk stopped two entries short of the table's end. Its last rounds
were therefore wider than the fit allowed.

An existing opt-in rescale compresses the round index so the last round maps
to index 703 (the old 704-round geometry); the table's end is reached near
round 694 and the last few rounds run at the floor of 8. This commit makes the
rescale the default. Every round now reads a
slightly later, narrower entry. To buy back some of the λ that costs, it adds
+1 bit at 100 fitted table indices (`WIDTH_REPAIR`). Net, the walk uses 1,132
fewer bit-rounds over both traversals.

The narrower walk also lowers the replay's footprint. That lets the author
lower both peak owners by one: the replay budget `SUB4_PP_PEAK` from 1275 to
1274, and the square's `SQUARE_LADDER` from 245 to 244. The result is 1274
qubits and 2,446 fewer average Toffoli.

## What changed and why it saves Toffoli and a qubit

All changes are in `src/point_add/pingpong_div.rs`, except the square budget
and two `mod.rs` lines.

1. **Rescale on by default** (`width_round_index`).
   - Before, the rescale ran only if `SUB4_PP_WIDTH_RESCALE` was set. Now it
     runs unless it is set to `0`.
   - The index becomes `round × (ROUNDS_DEFAULT − 1) / (rounds() − 1)` =
     `round × 703 / 697`, with `ROUNDS_DEFAULT = 704` and `rounds()` = 698.
     So round `r` reads table entry ≈ `1.0086·r`, which is narrower, since
     the table is non-increasing, and the walk reaches the floor of 8 on its
     last rounds.
   - The same index is used for the multiply traversal, which runs 696
     rounds.
   - Summed over the rounds run, bit-rounds go 196,948 → 195,616 (−1,332).
2. **Sparse repair** (`WIDTH_REPAIR`, `width_repair`).
   - A new constant list of 100 table indices. `value_width` adds +1 bit when
     the rescaled index is in the list. It applies only with the rescale
     active, and `SUB4_PP_WIDTH_REPAIR=0` turns it off.
   - The comment says the indices are a greedy cost-weighted cover of the
     marginal width violations the rescale creates. They were fitted on 640
     classical draws and checked on 320 held-out ones: −0.95 λ for +519
     Toffoli, with the peak profile unchanged.
   - It adds back 200 bit-rounds, so the net is 196,948 → 195,816 (−1,132).
   - See [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md),
     section "Width schedules": a narrowing is a *sell*, and the repair is a
     targeted *buy*.
3. **Peak owners lowered together.**
   - `plan()` defaults change: `SUB4_PP_PEAK` 1275 → 1274, `SUB4_PP_R1`
     342 → 340, `SUB4_PP_R2` 625 → 628. The comment says r1/r2 were re-tuned
     because the narrower interleaved walk shifts the cheapest chunk
     layouts.
   - `SQUARE_LADDER` 245 → 244 in
     `trailmix_ludicrous/square/product_register.rs`. It is the live
     carry-ladder budget of the square's wide adds.
   - The replay and the square both sat at the old cap, so both had to come
     down for Q to drop. Narrower ladders cost some Toffoli back. See
     [peak-qubits-and-budgets](../concepts/peak-qubits-and-budgets.md),
     section "Co-binders".
4. **Default-off diagnostics** (no effect on the shipped stream):
   - `wsched_override()` loads a replacement table from the CSV named by
     `SUB4_PP_WSCHED_FILE`.
   - `dump_width_schedule()`, reached through `SUB4_DUMP_WSCHED` in
     `mod.rs::build()`, prints the base and rescaled schedules and exits.
5. **Tail nonce** in `mod.rs`: 251000962439 → 100000045835813.

## Why it is still correct, and what it risks

- **Probabilistic.** Like any width schedule, the compressed one is a fit,
  not a proof. A trimmed top wire must be a copy of the sign, and an input
  that shrinks more slowly than the table assumes breaks that. The result is
  a classical failure, usually with phase and ancilla garbage.
- The rescale narrows every round a little, so it raises λ. The repair buys
  back about 0.95 of it at the 100 most marginal indices.
- **The budget moves are exact.** They change only chunk layouts. Narrower
  ladders can add approximate chunk boundaries, which is a small
  phase-channel exposure.
- The shipped nonce draws a clean set: 0 classical, 0 phase and 0 ancilla
  failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Most of the saving comes from narrower per-round walk widths, which is width
truncation. The one-qubit drop is a co-binder budget retune that the
narrower walk makes affordable. It could be filed separately as
ancilla-lifetime / venting, but it is the smaller part of the score change.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 087cafa -- src/point_add`.
   - Do not start from the git parent `b523ecf`. That is mochimodev's
     linear-schedule tree, and this commit was not built on it.
   - Against the parent, the diff is 10,784 lines in 8 files. It deletes
     b523ecf's three backup snapshots (`mod.rs.pre_live`,
     `pingpong_div.rs.pre_ts`, `pingpong_div.rs.rrm`). It also brings back
     087cafa's `*_dead_low` adders (181 lines in `arith/const_arith.rs`), a
     memory note, and the fitted `WIDTH_SCHEDULE` in place of the linear
     schedule. None of that is new work.
   - Against `087cafa`, `git diff --ignore-cr-at-eol 087cafa 2c79d2f -- src/point_add`
     is 113 lines in 3 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 2c79d2f -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `SUB4_*`
   environment variables set. `SUB4_PP_WIDTH_RESCALE` in particular must be
   unset. Expect:
   - 1274 qubits
   - 916,526 average Toffoli (rounded)
   - score 1,167,654,124
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `100000045835813` and an identical
op stream. Any other change needs a new nonce hunt.

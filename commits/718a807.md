## Summary

This is the same one-knob change as the author's [`73894fc`](73894fc.md). This
time it is applied to the 1250-qubit tree of [`87a1c68`](87a1c68.md), which had
just taken the frontier from the 1249-qubit line.

On divide rounds whose walk register is at least 38 bits wide, the base adds
one extra bit to the compare that repairs the replay cell's overflow flag.
Raising the threshold to 696, above any walk width, removes that bit
everywhere. The saving is 10 executed Toffoli at the same 1250 qubits. The
cost is a higher phase-error rate at those compares, so the nonce was
re-hunted.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `env_raw()`: `PP_FLAG_WIDEN_DIV` goes from `"38"` to
  `"696"`.
- What the knob means. It is read by `flag_widen_div()` (`pingpong.rs`) and
  used at every divide-side flag site:

  ```
  k = flag_compare(round) + [policy_width(round) >= PP_FLAG_WIDEN_DIV]
  ```

  - `policy_width(round)` is the walk register width from
    `PP_WIDTH_SCHEDULE`, between 259 and 8 bits. It is not a round index.
  - `flag_compare(round)` is `PP_REPLAY_FLAG_COMPARE` (20) plus the
    `PP_FLAG_SHAPE` band offset.
  - With 38, the divide rounds 0–615, which have width ≥ 38, got one extra
    bit. With 696, no round does. Any value above 259 would act the same.
- The sites that use it, all divide-side:
  - `replay_add_halve_impl`;
  - `joint_prebias::joint_prebias_div`;
  - the divide branch of the `joint_lowfold` planner;
  - the `retained_prebias` planner.
- At the two cell sites, the flag is measured out with `hmr`. Then
  `erase_with_compare` runs a top-`k` compare under `push_condition` on the
  outcome. Each bit costs one Toffoli on the about half of shots where the
  compare runs. See
  [measurement-uncompute](../concepts/measurement-uncompute.md) and
  [comparator-and-width-truncation](../concepts/comparator-and-width-truncation.md).
- Why only −10 here, against −17 on the 1249 tree:
  - Most divide cells take `retained_prebias::try_replay`, which erases the
    overflow exactly from the top-bit frame (`erase_overflow_from_frame`)
    and runs no flag compare. There the knob only enters the planner's
    saving estimate.
  - So the saving depends on how many divide cells fall back to the
    joint-prebias or plain cell. That count depends on the cap and the
    layouts. This tree has the 1250 cap and the older bridge profile, so its
    set of fallback cells differs from that of the 1249 tree of `73894fc`.
    Here the set is smaller.
  - This explanation is inferred from the code paths and the measured
    deltas. It was not traced per cell.
- **Tail nonce** `TAIL_NONCE`: 85023914663 → 92100003699992.

## Why it is still correct, and what it risks

The flag compare is approximate. It repairs the phase wrongly when the two
replay registers tie on all `k` compared bits, with probability about 2^-k.
One bit fewer roughly doubles that rate at each affected divide cell. Lambda
goes up, and a failure would show up as a phase error. The values are still
computed correctly.

The shipped nonce `92100003699992` draws a clean set: 0 classical, 0 phase and
0 ancilla failures. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change makes one family of truncated compares one bit
narrower. That is comparator/width truncation, the same as `73894fc`.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 87a1c68 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 87a1c68 718a807 -- src/point_add` is
   4 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 718a807 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh`. In this tree
   `env_raw()` is a fixed table and does not read the process environment, so
   `SUB4_*` or `PP_*` variables have no effect. Leave them unset anyway.
   Expect:
   - 1250 qubits
   - 888,879 average Toffoli (rounded)
   - score 1,111,098,750
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `92100003699992` and an identical op
stream. Any other change needs a new nonce hunt.

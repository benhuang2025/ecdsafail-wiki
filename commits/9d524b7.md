## Summary

The trailmix inversion applies each GCD step's decisions to a pair of
256-bit coordinate registers. One part of each step is a controlled swap of the
two registers, which costs 256 Toffoli. [`5c34dd1`](5c34dd1.md) already
skipped that swap in the first step of the forward multiply.

This commit adds the twin in the inverse direction (the `λ = dy/dx` division).
It skips the swap in the step that belongs to the last GCD iteration. At that
iteration a GCD that is going to finish never swaps, so the skipped gates do
nothing on any input the circuit gets right.

The saving is 259 average Toffoli: 256 from the swap, plus draw noise. Qubits
stay at 1159. The knob is general (skip the last K iterations), and only K = 1
is shipped.

## What changed and why it saves Toffoli

**`src/point_add/trailmix_ludicrous/gcd.rs`**

- New `apply_cswap_skip_dir(i, fwd) -> bool`.
  - If `TLM_APPLY_CSWAP_SKIP_LASTK = k` is set, it returns
    `k > 0 && i + k >= ITERS` for both directions.
  - Otherwise it reads `TLM_APPLY_CSWAP_SKIP_FWD` (default 1) or
    `TLM_APPLY_CSWAP_SKIP_INV` (default 0) with the same test.
- `apply_step_forward`: the old `TLM_APPLY_FWD_FIRST_CSWAP_SKIP && i + 1 == ITERS`
  test is replaced by `apply_cswap_skip_dir(i, true)`. With `k = 1` this is
  the same condition, so the forward multiply's op stream is unchanged.
  `TLM_APPLY_FWD_FIRST_CSWAP_SKIP` is still set in `build()`, but nothing reads
  it any more.
- `apply_step_reverse`, the inverse-direction apply: the 256-wire
  `cswap(swp, x_reg[j], y_reg[j])` loop now runs only if
  `!apply_cswap_skip_dir(i, false)`.

**`src/point_add/mod.rs`, `build()`**: new default
`TLM_APPLY_CSWAP_SKIP_LASTK = 1`. `DIALOG_TAIL_NONCE` goes from 200003194569
to 100009961111.

**Why the inverse-side swap at `i = ITERS−1` is the identity.**
- In `Direction::Inverse`, `forward_gcd_jump` runs `i = 0 … ITERS−1` and calls
  `apply_step_reverse` at each step ([trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md)).
  So `i = ITERS−1 = 257` is the last apply step, and its swap uses that step's
  flag `swp = subtracted AND (v < u)`.
- For the GCD to finish, `v` must be 0 after this step. That needs either no
  subtract (`subtracted = 0`, so `swp = 0`), or `v = u = 1` before it (then
  `v < u` is false, so `swp = 0`).
- `swp = 1` therefore happens only on inputs whose GCD has not converged by the
  last step, and the base already computes those wrong.
- Each `cswap` in the trailmix builder is `cx; ccx; cx`, so removing 256 of
  them saves 256 Toffoli.

**Why only K = 1.** The author's comment in `build()` records random-nonce runs
of the general knob. K = 2 saves about 785 Toffoli but gives about 18
classical and 8 phase failures per draw. K = 3 saves about 1,285 and gives
18–28 classical and 7–19 phase failures. At iteration `ITERS−2`, a converging
input can still swap, for example `u = 3, v = 1`. A larger K would therefore
make Lambda much larger, and a clean nonce much harder to find.

## Why it is still correct, and what it risks

- With K = 1 the skip changes no input that the base gets right, by the
  argument above. The author describes it as "value-exact except on
  non-converged inputs". Those inputs are already failures of the fixed
  258-step schedule. The ancilla channel is never affected: the skipped gate is
  a swap of data registers, and no scratch wire depends on it.
- If the skip were wrong on some input, the result would be a classical
  failure (a wrong `λ`), or a phase failure where later measured erasures
  recompute from swapped data.
- The shipped nonce `100009961111` draws a clean set: 9,024 of 9,024 shots,
  with 0 classical, 0 phase and 0 ancilla failures. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The commit removes 256 gates that act as the identity on every input the
circuit gets right. That is dead-gate removal. The runner-up was a
probabilistic truncation, if one counts the non-converged inputs, but at
K = 1 those inputs already fail in the base.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout f6ce76d -- src/point_add`.
   - Do not start from the git parent `6ba606a`. That is jieyilong's 1157-qubit
     retarget. It adds the per-call reserve maps, the lazy fold carry-in and
     its own `TLM_APPLY_INV_FIRST_CSWAP_SKIP`. This commit was built on the
     1159-qubit `f6ce76d` instead.
   - Against the parent, the diff (209 lines) would undo all of that.
   - Against `f6ce76d`, `git diff --ignore-cr-at-eol f6ce76d 9d524b7 -- src/point_add`
     is 46 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9d524b7 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `TLM_*`, `LUD_*` or `CONSTPROP_*` environment variables set,
   because they override the defaults in `build()`. Expect:
   - 1159 qubits
   - 1,378,377 average Toffoli (1,378,377.358 before rounding)
   - score 1,597,538,943
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `100009961111` and an identical op
stream. Any other change needs a new nonce hunt.

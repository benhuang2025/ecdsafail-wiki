## Summary

This commit changes one constant and the tail nonce. The 256-bit `λ²` square
builds its widest rows in two windows. The carry crossing each window boundary
is erased by measurement and then phase-repaired with a comparison of the top
`k` bits of the window (see [`d636d62`](d636d62.md)). This commit makes `k`
21 instead of 22. Each cleanup saves one CCX in the rebuild of the window's
row bits, which runs on every shot, and one CCX in the comparator, which runs
on half the shots. That is about 1.5 Toffoli per cleanup, or −223 average
Toffoli in all. Qubits are unchanged.

## What changed and why it saves Toffoli

- `src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`:
  - `SQUARE_ROW_WINDOW_CLEAN_COMPARE_BITS`: 22 → 21, with a new comment.
  - `DIALOG_TAIL_NONCE`: 9400000893246 → 17761178.
- The knob is read by `square_row_window_clean_compare_bits()` in
  `src/point_add/arith/multiply.rs`. It is used in the reverse sweep of
  `square_row_windowed_apply`.
  - For each interior boundary carry `cout`, the sweep rebuilds only the top
    `k` row bits of the window (`build_seg(b, hi − k, hi)`, one CCX per cross
    term bit).
  - It then runs `hmr(cout)`, and, under the outcome bit,
    `cmp_lt_phase_conditioned_with_cin_borrowed_carries`, a `k`-bit comparator
    with a zero carry-in.
- **Count.** With `SQUARE_ROW_MAX_SEG = 188`, rows `i = 0..68` (widths 257 down
  to 189) have one interior boundary each. The square is applied once forwards
  and once inverted, so there are about 138 cleanups.
- **Estimate.** At about 1.5 Toffoli each, that is about −207 against the
  measured −223. The rest is the shift in average measurement outcomes under a
  new Fiat–Shamir stream.
- Qubits are unchanged, because the comparator's carry lane is borrowed from
  the clean high tail of `tmp_ext`.

## Why it is still correct, and what it risks

- The compare ignores the carry coming from the low `seg_w − k` bits of the
  window. It recovers the wrong boundary carry when the top `k` bits of the
  partial sum and of the row window tie, about 2^-k per cleanup. Going from
  22 to 21 bits doubles that rate.
- A wrong carry gives a wrong phase repair after the `hmr`. That shows up as a
  phase failure. The wire itself is always reset.
- The shipped nonce `17761178` draws a clean set: 9,024 shots, 0 classical,
  0 phase and 0 ancilla failures. The submission note says the author found it
  with a GPU prefilter that also modelled this cleanup condition, and then
  confirmed it with the trusted evaluator. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The only circuit change is a narrower truncated comparator, so the label is
comparator/width truncation. The nonce change comes with every circuit change
and is not a separate lever.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 420e0c2 -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 420e0c2 5a783e4 -- src/point_add` is
   8 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 5a783e4 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with none of the
   route's variables (`DIALOG_*`, `SQUARE_*`, `KAL_*`, `KARA_*`, `ROUND84_*`,
   `R84_*`) set, because `set_default_env` only fills unset variables. Expect:
   - 1215 qubits
   - 1,403,115 average Toffoli (rounded; 1,403,115.070 in the submission note)
   - score 1,704,784,725
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `17761178` and an identical op
stream. Any other change needs a new nonce hunt.

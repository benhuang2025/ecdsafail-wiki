## Summary

The `λ²` square builds each row wider than 165 bits in two windows. The carry
crossing each boundary is erased by measurement and phase-repaired with a
compare of the top `k` bits of that window (see [`d636d62`](d636d62.md)).
Until now `k` was one global value, 21.

This commit makes `k` a per-row setting. The default drops to 19, and a
sparse map keeps 21 specific rows at 20, 21 or 22 bits. The author picked
those rows empirically, as the ones where truncation ties actually showed up
across sampled nonces. That puts the remaining accuracy only where it is
needed. The result is −442 average Toffoli at the same 1192 qubits.

## What changed and why it saves Toffoli

1. **`src/point_add/arith/multiply.rs`.**
   - `square_row_window_clean_compare_bits()` becomes
     `square_row_window_clean_compare_bits(row)`. It returns the
     `SQUARE_ROW_WINDOW_CLEAN_COMPARE_BITS` default, unless the new variable
     `SQUARE_ROW_WINDOW_CLEAN_ROW_BITS` (a `row:bits,…` list) has an entry for
     `row`.
   - `square_row_windowed_apply` now calls it with the row index `i`. The
     same width is used in the forward square and in the inverse square.
2. **`src/point_add/mod.rs`, `configure_ecdsafail_submission_route()`.**
   - `SQUARE_ROW_WINDOW_CLEAN_COMPARE_BITS`: 21 → 19, with a new comment.
   - `SQUARE_ROW_WINDOW_CLEAN_ROW_BITS` (new) =
     `2:20,11:20,12:20,13:21,16:22,19:20,20:21,21:20,26:21,29:21,32:21,37:21,44:22,46:20,53:21,56:20,64:20,70:20,75:20,78:20,87:20`.
     That is 12 rows at 20 bits, 7 at 21 and 2 at 22.
   - Both `DIALOG_TAIL_NONCE` lines: 2107498317 → 11556565. Only the first
     takes effect.

**Saving estimate.**
- With `SQUARE_ROW_MAX_SEG = 165`, rows `i = 0..91` are windowed, one
  boundary each, in both the forward and the inverse square. Each bit
  removed from a cleanup saves about 1.5 Toffoli: one CCX in the rebuild of
  the row bits, which runs on every shot, and ½ in the conditional compare.
- Against the old 21 bits:
  - 71 rows at 19: 142 cleanups × 3 = −426.
  - 12 rows at 20: 24 × 1.5 = −36.
  - 2 rows at 22: 4 × 1.5 = +6.
  - Total about −456, against the measured −442.

**How the map was chosen** (from the submission note):
- The author used a static budget of 128 Toffoli for the widened rows.
- Rows were chosen from two disjoint corpora of 128 nonces each, with
  cross-validation between the corpora.
- The map was then checked on an independent holdout of 256 nonces, each run
  over all 9,024 shots.
- The idea is that the chance of a top-bit tie is not uniform across rows.
  The row bits are structured products (`x_i · x_j` cross terms), so some
  rows tie more often, and only those rows get the extra bits.

## Why it is still correct, and what it risks

- **Every cleanup is still a truncated compare.** A tie in the top `k` bits
  gives a wrong phase repair after the `hmr`, which shows as a phase failure.
  The wire is always reset.
- At 19 bits the per-cleanup tie rate is about 4× the 21-bit rate. The row
  map gives back accuracy only on the rows where failures were observed.
- This is an empirical choice. On rows outside the map, a rare tie class that
  the 512 sampled nonces never hit would still cost a nonce re-hunt.
- The shipped nonce `11556565` draws a clean set: 9,024 shots, 0 classical,
  0 phase and 0 ancilla failures. A CUDA hunt over all 9,024 shots found it,
  with zero modelled square and apply phase risks, and a single-threaded Rust
  replay plus the trusted benchmark confirmed it. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The change narrows truncated comparators, now chosen per row. That is
comparator/width truncation. The per-row map is a refinement of the same
lever, not a new mechanism.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 0fa5c6f -- src/point_add`. The base is the git
   parent. `git diff --ignore-cr-at-eol 0fa5c6f cf99209 -- src/point_add` is
   42 lines in 2 files.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol cf99209 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with none of the
   route's variables (`DIALOG_*`, `SQUARE_*`, `KAL_*`, `KARA_*`, `ROUND84_*`,
   `R84_*`) set, because `set_default_env` only fills unset variables. Expect:
   - 1192 qubits
   - 1,411,983 average Toffoli (rounded; 1,411,982.856 in the submission note)
   - score 1,683,083,736
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with the nonce `11556565` and an identical op
stream. Any other change needs a new nonce hunt.

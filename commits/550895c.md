## Summary

Each step of the GCD apply pass does a controlled modular add or subtract,
`acc ± ctrl·a (mod p)`, on 256-bit registers. The base did it in this order:
- write all 256 bits of `f = ctrl AND a`;
- run a two-block measured adder, cut at bit 128 ([68e3653](68e3653.md));
- clear the carry between the blocks with a 128-bit comparator;
- erase `f`.

This commit changes three things:

1. **Chunked `f`.** Only the slice of `f` that the current block needs is
   written. It is erased right after that block's addition. Bits 0–69 are live
   for block 0 and bits 70–255 for block 1, never all 256 at once. The apply
   phase drops below the circuit's other peak, and the overall peak falls from
   1571 to 1567.
2. **Cut at bit 70 instead of 128.** The boundary carry is still cleared
   exactly, but with a 70-bit comparator instead of a 128-bit one. Because `f`
   has already been erased, it is a controlled comparator against `a`. This
   saves 57 Toffoli per call.
3. **Fused underflow clean.** The subtract's overflow flag used two 20-bit
   comparators. It now uses one controlled comparator, which saves 19 more per
   subtract.

There are 399 adds and 399 subtracts per point addition, so the total saving
is 399 × 56 + 399 × 76 = 52,668 Toffoli. That is the exact measured drop.

## What changed and why it saves qubits and Toffoli

All in `src/point_add/mod.rs`. New switches `DIALOG_GCD_APPLY_CHUNKED_F_BLOCKS`
(default `"2"`) and `DIALOG_GCD_APPLY_CHUNKED_F_CUT` (default `"70"`) are set in
`configure_ecdsafail_submission_route()`. When `BLOCKS ≥ 2` and
`DIALOG_GCD_RAW_APPLY_TRUNCATED_CLEAN` is on, `dialog_gcd_cmod_add_materialized_pseudomersenne`
and `..._sub_...` return early into new `_chunked` versions. The subtract also
needs `DIALOG_GCD_MEASURED_APPLY_SUB`.

### 1. Chunked materialization (`dialog_gcd_add_ctrl_chunked_low_to_ext`, `..._sub_...`)

For each block `[lo, hi)` of the 257-bit `acc_ext`:
- `dialog_gcd_load_controlled_slice(ctrl, a, lo, hi)` allocates `hi − lo` fresh
  wires and writes `ctrl AND a[i]` into them, one CCX each.
- The block is added: `cuccaro_add_fast` with a zero/`cout` extension for
  block 0, and `cuccaro_add_fast_low_to_ext` (from [36dcf6b](36dcf6b.md)) for
  the last block.
- `dialog_gcd_clear_controlled_slice_hmr` erases the slice with `hmr` plus
  `cz_if(ctrl, a[i], m)`, at no Toffoli cost, and the wires are freed.

`dialog_gcd_chunk_hi` places the first cut at `DIALOG_GCD_APPLY_CHUNKED_F_CUT = 70`
instead of `ext_n / 2 = 128`.

Live scratch in the apply phase:

| | base (`f` whole, cut 128) | this commit (chunked, cut 70) |
| --- | --- | --- |
| block 0 | 256 `f` + 128 carries + 2 | 70 `f` + 70 carries + 2 |
| block 1 | 256 `f` + 128 carries + `cout` | 186 `f` + 186 carries + `cout` |
| boundary clear | 256 `f` + 129 + `cout` | 70 + 1 + `cout` |

The maximum falls from about 386 to about 373 wires. The commit comment says
this puts the apply phase under "the ROUND84 peak binder", the x-tail square
phase, which now sets the peak at 1567. The memory note records the same 1567
for cuts 68, 70 and 72. Lower cuts save more Toffoli (see the next point);
cut 68 was cheaper at the same peak but failed its first draw, and 70 was
clean at reroll 4/15.

### 2. Shorter boundary-carry clear

Block 0's carry-out `cout` is cleared at the end with
`ccx_cmp_lt_into_fast(acc_ext[..70], a[..70], ctrl, cout)`. The subtract uses
`a` complemented in place by `X` gates.
- `ccx_cmp_lt_into_fast` costs `n + 1` Toffoli. Before, the clear was an
  uncontrolled `cmp_lt_into_fast` over `[..128]` against `f`, costing 128.
- The new identity is `cout = ctrl AND [acc_low < a_low]`. When `ctrl = 0`,
  `f` was 0 and nothing carried. It is exact, and it needs the control only
  because `f` is no longer live.
- The two blocks still cost 70 + 186 = 256 CCX, the same as 128 + 128.
- The net saving is 128 − 71 = 57 per call.

### 3. Overflow and underflow clean against `a` with a control

- **Add** (`..._add_materialized_pseudomersenne_chunked`). The overflow flag is
  erased by `ccx_cmp_lt_into_fast(acc[236..], a[236..], ctrl, acc_ovf)`, at 21
  Toffoli. Before, it was `cmp_lt_into_fast(acc[236..], f[236..])` at 20. The
  predicate is the same, because `f = ctrl·a`. This costs +1 per add.
- **Subtract** (new `dialog_gcd_clean_truncated_underflow`, also used in the
  non-chunked and borrowed-subtrahend subtract paths). Before:
  - compute `pred = NOT [acc_top < ~a_top]` into a temporary with one 20-bit
    comparator;
  - erase `acc_ovf` with `hmr` + `cz_if(ctrl, pred)`;
  - uncompute `pred` with a second comparator, 40 Toffoli in all.

  Now: `cx(ctrl, acc_ovf)`, then
  `ccx_cmp_lt_into_fast(acc_top, ~a_top, ctrl, acc_ovf)`. That XORs
  `ctrl AND NOT[acc < ~a]` into `acc_ovf` coherently, at 21 Toffoli, with no
  temporary. This saves 19 per subtract.

Per add: −57 + 1 = −56. Per subtract: −57 − 19 = −76. With 399 of each,
399 × 132 = 52,668.

### 4. Other

- `DIALOG_REROLL` 1 → 4 and `DIALOG_POST_SUB_REROLL` 0 → 15: the identity
  `X;X` pads, re-searched for a clean draw.
- New memory note `src/point_add/memory/2026-06-02-chunked-apply-f.md`. It
  gives the score as 2,647,954,335; the correct product is 2,647,454,335.

## Why it is still correct, and what it risks

The chunking and the boundary clear are exact:
- Each `f` slice is written and erased around exactly the block that uses it.
- The carry-out identity holds for both values of `ctrl`.

The overflow and underflow cleans compute the same 20-bit truncated predicates
as before, so they fail on the same rare ties, no more often. No new
approximation is added. The op stream changed, so a new clean draw was needed.
The pair (4, 15) draws 0 classical, 0 phase and 0 ancilla failures. The
author's scan found that cut 68, which is cheaper, failed on its first draw.
That is about the old truncations meeting a new test set, not about the cut
itself.

## Classification rationale

The census files this as ancilla-lifetime / venting, which describes the
chunked `f`: wires are held only while their block runs. Most of the score
gain is Toffoli, though. About 82.5 M of the −89.5 M comes from the 52,668
Toffoli, and only about 7 M from the 4 qubits. That Toffoli comes from an
exact restructuring of how the boundary carry and the underflow flag are
cleaned: a shorter comparator after moving the cut, and one fused controlled
comparator instead of compute-gate-uncompute. A reasonable alternative label is
Dead-Code and Redundancy Elimination (uncompute fusion), with the qubit cut as
the enabler.

     lines in 2 files, one of them the new memory note.

   The flag lets the patch apply whether the files use LF or CRLF line endings.
   It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 550895c -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*`, `KAL_*`, `KARA_*` or `ROUND84_*` environment variables set.
   Expect:
   - 1567 qubits
   - 1,689,505 average Toffoli (rounded)
   - score 2,647,454,335
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 4`,
`DIALOG_POST_SUB_REROLL = 15` and an identical op stream. Any other change
needs a new reroll scan.

## Summary

Three constants in the Kaliski inverse change. Two of them tighten W-TRUNC,
the empirical width envelope that every per-iteration width loop is cut to:
- the envelope starts at iteration 24 instead of 26;
- the safety margin above it goes from 3 bits to 0.

Together they make every truncated loop about 4.3 bits narrower. Since
[`404d630`](404d630.md), that includes the (u, v_w) conditional swaps. The
third change, `R_SMALL_THRESHOLD` 326 → 325, goes the other way. It costs a
little Toffoli and is there to land a clean test island.

Net: −27,422 average Toffoli at the same 2309 qubits. The point was found by
a joint sweep of all three knobs with the full 9,024-shot evaluator.

## What changed and why it saves Toffoli

All three are in `src/point_add/kaliski_state.rs`:

1. **`kal_wtrunc_k0()`: 26 → 24.**
   - `kal_wtrunc_width(it, n) = min(n, n − ⌊(it − K0)·2/3⌋ + margin)` for
     `it ≥ K0`, with `n = 256`.
   - Moving `K0` two iterations earlier lowers the envelope by 1 or 2 bits at
     every later iteration, 4/3 bits on average. See
     [`179ab10`](179ab10.md), which made the same move from 27 to 25.
2. **`kal_wtrunc_margin()`: 3 → 0.**
   - The envelope is now used with no added slack. Every truncated loop loses
     3 more bits.
   - The original fit from 80k random inputs had 1 to 7 bits of slack above
     the sample maximum, and that slack is all that is left.
3. **`R_SMALL_THRESHOLD`: 326 → 325.**
   - In Kaliski STEP 6–8, `r` is doubled mod p. For `iter < r_small_threshold()`
     the code uses `mod_double_no_corr`, a plain shift with no Toffoli. It
     bets that the top bit of `r` is still 0, so no `+c` correction is needed.
   - From the threshold on, it uses the full `mod_double_inplace_direct` or
     `_fast`, a shift plus a controlled `+c` with a carry chain.
   - Lowering the threshold makes iteration 325 use the full double, in the
     forward and backward runs of both inversions. This **adds** Toffoli and
     is the more conservative direction. It is a co-tuned island knob, not a
     saving. [`330186c`](330186c.md) puts it back to 326 for −698 Toffoli.

**Where W-TRUNC applies** (`src/point_add/kaliski_walk.rs`):
- the STEP-0 OR chain for `v_w == 0`;
- the STEP-2 comparator `u > v_w`;
- the STEP-4 load `add_f AND u` and the subtract into `v_w`;
- since `404d630`, the STEP-3 and STEP-9 (u, v_w) swaps, at
  `kal_uv_cswap_width = wtrunc + 1`.

Each loop is about one Toffoli per bit. About 4.3 fewer bits in each of these
loops, over about 1,600 forward and backward iterations, gives the net 27,422
after the R_SMALL cost.

## Why it is still correct, and what it risks

All three knobs are probabilistic.
- **W-TRUNC.** A loop of width `w` ignores bits of `u` and `v_w` above `w`. An
  input that converges more slowly than the bare fitted envelope gets a wrong
  comparison, subtraction or swap. With margin 0 there is no slack left
  beyond what the fit had, so this is the most aggressive W-TRUNC point so
  far. A failure shows up as a classical mismatch, and often as phase garbage
  from the broken uncompute too.
- **R_SMALL.** It is safer than in the base. The shift without correction is
  wrong if `r`'s top bit is already 1, and that risk now stops one iteration
  earlier.

There is no nonce in this era. Every knob value changes the op stream and
draws a different 9,024-shot set. The author's joint screen gave:
- `K0 = 24`, margin 0, `R_SMALL = 325`: clean, 0 classical, 0 phase and 0
  ancilla failures;
- `K0 = 23` fails at any setting;
- margin 0 with `R_SMALL` at 320, 322 or 323 fails.

The note says the same `K0 = 24`, margin 0 point fails on the pre-`404d630`
tree. The author's follow-up [`330186c`](330186c.md) contradicts part of
this screen: it reports `R_SMALL` 320 to 325 all clean at this point, and 326
clean and cheaper. So the move to 325 was not actually needed. See
[nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

The saving comes from narrowing the GCD walk's loops (W-TRUNC `K0` and
margin), which is comparator/width truncation. `R_SMALL_THRESHOLD` is an
iteration threshold, which makes iteration/threshold tuning the runner-up,
but it moves in the costly direction and only serves the island.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 404d630 -- src/point_add`.
   - Do not start from the git parent `c7e1ae5`. That is saucegodbased's
     tree, which adds the constant-adder majority fold (`majfold_add_enabled`
     in `cuccaro.rs`).
   - Against the parent, the diff is 37 lines in 2 files. It would show that
     fold being removed, which is not part of this change.
   - Against `404d630`, `git diff --ignore-cr-at-eol 404d630 9fa5a56 -- src/point_add`
     is 6 lines in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`. The flag lets the patch apply whether the files use LF or CRLF line endings. It is the
   complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 9fa5a56 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no `KAL_*`
   or other tuning environment variables set, and with `DUMMY_TOFFOLIS` unset.
   Expect:
   - 2309 qubits
   - 2,588,477 average Toffoli (rounded)
   - score 5,976,793,393
   - 0 classical, 0 phase and 0 ancilla failures

There is no nonce in this tree: the test set is a hash of the op stream, so the
score only reproduces with an identical op stream. Any other change draws a new
island.

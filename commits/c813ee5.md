## Summary

In the divide replay of the dialog GCD (see [`cddd5df`](cddd5df.md)), every
one of the 399 steps runs a controlled modular subtract `y -= ctrl·a`. Its
core is a raw 257-bit subtract of the loaded value `f = ctrl·a` from `y`. The
base used `sub_nbit_qq`, a Cuccaro subtractor whose carries are uncomputed with
a second Toffoli sweep. This commit switches it to `cuccaro_sub_fast`, which
uncomputes the carries by measurement. That costs about 256 fewer Toffoli per
call, so 102,144 average Toffoli in total, at the same 1698 qubits. The add in
the multiply replay was already built this way. The reroll `DIALOG_REROLL`
goes from 2 to 1.

## What changed and why it saves Toffoli

All changes are in `src/point_add/mod.rs`.

- **`dialog_gcd_cmod_sub_materialized_pseudomersenne()`, phase
  `dialog_gcd_materialized_special_raw_difference`.**
  - With the new switch `DIALOG_GCD_MEASURED_APPLY_SUB=1`, the call
    `sub_nbit_qq(b, &f_ext, &acc_ext)` becomes
    `cuccaro_sub_fast(b, &f_ext, &acc_ext, c_in)`, with a fresh `c_in`
    allocated and freed around it.
  - `cuccaro_sub_fast` computes the borrow chain with one Toffoli per bit
    into a carry register, then erases the carries with `hmr` plus `cz_if`
    instead of a reverse Toffoli sweep. See
    [measurement-uncompute](../concepts/measurement-uncompute.md) and
    [adders-and-carries](../concepts/adders-and-carries.md).
  - The subtract runs once per step of the 399-step divide replay
    (`..._apply_bitvector_reverse_exact_block_lifecycle`). The saving is
    102,144 = 256 × 399.
- **`configure_ecdsafail_submission_route()`.** It sets
  `DIALOG_GCD_MEASURED_APPLY_SUB = 1`, and changes `DIALOG_REROLL` from 2 to 1.
- **Qubits.** The fast subtractor allocates a 256-qubit carry register
  (`n − 1` for the 257-bit operands).
  The source comment says this is peak-safe because the matching replay add
  (`cuccaro_add_fast`) already uses the same amount in the same phase. The
  peak stays at 1698.

## Why it is still correct, and what it risks

- The two subtractors compute the same difference for every input, so the
  change is exact. A wrong measured uncompute would show as phase garbage.
- All the probabilistic truncations of the route are unchanged: the margin-28
  width envelope, the 75-bit compare, 399 steps, and the 20-bit overflow
  clear. The new op stream redraws the test inputs, and `DIALOG_REROLL = 1`
  gives a clean draw: 0 classical, 0 phase and 0 ancilla failures over 9,024
  shots. See [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

A reverse Toffoli sweep is replaced by measurement plus a CZ fix-up, so this
is Uncompute Strategy → measurement uncompute.

## Reproduce

1. **Start from the base.** Clone https://github.com/ecdsafail/ecdsafail-challenge
   and run `git checkout 6447611 -- src/point_add`. The base is the git parent.
   `git diff --ignore-cr-at-eol 6447611 c813ee5 -- src/point_add` is 23 lines
   in 1 file.
2. **Apply the patch below** from the repo root with `git apply --ignore-whitespace`.
   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol c813ee5 -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` or `ROUND*` environment variables set. Expect:
   - 1698 qubits
   - 1,981,734 average Toffoli (rounded)
   - score 3,364,984,332
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL = 1` and an identical op stream.
Any other change needs a new reroll search.

## Summary

The 1428 peak of [`dd188f8`](dd188f8.md) was set by the dialog-GCD wrappers,
which hold all of `u` plus the whole compressed transcript, and by the
apply-phase modular add and subtract. This commit lowers both with two
wire-sharing tricks:

- **Transcript runway.** The last 3 transcript blocks (15 qubits) are not
  allocated. They are mapped onto high wires of `u` that the shrinking GCD
  no longer uses by the time those blocks are written, and the reverse pass
  reads them back before `u` grows into those wires again.
- **Swap-host in the apply replay.** The replay used to copy each 5-qubit
  transcript block into the 6-qubit raw block with CNOTs. It now swaps
  them, so the 5 transcript cells are |0⟩ during the block's 3 replay steps.
  They host the chunked adder's carry-in, its spare zero and its two
  boundary carry-outs, which were fresh allocations before.

The chunk cuts of the apply adder are moved (123/133 → 118/140) so its widest
chunk shrinks. The peak falls from 1428 to 1416, where the round84 x-tail
square now binds. The cost is +10,160 Toffoli: the wider cut makes the
carry-out clearing comparator longer, and the width margin goes back from
25 to 26.

## What changed and why it saves qubits

All changes are in `src/point_add/mod.rs`.

### Background

The dialog GCD writes 2 branch bits per step. Every 3 steps the 6 raw bits
(only 27 of the 64 patterns can occur) are compressed into a 5-qubit block of
`compressed_log` (`DIALOG_GCD_HIGH_TAIL_ALIAS_GROUP_SIZE = 3`,
`DIALOG_GCD_HIGH_TAIL_ALIAS_BLOCK_BITS = 5`; 396 steps give 132 blocks, 660
qubits). Each wrapper
(`emit_dialog_gcd_compressed_sidecar_quotient_block_lifecycle` for `dy/dx`
and `emit_dialog_gcd_compressed_sidecar_ipmul_block_lifecycle` for the
x-tail product) runs: forward GCD on `(u, v)`, release the terminal `u`,
apply replay of the transcript on the 256-bit Bézout pair, reacquire `u`,
reverse GCD. See [`dd188f8`](dd188f8.md) for the per-block raw-block hosting
this builds on. This early codec is covered in
[transcript-codecs](../concepts/transcript-codecs.md); [trailmix-jump-gcd](../concepts/trailmix-jump-gcd.md) covers its successor.

### 1. Transcript runway on high `u` (`DIALOG_GCD_COMPRESSED_LOG_U_HIGH_RUNWAY=1`, `_BLOCKS=3`)

- **`dialog_gcd_runway_layout()`** finds the longest suffix of whole blocks,
  at most `DIALOG_GCD_COMPRESSED_LOG_U_HIGH_RUNWAY_BLOCKS` (set to 3; the
  code default is 16), that fits on `u` wires. Hosts are assigned downward
  from `u[249]`; the top 6 wires `u[250..256]` stay free for the hosted raw
  block. A cell may sit on `u[k]` only if `k ≥` the largest
  `dialog_gcd_tobitvector_active_width` of the block's steps. The earliest
  parked block gets the highest hosts, because it has the widest threshold.
- **`dialog_gcd_allocated_compressed_sidecar_bits()`** allocates 660 − 15
  qubits for `compressed_log`. **`dialog_gcd_build_compressed_log_u_high_runway`**
  builds `remapped_log`, the allocated cells followed by the 15 `u` wires,
  and every forward, apply and reverse call now takes this `replay_log`.
- **`dialog_gcd_release_terminal_u` / `dialog_gcd_reacquire_terminal_u`**
  free and reacquire every `u` wire except the parked ones, which still hold
  transcript data across the apply replay.
- **Safety plumbing.** `dialog_gcd_pick_runway_safe_borrow_slice` trims the
  borrowed carry slice before it reaches any active `u` wire, and uses the
  high-`u` fallback lane only when it overlaps no transcript cell. The raw
  block hosts (`dialog_gcd_forward_raw_block_host`,
  `dialog_gcd_reverse_raw_block_host`) skip candidates that overlap active
  `u` or parked cells. Asserts in the forward and reverse block emitters
  check that a parked block is never written or read while its hosts are
  inside the active prefix.
- This lowers the wrapper phases (terminal `u`, transcript passes) by up to
  15 qubits. The submission's phase trace puts them at 1348–1354 afterwards.

### 2. Swap-host in the apply replay (`DIALOG_GCD_APPLY_REPLAY_SWAP_HOST=1`)

- `dialog_gcd_copy_compressed_block_to_raw` and
  `dialog_gcd_clear_raw_block_copy` use `swap` instead of `cx` between the
  5 transcript cells and `raw_block`. After the swap-in the transcript cells
  hold |0⟩ (the raw block was |0⟩), and the swap-out after recompression
  puts the block back.
- Both apply emitters pass those 5 cells as `clean_scratch` to the new
  `dialog_gcd_cmod_add_materialized_pseudomersenne_with_clean_scratch` (and
  the `sub` twin). The chunked adder takes the first cell as its carry-in
  `c_in`, the next as the distinct zero pad of the first chunk, and the rest
  as the boundary carry-outs (`couts` / `bouts`). Before, each was a
  `b.alloc_qubit()`. The carry-outs stay dirty until the exact prefix
  comparator `ccx_cmp_lt_into_fast_prefix_targets` clears them, and they
  are back to |0⟩ before the swap-out.
- The code comments on both new gates still say "Prototype, deliberately NOT
  enabled by configure_ecdsafail_submission_route", but the route does set
  them to `1`.

### 3. Chunk cuts: `DIALOG_GCD_APPLY_CHUNKED_F_CUT` 123 → 118, `DIALOG_GCD_APPLY_CHUNKED_F_CUT2` 133 → 140

The apply add splits the 257-bit sum into `[0, CUT)`, `[CUT, CUT2)`,
`[CUT2, 257)`. Only one chunk's loaded addend and carry lane are live at a
time, so the widest chunk sets the phase's peak. Chunks go from 123/10/124 to
118/22/117 bits, so the widest drops by 6. With the 4 hosted cells, the
apply phases fall to 1415. The cost is that the carry-out clear compares the
prefix up to the last cut, which is now 7 bits longer on every apply call.
At the rate seen in [`dd188f8`](dd188f8.md) (+2,376 for 3 bits), that is
about +5,500 Toffoli.

### 4. `DIALOG_GCD_WIDTH_MARGIN` 25 → 26 and reroll pair

- The width-envelope margin goes back from 25 to 26, undoing
  [`b27f99c`](b27f99c.md). That adds about 4,600 Toffoli (see that note) and
  lowers λ. With item 3, it accounts for the +10,160. The submission note
  does not mention this change.
- `DIALOG_REROLL` 164 → 9, `DIALOG_POST_SUB_REROLL` 100 → 0. These counts
  of identity `X;X` pairs only re-seed the Fiat–Shamir test inputs.

## Why it is still correct, and what it risks

- **Swap-host and chunk cuts are exact.** The swapped-out transcript cells are
  exactly |0⟩, they are restored before recompression, and the chunked adder
  is exact for any cut.
- **The runway adds no new failure mode.** It uses the same premise as the
  width truncation and the terminal-`u` reuse: `u` is 0 above
  `active_width(step)`. An input that breaks this already fails the
  truncation. If it ever happened, a parked cell would start dirty or be
  overwritten, and the run would show classical or ancilla failures.
- **The margin give-back lowers λ** (fewer inputs overflow the envelope).
- The shipped pair (9, 0) is clean: 0 classical, 0 phase and 0 ancilla
  failures over all 9,024 shots, per the author. See
  [nonce-island-and-lambda](../concepts/nonce-island-and-lambda.md).

## Classification rationale

Both qubit savings put registers on wires that are already allocated and
known to be |0⟩: transcript cells on dead `u` lanes, and adder carry cells
on an emptied transcript block. That is scratch/ancilla reuse. The cut
retune is a rebalance that follows from it, and the margin change is a λ
choice.

     lines in 1 file.

   The flag lets the patch apply whether the files use LF or CRLF line
   endings. It is the complete diff against the base.
3. **Check the tree.** `git diff --ignore-cr-at-eol 3166bbd -- src/point_add`
   should print nothing.
4. **Run the benchmark.** Run `./setup.sh && ./benchmark.sh` with no
   `DIALOG_*` environment variables set, because `set_default_env` keeps any
   value already in the environment. Expect:
   - 1416 qubits
   - 1,724,727 average Toffoli (rounded)
   - score 2,442,213,432
   - 0 classical, 0 phase and 0 ancilla failures

The score only reproduces with `DIALOG_REROLL=9`,
`DIALOG_POST_SUB_REROLL=0` and an identical op stream. Any other change
needs a new reroll search.

+fn dialog_gcd_runway_layout() -> Vec<(usize, usize)> {
+    // Leave the top six u lanes unparked.  The accepted a8d8d5a route hosts a
+    // raw 3-step block there whenever the tail is wide enough; reserving those
+    // lanes keeps that scratch host disjoint from parked transcript cells.
+    let raw_block_bits = 2 * DIALOG_GCD_HIGH_TAIL_ALIAS_GROUP_SIZE;
+    let Some(highest_host) = N.checked_sub(raw_block_bits + 1) else {
+        return Vec::new();

+    let blocks = dialog_gcd_compressed_sidecar_blocks();

+    // forward order to descending u positions: the earliest parked block gets
+    // the highest hosts because it is replayed last and therefore needs the
+    // widest inactive-u threshold.
+    let first_allowed = blocks.saturating_sub(dialog_gcd_compressed_log_u_high_runway_blocks());

+        );
+        let mut fits = true;

+                .max()
+                .unwrap_or(1);
+            for slot in 0..DIALOG_GCD_HIGH_TAIL_ALIAS_BLOCK_BITS {
+                if next_host < active_threshold {

+                    break;
+                }

+                    break;
